# MathTest/Main.jack 程式說明

這是第 12 章 OS 的數學類別（`Math.jack`）測試主程式。它對 `Math` 的各個函式做了一組邊界值測試，把結果寫進 RAM[8000]–[8013]，再由 `MathTest.tst` 批次比對。

## 概述

- 測試目標：`Math.multiply`、`Math.divide`、`Math.sqrt`、`Math.min`、`Math.max`、`Math.abs`。
- 測值刻意包含：正/負/零、最大正數、overflow 邊界，確保實作者處理二補數溢位與絕對值極端值。
- 依賴：`Array`（當結果區）、`Math.*`、以及編譯期產生的「陣列元素存取」。

## 架構總覽

`function void main()`：單一 `var Array r`，以 `let r = 8000;` 指向 RAM。共 14 個 `r[*]` 指派，三個群組：

| 群組 | 運算式（含註解期望值） |
|------|------------------------|
| 乘法 | `r[0]=2*3=6`；`r[1]=r[0]*(-30)=-180`；`r[2]=r[1]*100=-18000`；`r[3]=1*r[2]=-18000`；`r[4]=r[3]*0=0` |
| 除法 | `r[5]=9/3=3`；`r[6]=-18000/6=-3000`；`r[7]=32766/(-32767)=0` |
| 函式 | `sqrt(9)=3`、`sqrt(32767)=181`、`min(345,123)=123`、`max(123,-345)=123`、`abs(27)=27`、`abs(-32767)=32767` |

最後 `return` 結束（無輸出，純 RAM 結果）。

## 原理

- **乘法/除法溢出**：Hack 是 16 位元二補數（範圍 −32768～32767）。`r[1] = 6 * (−30) = −180` 超過單一常數？不——它刻意驗證「負數乘法」；`r[7] = 32766 / (−32767)` 的除法商為 0（被除數小於除數），驗證除法的早期返回。
- **sqrt 邊界**：`sqrt(32767)=181`（因 181²=32761 ≤ 32767 且是最大可行值）。這測試平方根的二分/逐位演算法在半滿範圍的正確性，也繞過「平方會溢位」的危險地帶。
- **abs(−32767)**：刻意不測 `abs(−32768)`，因為 16 位元的 −32768 沒有對應正數，任何實作都會溢出——這是書上課堂上的經典陷阱。

## 實作細節

Jack 的 `*`、`/` 運算子並非常見硬體指令，編譯器直接把它們翻成 `call Math.multiply` / `call Math.divide`（見 `Math.jack` 對應說明）。所以 `let r[0] = 2 * 3;` 在 VM 長這樣：

```
push constant 0; push local 0; add      ; r 的基底 + 0
push constant 2; push constant 3
call Math.multiply 2
...
pop that 0
```

`r[1] = r[0] * (-30)` 則先讀 `r[0]`（`that 0`），再 `push constant 30; neg`。

## 測試與驗證

`MathTest.tst` 將結果列出並比對 `MathTest.cmp`：

```
repeat 1000000 { vmstep; }
output-list RAM[8000]..RAM[8013];
```

預期（節錄）：`RAM[8000]=6`、`RAM[8001]=-180`、`RAM[8002]=-18000`、`RAM[8005]=3`、`RAM[8008]=3`、`RAM[8009]=181`、`RAM[8010]=123`、`RAM[8013]=32767`。

## 延伸討論

因為 Jack 的 `*`、`/` 都縮寫成 `Math` 函式呼叫，這個測試幾乎涵蓋了「第 12 章 OS 最難的兩個演算法」：移位相加乘法與遞迴除法。若你的 `Math.multiply` 沒處理符號位（把 y 當無號數），`r[1]` 會是錯的；若 `Math.divide` 忘記 `y > x` 的快速返回，`r[7]` 會錯或在極端輸入下無窮遞迴。
