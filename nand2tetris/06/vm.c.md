# vm.c Hack CPU 模擬器程式說明

把組譯器輸出的 `.bin` 機械碼載入記憶體，用 C 語言「從頭到尾跑一遍 Hack 指令」，
最後印出每個 cycle 的 PC、指令、暫存器與記憶體狀態。它不是教科書第七章的 VM 翻譯器，
而是第六章用來**驗證 `.bin` 是否正確的軟體 CPU**——扮演課本 Hardware Simulator 的角色。

## 概述

- 輸入：`.bin` 二進位檔（`asm.cpp` 的產物）。
- 輸出：逐指令追蹤（DEBUG）與執行結果（A、D、PC、RAM[A] 的值）。
- 地位：第六章的除錯主工具。當你寫完組合器、懷疑 `.bin` 有錯時，
  `./vm add.bin` 一跑便知：`add` 程式結束時應看到 `m[A]=0000=0005`（RAM[0]=5），
  而 `sum` 程式結束時 `m[A]=0001=0037`（RAM[1]=55）。

`vm.c` 與 `dasm.c` 使用完全相同的拆位元手法，但目的相反：

- `dasm.c`：解出「文字」印給人看。
- `vm.c`：解出「語意」執行給機器的結果看。

取名 `vm`（virtual machine）其實是「用軟體模擬整台 Hack 電腦」的意思——
它把第 3 章的 CPU、第 4 章的記憶體用 C 語言寫活了。

## 架構總覽

| 資料/函式 | 用途 |
|-----------|------|
| `im[32768]` | ROM：儲存 32768 條指令（Hack 的 ROM 上限） |
| `m[65536]`  | RAM：65536 個 16 位元記憶體字（第 4 章 Memory 的規格） |
| `imTop`     | 指令數（決定什麼時候「跑完」） |
| `run()`     | 指令迴圈：fetch → decode → execute，含 ALU 與暫存器 |
| `main`      | 開檔、`fread` 載入 ROM、呼叫 `run` |

「暫存器」直接以區域變數模擬：

| 變數 | 對應硬體 | 意義 |
|------|----------|------|
| `PC` | PC（程式計數器）| 下一條要抓的位址 |
| `A`  | A 暫存器 | 位址/資料暫存器 |
| `D`  | D 暫存器 | 資料暫存器 |
| `I`  | instruction register | 目前抓到的指令 |
| `aluOut` | ALU 輸出 | C 指令的運算結果 |

## 原理

### 指令循環（instruction cycle）

與第 3 章 CPU.hdl 的硬體一樣，`run()` 是一圈「抓指令、解指令、執行指令」：

```
while (1) {
    if (PC >= imTop) break;      // 超出程式範圍 = 程式結束（類比 PC 沒被改寫持續遞增）
    I = im[PC];  PC++;           // fetch：抓指令、PC 先 +1
    if (A 指令) A = I;           // execute：設定 A 暫存器
    else { 解出 a/c/d/j；運算；寫入；可能跳躍改 PC }  // C 指令
}
```

A 指令被 `ADDA` *退路*：硬體上 A 指令把 `inM`/A 設為該常數，模擬器裡 `A = I` 一行搞定。

### A 指令

`(I & 0x8000) == 0`。高位置 0，直接把整條 16 位元指令當常數載入 A。

### C 指令的三個階段

第 3 章 CPU 的 C 指令流程是**同時**進行的，模擬器為了讓「一步一步」可閱讀，
拆成三個依序的階段，結果相同：

1. **取運算元**：`AM = (a==0) ? A : m[A]`。
   `a=0` 時 comp 對 A 暫存器運算，`a=1` 時對 `RAM[A]`（符號 M）運算——一次讀記憶體。
2. **ALU 運算**：`switch (c)` 依 7 位元 c 值算出 `aluOut`。這個 switch 就是第 3 章
   ALU 的六個控制位元 zx/nx/zy/ny/f/no 的「數學總表」：

| c 值 | 運算 | | c 值 | 運算 |
|------|------|-|------|------|
| `0x2A` | `0` | | `0x37` | `AM+1` |
| `0x3F` | `1` | | `0x0E` | `D-1` |
| `0x3A` | `-1`| | `0x32` | `AM-1` |
| `0x0C` | `D` | | `0x02` | `D+AM` |
| `0x30` | `AM`| | `0x13` | `D-AM` |
| `0x0D` | `D^0xFFFF`（即 `!D`）| | `0x07` | `AM-D` |
| `0x31` | `AM^0xFFFF`（`!AM`）| | `0x00` | `D&AM` |
| `0x0F` | `-D`| | `0x15` | `D\|AM` |
| `0x33` | `-AM`| | 其它 | `assert(0)` |
| `0x1F` | `D+1` | | | |

  注意 `!D` 用的是 `D ^ 0xFFFF`（16 位元逐位元反相），與第 2 章 Not16 的「每一位反相」語意一致。
3. **寫回與跳躍**：

```c
if (d & BIT(2)) A = aluOut;   // d 的 bit2 = 寫 A
if (d & BIT(1)) D = aluOut;   // d 的 bit1 = 寫 D
if (d & BIT(0)) m[A] = aluOut; // d 的 bit0 = 寫 M（RAM[A]）

switch (j) {                  // 依 aluOut 與 j 條件決定是否 PC = A
  case 0x1: if (aluOut >  0) PC = A; break;  // JGT
  case 0x2: if (aluOut == 0) PC = A; break;  // JEQ
  ... 0x3 JGE、0x4 JLT、0x5 JNE、0x6 JLE ...
  case 0x7: PC = A; break;                  // JMP（無條件）
}
```

`d`（dest）3 位元的每個 bit 對應「要不要寫入 A/D/M」，用 `BIT(i)` 宏展開成 `0x0001<<i`
逐位元測試——與第 3 章 dest 3 位元同時接住三個暫存器的 load 位元一一對應。
跳躍條件 `PC = A`：Hardware CPU 的 J 指令把 Mux 切到 A 暫存器連到 PC-in，模擬器一行就辦到。

## 實作細節

### DEBUG 追蹤資訊

每條指令印一行：

```
PC=0000 I=0002 A=0002 D=0000 m[A]=0000=0000
```

`A=%04X D=%04X m[A]=%04X=%04d` 同時顯示十六進位與十進位，方便人讀。
C 指令多了拆解結果：

```
PC=0001 I=EC10 A=0002 D=0002 m[A]=0000=0000 a=0 c=30 d=2 j=0
```

`EC10` 拆開：bit15=1（C 指令）、`a=0`、`c=0x30`（comp=A）、`d=2`（寫 D）、`j=0`（不跳）——
正好對應 `D=A` 的編碼 `111 0 110000 010 000`。

### 程式結束的判定

```c
if (PC >= imTop) { DEBUG("exit program !\n"); break; }
```

Hack 沒有 halt 指令，當程式執行到尾、PC 超出載入範圍即視為結束。
`sum.asm` 結尾那段被註解掉的 `(END) @END 0;JMP`（無限迴圈）如被啟用，模擬器將永遠跑不完——
這也正是真實 Hack 電腦「程式結束」的寫法：跳進無窮迴圈。

### 記憶體 m

`int16_t m[65536]` 直接對應第 4 章的 Memory 介面：位址 0..16383 是 RAM、
16384..24575 是螢幕（SCREEN）、24576 是鍵盤（KBD）。模擬器不特別區分，
反正 `m[A]` 一體適用。

## 測試與驗證

配合 `asm.cpp` 的完整流程：

```
./asm add          # 產生 add.bin
./vm  add.bin      # 期望：PC=0005 後 exit，m[0]=0005（2+3=5）
```

`add.bin` 執行追蹤的關鍵片段：

```
PC=0003 I=E090 A=0003 D=0005 m[A]=0000=0000   ← D 暫存器 = 3+2 = 5
PC=0004 I=0000 A=0000 D=0005 m[A]=0000=0000   ← A = 0（準備寫入）
PC=0005 I=E308 A=0000 D=0005 m[A]=0005=0005   ← RAM[0] = 5
exit program !
```

`sum.bin` 若要手動驗算：跑完 `ram[1]` 應等於 `1+2+...+10 = 55`（`0x37`）。
這是第 4 章 `.tst` 檔會檢查的結果，現在用 C 語言模擬器即可復現。

## 延伸討論

- **這不是第七章的 VM**：第六章的 `vm.c` 模擬的是「硬體 CPU」；第七章的 VM 則模擬
  「堆疊機器」並把 VM 指令翻譯成 Hack 組合語言，兩者層次完全不同。名字相同、功能相異，
  讀者要特別注意。
- **速度與忠實度**：C 編譯器執行 Hack 指令每條只要幾 ns，比 Hardware Simulator
  （繪製電路波形）快上幾個數量級，很適合大量組合語言程式的自動測試。
  犧牲的是看不出「時脈邊緣」與時序——它模擬的是功能行為（functional），不是時序行為。
- **可擴充處**：若要模擬輸入裝置，只要在 `m[24576]`（KBD）上寫入按鍵值即可互動；
  配合 `m` 的螢幕段輸出，甚至能做成一個純文字的 Screen 顯示器。
