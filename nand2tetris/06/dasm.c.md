# dasm.c 反組譯器（Disassembler）程式說明

把組譯器產出的 `.bin` 機器碼（16 位元 Hack 指令）逆向還原成組合語言文字，
是 `asm.cpp` 的**互逆程式**：`asm` 把符號變成位元，`dasm` 把位元變回符號。

## 概述

- 輸入：`.bin` 二進位檔（`asm.cpp` 的 `fwrite` 產物，一個指令 2 位元組）。
- 輸出：標準輸出（stdout）的組合語言文字，可直接與原始 `.asm` 對照。
- 地位：第六章的驗證工具。組譯正確與否，最直接的檢查就是
  `./dasm add.bin` 是否印出和 `add.asm` 一模一樣的程式——「組譯 → 反組譯」形成一個迴路。

資料流：

```
add.asm  ──asm.cpp──▶  add.bin  ──dasm.c──▶  原始組合語言
                    （機器碼）            （還原文字）
```

## 架構總覽

| 資料/函式 | 用途 |
|-----------|------|
| `im[32768]` | 載入機器碼的指令記憶體（最大 32768 個 16 位元字） |
| `imTop`     | 實際載入的指令數 |
| `jTable[]`  | jump 的 3 位元值 → 助憶碼（與 `asm.cpp` 的 jMap 互逆運算元） |
| `dTable[]`  | dest 的 3 位元值 → 助憶碼（與 `asm.cpp` 的 dMap 同序） |
| `disasm()`  | 主迴圈：逐條指令解析、重組、印出 |
| `main`      | 開檔、`fread` 讀入全部指令、呼叫 `disasm` |

## 原理

同一個 16 位元字 `I`，組譯器看的是「text brain」，反組譯器看的是「bit brain」。
判斷與拆解全憑位元位置：

- **是不是 A 指令**：`I & 0x8000 == 0`。bit15 是 0 → A 指令，直接 `printf("@%d\n", I)`
  （低 15 位就是常數位址）。
- **C 指令分解**（bit15=1 時），平移 + 遮罩取出各欄位：

| 欄位 | 取法 | 範例意義 |
|------|------|----------|
| `a` | `(I & 0x1000) >> 12` | 0 → 對 `A` 算；1 → 對 `M` 算 |
| `c` | `(I & 0x0FC0) >>  6` | 7 位元 ALU 函數選擇 |
| `d` | `(I & 0x0038) >>  3` | 3 位元 dest |
| `j` | `(I & 0x0007) >>  0` | 3 位元 jump |

`0x0FC0` = `0000 1111 1100 0000`：把第 11..5 位（c）夾出來再右移 6 位變成 0..0x3F 的小數。

接著是**查表反查**：組譯時 `comp ⟶ 7 位元`，反組譯就反過來 `7 位元 ⟶ comp 字串`。
因為 `A`/`M` 系列「7 位元相同、只差 a 位元」，`dasm` 先定 `AM = (a==0)?'A':'M'`，
再用一個 `switch(c)` 一次列出 18 種 7 位元值——每個 case 上方註解都標了對應的 comp：

| c（7 位元） | comp 文字 | 備註 |
|------------|-----------|------|
| `0x2A`=101010 | `0` | 常數 0 |
| `0x3F`=111111 | `1` | 常數 1 |
| `0x3A`=111010 | `-1` | |
| `0x0C`=001100 | `D` | |
| `0x30`=110000 | `A`/`M` | 看 a 位元 |
| `0x0D`=001101 | `!D` | |
| `0x31`=110001 | `!A`/`!M` | |
| `0x0F`=001111 | `-D` | |
| `0x33`=110011 | `-A`/`-M` | |
| `0x1F`=011111 | `D+1` | |
| `0x37`=110111 | `A+1`/`M+1` | |
| `0x0E`=001110 | `D-1` | |
| `0x32`=110010 | `A-1`/`M-1` | |
| `0x02`=000010 | `D+A`/`D+M` | |
| `0x13`=010011 | `D-A`/`D-M` | |
| `0x07`=000111 | `A-D`/`M-D` | |
| `0x00`=000000 | `D&A`/`D&M` | |
| `0x15`=010101 | `D\|A`/`D\|M` | |
| 其它 | — | `assert(0)`：不可能是合法指令 |

遇到不在表的 `c` 值直接 `assert(0)` 崩潰，因為那代表輸入的 `.bin` 根本不是合法的 Hack 指令。

## 實作細節

```c
char *jTable[] = {"","JGT","JEQ","JGE", "JLT", "JNE", "JLE", "JMP"};
char *dTable[] = {"", "M", "D",  "MD",  "A",   "AM",  "AD",  "AMD"};
```

這兩個陣列與 `asm.cpp` 的 `jMap`/`dMap` **完全同序**，而且 `j`/`d` 的 3 位元值剛好就是 0..7，
所以可直接當 `index` 用，不需要 `map`：

- `d=0` 表示沒有「寫入目標」，省略 `xxx=` 前綴；`d=1`（`M`）→ `M=`，`d=2`（`D`）→ `D=`……
- `j=0` 表示無跳躍，不印 `;xxx`；`j=1`（`JGT`）、`j=2`（`JEQ`）……

重組文字用三段接龍：

```c
char head[100]="", command[100];
if (d != 0) sprintf(head, "%s=", dTable[d]);   // 1. dest
if (op[0] != '\0') strcat(head, op);           // 2. comp
if (j != 0) sprintf(command, "%s;%s", head, jTable[j]);  // 3. ;jump
else        sprintf(command, "%s", head);
```

其中 `%c`, `AM` 的運用讓同一份 `switch` 同時吐出 `A` 與 `M` 兩種文字：
`case 0x30: sprintf(op, "%c", AM);` 當 a=1 就印 `M`。

print 出來即是 A 指令 `@n`、C 指令 `d=comp` 或 `comp;j`——與 `asm.cpp` 的輸入文法完全相容。

## 測試與驗證

```
make                    # gcc -std=c99 dasm.c -o dasm
./dasm add.bin
```

對 `add.bin`（`2+3` 那個程式）的預期輸出與原始 `add.asm` 一致：

```
@2
D=A
@3
D=D+A
@0
M=D
```

建議雙向驗證流程：

```
./asm  add          # add.asm → add.bin
./dasm add.bin      # add.bin → 文字
diff add.asm <(./dasm add.bin) --ignore-space-change   # 兩者比對
```

（除原始 `add.asm` 的註解行外，程式指令應逐字吻合。）

## 延伸討論

- 反組譯器不會還原**符號名**：機器碼裡只存位址，`@16` 究竟是 `@i` 還是 `@sum`
  在 `.bin` 中不可分辨。要重建符號需額外附帶 debug 資訊——真實世界的
  objdump/GDB 也仰賴 ELF 的 symbol table，道理相同。
- `assert(0)` 式的「遇到看不懂就死」在教學版恰到好處；生產級反組譯器
  （如 x86 的各式 disassembler）會對非法指令「猜長度」繼續掃，這是設計取捨。
- 本書第六章其實只要求「組合器」，`dasm` 屬額外工具，但正因為有了它，「組合器寫對沒」
  變成一個可以自動驗證的封閉迴圈，是很好的工程思維示範。
