# asm.cpp 組譯器（Assembler）程式說明

以 C++ 實作的 Hack 組譯器：把第 6 章的組合語言（.asm）轉成機器碼（.hack 文字檔與 .bin 二進位檔）。
整個程式只靠標準函式庫（iostream、map、cstdint、stdio）完成，是理解「符號如何變成位元」的最佳範例。

## 概述

- 輸入：`.asm` 組合語言檔（例如 `add.asm`、`sum.asm`）。
- 輸出：
  - `.hack`：一行一條 16 位元 0/1 字串的「機器碼文字檔」（第 4 章 Hardware Simulator 可直接載入）。
  - `.bin`：把 16 位元字（uint16_t）依序寫出的二進位檔（供 `./vm`、`./dasm` 使用）。
- 地位：這是 Nand2Tetris 第 6 章的核心程式。前幾章用 Hardware Simulator 手動維護的 `.hack`，
  現在由程式自動產生；下一章（第 7 章 VM 翻譯器）也會利用本章的符號解析與編碼技巧。

程式流程非常典型：

```
main → assemble(baseName)
        ├─ pass1(讀入 .asm，只掃描符號，建立符號表)
        └─ pass2(重讀 .asm，用符號表把所有指令編成 16 位元)
```

## 架構總覽（資料結構與模組）

全域資料結構就是「三個查表 + 一個符號表 + 一個變數計數器」：

| 名稱 | 型別 | 用途 |
|------|------|------|
| `dMap`  | `map<string,string>` | dest 助憶碼 → 3 位元編碼 |
| `cMap`  | `map<string,string>` | comp 助憶碼 → 7 位元編碼 |
| `jMap`  | `map<string,string>` | jump 助憶碼 → 3 位元編碼 |
| `symMap`| `map<string,int>`    | 符號（label 與變數）→ RAM/ROM 位址 |
| `varTop`| `int`                | 下一個可用變數位址（從 16 開始） |

函式分工：

| 函式 | 職責 |
|------|------|
| `parse()`   | 把一行原始行清成「純程式碼」（去空白、去注釋、去換行） |
| `pass1()`   | 第一趟掃描：數指令位址，把 `(LABEL)` 記入符號表 |
| `code2binary()` | 把一條指令文字編成 16 位元字串（A 指令或 C 指令） |
| `int2bin()` / `bin2int()` | 整數 ↔ 16 位元 0/1 字串 |
| `pass2()`   | 第二趟掃描：逐行編碼，輸出 `.hack` 與 `.bin` |
| `assemble()`| 組裝檔名的 `.asm/.hack/.bin` 三兄弟，呼叫 pass1 + pass2 |
| `symDump()` | 印出符號表內容（除錯用，主程式中被註解掉） |

## 原理

### Hack 指令格式（第 4 章的複習）

Hack 機器碼固定 16 位元，只有兩種指令，以**最高位元 bit15** 區分：

- **A 指令**（bit15 = 0）：`0 + 15 位元常數`。把位址/常數載入 `A` 暫存器，
  `@value`、`@symbol` 都屬此類。
  位元分佈：`[15]=0`，`[14..0]` 是 15 位元非負整數（0 ~ 32767）。

- **C 指令**（bit15 = 1）：`111 a ccccccc ddd jjj`，一次完成「算術運算 + 存到哪 + 是否跳躍」：

| 位元 | 欄位 | 寬度 | 意義 |
|------|------|------|------|
| 15..13 | `111` | 3 | C 指令標記（永遠是 1） |
| 12 | `a` | 1 | 0 → comp 對 `A` 運算；1 → comp 對 `M`(=RAM[A]) 運算 |
| 11..5 | `c` | 7 | comp：ALU 要算哪一種函數 |
| 4..2 | `d` | 3 | dest：結果寫入 A / D / M 的哪幾個 |
| 1..0 | `j` | 2 | jump：ALU 結果合條件時跳到 A |

### 為什麼需要兩趟掃描？

`@LOOP`、`@STOP` 這類符號可能在「前面」就被引用，卻在「後面」才定義。
掃描一遍時無法知道它的位址，所以：

1. **Pass1**：只做「符號收集」——逐行數指令位址（label 不佔位址），
   遇到 `(LABEL)` 就把 `LABEL → 目前位址` 記入符號表。
2. **Pass2**：重頭再讀一次檔，現在每個符號都查得到位址，可直接編碼。

兩趟掃描是組合器的經典設計，也正是本書組合器專案（Hack Assembler）的第 1 小題做法。

### 符號表的三種來源

`symMap` 的內容由三批資料合併而成：

1. **預設符號**（程式一啟動就有）：`R0`~`R15`、`SCREEN`、`KBD`、`SP`、`LCL`、`ARG`、`THIS`、`THAT`。
2. **標籤（label）**：pass1 掃到的 `(LABEL)`。
3. **變數**：pass2 才看到、又不在符號表裡的 `@xxx`，當場新配一個位址（從 16 起跳）。

因為變數是「第一次遇到時才分配」，所以 **pass1 只處理 label，絕不能先替變數配位址**，
否則變數會吃掉落在我 label 後的位址。

## 實作細節

### 三個查表（dMap / cMap / jMap）

C++11 的初始化列表讓查表一目瞭然。C 指令的組裝就是「查表 → 併字串」：

**dest 編碼（dMap，3 位元）**：

| dest | 編碼 | | dest | 編碼 |
|------|------|-|------|------|
| （空） | `000` | | A | `100` |
| M | `001` | | AM | `101` |
| D | `010` | | AD | `110` |
| MD | `011` | | AMD | `111` |

**jump 編碼（jMap，3 位元）**：

| jump | 編碼 | | jump | 編碼 |
|------|------|-|------|------|
| （空） | `000` | | JLT | `100` |
| JGT | `001` | | JNE | `101` |
| JEQ | `010` | | JLE | `110` |
| JGE | `011` | | JMP | `111` |

**comp 編碼（cMap，7 位元）全表**。注意 `c` 欄是「運算本身」，
`a` 位元決定運算元是 `A`（a=0）還是 `M`（a=1），所以 `A` 系列與 `M` 系列只差 bit12：

| comp | 編碼 | 備註 | comp | 編碼 | 備註 |
|------|------|------|------|------|------|
| `0` | `0101010` | 常數 0 | `M` | `1110000` | =RAM[A] |
| `1` | `0111111` | 常數 1 | `!M` | `1110001` | |
| `-1`| `0111010` | | `-M` | `1110011` | |
| `D` | `0001100` | | `M+1`| `1110111` | |
| `A` | `0110000` | | `M-1`| `1110010` | |
| `!D`| `0001101` | | `D+M`| `1000010` | |
| `!A`| `0110001` | | `D-M`| `1010011` | |
| `-D`| `0001111` | | `M-D`| `1000111` | |
| `-A`| `0110011` | | `D&M`| `1000000` | |
| `D+1`|`0011111` | | `D\|M`| `1010101` | |
| `A+1`|`0110111` | | | | |
| `D-1`|`0001110` | | | | |
| `A-1`|`0110010` | | | | |
| `D+A`|`0000010` | | | | |
| `D-A`|`0010011` | | | | |
| `A-D`|`0000111` | | | | |
| `D&A`|`0000000` | | | | |
| `D\|A`|`0010101` | | | | |

可以觀察：`A` 行與 `M` 行「完全相同表格」只差最高位元的 `0`/`1`
（例如 `A`=0110000、`M`=1110000），因為那就是 `a` 位元的功效。

### parse()：把一行清成程式碼

```c
char *parse(char *line) {
  char *codePtr = line, *codeEnd = line;
  while (strchr("\t ", *codePtr) != NULL) codePtr++;      // 跳過行首空白
  while (*codeEnd != '\0' && strchr("/\n\r", *codeEnd) == NULL) codeEnd++;
  *codeEnd = '\0';                                        // 遇到 /、換行就切斷
  return codePtr;
}
```

兩個指標搞定三件事：行首空白（`\t`、空白）往前跳；`/` 之後通通當註解刪掉
（`//` 註解的慣例剛好以一斜線開始）；`\n`、`\r` 換行字元也被切斷。
返回值是「有效程式碼的起點」，pass1、pass2、code2binary 都靠它。

### pass1()：記住符號位址

```c
int address = 0;
while (fgets(...)) {
  char *code = parse(line);
  if (strlen(code)==0) continue;            // 空白/註解行，跳過
  if (code[0] == '(') {                     // 只有 (LABEL) 行會動符號表
    sscanf(code, "(%[^)])", label);         // 抓括號內的 label
    symMap[lab] = address;                  // 記住 "這個位址"
    ...
  } else {
    address ++;                             // 一般指令才佔一個位址
  }
}
```

關鍵在 `address`：只有「真指令」才 `address++`。label 數到哪一行，就把它綁定到那行的位址。
重複定義同一個 label 時會印 `error`——這在正式組譯器裡應是致命錯誤，這裡只警示。

### code2binary()：一條指令 → 16 位元字串

以第一個字元分派：

- `@` **A 指令**：先試 `sscanf(code, "@%d", &address)` 看是否為數字。
  - 是數字 → 直接轉 16 位元。
  - 不是數字 → 取 `@xxx` 的 `xxx` 查符號表：
    - 查得到 → 用紀錄的位址；
    - 查不到 → **宣佈它是變數**：`symMap[sym] = varTop;` 配給目前 `varTop`，然後 `varTop++`。
      因此第一個變數是 16，第二個 17，依此類推——這就是書上「變數從位址 16 開始」的實作。
- 其餘 **C 指令**：依有沒有 `=` 分兩種形式：
  - `d=comp`：`sscanf(code, "%[^=]=%s", d, comp)` 拆開左邊 dest、右邊 comp，
    組出 `111 + ccode + dcode + 000`（jump 留 000）。
  - `comp;j`：`sscanf(code, "%[^;];%s", comp, j)`，
    組出 `111 + ccode + 000 + jcode`（dest 留 000）。

`sprintf(binary, "111%s%s000", ...)` 這個「後綴補 000」的寫法非常直觀：
兩種形式的缺口另一邊永遠是空位元。

### int2bin() / bin2int()：整數與字串互轉

```c
char *int2bin(int a, char *bin, int size) {
    bin += size; *bin-- = '\0';
    for (int i = size; i > 0; i--) {
        *bin-- = (a & 1) + '0';   // 從最低位開始填，指標從尾巴往回走
        a >>= 1;
    }
    return bin;
}
```

指標技巧：先指到字串尾端（`bin += size`），然後**由低位元往高位元**回填，
因為低位元位在最右邊。寫完指標剛好回到開頭，回傳的就是 16 位元字串開頭。
`bin2int` 則借用 `strtol(bin, NULL, 2)`（base 2）一次搞定。

### pass2()：輸出兩份檔

```c
FILE *fp  = fopen(inFile , "r");   // 再次讀組合語言
FILE *hfp = fopen(hackFile, "w");  // .hack 文字檔（寫入 16 位元字串）
FILE *bfp = fopen(binFile , "wb"); // .bin 二進位檔（寫入 2 位元組 uint16_t）
```

對每一行程式碼：
1. 若是 `(LABEL)` 行只會印出、不產出機器碼（label 不佔位址）。
2. 否則 `code2binary()` 得到 16 位元字串 → 印出（`%02X` 位址 + 十六進位）。
3. `fprintf(hfp, "%s\n", binary)` → `.hack` 一行一條 0/1 字串。
4. `uint16_t b = bin2int(binary); fwrite(&b, sizeof(b), 1, bfp)` → `.bin` 一筆 16 位元機器字。

`.bin` 是給後面的 `./vm`（模擬器）與 `./dasm`（反組譯器）吃的原始機器碼檔案。

### 預設符號與一個值得注意的小地方

```c
map<string, int> symMap {
  {"R0",0}, ..., {"R15",15},
  {"SCREEN",16384}, {"KBD",24576},
  {"SP",0}, {"LCL",0}, {"ARG",2}, {"THIS",3}, {"THAT",4}
};
```

對照書中第 6 章：`R0`~`R15` 與 `SP`/`LCL`/`ARG`/`THIS`/`THAT` 其實共用 0~4，
而本書慣例是 `LCL=1`。這裡將 `LCL` 誤設成 `0`（與 `SP`、`R0` 同名），
屬於實作上的瑕疵——功能上因為 `R1` 仍等於 1 所以範例不受影響，但讀者應知道
正規的組合器應設 `LCL=1`。這是很好的「抓蟲教材」：符號表少一行、錯一行，後果都難以預料。

## 測試與驗證

```
make                      # g++ -std=c++11 asm.cpp -o asm
./asm add                 # 組譯 add.asm → add.hack、add.bin
./vm  add.bin             # 模擬器驗證：最後 m[A]=0000=0005
./dasm add.bin            # 反組譯回 add.asm 原文（互逆驗證）
```

`add.asm` 的輸出（`./asm add` 的 PASS2 部分）：

```
00: @2                   0000000000000010 0002
01: D=A                  1110110000010000 ec10
02: @3                   0000000000000011 0003
03: D=D+A                1110000010010000 e090
04: @0                   0000000000000000 0000
05: M=D                  1110001100001000 e308
```

拿 `M=D`（`111 0 001100 001 000`）對照編碼表：comp=`D`=0001100、dest=`M`=001、jump=空，
與 `0xe308` 的位元 `1110001100001000` 完全吻合。這正是第 3 章 CPU 解碼時
`c=0C d=1 j=0` 的由來（見 `vm.c` 的追蹤輸出）。

## 延伸討論

- **符號表實作**：這裡用 `std::map`（紅黑樹）。組合器實務上更常用 hash table（如
  `std::unordered_map`），因為 $O(1)$ 查表；本書 Java 版組譯器也用 HashMap。
- **錯誤處理**：遇未定義符號（少數組譯器才允許）或重複 label 只印訊息、不回傳錯誤碼。
  正式工具應回傳非零 exit code 給 Makefile / CI 偵測。
- **數值極限**：A 指令只有 15 位元，參考值超過 32767 時 `int2bin` 會溢位截斷，
  需要錯誤檢查——教科書版組譯器同樣有此限制。
- **與後續章節的關係**：第 7 章 VM 翻譯器「把 VM 指令翻譯成 Hack 組合語言」
  產生的正是本程式能吃的 `.asm`；第 12 章的作業系統也是用組合語言寫成的。
  換句話說，這個 170 行的程式，是整台 Hack 電腦「最後一哩的編譯管線」。
