# sum.asm 範例程式說明

Hack 組合語言版的「累加器」程式：先在 `RAM[0]` 放入上限值 10，接著計算
`1 + 2 + ... + 10`，結果寫入 `RAM[1]`。它示範了本書的重要語法——**符號變數**、
**標籤（label）**、**條件跳躍**、**無條件跳躍**——幾乎把第六章組譯器該處理的
`@符號`、`(LABEL)`、`comp;jump` 全數用過一遍。

## 概述

- 目的：`RAM[0] = 10`，然後 `RAM[1] = 1+2+...+RAM[0]`（本程式算出 55）。
- 使用的符號：
  - 變數（分配在 RAM[16] 起）：`i`→16、`sum`→17。
  - 預設符號：`R0`→0、`R1`→1（與本書第 6 章預設符號表一致）。
  - 標籤：`(LOOP)`→8、`(STOP)`→22。
- 地位：第 6 章組譯器的第二支測試程式（比 add.asm 完整），
  同時驗證「pass1 記 label」與「pass2 給變數配位址」兩個機制。

## 對應的 C 語言版本

```c
RAM[0] = 10;
int i = 1;             /* i 在 RAM[16] */
int sum = 0;           /* sum 在 RAM[17] */
LOOP:
    if (i > RAM[0]) goto STOP;   /* i - RAM[0] > 0 就跳 */
    sum = sum + i;
    i = i + 1;
    goto LOOP;
STOP:
RAM[1] = sum;          /* 1+2+...+10 = 55 */
```

## 逐段說明（對照位址）

位址是組譯器 pass1 數出來的結果（`(LOOP)` 與 `(STOP)` 不佔位址）：

**初始化（位址 0..7）**

| 位址 | 指令 | 動作 |
|------|------|------|
| 0 | `@10` | `A = 10` |
| 1 | `D=A` | `D = 10` |
| 2 | `@0` | `A = 0` |
| 3 | `M=D` | `RAM[0] = 10`（上限） |
| 4 | `@i` | 第一次見到變數 `i`，組譯器配位址 **16** |
| 5 | `M=1` | `i = 1` |
| 6 | `@sum` | 變數 `sum` 配位址 **17** |
| 7 | `M=0` | `sum = 0` |

**迴圈體（位址 8..15）**

| 位址 | 指令 | 動作 |
|------|------|------|
| 8 | `(LOOP)` | 標籤，記為位址 `8` |
| 9 | `@i` `D=M` | `D = i`（`M` 讀 RAM[16]） |
| 11 | `@R0` | `A = 0`（預設符號 R0） |
| 12 | `D=D-M` | `D = i - RAM[0]` |
| 13 | `@STOP` `D;JGT` | 若 `i > RAM[0]`，跳到位址 22 |
| 15 | `@i` `D=M` | 否則 `D = i` |
| 17 | `@sum` `M=D+M` | `sum = i + sum` |
| 19 | `@i` `M=M+1` | `i = i + 1` |
| 21 | `@LOOP` `0;JMP` | 無條件跳回位址 8 |

**收尾（位址 22..25）**

| 位址 | 指令 | 動作 |
|------|------|------|
| 22 | `(STOP)` | 標籤，記為位址 `22` |
| 23 | `@sum` `D=M` | `D = sum` |
| 25 | `@R1` `M=D` | `RAM[1] = sum = 55` |

流程圖（文字化）：

```
RAM[0]=10; i=1; sum=0
        │
   ┌───▼────┐
   │  LOOP  │◄─────────┐
   └───┬────┘          │
       │ i > RAM[0] ?  │
       │ 是            │ 否
       ▼               ▼
     STOP        sum += i
   RAM[1]=sum     i++
       │            │
       ▼            └────► 回 LOOP
   （結束）
```

**空跳躍的寫法**：`0;JMP` 的 comp 是常數 `0`（編碼 0101010）、dest 全空、
jump=JMP。ALU 輸出什麼不重要，JMP 是無條件跳，這是 Hack 寫無窮跳／goto 的慣用形式。
（若把結尾啟用：`(END) @END 0;JMP` 就是 Halt 慣例。）

## 編碼重點

組譯器輸出的幾個關鍵位元（`./asm sum`）：

| 指令 | 機器碼 | 說明 |
|------|--------|------|
| `@i`（變數） | `0000000000010000` | 0x0010 = 16，變數 i 配位址 |
| `@sum` | `0000000000010001` | 0x0011 = 17，變數 sum |
| `@R0` | `0000000000000000` | 0x0000，預設符號 |
| `@STOP` | `0000000000010110` | 0x0016 = 22，label |
| `D;JGT` | `1110001100000001` | `111 0 001100 000 001` |
| `0;JMP` | `1110101010000111` | `111 0 010101 000 111` |
| `M=D+M` | `1111000010001000` | a=1（對 M 運算）、comp=D+M |

`M=D+M` 這條最重要的觀察點：由於是 `M` 系列，**a=1**，編碼變成 `1111...`
（bit12 為 1），ALU 的 `y` 輸入取自 `RAM[A]` 而非 A 暫存器。

## 測試與驗證

```
./asm sum        # 組譯，觀察 PASS1 印出 symbol:LOOP address=8、symbol:STOP address=22
./vm  sum.bin    # 執行，驗證 RAM[1]
```

`./vm sum.bin` 追蹤的關鍵片段（`i` 由 1 加到 10）：

```
PC=0011 I=F088 ... m[A]=0015=0021     ← sum=0+1+...+6=21
...                                   ← sum 一路累加
PC=0019 I=E308 A=0001 D=0037 ...      ← RAM[1] = 55（0x37）
exit program !
```

最後 `D=0037` = 十進位 55 = `1+2+...+10`。若改用 Hardware Simulator 載入
`sum.hack`，`RAM[1]` 同樣是 55。

**符號配置驗證**：變數 `i`、`sum` 分別是 RAM[16]、RAM[17]（因為是程式中
第一個、第二個「未定義的符號」，按第 6 章規則從 16 開始配）。
`@R0`/`@R1` 是預設符號得 0/1，`@STOP`/`@LOOP` 是 label 得 22/8。

## 延伸討論

- **記憶體指針 vs 變數**：`i` 與 `sum` 存在 RAM，等於 C 語言的「全域 int」。
  三種符號（R 系列、變數、label）在組譯器符號表裡混同儲存，靠「遇到時刻」區分身份。
- **邊界條件**：`RAM[0]=10` 時迴圈恰執行 10 次（i=1..10）。若改 `RAM[0]=0`，
  `i>0` 第一次就成立、直接跳 STOP，sum=0——組譯器/模擬器皆不需額外處理，符合預期。
- **本書第 6 章作業 hint**：官方組譯器對 `@i` 等變數也是「第一次見到才分配」，
  本程式正是驗證「變數配置 + label 位址」兩機制的最低限度測試。
