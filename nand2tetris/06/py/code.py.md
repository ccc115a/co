# py/code.py Code 編碼類別說明

`Code` 類別是 Python 組譯器（`asm.py`）的「編碼表」模組：把 comp / dest / jump 的
助憶碼換成對應的位元串，讓 `asm.py` 專心處理文法與指令分派。對應到 `asm.cpp`，
它就是 dMap / cMap / jMap 三個查表的 Python 化身。

## 概述

- 三個 `@staticmethod` 方法：`dest()`、`comp()`、`jump()`。
- 輸入：助憶碼字串；輸出：對應的 0/1 位元串（如 `'D'→'010'`）。
- 設計：每個方法都是一張「字典常數 + 馬上查表」——呼叫即回傳，無副作用。
- 地位：與 Hack 指令編碼表（第 4 章表 4.2/4.3）逐欄相符，是整份編碼規格的單一來源。

## 介面與規格

| 方法 | 輸入範圍 | 輸出長度 | 對應 asm.cpp |
|------|----------|----------|--------------|
| `dest(mnemonic)` | `''`, `M`, `D`, `MD`, `A`, `AM`, `AD`, `AMD` | 3 位元 | dMap |
| `comp(mnemonic)` | 18 種**以 A 計算**的 comp | 7 位元 | cMap（A 列） |
| `jump(mnemonic)` | `''`, `JGT`, `JEQ`, `JGE`, `JLT`, `JNE`, `JLE`, `JMP` | 3 位元 | jMap |

### dest 編碼（3 位元）

| dest | 位元 | | dest | 位元 |
|------|------|-|------|------|
| （空） | `000` | | A | `100` |
| M | `001` | | AM | `101` |
| D | `010` | | AD | `110` |
| MD | `011` | | AMD | `111` |

### jump 編碼（3 位元）

| jump | 位元 | | jump | 位元 |
|------|------|-|------|------|
| （空） | `000` | | JLT | `100` |
| JGT | `001` | | JNE | `101` |
| JEQ | `010` | | JLE | `110` |
| JGE | `011` | | JMP | `111` |

### comp 編碼（7 位元）——注意與 asm.cpp 的差異

| comp | 位元 | | comp | 位元 |
|------|------|-|------|------|
| `0` | `0101010` | | `!A` | `0110001` |
| `1` | `0111111` | | `-D` | `0001111` |
| `-1`| `0111010` | | `-A` | `0110011` |
| `D` | `0001100` | | `D+1`| `0011111` |
| `A` | `0110000` | | `A+1`| `0110111` |
| `!D`| `0001101` | | `D-1`| `0001110` |

| comp | 位元 | | comp | 位元 |
|------|------|-|------|------|
| `A-1`| `0110010` | | `D-A`| `0010011` |
| `D+A`| `0000010` | | `A-D`| `0000111` |
| `D&A`| `0000000` | | `D\|A`| `0010101` |

**這個表沒有 `M` 系列**（`M`、`!M`、`D+M`…）：在 C 語言版 `asm.cpp` 的 cMap 中，
那些 `A→M` 的「a 位元切換」被列成獨立的表項；Python 版則保留給練習者自行加入
（把整個表 `A` 的 7 位元最高位改 0→1 即是）。因此本版只能組譯只動 `A` 暫存器的指令，
`asm.py` 的範例 `add` 程式恰好只用 `D=A`、`D=D+A`，完全涵蓋。

## 原理

字典（dict）查表的時間複雜度 $O(1)$，與 `asm.cpp` 的 `std::map` 紅黑樹（$O(\log n)$）
相比更簡潔。整個方法體就是「字面 dict + `[...]` 立即查」：

```python
@staticmethod
def dest(mnemonic):
    return {
        '':   '000',
        'M':  '001',
        'D':  '010',
        ...
    }[mnemonic]
```

`: 之後直接 `[mnemonic]` 查表並回傳，一氣呵成。用的 key 是助憶碼的字面字串，
與 C 版用 `map<string,string>` 的寫法結構相同、語法更短。

`@staticmethod` 讓 `Code.dest('D')` 不必建物件即可呼叫，`asm.py` 用 `code.dest(comp)`
（例項呼叫）也同樣可用——語意上「編碼表格」本來就該是一組純函式。

## 實作細節

檔尾的範例區塊順帶示範三個查表：

```python
if __name__ == '__main__':
    code = Code()
    print(code.dest('D'))   # 010
    print(code.comp('A+1')) # 0110111
    print(code.jump('JGT')) # 001
```

`comp('A+1')→'0110111'` 與 `D+A` 的輸出若再拼上 `'111'` 前綴與別的 dest/jump，
就是一條完整 C 指令——`asm.py` 的 `translate_c_instruction` 正是這樣用它的。

若餵入不存在的助憶碼（如 `comp('X')`），會直接 `KeyError`，因為套用的是原生 dict
而非 `dict.get`——教學版把「錯誤檢查」留給錯誤本身，省一行是一行。

## 延伸討論

- **與 C 版查表的對照**：`Code.dest` ↔ `asm.cpp` 的 `dMap`、`Code.comp` ↔ `cMap`、
  `Code.jump` ↔ `jMap`。唯一分歧是 `comp` 缺 M 系列——補齊的方法是把 `'M'` 等
  8 個 M 系列助憶碼加進字典（位元與 A 系列一樣、最高位改 1），例如
  `'M'  → '1110000'`、`'D+M' → '1000010'`。
- **設計取捨**：用 `staticmethod` 而非普通方法，暗示「無狀態」；若改以常數字典
  模組變數（`DEST = {...}`），`asm.py` 也能直接 `DEST['D']`，兩種風格各有喜好者。
- **本書規格對照**：Hack 的 comp 欄其實是「6 位元 ALU 選擇 + 1 位元 a 開關」；
  這個類別把 a 位元一起編進 7 位元字串，與 Hardware Simulator 的 `.hack` 檔案格式一致。
