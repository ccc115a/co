# hdl2rs v0.3 — 版本紀錄

日期：2026-09-10（115 學年度 · 計算機結構）
對應里程碑：**M3 — 整台電腦核心（ch05 CPU）通過**

## 一句話

本版為 hdl2rs 加上 ch05 CPU 需要的**內建 16-bit 暫存器（`ARegister`/`DRegister`）**、
**`ROM32K`/`Screen`/`Keyboard` 內建型別**、**內部 `PinRef[]` 探測**，以及 `outM`
在 `writeM==0` 時未定義（`*******`）的官方語意——**`05/CPU.tst` 與 `05/CPU-external.tst`
雙雙 PASS**，連同 ch01~ch03 全數回歸維持 **29/29**。

## 目錄（workspace `_eda/`）

無結構變更。

## 本版實作內容

### CPU 的時序模型（先釐清，後實作）

`CPU.cmp` 的 `DRegister[]` 欄位在 `time 1+`（tick 後、tock 前）就顯示 `12345`
（`D=A` 指令取樣當下），表面上與 ch03「tick 取樣、tock 提交」矛盾。逐列對照
`CPU-external.cmp` 之後確認其實**一致**：

- `addressM`（A 暫存器輸出）在 `0+` 是 `0`、`1` 才變 `12345` → A 暫存器仍走
  **tock 提交**（child `q`）。
- 而 `DRegister[]` 內部探測回報的是 **master latch（未提交前的取樣值）**：
  `D=A` 在 tick 邊緣取樣 `ALUout=12345` 進 latch，探測讀 latch 故 tick 後立即可見。
- 結論：內建 `RegChip` 維持 `{ latch, q }`（`eval` 回 `q`、`sample` 依 load 寫
  `latch`、`tock` 提交 `q=latch`），**probe 讀 latch**，兩個 CPU `.tst` 全過。

> 修正先前 v0.2 紀錄中「`CPU.cmp` 有 2 列 artifact」的判斷：那 2 列（`pc@0+`、
> `DRegister[]@time1`）在正確的 latch-probe 模型下完全可推導，並非課程檔案矛盾。

### 內建晶片擴充（hackhdl/elab.rs）

`Builtin` 從 `{ Nand, Dff }` 擴充為：

```rust
enum Builtin { Nand, Dff, ARegister, DRegister, Rom32k, Screen, Keyboard }
```

各內建的 `in_out()` 接腳（`elab.rs:53`）與 `sequential()` 判定同步實作，
`resolve()` 的 child pin 解析直接走 `Builtin::in_out()`，`Screen`（`in/load/address[13]`）
與 `Keyboard`（無輸入）照樣進 library，`Memory.hdl` 可正常 elab。

### generator（hdl2rs/gen.rs）

- `chip_type()` 加五個內建分支：`ARegister|DRegister → RegChip`、
  `Rom32k → Rom32KChip`、`Screen → ScreenChip`、`Keyboard → KeyboardChip`。
- 新內建型別（一律產出，whether 用到）：
  - `RegChip { latch, q }`：與 DFF 同節奏但 16-bit 帶 `load`；`sample` 在
    `load!=0` 時 `latch=in`、`eval` 回 `q`、`tock` 提交 + `probe_whole/probe_bit`。
  - `Rom32KChip { mem: Vec<u16>[32768] }`：**combinational** 讀取
    `mem[address]`，`load(path)` 解析 `.hack` 文字二進位列循序填入。
  - `ScreenChip`（8192×16，`sample` 寫入）、`KeyboardChip`（固定輸出 0），
    v0.3 自動化測試不驅動，但行為完整。
- 每個晶片新增 `probe_whole(name)` / `probe_bit(name, i)`：對比對到
  （Builtin Dff/ARegister/DRegister）的 part label 回傳 latch（Whole）或單一位元；
  沒匹配回 `None`。
- 每個晶片新增 `load_program(path)`：把 `.hack` 轉發給（直接或經 user 子晶片
  遞迴的）`Rom32KChip`。
- **top Wrap**：`get_output(name)` 在匹配不到 top IN/OUT pin 後，以
  `PinRef::parse` 拆 `name[i]`，`Whole→inner.probe_whole`、`Bit→inner.probe_bit`；
  `outM` 在 `writeM==0` 時回 `None`（官方「any value may appear」，顯示 `*******`）；
  實作 `TopModel::load_rom` → `inner.load_program`。

### 格式化（hackrt/fmt.rs）

修正**未定義欄位**的官方行為：先前只把 `*` 填滿 `b` 寬度並保留 `a`/`c` 空白
（`outM%D1.6.0` 得到 ` ******`）；官方是把**整個 `a+b+c` 寬度**填滿 `*`
（`*******`）。此修正讓 86 列 outM mismatch 一次歸零，且不影響 ch01~03（過去沒有
未定義輸出欄位）。

### CLI（hdl2rs/main.rs）

`--test` 改為可**多次指定**（`Vec<String>`）：`test.sh` 同時列
`--test ../05/CPU.tst --test ../05/CPU-external.tst`。

## 本版遇到的坑（處理過程）

1. **outM 未定義寬度**：`%D1.6.0` 的未定義欄位官方填滿整個欄位寬度而非 `b` 寬度，
   86 列全差一格。改 `fmt.rs` 的 `None` 分支直接 `"*".repeat(f.width())`。
2. **probe 必須每層都有**：top Wrap 的 `get_output` 對任何名稱都先回 `None` 就
   不會走 probe；改為 regex 式的 `PinRef` 解析後回 `inner.probe_*`，並讓每個晶片
   都產出 `probe_whole/probe_bit`（沒可探測 part 的回 `None`），全省編譯。
3. **`--test` 單一限制**：50:50 後 `--test` 只能過一個檔；改成可重複參數後
   `test.sh` 一次跑兩份 CPU 測試。
