# v0.7 規劃 — ch12 OS 在 hackemu 上執行

> 狀態：🔲 規劃中（設計文件，未動工）
> 目標里程碑：**M7 — 把 `12/*.jack` 整包 OS 編譯、開機、執行，並在 hackemu 的
> GUI 上跑起需要 OS 的應用程式（例：Pong），可實際玩。**

## 一句話

把 v0.5 的工具鏈（`jack2vm` → `vm2asm` → `hackasm` → `hackemu`）接到課程
第 12 章：先編譯「OS + 應用程式」的 Jack 原始碼，經多檔 bootstrap
（`SP=256` + `call Sys.init 0`）開機，最後在 hackemu GUI / headless 執行。
若成功，`_eda` 這套工具就能跑完 Nand2Tetris 全專案。

## OS 現況盤點（`nand2tetris/12/`）

| 類別 | 行數 | static 數 | 作用 |
|---|---|---|---|
| `Array.jack` | 21 | 0 | `new`/`dispose`（走 Memory.alloc） |
| `Math.jack` | 143 | 1 | 數學運算（新版含 `abs`/`sqrt`…用 iter 逼近） |
| `Memory.jack` | 173 | 6 | `peek/poke/alloc/deAlloc`，freeList 由 **2048** 起 |
| `Output.jack` | 294 | 4 | 文字輸出（256 列螢幕的字元映射） |
| `Screen.jack` | 206 | 6 | `drawPixel/Line/Rectangle/Circle`…直接寫 SCREEN |
| `String.jack` | 156 | 0 | 字串、`intValue` 解析 |
| `Keyboard.jack` | 91 | 1 | `keyPressed/readChar/readLine/readInt` |
| `Sys.jack` | 50 | 0 | `init`（依序 init 各 OS 模組 → `Main.main` → `halt`） |

- 開機順序（`Sys.init`）：`Math.init → Output.init → Screen.init → Keyboard.init
  → Memory.init → Main.main → Sys.halt`。OS 不含 `Main`——**應用程式提供**
  （例：`11/jack/Pong/Main.jack`）。
- `12/*Test/` 子目錄（ArrayTest、MemoryTest…）各含 `Main.jack`，可當「最小測試
  應用程式」：編譯「OS + Test/Main」即可測單一模組。
- **鍵盤碼已對齊**：`Keyboard.jack` 註解的行為鍵碼（128 newline、129 backspace、
  130–133 方向、…141–152 F1–F12）與 hackemu 的 `KEY_*` 常數**逐字相同**（v0.6
  設計時便以 ch12 OS 規格為準）——為 v0.7 埋伏筆，現可交叉驗證。

## 執行鏈路

```
12/*.jack ──jack2vm──▶ *.vm（8 檔 OS）       11/jack/Pong/*.jack ──jack2vm──▶ *.vm
      └──────────────────────────┬──────────────────────────┘
                      vm2asm（多檔，bootstrap call Sys.init 0）
                                    │
                                    ▼
                                  app.asm
                                    │  hackasm --bin
                                    ▼
                                  app.bin ──hackemu──▶ GUI（Pong 可玩）/ headless
```

注意事項：

- `jack2vm` dir 模式**只收頂層 `*.jack`**（不遞迴），`12/` 下的 Test 子目錄
  不會被誤編，正好拿「OS 目錄」與「應用程式目錄」分開編譯。
- `vm2asm` 傳入所有 `.vm`（OS + app）→ **超過一個檔自動加 bootstrap**；
  `Sys.vm` 必須在輸入清單內（`call Sys.init 0` 的定義來源）。
- static 變數：OS 每檔只有 1–6 個，依檔名排序配到 RAM[16] 起，與
  Memory heap（2048 起）之間的餘裕超過 1700 words，綽綽有餘。

## 待解問題 / 設計決策

1. **螢幕方向**：若 Pong 的 `drawRect` 左右與預期相反，把 hackemu 畫素慣例
   `1 << (15 - col % 16)` 換成 `1 << (col % 16)`（作業 # 保守：先與官方
   模擬器對照後再動）。屆時單位測試同步調整。
2. **`Sys.wait` 忙迴圈**：`wait(50)` 約 1 萬條指令；Pong 每幀多次 → 建議 GUI
   Speed 開到上限，或 v0.7.1 對 `Sys.wait` 特判（選做，不建議——維持真硬體語意）。
3. **KBD 讀取語意**：`Keyboard.readChar` 等「按下→放開」的完整循環，hackemu
   的 `set_key(0)` 清空已處理；GUI 的 pressed 集合即可對應，無需改核心。
   唯一要小心：GUI 目前放開鍵才清 KBD，`keyPressed` 在按住期間一直讀到
   keycode——與 OS 期待的「按下時讀碼」相符。
4. **多檔 byte 相容**：OS 8 檔皆與 C 版 oracle 比對（單檔模式逐支）。這些檔案
   用了 vs 11/jack 更多的 feature（大型 String 操作、巢狀迴圈、指標運算），
   是 jack2vm 的天然壓力測試。
5. **`Memory.loadBin`（選做）**：讓 hdl2rs 的 Computer 也能直接 load `.bin`，
   補齊 v0.5/0.6 一直掛著的待辦；若做，驗收為「同一支 Pong 在 hdl2rs 與
   hackemu 上 RAM/SCREEN 一致」。
