# v0.9 — 網頁版 HDL 模擬器（批次跑完秀表格）［規劃＋實作紀錄］

> 狀態：✅ **已完成（2026-09-12）** — `bash verify.sh`／`bash test.sh` 的 v0.9 區段全綠。
> 目標：讓瀏覽器也能模擬 **HackHDL 晶片** — 選一章節晶片（或貼自訂 `.hdl`＋`.tst`），
> 伺服器以**真 hdl2rs 管線**（codegen → cargo build → 子程序跑官方 `.tst`）把結果呈現給使用者檢視。
> 延續 v0.8 的「Rust 伺服器 + 瀏覽器薄前端」路線，改動集中在拉 `hackserve` 與新頁面 `hdl.html`。

## 一句話

v0.8 讓網頁能跑 `.asm`；v0.9 讓網頁也能跑 `.hdl`。使用者選一章節晶片（01–05）或貼上自訂
`.hdl`＋`.tst`（可加 `.cmp`），點「執行」→ 伺服器走 **hdl2rs 原始管線**：
`.hdl ▸ hackhdl parse/elab ▸ hdl2rs codegen ▸ cargo build ▸ 子程序跑 .tst`（exit 0＝PASS）。
`.out` 由模擬子程序寫在暫存目錄，伺服器讀回後回傳給前端，**批次跑完秀表格**。

## 決策重點（已與老師確認）

1. **執行引擎：真 hdl2rs codegen＋cargo**（不另寫進程內直譯器）。
   明知每次執行要花數秒孵 crate＋編譯，但最大化忠於現有工具鏈，零語意分歧風險。
2. **互動模型：只要批次跑完秀表格**（不做 set/eval/tick/tock 單步）。
3. **晶片來源：內建章節語料 ＋ 自訂貼上**兩者都要。
4. **前端放置：獨立 `hdl.html`**，現有 `index.html`（asm 版）不動，header 加切換連結。

## 架構

```
瀏覽器（_eda/web/hdl.html + hdl.js）                Rust 伺服器（_eda/hackserve/)
┌───────────────────────────────┐   WS   ┌────────────────────────────────────────┐
│ 章節/晶片下拉（hdl-list）       │────────▶│  axum /ws（沿用 v0.8 session 模型＋      │
│ 或自訂 .hdl/.tst/.cmp 貼上     │   JSON  │   hdlMode）                              │
│ PASS/FAIL 橫幅 + .out 表格     │◀───────│  spawn hdl2rs ──▶ gen crate ──▶ cargo    │
└───────────────────────────────┘        │  build ──▶ <Top>_sim <tmp>/<Top>.tst      │
                                         └────────────────────────────────────────┘
```

- 伺服器 **spawn 已建好的 `hdl2rs` 二元檔**（`target/{debug,release}/hdl2rs`），原樣重用
  `run_one` 邏輯（`--dir` + `--test <檔>.tst` + `--out <tmp>/gen`），**不改 hdl2rs 本體**。
- 章節語料的 `.hdl/.cmp` **留在 repo 唯讀**；只把 `Top.tst`＋`Top.cmp` 複製到每次執行的
  **暫存目錄 `<tmp>/run<id>/`**，避免覆寫已 commit 的 `.out`、弄髒 git 樹。
- 自訂貼上：`<Name>.hdl`、`<Name>.tst` 寫進暫存目錄；有 compare 文字則同時寫 `<Name>.cmp`
  並把 `.tst` 的 `compare-to` 改指該檔（沒有則移除 compare-to＝只看輸出）。
- 全域**單一執行 mutex**（防並發 cargo lock 打架）；起服務前自動 `cargo build -p hdl2rs`
  補建。
- **不做**：進程內直譯器、逐行單步、多檔自訂。預設 debug 產出；長測可送 `release:true`。

## 協定（JSON over WS，延用 v0.8 的 `req/snapshot` 框架，已實作）

| 方向 | 訊息 | 內容/回應 |
|---|---|---|
| c→s | `hdl-list` | 掃 `../01..05/` → 回 `hdl-list{ chapters:[{name, cases:[{case, top, hasCompare}]}] }`。`name` 例 `01`/`03/a`；`case`＝主檔名（`ALU`）；`top`＝`.tst` 的 load 檔名（`ALU`）；`hasCompare`＝`.tst` 有 `compare-to` |
| c→s | `hdl-source{chapter, case}` | 回 `hdl-source{chapter, case, top, hdl, tst, cmp}`，前端作唯讀預覽 |
| c→s | `hdl-run{ chapter, case }`｜`{ hdl, tst, cmp?, top? }` | 找語料或寫暫存 → spawn hdl2rs → 回 `hdl-result{ ok, pass, out, lines, error? }`。`lines`＝`.out` 資料列數；`top` 可省略（自訂時伺服器從 `load X.hdl` 自行挑） |

- 語料優先序：`chapter+case` 內建路徑 → 直接伺服器讀 file（不經前端傳內容）；`hdl+tst` 為自訂貼上。
- `.out` 的 `pass` 語意（三態）：
  1. 模擬子程序 exit 0 → **跑完且與 `.cmp` 一致**＝`ok:true, pass:true`；
  2. exit ≠ 0 但 `.out` 存在 → **跑完、比對不符**＝`ok:true, pass:false`，`error`＝模擬器 stderr 尾部（含差異處）；
  3. exit ≠ 0 且無 `.out` → **elab/編譯錯誤**＝`ok:false`，`error`＝錯誤摘要。
  `cmp` 未提供時無 compare、`pass` 恆 true（立場＝「至少跑完」）。
- 前端批次執行**沒有回撥**；執行中右上 status 顯示「編譯中（數秒）…」，單一 `req` 等回覆。

## 前端畫面（仿官方 HardwareSimulator 的結果檢視，但批次式）

- **header**：回到組語模擬器的連結；執行中狀態。
- **左｜來源**：兩模式切換
  - 「章節晶片」：章節下拉（01…05）→ 晶片下拉（由 `hdl-list` 填，顯示 top + 是否有 compare）；
    附 `.hdl`／`.tst` 內容預覽（唯讀）。
  - 「自訂貼上」：三格 textarea＝`.hdl`、`.tst`、`.cmp`（後者可留空＝不比較）。
- **右｜結果**：PASS/FAIL 橫幅 → `.out` 表格化顯示（首列表頭＋資料列，直接拆
  `| a | b | out |` 分隔行重排成 `<table>`）；下方錯誤區（parse/elab 錯誤、`error` 訊息）。
- 無法單步；「執行」一次跑完整支 `.tst`。

## 風險與取捨

- **每次執行 = 一次 cargo build（數秒）**：教學單人互動可接受；後續優化（選做）＝按
  `(章節,top,內容 hash)` 快取產出 crate，重複 chip 免重編。
- **並發**：全域單一 mutex 序列化執行；lock 檔的細節由 cargo 自己擋，我們再加一道保險。
- **自訂貼上依賴章節晶片**：`--dir` 順序＝暫存目錄**後放**再補 01–05 章節目錄，讓自訂檔可
  引用 `Mux16` 等既有晶片（合併順序實作時確認 merge 優先權）。
- **不做多檔自訂**：v0.9 自訂只支援單一 `.hdl` top；要嵌多檔請改用章節語料或直接貼合併檔。
- 不引 DB/auth/多租戶；`hdl2rs` 本體零改動，未來若要直譯器也只是「另起一行」，不衝突。

### 踩到的坑

1. **`hdl-list` 回 id=0 導致前端 timeout**：`session()` 的 hdl-list 分支用
   `reply(&hdl::list_corpus(), 0)`，client waiter 依 `m.id`（從 1 起）查找永遠找不到 →
   20s timeout。改成帶 `v["id"]` 即解。
2. **自訂 `.tst` 的 directive 必須在指令之前**：原本把 `compare-to`/`output-file` **附在
   檔尾**，`hackrt::parse_script` 進入 `parse_seq` 後不再認得 directive →
   「無法辨識的指令：compare-to」。改為 `insert_str(0, …)` **前置插入**即解
   （官方 `.tst` 都是 directive 全置頂）。
3. **手寫自訂測試範例算錯**：第一個自訂測試寫 `Nand(a=a,b=a);`（NOT）卻預期它做對稱兩輸入，
   模擬器輸出其實正確。改用 `Nand(a=a,b=b)→Nand(n,n)` 的 AND 並配上正確 `.cmp`。
4. **`target/debug/{jack2vm,vm2asm,hackasm,hackemu}` 失蹤**：`cargo test -q` 不會把這些
   bin 留在 `target/debug`，verify.sh 中途 `No such file or directory`。在 verify.sh 補
   一行 `cargo build -q -p …` 顯式建四支工具。
5. **`top_of` 誤用 `?`**：`?` 讓「首個非 load 行」直接被當成失敗；改 for 迴圈累積搜尋。

### 已知限制（承接「風險與取捨」）

- 每次 `hdl-run` 都重新 codegen＋cargo build（debug 數秒；Computer 用 debug 較久，前端
  未暴露 release 選項，長測走 WS 送 `release:true`）。
- 自訂只支援單一 `.hdl`；16-bit 展寬語法（給 `A` 算 `out[0..8]` 這種寬度推導）由 hdl2rs
  原樣支援、伺服器不做額外魔法。
