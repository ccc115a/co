# v1.0 — 網頁版 Jack 全鏈路（.jack → .vm → .asm → HACK → Emulator 執行）

> 狀態：✅ **已實作完成**（後端＋前端＋文件；見文末「實作結果」）
> 範圍限定：**只動網頁版**（`hackserve` ＋ `web/`）。工具鏈引擎與既有 CLI 一律不動。
> 目標：瀏覽器一鍵把 Jack 程式編譯到底並執行 —
> `.jack ▸ jack2vm ▸ .vm ▸ vm2asm ▸ .asm ▸ hackasm ▸ .hack/.bin ▸ hackemu`，
> 每一階段的產物與輸出都能**展開查看**，讓使用者清楚看到編譯/組譯過程的每一道中間結果。

## 一句話

v0.8 網頁能跑 `.asm`、v0.9 能跑 `.hdl`；v1.0 讓網頁也能跑 **`.jack`**。
新增第三張網頁 `jack.html`：選一章節程式或貼上自訂 Jack → 點「編譯並執行」→
`hackserve` 把既有 CLI 當黑板子程序串成管線（`jack2vm → vm2asm → hackasm → hackemu`），
逐階段抓回產物（`.vm`／`.asm`／`.hack`／執行軌跡），前端以**階段側欄**展開顯示。

> 理由：v1.0 的改動本質是「把既有的四支 CLI 當子程序，再接一條網頁消費者管線」，屬於
> `hackserve`＋前端的外層工作，不碰任何引擎；若要改引擎那是後面版本的事。

## 現有零件（全部直接重用，照現有參數呼叫）

- `target/{debug,release}/jack2vm`：`-o <outdir> <file.jack|dir>`（目錄收集 `*.jack`，只看後綴、不吃 `.jack.md`）。
- `target/{debug,release}/vm2asm`：`vm2asm <output.asm> <file1.vm|dir> [file2.vm …]`。
- `target/{debug,release}/hackasm`：`hackasm <in.asm> [out.hack] [--bin]`。
- `target/{debug,release}/hackemu`：`--headless <bin> --max <N>`；輸出 `before/after PC A D SP`、`RAM[0..16]`、`RAM[N] static`。
- 語料：
  - `../11/jack/`：`Average`、`ComplexArrays`、`ConvertToBin`、`Pong`、`Seven`、`Square`（各含 `Main.jack`＋`.md` 伴讀）。**全部 `needsOS=true`**（用 `Output`/`Screen`/`Keyboard`/`Math` 等）。
  - `../11/jackNoOs/`：無 OS 案例 `Sum`、`Factorial`、`Fib`、`GCD`、`PrimeUnder100`（各含自帶 `Sys.jack`），**`needsOS=false`**（前端標「無 OS」）；`list` 回應帶 `noOS:true`。
  - `_eda/gen/os_src/`：**裁剪版 OS**（Array、Keyboard、Math、Memory、Output、Screen、String、Sys）＝ `withOS` 時併入編譯。
  - `_eda/gen/chain/`：虛擬 e2e 入口（自帶 `Main.jack`+`Sys.jack`，`needsOS=false`）＝既有 oracle `RAM[16] static = 5`。

## 架構

```
瀏覽器（_eda/web/jack.html + jack.js）                 Rust 伺服器（_eda/hackserve/）
┌───────────────────────────────┐   WS   ┌──────────────────────────────────────────┐
│ 程式/自訂多檔來源（jack-list） │────────▶│ /ws session 新增 jack 分支（async）        │
│ PASS/FAIL 橫幅 + 階段側欄      │◀───────│ 子程序管線（暫存目錄 run-<n>/, 單一 mutex） │
│ Jack ▸ VM ▸ ASM ▸ HACK ▸ SIM  │        │  spawn 既有 jack2vm/vm2asm/hackasm/hackemu │
└───────────────────────────────┘        └──────────────────────────────────────────┘
```

- 全域**單一執行 mutex**（`jack.rs` 內自帶一把 `RUN_LOCK`，限定同一 WS 管線內部）；暫存目錄沿用
  `<tmp>/hackeda-v1x-<pid>/run-<n>/`（`HACKEDA_KEEP_TMP` debug 開關），不弄髒 git 樹。
- 每階段抓回：exit code、stderr、**產物檔案清單與內容**；任一段失敗即停，該段 stderr 標紅為 `error`。

### 子程序管線（`jack.rs` 內，時序）

1. 建立暫存 `run-<n>/src/`。
2. 準備輸入：
   - 內建：直接以選定程式目錄（或單檔）為 jack2vm 輸入；`needsOS=true` → 把 `gen/os_src/*.jack` 併入同一 src 目錄。
   - 自訂：把 `files`（檔名＋內容）寫進 `src/`；`withOS=true` → 併入 `gen/os_src`。
3. `jack2vm -o run/vm run/src/<程式檔案或目錄>`。
4. `vm2asm run/out.asm run/vm/**/*.vm`（有 OS 時其 vm 排在前，處理順序＝對 `.vm` 檔名排序；與 v0.7 `show` 流程一致）。
5. `hackasm run/out.asm run/out.hack` 與 `hackasm run/out.asm run/out.bin --bin`。
6. `hackemu --headless run/out.bin --max <預設 5e6>` → `run/sim.txt`。
7. 截斷：單一產物 >400 行只留首尾 200＋「…（共 M 行）」；stderr 截 1200 字。

### SIM 摘要（`sim.summary`）

從 `hackemu --headless` 的 stdout 尾部取 12 行（`after/before: PC=… A=… D=… SP=…`、
`RAM[0..16]: […]`、`RAM[16] static: …`）放 `sim.summary`，完整軌跡放 `sim.trace`。

## 協定（JSON over WS，延用 v0.8/v0.9 的 `req` 框架）

| 方向 | 訊息 | 內容/回應 |
|---|---|---|
| c→s | `jack-list` | 回 `jack-list{ programs:[{name, files:[…], needsOS, isVirtual}] }` |
| c→s | `jack-source{program}` | 回 `jack-source{program, files:[{name, content}]}`（前端逐檔唯讀預覽） |
| c→s | `jack-run{program}`｜`jack-run{files:[{name, content}], withOS}` | 跑管線 → 回 `jack-result{ ok, stages:[{name, cmd, exit, stderr, artifacts:[{name, content}]}], sim:{summary, trace}, error? }` |

- 自訂入口：至少含 `Main.jack`，否則直接報錯；`needsOS`/`withOS` 的 OS＝`gen/os_src`（固定裁剪版）。
- 內建程式的 `isVirtual`＝非教材目錄的合成入口（目前只有 `chain`）。

## 前端畫面（`jack.html`）

- **header**：回 `index.html`／`hdl.html` 的導流連結；執行狀態。
- **左｜來源**：
  - 「內建程式」：程式下拉（依 `jack-list`，標示 `needsOS`／`isVirtual`）；選後逐檔唯讀預覽（`jack-source`）。
  - 「自訂貼上」：檔名 tabs（可新增，檔名輸入框可改）+ 單一編輯區；勾選「含作業系統」＝併入裁剪版 OS。
- **右｜結果**：「完成／失敗」狀態 → **階段側欄** `jack ▸ vm ▸ asm ▸ hack ▸ sim`，
  點選階段展開該段產物（jack 原始檔、VM 逐檔、ASM、HACK、sim 摘要/軌跡）；任一段 exit≠0 標紅 ✗。
- 不做單步；「編譯＋執行」一次跑完整條管線。

## 驗收 / 回歸（限定網頁版，不動既有腳本）

- `cargo test -q -p hackserve`（含新增 `jack.rs` 單元測）。
- WS 冒煙測（起 `hackserve` → node 直連）：
  1. `jack-list` 回 ≥6 支程式，含 `Seven`（`needsOS=true`）與 `chain`（`isVirtual=true`, `needsOS=false`）；
  2. `jack-run Seven`（inner 決定 withOS）→ 各階段 exit=0，`.vm` 產物數 >0、`.asm`/`.hack` 非空、`sim.summary` 含 `RAM[16]`；
  3. `jack-run chain` → `RAM[16] static = 5`（既有 oracle）；
  4. 自訂壞 Jack（語法錯）→ `ok:false`＋錯誤訊息；
  5. 自訂單檔 `Main.jack`（withOS）→ 跑完、SIM 有摘要。
- 人工：瀏覽器開 `jack.html` 選 `Pong` 開箱、逐步展開各階段看產物。
- **不進 `verify.sh`/`test.sh`**（既有回歸保持不動）。

## 實作結果（2026-09 收尾）

- **後端**：`hackserve/src/jack.rs`（新）＋`main.rs` 分派（`jack-list`/`jack-source`/`jack-run`，async）。
  語料表 `JACK_PROGRAMS`（6 支教材程式，全 `needsOS=true`）＋ `JACK_NOOS_PROGRAMS`
  （`11/jackNoOs` 的 5 支無 OS 案例，`noOS:true`）＋ `VIRTUAL_PROGRAMS`（chain，`false`）；
  OS 語料 `gen/os_src`；VM 排序 `OS_VM_NAMES` 排前再 app。
- **前端**：`web/jack.html`＋`jack.js`＋`style.css` v1.0 區段；`index.html`/`hdl.html` header 互導。
- **驗證**（全部通過）：
  - `cargo test -q -p hackserve` → **11 passed**（含 4 個新單元測：檔名過濾、語料清單、VM 排序、截斷）。
  - WS 冒煙（node 直連 `hackserve --port 8092`）：
    - `jack-list` → 7 支程式，`Seven{os:true}`…`chain{isVirtual:true, os:false}` 正確；
    - `jack-run Seven` → 4 階段 exit=0、`.vm`/`.asm`/`.hack` 產物非空、`sim.summary` 含 RAM；
    - `jack-run chain` → **`RAM[16] static: 5`**（e2e oracle 達成）；
    - 自訂 `Main.jack`＋withOS → 跑完；自訂壞 Jack → `ok:false` 且 `jack` 階段 exit=101 帶編譯器錯誤。
- **踩坑記錄**：
  - `jack.rs` 初版誤把思考草稿（含非 Rust 的假 snippet）寫進檔尾，編譯 72 errors → 整檔重寫修正。
  - `spawn(&mut Command)` 把借用送進 `spawn_blocking` 逃逸（E0521）；改用「owned `mut Command` 傳值」。
  - closure 內 `std::fs::…?` 的 `io::Error→String` 轉換（E0277）：改 `.map_err`。
  - 冒煙一度卡「未知訊息型別：jack-list」＝ target/debug 主二元檔是舊版（只跑過 `cargo test` 未 rebuild）；
    需 `cargo build -p hackserve` 正式建出後重起 server。
  - Node 端 `node:ws` 不可用，改 Node ≥22 內建全域 `WebSocket`；`ws.on` 不存在，用 `addEventListener`。
  - server 初次連不上＝環境殘留舊 hackserve 佔 8080，`pkill` 後再以 `--port 8092` 重起。

## 風險與取捨

- **SIM 軌跡可能巨量**：首尾＋摘要保留、中間截斷並標明總行數。
- **多檔自訂貼上 UX** 最花工：先做「檔名＋內容」每檔一格。
- **`needsOS` 依賴程式內容**：目前教材六支全 `true`、`chain` 為 `false`，用對照表常數（可調）；跑掛時以第二段（jack2vm）錯誤呈現。
- **入口 `Sys.init`**：OS 提供；無 OS 且無 `Sys` 的單檔程式依 `vm2asm` 現有行為執行（引擎不動、不特判）。
- 不改引擎/CLI，因此所有產物格式就是既有工具的真實輸出，跟 CLI 跑出來的結果一致（本身就是 oracle）。
