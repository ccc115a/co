## 一句話

`hackemu` 目前只有原生視窗（egui/eframe）。v0.8 把「模擬引擎」留在 Rust（效能全速），
前端換成瀏覽器薄客戶端，用 **WebSocket** 溝通：`assemble(asm)` → 組譯 → `simulate(steps)`
→ 回傳暫存器與螢幕變動 → Canvas 繪圖。學生**點網址就能玩，免安裝、免編譯**。

## 架構

```
瀏覽器（_eda/web/）                        Rust 伺服器（_eda/hackserve/）
┌───────────────────────────┐  WS  ┌──────────────────────────────────────┐
│ ASM editor + 載入 .asm     │─────▶│ axum + tower-http（靜態 + /ws）        │
│ Screen canvas (512×256)    │◀────│  每連線一個獨立 Vm（hackemu::Vm）        │
│ Inspector（暫存器/RAM/KBD） │ JSON │  hackasm::assemble ───▶ ROM words       │
│ 鍵盤 → scancode            │      │  每幀跑 N 條指令 → snapshot（螢幕 delta）│
└───────────────────────────┘      └──────────────────────────────────────┘
```

- 新 crate `hackserve/`（加入 `_eda/Cargo.toml` workspace members）：`axum`（路由/WebSocket）+
  `tower-http`（靜態檔）+ `serde/serde_json`（協定）。模擬與組譯直接吃既有 lib：
  - `hackasm::assemble(&str) -> Result<Vec<u16>, String>`（組譯）
  - `hackemu::Vm`（`load_bin` / `reset` / `step` / `run` / `set_key`，欄位 `pc/a/d/ram` 皆 pub）
- 前端 `_eda/web/`：純 HTML/JS/Canvas，**無框架、無 build step**（開檔即可伺服）。
- **零模擬邏輯分支**：egui 版、headless CLI、網頁版共用同一顆 `hackemu`/`hackasm` lib。

## 互動模型

沿用現 egui 版「每視覺幀跑 N 條指令」的模型，但**前端當節拍器**：

1. 前端 rAF/setInterval 迴圈 → 送 `simulate{ steps }`
2. 伺服器跑 N 條 → 回 `snapshot{ pc, a, d, sp, screenDelta, halted, error }`
3. 前端繪製螢幕差量、更新暫存器。

- **Speed 滑桿 = 每幀步數 N**（log 刻度，仿原生版 0..=10M）。
- Run/Pause = 起停節拍迴圈；Step = `simulate{1}`；Reset = `load`（或重新注入原 ROM）。
- LAN 上每次往返 <1ms 無感；WAN 靠加大 N / 降頻緩解，協定不變。

## 協定（JSON over WS；螢幕差量以 base64 包在 JSON rows 裡）

| 方向 | 訊息 | 內容/回應 |
|---|---|---|
| c→s | `assemble{ asm }` | 回 `asm-result{ ok, words, lines }`；錯誤回 `error` 字串 |
| c→s | `load{ asm }` | 組譯 + `reset()` + 燒 ROM（SP=256、PC=0）；回 `loaded{ ok, rom, lines, map[] }`（map：第 i 個 asm 行 → ROM word，None=註解/標籤） |
| c→s | `simulate{ steps }` | VM 跑 N 條，回 `snapshot{ pc,a,d,sp,cycles,halted,kbd,lines,regs[0..16],rows[] }` |
| c→s | `step` / `reset` | 快捷（reset 的 snapshot 帶 `reset:true`，前端清畫面） |
| c→s | `setKey{ code, down }` | 寫 RAM[KBD_ADDR]（沿用 egui 版的 egui Key→HACK 碼對映）；**不回包** |
| c→s | `ramDump{ start, len }` | 回 `ramDump{ start, data[] }`（檢視用，不干擾 VM） |

- **螢幕傳輸**：每列一個 u32 版本號（gen）；伺服器只送「與上一幀不同」的列，每列 32 word
  → 64 bytes 大端序 → base64。整幀也不過 ~16KB。
- 前端在此之上畫 Canvas（Nearest 縮放）、維護差異。

## 前端畫面（仿官方 CPU Emulator）

- **左｜ASM editor**：可貼上/載入 `.asm` 檔案；行號、組譯錯誤標記、
  **PC 高亮目前執行列**（.asm 一行 = ROM 一 word，地址可直接對行）。
- **中｜Screen canvas + 控制列**：Run / Pause / Step / Reset、Speed log 滑桿、FPS 顯示；
  半透明 overlay 疊出螢幕範圍（對照 SCREEN 16384–24575）。
- **右｜Inspector**：
  - 暫存器：PC、A、D、SP、static 區摘要（RAM[16..]）
  - 記憶體分頁：R0–R15、static 16–255、stack 256+、heap 2048+（**每秒降頻刷新**防閃爍）
  - KBD 24576 狀態、終端機輸出區（`Keyboard.readChar` 等）
- **鍵盤**：頁面聚焦 → keydown/keyup → scancode → `setKey`（持 last-held 語意）。

## 驗收 / 回歸

- verify.sh 增「v0.8」區段（WS 自動化）：`assemble` 官方 `.asm` 語料 → `simulate` N 步 →
  驗 PC 落點/螢幕字組/`halted`，與 CLI 版結果交叉一致。
- 人工：瀏覽器載入 .asm 即玩、暫存器/記憶體/螢幕三窗即時同步。

## 風險與取捨

- **WS 每幀往返**：LAN <1ms 無感；WAN 調 N/降頻，協定不擴展。
- **記憶體檢視**：只顯示、不干擾 stack/heap 語意（VM 狀態仍在伺服端單執行緒進化）。
- 不做 pixel 級 diff 演算法（螢幕二進位：整幀 ~16KB 已夠小）。
- 不引 DB/auth/多租戶——教學單進程，每 WS session 一個獨立 `Vm`。
