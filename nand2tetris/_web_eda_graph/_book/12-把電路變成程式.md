# 12 把電路變成程式：程式碼產生

## 用法

[`codegen.js`](../lib/hdl/codegen.js) 的 `generateJs` 吃 [11 章](11-從接線圖到執行順序.md)
的詳述結果，吐出**自足的 JavaScript 原始碼**（內建零件的行為一起產生，不依賴外部檔案）：`new Function` 載入即跑，或 `--keep` 存成 ESM 慢慢研究。
沿用 [`Not.hdl`](../third_party/courses/01/Not.hdl)，`generateJs` 吐出 93 行，
其中 `NotChip.eval` 全文如下（真實產物，一字未改）：

```js
  eval(in_) {
    let w_out = 0;
    // 定點收斂：依拓樸序反覆求值直到所有 wire 穩定
    for (let __it = 0; __it < 9; __it++) {
      const s0 = w_out;
      { // part 0: Nand (NandChip)
        let __i0 = ((in_ >> 0) & 0x1);
        let __i1 = ((in_ >> 0) & 0x1);
        const __o = this._p0.eval(__i0, __i1);
        w_out = setBits(w_out, 0, 1, ((__o.out >> 0) & 0x1));
      }
      if (w_out === s0) break;
    }
    return {
      out: w_out,
    };
  }
```

## 完整範例：對照著看，每個設計決策都找得到

- 局部 wire（`w_out`）是函式內的區域變數，不是物件屬性。
- 零件按 elab 排好的拓樸序求值（這裡只有 part 0）。
- `((in_ >> 0) & 0x1)` 是取位元的通用寫法（bus 切片都長這樣，只是換數字）。
- `setBits` 把零件輸出合併進目標 wire（多連線湊一條 bus 就靠它）。
- 最外層 `for` 是**定點收斂**：同一個順序重算到 wire 都不變就停
  （這裡上限 9 遍，純前向電路第一遍就停；這層保險讓複雜接線也不會讀到半成品）。
- `in_` 底線後綴：HDL 的 `in` 在 JS 是保留字，產生碼時改名
  （`san`／`pinSan` 就管這個）。

## 原理：三相時序與內建行為

真實時脈分兩半，產生碼也一樣（[`TopModel`](../lib/rt/model.js) 照此驅動）：

- `eval`：純組合求值——輸入進來、輸出出去，無記憶（上面就是）。
- `sample`（tick，前半拍）：有狀態零件（DFF、暫存器、RAM、RF32）
  把「現在看到的輸入」記下來，但輸出還維持舊值。
- `tock`（後半拍）：把記下來的東西正式提交（`DFF.q = latch`、
  `RAM32W` 寫入），輸出更新。

`tick, tock` 配成一對就是一個時脈周期；純組合電路用 `eval` 一次就算完。
這就是模擬跑得快的原因：接線和順序在編譯期（elab＋codegen）全算死了，
執行期零查表。

內建零件不用 HDL 寫，直接是程式：`DffChip` 用 `latch`／`q` 雙變數，
`tock` 才同步；`RAM32W` 兩相寫入，讀寫同一周期不打架就靠這個；
`Rf32Chip` 讀 0 號永遠回 0、寫 0 號直接丟掉（RISC-V 的 x0 硬接 0
就是這樣來的）；`Rom32KChip`／`Rom32WChip` 的 `load(檔名)` 先經
`HACKJS_FS` 找檔（命令列是真檔案，瀏覽器是語料 map），再逐行把
`0/1` 字串轉數字灌進陣列。

## 探測：`.tst` 怎麼看到電路內部

完整產物在 `eval` 之外還有 `probe_whole`／`probe_indexed(name,i)`／
`probe_width`／`set_whole`／`set_probe`：層層比對 part 標籤
（含 `SCREEN`／`KBD` 別名）再往子零件遞迴。`.tst` 裡的 `RAM16K[0]`、
`PC[]`、`Screen[..]` 全靠這套；沒有它，測試只能看到最外層腳位。
