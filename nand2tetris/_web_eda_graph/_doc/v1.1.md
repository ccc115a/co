# hdl2js v1.1 — 版本紀錄

日期：2026-09-13（115 學年度 · 計算機結構）
對應里程碑：**M11（選做解鎖）— Jack 全鏈路 ⇄ 組語 Emulator 橋接：編譯結果一鍵送進 Emulator 互動執行**

## 一句話

`jack.html` 編譯出來的 `.asm` 現在可以一鍵直送 `index.html` 的組語 Emulator：新視窗
自動載入、自動開跑，原本只能 headless 印 RAM dump 的 Pong 終於可以用 ←/→ 在瀏覽器裡
**真的玩**，球的軌跡、暫存器、RAM、SCREEN 全部即時可觀察。同時修掉兩個讓「看不到結果」
的 bug（內建程式漏帶 OS、HACK 組語沒寫回文字區），並把整條跨視窗通訊在真 Chrome 上驗證過。

## 本版實作內容（跨視窗橋接，file:// 免 server）

- **協議**（三種 message，全部 `postMessage(…, '*')`）：
  - `hackjs-ready`：Emulator 子視窗 init 完成後 `window.opener.postMessage` 通知父端。
  - `hackjs-load`：父端把 `{ asm: <一整串組語> }` 送進子視窗。
  - `hackjs-ping`：父端定時探活，子視窗收到就重發 `ready`（讓「復用舊視窗」也能對上）。
- **jack.html** 加「在組語 Emulator 跑 ▸」按鈕：若還沒編譯過會先自動「編譯＋執行」，
  再 `window.open('index.html')`。收 `ready` 就送 asm；子視窗關了就重開。
- **自救機制**：父端每 250ms ping，3.75 秒無回應就把子視窗帶新參數
  （`location.href = 'index.html?er=<ts>'`）強制重載一次，再無回應則在 status 提示
  手動 ⌘⇧R。因為 file:// 的舊快取是「一直載入失敗」的元兇。
- **index.html（dist/app.js）**：收 `hackjs-load` → `el.ta.value = asm`（寫回文字區）、
  `load(asm)`（組譯＋載入 VM）、自動開跑（可暫停）、`console.log('[hackjs] …')` 提示。
  鍵盤 ←/→/↑/↓ 維持原有對映（用 `keyname` 直接用即可，`held[]` 多鍵也有）。

## 修掉的 bug

- **內建程式漏帶 OS（畫面直條的元兇）**：`compileAll` 原本只在「custom 模式＋勾 OS」時
  才把 `gen/os_src` 排進 vmFiles；內建 Pong 等 needsOS 程式於是完全沒有 `Sys.init`
  bootstrap，PC 從垃圾位址開跑、滿屏亂塗成直條。改為「只要 withOS 勾選就帶 OS」
  （內建模式下 withOS 自動鎖定為 needsOS）。這個 bug 是 **UI 路徑**問題——
  `browser_jack_smoke.js` 測的是 library 路徑（OS 固定帶入），所以 12/12 全綠抓不到。
- **HACK 組語沒寫回文字區**：先前收到 `hackjs-load` 只 `load()` 組譯，不填 textarea，
  使用者看到「只有 PC 高亮有內容，程式沒進來」。

## 配套工程

- **cache-bust**：三頁的 `<script src>` 全部加 `?v=2`（corpus/hdl-rt/embed/hdl/jack/app），
  之後任何檔案改版、瀏覽器重載就必然拿到新版（不是吃舊快取，正是本版踩過的坑）。
  `verify.sh`/`test.sh` 對 `src="embed.js"`/`src="app.js"` 的 grep 同步放寬為容許版本參數。
- **改名配套**：目錄 `_html/→_web_eda/`、`_eda/→_rust_eda/` 後，把「可動作路徑」全部改新名——
  AGENTS.md、章節/子專案 README、`getting_started.md`、兩份 plan.md、`package.json`
  描述、以及 `test/test.js:550` 硬編的 `_html/dist/embed.js`（這處正是改名後唯一跑掛的單元測試）。
  歷史 `_doc/vN.md` 與 code 註解保留舊名不改。

## 已知限制

- 子視窗若吃舊版 `app.js`（無 message 監聽）會一直收不到；已靠 `?v=2`＋強制重載自救，
  仍無回應就手動對該視窗 ⌘⇧R。
- Playwright 對 file:// popup 的視窗追蹤有 bug（`ctx.pages` 抓不到子視窗），但 parent-log
  確認 ready/load 已交換；驗證用 iframe 直送同一接收路徑補足。

## v1.1 追補：第五章 Memory 上網頁批次（05 全章齊）

- 問題：`hdl.html` 的內建章節清單沒有 `../05/Memory`（`Memory.tst` 在 SKIP 互動名單）。
  Memory.tst 含兩段鍵盤 wait-while（`while out <> 75` 等 K、`while out <> 89` 等 Y），
  批次跑會卡死（上限 100000）。
- 解法：
  - `lib/rt/tst.js` 的 `While` step：當 `step.name === 'out'` 且目標為整數 → 先
    `model.setInput('KBD', step.val)`（批次下等同自動按腳本期待的鍵），再跑迴圈；
    開場 **不** 預設按鍵，避免污染鍵盤區早期的讀值（`%X6234` 那列預期 0）。
  - `dist/hdl.html` 加「KBD 鍵值」欄（id=`kbd`，預設 0；要持續按住某鍵才改）。
    之前墨蹟版預設 75 會讓 Memory 第 31 行 out=75≠cmp 的 0。
  - `tools/gen_corpus.js` SKIP 移除 Memory（現剩 Keyboard/Mult/Fill 互動例）；
    corpus 151→**153 檔**。三頁 cache-bust 升 `?v=5`。
  - `verify.sh` 對 script `src=…` 的比對放寬為 `(?v=[0-9a-z]+)?`（hdl/jack 引用檢查同）。
- 結果：`browser-smoke` **41 通過 / 0 失敗**（含 `../05/Memory.cmp`），
  `node --test` 97/97，`browser-jack-smoke` 12/12，`bash verify.sh` 全部 PASS。
