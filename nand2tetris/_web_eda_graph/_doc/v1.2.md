# hdl2js v1.2 — 版本紀錄

日期：2026-09-13（115 學年度 · 計算機結構）
對應：M11 之後的使用者體驗加值（書籤深連結）

## 一句話

三頁（`index.html` / `hdl.html` / `jack.html`）現在支援「書籤深連結」：在網址掛 `#`
fragment 就能直接指定範例，例如 `hdl.html#case=../05/Memory`。而且靠 `hashchange`
事件，**同頁點書籤只切 fragment、不重新載入**，範例可以連點連切；UI 上手動選取的
章節/案例/程式也會用 `history.replaceState` 反向寫回網址，隨時可複製成書籤或連結分享。

## 本版實作內容

- **統一 fragment 解析（每頁的 `hashWant()`）**，兩種語法都吃：
  - query 風格：`#case=../05/Memory`、`#case=../05/Memory&run=1`（hdl）、
    `#prog=Pong`、`#prog=Pong&run=1`（jack）、`#asm=<url-encoded>`、`#file=<corpusKey>`（index）。
  - 裸格式相容：`#../05/Memory`、`#../05/Memory!run`。
  - 語法解析完統一產出「want」，**hash 優先於 `?query`**。
- **`.tst` 正規化**：語料 key 以 `.tst` 結尾（下拉 `o.value` 就是完整 key），

  現在「有沒有 `.tst`」都能對上（`../05/Memory` ↔ `../05/Memory.tst`）。
- **`applyWant()`＝唯一套用入口**：啟動時執行一次（新分頁直開書籤），
  並註冊 `window.addEventListener('hashchange', applyWant)`——
  **同頁點書籤＝hash-only 導覽，瀏覽器不重載，即時切換**。
- **反向寫回（replaceState 不觸發 hashchange、不重載）**：
  - `hdl.html`：`el.chapter.onchange` / `el.case.onchange` → `#case=<去 .tst 的 key>`（`mirrorHash()` 產生）。
  - `jack.html`：`el.program.onchange` → `#prog=<名>`（僅 builtin 模式）。
  - `index.html` 沒有範例下拉，且自由 asm 文字不宜塞進網址，只讓 `#file`/`#asm` 深連結
    本身當書籤，手動貼程式不污染網址。
- **index.html 載入兩玩法**：
  - `#asm=` 鏡像原有 `?asm=`（原文餵文字）。
  - `#file=<corpusKey>`：從 `HACKJS_CORPUS` 取檔內容餵編輯器（經 `HACKJS_FS.read`）；
    這版起 `index.html` 也會載入 `corpus.js` + `hdl-rt.js`（只有 embed/app 時沒有語料可讀）。
    `load()` 新增「每一行都是 16 位元 `0/1` → 直接 `vm.loadHack()`」偵測，
    讓語料裡的 `.hack` 機器碼檔案（`../05/Add.hack` / `../04/fill/Fill.hack` 等）也能跑。

## 修掉的 bug

- `?case=../05/Memory`（無 `.tst`）原本**選不中**：`fillCase` 的 `o.value` 是含 `.tst`
  的完整語料 key，而啟動時直接用「使用者給的字串」比較，`../05/Memory ≠ ../05/Memory.tst`
  而靜默落到預設案例。`.tst` 正規化一併修好 query 與 fragment 兩條路。

## 已知限制

- 「零重載」只在**同一頁內** hash-only 導覽成立；從別的分頁/網址列直開書籤是一次
  完整載入（正常必有）。hash 與目前相同時不會觸發 `hashchange`（也屬正常：沒變化）。
- `index.html` 的 asm 編輯自由貼上不會反向寫回網址（見上）。
- `#file=` 只接受語料內存在的 key（`.hdl/.tst/.cmp/.hack/.jack` 皆可）；
  16 位元偵測若碰到「想當 asm 打但每行剛好都像二進位」的輸入會直接當機器碼，
  屬刻意設計（該寫法本就該走 `vm.loadHack`）。
