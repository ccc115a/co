# StackTest.asm 程式說明

這是以 vm2asm.c 翻譯 StackTest.vm 後存檔的 Hack 組合語言原始碼，共 380 行。其中約一半是 `// 原始 VM 指令` 的註解與 `// ======` 分隔線，一半是可執行指令。它是觀察「比較指令翻譯長相」的最佳教材檔，因為 9 組比較（3 組 eq、3 組 lt、3 組 gt）完整展示了 `label_count` 如何把 `TRUE_N/END_N` 依序編號為 0 到 8。

## 檔案總覽

| 段（依 vm 指令） | .asm 行數 |
|------------------|-----------|
| push constant×2（4 組） | 每組 8 行 |
| eq（3 組） | 每組 18 行 |
| lt（3 組） | 每組 18 行 |
| gt（3 組） | 每組 18 行 |
| add/sub/and/or | 每組 8 行 |
| neg/not | 每組 4 行 |

一個可記憶的對照：**每條 push constant 是 5 條指令，每對「push push」是 10 條，每組比較再加 8 條跳轉骨架**；相加結果完全吻合實際行數。

## 比較指令的翻譯樣板（以第一個 eq 為例，第 19–36 行）

```asm
// eq
@SP
AM=M-1
D=M
A=A-1
D=M-D        // D = x - y
@TRUE_0
D;JEQ        // 相等即跳
@SP
A=M-1
M=0          // 否則頂端寫 0
@END_0
0;JMP
(TRUE_0)
@SP
A=M-1
M=-1         // 若相等，頂端寫 -1
(END_0)
```

label 編號從 `TRUE_0/END_0` 開始，每組比較 +1：

| VM 指令 | 出現行數 | 使用的 label |
|---------|----------|--------------|
| eq（17,17） | 19–36 | TRUE_0 / END_0 |
| eq（17,16） | 53–70 | TRUE_1 / END_1 |
| eq（16,17） | 87–104 | TRUE_2 / END_2 |
| lt（892,891） | 121–138 | TRUE_3 / END_3 |
| lt（891,892） | 155–172 | TRUE_4 / END_4 |
| lt（891,891） | 189–206 | TRUE_5 / END_5 |
| gt（32767,32766） | 223–240 | TRUE_6 / END_6 |
| gt（32766,32767） | 257–274 | TRUE_7 / END_7 |
| gt（32766,32766） | 291–308 | TRUE_8 / END_8 |

三個型別的差異只在跳轉條件：eq 用 `D;JEQ`、lt 用 `D;JLT`、gt 用 `D;JGT`。

## 算術指令的翻譯樣板

以缺省的行進方式，`sub`（第 347–352 行）：

```asm
// sub
@SP
AM=M-1
D=M
A=A-1
M=M-D
```

而 `neg`（第 353–356 行）則只有 4 條：

```asm
// neg
@SP
A=M-1
M=-M
```

## 執行結果追蹤

程式依序執行到結尾時堆疊只剩一個元素：

1. 前三組 eq 依序留下 -1、0、0。
2. 三組 lt 依序留下 0、-1、0。
3. 三組 gt 依序留下 -1、0、0。
4. 最後一段算術：57 31 53 → add → 84，push 112 → sub → -28，neg → 28，and（57 & 28）→ 24，再 push 82 → or → 90，not → -91。

最終 `RAM[0]`（SP）=257、`RAM[256]`=-91，符合官方 StackTest.tst 的斷言。

## 對照原始 .vm

本檔開頭帶 `// ========== File: StackArithmetic/StackTest/StackTest.vm ==========`，這是翻譯器在 `translate_file` 時寫下的來源標記。往後每一段 `// 指令` 註解恰好對回 StackTest.vm 的一條指令，逐行比對即可看見「push → 8 行、比較 → 18 行、二元運算 → 8 行、一元運算 → 4 行」的固定規律。

## 延伸討論

- 這份 .asm 是「為翻譯器而寫」的測試輸出，不是通常意義上由人撰寫的哈克程式；它最重要的價值是當「黃金範本」，用 CPU Emulator 跑出的結果與 VM Emulator 跑原始 .vm 的結果互相驗證。
- 若手動檢錯，把握「每組比較的 `@TRUE_N` 唯一」這個不變量，就能快速找出翻譯器 label 命名 bug。
