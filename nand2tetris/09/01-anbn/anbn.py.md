# anbn.py 程式說明：以遞迴生成 aⁿbⁿ 字串

這個程式用一個 20 行的遞迴函式示範「上下文無關文法」（Context-Free Grammar, CFG）
的生成（derivation）概念。它是整套編譯器教學的開場白：在看得懂「文法規則」
之前，先讓學生親眼看到規則被套用、產生字串的過程。

## 概述

在「從 Nand 到 Tetris」課程中，第 9 章之前會先建立「語言 = 文法 + 語意」的直覺。
`anbn.py` 是這條學習路的第一站，它處理的文法是：

```
S → a S b     (遞迴規則)
S → a b       (基本規則)
```

只要反覆套用這兩條規則，就會得到 `aⁿbⁿ`（n 個 a 後接 n 個 b）的字串。這類語言
是文法教科書最經典的範例：它**無法**用正則表達式描述（因為需要「記住」已經看過
幾個 a，才能決定要輸出幾個 b），但用上下文無關文法三兩行就寫完了。

這個函式被自己呼叫（recursion），每一步都對應文法中的一次規則套用。

## 架構總覽

只有一個函式：

| 函式 | 參數 | 回傳 | 角色 |
|------|------|------|------|
| `S(n)` | n（正整數） | `str` | 模擬文法 S，生成 `a`×n + `b`×n |

程式最後用三個 `print` 展示 n=1、n=3、n=5 的輸出。

## 原理

### 文法與字串的對應

把文法規則想成「字串改寫」的步驟：

1. 起點是符號 `S`。
2. 每一次把一個 `S` 換成 `a S b`，就多包了一層 `a`……`b`：左邊多一個 a、右邊多一個 b。
3. 一旦改用 `S → ab`，遞迴結束，內層補上最基本的一對 ab。

例如生成 `a³b³`：

```
S
→ a S b              (套用 S → a S b)
→ a a S b b          (再套一次)
→ a a a b b b        (套用 S → ab)
```

很明顯，套用 k 次 `aSb` 再加一次 `ab`，就會得到 n = k+1 的字串，也就是 `aⁿbⁿ`。

### 遞迴的兩個支柱

所有遞迴程式都必須同時具備：

- **基底情況（base case）**：n=1 時直接回傳 `"ab"`，不再呼叫自己，否則會無限迴圈。
- **遞迴步驟（recursive step）**：n>1 時，把問題縮小為 n−1，再在外圈包上 a 與 b。

值得注意的是 n 在此處代表「第 n 次套用基底規則」，所以最小是 1，故 `n=1` 對應的
就是文法規則 `S → ab` 本身。

## 實作細節

```python
def S(n: int) -> str:
    if n == 1:                     # 基底：S → ab
        return "ab"
    middle_part = S(n - 1)         # 遞迴：S → a S b，先處理內層
    return 'a' + middle_part + 'b'
```

逐行說明：

1. `if n == 1:`：n 降到 1 時停止，回傳最小的合法字串 `"ab"`。
2. `S(n - 1)`：把規模縮小 1。每一次「外層套 a……b」，就消耗掉一個 n，剛好對應文法中
   一次 `S → aSb` 的套用。
3. `return 'a' + middle_part + 'b'`：在內層結果的外面包上 a 與 b，與規則右側
   `a S b` 的形狀完全一致——先把 S 換成 `a S b`，S 再繼續往下短。

把「遞迴呼叫分解＋外圈拼接」想成**衍生樹**（derivation tree）就更清楚了：樹根是
`S`，每個內部節點是一條 `S → a S b`，葉子就是 `a`、`b` 兩個字元。只要沿樹由左到右
讀葉子，就會讀出 `aⁿbⁿ`。

## 測試與驗證

直接執行即可：

```bash
python anbn.py
```

預期輸出：

```
n=1: ab
n=3: aaabbb
n=5: aaaaabbbbb
```

想多測試幾種 n，也可在 Python 互動環境輸入 `S(2)`、`S(6)` 等，一一驗證「b 的數量
恆等於 a 的數量」，且字串必是若干 a 後接若干 b。

## 延伸討論

- **為什麼不能用正則表達式？** `aⁿbⁿ` 需要無上限的「計數記憶」，而有限狀態機的狀態
  數是固定的，這就是它成為「上下文無關文法的第一個經典例子」的原因。
- **衍生樹的概念**：此處的遞迴執行軌跡，正是編譯器文法分析（3-parse 系列）畫出
  語法樹（parse tree）的雛形。看到 `a + (b * S(…))` 一層層展開，就等於看到「運算式
  文法的 E → E op E」在生成字串。
- **真正的編譯器反過來做**：這裡用文法「生成字串」（generation），下一章的
  03-expParser 則是用同樣的文法知識「剖析字串」（parsing），方向恰好相反。
