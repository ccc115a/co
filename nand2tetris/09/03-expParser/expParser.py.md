# expParser.py 程式說明：遞迴下降剖析運算式

這個程式把上一章隨機生成的運算式「反過來吃掉」：給定一個字串如 `10 + 2 * 3`，先用
`Tokenizer` 切成 token 串，再用`Parser`（遞迴下降剖析器，recursive descent parser）
邊剖析邊求值，算出結果。它是「文法理論 ＞ 字串生成」之後的下一步：「文法 ＞ 剖析 ＞ 語意」。

## 概述

本章示範編譯器中最重要的兩個前端元件：

1. **詞法分析（lexing / tokenizing）**：把字串切成有分類的單字（token），例如
   `10`、`+`、`2`、`*`、`3`。
2. **語法分析（parsing）**：依照文法規則吃掉 token 串，同時建立語意（此處直接求值）。

程式刻意把文法「寫在函式的結構裡」，而不是用剖析表（parse table）這類工具，讓背後的
原理一目瞭然：

```
exp    → term (('+' | '-') term)*           ← 真正的主文法
term   → number | variable | '(' exp ')'    ← 基本單元
```

程式裡的 `_expression()` 對應 `exp`，`_factor()` 對應 `term`，兩者互相呼叫，正是
「遞迴下降」名稱的由來。

## 架構總覽

| 類別 | 職責 | 關鍵介面 |
|------|------|----------|
| `Tokenizer` | 詞法分析：把字串切成 token 列表並提供遊標 | `get_next_token()`、`peek_token()` |
| `Parser` | 語法分析：依文法遞迴剖析並求值 | `parse()`、`_expression()`、`_factor()` |

`Parser` 內部持有一個 `Tokenizer`、一份變數表 `variables`（把變數名對應到數值），
剖析完成後 `parse()` 回傳一個數值（float）。

### 剖析方法的共同默契

- `get_next_token()`：**消耗**掉目前 token 並前進一格。
- `peek_token()`：**偷看**下一個 token 但不移動。

這對組合是手寫剖析器的標準工具：`peek` 用來決定「走哪條分支」，`get` 用來「吃掉」
已確認要用的 token。

## 原理

### 文法與函式的對應

文法 `exp → term (('+'|'-') term)*` 的意思拆開看：

- 一個運算式**起碼**是一個 term（`_expression` 開頭先呼叫 `_factor`）。
- 後面**可以重複**出現『運算子 + term』的組合（迴圈檢查 `peek` 是否為運算子）。

為什麼文法要寫成「term 開頭、後面迴圈」而不是 `exp → exp op exp`？因為 `exp → exp op
exp` 的右側**開頭也是 exp**，是「左遞迴」（left recursion）。遞迴下降剖析器在觸發
`_expression` 時會立刻又呼叫自己，永遠消耗不掉任何 token，形成無限迴圈。改成
「term 開頭 + 迴圈」正是為了避開左遞迴，同時**天然得到左結合**（left-associative）
的計算順序。

### 左結合是什麼意思

`10 - 2 - 3` 若從左邊算起是 `(10 - 2) - 3 = 5`。迴圈把「上一次的結果」當成下一次的
左運算元，正好實現左結合。請注意本程式**刻意不處理運算子優先權**（`*` 不會優先於
`+`），`10 + 2 * 3` 會先算 `10 + 2` 再乘 3，得到 36。這是示範簡化，延伸討論會說明。

### factor 的三種型態

`_factor` 對應文法中的基本單元，一次吃掉一個單元：

| 情況 | 文法規則 | 動作 |
|------|----------|------|
| token 是 `'('` | `term → '(' exp ')'` | 遞迴剖析內層 `exp`，再確認右括號存在 |
| token 是數字 | `term → number` | 轉成 `float` 回傳 |
| token 是英文字母 | `term → variable` | 查變數表取回數值，查不到則丟 `NameError` |

## 實作細節

### Tokenizer：一個正規表示式搞定

```python
self.tokens = re.findall(r'\d+|[a-zA-Z]|[+\-*/()]', expression)
```

這個 pattern 用 `|` 並列三種 token 型態，`re.findall` 會從頭到尾掃描：

- `\d+`：一個以上的數字（如 `10`、`273`）。
- `[a-zA-Z]`：單一字母，當成變數（如 `x`）。
- `[+\-*/()]`：單一字元的運算子或括號。注意 `-` 在字元類別中要寫成 `\-` 才不會被
  誤解成「範圍」符號。

`findall` 會自動跳過不匹配的字元，但這樣也會**靜默丟棄**非法字元。故 `Parser` 在建構
時先把所有空白移除（`expression.replace(' ', '')`），避免空格被忽略後 token 錯位。

### Parser：互遞迴剖析

`_expression` 的迴圈是整個剖析器的核心：

```python
result = self._factor()                     # 先吃一個 term 當左運算元
while True:
    op = self.tokenizer.peek_token()        # 偷看是否還有運算子
    if op in ['+', '-', '*', '/']:
        self.tokenizer.get_next_token()     # 消耗運算子
        right = self._factor()              # 吃右運算元（可能是括號！
        ... 依 op 計算並累加進 result      # 左結合落實處
    else:
        break                               # 遇到 ')' 或結尾即停
```

要點：

- `right = self._factor()` 很重要——右邊不一定是數字，也可能以 `(` 開頭，例如
  `y * (3 + z)`。`_factor` 遇 `(` 又會遞迴回去呼叫 `_expression`，所以**每個運算子
  的右側都能再包含一整個完整運算式**，這是巢狀括號能正確求值的關鍵。
- 運算完 `result` 就成為新的左運算元，繼續下一輪迴圈，實現左結合。
- `peek` 看到 `)` 或 `None` 時代表這個層級的運算式結束，回傳累積結果。

### 錯誤檢查（健壯性的示範）

- `_factor` 拿到 `None`：丟 `ValueError("Unexpected end …")`，表示運算式不完整。
- 左括號出現後 `get_next_token()` 不是 `)`：丟 `ValueError`。
- 變數查不到：丟 `NameError`。
- 除以 0：丟 `ZeroDivisionError`。
- 主程式剖析完還檢查 `peek_token()`，若有殘留 token 表示字串尾巴有多餘內容。

## 測試與驗證

直接執行：

```bash
python expParser.py
```

程式內建四個測試運算式。注意結果一律是**從左到右**、**忽略優先權**：

| 輸入 | 一般數學預期 | 本程式的 L-to-R 結果 | 說明 |
|------|--------------|----------------------|------|
| `10 + 2 * 3` | 16 | 36 | `(10+2)*3` |
| `5 - 2 + 1` | 4 | 4 | 左結合，與正規結果相同 |
| `x + y / z` | 12.5 | 7.5 | x=10,y=5,z=2 → `(10+5)/2` |
| `y * (3 + z)` | 25 | 25 | 括號優先，與正規結果相同 |

最後還刻意嘗試 `(1 + 2`（缺右括號），確認錯誤訊息能正確捕捉。

## 延伸討論

- **運算子優先權怎麼加？** 真正的編譯器不會只靠一層迴圈。標準做法是引入多層文法，
  例如 `expr → term (('+'|'-') term)*`、`term → factor (('*'|'/') factor)*`、
  `factor → '(' expr ')' | number | variable`，每一層各管一層優先權。Nand2Tetris
  第 10 章的 Jack 編譯器 `parseExpression`/`parseTerm` 正是這種多層遞迴的實作。
- **與書上 VM 的關聯**：本書目前的剖析器「邊剖析邊求值」，而真正的 Jack 編譯器是
  「邊剖析邊產生 VM 指令」——把求值動作換成 `push/pop` 與算術指令，就是第 8 章能
  跑出來的計算過程。可見語意動作（semantic action）可以換，剖析架構大同小異。
- **左遞迴 vs. 右結合**：本程式的迴圈寫法給出左結合；若改成 `exp → term (op exp)?`
  的右遞迴寫法，則會得到右結合。兩者對減法、除法的結果不同，是教學上很好的對照點。
