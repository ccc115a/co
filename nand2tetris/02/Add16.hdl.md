# Add16 程式說明 — 16 位元漣波進位加法器

這個電路把兩個 16 位元二補數整數相加，`out = a + b`，由 16 個 FullAdder 串接成一條進位鏈。

## 概述

Add16 是第二章的中樞元件：HalfAdder → FullAdder → Add16 → Inc16 → ALU，層層堆疊。它的輸入輸出都是 16 條線的 bus，代表 Hack 平台上的一個字（word）。任何需要加法的地方（ALU 的 `x+y`、Inc16 的 `+1`）最終都落到這裡。

## 介面與規格

```
CHIP Add16 {
    IN  a[16], b[16];
    OUT out[16];
}
```

- `out[0]` 是最低位元（LSB），`out[15]` 是最高位元（MSB）。
- 採用二補數表示，因此正數、負數、0 都共用同一套加電路，無需特判符號。
- **最高位的進位 `c15` 被捨棄**（overflow 溢位時輸出可能不正確，這是 16 位元字寬的固有限制）。

## 原理

人類寫直式加法時，從最低位逐位往高算，把每一位的進位交給上一位。Add16 把這件事機械化：第 i 位的 FullAdder 接收 `a[i]`、`b[i]`，以及前一位送來的進位 `c(i-1)`；第 0 位沒有前一位進位，所以 `c` 接常數 `false`。

```
第 i 位：  sum[i] = a[i] ⊕ b[i] ⊕ c(i-1)
          carry  c[i] = a[i]·b[i] + b[i]·c(i-1) + a[i]·c(i-1)
```

進位一路從 `c0` 傳到 `c15`，像水波一樣接力，因此取名「漣波進位（ripple carry）」。這也意味著計算延遲正比於位元數：最後一位的和要等所有進位傳遞完畢才穩定。

## 實作細節

```hdl
PARTS:
    FullAdder(a=a[0], b=b[0], c=false, sum=out[0], carry=c0);
    FullAdder(a=a[1], b=b[1], c=c0,    sum=out[1], carry=c1);
    ...
    FullAdder(a=a[15], b=b[15], c=c14, sum=out[15], carry=c15);
```

- 第 0 位：`c=false` 剛好實現「半加」效果，但與其另外接一個 HalfAdder，直接固定進位輸入為 0 更整齊。
- 中間線 `c0`…`c15` 是上一位的輸出接腳接到下一位的 `c` 輸入，構成進位鏈。這些線在 HDL 中沒有宣告，直接由 `carry=` 命名產生。
- 每一行都是同一個 pattern，只是 index 遞增，這是 bus slicing（`a[0]`、`out[15]`）最典型的應用。
- 最後一行仍然接出 `carry=c15`，讓進位停在鏈尾，但 `c15` 不連到任何輸出，等於被忽略。

## 測試與驗證

`Add16.tst` 涵蓋幾個刻意設計的邊界案例：

| a | b | 測驗重點 |
|---|---|---------|
| 0000000000000000 | 0000000000000000 | 0 + 0 = 0 |
| 0000000000000000 | 1111111111111111 | 0 + (-1) = -1 |
| 1111111111111111 | 1111111111111111 | (-1) + (-1) = -2，進位全鏈啟動 |
| 101010… | 010101… | 每位的 a、b 互補，最長進位傳遞 |
| 其他隨機 pattern | | 一般案例 |

比對用二進位格式（`%B1.16.1`），可一眼看出每一位 bit 是否正確。

## 延伸討論

漣波進位延遲在 16 位元時尚可接受，但真實 CPU（64 位元）會改用**前瞻進位加法器（carry look-ahead）**─預先平行計算每位元的 `generate`（a·b）與 `propagate`（a⊕b），把 O(n) 的串列延遲壓到接近 O(log n)。本書日後的 ALU 只要求功能正確，漣波架構足矣。
