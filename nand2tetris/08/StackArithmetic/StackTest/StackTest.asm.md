# StackTest.asm 程式說明

這是 `StackTest.vm` 翻譯出來的 Hack 組合語言檔，全檔 380 行。因為包含
九個比較指令（`eq/lt/gt`），它是最好的教材示範，展示「比較指令如何被展開
成需內建分支的機器碼」，以及翻譯器如何用編號標籤避免衝突。

## 概述

- 來源 VM 指令序列：見 `StackTest.vm.md`（三組 eq、三組 lt、三組 gt，
  加上一段 add/sub/neg/and/or/not）。
- 對應 C 語言（示意）：

```c
x = 17==17; x = 17==16; x = 16==17;
x = 892<891; x = 891<892; x = 891<891;
x = 32767>32766; x = 32766>32767; x = 32766>32766;
x = 57 & (31 + 53 - 112) neg;  ...
```

## 原理

### 比較指令的統一模板

每個比較指令都展開成同一種「if-else」模板，差別只在跳轉條件：

```
@SP
AM=M-1
D=M
A=A-1
D=M-D          // D = x - y
@TRUE_n
D;Jxx          // 條件跳轉（JEQ / JLT / JGT）
@SP
A=M-1
M=0            // false 分支：寫 0
@END_n
0;JMP
(TRUE_n)
@SP
A=M-1
M=-1           // true 分支：寫 -1
(END_n)
```

計數器 `n` 從 0 起每次加一，所以這個檔依序出現 `TRUE_0`…`TRUE_8`、
`END_0`…`END_8`。若沒有編號，九個模板的標籤會互相覆蓋。

## 實作細節（選取代表性片段）

### 第一個 eq（第 19–36 行）

```
@SP
AM=M-1
D=M
A=A-1
D=M-D        // 17 - 17 = 0
@TRUE_0
D;JEQ        // 相等 → TRUE_0
@SP
A=M-1
M=0          // （不會執行）
@END_0
0;JMP
(TRUE_0)
@SP
A=M-1
M=-1         // true = -1
(END_0)
```

### 第一個 lt（第 121–138 行）

同樣模板，但用 `@TRUE_3 / D;JLT`。執行 892<891 時因為 892−891=1 不為負，
走 false 分支寫 0。注意 Hack 比較的是二補數數值，所以 `D;JLT` 能直接判負。

### 結尾的位元運算（第 333–380 行）

最後以四個一元/二元運算收尾。`neg` 展開成 `@SP / A=M-1 / M=-M`
（第 353–356 行），`and` 展開成 `AM=M-1 / D=M / A=A-1 / M=D&M`
（第 357–362 行），`or`、`not` 同理。這就是 `57 & 28 | 82 | ~` 一連串的結果
-91。

## 測試與驗證

- 用 CPU Emulator 逐步執行並觀察堆疊頂。
- 完成九組比較後堆疊頂依序是 -1/0/0、0/-1/0、-1/0/0；最後一段運算後為 -91。
- 對照第 7 章專案的 `StackTest.cmp`。

## 延伸討論

- **`TRUE_n`/`END_n` 出現的次數正是比較指令的個數**：九個比較 → 九組標籤，
  這是快速核對翻譯器輸出是否缺漏的好方法。
- 這個檔同時也是很好的「反組譯教材」：同一模板重複九次，學生可看出
  分支、跳躍、立即數寫入如何在 Hack 中成形。
