# 70 語料與驗證：`gen/`、`tools/`、`verify.sh`

## 用法

全部驗證跑這兩個（在 `_web_eda_riscv/` 下）：

```
bash verify.sh   # 嚴格版：一段失敗即停
bash test.sh     # 容錯版：同清單但失敗繼續，最後看結果
```

## 完整範例：[`verify.sh`](../verify.sh) 都在驗什麼（截錄流程）

```
node --test                                              # 單元測試
node cli/hdl2js.js --dir ../01 --dir ../02 ...           # ch01~05 全部 .tst
node cli/jack2vm.js gen/chain/Main.jack ...              # 全鏈路重建
node cli/vm2asm.js gen/chain/chain.asm ...               # .vm → .asm
node cli/hackasm.js gen/chain/chain.asm                  # .asm → .hack/.bin
node cli/hdl2js.js ... --test gen/chain/chain.tst        # 跑在 Computer 上驗 RAM[16]=5
node cli/hackemu.js --headless gen/chain/chain.bin ...   # 同一支換模擬器交叉驗
node cli/hackemu.js --headless gen/pong.bin --keys ...   # Pong 按鍵分離（3 億步，bat＞100px）
node tools/browser_smoke.js                              # HDL 全章節無頭跑
```

## 語料（[`gen/`](../gen/)，產物不 commit——除了特別註明的）

| 目錄 | 內容 |
|---|---|
| [`gen/chain/`](../gen/chain/) | 全鏈路 e2e：`Main.jack`（`x=5`）＋`Sys.jack` → `.vm` → `.asm` → `.hack`，`chain.tst` 跑在 `Computer.hdl` 上看 `RAM[16]=5` |
| [`gen/sum/`](../gen/sum/) | 同鏈路的 1+…+10＝55 版（`RAM[16]=55`，中間和可見） |
| [`gen/os_src/`](../gen/os_src/) | ch12 裁剪版 OS（`Sys` 只初始化 Math/Screen/Keyboard/Memory；`Output` 是空殼，顯示靠 `vm2riscv` 內聯 UART，見 40 章） |

`chain`／`sum` 的 `.jack→.vm→.asm→.hack` 檔都留著，鏈路任一段都可單獨重跑；
上面流程會整鏈重建並比對，證明可重現。

## 原理：為什麼要三套驗證

- **單元測試**（`node --test`）：函式級，壞了立刻知道是哪個函式。
- **`.tst` 回歸**：官方測資，一字不差，保證和課程語意一致。
- **無頭 harness**（[`tools/browser_smoke.js`](../tools/browser_smoke.js) 跑 HDL
  全章節 44 案例、[`tools/browser_jack_smoke.js`](../tools/browser_jack_smoke.js)
  跑 Jack 12 支）：在 Node 裡跑**真實 `dist/*.js`**，`/tmp` 驗完即刪——
  保證「網頁上跑的」和「命令列測的」是同一份引擎。
  另有早期一次性 harness（Pong 按鍵、速度映射）驗完即刪，
  結論收進 `_doc/vX.Y.md`。

版本紀錄慣例：[`_doc/`](../_doc/) 的 `v*.md` 記每次修復的原因與數據；
改 `lib/`/`cli/` 影響網頁時重建 `dist/` 並 commit（`dist/` 靠本目錄
`.gitignore` 的 `!dist/` 收進 git，`npm run build` 是壞的不要用——見 AGENTS.md）。
