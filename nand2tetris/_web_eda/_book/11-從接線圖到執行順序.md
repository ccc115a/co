# 11 從接線圖到執行順序：詳述

## 用法

[`elab.js`](../lib/hdl/elab.js) 的用法：先 `loadLibrary` 收目錄成函式庫
（可 `mergeLibs` 疊多個，後蓋前），再 `elab(lib, 頂層名)` 得到整顆設計的
中間表示。沿用上章的 [`Not.hdl`](../../01/Not.hdl)：

```
node --input-type=module -e "
import { loadLibrary, mergeLibs, elab } from './lib/hdl/elab.js';
let lib = mergeLibs(loadLibrary('../01'), loadLibrary('../02'));
const e = elab(lib, 'Not');
const c = e.chips[e.top];
for (const w of c.wires) console.log('wire:', w.name, 'width=' + w.width);
console.log('evalOrder:', JSON.stringify(c.evalOrder));
"
```

## 完整範例（上段指令的真實輸出）

```
wire: out width=1
evalOrder: [0]
```

只有一條 wire（`out`，1 bit），求值順序只有一個零件（`[0]`，就是那顆 Nand）。
複雜一點的例子（[`And.hdl`](../../01/And.hdl)，兩顆 Nand 串起來）會得到
兩條 wire（`AnandB`、`out`）和順序 `[0, 1]`——第二顆要吃第一顆算出來的
`AnandB`，所以第一顆先算。兩顆都 `hasState: false`（純組合，無記憶）。

## 原理：接線圖不能直接跑，要先回答三個問題

1. **每條線有多寬？接得對不對？**——`a[16]` 接到 1-bit 的 pin 就是錯；
   同一條線被兩顆零件同時驅動也是錯（硬體短路）。
   對應 **Pass A**（掃*輸出*接線，記每條 wire 的驅動區間，重疊就報錯，
   wire 寬度取最大覆蓋，`OUT` 必須被完整驅動）
   和 **Pass B**（掃*輸入*接線，寬度不合、接到不存在的腳、重複驅動、
   覆蓋不全，全部報錯）。
2. **誰先算誰後算？**——把「寫線的→讀線的」畫成箭頭，排出大家都滿意的順序，
   這叫**拓樸排序**（Kahn 演算法，不斷拿掉入度為 0 的點；同層維持原文順序
   保證確定性）。排不完＝組合迴圈，直接報錯。
3. **有回饋怎麼辦？**——例如 [`Bit.hdl`](../../03/a/Bit.hdl) 把 DFF 的輸出繞回
   Mux 的輸入，箭頭繞一圈排不出來。這時認出「圈裡有記憶元件」：
   記憶元件的輸入是下一個時脈才要記的東西，不急著現在算，
   所以**讀記憶元件的人不列入排序依賴**——圈就斷開了。
   `DFF`、暫存器、RAM、RF32 被稱為「循序邏輯」，就是因為它們是時間上的斷點。

內建表（檔頭 `Builtin`）把每顆免解析零件的腳位寬度寫死：
`Nand`、`DFF`、`ARegister`、`DRegister`、`ROM32K`、`Screen`、`Keyboard`
是 16-bit 世界的；`ROM32`、`RAM32W`、`RF32`（32×32 暫存器檔）是給 RV32
處理器用的，查表就知道，不用解析。
