## 前言

到目前為止，這台 Hack 電腦還是「啞巴」——它會算數、會管理記憶體，但你什麼都看不到。要讓使用者「看到」程式在幹嘛，必須有螢幕輸出。Hack 的硬體（第四章、第五章）已經為我們準備了一塊**記憶體映射螢幕（memory-mapped screen）**：從位址 `SCREEN = 16384` 開始，連續 8192 個 16 位元字，對應到 256×512 的像素空間。

但硬體只提供「把 16 位元寫進某個位址，螢幕上某些點就亮起」——它不提供「畫一條線」「畫一個圓」這種高階能力。這正是 OS 的 `Screen` 類別要做的：它把「裸的記憶體映射螢幕」包裝成程式設計師一呼叫就「畫線、畫圓、畫方塊」的繪圖 API。

本節我們要寫出這個繪圖引擎。核心挑戰有兩個：

1. **座標 ↔ 位址的換算**：如何在 `(x, y)` 與「某一記憶體字的某一個位元」之間建立正確對應。
2. **幾何演算法**：只用整數運算，畫出平滑的字線與圓（因為 Hack 沒有浮點數、沒有硬體乘法「畫線處」，一切都得靠巧妙的整數演算法）。

## 1. Screen 類別的 API

`Screen` 提供的類別方法：

| 方法 | 簽名 | 功能說明 |
|------|------|----------|
| `init` | `Screen.init()` | 清空螢幕，設定預設顏色 |
| `clearScreen` | `Screen.clearScreen()` | 把整個螢幕擦成背景色 |
| `setColor` | `Screen.setColor(boolean black)` | 之後畫的所有圖形用黑色（black=true）或白色（black=false） |
| `drawPixel` | `Screen.drawPixel(int x, int y)` | 在 `(x,y)` 畫一個像素 |
| `drawLine` | `Screen.drawLine(int x1, int y1, int x2, int y2)` | 從 `(x1,y1)` 到 `(x2,y2)` 畫一條直線 |
| `drawRectangle` | `Screen.drawRectangle(int x1, int y1, int x2, int y2)` | 畫一個實心（填滿）矩形 |
| `drawCircle` | `Screen.drawCircle(int cx, int cy, int r)` | 以 `(cx,cy)` 為圓心、半徑 `r` 畫一個實心圓 |

Hack 螢幕規格：**寬 512、高 256**，座標 `(0,0)` 在左上角，`x` 向右增加、`y` 向下增加。座標若超出範圍，繪圖被忽略（或局限）。

## 2. 像素與記憶體位址的對應

### 2.1 螢幕記憶體映射

回想第四章的硬體映射：

- 螢幕對應到位址 `16384`（`SCREEN`）到 `16384 + 8192 - 1 = 24575`，共 **8192 個 16 位元字**。
- 每個字 = 16 個像素（每個位元一個像素）。所以螢幕共有 `8192 × 16 = 131072 = 512 × 256` 個像素。吻合！

佈局：螢幕被垂直切成 **256 列（rows，`y=0..255`）**，每一列佔 **512/16 = 32 個字**。所以：

```
記憶體位址   = SCREEN + y*32 + x/16
該位址中位元 = x mod 16（也就是第 x % 16 位）
```

更精確地說，掃描線是**從左到右、從上到下**。第 `y` 列的第一個字（`y*32`）涵蓋 `x=0..15`，第二個字涵蓋 `x=16..31`，依此類推。

### 2.2 位元順序

一個 16 位元字的**第 j 個位元**（`j=0..15`）對應到 `x = y*32 的那一列中，第 j 個像素`。Hack 約定：位元 `j` 是「由右向左」數——`bit 0` 是最低有效位（LSB），對應最左邊像素。這只是約定，重點是整個 OS 一致即可。

所以「點亮 `(x,y)`」的步驟：

1. `wordAddr = SCREEN + y*32 + x/16`
2. `bit = x % 16`
3. `Memory.poke(wordAddr, Memory.peek(wordAddr) | (1 << bit))`（設黑）或 `& ~(1<<bit)`（設白）

### 2.3 為什麼用 16 位元一字的原因

一次可以處理 16 個水平像素，這讓「水平畫線」與「填充矩形」可以**以字為單位**快速處理（一次寫入一個字 = 畫 16 個像素），而不是逐像素慢慢寫。這是效率關鍵。

> **設計思路**：因為 Hack 最小可定址單位是 16 位元，我們可以把「一條水平掃描線」切成「n 個完整字 + 兩個不完整的邊界位」。填充矩形時，**中間的完整字一次寫入**，兩端只改部分位元——這正是 `drawRectangle` 能「瞬間」填滿大面積的原因。

## 3. drawPixel：最基本的繪圖

先把最底層的 `drawPixel` 寫好，其他所有繪圖都建立在它之上（或借鑑它的位元操作）。

```
// 在 (x,y) 畫一個點；用目前顏色 (color) 決定設黑或設白
function void drawPixel(int x, int y) {
    var int addr, bit;

    // 範圍檢查：超出螢幕就忽略
    if ((x < 0) | (x > 511) | (y < 0) | (y > 255)) {
        return;
    }
    let addr = 16384 + y * 32 + x / 16;
    let bit = 1 << (x % 16);

    if (color) {                       // 黑色
        do Memory.poke(addr, Memory.peek(addr) | bit);
    } else {                           // 白色（清除）
        let bit = ~bit;                // 取反：該位為 0
        do Memory.poke(addr, Memory.peek(addr) & bit);
    }
    return;
}
```

> **設計思路**：顏色用一個類別變數 `color`（boolean）儲存。畫黑 = 用 OR 把該位設 1；畫白 = 用 AND 把該位清 0。這是「位元塗鴉」的原理。

`x/16` 與 `x%16` 依賴 `Math` 庫的除法，這正是我們先寫好 `Math` 的原因。

## 4. drawLine：Bresenham 直線演算法

### 4.1 樸素畫線的致命問題

最樸素的畫線：`y = y1 + (y2-y1)*(x-x1)/(x2-x1)`，但這需要浮點除法（Hack 沒有浮點），而且對「陡峭」（斜率 > 1）的線會斷裂。我們需要一個**只用整數加法、加減與符號判斷**的演算法——這就是 **Bresenham 演算法**。

### 4.2 Bresenham 的核心思想

想像從 `(x1,y1)` 走到 `(x2,y2)`。在每一「步」（在較長的那個軸上前進一格），另一個軸的座標「該不該 +1」？Bresenham 用一個「誤差項（error term）」來決定：

- 我們追蹤「理想的 y 位置」與「目前整數 y」之間的誤差；
- 每走一 `x` 步，誤差加上「斜率」（以整數表示，避免浮點）；
- 當誤差累積超過半格，就前進一個 `y`，並減去一格的誤差。

誤差用「整數」表示：把斜率放大 `2`（或 `2*大軸長`），用 `error` 變數追蹤。

### 4.3 Bresenham 的完整流程（處理四種象限）

要處理任意方向的直線，我們先判斷「這條線是『比較陡』（`|dy| > |dx|`）還是『比較平』」，並以**主軸（major axis）** 決定每步走哪裡。若以 `y` 為主軸，就是「每 `y` 步決定 `x` 是否 +1」。

Nand2Tetris 官方先判斷主軸方向，統一成「從頭到尾沿著主軸遞增」，並維護誤差。下面是官方 `drawLine` 的可讀版本：

```
function void drawLine(int x1, int y1, int x2, int y2) {
    var int dx, dy, sx, sy, err, e2;

    // 計算各方向增量與步進方向 (+1 或 -1)
    let dx = Math.abs(x2 - x1);
    let dy = Math.abs(y2 - y1);
    if (x1 < x2) { let sx = 1; } else { let sx = -1; }
    if (y1 < y2) { let sy = 1; } else { let sy = -1; }

    let err = dx - dy;    // 初使誤差

    while ((x1 != x2) | (y1 != y2)) {
        do drawPixel(x1, y1);
        let e2 = err * 2;
        if (e2 > -dy) {
            let err = err - dy;
            let x1 = x1 + sx;
        }
        if (e2 < dx) {
            let err = err + dx;
            let y1 = y1 + sy;
        }
    }
    do drawPixel(x1, y1);   // 最後一個點
    return;
}
```

**這是標準的 Bresenham 直線演算法**（任意斜率、任意方向，`dx`、`dy` 取絕對值，`sx`、`sy` 決定步進方向）。它是目前學界最經典、也最簡潔的整數直線畫法。

**逐行解說**：

- `dx, dy`：兩個方向的絕對距離（恒非負）。
- `sx, sy`：±1，決定從 `(x1,y1)` 往 `(x2,y2)` 的步進方向。
- `err = dx - dy`：誤差項起始值，決定哪個軸「落後」。
- 迴圈直到到達終點：
  - 先畫目前的點；
  - `e2 = 2*err`：把誤差放大，避免中間除以 2；
  - 若 `e2 > -dy`，代表「水平方向該走了」，就 `x1 += sx`，並調整誤差；
  - 若 `e2 < dx`，代表「垂直方向該走了」，就 `y1 += sy`，並調整誤差。

不需要乘法、不需要除法、不需要浮點——Bresenham 只用加、減與比較，是嵌入式繪圖與低階系統的最愛。

> **設計思路**：許多人誤以為「畫線 = 對每個 x 算一個 y」。Bresenham 的高明在於它**根本不算 y**，而是讓誤差項「自己決定」該不該在另一個軸上前進。這把「除法與浮點」徹底化為「加法與比較」，正是為無浮點硬體量身打造。

## 5. drawRectangle：實心矩形

一個「實心」矩形的畫法很直接：**把每一條水平掃描線填滿**。但要有效率，我們不逐像素呼叫 `drawPixel`（那會很慢），而是**以 16 位元字為單位**處理每一列。

官方 `drawRectangle` 的流程：對每一列 `y`（從 `y1` 到 `y2`），在 `x1..x2` 之間填滿。為了效率，它直接操作記憶體：一次寫一個字可畫 16 個像素。

```
function void drawRectangle(int x1, int y1, int x2, int y2) {
    var int x, y, K;
    // 標準化：確保 x1<=x2, y1<=y2
    if (x1 > x2) { let K = x1; let x1 = x2; let x2 = K; }
    if (y1 > y2) { let K = y1; let y1 = y2; let y2 = K; }

    let y = y1;
    while (y <= y2) {
        // 填滿從 x1..x2 這條水平線
        // 作法：先在 x1 與 x2 呼叫 drawPixel 設好邊界，
        //       中間的部分以「整個 16 位元字」填入
        let x = x1;
        while (x <= x2) {
            do drawPixel(x, y);
            let x = x + 1;
        }
        let y = y + 1;
    }
    return;
}
```

上面的版本正確且清晰（逐像素，慢但易懂）。**官方更快的版本**會直接以 `Memory.peek/poke` 填充「落在一整個 16 位元字內」的中間區段。對教學而言，逐像素版已能正確運作；對效能有要求的實作才會最佳化。我在「設計思路」中補充最佳化方法。

> **設計思路——最佳化**：矩形內部有大量「連續 16 個像素 = 一個字」的區段。真正的實作會：
> 1. 找出左邊界所在的字與位元、右邊界所在的字與位元；
> 2. 中間「完整字」直接 `Memory.poke` 寫入全 1（黑）或全 0（白）；
> 3. 左右兩端只改部分位元。
> 這樣一個矩形可以「每列一次寫入多個字」，比逐像素快 16 倍。本書列出逐像素版本以求清晰，實務上正式 OS 會採用上述最佳化。

## 6. drawCircle：實心圓

### 6.1 圓的方程式與對稱性

圓心 `(cx,cy)`、半徑 `r` 的圓滿足 `(x-cx)² + (y-cy)² = r²`。要畫**實心**圓，最直觀的方法是按列掃描：

對每一列 `y`，算出該列起 `x` 的跨距：

```
對 y 從 (cy - r) 到 (cy + r):
    dy = y - cy
    dx = sqrt(r*r - dy*dy)     // 半寬
    畫水平線從 (cx - dx, y) 到 (cx + dx, y)
```

這樣每列畫一條水平線，就把圓填滿了。它依賴 `Math.sqrt` 與 `Math.multiply`，正是我們第 12.1 節寫好的工具。

### 6.2 drawCircle 的 Jack 實作

```
function void drawCircle(int cx, int cy, int r) {
    var int dy, dx, y;

    let dy = -r;                       // 從圓頂開始
    while (dy <= r) {
        // 這種列 y = cy + dy 的半寬 dx = sqrt(r*r - dy*dy)
        let dx = Math.sqrt(Math.multiply(r, r) - Math.multiply(dy, dy));
        // 畫這條水平線
        do drawLine(cx - dx, cy + dy, cx + dx, cy + dy);
        let dy = dy + 1;
    }
    return;
}
```

**非常短、非常美**：每次計算該列新增的半寬 `dx`，用 `drawLine` 畫一條水平弦。由於 `drawLine` 已處理座標，圓就會一步步被「一層層的弦」填滿成實心圓。

> **設計思路**：這裡「一次畫一條水平線」的技巧，讓 `drawCircle` 只需要 `2r+1` 次 `drawLine`，而不是逐像素作業。圓的對稱性（每一列左右對稱於 `cx`）讓我們能一次畫一條水平弦。若要畫「空心圓」，只要改用 `drawPixel(cx±dx, y)` 兩個點即可，不必填滿。

### 6.3 效能注意

`Math.multiply(r,r)` 在迴圈中每列重算（其實只要算一次），你可以把 `r²` 提出迴圈外：

```
var int r2;
let r2 = Math.multiply(r, r);
let dy = -r;
while (dy <= r) {
    let dx = Math.sqrt(r2 - Math.multiply(dy, dy));
    do drawLine(cx - dx, cy + dy, cx + dx, cy + dy);
    let dy = dy + 1;
}
```

這樣更省。這是「迴圈不變量提升（hoisting）」的微優化。

## 7. clearScreen 與 init

### 7.1 init

`init` 要做的：把整個螢幕記憶體全部歸零（變成白色 / 背景色），並把 `color` 設為預設值（黑色）。因為 `Memory` 要先初始化，`Screen.init` 通常呼叫 `Memory.init()`。

```
function void init() {
    var int i;
    // 清螢幕
    let i = 0;
    while (i < 8192) {
        do Memory.poke(16384 + i, 0);   // 全寫 0 = 白
        let i = i + 1;
    }
    let color = true;                   // 預設畫黑色
    return;
}
```

### 7.2 clearScreen

把整個螢幕變成背景色。若背景是白（0），就全填 0；若預設畫黑色則保持。通常 `clearScreen` 就是把全部 8192 個字清成 0：

```
function void clearScreen() {
    var int i;
    let i = 0;
    while (i < 8192) {
        do Memory.poke(16384 + i, 0);
        let i = i + 1;
    }
    return;
}
```

> **設計思路**：`clearScreen` 一次掃描 8192 個字直接清 0，比「先 `setColor(white)` 再畫一個大矩形」快得多，也最乾淨。

## 8. 完整的 Screen.jack 實作

整合全部方法，寫成一個完整的 `Screen.jack`。請注意類別變數 `color` 需要在類別頂部以 `static boolean color;` 宣告。

```
// Screen.jack —— 螢幕繪圖引擎
class Screen {

    static boolean color;   // true = 黑, false = 白

    // 初始化：清螢幕、設預設顏色
    function void init() {
        var int i;
        let i = 0;
        while (i < 8192) {
            do Memory.poke(16384 + i, 0);
            let i = i + 1;
        }
        let color = true;
        return;
    }

    // 清空整個螢幕為背景色
    function void clearScreen() {
        var int i;
        let i = 0;
        while (i < 8192) {
            do Memory.poke(16384 + i, 0);
            let i = i + 1;
        }
        return;
    }

    // 設定之後繪圖所用顏色
    function void setColor(boolean black) {
        let color = black;
        return;
    }

    // 在 (x, y) 畫一個像素
    function void drawPixel(int x, int y) {
        var int addr, bit;
        if ((x < 0) | (x > 511) | (y < 0) | (y > 255)) { return; }
        let addr = 16384 + y * 32 + x / 16;
        let bit = 1 << (x % 16);
        if (color) {
            do Memory.poke(addr, Memory.peek(addr) | bit);
        } else {
            let bit = ~bit;
            do Memory.poke(addr, Memory.peek(addr) & bit);
        }
        return;
    }

    // Bresenham 直線演算法
    function void drawLine(int x1, int y1, int x2, int y2) {
        var int dx, dy, sx, sy, err, e2;
        let dx = Math.abs(x2 - x1);
        let dy = Math.abs(y2 - y1);
        if (x1 < x2) { let sx = 1; } else { let sx = -1; }
        if (y1 < y2) { let sy = 1; } else { let sy = -1; }
        let err = dx - dy;
        while ((x1 != x2) | (y1 != y2)) {
            do drawPixel(x1, y1);
            let e2 = err * 2;
            if (e2 > -dy) {
                let err = err - dy;
                let x1 = x1 + sx;
            }
            if (e2 < dx) {
                let err = err + dx;
                let y1 = y1 + sy;
            }
        }
        do drawPixel(x1, y1);
        return;
    }

    // 實心矩形
    function void drawRectangle(int x1, int y1, int x2, int y2) {
        var int x, y, K;
        if (x1 > x2) { let K = x1; let x1 = x2; let x2 = K; }
        if (y1 > y2) { let K = y1; let y1 = y2; let y2 = K; }
        let y = y1;
        while (y <= y2) {
            let x = x1;
            while (x <= x2) {
                do drawPixel(x, y);
                let x = x + 1;
            }
            let y = y + 1;
        }
        return;
    }

    // 實心圓
    function void drawCircle(int cx, int cy, int r) {
        var int dy, dx, y, r2;
        let r2 = Math.multiply(r, r);
        let dy = -r;
        while (dy <= r) {
            let dx = Math.sqrt(r2 - Math.multiply(dy, dy));
            do drawLine(cx - dx, cy + dy, cx + dx, cy + dy);
            let dy = dy + 1;
        }
        return;
    }
}
```

這個 `Screen.jack` 依賴 `Memory`（peek/poke）與 `Math`（abs、multiply、sqrt），全都在前面章節寫好了，形成一條完整的依賴鏈。

## 9. 設計思路與實作步驟

### 9.1 實作步驟

1. **寫 `init` + `clearScreen`**：清空 8192 個螢幕字，設定顏色。可以先用它驗證「螢幕能全黑/全白」。
2. **寫 `drawPixel`**：這是最關鍵的一步——把 `(x,y)` 換算成「位址 + 位元」。先測試一個點、幾個點是否能正確亮起。
3. **寫 `drawLine`**：實作 Bresenham。先用「水平線、垂直線、斜線」各別測試。
4. **寫 `drawRectangle`**：先簡單逐像素，再考慮以字為單位最佳化。
5. **寫 `drawCircle`**：利用 `Math.sqrt` 每列畫水平弦。

### 9.2 驗證策略

用一支 `ScreenTest.jack` 測試：

```
// ScreenTest 摘要
do Screen.init();
do Screen.setColor(true);
// 畫一個框
do Screen.drawLine(10, 10, 300, 10);   // 上緣（水平）
do Screen.drawLine(10, 10, 10, 200);   // 左緣（垂直）
do Screen.drawLine(300, 10, 300, 200); // 右緣
do Screen.drawLine(10, 200, 300, 200); // 下緣
// 畫斜線
do Screen.drawLine(10, 10, 300, 200);  // 對角線
// 畫矩形
do Screen.drawRectangle(50, 50, 150, 100);
// 畫圓
do Screen.drawCircle(200, 100, 60);
```

在 CPU Emulator 上觀察：直線是否平滑無鋸齒孔洞、矩形是否實心、圓是否對稱飽滿。

## 10. 本章小結

- Hack 螢幕是**記憶體映射**：位址 `16384 + y*32 + x/16` 的第 `x mod 16` 個位元，即像素 `(x,y)`。
- `drawPixel` 用 `OR`（黑）與 `AND `（白）做「位元塗鴉」，是其他所有繪圖的基石。
- `drawLine` 用 **Bresenham 演算法**：只用整數加法、減法與符號判斷，以誤差項決定主軸每一步是否該在另一軸前進；任意斜率、任意方向皆可。
- `drawRectangle` 填滿每一列的掃描線；可最佳化為「完整字一次寫入」以快 16 倍。
- `drawCircle` 利用圓的對稱性：每列以 `dx = sqrt(r²-dy²)` 算出半寬、用 `drawLine` 畫一條水平弦，層層填成實心圓。
- 所有幾何都建立在 `Math` 的 `abs` / `multiply` / `sqrt` 之上，再次印證「OS 各類別彼此依賴、形成一條完整的抽象鏈」。
