第五章 從晶片到電腦：系統整合與實作

前言

在前面的章節中，我們已經從最基本的 NAND 閘一路構建出 ALU、暫存器、記憶體等關鍵元件。現在，是時候將所有零件組裝在一起，真正「建造」出一台電腦了。本章將帶你完成 Hack 電腦的最後一塊拼圖——中央處理器（CPU），並逐步整合記憶體與 ROM，最終形成一台完整運作的電腦。這不僅是課程的高潮，更是一次從零開始理解「電腦究竟是什麼」的深刻體驗。

5.1 Hack 中央處理器（CPU）結構設計

CPU 的組成概覽

Hack CPU 是整個電腦系統的核心大腦。它的任務很簡單：從記憶體中讀取指令，解碼指令的含義，然後執行相應的運算。整個 CPU 由以下幾個關鍵模組組成：

  • ALU（算術邏輯單元）：執行算術與邏輯運算
  • A 暫存器：存放當前 A 指令的常數值，或作為記憶體位址的間接暫存器
  • D 暫存器：存放運算的資料值
  • PC（程式計數器）：指向下一個要執行的指令位址
  • 指令暫存器：暫存當前從記憶體讀取的指令
  • 控制邏輯：解碼指令並產生所有控制信號

CPU 的輸入輸出介面

理解 CPU 的介面是理解其運作方式的第一步：

輸入：

輸入訊號 位元寬度 說明
inM 16-bit 從記憶體讀取的資料
instruction 16-bit 從 ROM 讀取的當前指令
reset 1-bit 重設信號，將 PC 歸零

輸出：

輸出訊號 位元寬度 說明
outM 16-bit 要寫入記憶體的資料
writeM 1-bit 記憶體寫入使能訊號
addressM 15-bit 記憶體位址（A 暫存器的值）
pc 15-bit 程式計數器的輸出值

A-指令與 C-指令的解碼

Hack 架構定義了兩種指令格式：

A-指令（0vvvvvvvvvvvvvvv）：

  • 最高位元為 0，表示這是一個 A-指令
  • 低 15 位元為常數值
  • 執行動作：將常數值載入 A 暫存器

C-指令（111accccccdddjjj）：

  • 最高位元為 1，表示這是一個 C-指令
  • a 位元：決定 ALU 的第二個輸入來源（0=A 暫存器，1=M 暫存器）
  • cccccc：6 位元的 ALU 控制碼
  • ddd：目標暫存器編碼（決定結果寫入何處）
  • jjj：跳躍條件編碼

設計思路與實作步驟

  1. 解碼先行：CPU 首先判斷指令類型（A-指令或 C-指令），提取各控制欄位
  2. ALU 計算：根據 C-指令的 acccccc 控制碼執行運算
  3. 結果路由：根據 ddd 欄位決定將 ALU 結果寫入哪個暫存器
  4. 跳躍判定：根據 jjj 欄位與 ALU 的狀態旗標決定是否跳躍
  5. PC 更新：若需跳躍則載入 A 暫存器的值作為下一指令位址，否則遞增

硬佈線控制的概念

Hack CPU 採用**硬佈線控制（Hardwired Control）**而非微程式控制。這意味著：

  • 控制信號完全由指令的位元欄位直接產生
  • 沒有任何微碼（microcode）或控制暫存器
  • 所有解碼邏輯都由簡單的邏輯閘（NOT、AND、OR、MUX）構成
  • 效率極高，但灵活性有限——這正是 RISC 架構的精髓

這種設計讓我們清楚看到：一台電腦的控制邏輯，本質上就是一組組合邏輯電路，將指令位元「翻譯」成硬體控制訊號。

本章小結

  • Hack CPU 由 ALU、A 暫存器、D 暫存器、PC 和控制邏輯組成
  • CPU 透過 instruction 輸入接收指令，透過 addressM、outM、writeM 與記憶體互動
  • A-指令直接將常數載入 A 暫存器；C-指令經過解碼後驅動 ALU 與暫存器
  • 跳躍控制由 ALU 的狀態旗標與 j 欄位共同決定
  • 硬佈線控制使整個 CPU 的解碼過程純粹由組合邏輯完成
