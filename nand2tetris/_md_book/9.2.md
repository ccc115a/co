# 9.2 物件、陣列與指標的底層本質

## 學習目標

- 解釋物件在 Hack 記憶體（heap）中的實際布局
- 說明 `field` 欄位如何被編譯器映射為記憶體偏移量
- 理解 `this` 指標的本質：它就是物件在 heap 上的起始位址
- 說明 Jack 陣列在底層如何用 `Array.new` 分配、用偏移量存取
- 理解「指標運算」在 Jack 中如何被隱含地實現

## 前言

在 9.1 節中，你已經學會了 Jack 語言的語法。但作為一本「從 0 到 1 手寫電腦」的書，我們不滿足於「會用」——我們要知道**每一行 Jack 程式在記憶體裡到底做了什麼**。

這才是計算機科學家的思维方式：當你寫下 `p.x = 5` 時，腦海中浮現的不應該是「設定物件 p 的 x 欄位」，而是「把數值 5 寫入以 p 的位址為基底、偏移量為 0 的記憶體位置」。

本節揭開 Jack 語言的物件導向和陣列運算背後的**記憶體真相**。讀完後，你會發現：

- **物件 = heap 上的一段連續記憶體**
- **`this` = 物件在 heap 上的起始位址**
- **`field` 欄位 = 起始位址 + 偏移量**
- **陣列 = 也是物件，元素 = 起始位址 + 索引 × 2**
- **「指標」在 Jack 中並不存在，但陣列和物件已經提供了等價的能力**

## 1. 物件在記憶體中的表示

### 1.1 Heap：物件的家

Jack 程式的記憶體分為幾個區域：

```
記憶體位址空間（16-bit，0 ~ 32767）
┌───────────────┐ 0
│  Registers     │ 0-15      (R0-R15)
├───────────────┤ 16
│  Stack          │ 256-2047  (VM stack)
├───────────────┤ 2048
│  Heap (動態)    │ 2048-16383 (物件 + 陣列)
├───────────────┤ 16384
│  Screen (映射)  │ 16384-24575 (螢幕記憶體)
├───────────────┤ 24576
│  Keyboard (映射) │ 24576    (鍵盤輸入)
└───────────────┘
```

當你寫 `var Point p; let p = Point.new(3, 4);` 時：

1. `Point.new(3, 4)` 呼叫 constructor
2. constructor 內部會呼叫 `Memory.alloc(2)`（兩個 `int` 欄位 × 每個 1 word）
3. `Memory.alloc` 從 heap 中找到足夠大的空位，回傳起始位址
4. 這個位址被存入 `p`（本質上，`p` 就是一個 16-bit 整數 = 位址）

### 1.2 物件的內部布局

假設 `Point` 類別有兩個 `int` 欄位：

```jack
class Point {
    field int x;    // 偏移量 0
    field int y;    // 偏移量 1
}
```

當 `Point.new(3, 4)` 執行後，heap 中的記憶體狀態如下：

```
Heap 位址     內容         說明
──────────────────────────────────
2048          3           p.x（偏移 0）
2049          4           p.y（偏移 1）
```

變數 `p` 的值是 `2048`（heap 起始位址）。

### 1.3 操作物件的底層翻譯

當你在 Jack 中寫：

```jack
let p.x = 5;
```

編譯器將它翻譯成：

```
// p.x = 5  →  把 p 的位址 push 進 stack，再把 5 push 進 stack，然後 pop
push p       // 把 p 的值（2048）推入 stack
push 5       // 把常數 5 推入 stack
pop this 0   // 把 5 寫入 this[0]（即位址 2048 + 0 = 2048）
```

而方法呼叫 `p.move(1, 2)` 翻譯成：

```
// p.move(1, 2)
push p       // 把 p（this）作為第一隱含參數推入
push 1       // 參數 dx = 1
push 2       // 參數 dy = 2
call Point.move 3  // 呼叫方法（共 3 個參數 = 1 this + 2 顯式）
```

在 `Point.move` 方法內部，`this` segment 的映射是：

```
this 0 → p.x（偏移 0）
this 1 → p.y（偏移 1）
```

所以 `let x = x + dx` 翻譯為：

```
push this 0    // 讀取 p.x
push argument 1  // 讀取 dx
add
pop this 0     // 寫回 p.x
```

> **設計思路**：這就是為什麼 `method` 不能在 `function` 中呼叫——`method` 的第一參數隱含為 `this`（物件位址），如果沒有物件位址，`this` segment 的映射就是空的，記憶體存取會出錯。而 `constructor` 為什麼要 `return this`？因為呼叫者需要拿到新配到的位址，才能對它進行後續操作。

## 2. this 指標的概念

### 2.1 this 是什麼？

在 Jack 中，`this` 是一個**關鍵字**，代表當前正在執行的物件的位址。它在底層的實現非常直接：

- 當一個 `method` 被呼叫時，編譯器確保 `this` segment 指向正確的物件位址
- 當一個 `function` 執行時，`this` segment 的內容是**未定義的**（不該去讀它）

這就像 C++ 語言中的 `this` 指針或 Python 中的 `self` 參數，只不過 Jack 把它完全交給編譯器和 VM 來管理。

### 2.2 this 的生命週期

```jack
class Ball {
    field int x;
    field int y;

    constructor Ball new(int ax, int ay) {
        let x = ax;
        let y = ay;
        return this;        // this = 新配到的位址
    }

    method void setX(int nx) {
        let x = nx;         // this 仍然指向同一個物件
    }

    function void staticMethod() {
        // 這裡不能用 this！static 方法沒有 this
    }
}

class Main {
    function void main() {
        var Ball b1;
        var Ball b2;

        let b1 = Ball.new(10, 20);   // this → b1 的 heap 位址
        let b2 = Ball.new(30, 40);   // this → b2 的 heap 位址

        do b1.setX(50);              // this 暫時指向 b1
        do b2.setX(60);              // this 暫時指向 b2
        // 注意：b1 和 b2 是兩個不同的物件，各有各的 this
    }
}
```

### 2.3 用 C 語言類比理解

如果你熟悉 C，可以這樣理解 Jack 的物件：

```c
// Jack: class Point { field int x; field int y; }
// Jack: var Point p;

// 等價的 C 概念：
struct Point { int x; int y; };
struct Point* p = malloc(sizeof(struct Point));  // → Memory.alloc(2)
p->x = 5;    // → push p, push 5, pop this 0
p->y = 10;   // → push p, push 10, pop this 1
```

唯一差別：C 讓你直接操作指標（`struct Point*`），Jack 則把指標隱藏在物件型別背後。但底層機制完全相同。

## 3. 陣列在記憶體中的表示

### 3.1 陣列就是物件

在 Jack 中，`Array` 是一個內建類別。当你寫：

```jack
var Array arr;
let arr = Array.new(5);
```

`Array.new(5)` 做了什麼？

1. 呼叫 `Memory.alloc(5)`，配到 5 個 word 的連續記憶體
2. 回傳起始位址（例如 3000）

陣列在記憶體中的樣子：

```
Heap 位址     arr[i]     值
──────────────────────────────
3000          arr[0]     （未初始化）
3001          arr[1]     （未初始化）
3002          arr[2]     （未初始化）
3003          arr[3]     （未初始化）
3004          arr[4]     （未初始化）
```

變數 `arr` 本身的值是 `3000`——它就是一個**指到位址 3000 的指標**。

### 3.2 陣列元素的存取

```jack
let arr[2] = 42;
```

這在 VM 層被翻譯為：

```
push arr      // 把 arr 的值（3000）推入 stack
push 2        // 把索引 2 推入 stack
add           // 3000 + 2 = 3002（目標位址）
push 42       // 把值 42 推入
pop           // 寫入位址 3002
```

**關鍵洞察**：`arr[i]` 在底層就是 `arr + i` 的位址運算。沒有任何特殊機制，純粹是算術。

### 3.3 為什麼 Jack 只支援一維陣列？

因為底層已經自然支持多維：

```jack
// 模擬 3×4 的二維陣列
var Array matrix;
let matrix = Array.new(12);    // 3 * 4 = 12 個元素

// 存取 matrix[row][col]：
// matrix[(row * 4) + col]
let matrix[(row * 4) + col] = value;
```

不需要語言特性的支援，**數學就解決了**。

### 3.4 陣列與物件的關係

仔細想想：

| 操作 | 物件 | 陣列 |
|------|------|------|
| 建立 | `Point.new()` → `Memory.alloc(2)` | `Array.new(5)` → `Memory.alloc(5)` |
| 存取 | `p.x` → `push p, push 0, add, pop this` | `arr[2]` → `push arr, push 2, add, pop` |
| 位址 | 物件起始位址 + 欄位偏移 | 陣列起始位址 + 索引 |

**物件和陣列在底層是同一種東西**：heap 上的一段連續記憶體，透過起始位址和偏移量來存取。差別只在語意層面——物件有命名欄位，陣列用數字索引。

> **設計思路**：這也是為什麼 Jack 把陣列叫做「物件」而非「原始型別」。`Array.new(5)` 和 `Point.new()` 都呼叫 `Memory.alloc`，都回傳一個位址。在 Hack 硬體眼中，它們完全相同——只是人為的語意區分。理解這一點，你就理解了「物件導向」的底層本質：**物件導向 = 記憶體位址 + 偏移量查表**。

## 4. 指標運算的本質

### 4.1 Jack 沒有明確的指標型別，但處處是指標

Jack 語言沒有像 C 那樣的 `*`（取值）和 `&`（取址）運算符。但實際上，**物件變數和陣列變數本身就是指標**。

```jack
var Point p;     // p 是一個指標（位址），指向 heap 上的 Point 物件
var Array arr;   // arr 是一個指標（位址），指向 heap 上的陣列
```

兩者都是 16-bit 整數，儲存的是 heap 位址。

### 4.2 指標運算 = 陣列存取

在 C 中你會寫：

```c
int* p = malloc(10 * sizeof(int));
p[3] = 42;        // 指標運算
*(p + 3) = 42;    // 等價寫法
```

在 Jack 中完全等價：

```jack
var Array p;
let p = Array.new(10);
let p[3] = 42;    // 陣列存取 = 指標運算
```

底層 VM 碼完全相同：

```
push p          // 基底位址
push 3          // 偏移量
add             // 目標位址
push 42         // 值
pop             // 寫入
```

### 4.3 物件型別的「指標加法」

```jack
// 假設有一個物件 p 在位址 2000，有三個 int 欄位
// p.x = p[0]，p.y = p[1]，p.z = p[2]

// 這在概念上等同於：
// *(p + 0) = 5    → p.x = 5
// *(p + 1) = 10   → p.y = 10
// *(p + 2) = 15   → p.z = 15
```

### 4.4 實際的 VM 指令翻譯對照

以下是 Jack 程式到 VM 指令的完整翻譯對照：

```jack
// Jack 原始碼              // VM 指令                    // 實際記憶體操作
let p.x = 5;               // push p                     // 2000 → stack
                           // push 5                     // 5 → stack
                           // pop this 0                 // stack → M[2000]

let arr[3] = 42;           // push arr                   // 3000 → stack
                           // push 3                     // 3 → stack
                           // add                        // 3003 → stack
                           // push 42                    // 42 → stack
                           // pop                        // stack → M[3003]

let p.y = p.x + 1;        // push this 0                // M[2000] → stack
                           // push 1                     // 1 → stack
                           // add                        // 結果 → stack
                           // pop this 1                 // stack → M[2001]
```

## 5. 底層記憶體配置的關係

### 5.1 Memory.alloc 的角色

所有物件和陣列的記憶體配置都通過 `Memory.alloc` 函式（第 12 章會實作它）。它從 heap 中分配一塊連續空間，回傳起始位址。

```jack
// 這些呼叫在底層完全等價（都呼叫 Memory.alloc）
Point.new()           → Memory.alloc(2)    // 2 個 field
Ball.new()            → Memory.alloc(4)    // 4 個 field
Array.new(10)         → Memory.alloc(10)   // 10 個元素
```

### 5.2 物件大小的計算

編譯器在編譯時就能決定物件的大小：

```
物件大小 = 該類別的 field 數量（每個 field 佔 1 個 word）
```

例如：

```jack
class Player {
    field int x;          // 偏移 0
    field int y;          // 偏移 1
    field int score;      // 偏移 2
    field boolean alive;  // 偏移 3
}
// Player.new() → Memory.alloc(4)
```

### 5.3 完整的記憶體地圖範例

假設執行以下程式：

```jack
class Main {
    static Array table;
    field int x;
    field int y;

    constructor Main new(int ax, int ay) {
        let x = ax;
        let y = ay;
        return this;
    }

    function void main() {
        var Main m1;
        var Main m2;
        var Array arr;

        let table = Array.new(3);
        let m1 = Main.new(10, 20);
        let m2 = Main.new(30, 40);
        let arr = Array.new(5);
        let arr[0] = 99;
        let arr[1] = 88;
        let m1.x = 50;
        let m2.y = 60;
    }
}
```

記憶體狀態（假設 `table` 位址為 100，`m1` 為 200，`m2` 為 202，`arr` 為 300）：

```
位址   變數/欄位           值      說明
─────────────────────────────────────────
static: table            100     Array 在 heap 的起始位址
100    table[0]          ???     （未初始化）
101    table[1]          ???
102    table[2]          ???

static: m1               200     Main 物件在 heap 的起始位址
static: m2               202     Main 物件在 heap 的起始位址
200    m1.x              50
201    m1.y              20
202    m2.x              30
203    m2.y              60

static: arr              300     Array 在 heap 的起始位址
300    arr[0]            99
301    arr[1]            88
302    arr[2]            ???
303    arr[3]            ???
304    arr[4]            ???
```

## 6. 常見陷阱與重要注意事項

### 6.1 未初始化的物件不能使用

```jack
var Point p;
// let p.x = 5;    ← 錯誤！p 還沒有指向任何物件
let p = Point.new(0, 0);
let p.x = 5;       // 正確
```

未初始化的物件變數儲存的值是隨機的（heap 中某個位置），對它進行存取會讀寫到不該碰的地方。

### 6.2 陣列的邊界不檢查

```jack
var Array arr;
let arr = Array.new(3);   // 只有 3 個元素（index 0, 1, 2）
let arr[5] = 42;          // 不會報錯，但會寫到不屬於 arr 的記憶體！
```

這和 C 語言一樣——陣列邊界由你自己負責，語言和編譯器不保證安全。這是效率與安全的經典取捨。

### 6.3 所有物件大小相同嗎？

不。物件大小取決於該類別的 `field` 數量。每個 `field` 佔 1 個 word（16-bit）。`static` 變數不佔物件空間（它們在別的位址，由編譯器分配）。

### 6.4 物件可以被 GC 嗎？

Jack 的標準 OS 實作中**沒有 garbage collector**。你分配了記憶體（`Memory.alloc`），就要自己釋放（`Memory.deAlloc`）。在實際的遊戲開發中，這需要謹慎管理——第 12 章的 Memory 模組會提供 `dealloc` 功能。

## 本章小結

- **物件在記憶體中 = heap 上的一段連續記憶體**，起始位址就是物件的「代表值」。
- **`this` 指標的本質**：就是物件在 heap 上的起始位址，由編譯器在方法呼叫時自動傳入 VM 的 `this` segment。
- **`field` 欄位 = 起始位址 + 偏移量**：編譯器在編譯時就確定了每個 field 的偏移量，產生對應的 `push this N` / `pop this N` 指令。
- **陣列 = 也是物件**：`Array.new(N)` 呼叫 `Memory.alloc(N)`，回傳的位址就是陣列的「基底」，`arr[i]` 翻譯為「基底 + i」的記憶體運算。
- **指標運算的本質**：Jack 沒有明確的指標型別，但物件變數和陣列變數本身就是指標（儲存 heap 位址），陣列存取 `arr[i]` 本質上就是指標 + 偏移量的運算。
- **物件大小由 field 數量決定**：每個 field 佔 1 個 word（16-bit），編譯器在編譯時計算，傳給 `Memory.alloc`。
- **記憶體配置全部通過 `Memory.alloc`**：物件和陣列的底層機制完全相同，差別只在語意層。

這些理解將在第 11 章的編譯器實作中至關重要——當你生成 VM 碼時，你必須知道每個 `field` 的偏移量、每個 `static` 的位址、每次 `new` 需要 `alloc` 多少空間。**現在你懂了記憶體真相，寫編譯器時就不會心虛**。
