## 5.1 Hack 中央處理器（CPU）結構設計

### CPU 的組成概覽

Hack CPU 是整個電腦系統的核心大腦。它的任務很簡單：從記憶體中讀取指令，解碼指令的含義，然後執行相應的運算。整個 CPU 由以下幾個關鍵模組組成：

- **ALU（算術邏輯單元）**：執行算術與邏輯運算
- **A 暫存器**：存放當前 A 指令的常數值，或作為記憶體位址的間接暫存器
- **D 暫存器**：存放運算的資料值
- **PC（程式計數器）**：指向下一個要執行的指令位址
- **指令暫存器**：暫存當前從記憶體讀取的指令
- **控制邏輯**：解碼指令並產生所有控制信號

### CPU 的輸入輸出介面

理解 CPU 的介面是理解其運作方式的第一步：

**輸入：**
| 輸入訊號 | 位元寬度 | 說明 |
|-----------|----------|------|
| `inM` | 16-bit | 從記憶體讀取的資料 |
| `instruction` | 16-bit | 從 ROM 讀取的當前指令 |
| `reset` | 1-bit | 重設信號，將 PC 歸零 |

**輸出：**
| 輸出訊號 | 位元寬度 | 說明 |
|-----------|----------|------|
| `outM` | 16-bit | 要寫入記憶體的資料 |
| `writeM` | 1-bit | 記憶體寫入使能訊號 |
| `addressM` | 15-bit | 記憶體位址（A 暫存器的值） |
| `pc` | 15-bit | 程式計數器的輸出值 |

### A-指令與 C-指令的解碼

Hack 架構定義了兩種指令格式：

**A-指令（`0vvvvvvvvvvvvvvv`）：**
- 最高位元為 0，表示這是一個 A-指令
- 低 15 位元為常數值
- 執行動作：將常數值載入 A 暫存器

**C-指令（`111accccccdddjjj`）：**
- 最高位元為 1，表示這是一個 C-指令
- `a` 位元：決定 ALU 的第二個輸入來源（0=A 暫存器，1=M 暫存器）
- `cccccc`：6 位元的 ALU 控制碼
- `ddd`：目標暫存器編碼（決定結果寫入何處）
- `jjj`：跳躍條件編碼

### CPU HDL 實作

以下是完整的 `CPU.hdl` 實作：

```hdl
// Hack CPU：取指-解碼-執行
// 檔案：CPU.hdl

CHIP CPU {
    IN  inM[16],         // 從記憶體讀取的資料
        instruction[16], // 從 ROM 讀取的指令
        reset;           // 重設信號

    OUT outM[16],        // 輸出至記憶體的資料
        writeM,          // 是否要寫入記憶體
        addressM[15],    // 輸出至記憶體的位址
        pc[15];          // 程式計數器

    PARTS:

    // ============================================================
    // 第一步：解碼 instruction 的控制位元
    // ============================================================

    // 判斷是否為 A-指令：instruction[15] == 0
    Not(a=instruction[15], out=isAInstruction);

    // 從 C-指令中提取各控制欄位
    // a 位元：instruction[12] — 決定 ALU 第二輸入是 A 還是 M
    // c 欄位：instruction[6..11] — ALU 控制碼
    // d 欄位：instruction[3..5]  — 目標暫存器
    // j 欄位：instruction[0..2]  — 跳躍條件

    // ============================================================
    // 第二步：A 暫存器的輸入多工器（MUX）
    // A 暫存器在不同情況下載入不同的值：
    //   - A-指令：載入指令中的常數值
    //   - C-指令且 d1=1：載入 ALU 的輸出
    // ============================================================

    // 取得 A 暀存器的值（也用作 addressM 的輸出）
    // A 暫存器的輸入來源：
    //   isAInstruction=1 → instruction[0..14]（A-指令的常數）
    //   isAInstruction=0 → ALU out（C-指令可能需要寫入 A）
    // 但 ALU 的輸出在後面才產生，這裡先處理 A-指令路徑
    // 用一個暫時的選擇：先讓 A 暫存器的輸入在 A-指令時為常數值
    // 在 C-指令時，由 d1 決定是否寫入 ALU 結果

    // ============================================================
    // 第三步：C-指令的執行路徑
    // ============================================================

    // 從 A 暫存器取得輸出
    // ARegister 的輸出作為：
    //   1. addressM 的來源
    //   2. ALU 的第一輸入（x）（但要經過 d1 的處理？不，A 始終是 ALU 的 x）

    // ALU 的第二輸入（y）：由 instruction[12]（a 位元）決定
    // a=0 → 取 A 暫存器的值
    // a=1 → 取 inM 的值
    Mux16(a=ARegister.out, b=inM, sel=instruction[12], out=aluY);

    // ALU 接收：
    //   x = ARegister.out（始終如此）
    //   y = aluY（由 a 位元決定）
    //   zx, nx, zy, ny, f, no = instruction[6..11]
    ALU(
        x=ARegister.out,
        y=aluY,
        zx=instruction[11],
        nx=instruction[10],
        zy=instruction[9],
        ny=instruction[8],
        f=instruction[7],
        no=instruction[6],
        out=aluOut,
        out=outZ,
        out=outN
    );

    // ============================================================
    // 第四步：目標暫存器的寫入控制（d 欄位）
    // ============================================================
    // instruction[5] = d1 → 是否寫入 A 暫存器
    // instruction[4] = d2 → 是否寫入 D 暫存器
    // instruction[3] = d3 → 是否寫入 M（記憶體）

    // A 暫存器的載入控制：
    // 如果是 A-指令，總是載入
    // 如果是 C-指令，由 d1（instruction[5]）決定
    Or(a=isAInstruction, b=instruction[5], out=loadA);

    // A 暫存器的輸入多工器：
    // isAInstruction=1 → instruction[0..14]
    // isAInstruction=0 → aluOut
    Mux16(a=aluOut, b=instruction[0..14], sel=isAInstruction, out=aRegIn);

    // A 暫存器本體
    Register(in=aRegIn, load=loadA, out=ARegister.out, out[0..14]=addressM);

    // D 暫存器的載入控制：由 d2（instruction[4]）決定
    // D 暫存器只在 C-指令時才可能被寫入
    And(a=instruction[4], b=isAInstruction, out=notUsed);

    // 注意：D 暫存器只在 C-指令（isAInstruction=0）且 d2=1 時載入
    // 實際上 shouldLoadD = NOT(isAInstruction) AND instruction[4]
    // 但 isAInstruction=0 表示 C-指令，所以：
    Not(a=isAInstruction, out=isCInstruction);
    And(a=isCInstruction, b=instruction[4], out=loadD);

    // D 暫存器本體
    Register(in=aluOut, load=loadD, out=DRegister.out);

    // ============================================================
    // 第五步：記憶體寫入控制
    // ============================================================
    // writeM = C-指令 且 d3=1
    And(a=isCInstruction, b=instruction[3], out=writeM);

    // outM = ALU 的輸出（要寫入記憶體的資料）
    // outM 在 C-指令且 d3=1 時才有效，但線路上我們直接連接 ALU 輸出
    And(a=aluOut, b=aluOut, out=outM); // 直接傳遞 ALU 輸出

    // ============================================================
    // 第六步：跳躍控制（j 欄位）
    // ============================================================
    // j 欄位（instruction[0..2]）決定跳躍條件：
    //   j1=instruction[2], j2=instruction[1], j3=instruction[0]
    //
    // 跳躍條件：
    //   outgt = outN=0 AND outZ=0    （結果 > 0）
    //   outeq = outZ=1                （結果 = 0）
    //   outlt = outN=1                （結果 < 0）
    //
    // shouldJump = (j1 AND outgt) OR (j2 AND outeq) OR (j3 AND outlt)
    // 但要注意：只能在 C-指令時才跳躍

    // 計算跳躍條件
    Not(a=outN, out=notN);
    Not(a=outZ, out=notZ);
    And(a=notN, b=notZ, out=outGt);   // out > 0

    And(a=instruction[2], b=outGt, out=jmpGt);
    And(a=instruction[1], b=outZ,  out=jmpEq);
    And(a=instruction[0], b=outN,  out=jmpLt);

    Or(a=jmpGt, b=jmpEq, out=jmpGtOrEq);
    Or(a=jmpGtOrEq, b=jmpLt, out=shouldJumpRaw);

    // 跳躍只在 C-指令時生效
    And(a=shouldJumpRaw, b=isCInstruction, out=shouldJump);

    // ============================================================
    // 第七步：PC（程式計數器）
    // ============================================================
    PC(
        in=ARegister.out[0..14],
        load=shouldJump,
        inc=true,
        reset=reset,
        out[0..14]=pc
    );
}
```

> **注意**：上述 HDL 為教學用途的詳細展開版本。在實際的硬體模擬器中，部分連線需要精確對齊埠口寬度。不同版本的硬體模擬器對埠口名稱可能略有差異。

### 設計思路與實作步驟

1. **解碼先行**：CPU 首先判斷指令類型（A-指令或 C-指令），提取各控制欄位
2. **ALU 計算**：根據 C-指令的 `acccccc` 控制碼執行運算
3. **結果路由**：根據 `ddd` 欄位決定將 ALU 結果寫入哪個暫存器
4. **跳躍判定**：根據 `jjj` 欄位與 ALU 的狀態旗標決定是否跳躍
5. **PC 更新**：若需跳躍則載入 A 暫存器的值作為下一指令位址，否則遞增

### 硬佈線控制的概念

Hack CPU 採用**硬佈線控制（Hardwired Control）**而非微程式控制。這意味著：

- 控制信號完全由指令的位元欄位直接產生
- 沒有任何微碼（microcode）或控制暫存器
- 所有解碼邏輯都由簡單的邏輯閘（NOT、AND、OR、MUX）構成
- 效率極高，但灵活性有限——這正是 RISC 架構的精髓

這種設計讓我們清楚看到：一台電腦的控制邏輯，本質上就是一組組合邏輯電路，將指令位元「翻譯」成硬體控制訊號。

### 本章小結

- Hack CPU 由 ALU、A 暫存器、D 暫存器、PC 和控制邏輯組成
- CPU 透過 `instruction` 輸入接收指令，透過 `addressM`、`outM`、`writeM` 與記憶體互動
- A-指令直接將常數載入 A 暫存器；C-指令經過解碼後驅動 ALU 與暫存器
- 跳躍控制由 ALU 的狀態旗標與 j 欄位共同決定
- 硬佈線控制使整個 CPU 的解碼過程純粹由組合邏輯完成
