7.2 堆疊（Stack）資料結構與運算機制

前言

上一節我們理解了 VM 為什麼存在——它是高階語言與機器碼之間的橋樑。而 VM 的心臟，就是堆疊（Stack）。

堆疊是電腦科學中最基礎也最重要的資料結構之一。它的規則只有一條：最後放進去的，最先拿出來（Last In, First Out，簡稱 LIFO）。看起來很簡單，但它能表達出所有算術運算、函式呼叫、暫存器保存的語意。事實上，Nand2Tetris 的 VM 所有算術與邏輯運算都完全依賴堆疊——沒有堆疊，VM 就無法運作。

本節的目標是搞清楚三件事：堆疊的概念、VM 中的堆疊模型、以及如何在 Hack 硬體上實作堆疊。

1. 堆疊的基本概念：一疊盤子

堆疊最直覺的比喻就是一疊盤子：

  狀態 0（空的）       狀態 1（push 7）    狀態 2（push 3）    狀態 3（pop）
                                                      
     ┌───┐              ┌───┐              ┌───┐        ┌───┐
     │   │              │   │              │ 3 │ ← 頂   │   │
     ├───┤              ├───┤              ├───┤        ├───┤
     │   │              │ 7 │ ← 頂         │ 7 │        │ 7 │ ← 頂
     ├───┤              ├───┤              ├───┤        ├───┤
     │   │              │   │              │   │        │   │
     └───┘              └───┘              └───┘        └───┘

規則：

  • push：把新盤子放到最頂端
  • pop：從最頂端拿走一個盤子
  • 你永遠只能操作最頂端的盤子——不能從中間抽、不能從底部抽

1.1 LIFO：最後進，最先出

堆疊的 LIFO 特性意味著：

push 7 → push 3 → push 8 → pop → pop → pop
                                  ↓     ↓     ↓
                              拿到 8   拿到 3   拿到 7

順序完全反轉——這是堆疊最關鍵的性質。在 VM 中，這個性質讓我們可以用「先壓入、後取出」的方式來保存和恢復中間狀態。

2. VM 中的堆疊模型

在 Nand2Tetris 的 VM 中，堆疊是一個概念模型——它是一塊連續的記憶體空間，加上一個指向頂端的指標。

2.1 堆疊的運作圖

假設我們執行以下 VM 指令：

push constant 7
push constant 3
add

過程如下：

步驟 1：push constant 7

RAM 位址:   256   257   258   259  ...
            ┌───┐ ┌───┐ ┌───┐ ┌───┐
內容:       │ 7 │ │   │ │   │ │   │
            └───┘ └───┘ └───┘ └───┘
              ↑
              SP (stack pointer) = 257
              （指向「下一個可用位址」，即頂端的下一位）
  • 把值 7 寫入 RAM[256]（當前堆疊頂端）
  • SP 從 256 變成 257（向上移一格）

步驟 2：push constant 3

RAM 位址:   256   257   258   259
            ┌───┐ ┌───┐ ┌───┐ ┌───┐
內容:       │ 7 │ │ 3 │ │   │ │   │
            └───┘ └───┘ └───┘ └───┘
                    ↑
                    SP = 258
  • 把值 3 寫入 RAM[257]
  • SP 從 257 變成 258

步驟 3：add

  pop 取出 3（SP-1 位置）     pop 取出 7（SP-2 位置）
  pop 取出 7
  計算 7 + 3 = 10
  push 結果 10

RAM 位址:   256   257   258
            ┌───┐ ┌───┐ ┌───┐
內容:       │ 10│ │   │ │   │
            └───┘ └───┘ └───┘
              ↑
              SP = 257
  • 從 RAM[257] 取出 3，從 RAM[256] 取出 7
  • 計算 7 + 3 = 10
  • 把 10 寫回 RAM[256]
  • SP 從 258 變成 257（兩個運算元消失了，一個結果填進來）

2.2 Stack Pointer（SP）：堆疊的靈魂

堆疊的核心是堆疊指標（Stack Pointer，簡稱 SP）。SP 是一個變數，它的值永遠是「堆疊頂端的下一個可用位址」。

SP 的定義：
  SP 指向的位置 = 堆疊中「下一個空位」的位址
  堆疊頂端的值 = RAM[SP - 1]

為什麼 SP 指向「下一個空位」而不是「最後一個有值的位址」？因為這樣 push 和 pop 的操作最簡單：

push v:   RAM[SP] = v;  SP = SP + 1     // 先放、再移
pop:      SP = SP - 1;  x = RAM[SP]     // 先移、再拿

兩種順序都只要一條寫入 + 一條加減，不需要任何條件判斷。這是「哨兵值」（sentinel value）設計模式的經典應用。

2.3 運算指令在堆疊上的運作模式

所有算術與邏輯指令都遵循同一個模式，稱為 pop-binary-op 或 pop-unary-op：

二元運算（如 add、sub、eq）：

  ① 從 SP-1 取出第二個運算元（y）
  ② 從 SP-2 取出第一個運算元（x）
  ③ 計算 x op y
  ④ 把結果寫回 SP-2
  5  SP = SP - 1

一元運算（如 neg、not）：

  ① 從 SP-1 取出運算元（x）
  ② 計算 op x
  ③ 把結果寫回 SP-1
  （SP 不變）

視覺化二元運算：

  add 前:                         add 後:
  ┌───┐                           ┌───┐
  │ y │ ← SP-1  第二運算元        │   │
  ├───┤                           ├───┤
  │ x │ ← SP-2  第一運算元        │x+y│ ← SP-1  結果
  ├───┤                           ├───┤
  │   │                           │   │
  └───┘                           └───┘
    SP                                SP

設計思路：為什麼運算結果要「覆蓋」到 SP-2 的位置？因為運算消耗了兩個運算元、產生了一個結果——堆疊深度從 n 變成 n-1。把結果放在 SP-2、再把 SP 減 1，就精確地實現了這個效果。如果放在 SP-1 而不減 SP，堆疊會「溢出」一個空位；放在 SP-3 那就更不對了。這個「結果覆蓋第一運算元」的模式是所有 VM 實作的共同慣例。

3. 在 Hack 硬體上實作堆疊

Hack 硬體本身沒有「堆疊」的概念——它只有 RAM、A 暫存器、D 暫存器。所以 VM 翻譯器必須用 Hack 的記憶體來模擬堆疊。

3.1 堆疊在 Hack RAM 中的位置

根據 Nand2Tetris 的記憶體佈局規範：

  Hack RAM 位址空間（共 32768 個 word）：

  ┌──────────────────┐ 0
  │   R0 - R15       │   ← 16 個暫存器（SP 存在 R0，即 RAM[0]）
  ├──────────────────┤ 16
  │   (預留)         │
  ├──────────────────┤ 256
  │   堆疊（Stack）   │   ← 全域堆疊從位址 256 開始
  ├──────────────────┤ 2048
  │   LCL 段         │   ← 本地變數
  ├──────────────────┤
  │   ARG 段         │   ← 引數
  ├──────────────────┤
  │   THIS 段        │   ← 一般用途段 1
  ├──────────────────┤
  │   THAT 段        │   ← 一般用途段 2
  ├──────────────────┤
  │   (可用 RAM)      │
  ├──────────────────┤ 16384
  │   螢幕記憶體映射   │
  ├──────────────────┤ 24576
  │   鍵盤記憶體映射   │
  └──────────────────┘ 32768

堆疊從位址 256 開始，向下延伸（朝向更高的位址）。SP 初始值為 256，表示堆疊是空的。

3.2 SP 存在 RAM[0]

SP 本身也是 RAM 中的一個值。Nand2Tetris 把它放在 RAM[0]（也就是 R0）：

RAM[0] = SP（堆疊指標）
初始值：SP = 256

所以 push constant 7 的 Hack 組合語言翻譯，核心邏輯是：

// push constant 7 的翻譯
@7          // 把常數 7 載入 A
D=A         // D = 7
@SP         // A = SP 的位址（即 RAM[0]）
A=M         // A = SP 的值（即 256）
M=D         // RAM[256] = 7（把值放進堆疊頂端）
@SP         // A = 0（SP 的位址）
M=M+1       // SP = SP + 1（指標上移）

六條指令，就完成了一次 push。

3.3 Pop 的 Hack 翻譯

pop 是 push 的反操作——把堆疊頂端的值取出並丟棄（或存到別處）：

// pop（通用框架：取出值但不存到特定地方）
@SP         // A = 0
M=M-1       // SP = SP - 1（指標下移）
A=M         // A = SP 的值（指向剛才的頂端）
D=M         // D = RAM[SP]（取出值）

三條指令。如果是要把 pop 的值存到某個位址（例如 pop local 2），就再加上「把 D 寫到目標位址」的指令。

3.4 完整的 push/pop 對照表

操作 VM 指令 Hack 行為 大約指令數
push constant push constant 7 D=7; RAM[SP]=D; SP++ 6
push segment push local 0 取 segment[0] 的值; RAM[SP]=值; SP++ 12-14
pop segment pop local 0 SP--; 取值; 寫到 segment[0] 12-14
二元運算 add 取兩個值; 相加; 寫回; SP-- 10-12
一元運算 neg 取一個值; 取負; 寫回 6-8

4. 堆疊操作的完整 Hack 翻譯範例

4.1 完整範例：push constant 17

VM 指令：push constant 17

翻譯成 Hack 組合語言：

// push constant 17
@17         // A = 17（常數值）
D=A         // D = 17
@SP         // A = 0（SP 的 RAM 位址）
A=M         // A = SP 的值（例如 256）
M=D         // RAM[256] = 17
@SP         // A = 0
M=M+1       // SP = 257

逐行解說：

行 Hack 指令 效果 狀態變化
1 @17 A = 17 A: 17
2 D=A D = 17 D: 17
3 @SP A = 0 A: 0
4 A=M A = RAM[0] = SP 的值 A: 256（假設 SP 初始值）
5 M=D RAM[256] = 17 RAM[256]: 17
6 @SP A = 0 A: 0
7 M=M+1 RAM[0] = 257 SP: 257

4.2 完整範例：add（二元加法）

VM 指令：add

翻譯成 Hack 組合語言：

// add
@SP         // A = 0
M=M-1       // SP = SP - 1（現在 SP 指向第二運算元）
A=M         // A = SP 的值（指向 y）
D=M         // D = y（第二運算元）
@SP         // A = 0
M=M-1       // SP = SP - 1（現在指向 x）
A=M         // A = SP 的值（指向 x）
D=M+D       // D = x + y（新值）
M=D         // RAM[SP] = x + y（結果寫回）
@SP         // A = 0
M=M+1       // SP = SP + 1（結果佔據一個位置）

逐行解說（假設堆疊頂端有 17 和 3）：

行 Hack 指令 D 的值 SP 的值 RAM[256] RAM[257]
初始 — ? 258 17 3
1-2 @SP; M=M-1 ? 257 17 3
3-4 A=M; D=M 3 257 17 3
5-6 @SP; M=M-1 3 256 17 3
7-8 A=M; D=M+D 20 256 17 3
9 M=D 20 256 20 3
10-11 @SP; M=M+1 20 257 20 3

結果：堆疊中只剩一個值 20（= 17 + 3），SP = 257。完美。

4.3 完整範例：neg（一元取負）

VM 指令：neg

翻譯成 Hack 組合語言：

// neg
@SP         // A = 0
A=M-1       // A = SP - 1（指向堆疊頂端）
D=M         // D = 頂端的值
D=-D        // D = -值（取負）
M=D         // 寫回堆疊頂端

四條指令。注意 SP 沒有改變——一元運算不改變堆疊深度。

5. 堆疊的完整操作流程追蹤

把所有觀念串起來，追蹤一個稍微複雜的 VM 程式：

push constant 7
push constant 3
push constant 5
add
sub

目標：計算 7 + 3 - 5 = 5

步驟 0（初始）:
  SP=256, RAM[256..]=[0, 0, 0, ...]

步驟 1（push 7）:
  SP=257, RAM[256]=7

步驟 2（push 3）:
  SP=258, RAM[256]=7, RAM[257]=3

步驟 3（push 5）:
  SP=259, RAM[256]=7, RAM[257]=3, RAM[258]=5

步驟 4（add = pop 5, pop 3, push 3+5=8）:
  SP=258, RAM[256]=7, RAM[257]=8

步驟 5（sub = pop 8, pop 7, push 7-8=-1）:
  SP=257, RAM[256]=-1

等等... 7 + 3 - 5 應該是 5，怎麼是 -1？

啊！這裡有一個運算元順序的問題。VM 的 sub 定義是：

sub = pop 第二個值（y），pop 第一個值（x），push x - y

所以 add 之後堆疊是 [7, 8]，sub 會算 7 - 8 = -1。但我們想要的是 (7+3) - 5 = 5。

正確的 VM 程式應該是：

push constant 7
push constant 3
add          // 堆疊：[10]
push constant 5  // 堆疊：[10, 5]
sub          // 堆疊：[10 - 5 = 5]  ✓

設計思路：VM 指令的運算元順序是嚴格的——sub 永遠是 SP-2 的值減去 SP-1 的值。這與大多數數學符號的「左減右」一致。寫 VM 代碼時，push 的順序就決定了運算的順序，這一點必須牢記。

6. 堆疊的溢出與邊界問題

在 Hack 上實作堆疊，有兩個實際問題需要注意：

6.1 堆疊溢出（Stack Overflow）

如果 push 太多次，SP 會持續增加，最終進入 LCL/ARG 段的區域，覆蓋掉那些記憶體段的值。在 Nand2Tetris 中，堆疊從 256 開始，LCL 段從 2048 開始——所以堆疊最多可以使用 1792 個 word（256 到 2047）。對教學用途綽綽有餘。

6.2 堆疊底溢出（Stack Underflow）

如果 pop 太多次，SP 會降到 256 以下，進入暫存器區域。一個好的 VM 翻譯器在 pop 前應該檢查 SP > 256，但 Nand2Tetris 的簡化版不檢查——信任你寫的 VM 程式是正確的。

6.3 實際的位址範圍

  RAM 位址 0：      SP（堆疊指標）
  RAM 位址 1-15：   R1-R15（其他暫存器）
  RAM 位址 256-2047：堆疊空間
  RAM 位址 2048+：   LCL、ARG、THIS、THAT 段

這個佈局是 Nand2Tetris 的硬性約定，VM 翻譯器的所有位址計算都基於這些數字。

7. 本章小結

  • 堆疊是 LIFO（後進先出）的資料結構：push 壓入、pop 取出，都只能操作頂端。
  • VM 中的堆疊由一個連續記憶體區段加一個 Stack Pointer（SP） 組成。
  • SP 存在 RAM[0]，初始值為 256；堆疊從 RAM 位址 256 開始向高位址延伸。
  • push 的 Hack 實作：把值寫入 RAM[SP]，然後 SP++；pop 則相反：SP--，然後取出 RAM[SP]。
  • 二元運算（如 add）取出 SP-2 與 SP-1 的值，運算後結果寫回 SP-2，SP--；一元運算（如 neg）只處理 SP-1 的值，SP 不變。
  • 堆疊操作的 Hack 翻譯模式極為規則：push constant 約 6 條指令，add 約 10 條，neg 約 4 條。
  • 運算元順序是嚴格的：先 push 的是左運算元，後 push 的是右運算元。
