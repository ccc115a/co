第十章第四節：語法樹與 XML 結構輸出測試

前言

在前面兩節中，我們已經實作了詞法分析器（JackTokenizer）和語法分析器（CompilationEngine）。現在我們需要一個方法來驗證這些組件的正確性。在 nand2tetris 的設計中，這個驗證機制就是 XML 輸出。

XML（eXtensible Markup Language）是一種標記語言，具有自描述性、結構化的特點。nand2tetris 選擇 XML 作為語法樹的表示格式，是因為 XML 可以被一般文字工具（diff、grep、自訂比對器）輕鬆處理，同時又具有清晰的層次結構。

本節將完整介紹兩種 XML 輸出格式——tokenizer 輸出的 XxxT.xml 和 parser 輸出的 Xxx.xml，並展示如何使用 nand2tetris 提供的 TextComparer 工具驗證編譯器的正確性。

10.4.1 為何使用 XML？

在教學與驗證的脈絡下，XML 有以下優勢：

  1. 自描述性：每個 token 和語法結構都帶有標籤，例如 <keyword>class</keyword> 一看就知道是什麼。
  2. 層次結構：XML 的巢狀標籤天然對應語法樹的巢狀結構。
  3. 易於比對：XML 是純文字格式，可以用簡單的字串比對工具驗證輸出是否正確。
  4. 可讀性高：人類可以直接閱讀 XML 輸出，直覺地判斷語法樹是否正確。
  5. 工具支援：nand2tetris 提供了專用的 TextComparer 工具來比對 XML 輸出。

在實際的工業級編譯器中，通常不會使用 XML——而是使用更緊湊的資料結構（如 Python 的物件、C 的 struct）。XML 的輸出純粹是為了教學驗證而設計的。

10.4.2 Tokenizer 的輸出格式（XxxT.xml）

格式規範

XxxT.xml 是 tokenizer 的輸出，格式如下：

<tokens>
  <keyword> class </keyword>
  <identifier> Main </identifier>
  <symbol> { </symbol>
  ...
  <symbol> } </symbol>
</tokens>

規則

  1. 整個輸出被包在 <tokens> 和 </tokens> 標記中
  2. 每個 token 用對應型別的標籤包圍
  3. 標籤名稱與 token 型別的對應：
Token 型別 XML 標籤
KEYWORD <keyword>
SYMBOL <symbol>
IDENTIFIER <identifier>
INT_CONST <integerConstant>
STRING_CONST <stringConstant>
  1. 關鍵字和識別碼以原始形式輸出（不是小寫）
  2. 符號以原始形式輸出，但 XML 特殊字元需要轉義
  3. 每個 token 佔一行，前面有兩個空格的縮排
  4. token 的值與標籤之間有一個空格

XML 轉義規則

以下符號在 XML 中有特殊意義，輸出時必須轉義：

原始符號 XML 轉義 出現位置
< &lt; 小於運算符
> &gt; 大於運算符
& &amp; 邏輯且運算符
" &quot; 字串常量的邊界

例如，如果 Jack 程式中有 x < 100，tokenizer 的 XML 輸出會是：

  <identifier> x </identifier>
  <symbol> &lt; </symbol>
  <integerConstant> 100 </integerConstant>

完整範例：Square.jack

假設 Square.jack 的開頭如下：

// Square.jack
// From Nand2Tetris
class Square {
    field int x, y;
    field int size;
    ...
}

對應的 SquareT.xml 輸出：

<tokens>
  <keyword> class </keyword>
  <identifier> Square </identifier>
  <symbol> { </symbol>
  <keyword> field </keyword>
  <keyword> int </keyword>
  <identifier> x </identifier>
  <symbol> , </symbol>
  <identifier> y </identifier>
  <symbol> ; </symbol>
  <keyword> field </keyword>
  <keyword> int </keyword>
  <identifier> size </identifier>
  <symbol> ; </symbol>
  <symbol> } </symbol>
</tokens>

10.4.3 Parser 的輸出格式（Xxx.xml）

格式規範

Xxx.xml 是 CompilationEngine 的輸出，使用 XML 標籤來表示語法結構的層次關係。

層次結構

每個非終端符號（文法規則的左側）對應一對 XML 標籤：

<class>
  <keyword> class </keyword>
  <identifier> Main </identifier>
  <symbol> { </symbol>
  <classVarDec>
    <keyword> field </keyword>
    <keyword> int </keyword>
    <identifier> x </identifier>
    <symbol> ; </symbol>
  </classVarDec>
  <subroutineDec>
    <keyword> function </keyword>
    <keyword> void </keyword>
    <identifier> main </identifier>
    <symbol> ( </symbol>
    <parameterList>
    </parameterList>
    <symbol> ) </symbol>
    <subroutineBody>
      <symbol> { </symbol>
      <varDec>
        <keyword> var </keyword>
        <keyword> int </keyword>
        <identifier> x </identifier>
        <symbol> ; </symbol>
      </varDec>
      <statements>
        <letStatement>
          <keyword> let </keyword>
          <identifier> x </identifier>
          <symbol> = </symbol>
          <expression>
            <term>
              <integerConstant> 3 </integerConstant>
            </term>
          </expression>
          <symbol> ; </symbol>
        </letStatement>
      </statements>
      <symbol> } </symbol>
    </subroutineBody>
  </subroutineDec>
  <symbol> } </symbol>
</class>

輸出規則

  1. 結構性標籤（非終端符號）使用文法規則名稱，例如 <class>、<statements>、<expression>
  2. 葉節點（終端符號 / token）直接輸出 token 的 XML 表示
  3. 每一層增加兩個空格的縮排
  4. 空的結構也要輸出開始與結束標籤（例如空的 <parameterList> 或 <expressionList>）

常見的結構性標籤一覽

程式結構:     class, classVarDec, subroutineDec, parameterList,
              subroutineBody, varDec

語句:         statements, letStatement, ifStatement, whileStatement,
              doStatement, returnStatement

表達式:       expression, term, expressionList

10.4.5 使用 TextComparer 驗證輸出

nand2tetris 提供的比較工具

nand2tetris 的 tools 目錄中包含了 TextComparer.bat（Windows）和 TextComparer.sh（Mac/Linux），用於逐行比對你的輸出與預期的參考輸出。

使用方式

# 比較 tokenizer 輸出
./TextComparer.sh MainT.xml MyMainT.xml

# 比較 parser 輸出
./TextComparer.sh Main.xml MyMain.xml

其中：

  • 第一個參數是預期輸出（nand2tetris 提供的參考答案）
  • 第二個參數是你的輸出

比對結果

如果兩者完全一致，工具會顯示 "Match"。 如果有任何差異，工具會標示出第一個不同的行號，方便你定位錯誤。

Comparison results:
File 1: Main.xml
File 2: MyMain.xml

Mismatch found on line 42:
  Expected: "  <identifier> y </identifier>"
  Got:      "  <identifier> x </identifier>"

替代方案：使用 diff

如果沒有 TextComparer 工具，也可以使用系統的 diff 命令：

diff -u expected_main.xml MyMain.xml

或更直覺地使用 diff 的 side-by-side 模式：

diff -y expected_main.xml MyMain.xml

10.4.6 測試策略與建議

階段式測試

不要一次寫完整個編譯器再測試。建議按照以下順序逐步測試：

第一階段：Tokenizer 測試

先用最簡單的檔案測試 tokenizer：

// test.jack
class Main {
    function void main() {
        return;
    }
}

驗證 MainT.xml 輸出正確。

第二階段：空的結構

測試 parser 能否處理最小的合法程式：

class Main {
}

第三階段：逐語言特性

依序加入每個語言特性並測試：

  1. 變數宣告（var）
  2. let 語句（簡單賦值）
  3. do 語句（函式呼叫）
  4. if/else 語句
  5. while 語句
  6. return 語句
  7. 表達式（含運算符）
  8. 陣列存取
  9. 類別的函式呼叫

自訂測試案例

nand2tetris 的 test/ 目錄提供了許多預建的測試案例。以下是使用方式：

  1. 找到 test/ 目錄中對應的 .jack 檔案
  2. 確認對應的預期 XML 輸出是否存在
  3. 執行你的編譯器
  4. 使用 TextComparer 比對

10.4.7 常見錯誤與除錯技巧

錯誤一：XML 特殊字元未轉義

症狀：TextComparer 報告第一行就不同，XML 工具無法解析輸出。

原因：<、>、& 沒有被轉義。

修正：確保 tokenizer 在輸出 symbol 類型的 token 時進行轉義：

XML_ESCAPE = {
    "<": "&lt;",
    ">": "&gt;",
    "&": "&amp;",
    '"': "&quot;"
}

def token_to_xml(self):
    escaped = XML_ESCAPE.get(self.current_token, self.current_token)
    return f"<symbol> {escaped} </symbol>"

錯誤二：空的 parameterList / expressionList 被省略

症狀：TextComparer 報告差異，預期有 <parameterList>\n</parameterList>，但你的輸出省略了。

修正：即使參數列表或表達式列表是空的，也必須輸出開始和結束標籤：

<!-- 正確：即使是空的也要輸出標籤 -->
<parameterList>
</parameterList>

<!-- 錯誤：省略了空標籤 -->

錯誤三：縮排不正確

症狀：內容正確但空格數量不同。

修正：確保每層縮排恰好使用 兩個空格，並在進入結構性標籤時增加、離開時減少。

錯誤四：token 值中多餘的空格

症狀：<keyword> class</keyword> 少了前面或後面的空格。

修正：XML 格式要求標籤與值之間有一個空格，值與結束標籤之間也有空格：

def token_to_xml(self):
    return f"<{tag}> {value} </{tag}>"
#                    ^        ^
#                  空格      空格

錯誤五：符號 token 的 value 包含多個字元

症狀：<= 被拆成 < 和 = 兩個 token，但有些地方沒有正確處理。

注意：Jack 只有 < 和 = 是獨立的符號，<= 不是 Jack 的合法符號。如果遇到 < 後面跟 =，那是兩個獨立的 token。

錯誤六：字串常量中包含了引號

症狀：遇到 "Hello, World!" 時解析出錯。

修正：tokenizer 在遇到開頭的 " 後，應該一直掃描到下一個 " 為止，中間的所有字元（包括空格）都屬於字串內容。

10.4.8 整合測試：從 .jack 到 .xml

以下是整合 tokenizer 和 parser 的完整主程式：

import sys
import os
from JackTokenizer import JackTokenizer, tokenize_file
from CompilationEngine import CompilationEngine


def compile_jack(input_path: str) -> None:
    """編譯一個 .jack 檔案，產生 .xml 和 .vm 輸出。"""
    base = os.path.splitext(input_path)[0]

    # 步驟 1：詞法分析，產生 XxxT.xml
    tokenizer = JackTokenizer(input_path)
    tokenizer_xml_path = base + "T.xml"
    with open(tokenizer_xml_path, "w", encoding="utf-8") as f:
        f.write("<tokens>\n")
        while tokenizer.has_more_tokens():
            tokenizer.advance()
            f.write("  " + tokenizer.token_to_xml() + "\n")
        f.write("</tokens>\n")

    print(f"  Tokenizer output: {tokenizer_xml_path}")

    # 步驟 2：語法分析，產生 Xxx.xml
    tokenizer = JackTokenizer(input_path)  # 重新建立 tokenizer
    parser_xml_path = base + ".xml"
    engine = CompilationEngine(tokenizer, parser_xml_path)
    engine.compile()

    print(f"  Parser output:    {parser_xml_path}")


def main():
    if len(sys.argv) < 2:
        print("Usage: python JackCompiler.py <file.jack> | <directory>")
        sys.exit(1)

    path = sys.argv[1]
    if os.path.isdir(path):
        jack_files = [
            os.path.join(path, f)
            for f in os.listdir(path)
            if f.endswith(".jack")
        ]
    else:
        jack_files = [path]

    for jack_file in sorted(jack_files):
        print(f"Compiling: {jack_file}")
        compile_jack(jack_file)

    print("Done.")


if __name__ == "__main__":
    main()

使用方式

# 編譯單一檔案
python JackCompiler.py Main.jack

# 編譯整個目錄
python JackCompiler.py MyProgram/

輸出結果

Compiling: Main.jack
  Tokenizer output: MainT.xml
  Parser output:    Main.xml
Done.

10.4.9 XML 輸出的限制與注意事項

字元編碼

XML 檔案應使用 UTF-8 編碼。確保在寫入時指定編碼：

with open(output_path, "w", encoding="utf-8") as f:
    # ...

行尾符號

不同作業系統使用不同的行尾符號（Windows 用 \r\n，Unix/Linux/Mac 用 \n）。nand2tetris 的 TextComparer 工具通常會忽略行尾符號的差異，但為了一致性，建議統一使用 \n。

大型檔案

XML 輸出對於小型的 .jack 檔案完全沒問題，但對於像 Pong 這樣的大專案，XML 檔案可能相當大。這是正常的——XML 只是驗證工具，完成驗證後可以刪除。

格式化的一致性

確保每行恰好一條 XML 標記或 token。不要在同一行寫多個標記，也不要把一條標記拆成多行。

本章小結

本節完整介紹了 Jack 編譯器的 XML 輸出機制與測試方法：

  • XML 的選擇理由：結構化、自描述、易於比對，非常適合教學驗證。
  • XxxT.xml 格式：tokenizer 的輸出，每個 token 用對應的 XML 標籤包圍。
  • Xxx.xml 格式：parser 的輸出，以巢狀 XML 標籤表示語法樹的層次結構。
  • XML 轉義：<、>、&、" 四個字元必須被轉義。
  • TextComparer：nand2tetris 提供的比對工具，用於驗證輸出是否與預期一致。
  • 測試策略：建議從最簡單的檔案開始，逐步加入語言特性，每個特性都驗證通過後再繼續。
  • 常見錯誤：XML 轉義遺漏、空標籤省略、縮排錯誤、token 值前後空格缺失。

至此，你已經具備了建立一個完整的 Jack 編譯器所需的所有知識。詞法分析器將字元流轉為 token 流，語法分析器將 token 流組織為語法樹，而 XML 輸出讓我們能夠驗證每一步的正確性。在後續的章節中，我們將在CompilationEngine 中加入 VM 碼的生成能力，讓編譯器的輸出不僅是 XML，更是真正可以在 VM 上執行的虛擬機碼。這將完成從高階語言到可執行程式的完整翻譯管線。
