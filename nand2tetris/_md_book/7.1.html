7.1 為何需要虛擬機？跨平台與中間語言構想

前言

在第 6 章，我們親手打造了一個組譯器，把 Hack 組合語言翻譯成機器碼。組譯器的美妙之處在於「一對一」——每一條 .asm 指令對應一條 .hack 機器碼。但當你開始想寫真正的程式時，問題就來了：

組合語言太痛苦了。

想在螢幕上畫一個點？你需要管理記憶體位址、手動計算偏移量、用迴圈搬資料。想做一次陣列存取？你需要一整串 @offset、D=A、A=D+M、D=M 的指令。一個高階語言的 if-else，在組合語言裡可能是二十條指令加三個跳躍標號。

第 7 章開始的「虛擬機（Virtual Machine，簡稱 VM）」，正是為了解決這個問題而生的中間層。它讓你不必直接對著裸露的硬體寫作，而是透過一個「簡化的、抽象的計算模型」來表達程式的邏輯。本節先回答最根本的問題：為何需要 VM？它的核心理念是什麼？

1. 高階語言的「翻譯困境」

假設你正在設計一個新的高階語言（本書第 10 章的 Jack 語言），你想讓它能跑在不同的硬體平台上。你遇到的第一個問題是：

  Jack 程式（一次寫好）
       │
       ▼
  ┌────┴────┐
  │  目標？  │
  └────┬────┘
       │
       ├──→ Hack 組合語言？（本書的目標平台）
       ├──→ x86 組合語言？（Intel/AMD 的 PC）
       ├──→ ARM 組合語言？（手機、Apple Silicon）
       └──→ RISC-V 組合語言？（新興開源架構）

如果你直接把 Jack 翻譯成目標平台的組合語言，你就需要為每一個平台寫一套翻譯器。四個平台就是四套翻譯器。每個平台的暫存器數量不同、指令格式不同、記憶體模型不同——這是一場維護噩夢。

1.1 為什麼不能直接翻譯成機器碼？

一個看似合理的方案是：直接從高階語言翻譯成機器碼。但這裡有幾個深層的困難：

困難 說明
指令集差異 Hack 只有 A/C 兩種指令，x86 有數百種，RISC-V 有六種格式——直接翻譯意味著為每個平台重寫所有翻譯邏輯
暫存器分配 Hack 只有 A/D 兩個暫存器，x86 有 16 個通用暫存器，如何把高階語言的變數「分配」到暫存器？
記憶體模型 不同平台的堆疊方向、呼叫慣例、對齊要求都不同
最佳化的困難 直接在高階語言和機器碼之間做最佳化，搜索空間太大，幾乎不可能做到好

核心問題是：高階語言的抽象層次與機器碼的抽象層次差距太遠。中間缺少一個「緩衝區」。

2. 中間表示（Intermediate Representation，IR）的構想

計算機科學家在 1960 年代就發現了這個問題的解法：引入一個「中間層」，把翻譯拆成兩步。

  高階語言（Jack）
       │
       ▼  ← 第一步翻譯：高階 → IR（與平台無關）
  中間表示（VM Code / IR）
       │
       ▼  ← 第二步翻譯：IR → 目標平台（與平台有關）
  目標平台組合語言（Hack / x86 / ARM / ...）

這個中間表示（IR）的設計原則是：

  1. 平台無關：IR 不依賴任何特定硬體，同一段 IR 可以翻譯到任何平台
  2. 足夠簡單：比高階語言簡單得多，容易翻譯
  3. 足夠表達：能表達高階語言的所有控制流程與資料操作

2.1 常見的 IR 類型

計算機科學中有多種 IR 設計，各有特色：

IR 類型 代表 特點
堆疊式（Stack-based） Java Bytecode、Python Bytecode、Nand2Tetris VM 運算元隱含在堆疊頂端，指令極簡
暫存器式（Register-based） LLVM IR、Lua VM 類似組合語言，有明確的暫存器命名
三地址碼（Three-address code） GCC GIMPLE、LLVM IR 每條指令最多三個操作數

Nand2Tetris 選擇堆疊式 IR，因為它最簡單、指令最少、最適合教學。一條 VM 指令只需要一個單字，不需要指定運算元的位址——運算元就在堆疊頂端。

3. VM 抽象層：虛擬的電腦

VM 不只是一種 IR 格式——它本身也是一台虛擬的電腦。就像 Hack 硬體有 A/D 暫存器和 RAM 一樣，VM 也有自己的「硬體」：

VM 資源 說明 Hack 硬體的對應
運算堆疊（Stack） 用來放運算元與暫存結果 沒有直接對應（Hack 沒有堆疊指令）
記憶體段（Memory Segments） argument、local、static、this、that、pointer、temp、constant RAM 的不同區段
程式計數器（PC） 指向下一條要執行的 VM 指令 PC 暫存器
暫存器（有限） 只有 THIS、THAT 等少數幾個 A、D 暫存器

關鍵洞察：VM 的每一個資源，都需要翻譯成 Hack RAM 中的某些位址。這就是第 7 章的核心工作——把 VM 的抽象資源「映射」到 Hack 的實體硬體上。

3.1 VM 抽象的好處

把程式跑在 VM 上，而不是直接跑在硬體上，有幾個巨大的好處：

  Jack 程式
      │
      ▼
  VM 編譯器（Platform-Independent）
      │
      ▼
  VM 程式碼（.vm 檔案）
      │
      ├──→ VM 翻譯器（Hack 版）→ .asm → .hack → Hack 電腦
      ├──→ VM 翻譯器（x86 版）→ .s → 目標碼 → x86 電腦
      └──→ VM 翻譯器（ARM 版）→ .s → 目標碼 → ARM 電腦
  1. 跨平台：同一份 .vm 檔案可以翻譯到任何平台；換平台只需要改 VM 翻譯器，不需要改編譯器
  2. 模組化：編譯器（高階語言 → VM）和 VM 翻譯器（VM → 機器碼）可以分開開發
  3. 除錯容易：VM 代碼比機器碼可讀得多，可以在 VM 層級除錯
  4. 最佳化機會：可以在 IR 層級做平台無關的最佳化

4. Nand2Tetris 的 VM 語言：在 Jack 與 Hack 之間

在 Nand2Tetris 的工具鏈中，VM 佔據了第三層的位置：

  第 10 章：Jack 程式（高階語言，物件導向）
      │
      ▼  編譯器（第 10-11 章）
  第 7 章：VM 程式碼（堆疊式 IR）
      │
      ▼  VM 翻譯器（第 7 章）
  第 6 章：Hack 組合語言
      │
      ▼  組譯器（第 6 章）
  第 5 章：Hack 機器碼
      │
      ▼  硬體執行（第 4-5 章）
  Nand 閘（第 1-2 章）

VM 語言是這條翻譯鏈的中間樞紐。它上承 Jack 編譯器的輸出，下接 Hack 組譯器的輸入。

4.1 VM 程式碼長什麼樣？

一個簡單的 VM 程式範例——計算 17 + 10：

// 計算 17 + 10，結果放在堆疊頂端
push constant 17
push constant 10
add

三條指令，一目了然：

  1. push constant 17：把常數 17 壓進堆疊
  2. push constant 10：把常數 10 壓進堆疊
  3. add：從堆疊頂端彈出兩個值，相加，把結果壓回堆疊

對比同等功能的 Hack 組合語言：

// 計算 17 + 10，結果在 D 暫存器
@17
D=A
@10
D=D+A

VM 代碼更簡潔、更接近人類的思維方式。你不需要知道「哪個值在 A 暫存器、哪個值在 D 暫存器」——堆疊自動管理一切。

4.2 為什麼選擇堆疊式 VM？

Nand2Tetris 的 VM 設計成堆疊式（stack-based），而不是暫存器式（register-based），有一個很務實的原因：

堆疊式 VM 的指令集極小且規則。

一個堆疊式 VM 只需要很少的指令格式：

指令類型 語法範例 說明
堆疊操作 push constant 7、pop local 2 把值放進或取出堆疊
算術邏輯 add、sub、eq、and 從堆疊取運算元，運算，結果壓回
程式流程 label、goto、if-goto 分支與跳躍
函式呼叫 call function 2、function、return 呼叫與返回

對比暫存器式 VM（如 LLVM IR），你不需要做「暫存器分配」這個複雜的最佳化問題。所有運算元的位置都是隱含的——它就在堆疊頂端。這大幅簡化了翻譯器的複雜度。

設計思路：Nand2Tetris 的核心哲學是「先理解原理，再追求效率」。堆疊式 VM 牺牲了一些執行效率（因為需要更多的 push/pop），但換來了翻譯器的極簡性。當你在第 7 章寫出 VM 翻譯器時，你會發現每一條 VM 指令幾乎都可以翻譯成一個固定的 Hack 指令模式——這種「機械式翻譯」正是堆疊式 VM 的設計目標。

5. VM 指令的整體設計哲學

Nand2Tetris 的 VM 指令集只有四種類別，共約二十幾條指令。這種「極簡」不是隨意的——每一條指令都對應到一個明確的計算操作：

5.1 四種指令類別

┌─────────────────────────────────────────────┐
│              VM 指令集總覽                    │
├─────────────────────────────────────────────┤
│                                             │
│  ① 堆疊操作    push / pop                   │
│  ② 算術邏輯    add, sub, neg, eq, gt,       │
│                lt, and, or, not             │
│  ③ 程式流程    label, goto, if-goto         │
│  ④ 函式管理    function, call, return       │
│                                             │
└─────────────────────────────────────────────┘

第 7 章的前半段（7.1-7.4 節）集中在①②④——堆疊操作、算術邏輯、記憶體段；後半段（7.5-7.6 節）處理③④——程式流程控制與函式呼叫。

5.2 設計哲學：最小的指令集，最大的表達力

VM 指令集的設計遵循幾個原則：

原則一：每一條指令只做一件事

add 只做加法，push 只做壓入。沒有「加法後壓入」這種合併指令。這樣每個翻譯模組都是獨立的、可測試的。

原則二：所有運算都在堆疊上進行

算術指令不接受任何參數——它們從堆疊頂端自動取運算元。這意味著 add 的翻譯器永遠知道：第一個運算元在 SP-2，第二個在 SP-1，結果要寫回 SP-1。

原則三：記憶體段提供結構化存取

變數不是直接用位址存取，而是透過記憶體段（local 0、argument 1）存取。翻譯器把段名＋偏移量轉換成實際的 RAM 位址。

5.3 VM 翻譯器的角色

VM 翻譯器（也叫 VM Translator）的本質就是把每一條 VM 指令替換成一組 Hack 組合語言指令：

  .vm 檔案
     │
     ▼
  ┌──────────────────────┐
  │     VM 翻譯器         │
  │   VM Translator      │
  └──────────────────────┘
     │
     ▼
  .asm 檔案（Hack 組合語言）
     │
     ▼
  第 6 章的組譯器
     │
     ▼
  .hack 檔案（機器碼）

與組譯器「一對一」的翻譯不同，VM 翻譯器是一對多的翻譯：一條 VM 指令可能產生 5 到 50 條 Hack 指令。例如 add 只需要約 10 條 Hack 指令，但 call function 3 可能需要 40 條以上。

6. 從高階到低階：完整翻譯鏈範例

讓我們追蹤一段 Jack 程式如何層層翻譯，感受整個工具鏈的運作：

Jack 原始碼：

// 計算兩個數的和
var int a, b;
let a = 17;
let b = 10;
return a + b;

翻譯成 VM 碼：

function Main.main 2
push constant 17
pop local 0
push constant 10
pop local 1
push local 0
push local 1
add
return

翻譯成 Hack 組合語言（部分）：

// push constant 17
@17
D=A
@SP
A=M
M=D
@SP
M=M+1

// pop local 0
@LCL
D=M
@0
D=D+A
@R13
M=D
@SP
AM=M-1
D=M
@R13
A=M
M=D

// push local 0
@LCL
D=M
@0
A=D+A
D=M
@SP
A=M
M=D
@SP
M=M+1

// ...（後續指令類似）

從 Jack 的 3 行，到 VM 的 7 行，再到 Hack 的數十行——每一層翻譯都把抽象降低一個層次，直到硬體能理解的最終形式。VM 層是這個翻譯鏈的腰部：它足夠簡單，可以機械式地翻譯成任何目標平台；又足夠強大，可以表達高階語言的所有語意。

7. 本章小結

  • 高階語言直接翻譯成機器碼面臨跨平台困難、最佳化複雜的問題，需要一個中間層。
  • **中間表示（IR）**把翻譯拆成兩步：高階 → IR（平台無關），IR → 機器碼（平台相關）。
  • VM 是一種 IR 加上虛擬的執行環境；Nand2Tetris 採用堆疊式 VM，因為指令集最簡、翻譯最機械化。
  • VM 的四大指令類別：堆疊操作、算術邏輯、程式流程、函式管理。
  • VM 翻譯器的角色是把 .vm 翻譯成 .asm；與組譯器的「一對一」不同，VM 翻譯是「一對多」。
  • Nand2Tetris 的完整工具鏈：Jack → VM → Hack ASM → Hack 機器碼 → 硬體執行，VM 是這條鏈的中間樞紐。
