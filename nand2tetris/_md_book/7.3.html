7.3 VM 指令翻譯：算術與邏輯指令（add, sub, eq, gt...）

前言

上一節我們理解了堆疊的運作機制，也看過了 add 的 Hack 翻譯。本節要把它推到極致：把全部九條算術與邏輯指令都翻譯成 Hack 組合語言。

這九條指令是 VM 最核心的「計算引擎」。它們全都從堆疊取運算元、做運算、把結果放回堆疊。翻譯器的目標是為每一條指令建立一個固定的 Hack 指令模式（pattern），讓翻譯變成機械式的替換。

本節結束後，你將擁有完整的翻譯表，可以直接用在 VM 翻譯器的實作中。

1. 指令分類：兩種翻譯模式

九條指令可以分成兩類，對應兩種翻譯模式：

類別 指令 運算元數 翻譯模式
二元運算 add、sub、and、or 2 pop-binary-op
比較運算 eq、gt、lt 2 pop-binary-op + 跳躍技巧
一元運算 neg、not 1 pop-unary-op

核心思想：二元運算從堆疊取兩個值、算一個值；一元運算從堆疊取一個值、算一個值。比較運算本質也是二元運算，但結果只有 true（-1）或 false（0），需要額外的跳躍邏輯。

2. pop-unary-op 模式：一元運算的基礎

一元運算（neg 和 not）是最簡單的——只處理堆疊頂端一個值。

2.1 通用模板

// pop-unary-op 通用模板
@SP         // A = 0
A=M-1       // A = SP - 1（指向堆疊頂端）
D=M         // D = 堆疊頂端的值
// ← 這裡執行一元運算
M=D         // 結果寫回堆疊頂端

2.2 neg（取負）

neg 的語意：把堆疊頂端的值取負（x → -x）。

// neg
@SP         // A = 0
A=M-1       // A = SP - 1
D=M         // D = x
D=-D        // D = -x
M=D         // RAM[SP-1] = -x

5 條指令。 堆疊深度不變。

2.3 not（位元 NOT）

not 的語意：把堆疊頂端的值做位元取反（x → !x，每一位 0 變 1、1 變 0）。

// not
@SP         // A = 0
A=M-1       // A = SP - 1
D=M         // D = x
D=!D        // D = !x（位元取反）
M=D         // RAM[SP-1] = !x

5 條指令。 結構與 neg 完全相同，只差在運算從 D=-D 變成 D=!D。

3. pop-binary-op 模式：二元運算的基礎

二元運算（add、sub、and、or）從堆疊取兩個值，算出一個結果。

3.1 通用模板

// pop-binary-op 通用模板
@SP         // A = 0
M=M-1       // SP = SP - 1
A=M         // A = SP（指向 y，第二運算元）
D=M         // D = y
@SP         // A = 0
M=M-1       // SP = SP - 1（指向 x，第一運算元）
A=M         // A = SP
// ← 這裡執行二元運算，結果放在 D
M=D         // RAM[SP] = 結果
@SP         // A = 0
M=M+1       // SP = SP + 1（結果佔據一個位置）

11 條指令（含重複的 @SP）。 堆疊深度減少 1。

3.2 add（加法）

// add
@SP
M=M-1       // SP--
A=M         // A = SP
D=M         // D = y
@SP
M=M-1       // SP--
A=M         // A = SP
D=M+D       // D = x + y
M=D         // RAM[SP] = x + y
@SP
M=M+1       // SP++

10 條指令。

3.3 sub（減法）

// sub
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D=M-D       // D = x - y  （注意：是 x - y，不是 y - x）
M=D
@SP
M=M+1

10 條指令。 唯一差別：D=M+D 變成 D=M-D。

3.4 and（位元 AND）

// and
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D=M&D       // D = x AND y
M=D
@SP
M=M+1

10 條指令。 運算改成 D=M&D。

3.5 or（位元 OR）

// or
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D=M|D       // D = x OR y
M=D
@SP
M=M+1

10 條指令。 運算改成 D=M|D。

4. 比較指令的翻譯：跳躍技巧

比較指令（eq、gt、lt）是最有趣的部分。它們也需要從堆疊取兩個值，但運算結果不是數值，而是布林值：相等/大於/小於為 true（-1，全 1），否則為 false（0）。

4.1 Hack 沒有「比較後設定 D」的指令

Hack 的 ALU 可以做加減法和位元邏輯，但沒有「如果相等就設 D 為 -1」的指令。所以我們需要用跳躍技巧：

  1. 計算 x - y
  2. 如果結果為 0（表示相等），跳到「設為 true」的程式碼
  3. 否則（不相等），執行「設為 false」的程式碼
  4. 把結果寫回堆疊

4.2 eq（等於比較）

// eq
@SP
M=M-1       // SP--
A=M
D=M         // D = y
@SP
M=M-1       // SP--
A=M
D=M-D       // D = x - y

// 如果 D == 0（x == y），跳到 EQ_TRUE
@EQ_TRUE
D;JEQ

// 否則（x != y）：設為 false（0）
@SP
A=M
M=0         // RAM[SP] = 0
@EQ_END
0;JMP

(EQ_TRUE)
@SP
A=M
M=-1        // RAM[SP] = -1（true）

(EQ_END)
@SP
M=M+1       // SP++

翻譯後的指令約 17 條。

4.3 gt（大於比較）

// gt
@SP
M=M-1
A=M
D=M         // D = y
@SP
M=M-1
A=M
D=M-D       // D = x - y

// 如果 D > 0（x > y），跳到 GT_TRUE
@GT_TRUE
D;JGT

// 否則：設為 false
@SP
A=M
M=0
@GT_END
0;JMP

(GT_TRUE)
@SP
A=M
M=-1

(GT_END)
@SP
M=M+1

結構與 eq 完全相同，只差在跳躍條件從 JEQ 變成 JGT。

4.4 lt（小於比較）

// lt
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D=M-D       // D = x - y

@LT_TRUE
D;JLT       // 如果 D < 0（x < y），跳到 LT_TRUE

@SP
A=M
M=0
@LT_END
0;JMP

(LT_TRUE)
@SP
A=M
M=-1

(LT_END)
@SP
M=M+1

跳躍條件從 JGT 變成 JLT。

4.5 比較指令的模式總結

三條比較指令共享同一個翻譯骨架：

  ① pop y, pop x
  ② D = x - y
  ③ D;J<條件>  → 跳到 TRUE
  ④ 設為 0（false）→ 跳到 END
  5 TRUE: 設為 -1（true）
  6 END: SP++
指令 跳躍條件 true 條件
eq D;JEQ x - y == 0
gt D;JGT x - y > 0
lt D;JLT x - y < 0

設計思路：為什麼比較結果是 -1（全 1）而不是 1？因為 Hack 的布林系統中，true 定義為 -1（所有位元都是 1）。好處是：true AND true = true（-1 & -1 = -1）仍然成立，而 1 & 1 = 1 雖然也成立，但 1 OR 0 = 1 雖然對，-1 OR 0 = -1 也對——用 -1 確保所有位元運算都符合布林邏輯。

5. 四個跳躍標籤的命名問題

比較指令使用了跳躍標籤（如 EQ_TRUE、EQ_END）。問題是：如果 VM 程式中有兩個 eq 指令，標籤就會重複。

解決方案：用唯一名稱。翻譯器內部維護一個計數器，每翻譯一條比較指令就加一：

  第 1 個 eq → EQ_TRUE_1, EQ_END_1
  第 2 個 eq → EQ_TRUE_2, EQ_END_2
  第 1 個 gt → GT_TRUE_1, GT_END_1
  ...依此類推

在 Python 翻譯器中，可以用一個計數器實現：

class VMTranslator:
    def __init__(self):
        self.label_counter = 0

    def _unique_label(self, prefix):
        self.label_counter += 1
        return f"{prefix}_{self.label_counter}"

    def translate_eq(self):
        label_true = self._unique_label("EQ_TRUE")
        label_end = self._unique_label("EQ_END")
        return f"""
// eq
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D=M-D
@{label_true}
D;JEQ
@SP
A=M
M=0
@{label_end}
0;JMP
({label_true})
@SP
A=M
M=-1
({label_end})
@SP
M=M+1
"""

6. 完整的 VM → Hack 翻譯對照表

6.1 九條指令的完整對照

VM 指令 Hack 指令數 關鍵 Hack 運算 SP 變化
add 10 D=M+D -1
sub 10 D=M-D -1
and 10 D=M&D -1
or 10 D=M|D -1
neg 5 D=-D 不變
not 5 D=!D 不變
eq ~17 D=M-D + D;JEQ -1
gt ~17 D=M-D + D;JGT -1
lt ~17 D=M-D + D;JLT -1

6.2 完整追蹤範例

追蹤以下 VM 程式在 Hack 上的執行：

push constant 7
push constant 8
eq

步驟追蹤：

初始: SP=256

[push constant 7]
  @7       → A=7
  D=A      → D=7
  @SP      → A=0
  A=M      → A=256
  M=D      → RAM[256]=7
  @SP      → A=0
  M=M+1    → SP=257

[push constant 8]
  @8       → A=8
  D=A      → D=8
  @SP      → A=0
  A=M      → A=257
  M=D      → RAM[257]=8
  @SP      → A=0
  M=M+1    → SP=258

[eq]
  @SP; M=M-1     → SP=257
  A=M; D=M       → D=8（y）
  @SP; M=M-1     → SP=256
  A=M; D=M-D     → D=7-8=-1（x-y）
  @EQ_TRUE_1     → A=EQ_TRUE_1 的位址
  D;JEQ          → D=-1≠0，不跳
  @SP; A=M; M=0  → RAM[256]=0（false）
  @EQ_END_1; 0;JMP → 跳到 EQ_END_1

(EQ_END_1)
  @SP; M=M+1     → SP=257

最終: RAM[256]=0, SP=257

7 ≠ 8，所以 eq 結果是 0（false）。正確！

如果改成 push constant 7 再 push constant 7，D=M-D 的結果是 0，D;JEQ 會跳到 EQ_TRUE，RAM[256] 被設為 -1（true）。正確！

7. 實作步驟：建構翻譯器的算術模組

如果你正在寫一個 VM 翻譯器，算術模組的實作步驟如下：

步驟 1：建立翻譯表

用字典把 VM 指令映射到 Hack 程式碼模板：

ARITHMETIC_TABLE = {
    'add': _translate_add,
    'sub': _translate_sub,
    'neg': _translate_neg,
    'eq':  _translate_eq,
    'gt':  _translate_gt,
    'lt':  _translate_lt,
    'and': _translate_and,
    'or':  _translate_or,
    'not': _translate_not,
}

步驟 2：實作 pop-binary-op 輔助函式

因為四條二元運算的骨架相同，只差在運算式，可以抽成共用邏輯：

def _binary_op(alu_expr):
    """產生二元運算的 Hack 組合語言"""
    return f"""
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D={alu_expr}
M=D
@SP
M=M+1
"""

使用時：

def _translate_add(): return _binary_op("M+D")
def _translate_sub(): return _binary_op("M-D")
def _translate_and(): return _binary_op("M&D")
def _translate_or():  return _binary_op("M|D")

步驟 3：實作比較指令

比較指令需要唯一名稱，使用計數器：

def _translate_eq(self):
    t = self._unique_label("EQ_TRUE")
    e = self._unique_label("EQ_END")
    return f"""
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D=M-D
@{t}
D;JEQ
@SP
A=M
M=0
@{e}
0;JMP
({t})
@SP
A=M
M=-1
({e})
@SP
M=M+1
"""

步驟 4：串接主翻譯迴圈

def translate(self, command):
    if command in ARITHMETIC_TABLE:
        return ARITHMETIC_TABLE[command](self)
    elif command.startswith("push"):
        return self._translate_push(command)
    elif command.startswith("pop"):
        return self._translate_pop(command)
    # ... 其他指令

設計思路：把二元運算抽象成 _binary_op(alu_expr) 是**不要重複自己（DRY）**原則的體現。四條指令的翻譯骨架完全相同，只有運算式不同——如果分別寫四份，改一次要改四處；抽成函式，改一次就全改了。比較指令因為有跳躍標籤的複雜度，無法用同一個抽象，所以獨立實作。

8. 優化可能性（進階）

8.1 簡化 SP 操作

在某些情況下，可以減少 @SP 的出現次數：

// 優化前的 add（10 條指令）
@SP
M=M-1
A=M
D=M
@SP
M=M-1
A=M
D=M+D
M=D
@SP
M=M+1

// 優化後的 add（8 條指令）
@SP
AM=M-1    // A = SP-1, SP = SP-1（同時完成）
D=M       // D = y
A=A-1     // A = SP-2（指向 x）
D=M+D     // D = x + y
M=D       // 寫回
@SP
M=M+1     // SP++

Hack 允許 AM=M-1 這種「同時寫入 A 和 M」的指令，可以省掉一行。但這需要更細緻的位址追蹤。

8.2 避免冗餘的 SP 更新

比較指令可以重排分支，減少跳躍：

// 等一下！上面的比較指令都是設為 0 或 -1
// 如果直接算出布林值，可以更短嗎？

// 替代方案：用算術產生布林值
// D = (x - y == 0) ? -1 : 0
// 但 Hack 沒有「條件選取」指令，所以跳躍版仍是最佳選擇

對教學用途而言，清晰度比效率更重要。優化是進階課題。

9. 本章小結

  • 九條算術邏輯指令分為三類翻譯模式：pop-unary-op（neg、not）、pop-binary-op（add、sub、and、or）、比較+跳躍（eq、gt、lt）。
  • 一元運算（neg/not）：5 條 Hack 指令，直接處理 RAM[SP-1]，SP 不變。
  • 二元運算（add/sub/and/or）：10 條 Hack 指令，pop 兩個值、運算、push 結果、SP 減 1。
  • 比較運算（eq/gt/lt）：~17 條 Hack 指令，用 x - y 的差配合 JEQ/JGT/JLT 跳躍來產生布林值（true = -1，false = 0）。
  • 比較指令的跳躍標籤必須用唯一名稱（如 EQ_TRUE_1、GT_END_3），避免重複。
  • 核心設計原則：可重用的翻譯模式。二元運算用 _binary_op(alu_expr) 抽象；比較指令用統一骨架 + 可替換的跳躍條件。
  • VM 的 sub 是 x - y（先 push 的是 x，後 push 的是 y），寫 VM 時要注意運算元順序。
