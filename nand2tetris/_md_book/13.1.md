# 第 13 章　軟硬體全棧鏈條整合測試

## 前言

從第 1 章的 NAND 閘出發，歷經邏輯閘、組合邏輯、序序邏輯、CPU、組譯器、虛擬機、編譯器、作業系統，一路走到第 12 章的圖形化應用程式——我們已經分別征服了每一個抽象層級。然而，這些模組在各自獨立測試時「通過」，不代表串接在一起時仍能正確運作。本章的任務就是把整條鏈路串起來，進行全棧整合測試，驗證一個 Jack 程式從原始碼到硬體執行的每一步都正確無誤。

## 13.1.1　回顧：從邏輯閘到作業系統的完整鏈條

讓我們先用一張表回顧每一層的輸入、輸出與負責的工具：

| 層級 | 輸入 | 輸出 | 工具 |
|------|------|------|------|
| 1. 基本邏輯閘 | 真值表 | HDL 電路 | NAND, AND, OR, NOT, MUX… |
| 2. ALU | 控制位元 + 兩個輸入 | 運算結果 + 條件碼 | ALU.hdl |
| 3. 暫存器 | 資料 + 時脈 | 狀態保存 | PC, ARegister, DRegister |
| 4. 記憶體 | 位址 + 資料 | 記憶體矩陣 | RAM8…RAM16K, Screen, Keyboard |
| 5. CPU | 機器碼指令 | PC + 資料暫存器狀態 | CPU.hdl → Computer.hdl |
| 6. 組譯器 | .asm 文字檔 | .hack 二進位檔 | Assembler |
| 7. 虛擬機 | .vm 中間碼 | .asm 組語 | VM Translator |
| 8. 編譯器 | .jack 原始碼 | .vm 中間碼 | Jack Compiler |
| 9. 作業系統 | OS 模組 (Math, Screen, Keyboard…) | 系統服務 | Jack OS (用 Jack 寫成) |

每一層的輸出恰好是下一層的輸入——這就是 nand2tetris 的核心設計哲學：**層層抽象、逐層實作**。

## 13.1.2　全棧整合的意義

「整合」不只是把模組接起來，而是要驗證：

1. **介面相容性**：上一層的輸出格式是否完全符合下一層的輸入規格？例如 VM Translator 產生的組語指令，Assembler 是否全部能解碼？
2. **語意正確性**：每一層的轉換是否保持原始程式的語意？例如編譯器把 `if (x < 5)` 翻成 VM 的 `if-goto`，語意是否完全等價？
3. **端到端可觀測性**：最終在 CPU 模擬器上執行時，畫面上出現的結果是否與原始 Jack 程式的預期行為一致？

整合測試的價值在於：**單元測試只能證明個別模組正確，整合測試才能證明整個系統正確**。

## 13.1.3　工具鏈的搭配流程

完整的工具鏈執行流程如下：

```
┌─────────────────────────────────────────────────────┐
│  Jack 程式 (.jack)                                  │
│  ┌───────────────────────────────────────────────┐  │
│  │  Jack Compiler                                │  │
│  │  輸入: *.jack                                 │  │
│  │  輸出: *.vm (虛擬機中間碼)                     │  │
│  └───────────────────────────────────────────────┘  │
│                      ↓                              │
│  ┌───────────────────────────────────────────────┐  │
│  │  VM Translator                                │  │
│  │  輸入: *.vm                                   │  │
│  │  輸出: *.asm (組合語言)                        │  │
│  └───────────────────────────────────────────────┘  │
│                      ↓                              │
│  ┌───────────────────────────────────────────────┐  │
│  │  Assembler                                    │  │
│  │  輸入: *.asm                                  │  │
│  │  輸出: *.hack (二進位機器碼)                   │  │
│  └───────────────────────────────────────────────┘  │
│                      ↓                              │
│  ┌───────────────────────────────────────────────┐  │
│  │  CPU Simulator / Hardware Simulator            │  │
│  │  輸入: Computer.hdl + *.hack ROM 映像         │  │
│  │  輸出: 螢幕畫面、鍵盤互動                      │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

### 以命令列驅動的完整流程

```bash
# 步驟 1：編譯 Jack → VM
java -cp JackCompiler.jar JackCompiler MyProgram/

# 步驟 2：翻譯 VM → ASM
java -cp VMTranslator.jar VMTranslator MyProgram/

# 步驟 3：組譯 ASM → HACK
java -cp Assembler.jar Assembler MyProgram/MyProgram.asm

# 步驟 4：載入硬體模擬器執行
# 用 CPU Emulator 載入 Computer.hdl，並將 MyProgram.hack
# 載入為 ROM 映像，按 Yes 重置後按 Run
```

每一步的輸出都可以獨立檢查：

- **Compiler 輸出**：檢查 `.vm` 檔案中的虛擬碼是否合理（是否有 `push`, `pop`, `call`, `function` 等正確指令）。
- **VM Translator 輸出**：檢查 `.asm` 中的組語是否有正確的標籤、跳轉、以及對 Hack 指令集的正確使用。
- **Assembler 輸出**：檢查 `.hack` 檔案的每一行是否為 16 個 0/1 組成的字串，且行數符合預期。

## 13.1.4　驗證整條鏈路的策略

### 策略一：已知輸入/輸出法

撰寫一個簡單的 Jack 程式，其輸出是已知的。例如：

```jack
class Main {
    function void main() {
        do Output.printInt(42);
        return;
    }
}
```

預期輸出為 `42`。如果全棧整合正確，硬體模擬器的螢幕上應該顯示 `42`。

### 策略二：漸進式替換法

先用提供的官方工具走完全流程確認正確。然後逐步用自己的實作替換每一層：

1. 先用自己的 Assembler 替換官方 Assembler，確認結果一致。
2. 再用自己的 VM Translator 替換，確認結果一致。
3. 最後用自己的 Compiler 替換，確認結果一致。

每一步替換後都重新執行全棧測試，確保不引入回歸問題。

### 策略三：邊界值測試

測試極端情況：

- **空程式**：`Main.main()` 只有 `return;`，確認工具鏈不會崩潰。
- **大量運算**：遞迴計算費波那契數，確認暫存器和記憶體不會溢位。
- **邊界記憶體位址**：存取最高位址的 RAM，確認記憶體映射正確。

## 13.1.5　常見的整合問題與除錯

| 症狀 | 可能原因 | 除錯方向 |
|------|----------|----------|
| CPU 模擬器顯示空白 | ROM 未正確載入 | 檢查 `.hack` 檔案是否為空或格式錯誤 |
| 程式卡在無限迴圈 | VM `if-goto` 標籤不正確 | 檢查 VM Translator 的標籤生成 |
| 螢幕出現亂碼 | 記憶體映射錯誤 | 檢查 Screen RAM 的位址範圍 (16384–24576) |
| 鍵盤輸入無反應 | Keyboard 暫存器未接線 | 檢查 Computer.hdl 的 Keyboard 連接 |
| 運算結果不正確 | ALU 控制位元錯誤 | 回頭測試 ALU 的真值表 |

除錯的核心方法是**隔離法**：先確定問題出在哪一層，再在該層內定位具體的錯誤。

## 本章小結

本章回顧了 nand2tetris 的完整工具鏈，從 NAND 閘到 Jack 程式語言，每一層都有明確的輸入輸出介面。全棧整合測試的意義在於驗證這些層級串接後仍能正確運作。我們提出了三種驗證策略——已知輸入/輸出法、漸進式替換法、邊界值測試——並整理了常見的整合問題與除錯方向。有了這些方法論，讀者就可以自信地把自己的實作物件接成一條完整的管道，讓一個 Jack 程式從編譯一路跑到硬體模擬器上執行。
