11.2 物件導向特性的底層翻譯：Constructors, Methods, Fields

學習目標

讀完本節後，你應該能：

  • 說明 constructor 如何配置物件記憶體（透過 Memory.alloc）並把結果送回 this
  • 說明 method 如何「偷偷」接收 this——它被當作 argument 0，並複製到 local 0
  • 說明 function 與 constructor/method 在翻譯上的關鍵差異
  • 說明欄位（field）的存取如何經由 this 段的偏移（offset）達成
  • 理解 pointer 0 與 THIS 指標的關係，以及 VM translator 如何把它兌現成實際 RAM 位址
  • 能親手把一個完整的 Jack 類別翻譯成等價的 VM 代碼

前言

有了 11.1 節的符號表作為地基，這一節我們要挑戰 Jack 最「神奇」的部分：物件導向。

你在 Jack 裡寫 Clock c = Clock.new(9, 30); 然後呼叫 c.setHour(10);。看起來那麼自然。可是我們在第 8 章打造的 VM 是「無腦的」：它只有 pop、push、call、return 這一套極簡指令，既不知道什麼叫「建構物件」，也不知道什麼叫「呼叫方法」。

那這些物件導向的語法，到底被翻譯成什麼？答案是：全部化合為最基本的記憶體操作與函式呼叫。物件不過是一塊「用 Memory.alloc 換來的記憶體」，方法不過是「把 this 當隱藏參數傳進去的普通函式」。本節就是要拆穿這個魔術，讓你看清程式碼背後一切的真相。

1. 先釐清三種 subroutine 的角色

Jack 的 subroutine 一共有三種關鍵字：constructor、function、method。它們在翻譯規則上各有千秋，先總覽一張表：

關鍵字 屬於物件？ 接收 this？ 回傳什麼？ 使用時機
constructor 類別層級 否 回傳新建物件的 this 位址 建立物件（像 Clock.new）
function 類別層級 否 普通值 靜態工具函式（像 Memory.alloc）
method 實例層級 是（argument 0） 普通值 操作某個特定物件（像 c.setHour）

請特別看 constructor 與 method 的差別：

  • constructor 是「製造者」：它負責向 OS 要一塊記憶體當作物件空間，把 field 初始化好，最後把「這塊空間的位址」交給呼叫者。它本身不針對任何已存在的物件操作，所以不收 this。
  • method 是「操作者」：它一定要知道「我是在對哪個物件動手」。這個「哪個物件」就是隱藏的 this，看似沒寫在參數列，其實被 VM 悄悄排在 argument 0。

而 function 兩者都不是——它是個孤獨的全域函式，就像 C 語言裡的普通函式。

2. Constructor 的翻譯：alloc 之後回傳 this

2.1 為什麼 constructor 要先計算欄位數量

constructor 的第一件工作，是替物件開出空間。空間多大？取決於這個物件有幾個 field。還記得符號表嗎——field int hour; field int minute; 就有兩個 field，所以這個物件的空間就是 2 格。

Nand2Tetris 的做法是：在編譯 constructor 時，查類別符號表的 field 計數，得到 nFields，然後生成一個對 Memory.alloc(nFields) 的呼叫。Memory.alloc 是 Jack OS 裡負責「記憶體配置器」的函式，它會回傳一塊空白記憶體的起始位址。

2.2 關鍵技巧：把 this 段指向新建的記憶體

Memory.alloc 回傳的位址存在 stack 上。但接下來 constructor 內的 field 存取（例如 hour = 9）需要寫進「this 段的偏移」裡。於是一個關鍵動作發生：

把 alloc 回傳的位址，放進 THIS 指標（也就是 pointer 0）。 從此以後，pop this 0 這類指令就會寫進這塊新建的記憶體。

而 constructor 最後要「把 this 位址交給呼叫者」，所以它會 pop pointer 0（把位址放進 THIS）之後，再把 pointer 0 的值 push 回去，然後 return。呼叫者拿到這個位址，之後呼叫 method 時就靠它。

2.3 完整翻譯範例：Clock 類別 → VM

來看一個具體例子。我們定義一個帶兩個欄位的 Clock 類別：

// Clock.jack
class Clock {
    field int hour;
    field int minute;

    constructor Clock new(int h, int m) {
        let hour = h;
        let minute = m;
        return this;
    }

    method void print() {
        do Output.printInt(hour);
        do Output.printChar(58);  // ':'
        do Output.printInt(minute);
        return;
    }
}

先把符號表建立起來。類別符號表：

name type kind index
hour int field 0
minute int field 1

編譯 constructor new 時子程式符號表：

name type kind index
h int argument 0
m int argument 1

nFields = 2。現在逐步翻譯 constructor：

開頭（prologue）：

function Clock.new 0        // 宣告函式；0 個區域變數
push constant 2             // 這是欄位數量（nFields = field 計數）
call Memory.alloc 1         // 呼叫 alloc(2)，回傳物件位址
pop pointer 0               // 把位址放進 THIS（pointer 0）

接著處理 let hour = h;。這裡 hour 是 field 0 → this 0；h 是 argument 0。翻譯成：

push argument 0             // 把 h 推入 stack
pop this 0                  // 存進 this 0（即 THIS+0）

處理 let minute = m;，minute 是 field 1：

push argument 1
pop this 1

最後 return this;。this 這個「變數」其實就是 pointer 0。要把 this 的值當作回傳值：

push pointer 0              // 把 THIS 位址推入 stack 作為回傳值
return

設計思路：注意 return this; 生成的兩條指令 push pointer 0 + return。假如漏了 push pointer 0，return 就會把某個不相干的 stack 值當作回傳，呼叫者拿到的就不是物件位址了。constructor 的這個 closing 動作正是物件出生的最後關鍵一步。

所以完整的 Clock.new 翻譯是：

function Clock.new 0
push constant 2
call Memory.alloc 1
pop pointer 0
push argument 0
pop this 0
push argument 1
pop this 1
push pointer 0
return

3. Method 的翻譯：this 變成 argument 0 與 local 0

3.1 method 的「隱藏參數」

當你寫 c.setHour()，編譯器（語法層）看到的是呼叫一個 method。但底層，方法呼叫時除了真的參數之外，還得先傳入這個物件本身的位址。所以 method 的宣告在翻譯時，會被當作「比表面上看起來多一個參數」的函式：

  • 表面上 method int foo(int a) 只有一個參數 a
  • 實際上 VM 函式 Clock.foo 有 2 個參數：argument 0 = this（物件位址）、argument 1 = a

3.2 method 的 prologue：THIS = this，並備份到 local 0

method 進入後的第一件事，是把 argument 0（this）設定為當前的物件。做法是把 argument 0 抄到 pointer 0，讓 this 段指向這個物件——這樣 body 裡所有的 field 存取（this 0、this 1…）才會落在正確物件的記憶體上：

function Clock.print 0      // method：區域變數 0 個
push argument 0             // this（物件位址）在 argument 0
pop pointer 0               // THIS = 物件位址

另外，Nand2Tetris 教材還建議一個「保險措施」：把 this 也複製一份到 local 0。為何？因為 VM 的 function 定義行要寫區域變數數量，若本身沒有 var，我們仍想留一格來保存 this，就宣告 function Clock.print 1，然後 argument 0 → local 0。這樣即便 body 內部混亂指針，也仍保有 this 的副本。（後續小結會再提醒這點。）

3.3 method body 的欄位存取

body 內 Output.printInt(hour) 中，hour 是 field 0。要讀它的值，得先讓 this 段 指向正確物件（上面 prologue 已做），再：

push this 0

這條指令在後端的 VM translator 眼裡，是「把 RAM[THIS + 0] 推入 stack」。

完整的 Clock.print 方法翻譯（假設採「宣告 1 個區域變數並把 this 備份到 local 0」的策略）：

function Clock.print 1
push argument 0
pop pointer 0               // THIS = this
push argument 0
pop local 0                 // （選用）備份 this 到 local 0
push this 0
call Output.printInt 1
pop temp 0                  // 丟棄 printInt 的回傳值（do 陳述式）
push constant 58
call Output.printChar 1
pop temp 0
push this 1
call Output.printInt 1
pop temp 0
push constant 0
return

設計思路：do 陳述式呼叫完畢後回傳值沒人要用，所以用 pop temp 0 把它從 stack 上丟掉（避免 stack 髒掉）。而 method 的 return（沒有明確回傳值時）習慣上回傳 constant 0。

4. Function 的翻譯：最單純的平凡函式

function 既不管 alloc 也不接 this，是最乾淨的一種。它的翻譯規則就是最標準的 VM 函式：

  • function ClassName.name k 開場，k = 區域變數個數
  • body 直接翻譯，凡 var 變數依符號表 → local i，參數 → argument j

舉例，若有一個靜態工具函式：

function int twice(int x) {
    return 2 * x;
}

翻譯：

function ClassName.twice 0
push constant 2
push argument 0
call Math.multiply 2
return

（Math.multiply 是 Jack OS 提供的乘法函式，輸出輸出兩個參數。）

5. 欄位存取、pointer 0 與 THIS 的關係

5.1 一張圖看懂 THIS / pointer / this 段

VM 有一組特殊的虛擬暫存器，pointer 0 與 pointer 1 分別是 THIS 與 THAT 的替身。第 8 章的 VM translator 在實作時這樣設定，例如 Hack 上 THIS 落在 RAM[3]、THAT 落在 RAM[4]。

  • pop pointer 0 → 把值寫進 RAM[3]（即 THIS）
  • push pointer 0 → 讀出 RAM[3]
  • this i → 實際是 RAM[THIS + i]，也就是 RAM[RAM[3] + i]

所以「set THIS = 某物件位址」之後，所有 this i 的讀寫就全部指向該物件的第 i 個欄位。這正是物件欄位的存在方式：

        RAM[3]  (THIS)  ──►  [ hour | minute | ... ]   ← 物件空間
                               this 0   this 1

5.2 欄位移動的實質

「欄位存取 = 其中一個基址 + 偏移」——這個概念在本書 11.3 節處理陣列時會再次出現。簡單說，物件欄位就是把「物件起始位址（THIS）」當基址，再加上欄位編號作為偏移。this 0、this 1 二個就是 THIS+0、THIS+1。

6. 完整的 Jack 類別 → VM 翻譯範例

現在把前面各片段的 Clock 類別一次翻譯到位，方便你對照：

Jack（Clock.jack）：

class Clock {
    field int hour;
    field int minute;

    constructor Clock new(int h, int m) {
        let hour = h;
        let minute = m;
        return this;
    }

    method void print() {
        do Output.printInt(hour);
        do Output.printChar(58);
        do Output.printInt(minute);
        return;
    }
}

VM（Clock.vm）：

// Clock.new
function Clock.new 0            // 宣告 0 個區域變數（此處策略以宣告 0）
push constant 2
call Memory.alloc 1
pop pointer 0
push argument 0
pop this 0
push argument 1
pop this 1
push pointer 0
return

// Clock.print
function Clock.print 1          // 宣告 1 格用來備份 this
push argument 0
pop pointer 0
push argument 0
pop local 0
push this 0
call Output.printInt 1
pop temp 0
push constant 58
call Output.printChar 1
pop temp 0
push this 1
call Output.printInt 1
pop temp 0
push constant 0
return

驗證方法：把 Cloud 的 Clock.vm 交由第 8 章的 VM translator 轉成 Clock.asm，再交給第 6 章的組譯器與第 5 章的電腦模擬器。只要 this/pointer、call/return 的語意正確，這個物件就真的活了過來。

設計思路與實作步驟總整理

  1. constructor：算出 nFields → Memory.alloc(nFields) → pop pointer 0 → 初始化 field → push pointer 0（return this）。
  2. method：視為多一個參數（argument 0 = this）→ prologue 把 argument 0 設為 THIS（並可備份到 local 0）→ body 內 field 用 this i。
  3. function：最單純，無 this、無 alloc，直接翻譯 body。
  4. field 就是 THIS + 偏移；pointer 0 只是 THIS 在 VM 指令中的代稱。

7. 本章小結（本節）

  • constructor 翻譯三步曲：Memory.alloc(欄位數) → pop pointer 0（this 段指向新物件）→ 以 push pointer 0 回傳物件位址。
  • method 翻譯關鍵：隱藏參數 this 放在 argument 0，進入時複製到 THIS（argument 0 → pointer 0），讓 field 能用 this i 存取。
  • function 最單純：無物件、無 this，直接依符號表翻譯。
  • 欄位 = 物件基址(THIS) + 偏移；pop/push pointer 0 就是讀寫 THIS 指標本身。
  • do 呼叫後要 pop temp 0 丟棄回傳值；method 無回傳值時回傳 constant 0。
  • 一張符號表（11.1）＋ 這套翻譯規則，就足以讓 VM 執行真正的物件導向程式。
