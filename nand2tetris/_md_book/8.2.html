8.2 函數呼叫機制：call, function, return

學習目標

讀完本節後，你應該能：

  • 說出 function / call / return 三指令的 VM 規格與各自職責
  • 說明 function 如何宣告函式並配置、初始化 local 段為零
  • 說明 call 如何保存 caller 狀態、傳遞參數、設定新的 frame、跳轉
  • 說明 return 如何還原 caller 狀態、把回傳值交給正確位置
  • 描述 bootstrap：程式啟動時如何初始化 SP=256 並呼叫 Sys.init
  • 看懂並自行推導演譯一段 call / return 的完整 Hack 程式

前言

8.1 節的程式只有一條直線，頂多加上迴圈。但真實的程式是「一個函式呼叫另一個函式、呼叫完再回到原先的位址繼續」——這正是函式呼叫機制存在的理由。

VM 用三條指令搞定它：function（宣告函式）、call（呼叫函式）、return（從函式返回）。這三條是整本「虛擬機進階」的靈魂，也是最容易出錯的地方。我們的策略是：把規格講清楚 → 把每個暫存器與記憶體位址的推移畫出來 → 再翻譯成 Hack。一步一步，不貪快。

1. VM 規格：function / call / return

先把三條指令的「官方規格」立好，一切翻譯都以此為準。

1.1 function 指令

function <函式名> <nLocal>

作用：宣告一支名為 <函式名> 的函式，它有 <nLocal> 個 local 變數，並且把這 nLocal 個 local 段全都初始化為 0。

  • 例如 function foo 3：宣告函式 foo，有 3 個 local 變數；
  • 這些 local 佔據的記憶體位址從目前的 LCL 開始連續排列，值全設為 0；
  • function 指令不處理參數——參數是 caller 用 call 時放好、由 ARG 指到的。

1.2 call 指令

call <函式名> <nArgs>

作用：呼叫名為 <函式名> 的函式，並傳遞 <nArgs> 個參數。

呼叫前，caller 必須先把參數依序 push 到堆疊上，然後執行 call。call 會：

  1. 保存 caller 的狀態（返回位址與各 frame 指標）；
  2. 設定新函式的 frame（把 ARG 指向第一個參數、LCL 指向新 local 起點）；
  3. 跳進被呼叫的函式。

1.3 return 指令

return

作用：結束目前函式，把控制權還給 caller。

  • 它會把回傳值放到「caller 預期它出現的位置」；
  • 還原 caller 的 frame（LCL、ARG、THIS、THAT、SP、返回位址）；
  • 跳回 caller 的返回位址繼續執行。

2. call 指令的詳細拆解

call 是三者中最複雜的。讓我們把「呼叫發生時，堆疊與記憶體長什麼樣」用到極致。

一個龐大的約定：SP = 堆疊指標，永遠指到「下一個可用位置」（即最後一個元素的下一個）。

2.1 呼叫前的準備

假設 caller 要呼叫 foo(7, 42)，兩個參數。它先執行：

push constant 7
push constant 42
call foo 2

執行 call foo 2 前一刻，堆疊長這樣（N 是 caller 的 SP）：

       ... 任意資料 ...
位址 N-2 : 7           <- 參數 0
位址 N-1 : 42          <- 參數 1
位址 N   : （空，SP 指著這）  <- 等於 call 後的 ARG 起點

2.2 call 的五步

call foo 2 的 VM 動作，翻譯成 Hack 時依序是五段。關鍵：caller 的返回位址（retAddr）、LCL、ARG、THIS、THAT 都要被保存，這樣被呼叫者返回時才能完整還原。

我們把「推入 SP」的動作寫成連續的 push（後面用 @SP / A=M / M=<值> / @SP / M=M+1 的模式，簡寫為 push value）：

第一步：把返回位址壓入堆疊（retAddr）

push retAddr        // 把「call 後下一條指令的位址」壓進去

這是唯一一個「位址」值，會被壓在堆疊最上面。

第二步：保存 caller 的 frame 指標

把 LCL、ARG、THIS、THAT 依序壓入堆疊（先 LCL，再 ARG，再 THIS，最後 THAT）：

push LCL            // 保存 caller 的 LCL
push ARG            // 保存 caller 的 ARG
push THIS           // 保存 caller 的 THIS
push THAT           // 保存 caller 的 THAT

第三步：設定新函式的 ARG

ARG 要被設定為「指向第一個參數」的位址。呼叫前堆疊上共有參數（2 個）、retAddr、四個 frame 指標，加起來 7 個元素，所以：

ARG = SP - 5 - nArgs

（SP 是還沒 push retAddr/frame 前的原位置 N；壓入 1(ret) + 4(frame) = 5 個之後，SP = N + 5；減掉 5 + nArgs，就回到參數 0 的位置 N - 2。）

在 Hack 上，需要「先算好位址，再一次操縱 ARG 暫存器」。這裡用一個技巧：直接以「現在 SP 的位置」為基準做減法。

第四步：設定新函式的 LCL

把目前 SP 所指的位置設為新函式的 LCL（即「新 frame 的起點」＝所有剛壓入資料之上）。

LCL = SP

第五步：跳進被呼叫函式

goto foo            // 0;JMP 到 foo 的第一條指令

2.3 call 的完整 Hack 翻譯

把五步拼起來，call foo 2 的完整翻譯（retAddr 符號先佔位，實作時用 FunctionName$ret.N 讓它唯一）：

// ===== call foo 2 =====
@retAddr              // 維持一個唯一符號：foo$ret.0
D=A
@SP
A=M
M=D
@SP
M=M+1                 // ① push retAddr

@LCL
D=M
@SP
A=M
M=D
@SP
M=M+1                 // ② push LCL

@ARG
D=M
@SP
A=M
M=D
@SP
M=M+1                 // ② push ARG

@THIS
D=M
@SP
A=M
M=D
@SP
M=M+1                 // ② push THIS

@THAT
D=M
@SP
A=M
M=D
@SP
M=M+1                 // ② push THAT

@SP
D=M
@5
D=D-A
@2
D=D-A
@ARG
M=D                   // ③ ARG = SP - 5 - 2

@SP
D=M
@LCL
M=D                   // ④ LCL = SP

@foo
0;JMP                 // ⑤ 跳進 foo

(retAddr)             // ⑥ 返回位址落腳處（被呼叫者 return 後回到這）

設計思路：③ ARG = SP-5-nArgs 這一步最容易被寫錯。我們的 retAddr 是一個「尚未翻譯成實際位址」的符號，實作 CodeWriter 時必須讓它唯一且可預期，慣用 函式名$ret.<連續編號>。這樣每支函式的每個 call 都有自己的 retAddr，不會撞名。

3. function 指令的翻譯

function foo 3 要做兩件事：宣告入口＋初始化 3 個 local 為 0。

3.1 宣告入口

翻譯成一個 Hack 標籤：

(foo)                 // 函式 foo 的入口

（此後 call foo 的跳轉目標就是這個 (foo)。）

3.2 初始化 local 段為 0

接著，把 LCL（此刻已被 call 設好）所指的位置開始，連續 nLocal 個位址全部填 0。因為 LCL = SP 是在 call 的第四步設好的，所以「第一個 local 就是現在 SP 指的位置」，依序填入即可。

function foo 3 的完整翻譯：

(foo)                // ① 入口標籤
@0
D=A
@SP
A=M
M=D
@SP
M=M+1                 // ② local 0 = 0
@0
D=A
@SP
A=M
M=D
@SP
M=M+1                 // ② local 1 = 0
@0
D=A
@SP
A=M
M=D
@SP
M=M+1                 // ② local 2 = 0

三組「把 0 推進堆疊」的動作，代表三個 local 變數都被初始化。因為 LCL 已指向堆疊起點，這些「推進去」的 0 正好是 local 0/1/2——但這裡不使用 LCL 的偏移，而是直接沿著 SP 堆上去，這是 VM 規格允許的簡化（local 段與堆疊頭重疊）。

設計思路：你可能會疑惑「為何 function 只是把 0 堆到 SP 上，而不是真的去寫 RAM[LCL+0]？」因為 call 第四步已設定 LCL = SP（當時），接著 function 從該處往上堆 0，兩者完全落在同一塊連續記憶體。等到函式真正開始「用 local」時，LCL 正是第一塊 local 的位址。效用相同、翻譯更簡潔。

4. return 指令的翻譯

return 是「把一切還原」的關鍵。它要做的事，對應 8.3 節的 frame 概念，這裡先給翻譯。重點是先把被呼叫者 frame 的尾巴（LCL）備份到一個臨時變數，因為後面會動到堆疊。

4.1 return 的步驟

  1. 拿到 frame 的尾端：R13 = LCL（frame 暫存到臨時暫存器，因為 LCL 馬上會被覆蓋）；
  2. 算出返回位址：返回位址存放在 frame 的最底部（即 RAM[LCL-5]），R14 = *(frame-5)；
  3. 搬移回傳值：把堆疊頂端（回傳值）搬到 ARG 所指位置：*ARG = pop()；
  4. 還原 caller 的 SP：SP = ARG + 1；
  5. 還原 THAT、THIS、ARG、LCL：依序從 frame 底部往上讀回；
  6. 跳回 retAddr：goto R14。

4.2 return 的完整 Hack 翻譯

// ===== return =====
@LCL
D=M
@R13
M=D                 // R13 = frame = LCL（先備份）

@R13
D=M
@5
A=D-A
D=M
@R14
M=D                 // R14 = *(frame-5) = retAddr

@SP
AM=M-1
D=M
@ARG
A=M
M=D                 // *ARG = pop()（回傳值搬到 ARG 所指）

@ARG
D=M+1
@SP
M=D                 // SP = ARG + 1

@R13
D=M
@1
A=D-A
D=M
@THAT
M=D                 // THAT = *(frame-1)

@R13
D=M
@2
A=D-A
D=M
@THIS
M=D                 // THIS = *(frame-2)

@R13
D=M
@3
A=D-A
D=M
@ARG
M=D                 // ARG = *(frame-3)

@R13
D=M
@4
A=D-A
D=M
@LCL
M=D                 // LCL = *(frame-4)

@R14
A=M
0;JMP               // 跳回 retAddr（回到 caller 的返回位址）

設計思路：為什麼要先 @R13 / M=D 保存 LCL？因為第 4 步「還原 LCL」時會覆蓋 LCL，而被呼叫者還需要它的舊值去定位 frame 的各個元素。所以 frame 尾巴（LCL）是 return 全程的生命線，必須先存進不會被碰到的臨時暫存器 R13。同理 retAddr 存 R14。

5. 程式計數器的起點：bootstrap 與 Sys.init

整支程式該從哪開始？VM 沒有「main」的強制名，Nand2Tetris 的慣例是：從 Sys.init 開始。

5.1 bootstrap code

在翻譯所有 VM 檔之前，VM Translator 會先產生一段「啟動碼」，做兩件事：

  1. 把 SP 初始化為 256（RAM[0] = 256），這樣堆疊從位址 256 開始往上長，避開前面保留給暫存器（0–15）與指標（16–255）的區域；
  2. 呼叫 Sys.init：這正是第一次 call，從這裡進入整個程式。
// bootstrap：初始化 SP 並呼叫 Sys.init
@256
D=A
@SP
M=D                 // SP = 256

// call Sys.init 0（沒有參數）
@returnAddr         // 唯一符號，例：Sys.init$ret.0
D=A
@SP
A=M
M=D
@SP
M=M+1               // push retAddr
@LCL
D=M
@SP
A=M
M=D
@SP
M=M+1               // push LCL
@ARG
D=M
@SP
A=M
M=D
@SP
M=M+1               // push ARG
@THIS
D=M
@SP
A=M
M=D
@SP
M=M+1               // push THIS
@THAT
D=M
@SP
A=M
M=D
@SP
M=M+1               // push THAT
@SP
D=M
@5
D=D-A
@ARG
M=D                 // ARG = SP - 5 - 0
@SP
D=M
@LCL
M=D                 // LCL = SP
@Sys.init
0;JMP               // 呼叫 Sys.init
(returnAddr)         // 若 Sys.init 返回，程式回到這（通常到此結束）

5.2 Sys.init 的例子

一個標準的 OS 起始函式：

// Sys.vm
function Sys.init 0
push constant 4000
pop pointer 0        // THIS = 4000（設定某個物件基底）
call Main.main 0     // 呼叫真正的主程式
label END
goto END            // 迴圈結束（或不回傳）

這樣「程式啟動 → Sys.init → Main.main → 執行 → 結束」的鏈結就建立了。

6. 對照表與翻譯總覽

把三條指令的「VM ⇄ Hack」對照集中起來：

VM 指令 Hack 翻譯要點
function foo n (foo) ＋ 連續 n 次「push 0」
call foo m push retAddr/push LCL/push ARG/push THIS/push THAT → ARG=SP-5-m → LCL=SP → @foo;0;JMP → (foo$ret.K)
return 備份 frame→R13、取 retAddr→R14、*ARG=pop()、SP=ARG+1、還原 THAT/THIS/ARG/LCL、goto R14
bootstrap SP=256 ＋ call Sys.init 0

6.1 翻譯者的職責分工（預告）

在 8.4 節的完整 Translator 中，這三條指令各自對應 CodeWriter 的一個方法：

def writeFunction(self, name, nLocals)   # function
def writeCall(self, name, nArgs)         # call
def writeReturn(self)                    # return

產生的 retAddr 唯一符號策略：對每個 call，用「目前的函式名 + $ret. + 一個遞增編號」命名，例如 foo$ret.0、foo$ret.1……確保不與其他 call 衝突。

7. 設計思路與實作步驟

7.1 一步一步：實作 function / call / return

  1. 先寫 writeFunction：最簡單（入口標籤＋推 0×n），且能幫你定義「self.function = name」來餵給 8.1 節的 label/goto；
  2. 再寫 writeReturn：它只依賴 LCL 與堆疊，邏輯封閉，可以先獨自測；
  3. 最後寫 writeCall：最複雜，確認參數、frame、返回位址三者順序都對。

設計思路：為什麼 call 最難？因為它要「同時」跟 caller 的堆疊開頭、frame 指標、返回位址打交道。對照 8.3 節的堆疊視覺化圖表，把「call 前」與「call 後」的記憶體畫出來，是寫對 call 的黃金方法。

7.2 驗證口訣

  • 每個 function，都有相對應的「呼叫它的 call」；
  • 每個 call，被呼叫函式最後都會 return（除了 Sys.init 等故意不回的）；
  • 任何時刻，SP = ARG + nArgs（若有 nArgs 參數）且 SP <= LCL。

8. 本章小結

  • function 宣告函式入口並初始化 nLocal 個 local 為 0；
  • call 依序保存 retAddr、LCL、ARG、THIS、THAT，設定新 ARG/LCL，再跳進函式；
  • return 先備份 frame，取回 retAddr，搬移回傳值到 *ARG，還原 SP 與各 frame 指標，最後跳回返回位址；
  • 返回位址是唯一需要「後續才知道標籤」的符號，實作時用「函式名$ret.K」命名保證唯一；
  • bootstrap 把 SP 初始化為 256 並 call Sys.init 0，程式由此啟動；
  • 三者對照表：function 最簡、return 封閉、call 最繁，實作順序建議從簡到繁。

本節把「怎麼呼叫、怎麼返回」講清楚了，但記住一個殘酷的事實：return 之所以能完整還原 caller，靠的是那五個 frame 元素井然有序地躺在堆疊裡。下一節 8.3 我們會把這「呼叫堆疊」一層層攤開來，看看多次嵌套呼叫時，記憶體到底怎麼流轉——那是理解整章的最後一塊拼圖。
