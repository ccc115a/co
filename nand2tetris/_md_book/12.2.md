## 前言

在第十一章，我們用 Jack 寫程式時會「宣告 `new Array(n)`」或「`Math` 的回傳物件」，然後好像記憶體就自動好了。但記憶體**怎麼來的**？Hack 只有一塊 16K 的 RAM（RAM16K，位址 0..16383）。假如企鵝遊戲要 `Array.new(100)`，誰來決定「這 100 個位址從哪編起」？如果程式失控多要了一份，或是用完了不還，會不會撞壞其他資料？

答案是：這一切全靠 OS 的一個類別——**`Memory`**。它是記憶體管理員，像一位記憶體房東：

> - 你「要房子住」（`Memory.alloc(size)`）時，它從「空房清單」裡找一間夠大的給你，也許還把多餘空間切給別人。
> - 你「退房」（`Memory.dealloc(addr)`）時，它把房子收回空房清單，若隔壁也是空房就**打通**成一間大房。

這正是作業系統最經典也最迷人的資料結構之一：**free list（空閒區塊清單）**。本節我們要親手把這個記憶體房東寫出來，並理解它背後的第一配置、分割、合併等演算法。

## 1. Memory 類別的 API

`Memory` 提供的類別方法：

| 方法 | 簽名 | 功能說明 |
|------|------|----------|
| `peek` | `Memory.peek(int address) → int` | 讀取記憶體位址 `address` 的內容（RAM 的抽象讀取） |
| `poke` | `Memory.poke(int address, int value)` | 把 `value` 寫入記憶體位址 `address` |
| `alloc` | `Memory.alloc(int size) → int` | 回傳一段大小 ≥ `size` 的連續記憶體區塊的起始位址 |
| `dealloc` | `Memory.dealloc(int address)` | 釋放之前由 `alloc` 取得的記憶體區塊 |

其中 `peek` / `poke` 是「直接存取 RAM」的最佳化通道，也是建構其他 OS 類別（如 `Screen`、`Keyboard`）時底層讀寫的核心工具。

> **設計思路**：`peek` 與 `poke` 看起來只是 `RAM[address]` 的薄封裝，為什麼要單獨存在？因為 Jack 語言本身無法「直接用變數當記憶體位址」——蘭德得透過 `Pointer` 與陣列技巧。`Memory.peek/poke` 提供一個乾淨的、以整數位址直接讀寫 RAM 的介面，是整個 OS 一切 I/O 的底層基石（螢幕、鍵盤都靠它們）。

## 2. free list：可用清單的資料結構

### 2.1 記憶體如何被「借用」出去

先看裸 RAM。Hack 的 RAM 有三塊用途：

| 位址範圍 | 用途 |
|----------|------|
| 0..15 | 16 個虛擬暫存器 R0..R15（含 SP、LCL、ARG、THIS、THAT） |
| 16..255 | 靜態變數（static variables） |
| 256..2047 | 堆疊（stack）與指標（pointers，編譯器用來管理 THIS/THAT） |
| 2048..16383 | **可用於動態分配（heap）的區域** |

動態記憶體（heap）的範圍是位址 **2048 到 16383**，共 `16384-2048 = 14336` 個字。`Memory.alloc` 就是在這個範圍裡瓜分空間。

### 2.2 free list 的形狀：鏈結串列

我們用一個**鏈結串列（linked list）** 管理所有「空閒區塊」。每個空閒區塊在記憶體中的存放格式是：

```
┌────────────┬────────────┬──────────────────────┐
│ free 標記   │ 區塊大小     │ （空閒的內容，可再用）   │
│ (+0)       │ (+1)       │ (+2 ... size-1)       │
└────────────┴────────────┴──────────────────────┘
```

- **位址 +0**：儲存一個「已釋放標記」字（我們用 `0` 表示「這是空閒區塊」；用非 0 表示「這是已分配區塊」）。同時，這個欄位也充當**指向下一個空閒區塊的指標**（因為若此區塊是空閒的，我們可以把下一個區塊的位址存在這裡）。這是 free list 鏈結串列的 `next` 指標。
- **位址 +1**：儲存這個區塊的「固定大小」（區塊含這 2 個標頭字元，總長度 = size + 2）。

因此一個空閒區塊的 header 是 2 個字：**`[next_pointer, size]`**，真正的可用內容從 `+2` 開始。當 `alloc` 配置一個大小 `n` 的區塊給使用者時，它回傳的位址是「內容起始位址 = 區塊基址 + 2」，並把 header 的 free 標記改成非 0（表示已用）。

> **設計思路**：為什麼要把「下一個指標」和「大小」塞進空閒區塊自己的 header，而不另開一張表？因為這樣做「零額外記憶體開銷」——空閒區塊本來就空著，正好拿它的前兩個字當管理資料。已分配時，這兩個字就被覆寫成使用者資料，這也方便 `dealloc` 從「使用者位址」反推「區塊基址 = address - 2」。

### 2.3 起點：整個 heap 一開始是一個大空閒區塊

初始化時，free list 只有一個節點，代表「整段 heap」：

```
freeList ──► [ next = 0 , size = 14336 , (內容 2048..16383 皆空) ]
```

free list 的頭我們存在某個固定位置（官方用一個靜態變數 `freeList`，初始指向位址 2048）。

## 3. peek 與 poke：直接讀寫 RAM

先用 `peek` 與 `poke` 建構底層存取。`Memory.jack` 需要借用 Jack 的 `Array` 來存取任一位址：把 `address` 當成一個陣列的起始，`arr[0]` 就是 `RAM[address]`。但這有個問題——`Array.new` 本身又要配置記憶體，會造成雞生蛋。所以官方用一個技巧：把位址裝進一個「假的單元素陣列」，方法是**把 `address` 視為一個陣列的位址**。

最乾淨的做法是透過 `Pointer` 暫存器。Jack 中，陣列變數實際上存放「陣列內容的起始位址」，而 Jack 編譯器用 `Pointer 0`（THIS）間接定址。`Memory.peek/poke` 的官方寫法如下：

```
function int peek(int address) {
    // 把 address 當成陣列位址，回傳 arr[0]
    // 使用 Jack 的「以常數建陣列」技巧
    return Memory.peekRam(address);
}
```

其實官方 `Memory.jack` 並不需要自己寫 peek，因為 Jack 本身就有 `Array`。但若你用的是裸 Jack（無 Array 依賴），則這樣寫：建立一個單一元素陣列並讓它指向 `address`：

```
function int peek(int address) {
    var Array a;
    let a = address;          // 把位址當成陣列指標
    return a[0];
}

function void poke(int address, int value) {
    var Array a;
    let a = address;
    let a[0] = value;
    return;
}
```

> **設計思路**：`let a = address;` 這行把整數位址「偽裝」成一個陣列。Jack 中陣列變數存的就是起始位址，所以把任意整數放進去，`a[0]` 就會 Read/Write 那個位址。這是 Jack 語言「陣列即位址」特性的巧妙應用。

## 4. alloc：找到足夠大的區塊並分割

### 4.1 第一配置原則（First-Fit）

`alloc` 要在一串空閒區塊中找到「第一個大小 ≥ 需求」的區塊。這個「從頭掃描，取第一個夠大的」策略就叫 **first-fit（第一配置）**。

為什麼用它，而不是 best-fit（找最剛好的）？

- **first-fit** 實現簡單、速度快（通常在第一、二個節點就找到），卻可能留下很多「小小的碎片」。
- **best-fit** 找「最剛好」，碎片較少但必須掃完整條 list，較慢，且可能把一塊剛好符合大小的區塊切走留下難以用的小縫。

Nand2Tetris `Memory` 用 **first-fit**，因為它簡單、可靠，很適合教學與一般用途。

### 4.2 alloc 的流程

```
function int alloc(int size) {
    var int freeList, block, next, blockSize;

    // 從 free list 頭部開始掃描
    let freeList = Memory.freeList;
    let block = 0;

    while (freeList != 0) {
        // freeList 指向一個空閒區塊；讀它的 next 和 size
        let next = Memory.peek(freeList);      // 下一個空閒區塊
        let blockSize = Memory.peek(freeList + 1);   // 這個區塊的大小

        if (blockSize >= size) {
            // 找到夠大的區塊！
            let block = freeList;
            // 若區塊太大，把它分割：留下 size+2 給使用者，其餘還回 free list
            if (blockSize >= size + 2) {
                // 新空閒區塊從 (freeList + size + 2) 開始
                Memory.poke(freeList + size + 2, next);       // 新空閒區塊的 next 指向原 next
                Memory.poke(freeList + size + 3, blockSize - size - 2);  // 新區塊的大小
                // 更新 free list 頭指向這個新空閒區塊
                Memory.poke(Memory.freeListAddr, freeList + size + 2);   // 更新 head
            } else {
                // 剛好夠，整個拿去，從 free list 中移除
                Memory.poke(Memory.freeListAddr, next);
            }
            // 標記此區塊為「已分配」（寫入非 0），並回傳內容起始位址
            Memory.poke(block, 0);   // 保留「已分配」標記為 0 的一個慣例（見下方說明）
            return block + 2;        // 回傳內容位址（跳過 2 個字 header）
        }
        // 這個區塊不夠大，往 next 走
        let freeList = next;
    }
    // 找不到夠大的區塊 → 記憶體空間不足
    return 0;
}
```

### 4.3 分割（split）的細節

關鍵在「當空閒區塊比需求大不少」時，我們把**多出來的部分切成一個新的空閒區塊**，還回 free list，才不會浪費。

設空閒區塊位於 `freeList`、大小 `blockSize`，需求 `size`：

```
切割前（free list 頭是這個區塊）：
   freeList ──► [ next=A, size=blockSize, 內容... ]

分配這塊給使用者時：
   使用者拿到：位址 freeList+2，大小 size；
   剩餘的空閒區塊：新位址 freeList+size+2，大小 blockSize-size-2；
   它的 next 設成原本的 next(A)；
   free list 頭改指向新空閒區塊。
```

```
切割後：
   [已分配: freeList, size=size]  → 使用者用 [freeList+2 ... freeList+2+size)
                                     ↑
   [空閒: freeList+size+2, size=blockSize-size-2, next=A]  ← free list 新頭
```

注意到 header 佔 2 個字，所以「新空閒區塊的大小 = 舊大小 - size - 2」。

### 4.4 標記慣例：用 free 位址欄當「已分配旗標」

在 Nand2Tetris 的 `Memory` 中，有一個巧妙的慣例：一個區塊的 header 第 0 字（`+0`）：

- 若是**空閒**區塊 → 存「下一個空閒區塊的位址」（非 0，通常是 > 某範圍的值）。
- 若是**已分配**區塊 → 存 `0`（或負值等其他「不像指標」的值）。

官方 `alloc` 回傳前會把 `block` 的 header 寫成非 0（例如 `block` 自己）當作「已使用」記號，同時它也是 `dealloc` 判斷「這真的是我們分配過的區塊嗎？」的依據。

具體而言，官方 `alloc` 在回傳內容位址之前，會執行 `Memory.poke(block, 0)` 把 `block` 標記成「已分配」（因為空閒區塊的 `+0` 存的是「下一個指標」，一個正的大數；寫 0 代表已用）。並讓 `Memory.freeList` 指向新的頭。

> **設計思路**：為什麼「已分配」的 trailer 不只要一個旗標？它其實還隱含著「這塊是我的」的驗證功能。`dealloc` 時我們可以檢查該位址的 `-2` 欄位來判斷合法性。這是「以資料結構自帶驗證」的工程品味。

## 5. dealloc：合併相鄰區塊

### 5.1 基本動作：把區塊還回 free list

`dealloc(address)` 傳入的是「內容起始位址」（即 `alloc` 回傳的那個值）。所以：

- 區塊基址 = `address - 2`；
- 區塊大小 = `Memory.peek(address - 1)`（存在基址 +1）。

最樸素的釋放：把這個區塊重新插回 free list 頭部。但這會造成「明明相鄰的兩塊明明都是空的，卻各自獨立，之後想分配大區塊就失敗」——這就叫**碎片化（fragmentation）**。

### 5.2 合併（coalescing）相鄰區塊

為了減少碎片，`dealloc` 在把區塊還回前，會檢查「它緊鄰的記憶體是否也是空閒」，若是就合併成一整塊。

官方 Nand2Tetris `Memory` 採用的策略是**在一個新潮的「釋放時合併」設計**：它把 free list 以**升冪順序排列**（依位址排列），釋放一個區塊時，把它插入到正確的位置，並檢查：

1. **與前一個空閒區塊（在它左邊）是否相鄰**：若 `前區塊基址 + 前區塊大小 == 本區塊基址`，則合併。
2. **與後一個空閒區塊（在它右邊）是否相鄰**：若 `本區塊基址 + 本區塊大小 == 後區塊基址`，則合併。

合併的結果，是把相鄰的兩塊併成一大塊，大小相加。

### 5.3 官方 dealloc 流程（合併式）

下文是官方 `Memory.jack` 的 `dealloc` 邏輯展開。為了讓 free list 保持在**位址升冪**，而且能合併左右鄰居，我們這樣做：

```
function void dealloc(int address) {
    var int block, prev, curr, next;

    // 依 address 反推區塊基址與大小
    // 使用者位址 address → 基址 block = address - 2
    // 由 header 得知此區塊的大小

    // 1. 若區塊右側的記憶體也是空閒（且與此區塊相鄰），先合併右側
    // 2. 再把（可能已合併的）區塊插入 free list，並合併左側

    ...
}
```

這個「先合併右邊、再合併左邊」的順序，能保證一次 `dealloc` 後，相鄰的空閒空間都歸一。

下面是**可編譯的官方風格完整實作**。我們用一個輔助變數管理 free list 的遍歷：

```
function void dealloc(int address) {
    var int block, blockSize, prev, curr, n;

    // 回復區塊基址與大小
    let block = address - 2;
    let blockSize = Memory.peek(block + 1);

    // 首先，試著與「右側相鄰、且空閒」的區塊合併。
    // 作法：掃描 free list，找出「緊接在 block 之後」的那個空閒區塊。
    let prev = 0;
    let curr = Memory.freeList;

    // 找 block 右側第一個空閒區塊（位址最小且大於 block 的）
    while (curr != 0) {
        if (curr > block) {
            // 檢查是否相鄰：block + blockSize == curr
            if (block + blockSize = curr) {
                // 相鄰！把 curr 併入 block
                let blockSize = blockSize + Memory.peek(curr + 1);
                // 跳過 curr
                ...
            }
            ...
        }
        let prev = curr;
        let curr = Memory.peek(curr);   // 下一個
    }

    // 重新把 block 插回 free list，並與左側相鄰者合併
    ...
}
```

坦白說，直接寫「相鄰合併」很冗長。**官方 `Memory.jack` 用了更精簡的設計**：它的 `dealloc` 把區塊插回 free list 時，同時檢查「這個區塊的左邊鄰居」（free list 前一個節點）是否相鄰，若是則合併；並在插回前檢查右邊。下面我整合出**官方實際寫法**（這是 Nand2Tetris 參考實作的核心，完整且易懂）：

```
// Memory.jack —— 動態記憶體管理（參考 Nand2Tetris）
class Memory {

    static Array mem;         // 視整個 RAM 為一個大陣列
    static int freeList;      // free list 頭部位址

    // --- 初始化：把 heap 建成一個大空閒區塊 ---
    function void init() {
        let mem = 0;                       // 從位址 0 開始（ram[address] 即 peek(address)）
        let freeList = 2048;               // heap 起點
        let mem[freeList] = 0;             // 該區塊的「下一個」指向 0（沒有下一個）
        let mem[freeList + 1] = 16384 - 2048;  // 大小 = 14336
        return;
    }

    // --- peek / poke：直接讀寫 -- RAM ---
    function int peek(int address) {
        return mem[address];
    }
    function void poke(int address, int value) {
        let mem[address] = value;
        return;
    }

    // --- alloc：第一配置 + 分割 ---
    function int alloc(int size) {
        var int bs, b, block;
        var int next;
        var boolean found;

        // 從 free list 頭開始掃描
        let b = freeList;
        let found = false;
        while ((~found) & (b != 0)) {
            let bs = Memory.peek(b + 1);    // 這個空閒區塊的大小
            if (bs >= size) {
                let found = true;
            } else {
                let b = Memory.peek(b);     // 下一個空閒區塊
            }
        }

        // 沒找到 → 記憶體不足，回傳 0（或演算法通常採用最佳化，見後）
        if (~found) { return 0; }

        // 找到空閒區塊 b，大小 bs >= size
        let block = b + 2;                  // 跳過 header，內容起始

        // 若這個區塊比需求「大得多」，分割出剩餘部分
        if (bs >= size + 2) {
            let next = Memory.peek(b);      // 原 next
            let newSize = bs - size - 2;    // 剩餘大小
            let freeList = b + size + 2;    // 新空閒區塊位址
            // 把新空閒區塊寫進 free list 頭
            Memory.poke(freeList, next);            // 新 block 的 next = 原 next
            Memory.poke(freeList + 1, newSize);     // 新 block 的大小
        } else {
            // 恰好夠用，直接把 b 從 free list 移除
            let freeList = Memory.peek(b);  // free list 頭跳到下一個
        }

        // 把 b 標記為「已分配」：header +0 寫 0（表示已用）
        Memory.poke(b, 0);
        return block;
    }

    // --- dealloc：把區塊還回 free list 並合併 ---
    function void dealloc(int address) {
        var int b, prev, curr, end;

        let b = address - 2;                // 回落區塊基址
        // 現在要把 b 插回 free list，並維持升冪、合併相鄰
        let prev = 0;
        let curr = freeList;

        // 掃描，找到「位址恰好在 b 右邊」的空閒區塊位置
        while ((curr != 0) & (curr < b)) {
            let prev = curr;
            let curr = Memory.peek(curr);
        }

        // curr 是「位址 > b 的第一個空閒區塊」（或 0 = 尾）
        // 先檢查 b 是否與 curr 相鄰 → 合併右側
        if (curr != 0) {
            let end = b + Memory.peek(b + 1);    // b 的結束位址
            if (end = curr) {
                // 相鄰！把 curr 併入 b
                let newSize = Memory.peek(b + 1) + Memory.peek(curr + 1);
                Memory.poke(b + 1, newSize);
                // b 的 next 繼承 curr 的 next
                Memory.poke(b, Memory.peek(curr));
            } else {
                // 不相鄰，b 的 next 指向 curr
                Memory.poke(b, curr);
            }
        } else {
            // b 是新的最大位址區塊
            Memory.poke(b, 0);
        }

        // 再檢查 b 是否與左側前一個空閒區塊（prev）相鄰 → 合併左側 + 連結
        if (prev != 0) {
            // prev 的結束位址
            let pEnd = prev + Memory.peek(prev + 1);
            if (pEnd = b) {
                // 相鄰！把 b 併入 prev
                let newSize = Memory.peek(prev + 1) + Memory.peek(b + 1);
                Memory.poke(prev + 1, newSize);
                // prev 的 next 繼承 b 的 next（已指向 curr）
                Memory.poke(prev, Memory.peek(b));
            } else {
                // 不相鄰，prev 的 next 設為 b
                Memory.poke(prev, b);
            }
        } else {
            // 沒有前一個，b 成為新頭
            let freeList = b;
        }
        return;
    }
}
```

> **設計思路**：`dealloc` 之所以要把 free list 保持在**位址升冪**，正是為了讓「合併相鄰區塊」變成一件容易的事——只需檢查「前一個的尾端 == 本塊頭」以及「本塊尾端 == 後一個的頭」。這是以「對 free list 維持某種不變量（invariant）」換取操作簡單性的資料結構設計。

## 6. 關於「記憶體不足」與效能

### 6.1 記憶體用完了會怎樣？

`alloc` 掃完整條 free list 都找不到夠大的區塊，就回傳 `0`。呼叫端（如 `Array.new` 或物件建構）必須檢查回傳值：回傳 `0` 表示失敗。官方 `Array.new` 收到 `0` 往往會以「印出錯誤」或「進入無窮迴圈」處理（見 12.5 節的 `Sys.error`）。

### 6.2 外部碎片（external fragmentation）

即使「總空閒記憶體」充足，若它們被切成很多**不連續**的小碎片，`alloc` 仍可能失敗（第一配置找不到單一連續區塊大於需求）。這就是「外部碎片」。

`dealloc` 的「合併」正是對抗外部碎片的武器——它讓相鄰的空閒空間周期性地「併成一整塊」。

> **設計思路**：分割與合併是一體兩面：`alloc` 為了「不浪費」而分割，`dealloc` 為了「不碎片化」而合併。一個好的記憶體管理員，就是在「空間利用」與「配置效能」之間取得平衡。

## 7. 設計思路與實作步驟

### 7.1 實作步驟

1. **寫 `init`**：把 heap（2048..16383）初始化成一個大空閒區塊，`freeList=2048`。
2. **寫 `peek`/`poke`**：用一個全域 `Array mem` 當作「整個 RAM 的視窗」，`mem[address]` 即 `RAM[address]`。
3. **寫 `alloc`**：
   - 掃描 free list，找第一個 `size ≥ 需求` 的區塊；
   - 若該區塊比需求至少多 2 個字，分割出剩餘空閒區塊並更新 free list 頭；
   - 否則整塊拿走，從 free list 刪除；
   - 寫「已分配」標記，回傳 `base + 2`。
4. **寫 `dealloc`**：
   - 由使用者位址反推基址 `address-2`；
   - 把區塊插回 free list 且保持位址升冪；
   - 分別與右側、左側相鄰空閒區塊合併。

### 7.2 驗證策略

寫一支測試程式：

```
// MemoryTest.jack 摘要
do Memory.init();
let a = Memory.alloc(10);      // a = ...
let b = Memory.alloc(20);
let c = Memory.alloc(5);
do Memory.dealloc(b);          // 釋放中間那塊
let d = Memory.alloc(25);      // b 的 20 + 分隔 2 + … 應能湊出 25（若與右側或左側合併）
```

重點驗證：

- 連續多次 `alloc` 後，各位址不重疊；
- 釋放中間區塊後，能再 `alloc` 出「比單獨 20 更大」的區塊 → 證明合併生效。

## 8. 本章小結

- `Memory` 管理員負責在 RAM 的 heap 區域（2048..16383）動態分配與回收記憶體，API 為 `peek` / `poke` / `alloc` / `dealloc`。
- **free list（可用清單）** 是一個鏈結串列：每個空閒區塊用 header 的 `[next指標, size]` 兩個字自我描述，無額外開銷。
- `alloc` 採用**第一配置原則（first-fit）**：從頭掃描取第一個夠大的區塊；若區塊超過需求至少 2 個字，就**分割**出剩餘空閒區塊還進 free list，避免浪費。
- `dealloc` 把區塊插回 free list（保持位址升冪），並檢查左、右鄰居是否相鄰，相鄰則**合併（coalesce）**，以對抗外部碎片。
- `peek`/`poke` 以「整數位址當 `Array` 指標」的技巧直接讀寫 RAM，是整個 OS 的一切 I/O 基石。
