4.2 Hack 機器語言規格：A-指令與 C-指令

上一節確立了 ISA 的原則——Hack 只需兩類指令。現在我們把合約寫死：每一條指令的 16 個位元，分別代表什麼意思。本節是本書最重要的「規格書」章節，請把文中的兩張編碼總表（comp 與 dest/jump）當成字典使用——第六章寫組譯器時，就是把文字助記元對照這兩張表逐項翻譯；第五章做 CPU 時，也是依這兩張表把位元解讀成電路動作。本節最後會示範把一行行組合語言用手工翻譯成二進位機器碼，確認全程沒有模糊地帶。

三種指令都能做什麼？—— 兩類格式，一個故事

Hack 指令統一為 16 位元寬，所有指令分成兩大類。第一筆位元（最高位元 bit 15）是我們的「分類標籤」：

指令類型 bit15 其餘 15 位元 功能
A-指令（@xxx） 0 15 位元的位址或常數 把該數值載入 A 暫存器
C-指令（comp;dest;jump） 1 1、1、a、comp、dest、jump 計算、儲存、跳躍三合一

這種「看第一個位元就知道指令性質」的設計，讓第五章的 CPU 不用猜——電路只要檢查 bit15 是 0 還是 1，就能決定要把指令送進哪一條解碼路徑。

   A-指令： 0 ─────────────────────────────
            │ 0 │ x x x x x x x x x x x x x x x │
            「0 + 15 位元位址/常數」

   C-指令： 1 1 1 a c1 c2 c3 c4 c5 c6 d1 d2 d3 j1 j2 j3
            │固定│ │ 計算欄位 │ │ 目的欄位 │ │ 跳躍欄位 │

口訣：A 指令帶位址，C 指令帶運算。

A-指令：0 + 15 位元的位址/常數

格式

@value        其中 value 為 0~32767 的十進位整數
0 vvvvvvvvvvvvvvv        （最高位元 0 + 15 位元的數值）

語意

把 value 這個數值（同時也是位址）載入 A 暫存器。執行後：

  • A = value
  • 若指令的下一行要存取記憶體，則 M 就代表 RAM[value]
  • 若下一行是跳躍指令，跳躍目標就是 value

範例與編碼

組合語言 十進位值 15 位元二進位 完整 16 位元指令
@21 21 000000000010101 0 000000000010101 → 0000000000010101
@SCREEN 16384 100000000000000 0 100000000000000 → 0100000000000000
@KBD 24576 110000000000000 0 110000000000000 → 0110000000000000
@R5 5 000000000000101 0 000000000000101 → 0000000000000101

幾個重點：

  1. @ 後面既可以寫數字，也可以寫符號（如 SCREEN、R5、LOOP）。寫符號時，最終還是要由組譯器換成數字位址（第六章會處理）；但在概念上，位元層永遠是「0 + 15 位元數字」。
  2. 位址上限是 32767。A-指令無法表達 32768 以上的數字，這與 4.1 節說過的 32K 記憶體定址範圍一致。
  3. 「夾帶常數」的標準手法：A-指令本身不計算。想讓常數進入資料通路，慣例是先 @常數，緊接 D=A，把 A 裡的數值搬進 D 當運算元：
@100
D=A        // D = 100

C-指令：111 + a + cccccc + ddd + jjj

格式

comp ; dest ; jump        （分號在 Hack 語法中為可有可無的分隔記號）

1 1 1 a  c1 c2 c3 c4 c5 c6  d1 d2 d3  j1 j2 j3
│固定│ │  comp 欄位   │   dest 欄位 │  jump 欄位 │
欄位 位元位置 寬度 作用
前綴 111 bit 15~13 3 固定為 111，標示這是 C-指令。注意前綴必須與 bit12 以後區隔，避免與 A-指令混淆。
a bit 12 1 選擇計算運算元：0 表示用 A，1 表示用 M（即 RAM[A]）。
comp（ccc） bit 11~6 6 告訴 ALU 執行哪一種計算。
dest（ddd） bit 5~3 3 運算結果要寫進哪些地方（A / D / M，可複選）。
jump（jjj） bit 2~0 3 根據結果的負/零/正決定是否跳躍。

語意

一條 C-指令同時完成三件事，順序為：

  1. 計算：ALU 以 comp 指定的函數，用 D 與（由 a 選擇的）A 或 M 算出結果。
  2. 儲存：依 dest 把結果寫入 A、D、M（一個或多個）。
  3. 跳躍：依 jump 檢查結果的正負零，決定是否把 PC 設為 A 暫存器的值。

因為「計算結果」在同一個時脈內既被儲存、也被拿來判斷跳躍，所以 Hack 容許我們寫出例如 D=D+1;JGT 這種「邊算邊跳」的指令。

如何組合一個 C-指令

Hack 組合語言的 C-指令寫法是「dest=comp;jump」三段式，但三段都可以省略：

寫法 說明
D=M 只計算（comp=M）+ 存 D（dest=D），不跳。
D;JGT 只計算（comp=D）+ 跳躍（jump=JGT），不存。dest 留空。
MD=D+1 計算 D+1，同時存入 M 與 D。
0;JMP 計算常數 0，無條件跳躍（jump=JMP）。最經典的「無窮迴圈」。

「不指定 dest」時，引擎照樣算，只是不保存；「不指定 jump」時，引擎照樣算，只是不跳。這解釋了為什麼 0;JMP 這種「不存不跳錯」的寫法總是以 comp=0 隨便配一個計算欄位。

計算欄位 comp：一切交給 ALU

comp 指定 ALU「算什麼」，運算元是 D 與另一輸入。a=0 時另一個輸入是 A 暫存器的內容；a=1 時是 M（＝RAM[A]）。下表左半列出 a=0 的所有組合，右半列出對應的 a=1 版本。

comp 完整對照表

運算 a=0 c1c2c3c4c5c6 運算 a=1 c1c2c3c4c5c6 說明
0 101010 0 101010 常數 0（立即輸出 0）
1 111111 1 111111 常數 1
-1 111010 -1 111010 常數 -1（全 1）
D 001100 D 001100 D 暫存器的值
A 110000 M 110000 A 的值／RAM[A] 的值
!D 001101 !D 001101 對 D 逐位元取反
!A 110001 !M 110001 對 A／M 逐位元取反
-D 001111 -D 001111 D 的二補數取負
-A 110011 -M 110011 A／M 的負值
D+1 011111 D+1 011111 D 加 1
A+1 110111 M+1 110111 A／M 加 1
D-1 001110 D-1 001110 D 減 1
A-1 110010 M-1 110010 A／M 減 1
D+A 000010 D+M 000010 D + A／M
D-A 010011 D-M 010011 D − A／M
A-D 000111 M-D 000111 A/M − D
D&A 000000 D&M 000000 逐位元 AND
D\|A 010101 D\|M 010101 逐位元 OR

注意幾個有趣的對稱：

  1. A 與 M 的 c1…c6 完全相同，只是 a 位元不同——硬體共用一套電路，多一根選擇線切換輸入來源。
  2. 五個「原生函數」：0、1、-1、D、A/M 對應第二章 ALU 的五種最基礎輸出，其餘都是它們的組合。
  3. M=D+M 是合法的一條指令：comp 讀記憶體、dest 又寫回記憶體，硬體先算出 D+M 再把結果存回 RAM[A]，完全沒有衝突。

目的欄位 dest：結果要寫去哪

dest 的三個位元，由左至右依序對應 A、D、M 是否被寫入：

dest 助記元 d1(A) d2(D) d3(M) 動作
（空）null 0 0 0 不儲存結果
M 0 0 1 寫入 RAM[A]
D 0 1 0 寫入 D
MD 0 1 1 同時寫入 M 與 D
A 1 0 0 寫入 A
AM 1 0 1 同時寫入 A 與 M
AD 1 1 0 同時寫入 A 與 D
AMD 1 1 1 同時寫入 A、D、M

重點：

  • 任何對記憶體的寫入都必須透過 M，而 M 效力的前提是 A 暫存器先指向目標位址。
  • dest=A 雖然罕見，但它讓 D=A 與 A=M 這類指令成為可能。
  • dest 留空時（如 D;JGT），結果丟棄，但跳躍判斷仍看結果。

跳躍欄位 jump：結果的正負零決定去向

jump 的三個位元，由左至右依序是 j1（結果<0）、j2（結果=0）、j3（結果>0）：「看落點在哪一區就跳」。

jump 助記元 j1(<0) j2(=0) j3(>0) 跳躍條件
（空）null 0 0 0 不跳
JGT 0 0 1 結果 > 0
JEQ 0 1 0 結果 = 0
JGE 0 1 1 結果 ≥ 0（>0 或 =0）
JLT 1 0 0 結果 < 0
JNE 1 0 1 結果 ≠ 0（<0 或 >0）
JLE 1 1 0 結果 ≤ 0（<0 或 =0）
JMP 1 1 1 無條件跳躍

跳躍的機制是：若條件成立，下一條指令位址（PC）＝ A 暫存器現在的值。所以跳躍指令之前，永遠要先有一個 @目標 把目標位址放進 A：

@END
D;JEQ        // 若 D==0，跳去標籤 END（A 已載入 END 的位址）

組合語言寫法 @END 搭配 D;JEQ，在機器碼層次是兩條指令；END 這個標籤也會在組譯階段被換成真實的 ROM 位址。

位址暫存器 A 與記憶體 M：存取記憶體的「兩步舞」

前面反覆強調，「想碰 RAM，先餵 A」。這個規則是 Hack 指令集的靈魂，值得用一個小節講透。在 Hack 中：

  • M 只是「RAM[A]」的代名詞，世界上沒有獨立的 M 暫存器電路。
  • 因此，想要讀寫記憶體，任何程式都必須遵循同一個兩步節奏：
@100        // 步驟一：A = 100（指定位址）
M=D         // 步驟二：RAM[100] = D     （寫）

@100        // 步驟一：A = 100
D=M         // 步驟二：D = RAM[100]     （讀）

如果把「內容」與「位址」分開思考，A 在讀取的瞬間扮演了「指標」，而 D=M、M=D、M=M+1 這些指令則同時具備「解參考（dereference）」的意義。正是因為 A 具有「既是資料又是位址」的雙重身分，Hack 才能用如此精簡的指令集表達出指針程式設計的所有威力。這個「兩步舞」模式的萬用寫法如下：

// 將「位址指標」存在暫存器與記憶體中遊走
@addr        // A = 位址 addr 的位置
A=M          // A = RAM[addr]（把指標的值解出來，成為新位址）
D=M          // D = RAM[RAM[addr]]——真正的目標內容

上面的例子同時示範了 dest=A 的用途：A=M 把「指標所指的位址」放回 A，讓後續指令能繼續透過它存取目標。陣列走訪、螢幕塗色（4.3 節）全靠這招。

完整編碼實作：把一個程式手工組譯

理論讀夠了，現在動手把組合語言一行行翻成 0/1。我們用一個「兩個記憶體字組相加」的小程式當範例：

// Add2.asm：計算 RAM[2] = RAM[0] + RAM[1]
@R0
D=M          // D = RAM[0]
@R1
D=D+M        // D = RAM[0] + RAM[1]
@R2
M=D          // RAM[2] = D
(END)
@END
0;JMP        // 無窮迴圈：程式結束

逐行編碼（R0、R1、R2 是預先定義符號，值為 0、1、2；END 標籤落在第 6 條指令的位置）：

# 組合語言 判斷 16 位元二進位 十六進位
0 @R0 A-指令，值 0 0000000000000000 0x0000
1 D=M C：a=1, comp=M(110000), dest=D(010), jump=000 1111110000010000 0xFC10
2 @R1 A-指令，值 1 0000000000000001 0x0001
3 D=D+M C：a=1, comp=D+M(000010), dest=D(010), jump=000 1111000010010000 0xF090
4 @R2 A-指令，值 2 0000000000000010 0x0002
5 M=D C：a=0, comp=D(001100), dest=M(001), jump=000 1110001100001000 0xE308
6 @END A-指令，值 6 0000000000000110 0x0006
7 0;JMP C：a=0, comp=0(101010), dest=null(000), jump=JMP(111) 1110101010000111 0xEA87

產生的.hack 檔內容即為上表「16 位元二進位」那一欄逐行排列。你可以親手用下列公式驗證： D=M＝前綴 111＋a=1＋comp=110000＋dest=010＋jump=000 → 1111 1100 0001 0000（0xFC10），與上表一致。這就是組譯器（第六章）內部每天在做的事——只是它做得又準又快。

進階組合語言範例

學會兩張編碼表後，可以玩出更多花樣。下面兩個例子刻意把「運算、資料位置、跳躍」三個元素都塞進短短幾行。

例一：絕對值函數

// 計算 RAM[1] = |RAM[0]|
@R0
D=M          // D = RAM[0]
@POS
D;JGE        // 若 D ≥ 0，跳過取負
D=-D         // D = -D（利用 comp 的 -D 運算）
(POS)
@R1
M=D          // RAM[1] = |RAM[0]|
(END)
@END
0;JMP

例二：陣列走訪（指標解參考）

// 把 RAM[10] 開始的連續 5 個字組全部歸零
@5
D=A
@n
M=D          // n = 5（元素個數）
@10
D=A
@p
M=D          // p = 10（起始指標）
(LOOP)
@p
A=M          // A = 指標所指位址（解參考）
M=0          // RAM[p] = 0
@p
M=M+1        // p = p + 1（前進一個字組）
@n
M=M-1        // n = n - 1
@n
D=M
@LOOP
D;JGT        // n > 0 就繼續
(END)
@END
0;JMP

第二個例子把 A-指令、C-指令、標籤、變數符號（n、p）全部派上用場，正是第四節「正式寫程式」的預習。

設計思路與實作步驟

設計 Hack 指令格式時，我們依循了幾個明確的工程決策：

  1. 用 bit15 做指令分類：第一看看 0 或 111… 即知種類，解碼電路分岔最簡單。
  2. C-指令的欄位寬度固定：1+1+6+3+3=14 位元加上前綴正好 16 位元，不浪費、不重疊，位元位置直接刻進電路。
  3. comp 與第二章 ALU 對齊：c1…c6 直接餵給 ALU 的控制腳，第五章幾乎不用加解碼邏輯。
  4. 跳躍目標統一放 A：避免要為「跳躍專用暫存器」再分配位元；代價是跳躍前必須先 @目標。
  5. 導入符號層：@R0、@LOOP、@SCREEN 這些符號在組譯階段才解析成位址，程式設計師不用背數字。
  6. 用 CPU 模擬器驗證編碼：把上面的 .hack 檔載入模擬器逐步執行，檢查 D、A、RAM 的變化是否符合語意。

本章小結

  • A-指令：0＋15 位元數值，唯一任務是把位址/常數載入 A；可寫數字或符號，位址上限 32767。
  • C-指令：111 a cccccc ddd jjj，一次完成「計算、儲存、跳躍」；a 選 A/M，comp 指定 ALU 函數，dest 指定寫入目標，jump 依結果負零正決定是否把 PC 設為 A。
  • comp 表：0/1/-1/D/A(M)/!D/!A(!M)/-D/-A(-M)/D+1/A+1/M+1/D-1/…/D+A/D-A/A-D/D&A/D|A，且 A 與 M 共用同一組 c1…c6，只差 a 位元。
  • dest 表：null/M/D/MD/A/AM/AD/AMD；jump 表：null/JGT/JEQ/JGE/JLT/JNE/JLE/JMP。
  • 兩步舞守則：讀寫記憶體前必先 @位址 餵 A；A=M＋M=… 是強大的指標解參考組合。
  • 手工組譯：每一條指令都能透過「判斷指令種類 → 查表 → 填空」三步驟轉成 16 位元碼，這是第六章組譯器自動化的藍本。
