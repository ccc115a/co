# 第十章：編譯器 —— 從高階語言到虛擬機碼

## 前言

在前面的章節中，我們已經建造了一台完整的電腦：從硬體閘道（第 1 章）到 CPU 與記憶體（第 5 章），再到組譯器（第 6 章）與虛擬機（第 7 章）。如今，我們站在軟體棧的最頂端，準備挑戰最後一個也是最複雜的組件——**編譯器（Compiler）**。

編譯器是連接「人類思考方式」與「機器執行方式」之間的橋樑。它將高階、易讀的程式語言（如 Java、Python、C++），翻譯成低階的機器可執行指令。在 nand2tetris 的世界裡，我們要將自己設計的 **Jack 程式語言**，編譯成虛擬機碼（VM code），進而讓第 7 章建立的 VM 翻譯器（VM Translator）將其轉換為組語，最終在硬體上執行。

本章將帶領你從零開始，理解編譯器的基本原理，並動手實作一個完整的 Jack 編譯器。這是一趟從「理解語言」到「生成程式碼」的旅程。

---

## 10.1 編譯器的角色

### 編譯器是什麼？

簡單來說，**編譯器是一種程式，它將一種語言（來源語言）翻譯成另一種語言（目標語言）**。最常見的編譯器，是將高階程式語言翻譯成低階的機器語言或虛擬機碼。

打個比方：如果你是一位講中文的工程師，而機器只懂英文指令，那編譯器就是一位翻譯官——他聽你說中文，然後把你的意思精確地轉述成英文，讓機器能理解並執行。

### 編譯器的歷史意義

編譯器的發明是計算機科學史上最重要的突破之一。1957 年，John McCarthy 的團隊在 MIT 開發了第一個 LISP 編譯器，而更早的 Fortran 編譯器（1957 年，由 John Backus 領導的 IBM 團隊開發）則開創了高階語言編譯的先河。在此之前，程式設計師必須手寫組語或機器碼，極度低效且容易出錯。

有了編譯器之後，人類可以用接近自然語言的方式書寫程式，而交由電腦完成繁瑣的翻譯工作。這項技術直接催生了整個軟體產業。

## 10.2 編譯器的整體管線（Pipeline）

一個典型的編譯器可以分為兩個主要階段：**前端（Front End）** 與 **後端（Back End）**。

### 前端：理解來源語言

前端負責「閱讀」來原始碼，理解其結構與語意，並產生一種中間表示（Intermediate Representation, IR）。前端的工作與目標機器無關——無論你要編譯到 x86、ARM 還是虛擬機，前端的分析過程是一樣的。

前端通常包含以下幾個子階段：

```
原始碼 ──→ [詞法分析] ──→ [語法分析] ──→ [語意分析] ──→ 中間表示
           (Scanner)       (Parser)       (Semantic)
```

1. **詞法分析（Lexical Analysis / Scanning）**：將字元流（character stream）轉換為記號流（token stream）。空白、註解等會被移除，有意義的單元（關鍵字、識別碼、常數、符號）被提取出來。

2. **語法分析（Parsing / Syntactic Analysis）**：將記號流依照語法規則（文法）組織成一棵語法樹（Parse Tree 或 Abstract Syntax Tree, AST），檢查程式結構是否合法。

3. **語意分析（Semantic Analysis）**：檢查程式的邏輯意義是否正確。例如變數是否已宣告、型態是否匹配、函式呼叫的參數個數是否正確等。

### 後端：生成目標碼

後端負責將前端產生的中間表示翻譯成目標語言：

```
中間表示 ──→ [代碼生成] ──→ [代碼優化] ──→ 目標碼
             (Code Gen)      (Optimizer)
```

4. **代碼生成（Code Generation）**：根據中間表示，產生目標平台的指令碼。在 nand2tetris 中，目標是 VM 碼。

5. **代碼優化（Code Optimization）**（可選）：對生成的代碼進行各種變換，使其更小或更快。在 nand2tetris 的 Jack 編譯器中，我們通常省略這個步驟，以保持簡單性。

### 前端與後端分離的優勢

這種劃分的核心價值在於**可重用性**。同一個前端可以搭配不同的後端，產生不同平台的目標碼。例如，Java 的前端將 `.java` 編譯成 `.class` 的位元組碼（bytecode），而不同的 JVM 實作（HotSpot、OpenJ9）則可以作為後端，將位元組碼翻譯成不同作業系統上的機器碼。

在 nand2tetris 中，我們的編譯器也遵循這個架構：

- **前端**：JackTokenizer + CompilationEngine（分析 Jack 語言，產生 VM 碼）
- **後端**：VM Translator（將 VM 碼翻譯成組語）

## 10.3 Jack 編譯器的架構

在我們的 nand2tetris 專案中，Jack 編譯器需要處理以下工作：

```
.jack 檔案（原始碼）
    │
    ▼
┌─────────────────────────────┐
│       Jack 編譯器            │
│                             │
│  ┌───────────────────────┐  │
│  │  JackTokenizer        │  │
│  │  （詞法分析器）         │  │
│  └──────────┬────────────┘  │
│             ▼               │
│  ┌───────────────────────┐  │
│  │  CompilationEngine     │  │
│  │  （語法分析器 +         │  │
│  │   代碼生成器）          │  │
│  └──────────┬────────────┘  │
│             ▼               │
└─────────────┼───────────────┘
              │
              ▼
        .vm 檔案（VM 碼）
```

### 兩個核心組件

1. **JackTokenizer**（詞法分析器）：
   - 輸入：`.jack` 檔案的字元流
   - 輸出：token 序列
   - 職責：識別關鍵字、符號、識別碼、整數常量、字串常量

2. **CompilationEngine**（語法分析器 + 代碼生成器）：
   - 輸入：token 序列（從 JackTokenizer 取得）
   - 輸出：`.vm` 檔案
   - 職責：解析語法結構、驗證語意、產生 VM 碼

## 10.4 輸入與輸出

### 輸入：Jack 原始碼

Jack 是我們自己設計的高階物件導向語言。一個簡單的 Jack 程式可能長這樣：

```jack
// Main.jack
class Main {
    function void main() {
        var int x, y;
        let x = 17;
        let y = 24;
        do Output.printString("Hello, World! ");
        do Output.printInt(x + y);
        do Output.println();
        return;
    }
}
```

### 輸出：XML 與 VM 檔案

在我們的 nand2tetris 實作中，編譯器有兩個輔助輸出：

1. **`XxxT.xml`**：tokenizer 的輸出，列出所有 token
2. **`Xxx.xml`**：parser 的輸出，以 XML 標記呈現語法樹結構
3. **`Xxx.vm`**：最終的 VM 碼，是真正的編譯產物

XML 輸出的主要目的是**驗證與除錯**。nand2tetris 提供了 `TextComparer` 工具，可以比較你的輸出與預期輸出是否一致。

## 10.5 編譯器 vs 直譯器 vs 組譯器

理解編譯器的最佳方式，是將它與其他語言處理工具做比較：

| 特性 | 編譯器 (Compiler) | 直譯器 (Interpreter) | 組譯器 (Assembler) |
|------|-------------------|---------------------|-------------------|
| **翻譯時機** | 執行前（離線） | 執行時（即時） | 執行前（離線） |
| **輸入** | 高階語言原始碼 | 高階語言原始碼 | 組語原始碼 |
| **輸出** | 目標碼（機器碼/VM碼） | 無（直接執行） | 機器碼 |
| **執行速度** | 快（已翻譯） | 慢（逐行翻譯） | 快（直接執行） |
| **錯誤偵測** | 編譯時即可發現許多錯誤 | 只在執行到該行時才發現 | 編譯時 |
| **可移植性** | 較差（需針對平台編譯） | 較好（靠直譯器跨平台） | 最差（綁定特定架構） |
| **範例** | C, C++, Rust | Python, JavaScript, Ruby | x86 組語, ARM 組語 |

### 編譯器的優勢

- **執行效率高**：所有翻譯工作在編譯時完成，執行時不需要再進行語言分析
- **最佳化空間大**：編譯器可以在翻譯過程中對整體代碼進行分析與優化
- **錯誤偵測完整**：可以在編譯時檢查型態錯誤、未宣告變數等問題

### 直譯器的優勢

- **開發效率高**：修改後可立即執行，不需要等待編譯
- **可移植性好**：只要目標平台有直譯器，同一份原始碼到處可跑
- **互動性強**：適合 REPL（Read-Eval-Print Loop）式的互動開發

### 組譯器的特殊地位

組譯器與編譯器的最大差異在於：組語與機器碼之間幾乎是**一對一**的對應關係。每一條組語指令通常對應一條機器指令。而編譯器面對的高階語言與目標碼之間，則是**一對多**或**多對一**的複雜映射。

在 nand2tetris 中，我們依序建構了：組譯器（第 6 章）→ VM 翻譯器（第 7 章）→ 編譯器（本章）。這恰好是計算機科學中「逐層抽象」理念的完美體現。

## 10.6 nand2tetris 編譯器的設計理念

nand2tetris 的 Jack 編譯器被刻意設計得**簡單而完整**。它不追求效率或最佳化，而是要讓學生完整體驗編譯器的每一個核心步驟：

1. **遞迴下降（Recursive Descent）**：我們使用遞迴下降解析器，這是最直覺、最容易理解的語法分析方法。每個文法規則對應一個函式。

2. **單趟編譯（Single-Pass）**：在可能的範圍內，我們在一趟掃描中同時完成解析與代碼生成，而不像工業級編譯器那樣分為多趟。

3. **XML 作為中介表示**：XML 格式讓我們可以用文字工具（如 TextComparer）驗證編譯器的正確性，這是教學上的重要設計。

4. **模組化設計**：JackTokenizer 與 CompilationEngine 的職責分明，各自可以獨立測試。

## 10.7 編譯過程的總覽

以下是一個完整 Jack 程式的編譯流程圖：

```
          Jack 原始碼
               │
               ▼
    ┌─────────────────────┐
    │   字元流 (char)      │
    │   "class Main {     │
    │    function void..." │
    └─────────┬───────────┘
              │ JackTokenizer
              ▼
    ┌─────────────────────┐
    │   Token 流           │
    │   <keyword>class    │
    │   <identifier>Main  │
    │   <symbol>{         │
    │   <keyword>function │
    │   ...               │
    └─────────┬───────────┘
              │ CompilationEngine
              ▼
    ┌─────────────────────┐
    │   語法樹 (XML)       │
    │   <class>           │
    │     <keyword>class  │
    │     <identifier>    │
    │     <symbol>{       │
    │     <subroutineDec> │
    │       ...           │
    └─────────┬───────────┘
              │ 代碼生成
              ▼
    ┌─────────────────────┐
    │   VM 碼              │
    │   function Main     │
    │     .main 0         │
    │   push constant 17  │
    │   pop local 0       │
    │   ...               │
    └─────────────────────┘
```

## 本章小結

本章是第十章的導論，我們介紹了編譯器的基本概念：

- **編譯器**是將高階語言翻譯成低階語言的程式，是軟體棧中最上層的組件。
- 編譯器管線包含：詞法分析、語法分析、語意分析、代碼生成等階段。
- 前端負責理解來源語言（與目標機器無關），後端負責生成目標碼。
- 在 nand2tetris 中，Jack 編譯器的輸入是 `.jack` 檔案，輸出是 `.vm` 檔案（以及輔助的 XML 檔案）。
- Jack 編譯器使用遞迴下降解析法，由 JackTokenizer 和 CompilationEngine 兩個核心組件構成。
- 編譯器與直譯器、組譯器各有優劣，適用於不同場景。
