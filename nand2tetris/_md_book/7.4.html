7.4 記憶體段（Memory Segments）的映射與存取

前言

前兩節我們學會了 push constant 和所有算術邏輯指令的翻譯。但 VM 的強大之處不止於常數運算——它需要處理變數。而變數的存取，就是透過**記憶體段（Memory Segments）**來完成。

Nand2Tetris 的 VM 定義了八個記憶體段：argument、local、static、constant、this、that、pointer、temp。每個段都有自己的「虛擬位址空間」（從 0 開始的偏移量），VM 翻譯器的任務就是把这些虛擬位址映射到 Hack RAM 的實體位址。

本節將詳解每個段的映射規則、push/pop segment i 的完整 Hack 翻譯，以及完整的追蹤範例。

1. 八個記憶體段總覽

  VM 的八個記憶體段：

  ┌─────────────┬────────────────────┬─────────────────────────┐
  │ 段名         │ 虛擬位址範圍       │ Hack RAM 實體映射        │
  ├─────────────┼────────────────────┼─────────────────────────┤
  │ argument    │ 0, 1, 2, ...       │ RAM[ARG + i]            │
  │ local       │ 0, 1, 2, ...       │ RAM[LCL + i]            │
  │ static      │ 0, 1, 2, ...       │ RAM[16 + k]（唯一位址）   │
  │ constant    │ 0, 1, 2, ...       │ 不映射 RAM（虛擬常數）    │
  │ this        │ 0, 1, 2, ...       │ RAM[THIS + i]           │
  │ that        │ 0, 1, 2, ...       │ RAM[THAT + i]           │
  │ pointer     │ 0 或 1             │ THIS（位址 3）或 THAT（位址 4）│
  │ temp        │ 0 ~ 7              │ RAM[5 + i]              │
  └─────────────┴────────────────────┴─────────────────────────┘

每個段的核心概念：基地址（base address）+ 偏移量（offset）= 實體 RAM 位址。

2. 各段的映射規則详解

2.1 constant 段（特殊）

constant 段不映射到任何 RAM。它只是一個「值的來源」。push constant i 就是把整數 i 直接壓入堆疊——不需要從 RAM 讀取。

push constant 7   // 直接把 7 壓入堆疊

翻譯方式（與 7.2 節相同）：

@7
D=A
@SP
A=M
M=D
@SP
M=M+1

2.2 argument 段（引數）

argument 段存放函式的引數。基地址存在 ARG（這是一個「虛擬暫存器」，存在 RAM 的某個位址）。

push argument 0   // 讀取第一個引數
pop argument 2    // 寫入第三個引數位址

映射規則：argument i → RAM[ARG + i]

2.3 local 段（本地變數）

local 段存放函式的本地變數。基地址存在 LCL。

push local 0      // 讀取第一個本地變數
pop local 1       // 寫入第二個本地變數位址

映射規則：local i → RAM[LCL + i]

2.4 static 段（靜態變數）

static 段存放檔案級別的全域變數。與其他段不同，static 段不使用基地址+offset 的模式——每個 static i 被映射到一個全域唯一的 RAM 位址（從 16 開始）。

push static 0     // 讀取第 0 個靜態變數
pop static 1      // 寫入第 1 個靜態變數

映射規則：static i → RAM[16 + i]

（在組譯器中，static 0 被翻譯成 @Xxx.0、static 1 被翻譯成 @Xxx.1，其中 Xxx 是 VM 檔案名稱。）

2.5 this 段（物件資料）

this 段用來存取「當前物件」的資料欄位。基地址存在 THIS（虛擬暫存器）。

push this 0       // 讀取物件的第 0 個欄位
pop this 2        // 寫入物件的第 2 個欄位

映射規則：this i → RAM[THIS + i]

2.6 that 段（陣列元素）

that 段用來存取「由 THAT 指向的記憶體區塊」，通常用於陣列操作。

push that 0       // 讀取 THAT[0]
pop that 3        // 寫入 THAT[3]

映射規則：that i → RAM[THAT + i]

2.7 pointer 段（物件基地址操作）

pointer 段只有兩個值：0 和 1。它不是用來讀寫「資料」，而是用來設定 THIS 和 THAT 的值。

push pointer 0    // 把 THIS 的值壓入堆疊
pop pointer 1     // 把堆疊頂端的值設為 THAT

映射規則：

  • pointer 0 → 直接操作 THIS（存在 RAM[3]）
  • pointer 1 → 直接操作 THAT（存在 RAM[4]）

2.8 temp 段（臨時變數）

temp 段提供 8 個固定位址的臨時變數（不使用基地址+offset）。

push temp 0       // 讀取 RAM[5]
pop temp 3        // 寫入 RAM[8]

映射規則：temp i → RAM[5 + i]，其中 0 ≤ i ≤ 7

3. 堆疊指標（SP）與基地址的關係

VM 使用了兩個關鍵指標系統：

3.1 SP（Stack Pointer）

SP = RAM[0]
堆疊頂端的值 = RAM[SP - 1]
下一個可 push 的位址 = RAM[SP]

3.2 各段的基地址寄存器

Nand2Tetris 把基地址放在特定的 RAM 位址：

  RAM[0]   = SP   （堆疊指標）
  RAM[1]   = LCL  （local 段基地址）
  RAM[2]   = ARG  （argument 段基地址）
  RAM[3]   = THIS （物件資料基地址）
  RAM[4]   = THAT （陣列基地址）

這些位址在函式呼叫時由 VM 的 call 指令設定，在函式返回時由 return 指令恢復。本節先假設它們已經被正確設定。

4. push/pop segment i 的完整翻譯

4.1 push segment i（通用模板）

  目標：把 RAM[base + i] 的值壓入堆疊

  步驟：
  ① 取得 base 的值（從對應的基地址寄存器）
  ② 加上偏移量 i
  ③ 從那個位址讀取值
  ④ 把值寫入堆疊頂端
  5  SP++

以 push local 2 為例：

// push local 2
@LCL         // A = 1（LCL 的位址）
D=M          // D = LCL 的值（例如 2048）
@2           // A = 2（偏移量）
D=D+A        // D = 2048 + 2 = 2050（目標位址）
@R13         // A = 13（暫存位址）
M=D          // R13 = 2050（暫存目標位址）
@SP          // A = 0
A=M          // A = SP 的值
D=M          // D = SP 當前的值（不是要的！需要從目標位址讀取）

等等，上面的邏輯有問題——我們需要用 R13 暫存目標位址，然後從那個位址讀取。正確的翻譯是：

// push local 2
@LCL         // A = 1
D=M          // D = LCL（基地址，例如 2048）
@2           // A = 2
D=D+A        // D = LCL + 2 = 2050
@R13         // A = 13
M=D          // R13 = 2050（暫存目標位址）
@R13         // A = 13
A=M          // A = 2050
D=M          // D = RAM[2050]（讀取本地變數的值）
@SP          // A = 0
A=M          // A = SP
M=D          // RAM[SP] = D（值壓入堆疊）
@SP          // A = 0
M=M+1        // SP++

14 條指令。

但這個翻譯有冗餘的 @R13。更優化的版本：

// push local 2（優化版）
@LCL         // A = 1
D=M          // D = LCL
@2           // A = 2
D=D+A        // D = LCL + 2（目標位址）
A=D          // A = 目標位址（直接跳過去，不需要 R13）
D=M          // D = RAM[LCL + 2]
@SP          // A = 0
A=M          // A = SP
M=D          // RAM[SP] = 值
@SP          // A = 0
M=M+1        // SP++

10 條指令。 A=D 這條指令直接把目標位址載入 A，省掉了 R13 的中間步驟。

4.2 通用 push 模板的翻譯器實現

def _translate_push_segment(self, segment, index):
    """翻譯 push segment index"""
    base_reg = SEGMENT_BASE[segment]  # 'local'→'LCL', 'argument'→'ARG', etc.
    return f"""
@{base_reg}
D=M
@{index}
D=D+A
A=D
D=M
@SP
A=M
M=D
@SP
M=M+1
"""

其中段名到基地址寄存器的映射：

SEGMENT_BASE = {
    'local':    'LCL',
    'argument': 'ARG',
    'this':     'THIS',
    'that':     'THAT',
}

4.3 pop segment i（通用模板）

  目標：把堆疊頂端的值寫入 RAM[base + i]

  步驟：
  ① 取得 base 的值
  ② 加上偏移量 i，計算目標位址
  ③ 暫存目標位址
  ④ SP--
  5  從堆疊頂端取出值
  6  把值寫入目標位址

以 pop local 2 為例：

// pop local 2
@LCL         // A = 1
D=M          // D = LCL
@2           // A = 2
D=D+A        // D = LCL + 2（目標位址）
@R13         // A = 13
M=D          // R13 = 2050（暫存目標位址）
@SP          // A = 0
M=M-1        // SP--
A=M          // A = SP
D=M          // D = 堆疊頂端的值
@R13         // A = 13
A=M          // A = 2050
M=D          // RAM[2050] = 值

12 條指令。 注意 pop 必須使用 R13 暫存目標位址——因為 M=D 需要先設定 A 為目標位址，但我們需要先把 D 的值從堆疊取出來。這個「先暫存再取值」的模式是 pop 的固定套路。

4.4 通用 pop 模板的翻譯器實現

def _translate_pop_segment(self, segment, index):
    """翻譯 pop segment index"""
    base_reg = SEGMENT_BASE[segment]
    return f"""
@{base_reg}
D=M
@{index}
D=D+A
@R13
M=D
@SP
AM=M-1
D=M
@R13
A=M
M=D
"""

5. 特殊段的翻譯

5.1 push/pop pointer

pointer 段直接操作 THIS（位址 3）和 THAT（位址 4）：

push pointer 0   // 把 THIS 的值壓入堆疊

// push pointer 0
@THIS          // A = 3
D=M            // D = THIS 的值
@SP            // A = 0
A=M            // A = SP
M=D            // RAM[SP] = THIS
@SP            // A = 0
M=M+1          // SP++

7 條指令。 注意這裡的 THIS 是直接從 RAM[3] 讀取，不需要加偏移量——因為 pointer 只有 0 和 1 兩個值。

pop pointer 1   // 把堆疊頂端的值設為 THAT

// pop pointer 1
@SP            // A = 0
M=M-1          // SP--
A=M            // A = SP
D=M            // D = 堆疊頂端的值
@THAT          // A = 4
M=D            // THAT = D

6 條指令。 比其他 pop 簡單——因為不需要計算目標位址。

5.2 push/pop temp

temp 段有固定位址（RAM[5] 到 RAM[12]）：

push temp 3     // 讀取 RAM[8]

// push temp 3
@8             // A = 5 + 3 = 8（翻譯器計算好的實體位址）
D=M            // D = RAM[8]
@SP            // A = 0
A=M            // A = SP
M=D            // RAM[SP] = RAM[8]
@SP            // A = 0
M=M+1          // SP++

7 條指令。 翻譯器直接把 5 + i 計算好，硬編碼進去。

pop temp 3      // 寫入 RAM[8]

// pop temp 3
@SP            // A = 0
M=M-1          // SP--
A=M            // A = SP
D=M            // D = 堆疊頂端的值
@8             // A = 8（5 + 3）
M=D            // RAM[8] = D

6 條指令。 temp 段的 pop 比其他段簡單——因為位址是固定的，不需要 R13 暫存。

5.3 push/pop static

static 段在翻譯時會被替換成全域唯一位址：

push static 0   // 在 Foo.vm 中，這會翻譯成讀取 @Foo.0

// push static 0（Foo.vm）
@Foo.0          // A = Foo.0 的位址（由組譯器配置，例如 16）
D=M            // D = RAM[16]
@SP            // A = 0
A=M            // A = SP
M=D            // RAM[SP] = RAM[16]
@SP            // A = 0
M=M+1          // SP++

8 條指令。 @Foo.0 是一個符號，由第 6 章的組譯器解析成實際位址。

6.2 執行追蹤

假設 LCL = 2048、ARG = 3000，追蹤這個程式的記憶體變化：

步驟 0（初始）:
  SP=256, LCL=2048, ARG=3000

步驟 1（push constant 17）:
  SP=257, RAM[256]=17

步驟 2（pop local 0）:
  SP=256, RAM[2048]=17    ← local 0 = 17

步驟 3（push constant 3）:
  SP=257, RAM[256]=3

步驟 4（pop local 1）:
  SP=256, RAM[2049]=3     ← local 1 = 3

步驟 5（push local 0）:
  SP=257, RAM[256]=17     ← 從 RAM[2048] 讀取

步驟 6（push local 1）:
  SP=258, RAM[257]=3      ← 從 RAM[2049] 讀取

步驟 7（add）:
  SP=257, RAM[256]=20     ← 17 + 3 = 20

步驟 8（pop argument 0）:
  SP=256, RAM[3000]=20    ← argument 0 = 20

每一步的記憶體變化都可以用「基地址 + 偏移量」來驗證。

7. 七個段的翻譯模式對照表

段 push 的 Hack 行為 pop 的 Hack 行為 特殊處理
constant 載入常數到 D → push 不允許（會報錯） 不映射 RAM
local D=M(LCL+i) → push pop → M(LCL+i)=D 用 R13 暫存
argument D=M(ARG+i) → push pop → M(ARG+i)=D 用 R13 暫存
this D=M(THIS+i) → push pop → M(THIS+i)=D 用 R13 暫存
that D=M(THAT+i) → push pop → M(THAT+i)=D 用 R13 暫存
pointer 直接讀 THIS/THAT 直接寫 THIS/THAT i 只能是 0 或 1
temp 直接讀 RAM[5+i] 直接寫 RAM[5+i] i 只能是 0~7
static 讀 @Xxx.i 寫 @Xxx.i 由組譯器配置位址

8. 翻譯器實作的段處理模組

把所有段的翻譯整合成一個完整的處理器：

class VMTranslator:
    SEGMENT_BASE = {
        'local': 'LCL', 'argument': 'ARG',
        'this': 'THIS', 'that': 'THAT',
    }
    TEMP_BASE = 5

    def translate_push(self, segment, index):
        if segment == 'constant':
            return f"""
@{index}
D=A
@SP
A=M
M=D
@SP
M=M+1
"""
        elif segment in self.SEGMENT_BASE:
            base = self.SEGMENT_BASE[segment]
            return f"""
@{base}
D=M
@{index}
D=D+A
A=D
D=M
@SP
A=M
M=D
@SP
M=M+1
"""
        elif segment == 'pointer':
            reg = 'THIS' if index == 0 else 'THAT'
            return f"""
@{reg}
D=M
@SP
A=M
M=D
@SP
M=M+1
"""
        elif segment == 'temp':
            return f"""
@{self.TEMP_BASE + index}
D=M
@SP
A=M
M=D
@SP
M=M+1
"""
        elif segment == 'static':
            return f"""
@{self._static_var(index)}
D=M
@SP
A=M
M=D
@SP
M=M+1
"""

    def translate_pop(self, segment, index):
        if segment in self.SEGMENT_BASE:
            base = self.SEGMENT_BASE[segment]
            return f"""
@{base}
D=M
@{index}
D=D+A
@R13
M=D
@SP
AM=M-1
D=M
@R13
A=M
M=D
"""
        elif segment == 'pointer':
            reg = 'THIS' if index == 0 else 'THAT'
            return f"""
@SP
AM=M-1
D=M
@{reg}
M=D
"""
        elif segment == 'temp':
            return f"""
@SP
AM=M-1
D=M
@{self.TEMP_BASE + index}
M=D
"""
        elif segment == 'static':
            return f"""
@SP
AM=M-1
D=M
@{self._static_var(index)}
M=D
"""

設計思路：這段翻譯碼展現了一個重要的軟體設計模式——策略模式（Strategy Pattern）。每個段的翻譯邏輯不同，但介面相同（都是 translate_push/translate_pop）。用字典（SEGMENT_BASE）把「段名 → 基地址寄存器名」抽離出來，新增段只需要加一行字典項，不需要改翻譯邏輯。

9. 本章小結

  • VM 定義了八個記憶體段，每個段提供結構化的變數存取方式。
  • 五個「基地址段」（argument、local、this、that、static）使用基地址 + 偏移量的映射模式：RAM[base + i]。
  • pointer 段只有兩個值（0→THIS、1→THAT），直接操作物件基地址寄存器。
  • temp 段有固定位址（RAM[5] 到 RAM[12]），不需要基地址寄存器。
  • constant 段不映射 RAM，push constant i 直接把整數 i 壓入堆疊。
  • push segment i 的 Hack 翻譯：讀取基地址 → 加偏移量 → 從該位址讀取 → 壓入堆疊（~10 條指令）。
  • pop segment i 的 Hack 翻譯：計算目標位址 → 暫存到 R13 → SP-- → 取值 → 寫入 R13 指向的位址（~12 條指令）。
  • 特殊段（pointer、temp、static）的翻譯更簡短，因為它們不需要基地址+偏移量的計算。
