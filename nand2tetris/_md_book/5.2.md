# 5.2 記憶體晶片與匯流排整合（Memory Module）

## 前言

在上一節中，我們完成了 CPU 的設計。CPU 透過 `addressM`、`outM` 和 `writeM` 與記憶體溝通，但記憶體本身還是一個黑盒子。本節將揭開這個黑盒子，深入了解 Hack 記憶體系統的內部結構。Hack 的記憶體不僅僅是一個 RAM，它還整合了螢幕緩衝區與鍵盤輸入介面，形成一個統一的位址空間。理解記憶體模組的設計，是將 CPU 與電腦系統連接起來的關鍵一步。

---

## Hack Memory 的組成

Hack Memory 模組將三個不同的記憶體裝置整合在一個統一的位址空間中：

### 位址空間劃分

| 位址範圍 | 裝置 | 說明 |
|----------|------|------|
| `0 - 16383` | RAM16K | 通用隨機存取記憶體，16K 個 16-bit 字 |
| `16384 - 24575` | Screen | 螢幕記憶體映像（8K 個 16-bit 字） |
| `24576` | Keyboard | 鍵盤映射暫存器（1 個 16-bit 字） |

這個位址空間的設計非常優雅：

- **RAM16K** 提供 16,384 個 16-bit 記憶體位置，是程式的主要儲存空間
- **Screen** 占據 8K 位置，映射到 256×512 像素的螢幕緩衝區
- **Keyboard** 只有一個位置，反映當前按下的鍵碼

### Memory 晶片的 load/write 行為

Memory 模組的行為可以用以下規則描述：

1. **讀取永遠有效**：不論位址指向哪裡，讀取操作總是返回該位址的當前值
2. **寫入只在 RAM 區域有效**：只有當位址在 `0 - 16383` 範圍內，且 `load` 訊號為 1 時，資料才會被寫入
3. **Screen 寫入**：當位址在 `16384 - 24575` 且 `load=1` 時，資料寫入螢幕緩衝區，並立即反映在螢幕顯示上
4. **Keyboard 只讀**：Keyboard 暫存器不能被程式寫入，它只反映當前的按鍵狀態

### 記憶體與 CPU 之間的資料傳輸

CPU 與 Memory 之間的連接形成了一個緊密的迴路：

```
CPU ──addressM[14:0]──→ Memory
CPU ──outM[15:0]──────→ Memory
CPU ──writeM──────────→ Memory
Memory ──inM[15:0]───→ CPU
```

- `addressM`：CPU 輸出 15-bit 位址到 Memory（A 暫存器的值）
- `outM`：CPU 輸出要寫入 Memory 的 16-bit 資料
- `writeM`：CPU 輸出寫入使能訊號（1=寫入，0=不寫入）
- `inM`：Memory 輸出指定位置的 16-bit 資料給 CPU

## Memory HDL 實作

以下是完整的 `Memory.hdl` 實作：

```hdl
// Hack 記憶體系統：統一的位址空間
// 檔案：Memory.hdl

CHIP Memory {
    IN  in[16],      // 要寫入的資料
        load,        // 寫入使能
        address[15]; // 位址

    OUT out[16];     // 讀取的資料

    PARTS:

    // ============================================================
    // 位址範圍解碼
    // ============================================================
    // 判斷位址屬於哪個區域：
    //   RAM：  address[14] = 0（即位址 < 16384）
    //   Screen：address[14]=1 AND address[13]=0（16384-24575）
    //   Keyboard：address = 24576（address[13]=1）

    // 判斷是否為 RAM 區域（address < 16384）
    // 16384 = 100000000000000（二進位）
    // address[14]=0 表示位址在 0-16383 之間
    Not(a=address[14], out=isRAM);

    // 判斷是否為 Screen 區域（16384 <= address <= 24575）
    // Screen 區域：address[14]=1 且 address[13]=0
    And(a=address[14], b=address[13], out=isScreenOrKeyboard);
    Not(a=address[13], out=notAddr13);
    And(a=address[14], b=notAddr13, out=isScreen);

    // 判斷是否為 Keyboard 位置（address = 24576）
    // 24576 = 110000000000000（二進位）
    // 即 address[14]=1, address[13]=1, 其餘位元為 0
    // 簡化處理：address[13]=1 時我們視為 Keyboard 區域
    // 實際上 Keyboard 只有一個位置，但為簡化設計
    // 我們用 address[13]=1 來選擇 Keyboard
    And(a=address[14], b=address[13], out=isKeyboard);

    // ============================================================
    // RAM16K 實例
    // ============================================================
    // RAM16K 只在 isRAM=1 時被選中
    // load 訊號需要 AND isRAM（只有在 RAM 區域時才允許寫入）
    And(a=load, b=isRAM, out=ramLoad);

    RAM16K(in=in, load=ramLoad, address=address[0..13], out=ramOut);

    // ============================================================
    // Screen 記憶體
    // ============================================================
    // Screen 是 8K 的 RAM，映射到螢幕像素
    // Screen 的位址從 16384 開始，需要減去基底位址
    // Screen 基底 = 16384，相對位址 = address - 16384
    // 但 16384 = 1 << 14，所以 Screen 的相對位址就是
    // address[0..12]（去掉最高位元 14 和 13）
    And(a=load, b=isScreen, out=screenLoad);

    // Screen 使用 address[0..12] 作為內部位址
    // Screen 記憶體的大小為 8K = 8192，需要 13-bit 位址
    Screen(in=in, load=screenLoad, address=address[0..12], out=screenOut);

    // ============================================================
    // Keyboard 暫存器
    // ============================================================
    // Keyboard 只有一個位置（24576），不需要位址解碼
    // Keyboard 的值由硬體自動更新，不能被程式寫入
    Keyboard(out=keyboardOut);

    // ============================================================
    // 輸出多工器
    // ============================================================
    // 根據位址範圍選擇正確的資料來源作為 out
    //   isRAM=1     → ramOut
    //   isScreen=1  → screenOut
    //   isKeyboard=1 → keyboardOut

    Mux16(a=ramOut, b=screenOut, sel=isScreen, out=memOut);
    Mux16(a=memOut, b=keyboardOut, sel=isKeyboard, out=out);
}
```

### 設計思路與實作步驟

1. **位址解碼**：首先判斷位址落在哪個區域，產生三個選擇訊號 `isRAM`、`isScreen`、`isKeyboard`
2. **獨立模組**：RAM16K、Screen、Keyboard 三個模組各自獨立運作，互不干擾
3. **選擇性寫入**：`load` 訊號經過 AND 閘過濾，確保只在正確的區域寫入
4. **輸出多工器**：最後用一組多工器根據位址範圍選擇正確的資料來源

### 設計要點補充

**Screen 的基底位址偏移**：Screen 記憶體的實際起始位址是 16384，但 Screen 模組內部使用從 0 開始的相對位址。在 Memory 模組中，我們透過傳遞 `address[0..12]` 來實現這個偏移，因為位址 16384 的二進位是 `100000000000000`，去掉最高兩位後就是相對位址。

**Keyboard 的特殊性**：Keyboard 暫存器是整個記憶體系統中唯一不能被程式寫入的位置。它的值由鍵盤硬體掃描電路自動更新，程式只能讀取。這種「記憶體映射 I/O」的設計模式在真實電腦中非常普遍。

### 本章小結

- Hack Memory 整合了 RAM16K、Screen 和 Keyboard 三個裝置
- 統一位址空間：0-16383 為 RAM，16384-24575 為 Screen，24576 為 Keyboard
- 位址解碼邏輯決定哪個記憶體裝置被選中
- 只有 RAM 區域允許程式寫入資料
- Memory 透過 `inM`、`addressM`、`outM`、`writeM` 與 CPU 連接，形成完整的資料通路
- 這種記憶體映射的設計，讓所有裝置都能用統一的存取方式來操控
