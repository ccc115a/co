6.3 兩階段掃描（Two-Pass）組譯器實作

學習目標

讀完本節後，你應該能：

  • 說出「為什麼標號不能只掃描一遍」的根本原因
  • 說明第一遍掃描的任務（收集標號位址、計算指令行號）
  • 說明第二遍掃描的任務（翻譯 A-指令與 C-指令、分配變數）
  • 說出白空格、註解、常量等邊緣細節的正確處理方式
  • 看懂並自行修改一支完整、可執行的 Python 組譯器

前言

6.1 給了你編碼規則，6.2 給了你符號表。現在把它們合體——本節要寫出一支真正能用的組譯器，它會把 .asm 讀進來，產出 .hack 檔。

關鍵設計難題在於標號與變數的「時間差」：

  • 程式可能「先跳後宣告」——@LOOP 寫在前面，(LOOP) 宣告在後面；
  • 標號的位址＝指令行號，而指令行號只有「從頭掃一遍」才數得出來。

如果組譯器只掃描一次，碰到前面的 @LOOP 時根本不知道後面的 (LOOP) 在哪，就會把 LOOP 誤判成變數、配給位址 16，全盤皆錯。解法很古典、也很乾脆：組譯器對程式掃描兩次。

這，就是本節的標題：兩階段掃描（Two-Pass）組譯器。

1. 為什麼需要兩次掃描？

1.1 一次掃描的致命錯誤示範

假設只有一趟，遇到這種程式：

@i
M=1
@LOOP     // ← 此刻 LOOP 還沒被宣告！
0;JMP
(LOOP)
D=M

單趟掃描自左到右，走到 @LOOP 時：

  • 查符號表 → 找不到 LOOP；
  • 依 6.2 規則，當作變數 → 配位址 16；
  • 等走到 (LOOP) 時——才發現 LOOP 其實是標號，應該等於行號 3！

結果：跳躍目標完全錯了。這就像在別人告訴你目的地之前，就把計程車往錯誤方向開出去。

1.2 兩次的完美分工

掃描 任務 依賴資訊 產出
第一遍 只收集 (標號) → 位址 指令行號（數指令） 裝滿標號的符號表
第二遍 翻譯每一條指令 符號表 + 編碼表 .hack 位元串

第一遍結束時，所有標號都已定位，第二遍無論哪一行遇到 @LOOP 都能查到正確位址。變數則安心留在第二遍處理：反正 @i 這種陣仗，遇到再用 next_address 發號碼也不遲。

1.3 概括成一句話

第一遍：先讓所有「未來不在眼前的標號」變成已知數，第二遍：再從頭到尾無後顧之憂地翻譯。

2. 第一遍掃描：收集標號位址

第一遍的邏輯極簡。偽代碼：

pc = 0                        // 指令計數器，代替「目前行號」
st = SymbolTable()            // 載入預定義符號
for 每一行原始文字:
    line = 清理(line)
    if line 是空 → continue
    if line 是 (標號):
        st.add(標號, pc)       // 標號位址 = 目前指令行號
    else:
        pc += 1               // 這是一條真正的指令，行號 +1

注意：只有真正的指令才會讓 pc + 1。標號行、空行、註解都不算。這正是 6.1 節尾聲強調的「清理先行、再數位址」。

實作（Python）：

def first_pass(cleaned_lines: list[str], st: SymbolTable) -> None:
    """第一遍：把 (label) 與其後指令行號的對應填入符號表"""
    pc = 0
    for line in cleaned_lines:
        if line.startswith('('):
            label = line[1:-1]          # 剝掉左右括號
            st.add(label, pc)           # 標號位址 = 目前 pc
        else:
            pc += 1                     # 真正指令才累加行號

讓我們跑一遍上一節的例子來驗證：

cleaned_lines = ['@i', 'M=1', '@LOOP', '0;JMP', '(LOOP)', 'D=M']

（註：實際程式中 (LOOP) 之後的 D=M 也在清單尾部待處理。）

走訪過程：

行內容 動作 pc
@i pc += 1 1
M=1 pc += 1 2
@LOOP pc += 1 3
0;JMP pc += 1 4
(LOOP) st.add('LOOP', 4) 4

所以 LOOP = 4。完全符合「標號位址＝緊接其後指令行號」的規則。

3. 第二遍掃描：翻譯完整程式

第二遍帶著已經裝滿標號的符號表，重新掃過同一份清理後的清單，這回對每一條指令動手：

codes = []
next_address = [16]                     // 變數號碼機
for line in cleaned_lines:
    if line 是 (標號): continue          // 標號行不產出機器碼
    if line 以 @ 開頭:                   // A-指令
        解析 value（數字→直接算；符號→查表/配變數）
        codes.append('0' + 15 位元位址)
    else:                               // C-指令
        codes.append(111 + comp + dest + jump)

解析 @value 的四大分支：

def parse_a(line: str, st: SymbolTable, next_address: list):
    symbol = line[1:]                          # 去掉 @
    if symbol.isdigit():                       # (a) 純數字常數
        return int(symbol)
    if not st.contains(symbol):                # (b) 沒見過的符號 = 新變數
        st.add(symbol, next_address[0])
        next_address[0] += 1
    return st.getAddress(symbol)               # (c) 預定義符號 / 已分配變數

翻譯 C-指令的查表邏輯在 6.1 節已有 encode_c，這裡直接接上。其中「= 與 ; 都可選」的拆解，是唯一的文字處理技巧：

def encode_c(line: str) -> str:
    dest, comp, jump = '', line, ''
    if ';' in line:
        comp, jump = line.split(';')
    if '=' in line:
        dest, comp = comp.split('=')
    return '111' + COMP[comp] + DEST[dest] + JUMP[jump]

注意 dest 與 jump 的預設值都是空字串 ''，正好對應編碼表 DEST[''] = '000'、JUMP[''] = '000'——空欄位就是「不寫入 / 不跳躍」的合法狀態，所以拆法再這樣「盡量拆」就對了。

4. 在兩遍之間如何維護符號表

兩遍掃描共用同一張符號表，這是全案的關鍵脈絡：

        ┌─────────────────────────┐
        │   SymbolTable 物件       │
        │  （開始時只含預定義符號）  │
        └──────────▲──────────▲───┘
                   │          │
    第一遍：加入標號        第二遍：加入變數
    (LOOP)→4, (END)→18    i→16, sum→17

具體的生命週期：

  1. 建立：SymbolTable() 載入 SP/LCL/.../KBD 全部預定義符號；
  2. 第一遍：只 add(label, pc)，不動 pc 以外的任何東西；
  3. 第二遍：遇到不認識的 @sym 時 add(sym, next_address) 並遞增號碼機；
  4. 結束：表同時含有預定義符號＋標號＋變數，但第二遍結束後就沒有用了。

設計思路：為什麼變數要在第二遍配位址、而不是第一遍一起配？其實兩種做法都能讓符號表「最終完整」，但「變數放在第二遍」是教材的標準做法，好處是第二遍的分配順序與翻譯順序完全一致，方便對照 .hack 輸出一格一格除錯。若你日後改寫成一次掃描，就必須小心「後宣告標號」的地雷。

還要強調一個容易忽略的原則：同一支變數在呼叫 parse_a 多次時，只會配一次位址。因為第二次查 st.contains 就成立，直接回傳舊位址。這個「查得到就用舊的」保證了程式一致性。

5. 必須處理的細節：白空格、註解、常數

組譯器很容易寫錯的地方，往往不是編碼，而是文字前的清理。以下三件事必須處理：

5.1 白空格（Whitespace）

.asm 檔案來源百百種，可能有縮排、行尾空格、甚至全形空白。正規做法是 strip() 剝掉頭尾空白，但要小心：Hack 語法不允許指令中間出現空白（例如 D=A ; JGT 是錯的），所以我們只需頭尾清理即可：

line = raw.split('//')[0].strip()

5.2 註解

Hack 只認一種註解：// 到行尾。因此「先切掉 // 以後的所有字元，再做空白清理」就是完整的註解處理：

def clean(raw: str) -> str | None:
    line = raw.split('//')[0].strip()   # 去註解 + 去頭尾空白
    return line if line else None       # 空行 → None，上層直接略過

把「空行也回傳 None」很重要，這讓後續程式一律 if line is not None 跳過，不用重複判斷。

5.3 常數（這條最容易錯！）

@42 這種數字要特別注意，有兩個規格限制：

  1. 必須是無號十進位：Hack 不支援負數與十六進位的 A-指令常數；
  2. 必須 < 2^15 = 32768：再多就塞不進 15 位元位址空間。

實作時務必檢查，讓組譯器在越界時明確報錯，而不是默默截斷產生錯誤位元：

def parse_a(line, st, next_address):
    symbol = line[1:]
    if symbol.isdigit():
        value = int(symbol)
        if value >= 2**15:
            raise ValueError(f'位址太大：@{value}（必須 < 32768）')
        return value
    ...

另外，isdigit() 的清況要放在「查表」之前——因為 Hack 規定符號不能以數字爲首，所以 @7 一定不會是變數名。這一步先攔住，就不會把 7 誤存進符號表。

5.4 清理後的行進到兩遍掃描

整理成完整的「讀取＋清理」工具函數：

def load_program(asm_path: str) -> list[str]:
    """讀檔 → 逐行清理 → 回傳「只含真正指令與 (標號) 行」的清單"""
    lines = []
    with open(asm_path, 'r', encoding='utf-8') as f:
        for raw in f:
            line = clean(raw)
            if line is not None:
                lines.append(line)
    return lines

這份「清理後清單」會同時餵給第一遍與第二遍——前後一致，不能第一遍用清理版、第二遍用別版，否則行號與行號對不上。

6. 完整組譯器程式碼實作

把上述零件全部組裝起來，就是一支完整、可直接執行的 Python 組譯器。本書慣例，整個程式集中在單一檔案，方便您存檔執行：

#!/usr/bin/env python3
"""
HackAssembler.py —— 將 Hack 組合語言 (.asm) 組譯為機器碼 (.hack)

用法：
    python3 HackAssembler.py sum.asm
    （自動產生 sum.hack，並在終端印出簡報）

設計：兩階段掃描（Two-Pass）
    第一遍：收集 (標號) 位址
    第二遍：翻譯 A/C 指令、分配變數位址
"""

import sys


# ---------- 編碼表（6.1 節） ----------

COMP = {
    '0': '0101010', '1': '0111111', '-1': '0111010',
    'D': '0001100', 'A': '0110000', '!D': '0001101', '!A': '0110001',
    '-D': '0001111', '-A': '0110011',
    'D+1': '0011111', 'A+1': '0110111', 'D-1': '0001110', 'A-1': '0110010',
    'D+A': '0000010', 'D-A': '0010011', 'A-D': '0000111',
    'D&A': '0000000', 'D|A': '0010101',
    'M': '1110000', '!M': '1110001', '-M': '1110011',
    'M+1': '1110111', 'M-1': '1110010',
    'D+M': '1000010', 'D-M': '1010011', 'M-D': '1000111',
    'D&M': '1000000', 'D|M': '1010101',
}

DEST = {
    '': '000', 'M': '001', 'D': '010', 'MD': '011',
    'A': '100', 'AM': '101', 'AD': '110', 'AMD': '111',
}

JUMP = {
    '': '000', 'JGT': '001', 'JEQ': '010', 'JGE': '011',
    'JLT': '100', 'JNE': '101', 'JLE': '110', 'JMP': '111',
}


# ---------- 符號表（6.2 節） ----------

class SymbolTable:
    """含預定義符號的符號表，作為兩遍掃描之間的共同記憶"""

    def __init__(self):
        self._table = {
            'SP': 0, 'LCL': 1, 'ARG': 2, 'THIS': 3, 'THAT': 4,
            'R0': 0, 'R1': 1, 'R2': 2, 'R3': 3, 'R4': 4, 'R5': 5,
            'R6': 6, 'R7': 7, 'R8': 8, 'R9': 9, 'R10': 10,
            'R11': 11, 'R12': 12, 'R13': 13, 'R14': 14, 'R15': 15,
            'SCREEN': 16384, 'KBD': 24576,
        }

    def add(self, symbol, address):
        self._table[symbol] = address

    def contains(self, symbol):
        return symbol in self._table

    def getAddress(self, symbol):
        if symbol in self._table:
            return self._table[symbol]
        raise KeyError(f'未知符號：{symbol}')


# ---------- 讀取、清理 ----------

def clean(raw_line):
    """去註解（// 至行尾）、去頭尾空白；空行回傳 None"""
    line = raw_line.split('//')[0].strip()
    return line if line else None


def load_program(path):
    lines = []
    with open(path, 'r', encoding='utf-8') as f:
        for raw in f:
            line = clean(raw)
            if line is not None:
                lines.append(line)
    return lines


# ---------- 第一遍：收集標號 ----------

def first_pass(cleaned, st):
    pc = 0
    for line in cleaned:
        if line.startswith('('):
            label = line[1:-1]
            st.add(label, pc)      # 標號位址 = 下一條指令行號
        else:
            pc += 1               # 只有真正指令才累加行號


# ---------- 第二遍：翻譯 ----------

def parse_a(line, st, next_address):
    """解析 @sym / @num，回傳 0~32767 的數值位址"""
    symbol = line[1:]
    if symbol.isdigit():
        value = int(symbol)
        if value >= 2 ** 15:
            raise ValueError(f'A-指令位址過大：@{value}')
        return value
    if not st.contains(symbol):
        st.add(symbol, next_address[0])  # 新變數：發號碼
        next_address[0] += 1
    return st.getAddress(symbol)


def encode_c(line):
    """把 dest=comp;jump 譯成 111... 的 16 位元 C-指令"""
    dest, comp, jump = '', line, ''
    if ';' in line:
        comp, jump = line.split(';')
    if '=' in line:
        dest, comp = comp.split('=')
    if comp not in COMP:
        raise ValueError(f'未知的 comp 欄位：{comp}')
    return '111' + COMP[comp] + DEST[dest] + JUMP[jump]


def second_pass(cleaned, st):
    codes = []
    next_address = [16]            # 變數從位址 16 發起
    for line in cleaned:
        if line.startswith('('):
            continue               # 標號行不產生機器碼
        if line.startswith('@'):
            addr = parse_a(line, st, next_address)
            codes.append('0' + format(addr, '015b'))
        else:
            codes.append(encode_c(line))
    return codes


# ---------- 主程式 ----------

def assemble(asm_path):
    st = SymbolTable()
    cleaned = load_program(asm_path)

    first_pass(cleaned, st)      # 先收集標號
    codes = second_pass(cleaned, st)  # 再翻譯

    hack_path = asm_path.replace('.asm', '.hack')
    with open(hack_path, 'w', encoding='utf-8') as f:
        for code in codes:
            f.write(code + '\n')  # 每行一個 16 位元字串

    print(f'{asm_path} → {hack_path}  共 {len(codes)} 條指令')
    return hack_path


if __name__ == '__main__':
    if len(sys.argv) != 2:
        print('用法：python3 HackAssembler.py <xxx.asm>')
        sys.exit(1)
    assemble(sys.argv[1])

這就是完整組譯器。全部只有約 130 行，卻完成了：讀檔、去註解、去空白、第一遍標號定位、第二遍指令翻譯＋變數分配、輸出 .hack。每一步你都已在前面小節見過，這是它們的最終合體。

7. 運行示範：把一支程式組譯出來

用本節的組譯器試試一支真實程式——計算 1+2+...+n（n 放在 R0，結果放在 R1）：

// sum1ton.asm
// 計算 1+2+...+R0，結果存到 R1
@R0
D=M          // D = n
@n
M=D          // n = R0
@i
M=1          // i = 1
@sum
M=0          // sum = 0
(LOOP)
@i
D=M
@n
D=D-M        // D = i - n
@STORE
D;JGT        // 若 i > n，把結果存入 R1
@i
D=M
@sum
M=D+M        // sum += i
@i
M=M+1        // i++
@LOOP
0;JMP        // 回到迴圈
(STORE)
@sum
D=M
@R1
M=D          // R1 = sum
(END)
@END
0;JMP        // 無窮迴圈，程式結束

習題模擬

sum1ton.hack 的內容與程式行號逐行對應——第 0 行 @R0（位址 0）對應 0000000000000000，第 1 行 D=M 對應 1111110000010000，第 2 行 @n（新變數配 16）對應 0000000000010000，以此類推。整支程式經過 6.4 節的 CPU 模擬器執行後，可以驗證：R0=5 時 R1 得到 15（1+2+3+4+5），R0=100 時 R1 得到 5050（高斯求和公式的結果）。

設計思路：注意 .hack 的第 3 行 M=0 對應 1110101010001000，其中 comp 欄位是 0（全零運算），而 A 暫存器仍是前一步 @sum 載入的 17——於是「把 0 寫進 Memory[17]」就完成了 sum=0。這告訴我們：A-指令與 C-指令的連續組合，才是完整的「運算」；A 暫存器是兩者之間的傳輸帶。

8. 本章小結

  • 兩階段掃描解決「標號先引用、後宣告」的矛盾：第一遍收集標號，第二遍翻譯。
  • 第一遍用 pc 計算指令行號，只有真正指令才 pc += 1，標號位址＝ pc 當下值。
  • 第二遍對同一份清理後清單逐條翻譯：@num 直接轉、@sym 查表或配變數、C-指令查三張表拼位元。
  • 符號表是兩遍之間共同的「記憶體」，第一遍加標號、第二遍加變數，共用同一張表。
  • 必處理的細節：以 split('//') 去註解、strip() 去空白、空行略過、@ 常數必須 <32768 且先於查表判斷。
  • 本書提供的 HackAssembler.py 約 130 行即可完成整條管線，可直接執行、可自行修改。
