第 3.4 章：程式計數器（Program Counter, PC）設計

前言

在前面的章節中，我們建構了暫存器（Register）和記憶體（RAM），它們提供了儲存資料和程式碼的能力。但電腦要執行程式，還需要一個關鍵問題的答案：「下一個要執行的指令在哪裡？」

這正是**程式計數器（Program Counter，簡稱 PC）**的職責。PC 是 CPU 中最小但最重要的控制元件之一——它追蹤著程式執行的進度，指示記憶體「下一個要讀取的指令位址」。每執行完一條指令，PC 就前進一步；遇到跳轉指令時，PC 就跳到指定的位址。

PC 是組合邏輯、暫存器與控制邏輯的巧妙結合，理解 PC 的設計，將為我們完整理解 CPU 的指令週期打下基礎。

3.4.1 PC 的用途：追蹤下一條指令位址

程式執行的基本模型

電腦執行程式的過程可以概括為一個無限循環：

1. 從 RAM[PC] 讀取指令
2. 解碼並執行該指令
3. PC ← PC + 1（準備下一條指令）
4. 回到步驟 1

在這個循環中，PC 充當了程式執行進度的追蹤器：

RAM 中的程式：

位址    |  指令
--------|------------------
  0     |  LOAD R1, 5
  1     |  LOAD R2, 3
  2     |  ADD R3, R1, R2
  3     |  STORE R3, RAM[100]
  4     |  HALT

PC 的變化：
  執行前：  PC = 0
  執行後：  PC = 1 → 2 → 3 → 4 → 4（停在 HALT）

PC 的特性

PC 本質上是一個特殊的 16-bit 暫存器，但具備一般暫存器沒有的能力：

特性 一般 Register PC
資料寬度 16-bit 16-bit
寫入控制 load 信號 多重控制（見下文）
內建算術 無 內建 +1 功能（Inc16）
重置能力 無 可歸零（reset）

3.4.2 PC 的三個控制：load、inc、reset

PC 需要支援三種不同的操作，由控制信號決定：

操作 load inc reset PC 的變化
保持不變 0 0 0 PC ← PC
遞增 0 1 0 PC ← PC + 1
載入 1 X 0 PC ← in
重置 X X 1 PC ← 0

注意：reset 優先級最高，只要 reset=1，不論其他信號為何，PC 都歸零。

控制信號的來源

在 nand2tetris 的 CPU 中，這些控制信號來自指令解碼器：

  • reset：來自 CPU 的復位信號（程式開始執行時）
  • inc：在正常執行（非跳轉）時自動為 1
  • load：當指令是跳轉指令且條件滿足時為 1

邏輯表（真值表）

reset | load | inc | PC_next
------+------+-----+---------
  1   |  X   |  X  |  0000...0（重置）
  0   |  1   |  X  |  in（載入跳轉位址）
  0   |  0   |  1  |  PC + 1（遞增）
  0   |  0   |  0  |  PC（保持）

更精確地說，優先級為：reset > load > inc > hold

3.4.3 PC 的 HDL 實作

設計思路

PC 的建構使用我們已經學過的元件：

                    ┌──────┐
          in[15:0]─→│      │
                    │ Mux  │──→ ┌──────────┐
          PC+1 ────→│ 4:1  │    │          │──→ out[15:0]
                    │      │    │ Register │
     ┌──────┐      └──────┘    │          │
     │ Inc16│───→ PC+1          │  in      │
     │      │      ↑           │  load    │
     │  out │──────┘           │  clk     │
     └──────┘                  └──────────┘
                                      ↑
                                      │
                                 由控制信號決定 load

具體來說：

  1. Inc16 模組計算 PC + 1（內建加法器）
  2. Mux（4 選 1）根據控制信號選擇下一個值：
    • sel=00 → in（載入新位址）
    • sel=01 → PC+1（遞增）
    • sel=10 → 0（重置）
    • sel=11 → PC（保持）
  3. Register 在時脈邊緣鎖存 Mux 選擇的值

HDL 實作

// PC：程式計數器
// 具備 load、inc、reset 三種控制功能

CHIP PC {
    IN  in[16], load, inc, reset;
    OUT out[16];

    PARTS:
    // === 第一部分：計算 PC+1 ===
    Inc16(in=regOut, out=pcPlusOne);

    // === 第二部分：4 選 1 Mux 決定下一個值 ===
    // Mux4Way 的四個輸入：
    //   a（sel[1:0]=00）→ in    （載入）
    //   b（sel[1:0]=01）→ incout（遞增）
    //   c（sel[1:0]=10）→ zero  （重置）
    //   d（sel[1:0]=11）→ regOut（保持）

    // 將三個控制信號合併為 2-bit 的 Mux 選擇器
    // 需要先處理優先級：reset > load > inc

    // 重置歸零信號
    Not(a=reset, out=nreset);

    // 當 reset=0 且 load=1 時，選擇 in（載入）
    // 當 reset=0 且 load=0 且 inc=1 時，選擇 +1（遞增）
    // 當 reset=0 且 load=0 且 inc=0 時，選擇保持

    // 方法：使用分層 Mux
    // 第一層：在 load 路徑和 inc/hold 路徑之間選擇
    Mux16(a=incOrHold, b=in, sel=load, out=toReg);

    // 在遞增和保持之間選擇
    Mux16(a=regOut, b=pcPlusOne, sel=inc, out=incOrHold);

    // 第二層：在以上結果和 0（重置）之間選擇
    Mux16(a=toReg, b=false, out=regIn, sel=reset);

    // === 第三部分：暫存器鎖存 ===
    Register(in=regIn, load=true, out=regOut, out=out);
}

習題模擬

注意：上述寫法使用了兩層 Mux 來實現優先級。另一種更直觀的方式是使用 Mux4Way，但需要自行編碼控制信號的組合。以下是使用 Mux4Way 的替代實現：

替代實現：使用 Mux4Way

// PC：程式計數器（Mux4Way 版本）

CHIP PC {
    IN  in[16], load, inc, reset;
    OUT out[16];

    PARTS:
    // 計算 PC+1
    Inc16(in=regOut, out=pcPlusOne);

    // 準備四個候選值
    // a = in（載入）     → sel=00
    // b = pcPlusOne（遞增）→ sel=01
    // c = 0（重置）      → sel=10
    // d = regOut（保持）  → sel=11

    // 將控制信號編碼為 2-bit 選擇器
    // 編碼邏輯：
    //   reset=1         → sel=10（重置）
    //   reset=0,load=1  → sel=00（載入）
    //   reset=0,load=0,inc=1 → sel=01（遞增）
    //   reset=0,load=0,inc=0 → sel=11（保持）

    // 製作零值
    Or(a=false, b=false, out=zeroBit);  // 永遠為 0

    // 選擇器輸入
    Mux4Way16(a=in, b=pcPlusOne, c=false, d=regOut,
              sel=controlBits, out=regIn);

    // 暫存器
    Register(in=regIn, load=true, out=regOut, out=out);
}

習題模擬

實用的分層 Mux 方案（推薦）

最清晰且最常用的實現方式是使用三層 Mux 並實現明確的優先級：

// PC：程式計數器（推薦實現）
// 優先級：reset > load > inc > hold

CHIP PC {
    IN  in[16], load, inc, reset;
    OUT out[16];

    PARTS:
    // 步驟 1：計算 PC + 1
    Inc16(in=regOut, out=pcPlus1);

    // 步驟 2：Mux 層級選擇（從低優先級到高優先級）
    // 層 1：保持 vs 遞增（inc 控制）
    Mux16(a=regOut, b=pcPlus1, sel=inc, out=afterInc);

    // 層 2：上一步結果 vs 載入（load 控制）
    Mux16(a=afterInc, b=in, sel=load, out=afterLoad);

    // 層 3：上一步結果 vs 重置（reset 控制）
    Mux16(a=afterLoad, b=false, sel=reset, out=regIn);

    // 步驟 3：鎖存到暫存器
    Register(in=regIn, load=true, out=regOut, out=out);
}

習題模擬

設計解析

這個實現的精妙之處在於 Mux 的堆疊順序反映了優先級：

reset=0, load=0, inc=0：
  Mux1(regOut, regOut, 0) → regOut  （保持）
  Mux2(regOut, in, 0)     → regOut  （不載入）
  Mux3(regOut, 0, 0)      → regOut  （不重置）
  結果：PC 不變 ✓

reset=0, load=0, inc=1：
  Mux1(regOut, pcPlus1, 1) → pcPlus1  （遞增）
  Mux2(pcPlus1, in, 0)     → pcPlus1  （不載入）
  Mux3(pcPlus1, 0, 0)      → pcPlus1  （不重置）
  結果：PC + 1 ✓

reset=0, load=1, inc=X：
  Mux1(regOut, pcPlus1, X) → X  （不管結果是什麼）
  Mux2(X, in, 1)           → in  （載入）
  Mux3(in, 0, 0)           → in  （不重置）
  結果：PC ← in ✓

reset=1, load=X, inc=X：
  Mux1(regOut, pcPlus1, X) → X
  Mux2(X, in, X)           → X
  Mux3(X, 0, 1)            → 0  （重置）
  結果：PC ← 0 ✓

3.4.4 程式執行的時序

指令週期（Instruction Cycle）

每個時脈週期，CPU 完成一個完整的指令週期：

┌─────────────────────────────────────────────────────┐
│                  一個指令週期                          │
│                                                      │
│  ① 取指（Fetch）                                     │
│     - PC 輸出位址 → RAM → 取回指令                    │
│                                                      │
│  ② 解碼（Decode）                                    │
│     - 指令解碼器分析指令類型和操作數                    │
│                                                      │
│  ③ 執行（Execute）                                   │
│     - ALU 執行算術/邏輯運算                            │
│                                                      │
│  ④ 寫回（Write-back）                                │
│     - 結果寫回暫存器或記憶體                            │
│                                                      │
│  ⑤ 更新 PC                                           │
│     - PC ← PC + 1（或跳轉到位址）                     │
│                                                      │
└─────────────────────────────────────────────────────┘
              ↓ 下一個時脈週期
┌─────────────────────────────────────────────────────┐
│              下一個指令週期開始                          │
└─────────────────────────────────────────────────────┘

PC 在指令週期中的時序圖

時脈 clk  : ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
             │  │  │  │  │  │  │  │  │  │  │
         ────┘  └──┘  └──┘  └──┘  └──┘  └──┘

PC 值    : ──0───0───1───2───3───4───4──────
               ↑   ↑   ↑   ↑   ↑
              T0  T1  T2  T3  T4
              取指  取指  取指  取指  取指
              指令0 指令1 指令2 指令3 指令4

指令     : ──→LOAD→LOAD→ADD →STORE→HALT
           R1,5  R2,3 R3,R1  R3,100
                 ,R2

RAM[addr]: RAM[0] RAM[1] RAM[2] RAM[3] RAM[4]

時序說明：
T0：PC=0，從 RAM[0] 取指令 "LOAD R1,5"
    執行後 PC ← 0+1 = 1
T1：PC=1，從 RAM[1] 取指令 "LOAD R2,3"
    執行後 PC ← 1+1 = 2
T2：PC=2，從 RAM[2] 取指令 "ADD R3,R1,R2"
    執行後 PC ← 2+1 = 3
T3：PC=3，從 RAM[3] 取指令 "STORE R3,RAM[100]"
    執行後 PC ← 3+1 = 4
T4：PC=4，從 RAM[4] 取指令 "HALT"
    執行後 PC 保持 4

跳轉指令的時序

當遇到跳轉指令（如 JMP 或條件跳轉 JNE）時，PC 不是遞增而是載入目標位址：

時脈 clk  : ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
         ────┘  └──┘  └──┘  └──┘  └──┘  └──┘

PC 值    : ──0───0───1───2───0─────────────────
               ↑   ↑   ↑   ↑
              T0  T1  T2  T3
              取指  取指  取指  跳轉！
              指令0 指令1 指令2 指令3

指令     : ──→LOAD→LOAD→ADD →JMP 0
           R1,5  R2,3 R3,R1
                 ,R2

控制信號：
T0：inc=1, load=0, reset=0 → PC ← PC+1 = 1
T1：inc=1, load=0, reset=0 → PC ← PC+1 = 2
T2：inc=1, load=0, reset=0 → PC ← PC+1 = 3
T3：inc=X, load=1, reset=0 → PC ← in=0  ← 跳轉！

3.4.5 PC 與指令週期的關係

CPU 中的 PC

在完整的 CPU 架構中，PC 連接如下：

┌─────────────────────────────────────────────┐
│                    CPU                       │
│                                              │
│  ┌─────┐    ┌──────────┐    ┌─────┐        │
│  │  PC │───→│   RAM    │───→│指令  │        │
│  │     │←───│ address  │    │解碼器│        │
│  └──┬──┘    └──────────┘    └──┬──┘        │
│     │                          │             │
│     │ inc/load/reset           │ 控制信號    │
│     │                          ↓             │
│     │                     ┌──────────┐       │
│     │                     │  Control │       │
│     │                     └──────────┘       │
│     │                          │             │
│     │    ┌────────┐           │             │
│     ├───→│ Register│←──────────┘             │
│     │    │ (A 寄存器)│                        │
│     │    └────────┘                          │
│     │         │                               │
│     │    ┌────────┐                          │
│     │    │  ALU   │                          │
│     │    └────────┘                          │
│     │         │                               │
│     │    ┌────────┐                          │
│     └───→│Register│                          │
│          │ (D 寄存器)│                        │
│          └────────┘                          │
└─────────────────────────────────────────────┘

指令週期的微觀時序

每個時脈週期內的微觀操作序列：

時脈上升沿觸發：

  ┌─────────────────────────────────────────────┐
  │  1. PC 輸出位址 → RAM 的 address 輸入         │
  │  2. RAM 根據位址輸出指令 → 指令解碼器           │
  │  3. 解碼器產生控制信號                         │
  │  4. ALU 根據控制信號執行運算                    │
  │  5. 運算結果寫回暫存器/記憶體                   │
  │  6. PC 的控制信號決定 PC 的下一個值             │
  │  7. 【下一個時脈上升沿】PC 更新為新值            │
  └─────────────────────────────────────────────┘

注意第 6 步和第 7 步之間的微妙之處：PC 的新值在當前週期就已經被計算好了（透過 Mux 電路），但要等到下一個時脈上升沿才會被鎖存到 Register 中。這確保了：

  • 在整個當前週期內，PC 輸出的位址是穩定不變的
  • RAM 有足夠的時間讀取對應位址的指令
  • 不會出現「PC 還沒穩定就去讀指令」的問題

PC 的位址範圍

在 nand2tetris 中：

PC 的位址範圍：0 ～ 16383（14 位元可定址）

RAM16K 的空間分配：
  0 ～ 16383：程式記憶體（存放指令）

PC 始終指向 RAM 中的指令位址

本章小結

本章完成了 CPU 中最關鍵的控制元件——程式計數器的設計：

  1. PC 的功能：追蹤下一條指令的記憶體位址，是程式自動執行的核心

  2. PC 的三種控制模式：

    • reset=1：歸零（程式從頭開始）
    • load=1：載入指定的跳轉位址
    • inc=1：遞增（前進到下一條指令）
    • 以上都不滿足時：保持不變

  3. PC 的實現：Inc16 + Mux + Register 的組合

    • Inc16 計算 PC+1
    • Mux 層級實現優先級選擇
    • Register 鎖存最終的值

  4. 指令週期：Fetch → Decode → Execute → Write-back → 更新 PC

    • 正常情況：PC 自動 +1
    • 跳轉指令：PC 載入目標位址
    • 每個週期的 PC 值在時脈邊緣更新

  5. PC 連接了記憶體與控制：它從 RAM 讀取指令位址，又根據指令結果決定自己的下一個值，形成了 CPU 執行的自動化迴圈

至此，我們已經完成了 nand2tetris 中所有暫存器層級的元件設計。從最底層的 DFF 出發，經過 Bit、Register、RAM、到 PC，我們建構了一個完整的記憶與控制體系。這些元件將在後續章節中被組裝成完整的 CPU，最終運行我們用 Hack 組合語言編寫的程式。
