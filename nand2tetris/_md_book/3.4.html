第 3.4 章：程式計數器（Program Counter, PC）設計

前言

在前面的章節中，我們建構了暫存器（Register）和記憶體（RAM），它們提供了儲存資料和程式碼的能力。但電腦要執行程式，還需要一個關鍵問題的答案：「下一個要執行的指令在哪裡？」

這正是**程式計數器（Program Counter，簡稱 PC）**的職責。PC 是 CPU 中最小但最重要的控制元件之一——它追蹤著程式執行的進度，指示記憶體「下一個要讀取的指令位址」。每執行完一條指令，PC 就前進一步；遇到跳轉指令時，PC 就跳到指定的位址。

PC 是組合邏輯、暫存器與控制邏輯的巧妙結合，理解 PC 的設計，將為我們完整理解 CPU 的指令週期打下基礎。

3.4.2 PC 的三個控制：load、inc、reset

PC 需要支援三種不同的操作，由控制信號決定：

操作 load inc reset PC 的變化
保持不變 0 0 0 PC ← PC
遞增 0 1 0 PC ← PC + 1
載入 1 X 0 PC ← in
重置 X X 1 PC ← 0

注意：reset 優先級最高，只要 reset=1，不論其他信號為何，PC 都歸零。

控制信號的來源

在 nand2tetris 的 CPU 中，這些控制信號來自指令解碼器：

  • reset：來自 CPU 的復位信號（程式開始執行時）
  • inc：在正常執行（非跳轉）時自動為 1
  • load：當指令是跳轉指令且條件滿足時為 1

本章小結

本章完成了 CPU 中最關鍵的控制元件——程式計數器的設計：

  1. PC 的功能：追蹤下一條指令的記憶體位址，是程式自動執行的核心

  2. PC 的三種控制模式：

    • reset=1：歸零（程式從頭開始）
    • load=1：載入指定的跳轉位址
    • inc=1：遞增（前進到下一條指令）
    • 以上都不滿足時：保持不變

  3. PC 的實現：Inc16 + Mux + Register 的組合

    • Inc16 計算 PC+1
    • Mux 層級實現優先級選擇
    • Register 鎖存最終的值

  4. 指令週期：Fetch → Decode → Execute → Write-back → 更新 PC

    • 正常情況：PC 自動 +1
    • 跳轉指令：PC 載入目標位址
    • 每個週期的 PC 值在時脈邊緣更新

  5. PC 連接了記憶體與控制：它從 RAM 讀取指令位址，又根據指令結果決定自己的下一個值，形成了 CPU 執行的自動化迴圈
