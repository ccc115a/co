第 3.2 章：1-bit 與 16-bit 暫存器（Register）設計

前言

在上一章中，我們理解了 DFF 作為最基本記憶單元的運作方式——在時脈上升沿鎖存輸入值。但單純的 DFF 缺乏「選擇性」：它每次都會鎖存新的輸入，無法做到「有時載入新值、有時保持舊值」。

本章將組合 DFF 與 Mux，建構出具有 load 控制的暫存器。我們會先設計 1-bit 版本（稱為 Bit），再將 16 個 Bit 併聯組成 16-bit 的 Register。暫存器是 CPU 內部最基礎的工作單元，也是整個記憶體層級的起點。

3.2.1 Bit（1-bit 暫存器）的設計

設計目標

Bit 元件需要具備以下功能：

輸入 輸出 說明
in（1-bit） out（1-bit） 待寫入的資料 / 當前儲存的值
load（1-bit） 控制信號：1=寫入新值，0=保持
clk（1-bit） 時脈（隱含連接）

行為規範：

若 load = 1：在時脈上升沿，out ← in
若 load = 0：out 保持不變（即使 in 改變）

設計思路

核心思想是用 Mux 來選擇「要鎖存哪個值」：

          ┌─────┐
in ──────→│  M  │──→ ┌─────┐
          │  u  │    │ DFF │──→ out
old ─────→│  x  │    │     │
     ↑    └─────┘    └──┬──┘
     │                   │
     └───────────────────┘
        （回饋：Q 連回 Mux 輸入）

工作流程：

  1. Mux 根據 load 信號選擇輸入：
    • load = 1 → Mux 輸出 in（新資料）
    • load = 0 → Mux 輸出 out（DFF 當前值，即舊資料）
  2. DFF 在下一個時脈上升沿鎖存 Mux 的輸出

這形成了一個精巧的迴圈：DFF 的輸出回饋到 Mux 的輸入，當 load = 0 時，DFF 反覆鎖存自己的值，達到「保持」效果。

HDL 實作

// Bit：1-bit 暫存器
// 功能：當 load=1 時在時脈邊緣寫入 in；當 load=0 時保持不變

CHIP Bit {
    IN  in, load;
    OUT out;

    PARTS:
    // 用 Mux 選擇：load=1 選 in，load=0 選當前值
    Mux(a=oldValue, b=in, sel=load, out=toStore);

    // DFF 鎖存選中的值
    DFF(in=toStore, out=out);

    // 將輸出回饋為「當前值」（內部連接）
    // 在 HDL 中，同一個 pin 名稱即可隱含連結
    // 此處 oldValue 即為 out 的回饋
}

習題模擬

注意：在 nand2tetris 的 HDL 約定中，out 同時是輸出 pin 和內部信號。上面的程式碼中 oldValue 實際上就是 out 的回饋。在某些 HDL 環境中，你需要透過內部線路來表達這個回饋。以下是更精確的寫法：

// Bit：1-bit 暫存器（更精確的寫法）

CHIP Bit {
    IN  in, load;
    OUT out;

    PARTS:
    // DFF 的輸出連接
    DFF(in=toStore, out=out, out=feedback);

    // Mux 選擇要儲存的值
    Mux(a=feedback, b=in, sel=load, out=toStore);
}

習題模擬

更為清晰的表達方式（nand2tetris 標準風格）：

// Bit：1-bit 暫存器
// 當 load=1，時脈邊緣時寫入 in；load=0 時保持

CHIP Bit {
    IN  in, load;
    OUT out;

    PARTS:
    // 選擇器：決定鎖存什麼值
    Mux(a=dffOut, b=in, sel=load, out=toStore);

    // 觸發器：鎖存選中的值
    DFF(in=toStore, out=dffOut);

    // 將 DFF 的輸出連接到晶片輸出
    // dffOut 同時回饋到 Mux 的 a 輸入（load=0 時使用）
    // 在 nand2tetris HDL 中，同一個線名自動連接
}

習題模擬

設計關鍵：Mux 的 a 輸入（sel=0 時選中）連接到 DFF 的輸出——這就是「保持」路徑。Mux 的 b 輸入（sel=1 時選中）連接到外部輸入 in——這就是「寫入」路徑。

Bit 的時序圖

clk  : ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
        │  │  │  │  │  │  │  │  │  │  │  │  │
    ────┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘

in   : ───1───0───0───1───1───0───────────
                （輸入在不同時間變化）

load : ────────────1───────1───0───────────
                   ↑           ↑
                   寫入        保持

out  : ──0───0───1───1───0───0───0───────
              ↑       ↑       ↑
           第1次    第2次    第3次
           上升沿   上升沿   上升沿
           load=1   load=1   load=0
           Q=in=1   Q=in=0   Q 不變=0

逐邊緣分析：

時脈邊緣 load in DFF 輸入 out（新值） 說明
第 1 個 1 1 Mux 選 in → 1 1 載入新值 1
第 2 個 1 0 Mux 選 in → 0 0 載入新值 0
第 3 個 0 1 Mux 選 feedback → 0 0 保持舊值 0，忽略 in=1

3.2.2 Register（16-bit 暫存器）的設計

從 1-bit 到 16-bit

nand2tetris 的資料通道是 16-bit 寬的。一個 16-bit 暫存器本質上就是 16 個 Bit 元件並排，每個 Bit 負責儲存一個位元：

in[0]  ─→ Bit ─→ out[0]
in[1]  ─→ Bit ─→ out[1]
in[2]  ─→ Bit ─→ out[2]
  ⋮              ⋮
in[15] ─→ Bit ─→ out[15]

load  ─┬────────┬────────┬────── （所有 Bit 共用同一個 load 信號）
clk   ─┴────────┴────────┴────── （所有 Bit 共用同一個時脈）

HDL 實作

// Register：16-bit 暫存器
// 當 load=1，時脈邊緣時寫入全部 16 位元；load=0 時保持

CHIP Register {
    IN  in[16], load;
    OUT out[16];

    PARTS:
    // 16 個 Bit 元件，每個負責一個位元
    // 所有 Bit 共用 load 和 clk 信號
    Bit(in=in[0],  load=load, out=out[0]);
    Bit(in=in[1],  load=load, out=out[1]);
    Bit(in=in[2],  load=load, out=out[2]);
    Bit(in=in[3],  load=load, out=out[3]);
    Bit(in=in[4],  load=load, out=out[4]);
    Bit(in=in[5],  load=load, out=out[5]);
    Bit(in=in[6],  load=load, out=out[6]);
    Bit(in=in[7],  load=load, out=out[7]);
    Bit(in=in[8],  load=load, out=out[8]);
    Bit(in=in[9],  load=load, out=out[9]);
    Bit(in=in[10], load=load, out=out[10]);
    Bit(in=in[11], load=load, out=out[11]);
    Bit(in=in[12], load=load, out=out[12]);
    Bit(in=in[13], load=load, out=out[13]);
    Bit(in=in[14], load=load, out=out[14]);
    Bit(in=in[15], load=load, out=out[15]);
}

習題模擬

設計要點

  1. 平行寫入：16 個 Bit 同時在時脈邊緣更新，實現了一個時脈週期內寫入完整 16-bit 資料
  2. 統一控制：所有 Bit 共用同一個 load 信號，確保「要麼全部寫入，要麼全部保持」
  3. 模組化：Register 的正確性直接繼承自 Bit 的正確性——如果每個 Bit 都正確，整個 Register 就正確

3.2.3 load 控制：寫入與保留的時序行為

load 信號的完整語意

load 信號是暫存器的「開關」，它決定了暫存器的行為模式：

load 行為 隱喻
0 保持（Hold） 鎖上保險箱，鑰匙轉到「鎖定」位置
1 寫入（Load） 打開保險箱，放入新物品

多週期行為範例

假設一個 16-bit 暫存器接收以下序列：

時間點    |  in[15:0]     |  load  |  out[15:0]   |  說明
----------|---------------|--------|--------------|------------------
初始       |  00000000     |   -    |  00000000    |  重置為 0
T1（沿）   |  00000101     |   1    |  00000101    |  寫入 5
T2（沿）   |  00000011     |   1    |  00000011    |  寫入 3
T3（沿）   |  11111111     |   0    |  00000011    |  保持 3，忽略 -1
T4（沿）   |  00001000     |   0    |  00000011    |  仍然保持 3
T5（沿）   |  00001000     |   1    |  00001000    |  寫入 8

時序圖（多位元切片觀察）

clk  : ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
        │  │  │  │  │  │  │  │  │  │  │
    ────┘  └──┘  └──┘  └──┘  └──┘  └──┘

in[0] : ─1──0──1──1──0─────────────────
in[1] : ─0──1──1──1──0─────────────────
in[2] : ─0──0──0──1──0─────────────────
load  : ────────1───1───0───0───1──────
        ↑       ↑   ↑   ↑   ↑   ↑
        T1沿    T1  T2  T3  T4  T5

out[0]: ─0──1──1──1──1──1──1──0────────
out[1]: ─0──0──1──1──1──1──1──0────────
out[2]: ─0──0──0──0──0──0──0──0────────
        ↑       ↑       ↑       ↑
        T1:     T2:     T3-4:   T5:
        寫入    寫入    保持     寫入
        in=5    in=3    不變     in=8

為什麼回饋迴路是安全的？

你可能會擔心：「DFF 的輸出回饋到 Mux，再連回 DFF 的輸入，這樣不會產生迴圈嗎？」

答案是：不會，因為 DFF 的本質就是在「正確的時機」才接受輸入。在非觸發時刻，DFF 的輸出不會變化，因此回饋迴路中的信號是穩定的。只有在時脈上升沿的那一瞬間，DFF 才會「看一眼」輸入並更新輸出。這種「延遲一個時脈週期」的特性，打破了即時迴圈的可能。

時脈非觸發期間：
  feedback = Q（穩定不變）
  Mux 輸出 = f(load, feedback)（穩定不變）
  DFF 輸入 = Mux 輸出（穩定不變）
  → 整個迴路穩定

時脈上升沿：
  DFF 鎖存 Mux 輸出 → Q 更新為新值
  → 下一個非觸發期間，回饋穩定在新值

3.2.4 驗證 Bit 和 Register

測試腳本（Bit.tst）

// Bit 測試腳本
load CharacterPath & RAM[0];

set-pin in 0, write;
set-pin load 0, write;
tick; tock;
output;  // out 應為 0（初始值）

set-pin in 1, write;
set-pin load 1, write;
tick; tock;
output;  // out 應為 1（載入）

set-pin in 0, write;
set-pin load 0, write;
tick; tock;
output;  // out 應為 1（保持，不因 in=0 而改變）

set-pin in 0, write;
set-pin load 1, write;
tick; tock;
output;  // out 應為 0（再次載入，這次 in=0）

比較表（Bit.cmp）

in load out
0 0 0
1 1 1
0 0 1
0 1 0

測試腳本（Register.tst）

// Register 測試腳本
set in 0000000000000000, write;
set load 0, write;
tick; tock;
output;  // out 應為 0

set in 0000000000000101, write;
set load 1, write;
tick; tock;
output;  // out 應為 5

set in 0000000000000011, write;
set load 0, write;
tick; tock;
output;  // out 應為 5（保持）

set in 0000000000010000, write;
set load 1, write;
tick; tock;
output;  // out 應為 16

本章小結

本章完成了從 DFF 到暫存器的建構過程：

  1. Bit（1-bit 暫存器） = Mux + DFF

    • Mux 負責「選擇」：load=1 選新資料，load=0 選舊資料
    • DFF 負責「鎖存」：在時脈邊緣更新輸出
    • 回饋迴路讓 Bit 具備「保持」能力

  2. Register（16-bit 暫存器） = 16 個 Bit 並聯

    • 每個 Bit 獨立負責一個位元
    • 所有 Bit 共用 load 和時脈，實現並行寫入

  3. load 控制是暫存器的核心機制

    • load = 1：寫入新值
    • load = 0：保持當前值
    • 這種「有條件的更新」是電腦控制資料流動的基礎

暫存器是暫存資料的最基本單位，但它只能保存「一個資料」。接下來的章節（3.3）將展示如何將多個暫存器組織成記憶體陣列，透過位址來選擇存取哪一個暫存器——這就是 RAM 的核心概念。
