第 13 章（續）　從 Jack 編譯到 Hardware 執行的完整流轉

前言

上一節我們從巨觀角度審視了整條工具鏈。本節將以一個具體的 Jack 程式為例，逐步追蹤它在每一層的轉變，讓讀者親眼看到「抽象」如何一層一層被展開，最終化為硬體線路上的電壓變化。我們也將說明如何讓完整的 Tetris 遊戲在 Hack 平台上運行。

13.2.1　範例程式：一個簡單的互動常式

以下是一個小型的 Jack 程式——按下任意鍵時在螢幕上畫一個像素：

class PixelDrawer {
    function void main() {
        var int x, y, key;
        let x = 0;
        let y = 0;
        while (y < 256) {
            let x = 0;
            while (x < 512) {
                let key = Keyboard.readKey();
                if (key > 0) {
                    do Screen.drawPixel(x, y);
                }
                let x = x + 1;
            }
            let y = y + 1;
        }
        return;
    }
}

這個程式雖然簡短，但已經涵蓋了變數、迴圈、條件判斷、系統呼叫（Keyboard.readKey、Screen.drawPixel）等核心概念，足以展示全棧流轉。

13.2.2　第一層轉換：Jack Compiler（Source → VM Code）

編譯器接收 .jack 源碼，進行詞彙分析、語法分析、語意分析，最終產生 .vm 檔案。以下列舉關鍵轉換：

函式定義的轉換：

function void main() {

被轉換為：

function Main.main 3   // 3 個局部變數: x, y, key

let 賦值的轉換：

let x = 0;

被轉換為：

push constant 0
pop local 0       // x 的欄位索引為 0

while 迴圈的轉換：

// while (y < 256) 的條件檢查
label LOOP_START
push local 1       // y
push constant 256
lt
if-goto LOOP_END

// 迴圈本體
...
goto LOOP_START
label LOOP_END

方法呼叫的轉換：

do Screen.drawPixel(x, y);

被轉換為：

push local 0       // x
push local 1       // y
call Screen.drawPixel 2
pop temp 0          // 丢棄回傳值

編譯器的輸出（完整的 Main.vm）大致如下：

function Main.main 3
push constant 0
pop local 0
push constant 0
pop local 1
label WHILE_START0
push local 1
push constant 256
lt
not
if-goto WHILE_END0
push constant 0
pop local 0
label WHILE_START1
push local 0
push constant 512
lt
not
if-goto WHILE_END1
call Keyboard.readKey 0
pop local 2
push local 2
push constant 0
gt
not
if-goto IF_END0
push local 0
push local 1
call Screen.drawPixel 2
pop temp 0
label IF_END0
push local 0
push constant 1
add
pop local 0
goto WHILE_START1
label WHILE_END1
push local 1
push constant 1
add
pop local 1
goto WHILE_START0
label WHILE_END0
push constant 0
return

設計思路：編譯器在這一層已經把所有的高階結構（while、if、方法呼叫）攤平為純粹的堆疊操作與標籤跳轉。這種「攤平」就是抽象層轉換的核心——消除語法糖，留下可機械執行的基本動作。

13.2.3　第二層轉換：VM Translator（VM Code → Assembly）

VM Translator 接收 .vm 碼，將每一條虛擬機指令翻譯為 Hack 組合語言。以下展示幾個關鍵映射：

push constant 0：

@0
D=A          // D = 0
@SP
A=M          // A = SP 指向的位址
M=D          // RAM[SP] = 0
@SP
M=M+1        // SP++

pop local 0：

// 計算目標位址: LCL + 0
@LCL
D=M          // D = LCL
@0
D=D+A        // D = LCL + 0
@R13
M=D          // 暫存到 R13

@SP
AM=M-1       // SP--
D=M          // D = 彈出的值

@R13
A=M          // A = 目標位址
M=D          // 寫入

add：

@SP
AM=M-1       // SP--
D=M          // D = 第二個運算元
@SP
AM=M-1       // SP--
M=D+M        // RAM[SP] = D + RAM[SP]
@SP
M=M+1        // SP++

label、goto、if-goto：

// label WHILE_START0
(WHILE_START0)

// goto WHILE_START0
@WHILE_START0
0;JMP

// if-goto WHILE_END0
@SP
AM=M-1       // SP--
D=M          // D = 條件值
@WHILE_END0
D;JNE        // 若 D ≠ 0 則跳轉

call： 這是最複雜的指令之一，需要保存呼叫端狀態：

// call Screen.drawPixel 2
@RETURN_42   // 回傳位址的標籤
D=A
@SP
A=M
M=D          // 推入回傳位址
@SP
M=M+1
@LCL
D=M
@SP
A=M
M=D          // 推入 LCL
@SP
M=M+1
// ... 同樣推入 ARG, THIS, THEN
// 重定位 ARG = SP - 5 - 2
// 重定位 LCL = SP
// goto Screen.drawPixel

設計思路：VM Translator 的挑戰在於為 call 和 function 正確生成「棧框」（stack frame）的保存與恢復。每一個 VM 指令對應的組語指令數量不同，但翻譯是機械式的、無狀態的（除了標籤生成），這使得它比編譯器容易實作。

13.2.4　第三層轉換：Assembler（Assembly → Binary）

Assembler 將組語轉為 16-bit 二進位碼。整個過程分為兩趟掃描：

第一趟：建立符號表

掃描所有 (LABEL) 定式的標籤，記錄其對應的 ROM 位址。例如 (WHILE_START0) 可能對應位址 15。

第二趟：產生機器碼

逐行翻譯：

@0          → 0000000000000000   // A 指令：A = 0
D=A         → 1110110000010000   // C 指令：dest=D, comp=A, jump=null
@SP         → 0000000000010000   // A = 16 (SP 的位址)
A=M         → 1111110000010000   // A = RAM[A]
M=D         → 1110001100001000   // RAM[A] = D

Hack 的 A 指令格式為 0xxxxxxxxxxxxxxx（15 個位元表示常數或位址），C 指令格式為 111accccccdddjjj（comp + dest + jump 三個欄位）。

設計思路：Assembler 的設計非常簡潔——A 指令和 C 指令各自有固定的位元佈局，翻譯完全是查表與拼接。唯一需要額外處理的是符號解析（變數自動分配位址從 16 開始）。

13.2.5　第四層：CPU 執行（Binary → 硬體行為）

CPU 模擬器（或真實的 Hack 硬體）收到 .hack 後，將其載入 ROM。每個時脈週期，CPU：

  1. Fetch：讀取 ROM[PC] 取得當前指令。
  2. Decode：根據 bit 15 判斷是 A 指令或 C 指令。
  3. Execute：
    • A 指令：將 bit 0–14 的值寫入 A 暫存器。
    • C 指令：ALU 根據 comp 欄位運算，結果依 dest 欄位寫入目標暫存器，最後根據 jump 欄位決定是否跳轉。
  4. Write-back：ALU 輸出寫入 DRegister、ARegister 或記憶體。
  5. PC 更新：根據跳轉條件更新程式計數器。
// CPU.hdl 的核心邏輯（簡化）
Mux16(a=AOut, b=instruction, sel=isC, out=aluX);       // 運算元 X
Mux16(a=DRegister, b=ARegister, sel=instruction[12], out=aluY); // 運算元 Y
ALU(x=aluX, y=aluY, ... , out=aluOut, out=outM);

// 根據 dest 欄位寫入
Mux16(a=ARegister, b=aluOut, sel=instruction[5], out=aNext);  // dest a
Mux16(a=DRegister, b=aluOut, sel=instruction[4], out=dNext);  // dest d

從機器碼到螢幕像素——最終，call Screen.drawPixel 2 經過層層翻譯後，會在某個時脈週期把一個值寫入 RAM 位址 16384 到 24575 之間的某個位置，這個位置對應到 Screen Memory Map 的某個位元，Hardware Simulator 再將該位元渲染為螢幕上的一個亮點。

13.2.6　讓 Tetris 實際運行

nand2tetris 課程提供了一個完整的 Tetris.jack 專案，包含多個類別：

Tetris.jack/          // 專案目錄
├── Main.jack         // 程式入口
├── Game.jack         // 遊戲邏輯
├── Board.jack        // 棋盤管理
├── Piece.jack        // 方塊物件
├── Screen.jack       // 螢幕繪圖（覆寫 OS 版本）
├── Keyboard.jack     // 鍵盤處理
└── ... 其他輔助類別

執行步驟

# 1. 編譯所有 .jack 檔案
java -cp JackCompiler.jar JackCompiler Tetris.jack/

# 2. 確認產生了多個 .vm 檔案
ls Tetris.jack/*.vm
# Main.vm, Game.vm, Board.vm, Piece.vm, Screen.vm, Keyboard.vm, ...

# 3. 翻譯所有 VM 檔案為組語
java -cp VMTranslator.jar VMTranslator Tetris.jack/

# 4. 組譯為機器碼
java -cp Assembler.jar Assembler Tetris.jack/Tetris.asm

# 5. 在 CPU Emulator 中執行
#    載入 Computer.hdl，選擇 Tetris.hack 作為 ROM
#    按 Yes 重置，再按 Run

注意事項

  • OS 模組的處理：Tetris 使用了 OS 的 Math、Screen、Keyboard 等模組。這些 OS 模組需要先編譯成 Math.vm、Screen.vm 等，與遊戲的 VM 檔案一起送入 VM Translator。或者，使用提供的預編譯 OS（OS.hex 或 OS.tst）。
  • 自訂 Screen 模組：Tetris 專案可能包含自己的 Screen.jack，用更高效的方式直接操作 Screen Memory Map，覆寫 OS 預設的繪圖函式。
  • 鍵盤輸入：在 CPU Emulator 中，可以用滑鼠點擊鍵盤區域模擬按鍵。

13.2.7　全棧流轉的觀察

追蹤完整個流程後，我們可以觀察到幾個重要的模式：

  1. 資訊量守恆：每一層的轉換都不會丟失原始程式的語意資訊，只是換了一種表達方式。Jack 的 while 迴圈在 VM 層變成標籤跳轉，在組語層變成 @LABEL + 0;JMP，在機器碼層變成一串 16 個位元——但做的事完全一樣。

  2. 抽象逐層消融：越高階的結構（物件、方法、迴圈）在越低階的表示中被攤平。到 CPU 層，只剩下「讀記憶體、做運算、寫記憶體、更新程式計數器」這四個動作。

  3. 複雜度的轉移：編譯器承受了最大的複雜度（語法分析、語意分析、程式碼生成），而硬體則極度簡化（只有 A 指令和 C 指令兩種）。這是刻意的設計——把複雜度往上推，讓硬體保持簡單。

本章小結

本節以一個具體的 Jack 程式為例，完整追蹤了從原始碼到硬體執行的每一層轉換。我們看到了編譯器如何把高階語法攤平為堆疊操作，VM Translator 如何把虛擬碼翻譯為組語，Assembler 如何把組語編碼為 16-bit 機器碼，以及 CPU 如何在時脈驅動下逐步執行這些指令。最後，我們說明了如何讓 nand2tetris 提供的 Tetris 遊戲在 Hack 平台上實際運行。整個過程的核心啟示是：計算機系統的每一層都是上一層的「翻譯」，而所有翻譯都保持相同的計算語意。
