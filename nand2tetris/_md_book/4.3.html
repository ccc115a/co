4.3 記憶體映射 I/O：螢幕與鍵盤的控制原理

到目前為止，我們的程式只能「讀記憶體、算資料、存回記憶體」——如果記憶體背後掛的只是 RAM 晶片，那這台電腦就只是一個會算數但與世隔絕的離線機器。真實世界的電腦必須與外界溝通：把結果畫在螢幕上、接收使用者的按鍵。本節要揭曉 Hack 使用的解法——記憶體映射 I/O（Memory-Mapped I/O）：把螢幕與鍵盤「偽裝」成記憶體的某些位址，程式只要讀寫那幾個位址，就能控制真實的周邊裝置。這不但讓 I/O 的操作語法與記憶體完全一致，也讓我們的 CPU 完全不須知道螢幕與鍵盤的存在。

I/O 的兩個經典做法

要讓 CPU 與周邊裝置溝通，硬體設計師有兩條路可走：

做法 原理 代表
獨立 I/O 埠（Port-Mapped I/O） CPU 提供額外的 IN/OUT 指令與 I/O 匯流排，周邊有自己的編號位址 x86 的 in/out 指令
記憶體映射 I/O（Memory-Mapped I/O） 周邊裝置被賦予一段記憶體位址，讀寫該位址即與裝置互動 Hack、ARM、RISC-V 常用

記憶體映射的關鍵好處是：對 CPU 而言，螢幕與鍵盤「不存在」。CPU 只知道自己在讀寫記憶體；真正把「位址 16384～24575」導到螢幕、「位址 24576」導到鍵盤電路的，是位址解碼器（第五章的 Memory 晶片負責做這件事）。因此：

  • 想讓螢幕顯示某個像素？→ 對對應的記憶體位址寫入位元就行。
  • 想知道使用者按了什麼鍵？→ 讀「鍵盤位址」這一格就行。
  • 完全不需要新增任何指令！畫面的輸出語法就是 M=…，鍵盤的輸入語法就是 D=M。

資料流如下圖所示，硬體上所有的「裝置」都被閘在記憶體位址這道統一的介面後面：

        CPU（只會存取記憶體）
              │ 位址 / 資料
      ┌───────▼────────┐
      │   Memory 晶片   │   ← 位址解碼在這裡發生
      │  ┌────────────┐ │
      │  │ RAM 0~16383 │ │（程式資料）
      │  ├────────────┤ │
      │  │ Screen 映射 │ │   16384~24575
      │  │（8K 字組）  │ │
      │  ├────────────┤ │
      │  │ Keyboard    │ │   24576
      │  └────────────┘ │
      └───┬─────────┬───┘
          │         │
    ┌─────▼───┐ ┌──▼──────┐
    │  螢幕    │ │  鍵盤    │
    │ 512×256 │ │  電路    │
    └─────────┘ └─────────┘

Hack 記憶體空間總覽：RAM 與 I/O 映射的完整地圖

Hack 的記憶體位址空間共 32K 個字組（15 位元定址，位址 0～32767）。組譯器與作業系統共用這張地圖，其中一部分是真 RAM，兩段是 I/O 映射：

位址範圍 大小 用途
0 – 15 16 字組 預先定義符號 R0～R15（其中 R0~R4 兼任 SP、LCL、ARG、THIS、THAT）
16 – 255 240 字組 組譯器配置給「變數符號」的空間
256 – 16383 — 程式資料區（堆疊、堆積、暫存工作區）
16384 – 24575 8K 字組 螢幕映射（Screen）：256 × 512 像素，16 像素/字組
24576 1 字組 鍵盤映射（KBD）：存放目前按下的鍵盤掃描碼
24577 – 32767 — 未使用（保留給未來的擴充）

預先定義的兩個 I/O 符號因此是：

@SCREEN     // 等於 @16384
@KBD        // 等於 @24576

只要記得「螢幕從 16384 起占用 8K、鍵盤單獨掛在 24576」，整張地圖就凍結在你的腦海裡了。

螢幕記憶體映射：8K 對應 256×512 像素

規格

Hack 螢幕是一台黑白螢幕：

  • 解析度：256 列（row）× 512 行（column）。
  • 像素：每個像素 1 bit——1 表示黑，0 表示白。
  • 記憶體預算：256 × 512 = 131,072 個像素 ÷ 每字組 16 bit = 8,192 個字組（8K）——正好填滿 16384～24575。

映射公式

螢幕記憶體以「列為主（row-major）」排列：同一列依序占用 512/16 = 32 個字組，下一列接著從第 33 個字組開始：

像素 (row, col) 的位址 = 16384 + row × 32 + (col DIV 16)
像素 (row, col) 的位元 = col MOD 16            （0 號位元 = 該組最左邊的像素）

其中  0 ≤ row ≤ 255       0 ≤ col ≤ 511
每列    32 個字組 → 連成 512 個像素

畫面上列 0 的 512 個像素被切成 32 組、每組 16 像素入一個字組。同一個字組內，bit 0（LSB）對應「該組最左邊那個像素」，bit 15 對應最右邊。想塗黑一組 16 像素，最偷懶的寫法就是把整格寫成 -1（16 個 1）。

像素操作範例

範例 A：把整個螢幕塗黑（把 8K 個字組全寫成 -1）：

// FillBlack.asm：整個螢幕塗黑
@SCREEN
D=A          // D = 16384
@addr
M=D          // addr = 16384，起點指標
@8192
D=A
@count
M=D          // count = 8192 個字組
(LOOP)
@addr
A=M          // A = 目前要塗的字組位址
M=-1         // RAM[addr] = -1（16 個位元全 1，全黑）
@addr
M=M+1        // 前進一格
@count
M=M-1        // 計數器 -1
@count
D=M
@LOOP
D;JGT        // 還沒塗滿就繼續
(END)
@END
0;JMP        // 程式結束：停在自己身上

範例 B：只點亮一個像素 (row=2, col=5)：

位址 = 16384 + 2×32 + (5 DIV 16) = 16384 + 64 + 0 = 16448
位元 = 5 MOD 16 = 5

@16448       // A = 16448
@1           // 先讓 D=1……（見下）

嚴格來說要做「把第 5 個位元設成 1」的位元寫入。但 Hack 沒有一般的 OR 指令運算元與記憶體同步的語法，所以教科書慣用的簡易做法是「整格覆寫」。只要我們知道該格原本只有這個像素在動，@16448 / D=A / A=D / M=D 這類操作就是可行的。更精確的位元設定通常會透過 D|M 的概念來完成：

// MayBeON：把 (row, col) 點黑（欄位 bit = col MOD 16）
// 假設 bit 暫存於 D（例如由常數或移位產生），此處示範固定畫 (2,5)
@1             // bit 值 = 1（先示範 bit0）
D=A            // D = 1
@16448
M=D|M          // 讀出原本內容，OR 上新位元，再寫回（精確位元寫入）

上面的 M=D|M 一次讀、一次算、一次寫，正是記憶體映射螢幕最常被使用的「read-modify-write」模式——因為螢幕背後就是真實的 RAM，讀回與覆寫都不花特別功夫。

鍵盤記憶體映射：Keyboard 在位址 24576

鍵盤的介面比螢幕更簡單——只有「一格」記憶體：RAM[24576]（符號 KBD）。

  • CPU 端：程式用普通的讀記憶體指令——@KBD / D=M——就能「看到」當前被按下的鍵。
  • 鍵盤硬體端：按下一個鍵，鍵盤電路會把對應的掃描碼（scancode）寫進 RAM[24576]；放開所有鍵時，值回到 0。

掃描碼對照表

按鍵 值 按鍵 值
沒有按鍵 0 方向鍵 上↑ 131
a~z 97~122（ASCII） 方向鍵 下↓ 133
A~Z 65~90（ASCII） 方向鍵 左← 130
0~9 48~57（ASCII） 方向鍵 右→ 132
Enter（換行） 128 Home 134
Backspace 129 End 135
Esc 140 PageUp / PageDown 136 / 137
F1~F12 141~152 Insert / Delete 138 / 139

要特別強調的是：鍵盤只負責「寫入 RAM[24576]」，程式要自己不斷去輪詢（poll）這一格。以下範例展示「偵測按下的鍵並把它數值複製到 RAM[100]」：

// 等待使用者按下任意鍵，再把鍵盤掃描碼存到 RAM[100]
(WAIT_KEY)
@KBD
D=M          // D = 目前按鍵（沒按就是 0）
@WAIT_KEY
D;JEQ        // 還是 0？繼續等
@KBD
D=M          // 再讀一次，取得掃描碼
@100
M=D          // RAM[100] = 掃描碼
(END)
@END
0;JMP

CPU 如何「看到」螢幕與鍵盤？—— 位址解碼與 Memory 晶片

記憶體映射成功的關鍵，是第五章要組裝的 Memory 晶片。它的本質是一台位址路由器：

  1. 位址 0～16383 → 送到真實 RAM 的字組。
  2. 位址 16384～24575 → 送到螢幕的 8K 暫存器陣列（這些暫存器同時也是畫面像素的內容）。
  3. 位址 24576 → 送到鍵盤電路的輸出鎖存器（latch）。
  4. 對於鍵盤，記憶體晶片只做「讀」的轉接；對於螢幕，只做「寫」的轉接。

因為 CPU 整個「人生」只見過「位址 + 資料」兩種訊號，它完全不需要知道：自己對 20000 寫進去的 -1，其實是在把一排像素塗黑；自己從 24576 讀出來的值，其實是使用者剛按下的鍵。「記憶體映射」把裝置與 CPU 的耦合徹底切開，這也是它能成為現代 CPU 主流作法的主因。

完整程式：依按鍵動態塗色的互動示範

把螢幕與鍵盤的映射合起來，就能寫出第一個「互動」程式：按住任意鍵螢幕全黑，放開後螢幕全白，一直重複偵測——經典的 Fill.asm：

// Fill.asm：螢幕持續依按鍵狀態變色
(LOOP)
@KBD
D=M
@WHITE
D;JEQ      // 沒按鍵 → 塗白
@color
M=-1       // 有按鍵 → 塗黑（-1 = 16 個位元全 1）
@DRAW
0;JMP
(WHITE)
@color
M=0        // 顏色設為白
(DRAW)
@SCREEN
D=A
@addr
M=D        // addr = 16384
@512       // 我們先只塗一個區塊試試看
D=A
@n
M=D        // n = 512 個字組
(PAINT)
@color
D=M        // D = 現在要塗的顏色
@addr
A=M        // A = 目前字組位址
M=D        // 塗上顏色
@addr
M=M+1      // 前進
@n
M=M-1
@n
D=M
@PAINT
D;JGT      // 未塗完繼續
@LOOP
0;JMP      // 塗完一輪，回到 LOOP 重新偵測鍵盤

習題模擬

比起整螢幕 8192 個字組，本範例只塗 512 個字組（前 16 列），好讓你在模擬器上立刻看到「按鍵 → 上方一條黑帶」的即時反應。把它改成 @8192 就是全螢幕塗黑/塗白。這個程式同時示範了本節所有核心技能：位址計算（@SCREEN）、指標走訪（@addr / A=M）、鍵盤輪詢（@KBD / D=M）與條件跳躍。

設計思路與實作步驟

設計與驗收記憶體映射 I/O 的完整流程：

  1. 決定位址配置：在 32K 空間中，把 16384～24575 劃給螢幕（8K 恰好匹配 256×512 像素）、24576 劃給鍵盤，兩者都落在 A-指令可定址範圍內。
  2. 設計螢幕排列：列為主、每列 32 字組、每字組 16 像素由左而右以 LSB→MSB 對應；列出公式 位址 = 16384 + row×32 + col/16。
  3. 確認像素語意：訂下 1=黑、0=白，讓 M=-1 直接對應全黑、M=0 對應全白，方便程式塗色。
  4. 設計鍵盤行為：訂下掃描碼表格與「無鍵=0」的規約，鍵盤電路只在值變化時更新 RAM[24576]。
  5. 寫測試程式：先跑「塗黑一整列」再跑「輪詢鍵盤」，用來驗證位址公式是否逐像素正確。
  6. 在 CPU 模擬器驗收：載入 Fill 這類互動程式，用模擬器內建的鍵盤與螢幕視窗確認輸入輸出行為；第五章再用 Memory 晶片在硬體層把位址解碼出來。

本章小結

  • 記憶體映射 I/O：把螢幕與鍵盤掛在記憶體位址空間上，程式以一般的讀寫指令即可控制裝置，CPU 不需認識任何裝置。
  • Hack 記憶體地圖：0–16383 為 RAM 資料區、16384–24575 為螢幕映射（8K 字組）、24576 為鍵盤映射，預先定義符號 SCREEN=16384 與 KBD=24576。
  • 螢幕規格：256×512 黑白像素，1=黑、0=白；像素(row,col) 落在 16384 + row×32 + col/16 的 col MOD 16 位元上；M=-1 即可一次塗黑 16 個像素。
  • 鍵盤規格：RAM[24576] 存放目前按鍵的掃描碼（ASCII 或 128 以上的特殊鍵碼），無鍵為 0；程式必須主動輪詢。
  • 位址解碼的幕後功臣：Memory 晶片把位址路由到 RAM、螢幕或鍵盤，I/O 介面在硬體層面被完全隔離。
  • 實作成果：一個不到 30 行的 Fill 程式，就能做到「按住 → 塗黑、放開 → 塗白」的即時互動。

至此，我們已經備齊全部的工具——兩類指令 + 記憶體映射。下一節就把這些零件組合成真正的程式，正式開始在 CPU 模擬器上寫與執行 Hack 組合語言。
