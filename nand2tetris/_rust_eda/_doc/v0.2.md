# hdl2rs v0.2 — 版本紀錄

日期：2026-09-10（115 學年度 · 計算機結構）
對應里程碑：**M2 — 循序電路（ch03）全數通過**

## 一句話

本版為 hdl2rs 加上**真實的 tick/tock 兩階段語意**：內建 `DFF` 由「回傳常數」
升級成 master/slave 暫存器，且有狀態晶片（`Bit`/`Register`/`RAM8`/`RAM64`/
`RAM512`/`RAM4K`/`RAM16K`/`PC`）的求值改為線性的 `sample`（tick 取樣）/`tock`
（提交）串接，**第 1~3 章全部 29 個測試 PASS**。

## 目錄（workspace `_eda/`）

同 v0.1，無結構變更。

## 本版實作內容

### DFF 兩階段模型

官方硬體模擬器的語意（已用 `Bit.cmp`/`PC.cmp` 驗證）：

- DFF 初始 `q=0`；
- **tick**：把當前的輸入取樣到 master latch，此時 `q` **不變**；
  輸出欄位在 tick 後顯示的是**舊 `q`**（例如 `Bit.tst` 的 `set in | tick | out`）；
- **tock**：master latch 提交到 slave `q`，`q` 在 tock 後才改變；
- 輸入只在 `set` 時改變，測試多半是 `set; tick; output; tock; output;` 的節奏。

codegen 把每個晶片展開成三層方法，取代原本「eval 內含後處理」的寫法：

- `eval(ins) -> Out`：**單趟**求值組合部分（DFF 子晶片直接回傳目前 `q`），
  產出關聯性輸出；
- `sample(ins)`：重算一次 wire 串接後，**只遞迴取樣有狀態的子晶片**
  （`is_seq`），葉 DFF 把輸入寫入 `latch = in_ & 1`；
- `tock()`：遞迴提交所有子晶片的狀態（`q = latch`）。

頂層 `Wrap`：

- `tick()` = `inner.sample(ins…)` + `do_eval()`；
- `tock()` = `inner.tock() + do_eval()`；
- 純組合晶片（ch01/02）的 `tick()` 是空操作、`tock()` 只有 `do_eval()`，
  v0.1 主程式側語意不變。

### 深入逐層（資料流）

```
tick： top.sample(ins) ──▶ 重算 wire → is_seq 子晶片 .sample(args)
        └─▶ DffChip.sample(in) { latch = in & 1 }
tock： top.tock() ──▶ 全部子晶片 .tock() ──▶ DffChip.tock { q = latch }
       then top.do_eval() 產出新輸出
```

### 效能修正（本版最重要的坑）

v0.2 初版 DFF `eval` 會「記錄 pending」，而在 `eval` **結尾**用後處理迴圈
重跑有狀態子晶片、以落定的 wire 重新取樣——這讓每一層 child 的 `eval`
被巢狀重跑，`RAM16K`（7 層 Register → RAM8 → …）的求值次數以**指數**成長
（約 2^7 ≈ 128×），跑 ch03 全部測試超過 120 秒被截斷。

新版把「取樣」徹底移出 `eval`，獨立成 `sample()` 單趟串接；對有狀態子晶片
**不重跑其完整求值**，只遞迴其 `sample`。`RAM16K` 每幀求值次數回到線性
（約總元件數 × 2），全 ch03 在數秒內完成。

### hackhdl：elaboration 支援循序電路

- `load_library` 改為**遞迴**掃描子目錄（`collect_hdl`，每層排序、跳過 dot-dir）：
  `--dir ../03` 一次載入 `03/a` 與 `03/b` 兩冊。
- 新增 `is_seq`（子晶片需 Builtin Dff 或本身 `has_state`）與 `part_seq` 判定。
- **feedback 迴圈是合法設計**：`PC` 的 `Register` 輸出回饋到 `Inc16`→`Mux16`；
  拓撲排序對「有狀態 part 的輸入讀取」跳過建邊（它不在 `eval` 求值、是在 `tick`
  取樣），輸出仍正常建邊，`PC` 與整個 RAM 系列都能免回圈地展開。
- 新增整合測試 `elab_ch03_sequential`（Bit/Register/RAM8/RAM64/RAM512/RAM4K/
  RAM16K/PC 有狀態檢查 + Mux/Not16/Add16/ALU 組合檢查）。

### 其他

- generator 內建 Dff 型別改為 `DffChip { latch, q }`（原初版 `pending/latch/q` 三欄）。
- `NandChip` 與所有晶片都提供 `tock()`，但 `NandChip::tock` 是空操作。

## 本版遇到的坑（處理過程）

1. **`chip_type` 打錯**：Builtin Dff 曾輸出 `DFFChip`（但實際型別叫 `DffChip`），
   Bit 首次冒煙測試靠編譯錯誤揪出。
2. **tick 後輸出舊值**：官方行為是「tick 取樣、q 不動，tock 才提交」；
   v0.1 的「回傳目前 q」其實早已符合，真正缺的是取樣/提交分離。
3. **後處理重跑造成指數爆炸**（見上「效能修正」），改 `sample` 串接解決。
4. **`--dir` 不遞迴** → `collect_hdl` 遞迴掃子目錄，`03/a`/`03/b` 一併載入。
