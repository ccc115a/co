# Rust 工具鏈 v0.6 — HACK 虛擬機 `hackemu`（GUI + headless 雙模式）

日期：2026-09-10（115 學年度 · 計算機結構）
對應里程碑：**M6 — 一支能執行 `.bin`／`.hack` 的 HACK 虛擬機，GUI 顯示 SCREEN**
（左右搖桿旁的那台「假電腦」；Rust 專案，與本學期 Rust 工具鏈同 workspace）

## 一句話

本版在 workspace（`_eda/`）新增第 7 個 crate：**`hackemu`** —— 用純 std 實作
HACK 全機（32K RAM + SCREEN 16384..24576 + KBD 24576），可載入 `hackasm --bin`
產生的 **`.bin`（little-endian u16）** 或 `.hack` 文字檔；執行時用
**egui/eframe 0.36** 開一個 GUI 視窗，把 SCREEN 依 512×256 畫素渲染成畫面，
鍵盤以 HACK keycode 寫進 KBD 暫存器；另提供 `--headless` 無視窗模式供自動化。

正確性與全鏈路交叉驗證：v0.5 的 chain 程式（`Main.init` 把 static `Main.0`
設成 5 後進入無窮迴圈）在 `hackemu` 跑到穩定後 **RAM[16] == 5** —— 與在
**hdl2rs 的 Computer.hdl 全閘層模擬**上的結果完全一致。

## 目錄（workspace `_eda/`）

- 由 6 個 crate → **7 個**：`hackasm` / `hackhdl` / `hackrt` / `hdl2rs` / `vm2asm` /

## 本版實作內容

### VM 核心（`lib.rs`）

- 記憶體映射：`ram: [u16; 32768]`；SCREEN = `16384..24576`（256 列 × 512 欄，
  每列 32 個 word），KBD = `24576`（無按鍵為 0）。
- 指令語意（與教材 `CPU.hdl` 一致）：
  - A-inst 載入 `A`；C-inst 依 `comp`/`dest`/`jump` 運算，ALU 完整 18 種 comp。
  - **M 的寫入位址用「更新前」的 A、jump 用「更新後」的 A** —— 這是硬體
    同步取樣每週期的答案：`AM=M-1` 是「A=SP-1；同時把舊堆疊頂槽覆寫成垃圾」，
    `A=M;JMP` 則跳到新 A。抓到的 bug 見「坑 1」。
  - `pc >= rom.len()` 時 stop（回傳 false），`run(n)`/`step()`/`reset()`。
- 載入：`load_bin`（u16 little-endian；byte 數需偶數）、`load_hack`（每行
  16-bit 0/1）、`load_file`（依副檔名自動選擇）。
- 畫素慣例：**word 的 bit15（MSB）= 最左邊畫素**；畫面由
  `screen_bitmap/屏幕_pixel` 提供，GUI 與測試共用。

### GUI（`main.rs`，egui/eframe 0.36）

- 控制列：路徑輸入框 + **Load**、**Run/Pause**、**Step**、**Reset**、**Speed**
  滑桿（對數刻度 0..=50,000 條/幀）、狀態列 PC/A/D/SP/cycles。GUI 文字一律
  英文（egui 預設字型不含中文字形，顯示會變方塊）。
- 螢幕：每幀把 `screen_bitmap` 填進 `ColorImage` 上傳 texture，
  `centered_and_justified` 縮放顯示。
- 鍵盤：`Event::Key { key, physical_key, pressed, repeat, .. }` 用 `key_code()`
  對應到 HACK keycode（ASCII 32–126 + 128 newline、129 backspace、130–137
  方向/Home/End/PgUp/PgDn、138 insert、139 delete、140 esc、141–152 F1–F12），
  按下寫進 KBD、放開清 0。

### headless（`main.rs`）

`hackemu --headless <file.bin|.hack> [--max N]`：不開視窗，跑 N 條後印出
執行前後 PC/A/D/SP/cycles、RAM[0..16] 與「RAM[16] static」（首格，對齊
chain RAM[16]==5 檢查），供 `test.sh`/`verify.sh` grep 驗證。

- workspace `cargo test`：hackasm 6、hackhdl 3、hdl2rs 5、vm2asm 5、jack2vm 5、
  **hackemu 6**，共 **30 個單元測試全數通過**。hackemu 測試用 dev-dependency
  `hackasm::assemble` 產生指令（避免手寫編碼出錯）。
- `verify.sh` 全綠：ch01–03（29）＋ ch04（2）＋ ch05（8）＋ chain e2e（1）＝
  **40/40 PASS**，加上新加的 **hackemu headless 交叉檢查**（RAM[16]==5），
  `test.sh` exit 0。
- e2e 交叉一致：chain.bin（242 條指令，hackasm `--bin` 產出）在 `hackemu`

  Computer.hdl 模擬結果相同。
- GUI 在 macOS 上可正常開啟、存活（`cargo run -p hackemu gen/chain/chain.hack`）。

## 本版遇到的坑（處理過程）

1. **M 寫入位址用新 A → 堆疊直接寫爛（最關鍵）**：第一版對 C-inst 的 `M write`
   用「更新後」的 A 當位址，`pop` 慣用語 `@SP / AM=M-1 / D=M` 把整個堆疊槽
   覆寫成垃圾，SP 一路爆到 32768 → `d:0x8000`、index out of bounds。改成
   **寫入用舊 A、跳躍用新 A** 後 chain 立即正確（RAM[16]=5）。與硬體同步
   電路的取樣順序一致。
2. **測試用手寫指令碼錯多**：第一版測試自己把 `D=A` 編成 `0xE880`（錯），
   正確是 `0xEC10`。改成用 `hackasm::assemble`（dev-dependency）把組語轉成
   指令，程式與測試同一條組譯路徑，自此不手編。
3. **egui 0.36 API 大改**：`eframe::App` 沒有 `update(ctx, frame)`，改成
   `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`；
   `TopBottomPanel` 不存在 → `egui::Panel::top(id).show(ui, …)`；
   `CentralPanel::show(ui, …)`；`ColorImage::new([w,h], pixels)`
   （欄位多 `source_size`）；`TextureHandle::set(&mut self, impl Into<ImageData>, …)`
   （set 不再要 `&egui::Context` 之後的舊參數）；`Event::Key` 沒有
   `logical_key`，只有 `key: Key` + `physical_key: Option<Key>`。
4. **`Key` 對應的 E0029**：`match &key { Key::A..=Key::Z => … }` 在 enum range
   不穩定的情形下不能對 `&Key` 用 range pattern；把 `key_code` 改成**吃
   `Key` 本身**、內部用數值比較（`(A as u8..=Z as u8).contains(&k)`）就過。
5. **crate 命名 `hackvm` → `hackemu`**：`vm2asm`/`jack2vm` 的「vm」指 HACK VM
   中間語言（`.vm`），ch06 也有 `vm` 執行程式；「執行整台機器」的模擬器叫
   `hackvm` 會語意混淆。改名 `hackemu`（hack + emulator，沿用 `hack*` 三字母
   慣例），目錄/`Cargo.toml`/workspace member/`test.sh`/`verify.sh`/文件同步
   更新，二進位為 `target/debug/hackemu`。

## 已知限制 / 待辦（next）

- GUI 目前以 `--max` 之外沒有自動跑到頂的選項——用速度滑桿控制；方便起見
  **Run** 是不限步數直到使用者按 Pause。
- KBD 多鍵同時按只記「最後按下」的碼（HACK 本身一次也只能讀一個 keycode）。
- 尚未用 ch12 OS（Pong 等）驗證：若屆時發現左右相反，把畫素慣例
  `1 << (15 - col % 16)` 翻成 `1 << (col % 16)` 即可（唯一需動的地方）。
- `--bin` 尚未接進 Computer.hdl 模擬的「load `.bin`」路徑（hdl2rs 都餵 `.hack`）；
  與 v0.5 待辦相同，視需要再做 `Memory` 的 `loadBin`。
