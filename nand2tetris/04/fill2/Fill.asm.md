# fill2/Fill.asm 程式說明：以 i 直接當位址的螢幕填色

`fill2/Fill.asm` 是 `fill/Fill.asm` 的第二種寫法（教材自訂的變體）。它不另設 `arr`
基底與計數器 `i` 兩個變數，而是**直接把螢幕位址 16384 當成 i**，一路遞增到 24576---
i 本身同時是「掃到第幾格」與「要寫入的位址」。它的 C 語言版（註解內）長這樣：

```c
FOREVER:
  int i = 16384;          // i 直接從 SCREEN 起點開始
WHILE:
  if (i >= 24576) goto WEND;   // 掃完整個螢幕
  int color = 0;               // 白色
  if (M[24576] == 0) goto NEXT;  // 沒按鍵 → 填白
  color = -1;                  // 有按鍵 → 填黑
NEXT:
  M[i] = color;                // 寫入螢幕
  i++;
  goto WHILE;
WEND:
  goto FOREVER;
```

## 概述

- 角色：與 `fill/Fill.asm` 同樣的「按鍵 → 全黑、無按鍵 → 全白」，但：
  1. 顏色先算出「結果」存進 `color` 變數，再一次寫入（if/else 是「選值」而非「直接寫」）；
  2. `i` 自己就是位址，省掉 `arr`、`n`，只用 `A=M` 間接寫入。
- 對應的組合語言重點：`D;JGE`（i≥24576 離開）、`@i A=M M=D`（把 i 當位址間接寫）、
  條件式選色。
- 價值：示範「指標與計數器合一」與「用 `A=M` 間接寫入」兩種 Hack 進階技巧。

## 架構總覽：變數位址配置

| 符號 | 位址 | 角色 |
|------|------|------|
| `SCREEN` | 16384 | 螢幕記憶體起點（此程式直接寫入的區段 16384..24575） |
| `KBD` | 24576 | 鍵盤記憶體 |
| `i` | **RAM[16]** | 從 16384 走到 24575，兼當位址指標 |
| `color` | **RAM[17]** | 0（白）或 -1（黑） |

「i 從 16384 到 24575」總共正好 8192 格，等於 `fill/Fill.asm` 的 `arr+i` 掃過全部
螢幕 word——兩者是同一件事的兩種計數方式。文字化流程圖：

```
(FOREVER)  i ← 16384
(WHILE) ──► i-24576 ≥ 0 ? → (WEND) → 回 FOREVER
           │否
           color ← 0（白）
           KBD == 0 ? → (NEXT)
           │否
           color ← -1（黑）
(NEXT)    RAM[i] ← color
           i ← i+1
           └─ 回 WHILE
```

## 原理：讓 i 同時指標與計數器

螢幕區段是連續的 8192 格（16384..24575）。要「整片填色」，只需要一個指標從 16384
開始，每格寫完 +1，直到超過 24575。既然如此，何必分 `arr`（起點）與 `i`（偏移）？
直接把「起點」塞進 i 就好：`i` 既是迴圈計數變數，又因為 `@i A=M M=D` 而成為
間接寫入用的位址。程式少了一層加法，位址計算 `A=D+M` 被換成 `A=M`。

### `A=M` 的間接寫入

```
@i
A=M        // A ← i（把 RAM[16] 的「值」當位址，裝進 A）
M=D        // RAM[i] ← D（D 事先載好 color）
```

第一行 `@i` 讓 A 指到 RAM[16] 所在的位址；`A=M` 讀出 i 的「內容」再寫回 A，
於是 A 從「RAM[16] 的位置」變成「i 所指向的位置」；第二行的 M 就落在 RAM[i]。

## 實作細節：逐段解說

```
(FOREVER)
@16384
D=A       // D = 16384
@i
M=D       // i = 16384

(WHILE)
@24576
D=A       // D = 24576
@i
D=M-D     // D = i - 24576
@WEND
D;JGE     // if (i >= 24576) goto WEND
```

條件式 `i>=24576`：先載入常數 24576 到 D，再 `D = M - D` 得 `i-24576`，用 `JGE`
（greater-or-equal，D≥0 跳）判斷。比較對象 24576 正好 = KBD，兩者共用位址。

```
@color
M=0       // color = 0（白色）
@24576
D=M       // D = *KBD
@NEXT
D;JEQ     // if (鍵盤為 0) goto NEXT → 保留白色
@color
M=-1      // color = -1（黑色）
(NEXT)
@color
D=M       // D = color
@i
A=M       // A = i（間接）
M=D       // RAM[i] = color
@i
M=M+1     // i++
@WHILE
0;JMP
(WEND)
@FOREVER
0;JMP
```

注意這裡的 if/else 是「先設好預設值，被否定才覆寫」的 pattern（`D;JEQ` 成立時
「跳過蓋黑」），與 `fill/Fill.asm` 的「直接走兩條路徑」略有不同，但結果相同。

## 測試與驗證

與 `fill2/Fill.tst` 一樣：載入 `Fill.hack`，關閉動畫，到 Keyboard 視窗按住任一鍵，
確認螢幕全黑；放開確認全白。也建議和前一支合併觀察：兩個版本行為應完全一致
（自動化時可比較 RAM[16384..24575] 的內容）。

## 延伸討論

- **為什麼要 `M[i] = color` 而不是直接 `M[i] = -1`？** 組合語言每個 C 指令只能有一個
  comp/運算，不能「依條件選 -1 或 0」當場寫入。用 `color` 變數把「決定顏色」與
  「寫入螢幕」兩個動作拆開，正是必要的解耦。
- 本版每格也重新讀 KBD（8192 次/輪）。將鍵盤讀一次進 color 的改良版見 `screenclear.*`
  的註解設計（它把「等按鍵」與「整螢幕寫 -1」分為兩層迴圈）。
- `A=M`（間接）與 `A=D+M`（位址偏移）是 Hack 唯二的「算位址」方式；看懂兩者，
  就看懂了組合語言的指標運用。
