# fill2/screenclear.asm 程式說明：等按鍵後把整片螢幕塗黑

`screenclear.asm` 是一個「偽組合語言」的設計稿：原始檔內容其實是包在 ```cpp ``` 程式碼
區塊裡的 C + goto 混和虛擬碼，每一行敘述後附上它「打算翻譯成的組合語言」。它示範的是
`Fill.asm` 的另一種流程：**先空轉等待按鍵，一旦偵測到按鍵，就把整片螢幕全部填成 -1
（黑）**——把舊畫面遮蓋掉，執行「清螢幕」的效果。（檔名雖叫 screenclear，實作是填黑。）

以下是虛擬碼的實際內容（`WHILE1` 等即未來組合語言的 label）：

```cpp
(WHILE1)
// while (1) {
  if (M[24576] == 0) goto WHILE1   // 沒有按鍵就一直等
  // if (M[24576] != 0) {
    int i = 16384;
(WHILE2)
      if (i >= 24576) goto EXIT    // 掃完整個螢幕
//    while (i < 24576) {
      M[i] = -1;                   // 填黑
      i++;
      goto WHILE2
//    }
//  }
  goto WHILE1
(EXIT)
```

## 概述

- 角色：`feedback` 流程的設計範本——「先同步等待事件，再一次動作」；
  也示範把 `while` 迴圈展開成 label + goto 的方式。
- 行為階段：
  1. `WHILE1`：空轉，直到 `M[24576]`（鍵盤）非零；
  2. `WHILE2`：i 從 16384 到 24575，逐一 `M[i] = -1`；
  3. `EXIT`：程式結束（或接後續）。
- 與其他檔的關係：`fill2/Fill.asm` 是「掃描→依鍵盤選色」，它把「等鍵」與「整片寫」
  拆開；`fill2/screenclear.c` 與本檔內容完全相同（C 與 asm 檔共享這份虛擬碼）。

## 架構總覽：翻譯成「真正的」組合語言

把上方的虛擬碼逐行翻成合法 Hack 組合語言如下（假設變數 `i` 配置在 RAM[16]）：

```
(WHILE1)
  @24576
  D=M        // D = *KBD
  @WHILE1
  D;JEQ      // 鍵盤為 0 → 繼續等
  @16384
  D=A
  @i
  M=D        // i = 16384
(WHILE2)
  @24576
  D=A        // D = 24576
  @i
  D=M-D      // D = i - 24576
  @EXIT
  D;JGE      // i >= 24576 → 結束
  @i
  D=M        // D = i
  A=D        // A = i（把 i 當位址）
  M=-1       // RAM[i] = -1（填黑）
  @i
  M=M+1      // i++
  @WHILE2
  0;JMP
(EXIT)
  @EXIT
  0;JMP      // 結束（無窮迴圈）
```

### 位址對照

| 常數/符號 | 數值 | 用途 |
|------|------|------|
| `24576` | `KBD` | 鍵盤映射位址（讀鍵） |
| `16384` | `SCREEN` | 螢幕第一格 |
| `24576` | 螢幕區段終點（開區間） | 迴圈終止比較 |
| `i` | RAM[16] | 位址指標兼計數器 |

## 原理與實作細節

1. **空轉等待 `D;JEQ`**：`while(1)` 可以寫成「檢查條件為假就跳回自己的 label」。
   `M[24576]==0` → `@24576 D=M @WHILE1 D;JEQ`：這是把鍵盤「輪詢」用一個自跳迴圈
   表示，是 Hack 版本「等待外部輸入」的唯一作法（沒有中斷）。
2. **填黑 = 寫 -1**：`M=-1` 就是 16 個位元全部 1，比「各 bit 全設 1」快。
3. **`i >= 24576` 的比較**：先 `@24576 D=A` 載入常數，再 `@i D=M-D` 得到
   `i - 24576`，最後 `D;JGE` 在差 ≥ 0 時離開。
4. **`M[i] = -1` 的間接寫入**：`@i D=M A=D M=-1`。
   這三行與 `fill2/Fill.asm`（用 `@color D=M @i A=M M=D`）的手法相同，差別只在
   这里是「直接寫 -1」而不用先存 color。

### 執行追蹤

- 沒有任何按鍵時：卡在 `(WHILE1)` 的自跳，螢幕不變（RAM 不寫入）。
- 按下一個鍵後：`D=M` 讀到非零 → 進行一整輪 8192 格的 `M[i] = -1`，螢幕全黑。
- 然後又回到 `(WHILE1)` 等下一次按鍵（或直接掉到 `(EXIT)` 程式結束）。

## 測試與驗證

手動測試：CPU Emulator 中載入對應 `.hack`，按下鍵盤應看到螢幕一次全部變黑。
若要觀察「等待」階段，可開啟 Visual 動畫一格一格跑：無按鍵時 PC 會在 `(WHILE1)`
內跳動，按鍵後 PC 才前進到 `(WHILE2)`。

## 延伸討論

- 真正「清螢幕」（清成白）只要把 `M=-1` 改成 `M=0`，其餘完全一樣——可見本程式
  討  論的「填色迴圈」結構是通用的螢幕繪製基礎。
- 這個「等 → 動」的兩層迴圈，對應到作業系統的事件迴圈雛形：輪詢、處理、再輪詢。
  第 8 章以後的 VM 語言、第 12 章 OS 內的 Screen.clearScreen 也是同一骨架。
- 註解裡的 `i <= 24576` 型終止條件用 `D;JGE` 實現（大於等於跳）；若改用
  `D;JGT`（>）則會多或少一格，寫組合語言時「等下一個不如比較下一個」容易出錯，
  建議先用 `i` 追蹤一遍位址範圍。
