# drawA.asm 程式說明：以點陣存入字母 A 的字模表

`drawA.asm` 在 RAM[10]~RAM[17] 連續 8 格寫入 8 個 16 位元值，構成字母 **A** 的
「字模（character bitmap）」資料表：每一列一行、每一格一個 word，word 中被設為 1
的位元就是該列要點亮的像素。程式本身不畫圖，只負責「準備好資料」；之後的
`test.asm` 或畫圖程式再取用這張表把 'A' 顯示在螢幕上。

## 概述

- 角色：字元點陣資料表（glyph table）的建立範例，展示「把資料直接寫進 RAM 的連續
  位址」這種最原始的陣列寫法。
- 資料存放：`A[0..7]` 對應 RAM[10..17]。RAM[10]=A[0]、RAM[11]=A[1]、…、RAM[17]=A[7]。
- 使用的指令全部是「A 指令 + `M=常數`」：沒有迴圈、沒有跳轉，是最簡單的「資料段」。

## 架構總覽：字模表與位址配置

| 元素 | 位址 | 值 | 二進位（bit15...bit0） |
|------|------|------|------|
| A[0] | RAM[10] | 0 | `0000000000000000` |
| A[1] | RAM[11] | 96 | `0000000001100000` |
| A[2] | RAM[12] | 400 | `0000000110010000` |
| A[3] | RAM[13] | 528 | `0000001000010000` |
| A[4] | RAM[14] | 1040 | `0000010000010000` |
| A[5] | RAM[15] | 4088 | `0000111111111000` |
| A[6] | RAM[16] | 4104 | `0001000000001000` |
| A[7] | RAM[17] | 8196 | `0010000000000100` |

把每一列的 1 描成像素（lsb 在右邊）：

```
A[0]  0      ................
A[1]  96     .........##.....   ← 筆畫頂部（兩點）
A[2]  400    .......##..#....
A[3]  528    ......#....#....   ← 左斜筆 col4，右斜筆漸右移
A[4]  1040   .....#.....#....
A[5]  4088   ....#########...   ← 橫槓（col3..11 全亮）
A[6]  4104   ...#........#...
A[7]  8196   ..#..........#..   ← 兩道腳（col2、col13）
```

由上而下看：頂端收攏成窄點（col 5,6），左右兩筆順著往下往外斜（左到 col2、右到 col13），
中間一條又長又粗的橫槓——輪廓就是一個風格化的字母 **A**。

## 原理：一個 word = 一列像素

Hack 螢幕每列 512 像素，切成 32 個 16-bit word。要畫一個字元，常用的設計是把
「一個字模」做成 5×7 或 8×8 的點陣：一個字模 = 7~8 列，每列恰好一個 16-bit word，
其中某幾個 bit 是 1。本表共 8 列（含 A[0]=0 當頂端空白間距），正好貼合「8×16
點陣」格局，方便接著用迴圈一個字一個字搬到螢幕上。

`M=96` 為什麼就是那兩個像素？96 = 0x60 = `0000 0000 0110 0000`，bit5、bit6 為 1。
同理 4088 = 0xFF8 = 連續 9 個位元是 1。**先把十進位拆回二進位、再用位元位置推像素**，
是解讀一切字模/圖形資料的基本功。

## 實作細節：逐段解說

```
@10
M=0        // A[0] = 0，空白列
@11
M=96       // A[1] = 96
@12
M=400      // A[2] = 400
@13
M=528      // A[3] = 528
@14
M=1040     // A[4] = 1040
@15
M=4088     // A[5] = 4088
@16
M=4104     // A[6] = 4104
@17
M=8196     // A[7] = 8196
```

每一行都是固定格式：`@n` 選定位址 n，`M=值` 把值寫入 RAM[n]。
注意 `@10` 這裡是**十進位常數**，代表「真的 RAM[10]」；這與 `@SCREEN`（符號＝16384）
或 `@R10`（符號＝10）是同一件事的不同寫法。用絕對位址寫資料有缺點：一旦程式加上
其他變數，位址就得手動重算（第 6 章組合器會自動處理符號變數）。

## 測試與驗證

- 沒有對應的 .tst（「資料段」程式一跑就結束），可在 CPU Emulator 中執行後檢查
  RAM[10..17] 是否分別是 `0, 96, 400, 528, 1040, 4088, 4104, 8196`。
- 驗證字模是否成像：把 `A[1..7]` 逐列畫到螢幕上（每列一個 word，放在 SCREEN 連續位址，
  或放到 SCREEN+34*row 等間距），眼睛即可比對上面的像素圖。

## 延伸討論

- 這張表之後被誰用？`test.asm` 只有 `@13 D=A` 一行，是「取 A[3]（位址 13）的值」
  的暖身指令；真正的「把字模搬到螢幕」迴圈（a-la Fill.asm 的 `RAM[arr+i]` 寫法）
  會在後續範例補齊。
- 一個 5×7 的字模 = 7 個 16-bit word；英文大小寫 + 數字 26+26+10≈62 字元，約 434
  word，不過 1 KB。第 12 章 OS 的 `Output.jack` 字模表就是用同樣的「每字元 8 個
  word」格式放在 ROM/RAM 裡，程式開機時再搬進 RAM。
