# mult2/Mult.asm 程式說明：Gemini 產生的移位快速乘法

`mult2/Mult.asm` 是 Gemini 特意「以組合語言直接實作快速乘法」的作品（對話網址見檔案開頭），
經測試結果正確。它不採用重複加法，而是對 R0 的 **16 個位元**逐一測試：某位元為 1 就把
「目前倍數的 R1（放在 MAND）」加進 R2，然後 MAND 與 MASK 雙雙翻倍，檢查下一位元。
這正是 `multFastFunc.c` / `multFast.c` 演算法的純組合語言版本。

## 概述

- 角色：第四章快速乘法的組合語言實作；用 RAM[3]、RAM[4] 當暫存變數。
- 輸入：R0（乘數）、R1（被乘數）；輸出：R2 = R0 × R1（16 位元二補數，mod 2^16）。
- 演算法：Shift-and-Add（移位加法），與 `mult.c` 的 O(R0) 相比只需 16 圈。
- 暫存變數命名（註解取自原始檔）：`MAND` = Multiplicand（被乘數的倍數）、
  `MASK` = 位元遮罩。

## 架構總覽：變數位址配置

| 符號 | 位址 | 角色 |
|------|------|------|
| `R0` | RAM[0] | 乘數（提供被測試的位元） |
| `R1` | RAM[1] | 被乘數 |
| `R2` | RAM[2] | 結果累積器 |
| `MAND`(=R3) | RAM[3] | R1 的倍數，每圈 ×2 |
| `MASK`(=R4) | RAM[4] | 位元遮罩，每圈 ×2 |
| `(LOOP)` | 迴圈入口 | 檢查 MASK 是否歸零 |
| `(ADD_PARTIAL)` | 加法的入口（R0 該位元為 1） |
| `(SHIFT_STEP)` | 移位步驟（兩者共用） |
| `(END)` | 結束（無窮迴圈） |

程式流（文字化流程圖）：

```
              MASK ← 1,  MAND ← R1,  R2 ← 0
              ┌──────────────────────────────┐
              ↓                              │
(LOOP)   MASK == 0 ?  ──是──► (END) 無窮迴圈
              │否
              R0 & MASK == 0 ?
              │否                                    │是
        R2 ← R2 + MAND  ──┐                         │
              └───────────┼─────────────────────────┤
              (SHIFT_STEP)  MAND ← MAND×2            │
                            MASK ← MASK×2            │
              0;JMP ─────────────────────────────────┘
```

## 原理：遮罩式移位乘法

`13 × 5`：13 = 1101b，所以 `13×5 = (8+4+1)×5 = 8×5+4×5+1×5`。要找出「哪幾個位元
是 1」，用遮罩：`MASK` 依序等於 `1,2,4,8,16,…`，每次做 `R0 AND MASK`——非 0 代表該
位元是 1。同時 `MAND` 依序等於 `R1, 2R1, 4R1, 8R1, …`（「被乘數的倍數」）。
某位元為 1 時，把當下的 MAND 加進 R2 即可。

追蹤 R0=6（110b）、R1=7：

| 圈 | MASK | R0&MASK | MAND | 動作 | R2 |
|----|----|----|----|----|----|
| 1 | 1 | 0 | 7 | 不加 | 0 |
| 2 | 2 | 2≠0 | 14 | R2+=14 | 14 |
| 3 | 4 | 4≠0 | 28 | R2+=28 | 42 |
| 4 | 8 | 0 | 56 | 不加 | 42 |
| … | 16 | 0 | 112 | … | 42 |

`6×7 = 42` 正確。遮罩每次翻倍後依次為 1,2,4,8,…,32768，**再翻倍一次就溢位成 0**
——這正是迴圈的結束條件：`D;JEQ MASK==0` 時，表示 16 個位元全部檢查完。

### 為什麼他的寫法在 16 位元下對負數也「順便正確」？

Hack 的 R0 若為負，其二補數表示第 15 位元是 1。程式照樣把所有 16 位元當「權重」
相加：這等價於「把 R0 當成無號數乘 R1（mod 2^16）」。就「低 16 位元結果」而言，
無號乘法與二補數有號乘法的介面結果一致，所以 `R2 = R0×R1 (mod 2^16)` 對負數輸入
依然成立——不需要像 `multFast.c` 特別處理正負號。

## 實作細節：逐段解說

### 初始化

```
@R2
M=0       // R2 = 0

@R1
D=M       // D = R1
@R3
M=D       // MAND = R1

@1
D=A       // D = 1  （A 指令載入常數 1）
@R4
M=D       // MASK = 1
```

### 迴圈主體

```
(LOOP)
    @R4
    D=M       // D = MASK
    @END
    D;JEQ     // MASK 變成 0 → 全部位元檢查完 → 結束

    // 1. 檢查 R0 的目前位元
    @R0
    D=M       // D = R0
    @R4
    A=M       // A = MASK（A 暫存器＝遮罩值，下一行的 M 指 RAM[MASK]）
    D=D&A     // D = R0 AND MASK，單指測出「這一位元」

    @SHIFT_STEP
    D;JEQ     // 若位元為 0，跳過加法，直接進移位
```

**`@R4 A=M`** 是本程式最刁的一行：把 RAM[4] 的「值」（遮罩）搬到 A 暫存器，
於是接下來 `D=D&A` 裡的 M 讀的是 RAM[MASK]——注意這裡 MASK 的「數值」被當成
位址來用，這與「把 A 當一般暫存器」的用途完全不同，是 Hack 間接定址的精華。

```
(ADD_PARTIAL)
    @R3
    D=M       // D = MAND
    @R2
    M=D+M     // R2 = R2 + MAND

(SHIFT_STEP)
    @R3
    D=M
    M=D+M     // MAND = MAND×2   （M 指 RAM[3]，自己加自己＝左移一位）

    @R4
    D=M
    M=D+M     // MASK = MASK×2

    @LOOP
    0;JMP     // 回迴圈
```

`M=D+M` 是「乘 2」的標準 Hack 手法：沒有 shift 指令，只好用
「自己加自己」。ALU 的 `D+M` 元件天然支援，組合語言一行搞定。

### 結束

```
(END)
    @END
    0;JMP     // 無窮迴圈結束
```

## 測試與驗證

使用 `Mult.tst`（六組輸入）與 `Mult.cmp` 比對：0×0=0、1×0=0、0×2=0、3×1=3、2×4=8、
6×7=42。檔案頭部註解標明「經測試，結果是對的」。同樣可在 CPU Emulator
`load Mult.hack` 後逐組設定 RAM[0]/RAM[1] 驗證。

## 延伸討論

- 對照 `multFastFunc.c` 可以看出：C 的 `if (b%2==1) r+=a; b>>=1; a<<=1;`
  對應到這裡的「測位元 → 加 MAND → MAND×2」。C 用 b 自己移位，組合語言用
  MASK 劃出要測的位元，兩種表面作法骨子裏是同一演算法。
- 對照 `multFast.c` 的 maskList 陣列：那是「先把遮罩全部存在 RAM」，本程式是
  「遮罩每圈現場翻倍」，後者省下 15 格記憶體，更適合組合語言。
- 本程式需要 2 個額外暫存格（R3、R4）。如果變數超過 R15，就要動到「符號變數」區
  （RAM[16] 起）——這是第 6 章組合器的領域。
