# multFast.c 程式說明：遮罩與倍增值的快速乘法

`multFast.c` 是第二種乘法演算法：不再「加 R1 共 R0 次」，改成「用位元遮罩檢查 R0 的
每一個位元，對應加進 R2，並在每一步之間把 R2 乘以 2」。作法上它先建立 15 個位元遮罩
放在陣列 `maskList[0..14]`，再從最高位元（i=14）往下掃到最低位元（i=0），因此叫「遮罩結合倍增值」的移位乘法。

## 概述

- 角色：第 4 章補充教材，示範比 O(R0) 快得多的 O(15) 演算法，以及負數（二補數）處理。
- 輸入：R0、R1（`short`，16 位元二補數）；輸出：R2。
- 重點技巧：重複加法 → 移位加法、`mask + mask` 產生 2 的冪、`~R2 + 1` 取負號。
- 與 `multFastFunc.c` 的關係：兩者都是「移位加法」，但本檔把遮罩*預先全部建好*放在陣列，
  再依序比對，而 `multFastFunc.c` 是動態地 `b>>=1; a<<=1;` 邊移位邊比對。

```c
short P = (R0 < 0) ? -R0 : R0;   // P = |R0|
short maskList[15];              // 每個元素 = 2^i，i = 0..14
...
i = 14;
while (1) {
  bit = P & maskList[i];     // 測試 R0 的第 i 位元
  if (bit != 0) R2 += R1;    // 該位元為 1，就把目前倍數的 R1 加進去
  if (i <= 0) break;
  R2 = R2 * 2;               // 下一個位元的權重差兩倍 → R2 先乘 2
  i--;
}
if (R0 < 0) R2 = ~R2 + 1;    // R2 = -R2
```

## 原理：二進位乘法與位元遮罩

任何整數都可以寫成二進位：`13 = 8+4+1 = 1101b`。所以

`13 × 5 = (8+4+1) × 5 = 8×5 + 4×5 + 1×5`

寫成平均分佈的機器運算，就是「對每個 1 位元，把該位元代表的 2^i 倍 R1 累加」。
二進位乘法＝**逐位元測試（AND 遮罩）＋移位求和**。

關鍵關係：**位元 i 的權重是位元 i-1 的兩倍**（16 位元中 `2^i = 2 × 2^(i-1)`）。
所以從高位元往低位元掃，每次「往下走一位」，前面累積的 R2 就必須乘 2，才能讓它
落到位元 i-1 的正確權重上。

### 遮罩與 15 位元的限制

`maskList[i] = 1 << i`，也就是 `mask = mask + mask` 翻倍 15 次：

| i | maskList[i] | 二進位 |
|----|----|----|
| 0 | 1 | 0000...0001 |
| 1 | 2 | 0000...0010 |
| … | … | … |
| 14 | 16384 | 0100...0000 |

只建到 14，是因為 16 位元帶正負號數中，第 15 位元是**正負號位元**；P=|R0| 保證非負，
其有效位元只到 bit 14。若你改用不帶正負號的 16 位元，則應建到 bit 15（遮罩 16384 之後
再翻倍會變 0，可看出是否溢位）。

## 實作細節：逐段解說

### 第一階段：建立遮罩陣列

```c
short mask = 1;           // maskList[0] = 1
short i = 0;
while (i < 15) {
  maskList[i] = mask;
  mask = mask + mask;     // 翻倍 → 2^i
  i++;
}
```

`mask + mask` 對 16 位元 `short` 而言就是「左移一位」（`mask << 1`）。Hack 組合語言裡
左移沒有專用指令，於是靠 `D+M` 或 `M+M` 實現（`mult2/Mult.asm` 就是用 `M=D+M` 做倍數）。

### 第二階段：從 bit 14 掃到 bit 0

```c
i = 14;
while (1) {
  bit = P & maskList[i];       // 抓到第 i 位元（0 或非 0）
  if (bit != 0) R2 = R2 + R1;
  if (i <= 0) break;
  R2 = R2 + R2;                // R2 *= 2（下一位的權重）
  i--;
}
```

**為什麼 `R2 = R2 + R2` 而不是 `R2 = R1 * (2^i)` 或把 R1 移位？** 因為累積器從最低
有效位元開始「累加完、再整個乘 2」：把目前已累積的 R2 乘 2，等同把先前所有加進去的
R1 貢獻都左移一位（`R2*2 = (Σ 2^j · R1_j)·2 = Σ 2^(j+1)·R1_j`）。這樣不必替 R1 做
乘 2 預處理，最後一位元處理完，R2 就是正確答案而不再乘 2。

**以 R0=3、R1=5 追蹤**（P=3=011b）：

| i | P & maskList[i] | R2（若加） | 之後 R2×2 | i |
|----|----|----|----|----|
| 14..2 | 3 與 4 以上的 mask 皆為 0 | R2 不動 | 仍 0 | … |
| 1 | 3 & 2 = 2 ≠ 0 → R2=0+5 | 5 | 5×2=10 | 0 |
| 0 | 3 & 1 = 1 ≠ 0 → R2=10+5 | 15 | 停止（i≤0 break） | ─ |

答案 15 正確。再驗 R0=13（1101b）、R1=5：i=3 → R2=5（×2=10）；i=2 → R2=15（×2=30）；
i=1 → R2=30（位元 0，×2=60）；i=0 → R2=65。8+4+1 正是 13，答案 65 正確。

### 負號與二補數

```c
if (R0 < 0) R2 = ~R2 + 1;   // R2 = -R2
```

因為程序用 P=|R0| 運算，若要真正得到 `R0 × R1`（R0 為負），最後要把正結果變號。
二補數取負＝「全部位元反相 + 1」：`-x = ~x + 1`。注意 `~R2 + 1` 套在 Hack 的 16 位元
ALU 上就是 `M=!M` 搭配 `M=M+1`，兩步完成。

## 測試與驗證

```
$ cc multFast.c -o multFast && ./multFast
maskList[0]=1
maskList[1]=2
...
maskList[14]=16384
R0=-13 R1=-5 R2=65 i=0 bit=1   ...（節錄）
R2=65
```

`(-13)×(-5)=65`，正負號處理正確。可再測（13,-5）→ -65、（-13,5）→ -65、
（0,5）→ 0 等組合。

## 延伸討論

- 這個「先建 maskList、再倒序掃」的版本，在沒有陣列的直接組合語言裡較難照抄
  （需 RAM 連續 15 格）。單純寫成組合語言時，通常改用 `mult2/Mult.asm` 的做法：
  遮罩每圈翻倍、被乘數每圈翻倍，比碰記憶體陣列簡單。
- 相對於 `mult.c` 的 O(R0)，本程式是固定 15 圈，效能與輸入大小無關，是「演算法
  設計改變複雜度」的示範。
- `mask = mask + mask` 最後一次會由 16384 跳到 32768>>>15 bit，若繼續翻倍（16384×2）
  會溢位變成 -32768 或 0。設計上「只建 15 個」正是刻意避開這格。
