# mult.c 程式說明：重複加法乘法的 C 語原始碼

`mult.c` 是把第 4 章乘法習題寫成 C 語言的版本：用「把 R1 連續加 R0 次」的方式計算
`R2 = R0 × R1`。它是 `Mult.asm`、`Mult1.asm`、`multGoto.asm` 三個組合語言版本的
源頭，也是理解組合語言檔「每一行在幹嘛」的地圖。

## 概述

- 角色：C 語言的對照版（與 `multGoto.c` 幾乎相同，只是用正統 `while` 迴圈）。
- 輸入：變數 R0、R1；輸出：變數 R2。
- 與 `multGoto.c` 的關係：`multGoto.c` 是把這隻程式的 `while` 手工改成 `goto`
  的版本；`Mult.asm`/`multGoto.asm` 又是 `goto` 版的逐行組合語言翻譯。

```c
#include <stdio.h>

int main() {
    int R0 = 3;
    int R1 = 5;
    int R2 = 0;

    while (R0 > 0) {
      R2 = R2 + R1;
      R0 = R0 - 1;
      printf("R0=%d R1=%d R2=%d\n", R0, R1, R2);
    }
    printf("R2=%d\n", R2);
}
```

## 架構總覽

全域的「記憶體配置」概念（在 Hack 組合語言中，這些 `int` 就是 RAM 裡的格子）：

| 變數 | 對應 RAM | 用途 |
|------|------|------|
| R0 | RAM[0] | 乘數，兼迴圈計數器 |
| R1 | RAM[1] | 被乘數 |
| R2 | RAM[2] | 累加結果 |

主流程：初始化 → while 迴圈（累加 → 計數器減 1）→ 印出結果。`printf` 在組合語言版裡
被整行刪掉（Hack 沒有輸出入），只剩計算。

## 原理：重複加法＝乘法

國小數學：`3 × 5 = 5 + 5 + 5`。因為正整數乘法就是重複加法，所以只要：

1. 把 R2 歸零；
2. 把 R1 加進 R2；
3. 把 R0 減 1；
4. 若 R0 還沒變成 0，回到第 2 步。

執行 R0 次之後，`R2 = R1 × R0`。這個演算法正確性由迴圈不變量
「R2 + R1 × R0 = 原來的 R1 × 原來的 R0」保證：每圈 R2 增加 R1、R0 減少 1，
總和保持不變；R0=0 時 R2 就是答案。

## 實作細節

**為何用 `R0` 當計數器？** 迴圈次數正好是 R0，直接把乘數拿來數最省事。缺點是
迴圈結束後 R0 變成 0——原始輸入被用壞了（`Mult1.asm` 用暫存變數 `a` 解決這個問題）。

**組合語言對照**（取自 `Mult.asm`）：

```c
R2 = 0;                 →   @2;  M=0
loop:
  if (R0 <= 0) goto exit1;   →   @0; D=M; @exit1; D;JLE
  R2 = R2 + R1;              →   @1; D=M; @2;  M=D+M
  R0 = R0 - 1;               →   @0; M=M-1
  goto loop;                 →   @loop; 0;JMP
exit1:
```

幾個 C 敘述被捨棄或改寫的理由：

- `#include <stdio.h>`、`main()`：Hack 組合語言沒有函式與標頭檔，程式直接從第一行開始跑。
- `printf(...)`：Hack 沒有 printf，輸出改由 RAM 檢查（`Mult.tst` 讀 RAM[0..2] 比對）。
- `int R0 = 3; int R1 = 5;`：Hack 版不改 R0/R1，是由**測試程式**從外部設定
  （`multGoto.c` 的註解明白寫著「測試程式會設，自己不要去設定」）。

## 測試與驗證

- 本機驗證演算法是否正確（mac 上）：

```
$ cc mult.c -o mult && ./mult
R0=2 R1=5 R2=5
R0=1 R1=5 R2=10
R0=0 R1=5 R2=15
R2=15
```

- 對照 `Mult.tst`：它在 CPU Emulator 設定 R0/R1 後跑固定時脈數，再比對 `Mult.cmp`。
  本程式印出的 `R2=15` 正好對應 `Mult.cmp` 中 3×1=3、2×4=8、6×7=42 這類「不同輸入」的
  結果格式。

## 延伸討論

- 時間複雜度 O(R0)：R0=10000 就要 10000 次加法。這正是 `multFast.c`（移位乘法）存在的
  理由——改用位元運算後，16 位元數最多只要 16 次迴圈。
- `int` 在 Hack 是 16 位元二補數，0~32767 是正數。若 R0 傳入負數或 >32767，重複加法
  會算出錯的「位元組截斷」結果；快速乘法版（`multFast.c`）特別處理了負號。
