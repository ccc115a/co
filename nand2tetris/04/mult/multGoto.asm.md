# multGoto.asm 程式說明：以 R0/R1/R2 符號撰寫的重複加法乘法

`multGoto.asm` 與 `Mult.asm` 是同一支乘法程式（`R2 = R0 × R1`，重複加法），差別在於
本檔完全改用**符號名稱** `@R0`、`@R1`、`@R2` 書寫，而且把 R2 歸零的方式寫成
`@0 D=A`（把常數 0 經由 A 載入 D），而不是 `M=0`。它的註解直接來自對應的 C 語言檔
`multGoto.c`，是理解「while → goto → 組合語言」三層轉換的最好橋樑。

## 概述

- 角色：第 4 章「從 C 到組合語言」的教學示範（對應 `doc/c2asm.md` 的第四章乘法習題章節）。
- 對應的 C 語言檔：`multGoto.c`，它正好把 C 改成 `goto` 版本，兩行之間的對應一一可見。
- 與 `Mult.asm`（官方版）的差異：
  1. 全用符號 `@R0`/`@R1`/`@R2`，不用 `@0`/`@1`/`@2`。
  2. `R2 = 0` 用了「載入常數」式寫法 `@0 D=A @R2 M=D`。
  3. `(exit1)` 之後**沒有** `@exit1 0;JMP`，程式跑完直接自然結束（不進無窮迴圈）。

## 對應的 C 語言版本（multGoto.c）

```c
int R0 = 3;
int R1 = 5;
int R2 = 0;

loop:                       // (loop)
    if (R0 <= 0) goto exit1;  // @R0 D=M @exit1 D;JLE
    R2 = R2 + R1;             // @R1 D=M @R2 M=D+M
    R0 = R0 - 1;              // @R0 M=M-1
    goto loop;                // @loop 0;JMP
exit1:
```

組合語言檔內每一行 C 註解後面，緊接著就是對應的 asm 指令——這正是「高階語言敘述
如何一一變成組合語言」的活教材。

## 架構總覽：變數位址與程式流

| 符號 | 位址 | 角色 |
|------|------|------|
| `R0` | RAM[0] | 乘數 + 迴圈計數器 |
| `R1` | RAM[1] | 被乘數 |
| `R2` | RAM[2] | 結果，從 0 開始累加 |
| `(loop)` | 程式第 13 行 | 迴圈入口 |

程式流（文字化流程圖）：

```
R2 ← 0
loop: ──► 若 R0 ≤ 0 → 跳到 exit1（結束）
           │
           R2 ← R2 + R1
           R0 ← R0 - 1
           └── 跳回 loop
```

## 實作細節：逐段解說

```
// int R2 = 0;
@0       // A = 0（取出「位址 0」這個值）
D=A      // D = 0   （A 暫存器的值 = 0）
@R2      // A = 2
M=D      // RAM[2] = 0
```

這裡用 `@0 D=A` 產生常數 0。`@0` 是 A 指令，載入的是「數值 0」（同時也是 RAM[0] 的
位址），`D=A` 把「A 暫存器目前的值」抄進 D，於是 D=0。這是 `D=A` vs `D=M` 的重要對比：
`D=A` 取「A 暫存器內容」，`D=M` 取「RAM[A] 內容」。前者用在「想要常數」時，後者用在
「想要記憶體的值」時。

```
(loop)
// if (R0 <= 0) goto exit1;
@R0
D=M      // D = R0
@exit1
D;JLE    // R0 ≤ 0 → 跳到 exit1

// R2 = R2 + R1;
@R1
D=M      // D = R1
@R2
M=D+M    // R2 = R1 + R2

// R0 = R0 - 1;
@R0
M=M-1    // R0--

// goto loop;
@loop
0;JMP
(exit1)  // 結束（無窮迴圈或自然跑完皆可）
```

與 `Mult.asm` 唯一的「語意差別」在 `R0` 變 0 之後：`Mult.asm` 停在
`@exit1 0;JMP`，本檔則直接落在 `(exit1)` 之後。Hack 組合語言沒有 end 指令，
程式照 PC 順序往下執行的話，可能在 exit1 之後執行到編譯器補的隨機位址內容——
在 CPU Emulator 中通常無妨，但嚴謹一點還是建議結尾加無窮迴圈。

## 執行追蹤（R0=3, R1=5）

| 迴圈次 | R0 | 動作 | R2 |
|------|------|------|------|
| 1 | 3 | R2=0+5 | 5 |
| 2 | 2 | R2=5+5 | 10 |
| 3 | 1 | R2=10+5 | 15 |
| 4 | 0 | D；JLE 成立 → exit1 | 15 |

## 測試與驗證

- 與 `Mult.tst` 流程相同：載入 `.hack` 檔，設定 RAM[0]、RAM[1]，執行後檢查 RAM[2]。
- 可用 `multGoto.js`（行為與本程式完全相同的 JavaScript）先在 Node 裡跑一遍對答案：

```
$ node multGoto.js
R0= 2 R1= 5 R2= 5
R0= 1 R1= 5 R2= 10
R0= 0 R1= 5 R2= 15
R2= 15
```

## 延伸討論

- `multGoto.c` 用 `goto` 寫出的版本，和組合語言幾乎一行對一行，這是編譯器
  「控制流程轉換」的實例：高階語言的 `while` 會被編譯器改寫成 label + 條件跳轉。
- 練習：把 `@0 D=A` 換成 `@R2 M=0`（`Mult.asm` 的寫法），行為完全一樣。這說明
  「常數載入」與「記憶體直接歸零」在 HACK 上常常是等價的選擇，看懂兩種寫法
  才算真正掌握 `D=A` 與 `M=0` 的語意。
