# Mult.asm 程式說明：用重複加法計算 R0 × R1

這是 Nand2Tetris 第 4 章（Hack 機器語言）的正式習題程式。它不做任何輸出入，只負責計算
`R2 = R0 × R1`，把答案放進 RAM[2]，然後停在無窮迴圈裡。乘法是用「重複加法」實現的：
把 R1 連續加 R0 次。

## 概述

- 在第 4 章中的地位：這是第一個要自己寫的組合語言程式（`projects/04/mult/Mult.asm`）。
- 輸入：RAM[0]（R0）、RAM[1]（R1）。
- 輸出：RAM[2]（R2）＝ R0 × R1。
- 演算法：`while (R0 > 0) { R2 = R2 + R1; R0 = R0 - 1; }`。
- 這是第四章兩個習題之一（另一個是 Fill.asm），處理「迴圈 + 條件跳轉」的核心概念。

本檔案的 C 語言對照版是同一目錄的 `mult.c`，兩者一一對照：

```c
int R0 = 3;
int R1 = 5;
int R2 = 0;
while (R0 > 0) {
  R2 = R2 + R1;
  R0 = R0 - 1;
}
```

## 對應的 C 語言版本

把上方的 while 迴圈改成「label + goto」形式，就像這個程式的骨架：

```c
int R2 = 0;
loop:
  if (R0 <= 0) goto exit1;   // while(R0>0) 的反向條件
  R2 = R2 + R1;
  R0 = R0 - 1;
  goto loop;
exit1:
```

Hack 組合語言沒有 `while`、沒有 `if`，只留下兩件事：

1. **label**（行標記）：用 `(名字)` 宣告，例如 `(loop)`、`(exit1)`。
2. **條件跳轉**：由 C 指令尾端的 `;JLE`、`;JMP` 等負責。

## 架構總覽：變數位址與指令格式

### 變數對應的 RAM 位址

| 符號 | 位址 | 角色 |
|------|------|------|
| `R0` | RAM[0] | 乘數，同時扮演迴圈計數器（每次減 1） |
| `R1` | RAM[1] | 被乘數，每一次迴圈都要加 |
| `R2` | RAM[2] | 累積結果 |
| `(loop)` | 程式第 4 行 | 迴圈入口 |
| `(exit1)` | 程式第 15 行 | 迴圈出口 |

注意這個檔案直接寫 `@0`、`@1`、`@2` 而不是 `@R0`、`@R1`、`@R2`。在 Hack 組合語言中，
`R0`~`R15` 這 16 個預定義符號正好指到 RAM[0]~RAM[15]，所以 `@R0` 和 `@0` 完全等價。

### 兩種指令如何控制暫存器

- **A 指令**：`@value`（或 `@symbol`）。把 value 載入 A 暫存器。之後：
  - `D=A` → 把「那個值」複製到 D（`A` 是指「A 暫存器的值」）。
  - `D=M` → 把「RAM[A] 的內容」複製到 D（`M` 是指「以 A 為位址的記憶體」）。
- **C 指令**：`dest=comp;jump`。ALU 先算出 `comp`，然後依 `dest` 決定存到 D、A 或 M 的哪裡；
  再依 `jump` 判斷要不要跳到 A 所指的位址。

這整支程式只用到了少數幾個 C 指令元件：

| 指令 | 意義 |
|------|------|
| `M=0` | RAM[A] ← 0 |
| `D=M` | D ← RAM[A] |
| `M=D+M` | RAM[A] ← RAM[A] + D |
| `M=M-1` | RAM[A] ← RAM[A] - 1 |
| `D;JLE` | 若 D ≤ 0 則跳到 A 所指的指令 |
| `0;JMP` | 無條件跳到 A 所指的指令 |

## 實作細節：逐段解說

整支程式如下（含 C 語言的註解對照）：

```
// int R2 = 0;
@2        // A = 2（指向 RAM[2]）
M=0       // RAM[2] = 0，R2 歸零

// while (R0 > 0) {  → 改成 loop: / if (R0 <= 0) goto exit1;
(loop)    // 宣告 label loop
@0        // A = 0
D=M       // D = R0
@exit1    // A = exit1 的位址
D;JLE     // 若 R0 <= 0 就跳到 exit1（迴圈結束）

// R2 = R2 + R1;
@1        // A = 1
D=M       // D = R1
@2        // A = 2
M=D+M     // RAM[2] = R1 + RAM[2]  （此刻 M 就是 R2）

// R0 = R0 - 1;
@0        // A = 0
M=M-1     // RAM[0] = RAM[0] - 1

// }  → 改成 goto loop;
@loop     // A = loop 的位址
0;JMP     // 跳回迴圈開頭

// exit1:
(exit1)
@exit1
0;JMP     // 無窮迴圈：程式「結束」（停在這裡）
```

### 兩個不容易直觀理解的點

1. **`D;JLE` 的條件方向是反的**。C 語言寫 `while (R0>0)`，組合語言沒有 `while`，
   只能寫「反條件就跳出」：`if (R0 <= 0) goto exit1`。迴圈每一次都先檢查、再決定繼續或離開。

2. **`M=D+M` 比 `M=D` 多做的事情**。`@2 M=D+M` 這一行，`M` 指的是「上一行 `@2` 設定好的
   RAM[2]」，所以 `M=D+M` 是 `RAM[2] = D + RAM[2]`＝Ｒ2 累加 R1。若寫成 `M=D` 就變成覆寫，
   每次迴圈都會把 R2 蓋掉。

### 執行追蹤（R0=3, R1=5）

| 第幾次進迴圈 | 進入時 R0 | 做完 `R2=D+M` | 做完 `M=M-1` 後 R0 | R2 |
|------|------|------|------|------|
| 1 | 3 | 0+5=5 | 2 | 5 |
| 2 | 2 | 5+5=10 | 1 | 10 |
| 3 | 1 | 10+5=15 | 0 | 15 |
| 4 | 0 | ── D≤0，跳到 exit1 ── | 0 | 15 |

得到 `R2 = 3 × 5 = 15`，答案正確。

## 測試與驗證

用 CPU Emulator 搭配 `Mult.tst`、`Mult.cmp`：

```
load Mult.hack,
output-file Mult.out,
compare-to Mult.cmp,
output-list RAM[0]%D2.6.2 RAM[1]%D2.6.2 RAM[2]%D2.6.2;
set RAM[0] 6,  set RAM[1] 7,  set RAM[2] -1;
repeat 210 { ticktock; }
```

測試檔會連續六組輸入（0×0、1×0、0×2、3×1、2×4、6×7），每組都把 RAM[2] 預先設成 -1，
用來確認程式「真的有把 R2 重新初始化為 0」。期望輸出（`Mult.cmp`）：

| RAM[0] | RAM[1] | RAM[2] |
|--------|--------|--------|
| 6 | 7 | 42 |

測試方法：在 CPU Emulator 中 `load Mult.asm` → 按 Run，或直接用指令執行
`load Mult.hack, repeat 210 { ticktock; }` 後比對輸出。

## 延伸討論

- 這個演算法需要 O(R0) 次加法：R0=6、R1=7 就要 6 次迴圈。若 R0 接近 65535，會慢得可怕。
  `multFast.c` 與 `mult2/Mult.asm` 用「移位 + 加法」把次數降為固定 16 次，就是為了解決這點。
- 這裡 R0 同時是乘數又是迴圈計數器；若後面還要用到原來的 R0，得先複製一份（像 `Mult1.asm`
  用變數 `a` 保存一份計數器），這是「用變數保存暫存器副本」的典型範例。
- 最後的 `@exit1 0;JMP` 無窮迴圈是 Hack 程式的標準「結束」方式——Hack 沒有 halt 指令，
  程式跑完必須自己找個地方空轉。
