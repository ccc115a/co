# Bit 程式說明 — 1 位元暫存器（記憶單元）

這個電路由一個 DFF（資料正反器）與一個 Mux 迴授構成，能記住 1 個位元；`load=1` 時把輸入存起來，否則保持原值。

## 概述

Bit 是整座「記憶體金字塔」的最底層。第 1 章建立的加法器、多工器都是**組合邏輯**（輸出完全由當前輸入決定，一旦輸入消失輸出就跟著消失），而電腦要「記得」東西，就需要**循序邏輯**：把上一個時刻的值留存到下一時刻。

本書把所有時序行為都封裝在 `DFF`（內建晶片）裡：它在時脈上升沿讀取輸入，並在下一時刻把該值呈現在輸出上。Bit 的任務就是在 DFF 外面套一層「要存就存、不存就別動」的決策邏輯，靠的是 Mux 迴授。

## 介面與規格

```
CHIP Bit {
    IN  in, load;
    OUT out;
}
```

時序規格（書上用 `[t]` 表示第 t 個時步）：

- 若 `load[t] = 1`：`out[t+1] = in[t]`（把這一個位元寫入）。
- 否則：`out[t+1] = out[t]`（維持原值不動）。

`load` 是「寫入致能」，一個位元被「鎖住」還是「可覆寫」完全由它決定。

## 原理

### 記憶 = 「自己的輸出」迴授

DFF 本身已經能「記住」一拍：它的輸出永遠是「上一個時步的輸入」。問題是，若不設防，每一拍它都會去追蹤目前 DFF 的輸入，無法選擇「這拍要不要更新」。

解法：接一個 **Mux** 選「更新來源」。若 `load=1`，把 Mux 選到外面的 `in`，這一拍 DFF 存下 `in`；若 `load=0`，把 Mux 選到 DFF **自己的輸出** `do`，形成迴路 — DFF 下一個時步的輸入就是它此刻的輸出，於是原值被留住了。

```
        in ──┐
              Mux ──→ DFF ──┬──→ out
        do ←──┘     ↑      │
              load ─┘      └──→ do（迴授回去）
```

## 實作細節

```hdl
PARTS:
    Mux(a=do, b=in, sel=load, out=mo);
    DFF(in=mo, out=do, out=out);
```

- `Mux(a=do, b=in, sel=load)`：`load=0` 選 `a=do`（自己的輸出），`load=1` 選 `b=in`（外部輸入）。因此 Mux 的輸出 `mo` 就是「DDF 下一拍該吃的值」。
- `DFF(in=mo, out=do, out=out)`：`do` 被同時用作（1）迴授給 Mux 的 `a` 輸入、（2）晶片輸出 `out`。一條信號線可以同時命名給兩個接腳，這是 HDL 常見寫法。
- 整個電路是一個**回授環路**：`do → Mux → DFF → do`。組合電路（Mux）負責決定，循序元件（DFF）負責定時，兩者合作無間。

注意 Bus 寬度：全部都是單一 bit，沒有 `[n]`。

## 測試與驗證

`Bit.tst` 用 `tick`/`tock` 一再驗證時序規格。`tick` 讓時脈到達 DFF、隨即 `tock` 讓輸出反映新值。測試反覆操作：

| in | load | 期望行為（下一時步） |
|----|------|---------------------|
| 0 | 0 | out 保持原值 |
| 0 | 1 | out 變成 0 |
| 1 | 0 | out 保持（仍是 0…） |
| 1 | 1 | out 變成 1 |
| — | 0 | 長時間保持，證明 `load=0` 時雷打不動 |

後半段一大串重複的 `in=0, load=0` 正是在測試「穩定 hold」：即使輸入歸零，只要 `load=0`，輸出一路保持先前寫入的值。這驗證了回授迴路的持值能力。

## 延伸討論

- 真實 RAM 常用 6 顆電晶體的 SRAM cell 或用電容的 DRAM cell，這裡的病態簡化（Mux + DFF）雖然慢，但邏輯完全等價。
- `load` 的概念會一路沿用：Register、RAM 全部只多不少地在傳遞同一個「寫入致能」訊號。
- DFF 是「時脈邊緣觸發」的抽象，本書刻意不解其門—它是第 1 章唯一允許視為黑箱的元件。
