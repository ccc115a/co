# RAM64 程式說明 — 64 字元記憶體（二層位址解碼）

這個電路由 8 個 RAM8 組成，用 6 條位址線在 64 個位置中擇一讀寫。它示範了理解 RAM 家族的關鍵概念：**先以高位位址選塊、再以低位位址選單元**。

## 概述

RAM64 是 RAM8 的第一次擴充，也是「分治式記憶體」的模板：不要直接做一個 64 選 1 的超大多工器，而是把 64 個 Register 裝進 8 個 RAM8，再用兩層位址解碼。

這套「塊 + 子位址」的結構在後續 RAM512、RAM4K 完全複製，因此讀懂 RAM64 就等於讀懂整條 RAM 家族。

## 介面與規格

```
CHIP RAM64 {
    IN  in[16], load, address[6];
    OUT out[16];
}
```

- `address[6]`：6 條位址線 → 2⁶ = 64 個位置。
- 位址分成兩段：`address[0..2]`（低 3 位）選**塊內的單元**，`address[3..5]`（高 3 位）選**是 8 塊中的哪一塊**。
- 行為與 RAM8 相同：`load=1` 時寫入被選中的位置，否則僅讀取。

## 原理

### 兩層解碼

64 個位置拆成「8 塊 × 每塊 8 個」。於是：

- `address[3..5]` 決定「哪一個 RAM8」被選中 — 用作 `DMux8Way` 的 `sel`，把 `load` 只送給那一塊 → `L0..L7` 之一為 1。
- `address[0..2]` 決定「在那一塊的哪一個 Register」— 原封不動直接傳給每塊 RAM8 內部的 `address`。被選中的塊內部再用自己的 DMux/Mux。未被選中的塊因 `load=0`，內部解碼做什麼都無所謂。
- 讀取同理：每塊 RAM8 各自用自己的 `address[0..2]` 求出區內輸出 `o0..o7`，再由外部 `Mux8Way16` 用 `address[3..5]` 挑出最終 `out`。

```
address[0..2] ──► 每一塊 RAM8 的內部 address（選單元）
address[3..5] ──► DMux8Way 選塊（寫入）／ Mux8Way16 選塊（讀出）
```

### 為什麼分層比較好

若做成單一 64 選 1 的元件，多工器要拉 64×16 條線、電路面積與延遲暴增；分層後每層只有 8 選 1，「選擇線的寬度」與「資料線的長度」都被壓縮。

## 實作細節

```hdl
PARTS:
    DMux8Way(in=load, sel=address[3..5], a=L0, b=L1, c=L2, d=L3,
                                          e=L4, f=L5, g=L6, h=L7);

    RAM8(in=in,  load=L0, address=address[0..2], out=o0);
    RAM8(in=in,  load=L1, address=address[0..2], out=o1);
    ...
    RAM8(in=in,  load=L7, address=address[0..2], out=o7);

    Mux8Way16(a=o0, b=o1, c=o2, d=o3, e=o4, f=o5, g=o6, h=o7,
              sel=address[3..5], out=out);
```

- **bus slicing 的層次對應**：`address[3..5]` 高三位看起來「大」，負責挑整個 8 塊；`address[0..2]` 低三位看起來「小」，只負責區內。位元權重完全等比例：位置 = `address[3..5] * 8 + address[0..2]`。
- 8 個 `RAM8` 的 `address` 通通收到 `address[0..2]` — 未選中的塊雖然也在解內部位址，但因為 `load=L0..L7` 中只有自己的那條為 1 的人才動作，其餘都是「讀取, 讀再多也不會洗掉資料」。
- 中繼線 `o0..o7` 是各塊的整塊輸出，最後匯入選塊 Mux。

## 測試與驗證

`RAM64.tst` 的手法與 RAM8 完全同型，只是位址從 3 位元變 6 位元：

1. 寫到「跨塊」的位址：如 `address=13`（塊 1、單元 5）、`address=47`（塊 5、單元 7），驗證高三位 `address[3..5]` 真的挑對塊。
2. 讀回「塊 0」檢查其他塊沒被波及。
3. `load=0` 時大量地改讀不同位址，每次都該返回各自先前寫入的值。

輸出格式 `address%D2.3.2` 用十進位顯示 6-bit 位址，方便直觀對照書本例子。

## 延伸討論

- 記憶體位址的「分塊」概念在真實電腦無所不在：SRAM/DRAM 的 bank、cache 的 set、分頁系統的 page，全是同一種「高位選區、低位選址」解碼樹。
- 下一步 RAM512 就是把「塊」換成 RAM64、把高 3 位 `address[6..8]` 當作新的選塊訊號 — 遞迴堆疊即可。
