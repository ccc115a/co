# RAM512 程式說明 — 512 字元記憶體

這個電路把 8 個 RAM64 用「高位位址選塊、低位位址選單元」的兩層架構組起來，共 512 個位置，位址線 9 條（`2^9 = 512`）。

## 概述

RAM512 是遞迴擴充的第二步：RAM8（3-bit）→ RAM64（6-bit）→ RAM512（9-bit）。它的 `.hdl` 與 RAM64 幾乎是同一個模子，只多了三條位址線，示範「把上一層 RAM 當作子元件堆疊」的無痛擴充。

## 介面與規格

```
CHIP RAM512 {
    IN  in[16], load, address[9];
    OUT out[16];
}
```

位址分工：

- `address[0..5]`：送給每個 RAM64 當內部位址（選 64 個單元之一）。因為 `2^6 = 64`。
- `address[6..8]`：高三位，選「8 塊 RAM64 中的哪一塊」。因為 `2^3 = 8`。

總容量：8 × 64 = 512。

## 原理

與 RAM64 完全同構的兩層解碼，只把「塊」的形態從 RAM8 換成 RAM64：

```
address[0..5] ──► 所有 RAM64 的內部位址（選單元）
address[6..8] ──► DMux8Way 選塊：把 load 只放行給其中一顆 RAM64
              ──► Mux8Way16 選塊：把該顆的輸出放上 out
```

高位的三條線 `address[6..8]` 第一次出現，但承擔的角色和 RAM64 中的 `address[3..5]` 一模一樣 — 這就是「每三條位址線換一批更大的子塊」的規律。

## 實作細節

```hdl
PARTS:
    DMux8Way(in=load, sel=address[6..8], a=L0, b=L1, ..., h=L7);

    RAM64(in=in,  load=L0, address=address[0..5], out=o0);
    RAM64(in=in,  load=L1, address=address[0..5], out=o1);
    ...
    RAM64(in=in,  load=L7, address=address[0..5], out=o7);

    Mux8Way16(a=o0, b=o1, ..., h=o7, sel=address[6..8], out=out);
```

各接腳的意義與 RAM64 逐字對應，唯一的差別是：

- `sel=address[6..8]` 而非 `address[3..5]` — 塊選擇提高三條線；
- 子元件從 `RAM8` 換成 `RAM64`，`address=address[0..5]`（六條而非三條）。

中繼線 `o0..o7` 仍是「每顆 RAM64 的整塊輸出」，最後經 `Mux8Way16` 收斂。

## 測試與驗證

`RAM512.tst` 沿用「挑跨塊位址寫入 → 回到塊 0 驗證未波及 → load=0 讀回」的套路，但位址更大，例如寫 `130`、`472`。輸出用 `address%D2.3.2`（十進位）方便對照。寫入從零開始再「set load 1 → tick/tock」的編排，讓記憶體由已知狀態起跑。

## 延伸討論

RAM512 已超出 Hack 電腦日常使用的記憶體大小（Hack 的 RAM16K 是標準工作記憶體），但它的存在展示了硬體設計「一行不改、只加大位址與換子元件」的擴充藝術。螢幕共用與資料記憶體的位置對映，在第五章全賴這種分層 RAM 的位址切分。
