# hdl2js v0.4 — 版本紀錄

日期：2026-09-13（115 學年度 · 計算機結構）
對應里程碑：**M4 — HACK 平台（ch04）2/2 通過**

## 一句話

`Mult.hack` / `Fill.hack` 兩支組語程式直接跑在 `Computer.hdl` 全機模擬上，驗收
`Mult-hw.tst` / `Fill-hw.tst` **2/2 PASS**；本版順手把效能洞補上：標準 RAM 結構融合成
原生 cell 陣列後，每週期成本掉 ~2700 倍。

## 本版實作內容

### test 收尾

- `reportCompare` 允許檔尾換行與否差異（`split('\n')` 尾端空串兩側都 pop；
  同 Rust `lines()` 語意）。`Mult-hw.cmp` 是老師自製、無結尾換行，之前因此誤判
  「行數不符」（6 個檢查點其實全對）。

### 效能：原生 RAM 融合（codegen）

- 病根：`Computer.sample` 每個 tick 都要對整棵 RAM 樹做 cascade＋回饋重算＋遞迴取樣，
  而 RAM16K = 16384 cell × 16 Bit × DFF 方法呼叫，單次 `RAM16K.eval` 就要
  **16ms**；整個 tick 約 **138ms**。Mult（630 週期）因此要 100 秒、Fill（4000 週期）
  估計 >800 秒。
- 作法：在 codegen 辨識「教材標準 RAM 結構」——`RAM8/64/512/4K/16K` 名字＋
  結構＝`DMux8Way + 8×Register/RAM* + Mux8Way16`（10 個 part）——則該晶片
  以 **`Uint16Array` cell 陣列**實作，語意與 gate 版完全等價：
  - `eval`：`out = mem[address]`（O(1)，仍是「tock 前的舊值」）。
  - `sample`：把 (address, in, load) 記進單字緩衝（兩相時序保留）。
  - `tock`：才寫回 `mem`（位元/暫存器可見性不變，`tick, output` 中段讀值照舊）。
  - `set_probe(name, i, v)`：直接寫 `mem[i]`（與 Rust 的 set_probe 語意一致）。
- 效果（Computer 全機、跑 Fill.hack）：
  - tick（sample）138ms → **0.05ms**，tock 5ms → 0.012ms，約 **2700×**。
  - `Fill-hw.tst`（4000 週期）：>800s（無法跑完）→ **0.22s**。
  - ch01–03 與 ch05 全部測試**照舊全綠**（29/29、8/8）——融合只動 codegen，
    elab 的 gate 圖、拓撲、回圈偵測全都沒變；`Register`/`Bit`/`PC` 仍是 gate 級。
