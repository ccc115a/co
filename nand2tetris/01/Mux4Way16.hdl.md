# Mux4Way16.hdl 程式說明

四路 16 位元多工器：兩條選擇位元 `sel[1..0]` 從四條 16-bit bus（`a`、`b`、`c`、`d`）中挑出一條輸出。

## 概述

`Mux4Way16` 是第一顆「多路多工器」，也是第一顆使用**多位元的選擇訊號（位址）**的電路。1-bit 選擇只能從 2 條路挑 1；這裡用 `sel[2]`（2 bit）編出 2² = 4 種選擇碼，輸出正好對應四條輸入 bus。它由三顆 `Mux16` 以「兩層樹」組織而成，宣告了第二章 ALU / RAM 位址解碼的雛形。

## 介面與規格

| IN/OUT | 名稱 | 寬度 |
|--------|------|------|
| IN | `a`, `b`, `c`, `d` | 各 16 bit |
| IN | `sel[2]` | 2 bit |
| OUT | `out[16]` | 16 bit |

真值表（`sel` 以二進位、最高位在前寫出）：

| sel | 輸出 |
|-----|------|
| 00  | a    |
| 01  | b    |
| 10  | c    |
| 11  | d    |

`sel[i]` 的索引約定：`sel[0]` 是最低位元（LSB），`sel[1]` 是最高位元（MSB）。所以 `sel=01` 時二進位 `01` = 十進位 1 → 選 b；`sel=10` → 選 c；`sel=11` → 選 d。

## 原理

「四選一」可拆成兩個階段：先兩兩對決，再對勝者對決。

- 第一階段：`sel[0]`（最低位）決定「(a,b) 這對挑誰」與「(c,d) 這對挑誰」。
- 第二階段：`sel[1]`（最高位）決定「挑 (a,b) 的勝者」還是「挑 (c,d) 的勝者」。

這正是**位址位元遞增（從 LSB 到 MSB）的樹狀解碼**：先由低位元分派，再由高位元定最終隸屬。拉開來看，`sel` 的三種二進位組合正是輸出資料的路徑編碼：

```
out = sel[1]==0 ? (sel[0]==0 ? a : b) : (sel[0]==0 ? c : d)
```

## 實作細節

```hdl
Mux16(a=a, b=b, sel=sel[0], out=outab);
Mux16(a=c, b=d, sel=sel[0], out=outcd);
Mux16(a=outab, b=outcd, sel=sel[1], out=out);
```

- `outab`：`sel[0]` 從 (a,b) 挑出的 16 位元結果。
- `outcd`：`sel[0]` 從 (c,d) 挑出的 16 位元結果。
- 第三顆 `Mux16` 以 `sel[1]` 從 `outab` / `outcd` 中擇一 → `out`。

思考範例：`sel = 10` → `sel[0]=0`、`sel[1]=1`。第一層挑出 `outab = a`、`outcd = c`；第二層 `sel[1]=1` 選 `b`（右邊輸入）→ `out = c`。與真值表 `sel=10 → c` 一致。

## 測試與驗證

執行 `Mux4Way16.tst`，前四組 `set sel 0/1/2/3`（十進位書寫，對應 `00/01/10/11`）配合全 0 輸入，之後再以四條不同的非零 bus 各測 `sel=0..3`，確認每次輸出恰為對應的那條輸入。注意測試以十進位 `set sel 2` 指定選擇碼，而 `.tst` 的 `output-list` 中 `sel%B2.2.2` 以二進位顯示。與 `Mux4Way16.cmp` 比對。

## 延伸討論

- 概念上 `Mux4Way16` 就是「兩個位元的位址 → 四條資料線」的去碼資料路徑。第三章 `RAM4K`、`RAM16K` 的位址解碼器（decoder）正是同一種樹：低位元切一級、高位元再切一級。
- 若要擴充到任意 2^n 路輸入，只需把樹加高 n 層；`Mux8Way16` 便是把本電路再當「葉元件」往上疊一層。
