# 4.1 組合語言與 ABI 規範

## 學習目標

## 1. ABI 是什麼？

**ABI（Application Binary Interface）** = 二進位層級的介面契約，決定**編譯器產生的機械碼如何互相合作**：

1. **Calling Convention**：函式間參數放哪、傳回值放哪、哪些暫存器誰負責保存。
2. **Data Layout**：struct 的對齊（Alignment）與 padding。

ABI 讓不同編譯器（GCC/LLVM/clang）編譯的 .o 可以互相鏈結；也讓 OS 核心能安全支援動態鏈結。RISC-V 採用 **rv32/rv64 psABI**（Linux 常用 ILP32/LP64）。

## 2. 函式呼叫約定 (Calling Conventions) 與暫存器分工

### 2.1 回顧暫存器的角色（1.1 表的簡化）

| 類別 | 暫存器 | 誰保存 |
|------|--------|--------|
| Parameters/Args | `a0–a7`（x10–x17） | **Caller** |
| Return Value | `a0`（必要時 `a1`） | Caller 收 |
| Temporary | `t0–t6`（x5–x7, x28–x31） | **Caller-Saved** |
| Saved | `s0–s11`（x8–x9, x18–x27） | **Callee-Saved** |
| `ra` | x1 | Caller（若呼叫其他函式須自己保存） |
| `sp` | x2 | Callee 維持 |
| `fp`/`s0` | x8 | 可作 Frame Pointer |

**Caller-Saved（volatile）**：呼叫者（Caller）在 `call` 之前若還需要這些值，必須自己壓棧保存。

**Callee-Saved（non-volatile）**：被呼叫者（Callee）若要用，必須在 **Prologue** 保存（壓棧）、**Epilogue** 恢復——這保證 Caller 的 `s0–s11` 值跨 call 不變。

### 2.2 引數傳遞與傳回值

RISC-V psABI 規則：

- 頭 8 個整數參數依序放 `a0-a7`；浮點放 `fa0-fa7`（RV32F/D 擴充）。
- 多於 8 個的參數：**由右至左溢出（overflow）到 stack**（處理位置對齊到 stack size 的倍數）。
- 傳回值：`a0`（32 位整數）、必要時 `a1`（64 位）；傳回 float → `fa0`、double → `fa0-fa1`。

範例：`int f(int a, int b, int c, int d, int e, int f, int g, int h, int i)` —— `a..h` 走 `a0..a7`，第 9 個參數 `i` 放 stack（`sp + 0` 位置，呼叫者負責）。

```asm
# 呼叫 func(1,2,3,4,5,6,7,8,9)
li   a0, 1
li   a1, 2
li   a2, 3
li   a3, 4
li   a4, 5
li   a5, 6
li   a6, 7
li   a7, 8
li   t0, 9
addi sp, sp, -16      # 保留 stack 給第 9 參數（對齊）
sw   t0, 0(sp)
call func
addi sp, sp, 16
```

## 3. 堆疊框架管理 (Stack Frame Architecture)

### 3.1 Stack Alignment

- RISC-V psABI 要求 `sp` 在任何函式呼叫邊界維持 **16-byte 對齊**——為了支援 SIMD（RV V）、雙精度浮點存取與 ABI 的一致性。
- 檔位切換：Prologue 每次 `addi sp, sp, -size` 的 `size` 必須是 16 的倍數（即使函式只需 4 bytes，也補到 16 的倍數）。

### 3.2 Prologue 與 Epilogue（標準模式）

```asm
my_func:
    addi sp, sp, -32     # Prologue：為 frame 保留 32B（16 對齊）
    sw   ra, 28(sp)      # 保存 ra（x1）
    sw   s0, 24(sp)      # 保存 callee-saved s0
    addi s0, sp, 32      # 建立 Frame Pointer（可選）
    # ... 函式本體（使用 a0~a7、t0~tX 等 caller-saved 任意改寫）
    lw   s0, 24(sp)      # Epilogue：恢復 s0
    lw   ra, 28(sp)      # 恢復 ra
    addi sp, sp, 32      # 收回 frame
    ret                  # = jalr x0, 0(ra) —— 跳回呼叫處
```

- **Stack 往下長**（sp 減向低位址）；`fp`（若用）標記 frame 起點，方便 debugger / unwind。
- **葉函式（leaf function，不再呼叫別人）**：`ra` 不必保存，Prologue/Epilogue 可省略——效能小技巧。

### 3.3 Frame 布局（從高地址往低）：

```
          高地址
 ┌───────────────────────┐
 │       local vars      │
 ├→ fp（指向 frame 起始） │
 │       saved ra        │
 │       saved s0..      │
 │       overflow args（caller 預留） │
 └─ sp →                  │（sp 現在指向 frame 底部）
```

### 3.4 variadic（可變參數）與 stack pointer 技巧

- variadic 函式（如 `printf`）需知道「哪些參數在 stack」，ABI 規定：呼叫者把 stack 參數**連續排放**並以對齊規格擺放，被呼叫者可用 `va_arg` 依指標循序取。
- 這就是為何 `printf` 家族要特別小心 type 不匹配（用 `%d` 讀了 double 的位元組 → undefined）。

## 4. 位置無關程式碼 (PIC) 與動態連結原理

### 4.1 問題：共享庫要被載入「任何處」

共享庫 (.so) 的位址無法事先固定（ASLR 隨機化、多個 process 各自 mapping）。若指令內部寫了絕對位址，換 base 就全部報廢。**PIC** 是讓程式碼**只用「相對自身」的偏移**存取自己資料的機制——不需 link-time fixup。

### 4.2 GOT（Global Offset Table）

- 在 shared object 的 **Data Segment** 建立一個 **您放「全域變數與函式位址」的表**。
- 指令不得直接寫絕對常數；而是：

```asm
auipc  t0, %pcrel_hi(gvar)    # t0 = PC + 高位偏移
addi   t0, t0, %pcrel_lo(...) # t0 = &gvar 在 GOT 的位置
lw     t1, 0(t0)              # t1 = gvar 目前的值（透過 GOT）
```

- 因為 GOT 本身在**同一 shared object** 內，其位址也可用 PC-relative 取得 → 整個 .so 不依賴絕對 base。data 與 code **皆可搬到任何虛擬位址**。

### 4.3 PLT（Procedure Linkage Table）與 Lazy Binding

如果每個函式 symbol 都在載入時解析，啟動會極慢。**PLT + GOT 的 Lazy Binding** 讓 symbol 解析「首次呼叫才發生」：

```
PLT[printf] 的流程（首呼）：
  1. 跳 PLT stub：先讀 GOT[printf]；initial 值 = PLT+表尾（未解析）
  2. 未解析 → 呼叫 dynamic linker（_dl_runtime_resolve）
  3. linker 找 symbol → 寫真位址回 GOT[printf]
  4. 跳到 printf 本體
後續呼叫（已解析）：GOT[printf] 已經是真正 printf → 直跳（幾 cycle）
```

| 優點 | 缺點 |
|------|------|
| 程式啟動只解析「會用到」的函式 | 首次呼叫有幾百 cycles 的解析懲罰 |
| 大量未用的函式不必動 linker | 若全程只呼叫一次，偶爾更慢 |

x86 → RISC-V 概念相同（`auipc`+`jalr` 對應 GOT/PLT 樣板）。

### 4.4 其他 ABI 細節（略）

- 資料對齊：`_Alignas`、struct padding，RV64 的 LP64 ABI（long=64bit、pointer=64bit）。
- Thread-Local Storage（TLS）：`tp` 基底 + offset，`tls` 區段。

---

## 5. 總結

- Calling Convention：caller-saved `t`/`a` 暫存器、callee-saved `s` 暫存器、`a0-a7` 頭 8 個參數、stack 放剩餘。
- Stack Frame：16-byte 對齊、Prologue（保存 ra/s + 建 fp）、Epilogue（還原 + `ret`）。
- PIC：所有資料透過 GOT 的 PC-relative 存取，讓 .so 可被搬到任意位址。
- PLT：首次呼叫才解析 symbol（Lazy Binding），加速啟動。
