## 1. 編譯器管線總覽：四大模組

一個完整的 Jack 編譯器由四個層次分明、可獨立測試的模組構成：

```
                 ┌──────────────────────┐
   Jack 原始碼   │   1. JackTokenizer    │  詞法分析：切成 token 串流
                 └──────────────────────┘
                            │ token 串流
                 ┌──────────────────────┐
                 │   2. CompilationEngine│  語法分析 + 代碼生成（遞迴下降）
                 └──────────────────────┘
                            │ .vm 指令
                 ┌──────────────────────┐
                 │   3. SymbolTable      │  11.1 節：查名字、得段與偏移
                 └──────────────────────┘
                 ┌──────────────────────┐
                 │   4. VMWriter         │ 把抽象動作寫成 .vm 文字
                 └──────────────────────┘
                            ▼
                        .vm 檔案
```

- **JackTokenizer（詞法分析）**：把原始碼切成一顆顆 token，過濾空白與註解。這是第 10 章已經做好的部分，直接用。
- **CompilationEngine（語法分析＋代碼生成）**：按文法走訪 token，同時**邊剖析邊發 VM 指令**。這是本章的主力模組，採用「編譯後端（syntax-directed translation）」——剖析的同時就把動作吐出來，不必先建一整棵樹。
- **SymbolTable（符號表）**：11.1 節那張能查名字、得段與偏移的表。
- **VMWriter（VM 寫入器）**：把「push/pop/call/function……」這些抽象動作寫進輸出檔的薄介面。它接受 `push("local", 3)` 之類的高階呼叫，內部轉成 `push local 3` 的實體文字。

> **設計思路**：把 writer 獨立出來，是為了讓 CompilationEngine 不必管「VM 指令長什麼字面樣」——Engine 只說「我要 `push` 一個 local 3、`call` 一個 `Math.multiply` 吃兩個參數」，writer 負責排版。這種「發令者」與「執行細務」的分離，讓整隻編譯器好讀、好改、好測。

## 2. 從 token 到 VM：語法在前、動作在後

CompilationEngine 是關鍵。它採用**遞迴下降**（recursive descent）的方式，針對 Jack 文法中的每個產生式（rule）寫一個對應的剖析方法。例如 Jack 的 assign 陳述式：

```
statements: statement*
statement : letStatement | ifStatement | whileStatement | doStatement | returnStatement
letStatement: 'let' varName ('[' expression ']')? '=' expression ';'
```

Engine 就有 `compileStatements()`、`compileLet()`、`compileIf()`、`compileExpression()`……每個方法先依文法取 token，再在適當時機呼叫 VMWriter 發指令。

一個最有代表性的對照：**`term` 遇見 `varName` 時**，得判斷它是普通變數、陣列元素，還是字串常數。這就是 11.1、11.3 的符號表與指標技巧真正發光發熱的地方：

```python
def compile_term(self):
    token, kind, value = self.tokenizer.peek()
    if token == 'identifier':
        if self.tokenizer.peek(1) == '[':       # 陣列元素：a[i]
            self.compile_array_read()            # (11.3：base+index→that→push that 0)
        else:
            self.compile_var_push()              # 查符號表 → push segment index
    elif token == 'integerConstant':
        self.writer.write_push('constant', value)
    # ... 其餘：字串、運算子括號、subroutine call……
```

如此一來，整隻編譯器的工作就變成：「**沿文法走，遇到該『取值』時 push、該『存值』時 pop、該『呼叫』時 call**」。

## 3. 編譯整個專案：多個 .jack 檔案

Jack 專案通常由多個類別組成，例如一個猜數字遊戲可能是：

```
Main.jack
Game.jack
Player.jack
```

nand2tetris 的作業規定：**每個 `.jack` 檔對應一個 `.vm` 檔**。編譯器要：

1. 掃描目錄，找出所有 `.jack` 檔案
2. 對每個 `.jack` 檔，把內容丟給 tokenizer → engine 走一遍
3. 產出同名的 `.vm` 檔（例如 `Main.jack → Main.vm`）

在 Python 主程式裡大概是：

```python
import os, sys
from jack_tokenizer import JackTokenizer
from compilation_engine import CompilationEngine

def compile_file(jack_path, vm_path):
    tk = JackTokenizer(jack_path)
    engine = CompilationEngine(tk, vm_path)   # 邊剖析邊寫
    engine.compile_class()                     # 剖析整類並輸出 VM
    engine.close()

def main(dir_path):
    for name in sorted(os.listdir(dir_path)):
        if name.endswith(".jack"):
            base = name[:-5]                   # 去掉 .jack
            compile_file(
                os.path.join(dir_path, name),
                os.path.join(dir_path, base + ".vm"),
            )

if __name__ == "__main__":
    main(sys.argv[1])
```

每個 `.jack` 的編譯就是呼叫一次 `compile_class()`——它會開一張新的類別符號表，然後依序處理 static/field 宣告與所有 subroutine。

## 4. 產出的 .vm 如何與 VM translator 對接

編譯產物是一堆 `.vm` 檔。下一站是我們第 8 章親手打造的 **VM translator**：它接收一個目錄（或單一 .vm 檔），把所有 `.vm` 合併產生一個單一的 `.asm` 檔，其中的 `function/call/return` 都會被翻譯成真正的 Hack 組語（包含 C_ALLOC 這類的記憶體初始化）。

一個「完整可執行」的 Jack 程式，還需要 **Jack OS**（`Sys.jack` 等作業系統類別）一同編譯。整個 apps 資料夾的標準布局例如：

```
Main.jack      ← 主程式（Sys.init 會對其呼叫）
...其他.jack
Sys.jack       ← OS：Sys.init、Memory、Math、Output、Keyboard、String、Array、Screen…
```

Sys.init 是程式入口，它會 `call Main.main` 去啟動使用者程式。所以「完整跑通」的順序是：

1. **編譯**：把所有 `.jack`（含 Sys 與你的類別）統統編成 `.vm`。
2. **翻譯**：VM translator 把整個 `.vm` 資料夾合成 `.asm`。
3. **組譯**：第 6 章的組譯器把 `.asm` 變成 `.hack`。
4. **執行**：第 5 章（或模擬器 / CPU emulator）載入 `.hack` 執行。

在 nand2tetris 提供的 **CPU Emulator** 網頁工具裡，甚至可以「直接載入資料夾的 .vm」，由內建 translator 現場翻譯執行——非常適合快速驗證「編譯器輸出正確與否」。

## 6. 測試與除錯編譯器的方法

編譯器出錯才是最痛苦的除錯，因為「第一行程式碼看起來對、但整支程式卻跑不出來」。以下是務實的策略，由淺入深。

### 6.1 逐步輸出（tracing）

在 `compile_*` 方法裡加入可選的 print，觀察剖析流程：

```python
def compile_let(self):
    print("[compileLet]")          # 可選除錯輸出
    self.tokenizer.advance()       # 吃掉 'let'
    # ...
```

這是了解「剖析走到哪、token 是哪顆」的最快方式。

### 6.2 與官方編譯器 diff 比對

這是最強的一招。對同一個 `.jack`：

1. 用**官方 JackCompiler** 編譯出 `official.vm`
2. 用自己的編譯器編譯出 `mine.vm`
3. `diff` 兩者

```bash
diff official.vm mine.vm
```

兩者雖不保證逐字相同（例如 while 的標號命名、常數處理方式），但只要語意一致，大體結構應相似。靠著這招，可以把錯誤範圍迅速縮小到「某一種陳述式」甚至「某一小段指令」。

### 6.3 用測試檔案逐特性驗證

nand2tetris 官方提供了一系列 `.jack` 測試檔，每個針對一種語法特性（ExpressionLessSquare、Square、ArrayTest、StatementsTest 等）。對每個測試檔：

- 先用官方編譯器編譯，取得 `.vm.tst` 的「期望對照輸出」
- 再跑自己的編譯器，看能不能通過官方附的 `.tst` 測試腳本

這叫做**黃金級（golden）對照測試**——拿標準答案當標尺。

### 6.4 在 VM Emulator 上單步

VM Emulator 可以一步步執行你的 .vm，看 stack、段、指標的變化。對照官方解法跑同一組動作，若某個 `pop this 0` 之後值不對，就回溯到「那條指令的產生邏輯」去修。

### 6.5 常見 bug 樣板

編譯器除錯時特別留意這幾類慣犯：

- **this 沒設好**：method prologue 忘了 `argument 0 → pointer 0`，導致 field 全部指向錯誤位址。
- **constructor 沒回 this**：少了結尾 `push pointer 0`，呼叫者拿到垃圾位址。
- **該 pop temp 卻留著回傳值**：`do` 陳述式呼叫後沒丟棄回傳值，污染 stack。
- **while 標號跳錯**：`if-goto` 的條件方向搞反（`not` 多/少一次）。
- **符號表沒在 subroutine 邊界重設**：subroutine 符號表跨了界，index 錯亂，陣列/參數全錯位。

掌握這些樣板，能大幅縮短你「看到壞輸出→找到壞函式」的距離。

## 7. 完整編譯器程式碼實作策略

最後，整理一份「從零到可用」的實作策略，依照依賴順序推出：

1. **先有 JackTokenizer**（第 10 章）：確認它能吐出一串 token。
2. **建立 VMWriter**：提供 `write_push(seg, index)`、`write_pop`、`write_arithmetic(op)`、`write_label`、`write_goto`、`write_if`、`write_call(name, nArgs)`、`write_function(name, nVars)`、`write_return`、`close()`。
3. **建立 SymbolTable**（11.1）：能 `start_subroutine/define/var_count/kind_of/type_of/index_of`。
4. **寫 CompilationEngine 的 `compile_class`**：開類別符號表 → static/field → 各 subroutine。
5. **依序實作 subroutine 三種**：constructor（alloc 回 this）、method（this 設 THIS）、function。
6. **再實作 statements 與 expression**：let/if/while/do/return；term 依 11.2/11.3 處理物件呼叫與陣列。
7. **用官方測試檔逐一過關**，與官方 `.vm` diff，修正差異。
8. **合併成主程式**（編譯整個資料夾）並接上工具鏈跑通完整專案（如 Pong）。

對照官方 Java 版的典型類別命名，你的 Python 版大致是：

```
JackTokenizer.py        # 詞法
SymbolTable.py          # 符號表
VMWriter.py             # 寫 VM
CompilationEngine.py    # 遞迴下降剖析 + 發指令
JackCompiler.py         # 主程式：掃描資料夾、串接各模組
```

> **設計思路**：關鍵心法是**由上而下切、由下而上組**。剖析規則（文法）定義「怎麼走」，符號表與 VMWriter 定義「走到後做什麼」，兩者透過 CompilationEngine 咬合。任何一層都保持清晰單一職責，之後想支援更多語法（例如 JC）時，只要在對應的 compile_* 方法動手，其餘不動。

## 8. 本章小結（本節）

- 完整編譯器 = **詞法（tokenizer）＋ 語法/代碼生成（engine）＋ 符號表 ＋ 寫入器（writer）**。
- CompilationEngine 用**遞迴下降**邊剖析邊發 VM 指令（syntax-directed translation），不必先建整棵樹。
- 編譯一個專案＝對每個 `.jack` 產生對應的 `.vm`；主程式只要掃描資料夾、逐一呼叫 `compile_class()`。
- 產出的 `.vm` 交由 VM translator → 組譯器 → Hack 電腦執行；標準 nand2tetris 工具鏈（CPU Emulator / VM Emulator）可快速驗證。
- 完整跑通 = **編譯 → 翻譯 → 組譯 → 載入執行**，可搭配官方工具縮短驗證迴路。
- 除錯策略：逐步輸出、與官方 `.vm` diff、官方黃金測試檔、VM Emulator 單步、熟記常見 bug 樣板。
- 實作次序：先讓 tokenizer 穩定，再 writer → symbol table → engine → 主程式，最後用測試檔逐特性的關閉缺口。

到這裡，你已經擁有了一把完整的魔法棒：**從一行高階的 Jack 程式，到最終在 Hack 硬體上跳動的 0 與 1**。第 6、8、10 章與本章的四把鑰匙，終於湊齊了整套「從原始碼到機器碼」的編譯工具鏈。接下來，你可以把玩你自己的高階語言、寫自己的遊戲（如 Pong、Tetris、甚至迷你作業系統），真正體會「從無到有，手寫一台電腦」的完整奇幻旅程。
