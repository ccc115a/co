# 第 13 章（續）　回顧與展望：現代計算機架構的演進

## 前言

恭喜你完成了從 NAND 閘到作業系統的全部旅程。Hack 平台是一個精心設計的教學工具——它足夠簡單，讓你能在一個學期內從零建構完整個計算機系統；又足夠真實，讓你學到的概念可以直接映射到真實世界的計算機。本章最後一節，我們要從 Hack 出發，回望真實世界，看看你學到的每一個核心概念在現代計算機中是如何體現的，以及技術是如何演進的。

## 13.3.1　從 Hack 指令集到現代指令集架構（ISA）

### Hack 的指令集

Hack 只有兩種指令：A 指令（載入常數/位址）和 C 指令（運算 + 跳轉）。這種極簡設計讓你理解了指令集的本質——**指令集是硬體與軟體之間的合約**。

### 現代指令集

| 特性 | Hack | x86-64 | ARM (AArch64) | RISC-V |
|------|------|--------|---------------|--------|
| 指令長度 | 固定 16-bit | 變長 1–15 bytes | 固定 32-bit | 固定 32-bit（基本） |
| 暫存器數量 | 3 個（A, D, M） | 16 個通用暫存器 | 31 個通用暫存器 | 32 個通用暫存器 |
| 記憶體存取 | 只有 C 指令的間接定址 | 豐富的定址模式 | Load/Store 架構 | Load/Store 架構 |
| 指令數量 | ~25 | 數百條 | 數百條 | 可擴展模組化 |

**x86-64** 是 CISC（Complex Instruction Set Computing）的代表，源自 1978 年的 Intel 8086，指令格式複雜且不固定。**ARM** 是 RISC（Reduced Instruction Set Computing）的典範，強調簡單指令與高時脈頻率。**RISC-V** 是 2010 年代誕生的開源指令集，設計哲學是「只保留真正必要的指令，其餘用擴展模組實現」。

### RISC-V 與 Hack 的精神對照

RISC-V 的基礎指令集（RV32I）只有約 40 條指令，與 Hack 的極簡精神一脈相承。RISC-V 設計者從教科書式的 RISC 原則出發，刻意保持乾淨的指令格式：

```
RISC-V R-type:  [funct7][rs2][rs1][funct3][rd][opcode]
Hack C-instr:   [111][comp][dest][jump]
```

兩者都追求「每條指令做一件事，指令格式規律」。差異在於 RISC-V 有更多暫存器、更豐富的尋址模式，以及模組化的擴展（乘除法 `M`、浮點 `F/D`、向量 `V` 等）。

## 13.3.2　從 Hack CPU 到現代處理器

### Hack CPU：單週期執行

Hack 的 CPU 在**一個時脈週期**內完成 Fetch → Decode → Execute → Write-back。這意味著一個時脈週期要做最多事情，因此時脈頻率受限於最慢的路徑。

```
時脈週期 ─┬─ Fetch ─┬─ Decode ─┬─ Execute ─┬─ Write-back ─┐
          │         │          │           │               │
          └─────────┴──────────┴───────────┴───────────────┘
                         一個完整的週期
```

### 現代處理器：管線化（Pipelining）

現代 CPU 把執行過程切成多個階段，讓多條指令同時在不同階段執行：

```
指令 1:  Fetch ──┬─ Decode ──┬─ Execute ──┬─ Memory ──┬─ Write-back
指令 2:          Fetch ──┬─ Decode ──┬─ Execute ──┬─ Memory ──┬─ WB
指令 3:                   Fetch ──┬─ Decode ──┬─ Execute ──┬─ Memory ──┬─ WB
```

這就像工廠的流水線：每個工人只做一個步驟，但所有工人同時工作，整體產能大幅提升。常見的管線有 5 階段（經典 RISC）到 14+ 階段（現代 Intel/ARM）。

**管線 Hazards（危險）：**

- **資料冒險**：下一條指令需要前一條尚未完成的結果。解決方案：**前遞**（forwarding）、暫存器重命名。
- **控制冒險**：條件跳轉的結果尚未決定時，後續指令已經進入管線。解決方案：**分支預測**。
- **結構冒險**：多條指令同時需要同一個硬體資源。解決方案：**資源複製**（如多個 ALU）。

### 快取記憶體（Cache）

Hack 使用平坦的 RAM，每次存取時間相同。但真實記憶體的存取速度遠慢於 CPU，因此現代處理器引入了多層快取：

```
CPU 核心
  ├─ L1 快取（~1 KB–64 KB，~1–4 個時脈週期）
  │    ├─ L1 I-Cache（指令）
  │    └─ L1 D-Cache（資料）
  ├─ L2 快取（~256 KB–1 MB，~10–20 個時脈週期）
  └─ L3 共享快取（~數 MB–數十 MB，~30–50 個時脈週期）

主記憶體（DRAM）：~100–300 個時脈週期
```

快取利用了**時間 locality**（最近存取的位址很可能再次被存取）和**空間 locality**（存取某個位址時，鄰近位址也很可能被存取）的原理。Cache miss 時會從下一層載入一整個 cache line（通常 64 bytes）。

### 分支預測（Branch Prediction）

管線化的 CPU 需要猜測條件跳轉的結果，以便提前取得下一條指令。現代處理器使用**動態分支預測**：

- **1-bit 預測器**：記住上次的結果（太簡單，容易反覆失敗）。
- **2-bit 飽和計數器**：需要連續兩次不同的結果才改變預測。
- **TAGE 預測器**（Tagged Geometric History Length）：用不同長度的歷史來匹配不同的跳轉模式，準確率可達 95%+。

如果預測失敗，管線要被沖刷（flush），浪費的時脈週期數量取決於管線深度。這就是為什麼深管線的 CPU（如早期的 Pentium 4）在分支密集的程式碼中表現反而較差。

### 超純量與亂序執行（Superscalar & Out-of-Order Execution）

現代 CPU 不只管線化，還能在同一個時脈週期內**同時發射多條指令**（超純量），甚至**打亂指令順序**以最大化執行單元的利用率（亂序執行）：

```
程式順序：      A → B → C → D → E
實際執行順序：  A → C → B → D → E   （B 等待 C 的結果，先執行 C）
```

這需要大量的硬體支援：重排序緩衝區（ROB）、暫存器重命名（Register Renaming）、保留站（Reservation Stations）。這些機制的核心目的是**找到指令之間的真正相依性，消除人為的順序限制**。

## 13.3.3　從 Hack 記憶體到現代作業系統

### 虛擬記憶體（Virtual Memory）

Hack 的程式直接存取真實的 RAM 位址。在現代作業系統中，每個行程有自己的**虛擬位址空間**，由硬體的**記憶體管理單元（MMU）**透過**頁表（Page Table）**轉換為真實的物理位址。

```
行程的虛擬位址空間          物理記憶體
┌─────────────┐           ┌─────────────┐
│ 0x00000000  │ ───────→  │ 物理頁框 42  │
│ 0x10000000  │ ───────→  │ 物理頁框 7   │
│ 0x7FFF0000  │ ───────→  │ 物理頁框 103 │
│ (未映射)     │ ──×       │              │
└─────────────┘           └─────────────┘
```

核心優勢：
- **記憶體保護**：一個行程不能存取另一個行程的記憶體。
- **記憶體過度配置（Overcommit）**：多個行程的虛擬位址總和可以大於物理記憶體。
- **共享記憶體**：不同行程的虛擬位址可以映射到同一個物理頁框。

### 多工（Multitasking）

Hack 執行程式時是完全佔用的——沒有「同時」執行多個程式的能力。現代作業系統透過**行程切換**實現多工：

1. **時間片（Time Slice）**：每個行程被分配一小段 CPU 時間（通常 1–10 毫秒）。
2. **情境切換（Context Switch）**：時間片用完時，OS 保存目前行程的所有暫存器狀態，載入下一個行程的狀態。這個過程需要硬體支援（中斷向量、暫存器保存區）。
3. **排程器（Scheduler）**：決定下一個要執行的行程。常見演算法：CFS（Linux）、多級回饋佇列（Windows）。

### 保護模式（Protection Ring）

現代 CPU 提供多個**執行權限等級**：

```
Ring 0（核心模式）：OS 核心、驅動程式   ─── 最高權限
Ring 1：驅動程式（實務上少用）
Ring 2：驅動程式（實務上少用）
Ring 3（使用者模式）：應用程式          ─── 最低權限
```

使用者程式無法直接執行特權指令（如修改頁表、存取 I/O 端口）。如果嘗試，CPU 會觸發**一般保護異常（General Protection Fault）**，交由 OS 處理。這就是為什麼你的應用程式崩潰時不會拖垮整個系統。

## 13.3.4　從 Jack Compiler 到現代編譯器優化

### Hack 的 VM 與編譯器

Hack 的 VM Translator 基本上是機械式翻譯，沒有優化。Jack Compiler 也很直接——把語法結構攤平為 VM 指令。這在教學上是正確的，因為清晰比效率更重要。

### 現代編譯器的優化技術

現代編譯器（如 GCC、LLVM、Clang）使用多階段優化管線，核心概念包括：

**1. 中間表示（IR, Intermediate Representation）**

編譯器通常把原始碼轉為一個平台無關的 IR（如 LLVM IR），在 IR 層進行大部分優化，最後才針對目標平台產生機器碼。

```
C 原始碼 → 前端（詞法/語法/語意分析）→ IR → 優化管線 → 後端（目標碼生成）→ 機器碼
```

**2. 靜態單一賦值形式（SSA, Static Single Assignment）**

SSA 要求每個變數只被賦值一次。這大大簡化了資料流分析：

```
// 一般形式        // SSA 形式
x = 1;            x1 = 1;
x = x + 1;        x2 = x1 + 1;
y = x * 2;        y1 = x2 * 2;
```

在 SSA 中，`phi` 函式用於合併不同控制流路徑的變數版本。大部分現代編譯器的優化管線都基於 SSA。

**3. 暫存器分配（Register Allocation）**

當可用暫存器的數量不足以容納所有變數時，編譯器必須決定哪些變數放在暫存器中、哪些溢位（spill）到記憶體。這是一個 NP-hard 問題，實務上常用圖著色演算法或貪婪演算法近似求解。

**4. 常見優化**

| 優化技術 | 說明 | 範例 |
|----------|------|------|
| 常數摺疊 | 編譯時計算常數表達式 | `3 + 4` → `7` |
| 常數傳播 | 用已知的常數值替換變數 | `x = 5; y = x` → `y = 5` |
| 死亡碼消除 | 移除永遠不會被使用的計算 | `x = 1; (x 未再使用)` → 刪除 |
| 循環不變量外提 | 把迴圈中不變的計算移到迴圈外 | `while(...){ sin(x) }` → `t=sin(x); while(...){ t }` |
| 循環展開 | 減少迴圈控制開銷 | 迭代 4 次 → 展開為 4 個獨立區塊 |
| 內聯展開 | 把小函式的呼叫替換為函式本體 | `add(a,b)` → 直接插入 `a+b` 的程式碼 |
| 向量化 | 把逐元素運算改為 SIMD 指令 | 迴圈加法 → `vadd v0, v1, v2` |

**5. JIT 編譯（Just-In-Time Compilation）**

現代虛擬機（如 Java JVM、JavaScript V8）不在程式啟動前完成全部編譯，而是在程式運行時動態編譯熱點程式碼（hot code），並根據運行時資訊進行更精準的優化。這結合了編譯語言的效能與直譯語言的靈活性。

## 13.3.5　Hack 學到的核心概念在真實系統中的體現

你在 nand2tetris 中學到的每一個概念，都在真實系統中有直接的對應：

| 你在 Hack 中學到的 | 真實系統中的對應 |
|--------------------|--------------------|
| NAND 閘 | 真實晶片中由數十億個電晶體組成的邏輯閘 |
| ALU | 現代 CPU 中有多個 ALU（含整數 ALU、浮點 ALU、向量 ALU） |
| 暫存器 | x86-64 有 RAX–R15 共 16 個通用暫存器；ARM 有 31 個 |
| RAM / 記憶體映射 | 現代系統的 MMIO（記憶體映射 I/O）用同樣的方式控制週邊裝置 |
| A/C 指令格式 | 現代 ISA 的固定/變長編碼，概念完全相同 |
| 組譯器 | 現代組譯器（GNU AS、NASM）做完全相同的事 |
| VM / 中間碼 | Java bytecode、.NET CIL、Python bytecode 都是 VM 中間碼 |
| 編譯器的語法分析 | 現代編譯器使用 LR/LL 解析器或 PEG，原理相同 |
| OS 的系統呼叫 | Linux 的 syscall、Windows 的 Win32 API 本質上是同一概念 |
| Memory-mapped Screen | 現代 GPU 的 framebuffer 就是記憶體映射的繪圖區域 |
| Memory-mapped Keyboard | 現代 USB HID 裝置最終也映射到記憶體或 I/O 端口 |

**這就是 nand2tetris 的力量：你不需要理解所有細節，但你需要理解所有概念。** 真實系統只是把這些概念放大、加速、加上工程上的各種技巧——核心邏輯完全一樣。

## 13.3.6　給讀者的下一步學習指引

完成 nand2tetris 後，你已經有了紮實的全棧基礎。以下是不同方向的深入建議：

### 硬體方向

- **《Computer Organization and Design》（Patterson & Hennessy）**：經典計算機組織教科書，深入 RISC-V 版本。
- **學習 RISC-V**：從 RV32I 開始，用 HDL 實作一個簡單的 RISC-V CPU（許多開源專案可參考，如 Ben Eater 的 8-bit CPU 系列影片）。
- **FPGA 實作**：把你的 Hack CPU 實作在 FPGA 上（如 Xilinx Basys 3），體驗真實硬體的時序約束。

### 軟體方向

- **《Compilers: Principles, Techniques, and Tools》（Dragon Book）**：編譯器的聖經，深入學習詞法分析、語法分析、語意分析、程式碼優化。
- **LLVM 專案**：實際研究一個工業級編譯器的 IR 與優化管線。
- **作業系統**：嘗試 xv6（MIT 的教學 OS）或自己寫一個微型核心（如 Writing an OS in Rust 系列）。

### 系統整合方向

- **《Computer Systems: A Programmer's Perspective》（CS:APP）**：從程式設計師的角度理解系統——連結、執行、記憶體層次、並行等。
- **嘗試完整專案**：用 nand2tetris 的經驗做一個自己的小作業系統、或一個完整的編譯器前端。

## 13.3.7　本書總結

這本書從一個看似不可能的問題出發：**如果我們從最基本的元件開始，能不能從零建造一台電腦？**

答案是可以的。我們證明了這條路：

```
NAND 閘
  → 基本邏輯閘（AND, OR, NOT, MUX）
    → 組合邏輯（加法器、ALU）
      → 序序邏輯（暫存器、計數器、記憶體）
        → CPU（Fetch-Decode-Execute 週期）
          → 記憶體系統（RAM、ROM、記憶體映射）
            → 計算機（CPU + RAM + ROM + I/O）
              → 組譯器（組語 → 機器碼）
                → 虛擬機（VM → 組語）
                  → 編譯器（高階語言 → VM）
                    → 作業系統（系統服務）
                      → 應用程式（Tetris!）
```

每一層都是下一個層級的基礎，每一層的實作都依賴你對上一層的理解。這種**層層建構**的方法論，不只是建造電腦的方法，更是理解任何複雜系統的方法——**把大問題拆成小問題，把小問題逐個擊破，最後再把它們組合起來**。

你在這趟旅程中學到的核心能力——硬體描述語言、數位邏輯設計、組譯器實作、編譯器實作、虛擬機設計、作業系統概念——這些不是教科書上的知識，而是你自己親手建造出來的理解。

當你下次打開電腦、執行一個程式、或瀏覽一個網站時，你會看到別人看不到的東西：在那個看似魔法的黑盒子裡面，從最底層的 NAND 閘到最頂層的應用程式，每一層都是清晰可理解的工程。你不再只是使用者——**你是建造者**。

**這就是從 0 到 1 的旅程。不是神秘，不是魔法，而是工程。**

本節從 Hack 教學平台出發，回望了現代計算機系統的四大領域：指令集架構（x86-64、ARM、RISC-V）、處理器微架構（管線化、快取、分支預測、超純量亂序執行）、作業系統（虛擬記憶體、多工、保護模式）、編譯器優化（IR、SSA、暫存器分配、JIT）。我們看到，nand2tetris 中的每一個核心概念在真實系統中都有直接的體現——真實系統只是把這些概念放大、加速、加上工程技巧。最後，我們為讀者提供了不同方向的深入學習建議，並回顧了全書的核心精神：**把複雜系統拆為可理解的層級，逐層建造，最後組成一個完整的整體**。恭喜你完成了這趟從 0 到 1 的奇幻之旅。
