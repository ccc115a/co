# 5.4 硬體模擬器上的系統調試

## 前言

完成 CPU 和 Memory 的組合，並成功構建出 Computer 晶片後，最精彩的部分才正要開始：讓這台你在紙面上設計出來的電腦真正「動起來」。硬體模擬器（Hardware Simulator，HDL Simulator）是 Nand2Tetris 課程提供的重要工具，它讓我們不須購買任何真實硬體，就能載入程式、執行指令、觀察每一個內部訊號的變化。本節將完整介紹如何在硬體模擬器上進行系統層級的除錯。

---

## 如何在 Hardware Simulator 中載入 Computer.hdl 與 ROM

### 準備工作

在開始之前，請確認你已經具備以下檔案，並確認它們位於同一個目錄：

```
├── Computer.hdl       # 完整的電腦晶片
├── CPU.hdl            # CPU 晶片
├── Memory.hdl         # 記憶體晶片
├── RAM16K.hdl         # 通用記憶體
├── Screen.hdl         # 螢幕記憶體
├── Keyboard.hdl       # 鍵盤介面
├── ROM32K.hdl         # 程式唯讀記憶體
└── xxx.hack           # 你的組合語言後製產物（機器碼）
```

### 載入步驟

1. 開啟硬體模擬器（Hardware Simulator）
2. 點擊 `File → Load Chip`，選擇載入 `Computer.hdl`
3. 載入後，介面左側會顯示 Computer 晶片的接腳（只有 `reset` 一個輸入）
4. 若是尚未組合語言的部分，請先用 `nand2tetris/tools` 中的 Assembler 將 `.asm` 檔案轉換成 `.hack` 檔案

### 測試腳本範例

硬體模擬器支援 `.tst` 測試腳本，可以控制重設時序並驗證執行結果。以下是一個基本測試腳本：

```tcl
// 測試腳本範例：執行並顯示 PC
load Computer.hdl,
output-file Computer.out,
compare-to Computer.cmp,
output-list time%S0.4.0 reset%B2.1.3 ARegister[]%D1.7.1 DRegister[]%D1.7.1 PC[]%D0.4.0;

// 啟動：reset=1，將 PC 重設為 0
set reset 1,
set RAM16K[0] 0,   // 設定初始記憶體內容
output;

// 釋放 reset，開始執行
set reset 0,

// 逐步查看前幾個週期的暫存器狀態
tick, tock, output;
tick, tock, output;
tick, tock, output;
```

## 撰寫自訂 .hack 程式放入 ROM

### 撰寫組合語言程式

首先撰寫一個簡單的 `.asm` 組合語言程式。例如，一個將 RAM[0] 的內容加一後存回 RAM[0] 的程式：

```asm
// AddOne.asm
// RAM[0] = RAM[0] + 1
@0
D=M
D=D+1
@0
M=D
@6
0;JMP   // 無窮迴圈
```

### 轉換成機器碼

使用工具目錄中的組合器，將 `.asm` 轉換為 `.hack`：

```bash
cd nand2tetris/tools
./Assembler.sh AddOne.asm
```

執行後會產生 `AddOne.hack` 檔案，內容類似：

```
0000000000000000
1111110000010000
1111110111010000
0000000000000000
1110001100001001
0000000000000110
1110101010000111
```

每一行都是一個 16-bit 的機器碼指令。`.hack` 檔案會被自動載入到 ROM32K 中，從位址 0 開始執行。

### 讓程式運行

在硬體模擬器中：

1. 載入 `Computer.hdl`
2. 確認同名目錄下有 `.hack` 檔案（模擬器會自動將同名的 `.hack` 載入 ROM32K）
3. 設定 `reset=1`，執行一個 `tick`/`tock`（或點擊一次快進）
4. 設定 `reset=0`，開始逐步執行
5. 觀察右側面板中 `PC`、`ARegister`、`DRegister` 的變化

## 逐步執行的除錯技巧

### 單步執行（Single-step）

硬體模擬器提供 `tick` 與 `tock` 兩種步進指令：

- **tick（時脈前緣）**：暫存器、PC、RAM 等在時脈邊緣更新前的穩定狀態
- **tock（時脈後緣）**：時脈完成，暫存器內容已更新

逐步執行技巧：

1. 在 CPU 的**時脈邊緣**前後分別觀察訊號，確認暫存器載入時機是否正確
2. 觀察 `instruction` 的位元內容，練習「肉眼解碼」：
   - `instruction[15]=0` → A-指令
   - `instruction[15..13]=111` → C-指令
3. 對照 `PC` 的變化，確認跳躍是否在正確的時機發生

### 觀察內部暫存器與記憶體

硬體模擬器的貼心設計是「雙擊」功能：

1. 在 CPU 內部，雙擊 A 暫存器或 D 暫存器，可以檢視裡面的值
2. 在 Memory 內部，雙擊 RAM16K，可以看到完整 16K 的記憶體內容
3. 螢幕記憶體會即時反映為畫面上的視覺化輸出
4. Keyboard 模擬器提供一個小鍵盤視窗，可以模擬按鍵輸入

### 使用「檢視內部」功能

若想檢視電腦內部各模組的詳細狀態，可以：

1. 點擊 `View → Chip view`，展開 Computer 內部的連線圖
2. 點擊其中任一模組（CPU、Memory、ROM32K）進入下一層
3. 逐步深入，直到看到最底層的 RAM 單元或邏輯閘

這種多層次的檢視方式，讓你能像剝洋蔥一樣，從最高層的電腦一路看到最底層的邏輯閘訊號。

### 使用「暫存器監看」功能

設定 `output` 指令，可以在輸出檔中持續追蹤特定訊號：

```tcl
output-list
  RAM16K[0]%D2.6.1
  RAM16K[1]%D2.6.1
  PC[]%D0.4.0;
```

這樣每一行輸出都會記下 RAM[0]、RAM[1] 與 PC 的值，方便比對程式執行效果。

## 驗證功能的測試

### 使用 compare 功能作自動化驗證

硬體模擬器支援「比較驗證」功能：將模擬結果與預期的輸出檔比對。

```tcl
load Computer.hdl,
output-file Computer.out,
compare-to Computer.cmp,
output-list RAM16K[0]%D2.6.1 RAM16K[1]%D2.6.1;

set RAM16K[0] 5,   // 初始值：RAM[0]=5
set RAM16K[1] 3,   // RAM[1]=3

set reset 1, tick, tock;   // 開機
set reset 0, tick, tock;   // 開始執行

// 執行一段時間（例如執行若干週期）
repeat 100 { tick, tock; }

output;  // 比較輸出
```

### 撰寫自己的 .cmp 驗證檔

建立 `Computer.cmp` 檔案，內容為期望的輸出：

```
|   RAM[0]   |   RAM[1]   |
|      110   |        3   |
```

當模擬結果與 `.cmp` 內容不一致時，模擬器會明確指出差異，幫助你定位錯誤。

## 常見問題疑難排解

### 問題 1：程式完全不動，PC 停留在 0

| 可能原因 | 解決方法 |
|----------|----------|
| `reset` 一直為 1 | 確認執行一段時間後將 `reset` 設為 0 |
| ROM32K 載入失敗 | 確認 `.hack` 檔案與 `.hdl` 在同目錄、檔案名稱正確 |
| 程式第一行就是死迴圈 | 檢查 PC 遞增邏輯 | 

### 問題 2：記憶體寫入無效

| 可能原因 | 解決方法 |
|----------|----------|
| `writeM` 訊號錯誤 | 檢查 CPU 中 d3 位元與 C-指令的解碼邏輯 |
| `addressM` 超出範圍 | Hack 只有 15-bit 位址（0-32767），超過即無效 |
| RAM 區域誤寫入 Screen | 檢查 Memory 的位址解碼邏輯 |

### 問題 3：跳躍不正常

| 可能原因 | 解決方法 |
|----------|----------|
| 旗標與 j 欄位邏輯錯誤 | 檢查 `outGt`/`outEq`/`outLt` 的計算 |
| A 暫存器未先載入目標位址 | C-指令的跳躍目標是 A 暫存器的值，跳躍前必須先用 A-指令載入目標位址 |
| 跳躍條件在 A-指令時誤觸發 | 確認跳躍只在 C-指令時有效 |

### 問題 4：模擬器出現「輸出超範圍」或連線錯誤

| 可能原因 | 解決方法 |
|----------|----------|
| 參數名稱拼錯 | 檢查各 CHIP 的 `IN`/`OUT` 宣告名稱 |
| 位元寬度不匹配 | 確認 15-bit 與 16-bit 訊號的切割正確（如 `[0..14]`） |
| 大量使用書中結構（如 `out=ARegister.out`） | 確認版本支援，必要時改用簡化命名如 `out=aOut` |

### 問題 5：Screen 沒有正確顯示

| 可能原因 | 解決方法 |
|----------|----------|
| Screen 位址映射錯誤 | 確認 Screen 基底位址為 16384（位址 `100000000000000`） |
| 寫入時 `load` 未被 AND 到 Screen | 檢查 Memory.hdl 中 `screenLoad` 的控制邏輯 |
| Screen 位址行數不足 | 256×512 像素需 8K 個 16-bit 字，檢查位址切割 |

## 本章小結

- 硬體模擬器是驗證 Computer 晶片的最佳工具，結合 `tick/tock` 可以精確控制時序
- `.asm` → `.hack` → ROM32K 的流程，讓程式執行與硬體架構無縫接軌
- 逐步執行與內部檢視功能，是解決邏輯錯誤的不二法門
- 自動化 `.tst` 測試腳本與 `.cmp` 比較驗證，確保硬體行為可重現
- 常見問題多集中在位址解碼、跳躍條件與時序控制，掌握這些要點就能快速除錯
- 當你的程式第一次在自製電腦上正確跑動起來的那一刻，你已真正「從 0 到 1」地走完建造電腦的全過程
