# 2.4 ALU 標誌位與運算邏輯驗證

> 在 2.3 節，我們完成了一顆能算出 `out` 的 ALU。但一顆「只會算、不會說話」的 ALU，還無法驅動程式流程。本節要為 ALU 加上最後的兩隻眼睛——`zr`（結果為零）與 `ng`（結果為負）——並探討它們在 CPU 條件跳躍中的角色，最後學會在硬體模擬器上徹底驗證 ALU。

## 前言

一台電腦除了「能算」，還必須能「做決定」：例如「如果 x 等於 0，就跳到某一行執行」。這些「決定」依賴的是硬體提供的**條件判斷**能力。而在 Hack 架構中，這種判斷的關鍵訊號，正是 ALU 輸出的兩個標誌位：

- **zr（zero）**：當 `out == 0` 時為 1。
- **ng（negative）**：當 `out < 0` 時為 1。

有了這兩個標誌，CPU 就能組合出「等於、不等於、大於、小於、大於等於、小於等於……」等多種條件，進而實現條件跳躍與迴圈。因此，本節要完成兩件事：**第一，為 ALU 產生正確的 zr 與 ng；第二，建立一套嚴謹的驗證流程，確保 ALU 的每一種運算都正確無誤。**

## zr 標誌：結果是否為零

### 設計思路

`zr` 的語義是「out 是否等於 0」。直覺的做法是：逐一檢查 out 的 16 個位元是否全都為 0——只要有任何一個位元是 1，zr 就該等於 0。

我們可以用一個 **Or8Way**（8 輸入 OR，輸出 8 個輸入的 OR）與一個 **Or** 閘來「濃縮」這 16 個位元：

```
zr = ~( out[15] | out[14] | ... | out[0] )
```

只要有一個位元為 1，OR 的結果就是 1，取反後 zr = 0。只有當 16 個位元全為 0 時，OR 結果為 0，取反後 zr = 1，才表示「結果為零」。

### 實作步驟

1. 把 `out` 的高 8 位（`out[15..8]`）送進 `Or8Way`，得到 `orHigh`。
2. 把 `out` 的低 8 位（`out[7..0]`）送進另一個 `Or8Way`，得到 `orLow`。
3. 用一個 `Or` 閘把 `orHigh` 與 `orLow` 合併。
4. 再用 `Not` 取反，即得 `zr`。

## ng 標誌：結果是否為負

### 設計思路

在多數二補數系統中，判斷一個 16 位元數是否為負，只需看**最高有效位（MSB，也就是符號位）** `out[15]`：

- `out[15] = 1` → 結果為負（ng = 1）。
- `out[15] = 0` → 結果非負（ng = 0）。

這是一條極簡的捷徑：**`ng` 就是 `out[15]` 的訊號**。比起逐位元檢查，這實在太方便了。

```hdl
// ng = out[15]
```

### 為何 MSB 能代表符號

回想 2.2 節的二補數：16 位元的範圍中，`1000 ... 0000`（MSB=1）到 `1111 ... 1111` 代表負數 -32768 到 -1；而 `0000 ... 0000` 到 `0111 ... 1111`（MSB=0）代表非負數 0 到 32767。因此 MSB 恰好就是「符號位」，直接取來當作 `ng` 即可。

## 在 CPU 中的用途：條件跳躍

### 條件跳躍的動機

假設我們要執行「若 x 等於 0 就跳轉」這類邏輯。Hack 機器語言中的 C-指令包含跳躍條件欄位（如 `JGT`、`JEQ`、`JLT` 等），而這些跳躍條件正是由 ALU 的 `zr` 與 `ng` 標誌組合判斷的。

ALU 將 `zr`、`ng` 與計算結果一同送進 CPU，CPU 再依指令的跳躍位元決定是否改變程式計數器（PC）的內容。

### 各條件的組合方式

有了 `zr` 與 `ng`，我們可以拼出各種比較條件。以下以「比較一個值 v 與 0」及「比較兩個值 x 與 y」為例說明其原理：

| 欲判斷的條件 | 對 ALU 的組合 | 使用的標誌 |
|:-----------|:-------------|:----------|
| x == 0 | 計算 `x`，看 `zr` | zr |
| x < 0 | 計算 `x`，看 `ng` | ng |
| x == y | 計算 `x - y`，看 `zr` | zr |
| x < y | 計算 `x - y`，看 `ng` | ng |
| x > y | 計算 `y - x`，看 `ng`，再取反 | ~ng |
| x ≥ y | 計算 `x - y`，看 `ng`，再取反 | ~ng |

> 這些僅是概念示意。在實際 Hack CPU 中，C-指令的跳躍欄位會直接對應到 zr 與 ng 的各種邏輯組合，例如 `JGT` 即「~zr & ~ng」，`JEQ` 即「zr」，`JLT` 即「ng」。

### 一個具體例子

考慮指令：`if D == 0 goto LOOP`。執行流程：

1. CPU 讓 ALU 計算 `D - 0`（或直接傳遞 D）。
2. ALU 輸出結果與 `zr`、`ng`。
3. 若 `zr = 1`（表示結果為 0），CPU 把 `LOOP` 的位址載入程式計數器 PC。
4. 否則 PC 依序 `+1`，繼續下一條指令。

由此可見，`zr` 與 `ng` 是**硬體判斷的「神經」，讓電腦從「純計算」進化為「有決策能力」**。

## 如何驗證 ALU 的運算

### 驗證策略總覽

由於 ALU 有 6 個控制位元（`zx, nx, zy, ny, f, no`）、兩個 16 位元輸入，理論上輸入組合極其龐大。我們不可能窮舉所有情況，因此驗證需要分層進行：

1. **數學真值驗證**：逐一比對 ALU 的 18 種運算結果與參考計算。
2. **批量隨機測試**：用大量隨機的 x、y 與控制位元組合，交叉驗證每一種運算。
3. **邊界與極端值測試**：測試 0、1、-1、最大正數、最小負數等邊界。
4. **模擬器載入測試檔**：用 Nand2Tetris 提供的硬體模擬器與 .tst 測試腳本自動比對。

### 邊界測試清單

| 測試類別 | 輸入值 | 期望 |
|:--------|:------|:-----|
| 全零 | x=0, y=0 | out=0, zr=1, ng=0 |
| 最大正數 | x=32767 | out 依運算 |
| 最小負數 | x=-32768 | out 依運算，ng=1 |
| 加一溢出 | 32767+1 | -32768（二補數繞回） |
| 減法反轉 | x-y 與 y-x | 互為相反數 |

## 硬體模擬器上測試 ALU

Nand2Tetris 提供圖形化的**硬體模擬器（Hardware Simulator）**，可用 .tst 測試腳本自動驗證晶片。測試腳本法大致如下：

1. **載入晶片**：把 `ALU.hdl` 編譯載入模擬器。
2. **設定輸入**：設定 `x[16]`、`y[16]` 與 6 個控制位元。
3. **讀取並比對輸出**：逐一比對 `out`、`zr`、`ng` 與預期值。

### 一個示意性的測試腳本

以下展示如何在硬體模擬器中測試幾種 ALU 運算（以 .tst 的語法為概念示範）：

```tst
// 概念性測試腳本：測試 ALU 的部分運算
load ALU.hdl,
output-file ALU.out,
compare-to ALU.cmp,
output-list x%B1.16.1 y%B1.16.1 zr%B1.1.1 ng%B1.1.1 out%B1.16.1;

// 測試: out = 0          (zx=1,nx=0,zy=1,ny=0,f=1,no=0)
set x 0, set y 0,
set zx 1, set nx 0, set zy 1, set ny 0, set f 1, set no 0,
eval, output;

// 測試: out = x          (zx=0,nx=0,zy=1,ny=1,f=0,no=0)
set x %B0000000000010101, set y 0,
set zx 0, set nx 0, set zy 1, set ny 1, set f 0, set no 0,
eval, output;

// 測試: out = x+y        (zx=0,nx=0,zy=0,ny=0,f=1,no=0)
set x %B0000000000000111, set y %B0000000000000101,
set zx 0, set nx 0, set zy 0, set ny 0, set f 1, set no 0,
eval, output;
```

> 完整且詳盡的測試檔（如 `ALU.tst`）通常會一列一列地把 18 種運算全部列出，並對照 `.cmp` 檔案中的正確答案。你可以把這些測試當成 ALU 的「規格書」，用來驗證你的實作是否達標。

## 完整 ALU 電路圖與控制位元說明

### 電路資料流總圖

```
        x[16]                     y[16]
          │                         │
   [Mux16: 歸零?] zx        [Mux16: 歸零?] zy
          │                         │
   [Not16]──[Mux16: 取反?] nx   [Not16]──[Mux16: 取反?] ny
          └───────────┬─────────────┘
                      │
   ┌──────────────────┴──────────────────┐
   │        [And16]          [Add16]      │
   │        x&y              x+y          │
   └──────────┬─────────┬────────────────┘
              │  [Mux16: 選 f] (f=0→AND, f=1→+)   │
              └────────────┬──────────────────────┘
                           │
                   [Not16]──[Mux16: 取反 out?] no
                           │
                         out[16]
                           │
        ┌──────────────────┴──────────────┐
   [Or8Way+Or8Way] → Not → zr      direct → ng (=out[15])
```

### 控制位元彙整對照表

| 位元 | 作用對象 | 作用 |
|:----:|:--------|:-----|
| zx | x | 歸零 x（x=0） |
| nx | x | 取反 x（x=~x） |
| zy | y | 歸零 y（y=0） |
| ny | y | 取反 y（y=~y） |
| f | 主結果 | 0=AND，1=加法 |
| no | 最終結果 | 是否取反輸出 |

對應到輸出標誌：

- `zr`：out 全部位元為 0 時為 1（由 OR 濃縮後取反而得）。
- `ng`：直接等於 `out[15]`（最高有效位／符號位）。

## 完成後的 ALU HDL（含標誌位）

將 2.3 節的 ALU 補上 `zr` 與 `ng` 的產生邏輯，即為完整實作：

```hdl
// The ALU (Arithmetic Logic Unit)
CHIP ALU {
    IN
        x[16], y[16],
        zx, nx, zy, ny, f, no;
    OUT
        out[16], zr, ng;

    PARTS:
    // 歸零與取反 x
    Mux16(a=x, b=false, sel=zx, out=x1);
    Not16(in=x1, out=notx);
    Mux16(a=x1, b=notx, sel=nx, out=x2);

    // 歸零與取反 y
    Mux16(a=y, b=false, sel=zy, out=y1);
    Not16(in=y1, out=noty);
    Mux16(a=y1, b=noty, sel=ny, out=y2);

    // 主運算（AND 與 加法 同時預先算出）
    And16(a=x2, b=y2, out=xAndy);
    Add16(a=x2, b=y2, out=xPlusy);
    Mux16(a=xAndy, b=xPlusy, sel=f, out=preOut);

    // 最終取反
    Not16(in=preOut, out=notPreOut);
    Mux16(a=preOut, b=notPreOut, sel=no, out=out);

    // ---- 標誌位產生 ----
    // zr: out 是否為 0（高 8 位 OR、低 8 位 OR，再 OR、取反）
    Or8Way(in=out[0..7],  out=lowOr);
    Or8Way(in=out[8..15], out=highOr);
    Or(a=lowOr, b=highOr, out=anyOne);
    Not(in=anyOne, out=zr);

    // ng: 直接取最高有效位（符號位）
    // 可直接接線: ng = out[15]
    // （在 HDL 中可省略實體、於測試檔觀察 out[15]，或利用內部 bus 接線）
    // 實務上可寫:  A16-bit bus 的一部分即可反映; 此處以邏輯明確呈現
}
```

> 關於 `ng` 的接線：在標準 Nand2Tetris 的 ALU 實作中，`ng` 通常直接來自 `out[15]`（符號位）。某些實作者會為了在 HDL 中「明確」產生一個訊號而寫成 `Mux16(... , out=unused) ; ...` 等技巧，但本質上 `ng = out[15]`，接線也最直接。如果你的模擬器版本在 HDL 中不允許「直接把輸出腳位相連」，可改用內部訊號暫存後再指派。

### 驗證 zr 與 ng 的合理性

以 `out = 0` 為例：16 個位元全為 0 → `lowOr = 0`、`highOr = 0` → `anyOne = 0` → `zr = 1`，且 `out[15]=0 → ng = 0`，正確。

以 `out = -1`（`1111...1111`）為例：任一位元為 1 → `anyOne = 1` → `zr = 0`；且 `out[15]=1 → ng = 1`，正確。

以 `out = 5`（`...0101`）為例：`anyOne = 1 → zr = 0`；`out[15]=0 → ng = 0`，正確。

## 本章小結

- **zr**（結果為零）：由「所有位元之 OR 再取反」產生，只有全零才會為 1。
- **ng**（結果為負）：直接取 **out[15]**（二補數的符號位）。
- **條件跳躍**：CPU 依 `zr`、`ng` 與指令的跳躍欄位，決定是否改變程式計數器 PC，藉此實現「等於、不等於、大於、小於」等控制流程。
- **驗證策略**：以真值表、隨機批量、邊界值與硬體模擬器測試腳本四管齊下，確認 18 種運算與兩枚標誌皆正確。
- 至此，**第二張「運算的核心」（ALU）正式完成**：它涵蓋算術與邏輯運算，並輸出可供條件跳躍的標誌。

有了 ALU，電腦的「運算心臟」已然成形。但 ALU 目前是**組合邏輯**——它沒有記憶。要讓電腦能「記住」運算結果、能依序執行指令，我們還需要**記憶與時間**。這就是第三章「記憶與時間 —— 時序邏輯與記憶體」的主題。
