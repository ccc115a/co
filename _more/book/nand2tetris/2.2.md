# 2.2 增量器與多位元加法器（Inc / Add16）

> 有了半加器與全加器做地基，本節我們要把它們拼成「真正能幹活」的運算單元：一次算 16 個位元的加法器 Add16，以及程式計數器（Program Counter）賴以為生的增量器 Inc16。同時，我們也會重新認識電腦如何用**二補數**來表示負數，讓加法器順理成章地也能做「減法」。

## 前言

在 2.1 節，我們建好了 1 個位元的半加器與全加器。但現實世界的資料是 16 位元的——一個整數需要 16 條線路同時表示。因此，我們需要把全加器「複製」16 份並串接起來，讓它一次處理一整個 16 位元的數字。這便是 **Add16（16 位元加法器）**。

另一方面，程式中有一個極度高頻的運算：「加一」。無論是迴圈的計數、陣列的索引，還是下一條指令的位址，都依賴「加一」這個動作。為此，Nand2Tetris 提供了一個專門的 **Inc16** 晶片：把輸入值加 1。

最後，我們要面對一個關鍵問題：**電腦怎麼表示負數？** 答案是**二補數（Two's Complement）**。只要採用二補數表示法，我們就能用「加法電路」來完成減法——這是一個非常漂亮、幾乎「免費」的設計。

## 多位元加法：從 1-bit 到 16-bit

一個 16 位元數字 `a[16]`，我們可將它視為 16 條平行的輸入線 `a[0]` 到 `a[15]`，其中 `a[0]` 是最低有效位（LSB，最右邊），`a[15]` 是最高有效位（MSB，最左邊）。

把兩個 16 位元數字相加的做法是：**從最低位開始，逐位使用「全加器」，並把低位的 carry 串到高位的 carry-in**。具體接線方式如下：

```
           a15      a14  ...  a1      a0
           b15      b14  ...  b1      b0
            |        |         |       |
        [ FA15 ]  [ FA14 ]  [ FA1 ] [ FA0 ]
            |        |         |       |      ← carry 往高位傳
          sum15    sum14     sum1    sum0
```

- 最低位 FA0 的 carry-in 接 0。
- 每顆全加器 FA_k 的 carry-out 接到 FA_{k+1} 的 carry-in。
- 最後一顆 FA15 的 carry-out，稱為「溢出進位」，通常會被丟棄（或在進位旗標中使用）。

這就是**漣波進位加法器（Ripple-Carry Adder）**。它的缺點是：carry 要一顆顆「漣漪」地傳過去，位元愈多、延遲愈長。但以本課程的教學目的與模擬器環境而言，這種簡單、正確的設計已完全足夠。

## 16 位元加法器：Add16

### 設計思路

Add16 的介面如下：

- 輸入：`a[16]`、`b[16]`。
- 輸出：`out[16]`，且 `out = a + b`（以二補數表示）。

實作方式：串接 16 個全加器。最低位的 carry-in 直接給 0；其餘每個全加器的 carry-in 接上一個的 carry-out。

### Add16 HDL

```hdl
// 16-bit Adder: out = a + b
CHIP Add16 {
    IN a[16], b[16];
    OUT out[16];

    PARTS:
    // 最低位（a[0], b[0]）: 直接使用一個 carry 輸入為 0 的全加器
    FullAdder(a=a[0], b=b[0], c=false, sum=out[0], carry=carry0);

    FullAdder(a=a[1],  b=b[1],  c=carry0, sum=out[1],  carry=carry1);
    FullAdder(a=a[2],  b=b[2],  c=carry1, sum=out[2],  carry=carry2);
    FullAdder(a=a[3],  b=b[3],  c=carry2, sum=out[3],  carry=carry3);
    FullAdder(a=a[4],  b=b[4],  c=carry3, sum=out[4],  carry=carry4);
    FullAdder(a=a[5],  b=b[5],  c=carry4, sum=out[5],  carry=carry5);
    FullAdder(a=a[6],  b=b[6],  c=carry5, sum=out[6],  carry=carry6);
    FullAdder(a=a[7],  b=b[7],  c=carry6, sum=out[7],  carry=carry7);
    FullAdder(a=a[8],  b=b[8],  c=carry7, sum=out[8],  carry=carry8);
    FullAdder(a=a[9],  b=b[9],  c=carry8, sum=out[9],  carry=carry9);
    FullAdder(a=a[10], b=b[10], c=carry9, sum=out[10], carry=carry10);
    FullAdder(a=a[11], b=b[11], c=carry10, sum=out[11], carry=carry11);
    FullAdder(a=a[12], b=b[12], c=carry11, sum=out[12], carry=carry12);
    FullAdder(a=a[13], b=b[13], c=carry12, sum=out[13], carry=carry13);
    FullAdder(a=a[14], b=b[14], c=carry13, sum=out[14], carry=carry14);
    FullAdder(a=a[15], b=b[15], c=carry14, sum=out[15], carry=carry15);
    // 注意: carry15（最後的溢出進位）此處不使用
}
```

> 補充：HDL 中 `false` 表示常數 0，可直接接在輸入腳位；也可使用 `a=a[?]` 的 bus slicing 語法簡化。上面的寫法把每個全加器的 carry 用變數 `carry0...carry15` 明確串接，邏輯清楚、易於除錯。

### 一個範例驗證

```
   a  = 0011 0011 0011 0011   (13107)
   b  = 0000 0000 0000 0101   (     5)
 out  = 0011 0011 0011 1000   (13112)
```

從最低位一路相加，得到完全正確的 `13112`。你可以用硬體模擬器（Hardware Simulator）載入 Add16.hdl 逐一測試不同的輸入組合。

## 進位的傳播（Carry Propagation）

「進位的傳播」指的是 carry 從最低位依序傳到最高位的過程。在漣波進位加法器裡，這是**串列**的行為：第 k 位要能正確相加，必須先等到低位的 carry 傳進來。因此最壞情況下的延遲為：

```
延遲 ≈ 位元數 × 單顆全加器的延遲
```

也就是說，16 位元加法器最壞要等 16 倍的單顆全加器延遲。雖然真實 CPU 會用更快的「前瞻進位加法器（Carry-Lookahead Adder）」來改善，但以教學與正確性而言，漣波架構已是絕佳的起點。

實作上，你可以觀察到一件重要的事：**`out[15]`（最高位的和）與「最後的 carry15」是分開的**。`out[15]` 是加法的最高有效位結果，而 carry15 是「溢位」旗標（overflow）——當兩正數相加結果為負（超出 16 位元範圍）時，這個進位就會「丟失」。這正是二補數溢位的來源。

## 二補數表示法與負數

### 為何需要二補數

硬體只有 0 與 1，沒有「負號」這條線。那麼我們該如何用有限的位元表示正數與負數？最直覺的做法是**用一個位元當符號位**，但這會造成「+0」與「-0」同時存在、且加減法電路變複雜。

**二補數（Two's Complement）** 是現代電腦的標準解法。16 位元二補數的規則非常簡單：

> 一個負數 `-x` 的二補數表示，等於 `x` 的每一位取反後再加 1。

```
-x = (~x) + 1
```

### 二補數的直覺理解

我們想像 16 位元是一個「鐘面」，從 `0000 0000 0000 0000`（0）開始往上數，加一後就依序變成 1、2、3……直到 `0111 1111 1111 1111`（32767，最大的正數）。再往上加一，就「繞回」成 `1000 0000 0000 0000`，也就是 **-32768**（最小的負數）。繼續加，會依序變成 -32767、-32766……直到 `1111 1111 1111 1111`（-1），再加一又繞回 0。

這個「鐘面」式的循環結構，正是二補數的精髓：

```
 0000 ... 0000      =  0
 0000 ... 0001      =  1
 ...
 0111 ... 1111      =  32767      (最大正數)
 1000 ... 0000      = -32768      (最小負數)
 ...
 1111 ... 1110      = -2
 1111 ... 1111      = -1
```

### 驗證：為甚麼二補數能讓「加減合一」

我們來驗證 `5 + (-3) = 2` 是否真的能用同一個加法器完成：

- 5 的二補數：`0000 0000 0000 0101`
- -3 的二補數：`~3 + 1 = 1111 1111 1111 1100 + 1 = 1111 1111 1111 1101`

把兩者用 Add16 相加：

```
   0000 0000 0000 0101   ( 5)
 + 1111 1111 1111 1101   (-3)
 ----------------------
 1 0000 0000 0000 0010   去掉溢位 carry
   0000 0000 0000 0010   ( 2)  ✓ 正確!
```

溢位出來的「1」被丟棄，剩下的 `...0010 = 2` 完全正確。這證明了：**只要以二補數表示，減法 `x - y` 就等價於加法 `x + (~y + 1)`，不需要額外的減法電路**。這也為我們在本章稍後設計 ALU 的 `x-y` 運算埋下伏筆。

## 增量器：Inc16

### 設計思路

**Inc16（增量器）** 的介面：

- 輸入：`in[16]`。
- 輸出：`out[16]`，且 `out = in + 1`。

它本質上就是一個「把 b 固定為 1」的 16 位元加法器。我們有兩種直覺的實作方式：

1. **概念上的做法**：把 `in` 與常數 1 丟進 Add16。但我們並未假設有 Add16 內的 b 值固定能力，讓它去加「常數 1」是合理的。
2. **優化做法**：既然只要加 1，最低位用半加器（加 1 對最低位），其餘位用全加器串接 carry。這樣更省電路。

### 使用 Add16 的直覺版（僅供理解）

```hdl
// 概念示意: out = in + 1 （利用 Add16 加上常數 1）
// 注意: Nand2Tetris 的標準作法並非直接呼叫 Add16，而是自行串接全加器。
// 以下僅為概念展示，方便理解「加一就是加法特例」。
```

### Inc16 標準 HDL（自行串接全加器）

```hdl
// 16-bit Incrementer: out = in + 1
CHIP Inc16 {
    IN in[16];
    OUT out[16];

    PARTS:
    // 最低位: in+1, 用半加器處理（carry-in 為 0，只需處理 in[0] 與常數 1）
    HalfAdder(a=in[0], b=true, sum=out[0], carry=carry0);

    FullAdder(a=in[1],  b=false, c=carry0, sum=out[1],  carry=carry1);
    FullAdder(a=in[2],  b=false, c=carry1, sum=out[2],  carry=carry2);
    FullAdder(a=in[3],  b=false, c=carry2, sum=out[3],  carry=carry3);
    FullAdder(a=in[4],  b=false, c=carry3, sum=out[4],  carry=carry4);
    FullAdder(a=in[5],  b=false, c=carry4, sum=out[5],  carry=carry5);
    FullAdder(a=in[6],  b=false, c=carry5, sum=out[6],  carry=carry6);
    FullAdder(a=in[7],  b=false, c=carry6, sum=out[7],  carry=carry7);
    FullAdder(a=in[8],  b=false, c=carry7, sum=out[8],  carry=carry8);
    FullAdder(a=in[9],  b=false, c=carry8, sum=out[9],  carry=carry9);
    FullAdder(a=in[10], b=false, c=carry9, sum=out[10], carry=carry10);
    FullAdder(a=in[11], b=false, c=carry10, sum=out[11], carry=carry11);
    FullAdder(a=in[12], b=false, c=carry11, sum=out[12], carry=carry12);
    FullAdder(a=in[13], b=false, c=carry12, sum=out[13], carry=carry13);
    FullAdder(a=in[14], b=false, c=carry13, sum=out[14], carry=carry14);
    FullAdder(a=in[15], b=false, c=carry14, sum=out[15], carry=carry15);
    // carry15（溢出進位）此處不使用
}
```

說明：因為除了最低位外，其餘每一位都只是「把 `in[k]` 加上來自低位的進位」，所以 `b` 恆為 0（`false`），僅最低位 `in[0]` 要加常數 1（`true`）。這樣極省電路資源。

### Inc16 的應用

Inc16 看起來微不足道，卻是**程式計數器（Program Counter, PC）**的核心零件：電腦執行完一條指令後，程式計數器通常要「加一」以指向下一條指令位址。我們會在第三章深入探討。

## 本章小結

- **Add16**：串接 16 個全加器，最低位 carry-in = 0，形成漣波進位加法器，一次計算 `a + b`。
- **進位的傳播**：carry 由低位往高位串列傳遞，是漣波加法器的主要延遲來源。
- **Inc16**：只是「加 1」的特例，最低位用半加器、其餘位用全加器即可，是 PC 的核心零件。
- **二補數**：`-x = (~x) + 1`，讓「減法 = 加法」成立，不需額外減法電路，是 ALU 設計的關鍵基礎。
