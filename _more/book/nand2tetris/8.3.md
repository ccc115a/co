# 8.3 呼叫堆疊（Call Stack）與區域變數維護

## 學習目標

讀完本節後，你應該能：

- 說明 frame 的概念，以及 `LCL / ARG / THIS / THAT / retAddr` 五個 frame 元素的意義
- 說明呼叫堆疊（call stack）是「如何被 push 的佇列」與「如何被 pop 的佇列」
- 追蹤一次呼叫、多次嵌套呼叫時，堆疊與各暫存器的推移
- 說明 return 時如何搬移回傳值並還原 SP
- 說明區域變數（local）如何被分配、使用與回收

---

## 前言

8.2 節把 `call` / `function` / `return` 的個別翻譯講完了。但那三條指令**必須連在一起**才能成立——它們共享同一個舞台：**呼叫堆疊（call stack）**。

本節換一個視角：不再看「單一指令怎麼翻譯」，而是**把整個記憶體當作電影膠捲，一格一格放給你看**。當你看到 `main` 呼叫 `foo`、`foo` 又呼叫 `bar`，然後 `bar` 返回、`foo` 返回、最後 `main` 返回，記憶體裡的 frame 如何一層層疊上去、又一層層拆下來，你就真正理解 VM 了。

一切的基礎，是「**frame**」這個概念。

---

## 1. frame：一個函式呼叫的「完整狀態」

每一個「正在執行的函式呼叫」，在堆疊上都佔有一塊連續的記憶體，叫做一個 **frame**。frame 記錄了「執行這個函式所需的一切」：參數、區域變數、以及回到 caller 需要的五個元素。

### 1.1 frame 的五大元素

Nand2Tetris 的 frame 結構，從「呼叫時壓入堆疊的順序」可以倒推出來。回想 8.2 節 `call foo 2` 壓入的內容（從上往下是「越晚壓入越高位址」）：

```
高位址 ┌──────────────────────────────┐
       │  （被呼叫函式的工作區）          │
       │  local 2                      │  ← 區域變數往上長
       │  local 1                      │
       │  local 0                      │
       ├──────────────────────────────┤
       │  THAT   ← frame-1             │
       │  THIS   ← frame-2             │
       │  ARG    ← frame-3             │
       │  LCL    ← frame-4             │
       │  retAddr← frame-5             │  ← frame = LCL（被呼叫者的 LCL）
       ├──────────────────────────────┤
       │  參數 1                        │
       │  參數 0   ← ARG（指向第一個參數）│
低位址 └──────────────────────────────┘
```

以「被呼叫者的 LCL」為 frame 的錨點（`frame = LCL`），五個元素的位置是：

| 元素 | 存放位置 | 意義 |
|------|----------|------|
| **retAddr** | `frame - 5` | 返回位址（call 後下一條指令） |
| **LCL** | `frame - 4` | 呼叫前的 LCL |
| **ARG** | `frame - 3` | 呼叫前的 ARG |
| **THIS** | `frame - 2` | 呼叫前的 THIS |
| **THAT** | `frame - 1` | 呼叫前的 THAT |

> **設計思路**：這五個元素是「return 要還原的就這些」。你把 `return` 的 Hack 翻譯對照一下——它正是依序從 `frame-1..5` 讀回 THAT、THIS、ARG、LCL、retAddr。所以 frame 的佈局不是隨便畫的，**它是 `return` 指令的「劇本」**。

### 1.2 frame 為什麼重要

frame 讓不同的函式呼叫**各自擁有獨立的區域變數與參數空間**，彼此不干擾。`foo` 改了它的 local 1，絕對不會影響 `main` 的 local 1，因為它們住在堆疊的不同高度。這就是「區域變數（local）」能夠「區域」的真正原因——**它只是 frame 內的一段記憶體**。

## 2. 呼叫堆疊的運作

### 2.1 一體兩面的記憶體

關鍵心法：**SP（RAM[0]）以上的所有記憶體，永遠只有兩種身分——「尚未被使用」或「屬於某個 frame」**。而 ARG/LCL/THIS/THAT 這四個暫存器，就像四個游標，把「當前 frame」切出來給你用。

呼叫堆疊的本質：

- **call 一個新函式** = 把新 frame 的參數、五元素連續 push 到堆疊頂（堆疊往高處長）；
- **return** = 把目前 frame 整個「丟掉」，SP 退回 caller 的位置（堆疊往低處縮）。

這是一條「後進先出」（LIFO）的佇列——正是「堆疊（stack）」一詞的由來。

### 2.2 用一條時間線展示

假設 `main` 呼叫 `foo(7, 42)`，而 `foo` 內部又呼叫 `bar(1)`。我們用「堆疊高度（SP 數值）」與「四個指標的位置」來畫出演進：

**時間點 A：`main` 正要 `call foo 2`**

```
堆疊：... | 7 | 42 | ↑
               ARG?   SP
（SP 原本在某個高度 N；7、42 是兩個參數）
```

**時間點 B：執行完 `call foo 2`，進入 foo 的 `function foo 0`**

```
高位址 │                    │
      │ THAT (old main)     │
      │ THIS (old main)     │
      │ ARG  (old main)     │
      │ LCL  (old main)     │
      │ retAddr (回 main)   │
      │ 7  ← ARG            │
      │ 42                   │
      │ ...（main 的 frame）  │
      SP = LCL（foo 的 frame 起點）
```

foo 從自己的 frame 起點開始運作，local 從 SP/LCL 往上推。

**時間點 C：foo 又執行 `push constant 1; call bar 1`**（`call bar` 已壓入五元素並設好 bar 的 ARG/LCL）

```
高位址 │（bar 的工作區）        │
      │ THAT (old foo)        │
      │ THIS (old foo)        │
      │ ARG  (old foo)        │
      │ LCL  (old foo)        │
      │ retAddr (回 foo)      │
      │ 1  ← ARG（bar 的參數） │
      │ （foo 的 local...）     │
      │ THAT/THIS/ARG/LCL/ret ←（foo 的 frame 五元素）
      │ 7  ← ARG（foo 的參數） │
      │ 42                    │
      │ ...（main 的 frame）    │
```

此時兩個 frame（main 的、foo 的）與正在形成的第三個（bar）都堆在同一塊記憶體上。**return 是 pop 的逆運算**：`bar` return 後，那些 `1 / THAT / THIS / ARG / LCL / retAddr` 全部「被遺忘」，SP 回到 foo 的 frame，foo 從 retAddr 繼續。

> **設計思路**：注意「被遺忘」不是「被清理成 0」。return 只是把 SP 縮回去，舊資料還留在原地，只是不再被參照。這正是堆疊高效的地方——**回收一個 frame 的開銷是 O(1)**，SP 一指就完成了。

## 3. 五個 frame 元素的保存與還原

把「保存」與「還原」這兩組動作對照，是理解整套機制的最佳方式。

### 3.1 保存（call 時）

| 順序 | 動作 |
|------|------|
| 1 | push `retAddr`（call 後下一條指令位址） |
| 2 | push 目前的 `LCL` |
| 3 | push 目前的 `ARG` |
| 4 | push 目前的 `THIS` |
| 5 | push 目前的 `THAT` |
| 6 | `ARG = SP - 5 - nArgs`（指向第一個參數） |
| 7 | `LCL = SP`（frame 起點） |
| 8 | `goto` 被呼叫函式 |

### 3.2 還原（return 時，依相反順序）

| 順序 | 動作 |
|------|------|
| 1 | `R13 = LCL`（保存 frame 錨點） |
| 2 | `R14 = *(R13 - 5)`（取出 retAddr） |
| 3 | `*ARG = pop()`（回傳值搬到 ARG 所指，取代第一個參數） |
| 4 | `SP = ARG + 1`（把 SP 設回 caller 的「回傳值之後」） |
| 5 | `THAT = *(R13 - 1)` |
| 6 | `THIS = *(R13 - 2)` |
| 7 | `ARG = *(R13 - 3)` |
| 8 | `LCL = *(R13 - 4)` |
| 9 | `goto R14`（回到 caller 的返回位址） |

對照著看：**保存時「LCL→ARG→THIS→THAT→retAddr」的 push 順序，正好是還原時「THAT→THIS→ARG→LCL→retAddr」的讀回順序的倒影**。因為越晚 push（越高位址）的元素，return 時要先處理——就像疊盤子，後放的要先拿。

> **設計思路**：這不是巧合。VM 規格刻意讓 caller 的五元素「以固定偏移躺在 frame 尾部」，return 就能用「固定偏移」（frame-1 到 frame-5）把它們一次讀回，不必記錄「我當初是不是改了暫存器」。這種「儲存-還原」的固定契約，讓 call/return 可以無限嵌套而永不亂套。

### 3.3 return 如何搬移回傳值並還原 SP

這是 return 最精巧的兩步，特別標出來：

1. **搬移回傳值**：被呼叫函式把回傳值留在堆疊頂（`RAM[SP-1]`）。return 不把這個值還原掉，而是**搬到 `ARG`（caller 的第一個參數位置）**，等於「用回傳值覆寫掉第一個參數」——這樣 caller 在 `call` 之後 stack 頂端自然就是回傳值，可以直接取用。
2. **還原 SP**：`SP = ARG + 1`。因為回傳值現在住在 `ARG`，所以 SP 設為 `ARG+1`，讓 caller 一回來就看到「堆疊頂是回傳值」。

```asm
@SP
AM=M-1
D=M
@ARG
A=M
M=D       // *ARG = pop()：回傳值放到 caller 的 ARG
@ARG
D=M+1
@SP
M=D       // SP = ARG + 1
```

## 4. 多次嵌套呼叫的堆疊視覺化

把 2.2 節的觀察，用一張「完整旅程」圖呈現——`main → foo → bar → 返回 foo → 返回 main`：

```
SP的高度（示意）
  │
  │  ┌─────────┐   ┌─────────┐   ┌─────────┐
  │  │main frame│   │foo frame│   │bar frame│
  │  │  ...     │   │ local   │   │ local   │
  │  │          │   │ THAT    │   │ THAT    │
  │  │          │   │ THIS    │   │ THIS    │
  │  │          │   │ ARG     │   │ ARG     │
  │  │          │   │ LCL     │   │ LCL     │
  │  │          │   │ retAddr │   │ retAddr │
  │  │          │   │ 參數7,42│   │ 參數1    │
  │  └─────────┘   └─────────┘   └─────────┘
  └──────────────────────────────────────────→ 時間
     call foo          call bar     bar return  foo return
```

步驟拆解：

1. `main call foo` → 在 main frame 頂上疊起 foo frame；
2. `foo call bar` → 在 foo frame 頂上疊起 bar frame；
3. `bar return` → 拆掉 bar frame，SP 縮回，foo 從 retAddr 繼續；
4. `foo return` → 拆掉 foo frame，SP 縮回，main 從 retAddr 繼續。

每個 frame 的生命週期都是「push 上去、執行、pop 下來」——**先被 call 的 frame 反而最後才 return**，完全符合 LIFO。

### 4.1 迴圈與遞迴

如果 `bar` 呼叫的對象是它自己，就形成**遞迴**。遞迴並不需要任何新機制——每次自呼都只是「再疊一個相同結構的 frame」，只是參數不同、local 不同。這解釋了為何遞迴「還行但不會爆」：每次呼叫都耗掉一段堆疊，無限遞迴終將把 SP 推到記憶體頂端，溢出。

## 5. 區域變數的維護

### 5.1 分配（function 時）

`function foo 3` 把三個 0 推上堆疊，frame 起點（LCL）往上長出 3 個 local。之後「local 段」就是 `LCL` 往上的連續記憶體，第 i 個 local 在 `RAM[LCL+i]`。

### 5.2 存取（pop local i / push local i）

第 7 章已學過記憶體段翻譯，這裡回顧並強調「local 恰好是 frame 的一部分」：

```asm
// push local 2：把 RAM[LCL+2] 的值推上堆疊
@LCL
D=M
@2
A=D+A
D=M
@SP
A=M
M=D
@SP
M=M+1
```

```asm
// pop local 2：從堆疊彈出，寫入 RAM[LCL+2]
@LCL
D=M
@2
D=D+A
@R13
M=D          // R13 = LCL + 2（先算目標位址）
@SP
AM=M-1
D=M
@R13
A=M
M=D
```

### 5.3 回收（return 時）

區域變數**不需要**逐一清除。`return` 只管把 SP 縮回 `ARG+1`，那些 local 就「超出 SP」而自動變成可被未來 frame 覆蓋的空間。**local 的生命週期 = frame 的生命週期**，這是堆疊式的區域變數與「堆積（heap）」式動態記憶體最大的不同。

> **設計思路**：正因為 local 的回收是「免費的」（return 順手把 SP 縮回去就完成了），所以區域變數才能如此廉價地「誕生與消滅」。對比第 12 章的 Memory.alloc（堆積管理），這正是堆疊與堆積的本質差別。

## 6. 設計思路與實作步驟

實作時，最容易出錯的三個地方對應「三張檢查清單」:

1. **call 的 ARG**：`ARG = SP - 5 - nArgs`，務必確認減法順序與參數數量；
2. **return 的回傳值**：在「重新設定 SP」**之前**先搬移回傳值，不然會搬錯位置；
3. **五元素的還原順序**：THAT→THIS→ARG→LCL（由上往下），retAddr 最後拿來跳。

第 8.4 節的完整 Translator 會把這些落成程式。此處先總結成「驗證口訣」：

- `call` 之後：`SP` 比 `LCL` 高（新 frame 已在堆疊上）；
- 函式執行中：`ARG <= 參數 < SP <= LCL`；
- `return` 之後：堆疊頂是回傳值，`SP` 精準停在 `ARG+1`。

---

## 7. 本章小結

- **frame** 是單一函式呼叫的完整狀態，錨點是 `LCL`。
- 五個 frame 元素：`retAddr(LCL-5)、LCL(LCL-4)、ARG(LCL-3)、THIS(LCL-2)、THAT(LCL-1)`，是 return 的還原劇本。
- 呼叫堆疊是 LIFO：`call` 把新 frame push 到頂，`return` 把 frame pop 掉，SP 一指完成回收（O(1)）。
- `return` 把回傳值搬到 `*ARG` 並設 `SP = ARG + 1`，讓 caller 一回來堆疊頂就是回傳值。
- 保存五元素（call）與還原五元素（return）是互為倒影的固定契約，因而可無限嵌套、永不亂套。
- 區域變數是 frame 內的一段記憶體，分配靠 `function` 推 0，回收靠 `return` 縮 SP——生命週期與 frame 完全同步。
