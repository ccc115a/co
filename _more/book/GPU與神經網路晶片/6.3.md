# 6.3 稀疏性（Sparsity）加速：NVIDIA 2:4 稀疏架構與硬體解碼器

## 稀疏性的基礎

### 什麼是稀疏性

```
稀疏性定義：
┌─────────────────────────────────────────────────┐
│  稀疏性 = 1 -（非零值數量 / 總元素數量）        │
│                                                  │
│  範例：                                          │
│  稠密矩陣（稀疏性 0%）：                         │
│  [1.5  0.8  2.1  0.3]                           │
│  [0.9  1.2  0.4  1.7]                           │
│                                                  │
│  稀疏矩陣（稀疏性 50%）：                        │
│  [1.5   0   2.1   0]                            │
│  [ 0   1.2   0   1.7]                           │
│                                                  │
│  高度稀疏矩陣（稀疏性 90%+）：                   │
│  [1.5   0    0    0]                            │
│  [ 0    0    0   1.7]                           │
└─────────────────────────────────────────────────┘
```

### 神經網路中的稀疏性

```
神經網路稀疏性來源：
┌─────────────────────────────────────────────────┐
│  1. 活化函數稀疏性                              │
│     ReLU(x) = max(0, x)                        │
│     - 負值輸出為 0                              │
│     - 產生活化稀疏性                           │
│                                                  │
│  2. 權重稀疏性                                  │
│     - 剪枝（Pruning）移除小權重                │
│     - 產生結構化稀疏                            │
│                                                  │
│  3. 梯度稀疏性                                  │
│     - 訓練過程中部分梯度接近 0                 │
│     - 可跳過更新                               │
│                                                  │
│  稀疏性帶來的好處：                              │
│  - 跳過零值運算→ 效能提升                     │
│  - 減少記憶體儲存 → 記憶體節省                │
│  - 減少功耗                                   │
└─────────────────────────────────────────────────┘
```

## NVIDIA 2:4 結構化稀疏

### 2:4 稀疏定義

```
2:4 結構化稀疏：
┌─────────────────────────────────────────────────┐
│  定義：                                          │
│  在每 4 個連續元素中，至多保留 2 個非零值       │
│                                                  │
│  ┌────┬────┬────┬────┐                          │
│  │ 1.0│ 0  │0.5 │ 0  │  → 2:4 稀疏（符合）    │
│  └────┴────┴────┴────┘                          │
│                                                  │
│  ┌────┬────┬────┬────┐                          │
│  │ 1.0│0.8 │0.5 │ 0  │  → 3:4 稀疏（不符合）  │
│  └────┴────┴────┴────┘                          │
│                                                  │
│  特性：                                          │
│  - 稀疏度固定：50%                              │
│  - 規則模式：易於硬體實現                      │
│  - 可預測的控制邏輯                            │
└─────────────────────────────────────────────────┘
```

### 為什麼選擇 2:4

```
2:4 稀疏的選擇理由：
┌─────────────────────────────────────────────────┐
│  1. 精簡的索引                                  │
│     - 2 個非零值/4 元素                         │
│     - 需 2 bits 標記位置（4 種組合）           │
│                                                  │
│  2. 硬體友好                                    │
│     - 規則的模式                              │
│     - 簡單的解碼邏輯                           │
│     - 可預測的負載                            │
│                                                  │
│  3. 精度保留                                    │
│     - 研究表明相較非結構化稀疏                 │
│     - 2:4 稀疏在相同稀疏度下                  │
│     - 精度損失可接受                           │
│                                                  │
│  4. 訓練可行性                                  │
│     - 可從稠密模型轉換                        │
│     - 透過剪枝達成                            │
└─────────────────────────────────────────────────┘
```

## 2:4 稀疏硬體架構

### 稀疏矩陣乘法的挑戰

```
稀疏矩陣乘法的硬體挑戰：
┌─────────────────────────────────────────────────┐
│  問題：                                          │
│  稠密乘法：固定位置，規則資料流                  │
│  稀疏乘法：位置可變，需動態解碼                │
│                                                  │
│  挑戰：                                          │
│  1. 收集非零值                                 │
│  2. 分配資料到正確的 PE                        │
│  3. 同步不同資料的時序                        │
│  4. 平衡 PE 間的負載                          │
└─────────────────────────────────────────────────┘
```

### 2:4 稀疏解碼器

```
2:4 稀疏解碼器：
┌─────────────────────────────────────────────────┐
│  輸入：                                          │
│  ┌────╥────╥────╥────┐                         │
│  │d(2b)│d(2b)│d(2b)│d(2b)│  非零值資料       │
│  └────╨────╨────╨────┘                         │
│  ┌────────────────────┐                         │
│  │    2-bit 索引     │                         │
│  │  標記非零位置     │                         │
│  └────────────────────┘                         │
│                                                 │
│  解碼器功能：                                    │
│  ┌──────────────────────────────────────────┐   │
│  │  1. 解析 2-bit 索引                      │   │
│  │     → 確定非零值的位置                   │   │
│  │                                          │   │
│  │  2. 建立路由表                          │   │
│  │     → 決定資料送往哪個 PE                │   │
│  │                                          │   │
│  │  3. 產生控制信號                        │   │
│  │     → 控制乘法器啟用/停用               │   │
│  │                                          │   │
│  │  4. 累加器操作                          │   │
│  │     → 在正確位置累加結果                │   │
│  └──────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

## 稀疏矩陣乘法演算法

### 降低維度

```
2:4 稀疏乘法 → 降低維度：
┌─────────────────────────────────────────────────┐
│  稠密乘法：                                      │
│  C[M][N] = Σ A[M][K] × B[K][N]                 │
│  計算量：2×M×N×K                               │
│                                                  │
│  稀疏乘法（稀疏度 s）：                          │
│  只有 50% 的乘法需要執行                       │
│  計算量：2×M×N×K×0.5                          │
│                                                  │
│  等效做法：                                      │
│  將 A 稀疏壓縮為 A'（M×(K/2)）                │
│  將 B 稀疏壓縮為 B'（(K/2)×N）                │
│  C = A' × B'（稠密乘法）                       │
│                                                  │
│  好處：                                          │
│  - 使用標準的張量核心                        │
│  - 無需修改乘法核心                          │
│  - 只需解碼器將稀疏轉為稠密                  │
└─────────────────────────────────────────────────┘
```

## 效能分析

### 稀疏加速效益

```
稀疏加速成效：
┌─────────────────────────────────────────────────┐
│  NVIDIA A100（Ampere）：                          │
│  - 稠密 FP16：312 TFLOPS                       │
│  - 稀疏 FP16：624 TFLOPS（2 倍）               │
│                                                  │
│  NVIDIA H100（Hopper）：                         │
│  - 稠密 FP16：1,979 TFLOPS                     │
│  - 稀疏 FP16：3,958 TFLOPS（2 倍）             │
│                                                  │
│  實際工作負載：                                  │
│  - 若模型稀疏度達 50%：                        │
│    理論加速 2 倍                                │
│  - 若模型稀疏度僅 20%：                        │
│    實際加速 <2 倍（控制開銷）                 │
└─────────────────────────────────────────────────┘
```

### 利用率控制

```
稀疏利用率的影響因素：
┌─────────────────────────────────────────────────┐
│  1. 稀疏度                                      │
│     - 必須至少 50%（2:4）                      │
│     - 若小於 50%，浪費硬體                    │
│                                                  │
│  2. 負載均衡                                   │
│     - 每個 PE 的稀疏模式不同                  │
│     - 可能產生不平衡                          │
│                                                  │
│  3. 資料對齊                                   │
│     - 稀疏資料需正確對齊                      │
│     - 需要額外的索引資訊                      │
│                                                  │
│  實際達成：                                      │
│  - 理論峰值：2 倍                              │
│  - 實際：1.5-1.9 倍（依模型）                  │
└─────────────────────────────────────────────────┘
```

## 剪枝與訓練

### 達成 2:4 稀疏的方法

```
2:4 稀疏達成步驟：
┌─────────────────────────────────────────────────┐
│  方法 1：訓練後剪枝                             │
│  1. 訓練稠密模型                                │
│  2. 移除小權重（每 4 個移除 2 個）             │
│  3. 微調恢復精度                                │
│                                                  │
│  方法 2：訓練時剪枝                             │
│  1. 訓練時加入稀疏約束                         │
│  2. 使用遮罩強制 2:4 模式                      │
│  3. 保持稀疏度直到收斂                         │
│                                                  │
│  方法 3：重新結構化                              │
│  1. 重新排列權重                                │
│  2. 使符合 2:4 模式                           │
│  3. 微調                                       │
└─────────────────────────────────────────────────┘
```

### 和其他稀疏硬體比較

```
其他稀疏硬體方案：
┌─────────────────────────────────────────────────┐
│  1. NVIDIA 2:4 稀疏                             │
│     - 規則、高利用率                          │
│     - 固定 50% 稀疏度                          │
│                                                  │
│  2. 非結構化稀疏（如 Groq）                     │
│     - 任意稀疏模式                              │
│     - 需要動態收集非零值                       │
│     - 利用率較低但更靈活                      │
│                                                  │
│  3. 塊稀疏（Block Sparsity）                    │
│     - 以塊為單位稀疏                          │
│     - 減少索引開銷                              │
│     - 彈性較高                                  │
└─────────────────────────────────────────────────┘
```

## 本章小結

- 稀疏性可透過跳過零值運算提升效能
- NVIDIA 2:4 稀疏每 4 元素保留 2 個，稀疏度固定 50%
- 需要硬體解碼器解析索引並路由資料
- 稀疏權重儲存可節省 50% 記憶體
- 稀疏 Tensor Core 可提供 2 倍效能提升
- 剪枝與微調是達成 2:4 稀疏的主要方法
