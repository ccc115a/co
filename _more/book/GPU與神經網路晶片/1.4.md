# 1.4 計算密度（FLOPs）、記憶體頻寬（BW）與算力利用率（MFU）

## 計算密度（FLOPs）

### FLOPs 的定義

FLOPs（Floating-Point Operations）是衡量計算量的基本單位，表示浮點運算的次數。常見的衍生單位：

| 單位 | 說明 | 數值 |
|------|------|------|
| FLOP | 單次浮點運算 | 1 |
| KFLOPS | 千次浮點運算 | 10³ |
| MFLOPS | 百萬次浮點運算 | 10⁶ |
| GFLOPS | 十億次浮點運算 | 10⁹ |
| TFLOPS | 兆次浮點運算 | 10¹² |
| PFLOPS | 千兆次浮點運算 | 10¹⁵ |
| EFLOPS | 百京次浮點運算 | 10¹⁸ |

### 矩陣乘法的計算量

對於矩陣乘法 C = A × B，其中 A 為 m×k 矩陣，B 為 k×n 矩陣：

```
計算量 = 2 × m × n × k FLOPs

範例：
- A: 1024×1024, B: 1024×1024
- 計算量 = 2 × 1024³ ≈ 2.1 GFLOPS
```

### 不同精度格式的計算量

| 精度格式 | 位元數 | 每次運算的 FLOPs |
|----------|--------|-----------------|
| FP64 | 64 | 1 |
| FP32 | 32 | 1 |
| FP16/BF16 | 16 | 1 |
| TF32 | 19 | 1 |
| FP8 | 8 | 1 |
| INT8 | 8 | 1 |
| INT4 | 4 | 1 |

某些硬體支援向量化運算，可在單一時脈週期內執行多個運算：

```
FP16 Tensor Core：
- 每個 SM 每時脈可執行 64 個 FP16 乘加運算
- 等效於 128 FLOPs/SM/時脈
```

## 記憶體頻寬（Bandwidth）

### 頻寬的定義

記憶體頻寬（Bandwidth, BW）表示單位時間內可傳輸的資料量：

```
頻寬 = 資料量 / 時間
單位：Bytes/sec 或 bits/sec
```

### 不同記憶體技術的頻寬

| 記憶體類型 | 頻寬 | 延遲 | 應用場景 |
|------------|------|------|----------|
| DDR4-3200 | 25.6 GB/s | ~50 ns | 一般電腦 |
| DDR5-4800 | 38.4 GB/s | ~40 ns | 新一代電腦 |
| GDDR6 | 192-384 GB/s | ~20 ns | 遊戲 GPU |
| GDDR6X | 500-1000 GB/s | ~15 ns | 高端 GPU |
| HBM2e | 400-600 GB/s | ~30 ns | AI 加速器 |
| HBM3 | 800-1200 GB/s | ~25 ns | 新一代 AI 晶片 |

### 頻寬的計算範例

假設使用 HBM3 記憶體：
```
HBM3 頻寬：1 TB/s = 1000 GB/s
FP32 資料大小：4 bytes

每秒可載入的 FP32 元素數 = 1000 GB/s / 4 bytes = 250 G 元素/秒
```

## 算力利用率（MFU）

### MFU 的定義

MFU（Model FLOPs Utilization）或 AHU（Arithmetic Hardware Utilization）是衡量硬體算力實際使用效率的指標：

```
MFU = 實際運算量 / 理論峰值運算量 × 100%
```

### 影響 MFU 的因素

1. **記憶體瓶頸**：當運算受限於記憶體頻寬時，無法充分利用計算單元
2. **負載不均衡**：平行運算中，部分核心閒置等待其他核心完成
3. **控制開銷**：指令解碼、分支預測等控制邏輯消耗的週期
4. **資料搬運**：資料在記憶體層級間搬運的時間
5. **同步開銷**：執行緒或核心間同步的等待時間

### 不同運算的 MFU 範例

```
矩陣乘法（大矩陣）：
- 理論峰值：312 TFLOPS（H100 FP16 Tensor Core）
- 實際效能：~150-200 TFLOPS
- MFU：~50-65%

逐元素運算：
- 理論峰值：312 TFLOPS
- 實際效能：~10-50 TFLOPS
- MFU：~3-15%

記憶體受限運算（如向量加法）：
- 理論峰值：312 TFLOPS
- 實際效能：~5-10 TFLOPS
- MFU：~2-3%
```

## Roof-Model 分析

Roof-Model 是分析程式瓶頸的視覺化工具，用於判斷運算是「計算受限」（Compute-Bound）或「記憶體受限」（Memory-Bound）。

### Roof-Line 模型

```
效能 (FLOPS)
    │
    │         ┌──────────────── 計算受限（Compute-Bound）
    │        /
    │       /
    │      /
    │     /
    │    /
    │   /
    │  /
    │ / 記憶體受限（Memory-Bound）
    │/    /
    └────────────────────────
         運算密度 (FLOPS/Byte)
```

### 瓶頸判定公式

```
 attainable_FLOPS = min(Peak_FLOPS, Peak_BW × Arithmetic_Intensity)

其中：
- Arithmetic_Intensity = FLOPs / Bytes
- Peak_FLOPS：硬體峰值運算效能
- Peak_BW：記憶體峰值頻寬
```

### 範例分析

以 NVIDIA A100 為例：
```
峰值效能：312 TFLOPS（FP16 Tensor Core）
峰值頻寬：2 TB/s（HBM2e）

運算密度臨界值 = 312 TFLOPS / 2 TB/s = 156 FLOPS/Byte

- 若程式運算密度 > 156 FLOPS/Byte：計算受限
- 若程式運算密度 < 156 FLOPS/Byte：記憶體受限
```

## 優化策略

### 1. 提升運算密度

- **算子融合（Operator Fusion）**：將多個運算合併，減少記憶體存取
- **暫存器重用**：將常用資料保存於暫存器中
- **共享記憶體**：利用共享記憶體進行區塊資料重用

### 2. 提升記憶體效率

- **記憶體連鎖**：合併相鄰記憶體存取
- **向量化存取**：使用 128-bit 或 256-bit 向量存取
- **預取**：提前載入所需資料

### 3. 減少控制開銷

- ** warp 調度**：優化執行緒排程以提升佔用率
- **指令級平行（ILP）**：重疊獨立指令的執行

## 本章小結

- FLOPs 是衡量計算量的基本單位，矩陣乘法的計算量與矩陣大小的立方成正比
- 記憶體頻寬決定資料搬運的速率，是記憶體受限運算的瓶頸
- MFU 衡量硬體算力的實際使用效率，通常在 30-70% 之間
- Roof-Model 可用於判斷運算是計算受限或記憶體受限
- 優化策略應針對瓶頸類型選擇（提升運算密度或記憶體效率）
