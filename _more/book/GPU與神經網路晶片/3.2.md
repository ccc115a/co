# 3.2 執行緒調度與資源分配：Warp Scheduling 與 Occupancy 優化

## Warp 調度基礎

### Warp 的定義與結構

Warp 是 GPU 執行的基本單位，由 32 個連續的執行緒組成：

```
Warp 結構：
┌─────────────────────────────────────────────────┐
│                    Warp (32 Threads)            │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐        │
│  │ T0  │ T1  │ T2  │ T3  │ ... │ T31 │        │
│  └──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┘        │
│     │     │     │     │     │     │            │
│     ↓     ↓     ↓     ↓     ↓     ↓            │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐        │
│  │PC0  │PC1  │PC2  │PC3  │...  │PC31 │        │
│  └─────┴─────┴─────┴─────┴─────┴─────┘        │
│                                                  │
│  特性：                                          │
│  - 所有執行緒共享同一程式計數器（PC）            │
│  - 同一時脈週期執行相同指令                     │
│  - 資料位址可不同（SIMT 模型）                  │
└─────────────────────────────────────────────────┘
```

### Warp 調度器（Warp Scheduler）

每個 SM 包含多個 Warp 調度器：

```
多 Warp 調度器架構：
┌─────────────────────────────────────────────────┐
│              Streaming Multiprocessor            │
│  ┌─────────────────────────────────────────────┐│
│  │           Warp Scheduling Unit              ││
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐   ││
│  │  │Scheduler │ │Scheduler │ │Scheduler │   ││
│  │  │    #0    │ │    #1    │ │    #2    │   ││
│  │  └────┬─────┘ └────┬─────┘ └────┬─────┘   ││
│  │       │            │            │           ││
│  │       ↓            ↓            ↓           ││
│  │  ┌─────────────────────────────────────┐   ││
│  │  │        Warp Pool                    │   ││
│  │  │  ┌─────┬─────┬─────┬─────┬─────┐   │   ││
│  │  │  │ W0  │ W1  │ W2  │ ... │ W47 │   │   ││
│  │  │  └─────┴─────┴─────┴─────┴─────┘   │   ││
│  │  └─────────────────────────────────────┘   ││
│  └─────────────────────────────────────────────┘│
│                                                  │
│  H100 SM：3 個 Warp 調度器                      │
│  每個調度器每時脈可選擇 1 個 Warp 發射指令       │
└─────────────────────────────────────────────────┘
```

## 調度策略

### 1. Greedy Then Oldest (GTO)

```
GTO 調度策略：
┌─────────────────────────────────────────────────┐
│  原則：                                          │
│  - 優先執行同一 Warp 的連續指令                 │
│  - 直到該 Warp 被阻塞                           │
│  - 然後選擇最老的就緒 Warp                      │
│                                                  │
│  優點：                                          │
│  - 減少 Warp 切換開銷                           │
│  - 提升暫存器重用                               │
│                                                  │
│  缺點：                                          │
│  - 可能導致其他 Warp 饑餓                       │
└─────────────────────────────────────────────────┘
```

### 2. Two-Level Scheduler

```
Two-Level 調度：
┌─────────────────────────────────────────────────┐
│  第一層：微观調度（Micro-scheduling）            │
│  - 在 SM 內部                                   │
│  - 決定哪個 Warp 發射指令                       │
│                                                  │
│  第二層：宏观調度（Macro-scheduling）            │
│  - 在 GPC/晶片層級                              │
│  - 決定哪個 Warp 分配到哪個 SM                  │
│                                                  │
│  目標：                                          │
│  - 平衡 SM 間的負載                             │
│  - 最大化整體吞吐量                             │
└─────────────────────────────────────────────────┘
```

### 3. EPA（Equal-Priority Arbitration）

```
EPA 調度：
┌─────────────────────────────────────────────────┐
│  原則：                                          │
│  - 所有 Warp 擁有相同優先權                     │
│  - 輪流選擇 Warp 發射指令                       │
│                                                  │
│  優點：                                          │
│  - 公平性高                                     │
│  - 避免 Warp 饑餓                               │
│                                                  │
│  缺點：                                          │
│  - 頻繁切換增加開銷                             │
│  - 可能降低暫存器重用率                         │
└─────────────────────────────────────────────────┘
```

## 佔用率（Occupancy）深入分析

### 佔用率的定義

```
佔用率 = 活躍 Warp 數 / SM 最大 Warp 數 × 100%

範例（H100 SM）：
- 最大 Warp 數：48 warps
- 活躍 Warp 數：36 warps
- 佔用率：36/48 = 75%
```

### 資源限制因素

```
佔用率限制因素：
┌─────────────────────────────────────────────────┐
│  1. 暫存器使用量                                │
│     ┌─────────────────────────────────────┐    │
│     │  每 SM 暫存器總數：65536            │    │
│     │  每執行緒使用量：N registers         │    │
│     │  最多執行緒數：65536/N               │    │
│     │  最多 Warp 數：(65536/N)/32         │    │
│     └─────────────────────────────────────┘    │
│                                                  │
│  2. 共享記憶體使用量                            │
│     ┌─────────────────────────────────────┐    │
│     │  每 SM 共享記憶體：48-228 KB        │    │
│     │  每 Block 使用量：M bytes            │    │
│     │  最多 Block 數：(SM 共享記憶體)/M   │    │
│     │  限制：每個 SM 最多 32 個 Blocks    │    │
│     └─────────────────────────────────────┘    │
│                                                  │
│  3. 每 Block 執行緒數                           │
│     ┌─────────────────────────────────────┐    │
│     │  每 Block 最多 1024 個執行緒        │    │
│     │  以 Warp 計算：最多 32 warps/block  │    │
│     └─────────────────────────────────────┘    │
│                                                  │
│  4. SM 的 Block 容量                            │
│     ┌─────────────────────────────────────┐    │
│     │  每 SM 最多 32 個 Blocks            │    │
│     └─────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
```

### 佔用率計算範例

```
假設條件：
- H100 SM：65536 暫存器，228 KB 共享記憶體
- Kernel 設定：每 Block 256 個執行緒（8 warps）
- 暫存器使用：每執行緒 64 個暫存器
- 共享記憶體使用：每 Block 16 KB

計算：
1. 暫存器限制：
   每 Block 使用：256 × 64 = 16384 暫存器
   最多 Blocks：65536 / 16384 = 4 blocks
   最多執行緒：4 × 256 = 1024 threads
   最多 Warps：32 warps
   佔用率：32/48 = 67%

2. 共享記憶體限制：
   最多 Blocks：228 KB / 16 KB ≈ 14 blocks
   （但暫存器限制更嚴格，故取 4 blocks）

結論：佔用率受限於暫存器使用量，為 67%
```

## 佔用率與效能的關係

### 高佔用率的優勢

```
高佔用率好處：
┌─────────────────────────────────────────────────┐
│  1. 更好的延遲隱藏                              │
│     - 更多 Warp 可用於切換                      │
│     - 當一個 Warp 等待記憶體時                   │
│       可切換到其他 Warp                         │
│                                                  │
│  2. 更高的指令級平行（ILP）                     │
│     - 多個 Warp 可同時執行不同指令              │
│     - 提升管線利用率                            │
│                                                  │
│  3. 更好的負載均衡                              │
│     - SM 間的工作分配更均勻                     │
│     - 減少閒置時間                              │
└─────────────────────────────────────────────────┘
```

### 佔用率 vs 效能曲線

```
效能
    │
    │                    ┌───────── 高佔用率區
    │                   /         （延遲隱藏充足）
    │                  /
    │                 /
    │                /
    │               /
    │              /
    │             /
    │            /
    │           /
    │          /
    │         /
    │        /
    │       /
    │      /
    │     /
    │    /
    │   /
    │  / ← 低佔用率區
    │ /    （延遲隱藏不足）
    └──────────────────────────────────── 佔用率

觀察：
- 佔用率提升初期，效能成長顯著
- 佔用率超過某個點後，效能成長趨緩
- 存在一個「甜蜜點」，平衡佔用率與資源使用
```

## 延遲隱藏機制

### 記憶體延遲隱藏

```
延遲隱藏示意：
┌─────────────────────────────────────────────────┐
│  時脈週期 │  Warp 0  │  Warp 1  │  Warp 2  │  │
│  ─────────┼──────────┼──────────┼──────────│  │
│     1     │  執行    │          │          │  │
│     2     │  等待    │  執行    │          │  │
│     3     │  等待    │  等待    │  執行    │  │
│     4     │  等待    │  等待    │  等待    │  │
│     5     │  完成    │  等待    │  等待    │  │
│     6     │          │  完成    │  等待    │  │
│     7     │  執行    │          │  完成    │  │
│     ...   │  ...     │  ...     │  ...     │  │
│                                                  │
│  效果：                                          │
│  - 單一 Warp 需要 5 週期完成記憶體存取          │
│  - 透過 3 個 Warp 交替，每週期都可執行          │
│  - 有效延遲從 5 週期降至 ~1 週期                │
└─────────────────────────────────────────────────┘
```

### Warp 切換開銷

```
Warp 切換開銷：
┌─────────────────────────────────────────────────┐
│  無開銷切換（Zero-Overhead Switching）：         │
│                                                  │
│  - 暫存器檔保留所有 Warp 的狀態                 │
│  - 切換只需更新 Warp ID 暫存器                  │
│  - 無需儲存/載入暫存器內容                      │
│                                                  │
│  這是 GPU 相對於 CPU 的重要優勢：               │
│  - CPU：需要儲存/載入完整的執行緒狀態           │
│  - GPU：所有 Warp 狀態同時存在於暫存器檔       │
└─────────────────────────────────────────────────┘
```

## Occupancy 優化策略

### 1. 暫存器使用優化

```
暫存器優化技巧：
┌─────────────────────────────────────────────────┐
│  1. 使用較少的局部變數                           │
│                                                  │
│  // 不佳的寫法                                  │
│  float temp1 = a * b;                           │
│  float temp2 = c * d;                           │
│  float temp3 = temp1 + temp2;                   │
│  // 使用 3 個暫存器                             │
│                                                  │
│  // 較好的寫法                                  │
│  float result = a * b + c * d;                   │
│  // 使用 2 個暫存器                             │
│                                                  │
│  2. 使用 __launch_bounds__ 指定暫存器限制        │
│                                                  │
│  __global__ void kernel() {                      │
│      // ...                                     │
│  }                                              │
│  // 編譯時指定：每執行緒最多 64 個暫存器        │
│  kernel<<<grid, block>>>(...)                   │
│                                                  │
│  3. 使用 `#pragma unroll` 控制展開              │
│     - 展開會增加暫存器使用                      │
│     - 需要權衡展開程度與佔用率                  │
└─────────────────────────────────────────────────┘
```

### 2. 共享記憶體優化

```
共享記憶體優化：
┌─────────────────────────────────────────────────┐
│  1. 動態分配                                     │
│                                                  │
│  extern __shared__ float smem[];                 │
│  // 依據運行時條件決定大小                       │
│                                                  │
│  2. 使用較小的資料結構                           │
│                                                  │
│  // 使用 half 代替 float                        │
│  __shared__ half smem_half[];                    │
│  // 佔用率提升 2 倍                              │
│                                                  │
│  3. 避免 Bank Conflict                          │
│                                                  │
│  // 加入 padding 消除衝突                        │
│  __shared__ float smem[TILE_SIZE + 1];          │
└─────────────────────────────────────────────────┘
```

### 3. Block 大小優化

```
Block 大小選擇：
┌─────────────────────────────────────────────────┐
│  考慮因素：                                      │
│                                                  │
│  1. Warp 對齊                                   │
│     - Block 大小應為 32 的倍數                  │
│     - 避免部分 Warp 浪費                        │
│                                                  │
│  2. 佔用率影響                                  │
│     - 較小的 Block → 較多 Blocks/SM → 較高佔用率│
│     - 但過小可能影響指令效率                    │
│                                                  │
│  3. 實務建議                                   │
│     - 從 256 開始                               │
│     - 嘗試 128, 256, 512                        │
│     - 使用 profiler 驗證                        │
│                                                  │
│  範例比較：                                     │
│  - 128 threads/block：可有 24 blocks/SM        │
│  - 256 threads/block：可有 12 blocks/SM        │
│  - 512 threads/block：可有 6 blocks/SM         │
│  - 1024 threads/block：可有 3 blocks/SM        │
└─────────────────────────────────────────────────┘
```

## 本章小結

- Warp 是 GPU 執行的基本單位，由 32 個執行緒組成
- Warp 調度器負責選擇就緒的 Warp 發射指令
- 佔用率是衡量 SM 資源使用效率的關鍵指標
- 延遲隱藏是 GPU 隱藏記憶體延遲的主要機制
- 優化佔用率需要平衡暫存器、共享記憶體、Block 大小等因素
