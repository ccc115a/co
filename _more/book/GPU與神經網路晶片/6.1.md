# 6.1 數值格式演進：FP32、FP16、BF16、INT8、FP8 至 FP4

## 數值格式的重要性

### 精度與效能的取捨

```
精度 vs 效能權衡：
┌─────────────────────────────────────────────────┐
│                                                  │
│  高精度 ←────────────────────────→ 低精度      │
│                                                  │
│  準確性高                    效能高            │
│  記憶體需求大              記憶體需求小       │
│  運算速度慢                運算速度快         │
│  能耗高                    能耗低             │
│                                                  │
│  格式演進：                                      │
│  FP64 → FP32 → FP16/BF16 → INT8 → FP8 → FP4  │
│                                                  │
│  每次精度減半：                                  │
│  - 運算吞吐量 ×2                               │
│  - 記憶體需求 ÷2                               │
│  - 能效比 ×2                                   │
└─────────────────────────────────────────────────┘
```

## IEEE 754 浮點格式

### FP32（單精度浮點）

```
FP32 格式（32-bit）：
┌─────────────────────────────────────────────────┐
│  符號（1 bit）  指數（8 bits）  尾數（23 bits）  │
│  ┌─────┬──────────────┬──────────────────────┐  │
│  │  S  │  E (偏差127) │  M (隱含1)           │  │
│  └─────┴──────────────┴──────────────────────┘  │
│  31    30           23    22                 0  │
│                                                  │
│  數值計算：                                      │
│  value = (-1)^S × 1.M × 2^(E-127)              │
│                                                  │
│  特性：                                          │
│  - 最大整數：2^24 = 16,777,216                 │
│  - 最小值：~1.4×10^-45                        │
│  - 範圍：±1.2×10^-38 到 ±3.4×10^38            │
│  - 精度：~7 位十進位數                         │
└─────────────────────────────────────────────────┘
```

## FP16（半精度浮點）

### FP16 格式

```
FP16 格式（16-bit）：
┌─────────────────────────────────────────────────┐
│  符號（1 bit）  指數（5 bits）  尾數（10 bits）  │
│  ┌─────┬─────────┬──────────────────────────┐  │
│  │  S  │E(偏差15)│     M (隱含1)           │  │
│  └─────┴─────────┴──────────────────────────┘  │
│  15    14       10    9                    0   │
│                                                  │
│  數值計算：                                      │
│  value = (-1)^S × 1.M × 2^(E-15)              │
│                                                  │
│  特性：                                          │
│  - 最大整數：2^11 = 2048                       │
│  - 範圍：±6.1×10^-5 到 ±65504                 │
│  - 精度：~3-4 位十進位數                       │
│                                                  │
│  優點：                                          │
│  - 記憶體減少 50%                              │
│  - 運算速度提升 2 倍                           │
│  - Tensor Core 原生支援                       │
└─────────────────────────────────────────────────┘
```

### FP16 的問題

```
FP16 的限制：
┌─────────────────────────────────────────────────┐
│  1. 範圍有限                                    │
│     - 最大到 65504                             │
│     - 容易溢位或下溢                           │
│                                                  │
│  2. 精度有限                                    │
│     - 只有 10-bit 尾數                        │
│     - 大數值的相對精度低                      │
│                                                  │
│  3. 訓練困難                                    │
│     - 梯度可能太小而無法表示                  │
│     - 需要額外的縮放處理                      │
│                                                  │
│  解法：混合精度訓練                            │
│  - 權重用 FP32 儲存                           │
│  - 運算用 FP16                                 │
│  - 累加用 FP32                                 │
└─────────────────────────────────────────────────┘
```

## BF16（Brain Floating Point）

### BF16 格式

```
BF16 格式（16-bit）：
┌─────────────────────────────────────────────────┐
│  符號（1 bit）  指數（8 bits）  尾數（7 bits）   │
│  ┌─────┬────────────────┬───────────────────┐  │
│  │  S  │ E (偏差127)   │   M (隱含1)       │  │
│  └─────┴────────────────┴───────────────────┘  │
│  15    14             7    6              0   │
│                                                  │
│  數值計算：                                      │
│  value = (-1)^S × 1.M × 2^(E-127)              │
│                                                  │
│  特性：                                          │
│  - 範圍：與 FP32 相同（±3.4×10^38）            │
│  - 精度：~3 位十進位數                          │
│  - 只保留 FP32 的 8-bit 指數與 7-bit 尾數     │
│                                                  │
│  優勢：                                          │
│  - 與 FP32 相同動態範圍                        │
│  - 在深度學習中常足夠使用                     │
│  - 無需複雜的縮放處理                          │
└─────────────────────────────────────────────────┘
```

### FP16 vs BF16

```
FP16 vs BF16 比較：
┌─────────────────────────────────────────────────┐
│  特性       │      FP16       │    BF16         │
├─────────────────────────────────────────────────┤
│  指數位元   │       5         │      8         │
│  尾數位元   │      10         │      7         │
│  動態範圍   │  ±65504        │  ±3.4×10^38   │
│  精度       │  ~3-4 位       │  ~3 位         │
│  訓練適用性 │  需要縮放      │  不需縮放      │
│  硬體支援   │  NVIDIA+Google │  Google+NVIDIA │
│  能耗       │  低            │  低            │
└─────────────────────────────────────────────────┘

選擇建議：
- FP16：需要高精度的小數值
- BF16：需要大動態範圍（訓練常用）
```

## INT8（整數格式）

### INT8 格式

```
INT8 格式（8-bit）：
┌─────────────────────────────────────────────────┐
│  有號整數（2's complement）：                   │
│  - 範圍：-128 到 127                           │
│                                                  │
│  無號整數：                                      │
│  - 範圍：0 到 255                               │
│                                                  │
│  應用：量化                                    │
│  float_value = int_value × scale                │
│                                                  │
│  ▒                        ▒                     │
│  ▒  需要縮放因子管理         ▒                  │
│  ▒  輸入 → 量化 → 運算 → 反量化 → 輸出  ▒     │
└─────────────────────────────────────────────────┘
```

### INT8 量化

```
量化過程：
┌─────────────────────────────────────────────────┐
│  1. 確定縮放因子（Scale）                       │
│     scale = max_abs / 127                      │
│                                                  │
│  2. 量化                                          │
│     int8_value = round(float_value / scale)     │
│                                                  │
│  3. 運算                                          │
│     int32_sum = Σ(int8_a × int8_b)             │
│                                                  │
│  4. 反量化                                      │
│     float_result = int32_sum × (scale_a × scale_b)│
│                                                  │
│  問題：                                          │
│  - 量化誤差                                  │
│  - 需要重新校準（Calibration）                │
│  - 對分佈敏感的模型不友好                     │
└─────────────────────────────────────────────────┘
```

## FP8 格式

### FP8 的提出

FP8 是為降低記憶體需求與提升運算效能而提出的 8-bit 浮點格式：

```
FP8 兩種格式：
┌─────────────────────────────────────────────────┐
│  1. E4M3（高精度）                               │
│     ┌─────┬────────┬────────────┐              │
│     │  S  │E(4bit) │M(3bit)    │              │
│     └─────┴────────┴────────────┘              │
│     - 範圍：±448                              │
│     - 精度：~3 位十進位數                      │
│     - 適合正向傳播                            │
│                                                  │
│  2. E5M2（高動態範圍）                          │
│     ┌─────┬────────┬────────────┐              │
│     │  S  │E(5bit) │M(2bit)    │              │
│     └─────┴────────┴────────────┘              │
│     - 範圍：±57344                             │
│     - 精度：~2 位十進位數                      │
│     - 適合反向傳播的梯度                      │
└─────────────────────────────────────────────────┘
```

### FP8 應用場景

```
FP8 部署：
┌─────────────────────────────────────────────────┐
│  正向傳播：使用 E4M3                            │
│  - Activation 使用 E4M3                        │
│  - 權重使用 E4M3                               │
│  - 精度較高                                   │
│                                                  │
│  反向傳播：使用 E5M2                            │
│  - 梯度使用 E5M2                               │
│  - 需要大動態範圍                              │
│  - 防止溢位                                    │
│                                                  │
│  好處：                                          │
│  - 記憶體需求減半（相比 FP16）                 │
│  - 運算吞吐量加倍                              │
│  - H100 可達 3,958 TFLOPS                      │
└─────────────────────────────────────────────────┘
```

## FP4 格式

### FP4 格式

```
FP4 格式（4-bit）：
┌─────────────────────────────────────────────────┐
│  兩種主流格式：                                  │
│                                                  │
│  1. E1M2：                                       │
│     ┌─────┬─────┬───────┐                      │
│     │  S  │E(1b)│M(2bit)│                      │
│     └─────┴─────┴───────┘                      │
│     - 範圍：±6                                  │
│     - 精度：~1 位                              │
│                                                  │
│  2. E2M1：                                       │
│     ┌─────┬─────┬───────┐                      │
│     │  S  │E(2b)│M(1bit)│                      │
│     └─────┴─────┴───────┘                      │
│     - 範圍：±30                                 │
│     - 精度：~1 位                              │
│                                                  │
│  特性：                                          │
│  - 記憶體大幅減少                              │
│  - 運算吞吐量大增                              │
│  - 精度損失顯著                                │
└─────────────────────────────────────────────────┘
```

### FP4 挑戰

```
FP4 的限制與挑戰：
┌─────────────────────────────────────────────────┐
│  1. 精度損失大                                  │
│     - 只有 4 bits 表示資訊                     │
│     - 需要非常精確的縮放                      │
│                                                  │
│  2. 只適合特定模型                              │
│     - 簡單模型適用                             │
│     - 複雜模型需混合精度                      │
│                                                  │
│  3. 需要密集量化（Block-wise）                 │
│     - 逐區塊縮放                              │
│     - 增加元資料開銷                          │
│                                                  │
│  應用：                                          │
│  - 大型模型的壓縮推論                          │
│  - Blackwell B200 支援 FP4                      │
│  - 極端低功耗邊緣裝置                          │
└─────────────────────────────────────────────────┘
```

## 精度選擇策略

### 應用場景建議

```
精度選擇指南：
┌─────────────────────────────────────────────────┐
│  應用場景              │  推薦格式              │
├─────────────────────────────────────────────────┤
│  科學計算              │  FP64 / FP32          │
│  模型訓練（正向）      │  BF16 / FP16          │
│  模型訓練（梯度）      │  FP32 / FP8(E5M2)     │
│  混合精度訓練          │  FP16/BF16 + FP32     │
│  推論（高精度）        │  FP16 / INT8          │
│  推論（高吞吐量）      │  INT8 / FP8           │
│  推論（低資源）        │  FP8 / INT4           │
│  極低資源推論          │  FP4 / INT4           │
└─────────────────────────────────────────────────┘
```

### 實務考量

```
選擇格式的考量因素：
┌─────────────────────────────────────────────────┐
│  1. 模型精度要求                                │
│     - 任務的容錯程度                           │
│                                                 │
│  2. 硬體支援                                    │
│     - Tensor Core 支援的格式                   │
│     - 格式轉換的效能成本                       │
│                                                 │
│  3. 記憶體限制                                  │
│     - 模型大小與可用記憶體                     │
│                                                 │
│  4. 精度蒸發監控                                │
│     - 訓練時監控 loss 變化                     │
│     - 必要時回退到更高精度                     │
└─────────────────────────────────────────────────┘
```

## 本章小結

- 數值格式在精度、範圍、效能間進行權衡
- FP32 是基準精度，FP16/BF16 是訓練常用格式
- BF16 提供與 FP32 相同動態範圍，適合訓練
- INT8/FP8 常用於推論加速
- FP4/INT4 是極端優化，需謹慎使用
- 混合精度策略可兼顧效能與準確性
