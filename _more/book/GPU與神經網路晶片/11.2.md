# 11.2 FlashAttention 硬體感知的 Attention 計算演算法

## Attention 機制與記憶體瓶頸

### Attention 計算

```
標準 Attention 計算：
┌─────────────────────────────────────────────────┐
│  輸入：                                          │
│  Q, K, V：形狀 (N, d)                          │
│  N：序列長度，d：每頭維度                    │
│                                                  │
│  計算步驟：                                      │
│  1. S = Q × K^T          （N×N 矩陣）          │
│  2. P = softmax(S)                              │
│  3. O = P × V            （N×d 輸出）          │
│                                                  │
│  記憶體問題：                                    │
│  - S 是 N×N 矩陣（O(N²) 記憶體）              │
│  - 當 N 很大（如 32K、128K）                  │
│    → 需要巨大記憶體                          │
│                                                  │
│  範例（N=32K, d=64）：                           │
│  S 大小 = 32K × 32K × 2 bytes = 2 GB！        │
└─────────────────────────────────────────────────┘
```

### 標準實現的瓶頸

```
傳統 Attention 記憶體瓶頸：
┌─────────────────────────────────────────────────┐
│  傳統實現（多次 HBM 來回）：                     │
│                                                  │
│  1. 從 HBM 讀 Q, K                      │
│  2. 計算 S 寫回 HBM）             │
│  3. 從 HBM 讀 S，做 softmax             │
│  4. 計算 P，寫回 HBM              │
│  5. 讀 P 和 V，計算 O                   │
│  6. 寫回 O                        │
│                                                  │
│  記憶體往返：多次 HBM 存取                    │
│  S 和 P 這個 N×N 中間矩陣                │
│  需要寫入並讀回 HBM                      │
│                                                  │
│  問題：                                          │
│  - HBM 是瓶頸（Memory-Bound）            │
│  - 大量中間矩陣搬運                      │
│  - O(N²) 記憶體需求                        │
└─────────────────────────────────────────────────┘
```

## FlashAttention 核心思想

### IO 感知設計

```
FlashAttention 核心思想：
┌─────────────────────────────────────────────────┐
│  IO-Aware（感知輸入輸出層級）：                  │
│  針對 GPU 的記憶體層次結構                      │
│  將計算「分塊」在片上完成              │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │        GPU 記憶體層級                   │   │
│  │  ┌────────────────────────────────────┐  │   │
│  │  │       HBM（慢、大）  ← 減少讀寫   │  │   │
│  │  └────────────────────────────────────┘  │   │
│  │                    ↑                    │   │
│  │  ┌────────────────────────────────────┐  │   │
│  │  │   Shared Memory / SRAM（快、小）   │  │   │
│  │  │   ← 分塊計算全部在片上完成       │  │   │
│  │  └────────────────────────────────────┘  │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  目標：                                          │
│  - 避免 N×N 中間矩陣寫入 HBM                │
│  - 所有計算在片上（SRAM）進行                │
│  - 大幅減少 HBM 存取                        │
└─────────────────────────────────────────────────┘
```

### 分塊（Tiling）策略

```
FlashAttention 分塊：
┌─────────────────────────────────────────────────┐
│  將 Q、K、V 分割成區塊（Block）：                │
│                                                  │
│  Q：分成 Q_1, Q_2, ...（Block）                │
│  K：分成 K_1, K_2, ...（Block）                │
│  V：分成 V_1, V_2, ...（Block）                │
│                                                  │
│  對每個 Q_block：                                 │
│  處理所有 K/V blocks：                           │
│                                                  │
│  for j in K_blocks:                             │
│      S_ij = Q_i × K_j^T     （在片上）          │
│      P_ij = softmax(S_ij)  （在片上）           │
│      O_i += P_ij × V_j     （累加在片上）       │
│                                                  │
│  每個 block 只載入所需到 SRAM               │
│  中間矩陣 S、P 不寫回 HBM                   │
└─────────────────────────────────────────────────┘
```

## 精確 Softmax 的困難

### 為什麼 softmax 難分塊

```
Softmax 需要全局資訊：
┌─────────────────────────────────────────────────┐
│  Softmax：                                      │
│  P_i = exp(S_i - max(S)) / Σexp(S_j - max(S))  │
│                                                  │
│  問題：                                          │
│  - softmax 的分母是所有 row 的總和            │
│  - 需要「全局」最大值與總和                 │
│  - 分塊時如何知道全局資訊？               │
│                                                  │
│  解法：Online Softmax（線上 softmax）          │
│  - 逐塊更新最大值的估計                    │
│  - 維護累積的歸一化因子                      │
│  - 得到精確結果（非近似）                 │
└─────────────────────────────────────────────────┘
```

### Online Softmax 演算法

```
Online Softmax：
┌─────────────────────────────────────────────────┐
│  逐步處理每個 block：                            │
│                                                  │
│  初始化：                                        │
│  m_0 = -∞（最大值）                          │
│  l_0 = 0（總和）                             │
│  O_0 = 0                                       │
│                                                  │
│  對每個 block（i 從 1 到 N_block）：              │
│  1. 計算新 block 的最大值：                    │
│     m_i = max(m_{i-1}, max(S_block))            │
│                                                  │
│  2. 更新歸一化因子（修正舊的值）：               │
│     l_i = l_{i-1} × exp(m_{i-1} - m_i)          │
│           + Σexp(S_block - m_i)                 │
│                                                  │
│  3. 修正累積輸出：                               │
│     O_i = O_{i-1} × exp(m_{i-1} - m_i)           │
│           + P_block × V_block                   │
│                                                  │
│  最後：                                          │
│  O = O_N / l_N                                   │
│                                                  │
│  → 得到與全局 softmax 相同結果                │
└─────────────────────────────────────────────────┘
```

## FlashAttention-2

### FlashAttention-2 的改進

```
FlashAttention-2 改進：
┌─────────────────────────────────────────────────┐
│  1. 減少非矩陣乘法                                │
│     - 標準：rescale 是 O(N)                    │
│     - FA2：優化這個操作                    │
│     - 提高矩陣乘法佔比                      │
│                                                  │
│  2. 平行策略                                  │
│     - 在序列維度上平行（更多序列平行）                │
│     - 增加平行度                      │
│                                                  │
│  3. 減少 HBM 往返                            │
│     - 進一步減少中間資料寫回            │
│                                                  │
│  4. 更好的 Warp 分區                        │
│     - 更平衡的工作分配                  │
│     - 提升 GPU 利用率                  │
│                                                  │
│  結果：                                          │
│  - 比 FA1 快 ~2 倍（在長序列）              │
│  - 更好的算力利用率                        │
└─────────────────────────────────────────────────┘
```

## 本章小結

- 標準 Attention 有 O(N²) 記憶體需求瓶頸
- FlashAttention 透過分塊 + IO-Aware 設計克服
- Online Softmax 達成精確的全局歸一化
- FlashAttention-2 進一步提升矩陣乘法佔比與平行度
- 記憶體從 O(N²) 降到 O(N)
- 長序列時速度快 2-8 倍
- 體現硬體感知（Hardware-Aware）演算法設計理念
