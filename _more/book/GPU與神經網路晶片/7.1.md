# 7.1 Scratchpad Memory vs. Cache 系統

## 片上記憶體的基本概念

### 片上記憶體的角色

```
片上記憶體（On-Chip Memory）：
┌─────────────────────────────────────────────────┐
│  片上記憶體的位置：                              │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │              晶片（Chip）                 │   │
│  │  ┌────────┐  ┌──────────┐  ┌────────┐   │   │
│  │  │  運算   │  │  片上記憶體 │  │  控制   │   │
│  │  │  單元   │  │ (SRAM)   │  │  邏輯   │   │
│  │  └────────┘  └──────────┘  └────────┘   │   │
│  └────────────────────┬─────────────────────┘   │
│                       │                         │
│  ┌────────────────────┴─────────────────────┐   │
│  │         外部記憶體（HBM/DRAM）            │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  片上記憶體的優勢：                              │
│  - 延遲低（~10-30 ns vs ~100-300 ns）          │
│  - 頻寬高（~20 TB/s vs ~2-4 TB/s）             │
│  - 功耗低（相比外部記憶體）                    │
└─────────────────────────────────────────────────┘
```

### 兩大陣營

```
片上記憶體兩大方法：
┌─────────────────────────────────────────────────┐
│  1. Scratchpad Memory（手動管理）               │
│     - 程式控制資料搬運                        │
│     - 可預測的行為                            │
│     - 需要手動優化                            │
│     - 常見於 TPU/NPU                          │
│                                                  │
│  2. Cache（自動管理）                            │
│     - 硬體自動管理資料搬運                    │
│     - 對程式透明                              │
│     - 有快取命中/失效                        │
│     - 常見於 CPU/GPU                          │
└─────────────────────────────────────────────────┘
```

## Scratchpad Memory 深入分析

### Scratchpad 的特性

```
Scratchpad Memory 特性：
┌─────────────────────────────────────────────────┐
│  1. 程式控制                                    │
│     - 軟體（編譯器/程式員）管理               │
│     - 明確的載入/儲存操作                     │
│     - 明確的資料生命週期                      │
│                                                  │
│  2. 可預測性                                    │
│     - 無命中/失效概念                          │
│     - 存取時間固定                            │
│     - 易於效能建模                            │
│                                                  │
│  3. 無標記（Tag）                              │
│     - 不需要標記記憶體                        │
│     - 節省面積                              │
│     - 減少功耗                                │
│                                                  │
│  4. 資料重用控制                                │
│     - 軟體明確控制資料重用                    │
│     - 可程式設計 reuse 策略                   │
└─────────────────────────────────────────────────┘
```

### Scratchpad 的運作方式

```
Scratchpad 運作：
┌─────────────────────────────────────────────────┐
│  手動管理流程：                                  │
│                                                  │
│  ┌─────────────┐    ┌─────────────────────┐     │
│  │  外部記憶體 │─→｜  DMA 搬運 │→｜ Scratchpad │
│  └─────────────┘    └─────────────────────┘     │
│       ↑                  ↓                      │
│  ┌─────────────┐    ┌─────────────────────┐     │
│  │  運算單元   │←──｜  從 Scratchpad 讀取 │→｜   │
│  └─────────────┘    └─────────────────────┘     │
│                                                  │
│  程式範例（偽代碼）：                            │
│  1. DMA_load(scratchpad[0], weight_addr, ...)   │
│  2. DMA_load(scratchpad[1], input_addr, ...)    │
│  3. 運算(scratchpad[0], scratchpad[1],          │
│         scratchpad[2])                           │
│  4. DMA_store(scratchpad[2], output_addr, ...)  │
└─────────────────────────────────────────────────┘
```

### Scratchpad 的優缺點

```
Scratchpad Memory 優缺點：
┌─────────────────────────────────────────────────┐
│  優點：                                          │
│  ✓ 可預測的效能                                │
│  ✓ 無快取標記開銷                              │
│  ✓ 高效率的資料重用                            │
│  ✓ 低功耗                                      │
│  ✓ 易於硬體設計                              │
│                                                  │
│  缺點：                                          │
│  ✗ 需要軟體管理（複雜）                       │
│  ✗ 程式可移植性差                              │
│  ✗ 無法自動適應存取模式                       │
│  ✗ 程式員負擔大                               │
└─────────────────────────────────────────────────┘
```

## Cache 系統深入分析

### Cache 的特性

```
Cache 特性：
┌─────────────────────────────────────────────────┐
│  1. 硬體管理                                    │
│     - 自動偵測資料重用                        │
│     - 自動替換被淘汰的資料                   │
│     - 對程式透明                              │
│                                                  │
│  2. 空間與時間局部性                            │
│     - 時間局部性：近期使用的資料                │
│       很可能再次使用                          │
│     - 空間局部性：相鄰的資料                    │
│       很可能被一起存取                        │
│                                                  │
│  3. 命中/失效                                │
│     - 命中：資料在 Cache 中                    │
│     - 失效：資料不在 Cache 中                 │
│     - 命中率影響效能                          │
│                                                  │
│  4. 替換策略                                    │
│     - LRU（最近最少使用）                     │
│     - LFU（最不常使用）                       │
│     - 隨機替換（Random）                      │
└─────────────────────────────────────────────────┘
```

### Cache 結構

```
Cache 基本結構：
┌─────────────────────────────────────────────────┐
│              Cache 組織方式：                     │
│                                                  │
│  1. 直接映射（Direct-Mapped）：                  │
│     ┌─────┬─────┬─────┬─────┬─────┐            │
│     │Set0 │Se t1│Set2 │Set3 │...  │            │
│     └──┬──┴──┬──┴──┬──┴──┬──┴──┬──┘            │
│        每個集合只有 1 路                          │
│                                                  │
│  2. 集合關聯（Set-Associative）：                │
│     ┌──────────────┬──────────────┐             │
│     │   Set 0      │   Set 0      │             │
│     │   (Way 0)    │   (Way 1)    │             │
│     ├──────────────┼──────────────┤             │
│     │   Set 1      │   Set 1      │             │
│     ├──────────────┼──────────────┤             │
│     │   ...        │   ...        │             │
│     └──────────────┴──────────────┘             │
│        如：4-way set-associative                 │
│                                                  │
│  3. 全關聯（Fully Associative）：                │
│     ┌────┬────┬────┬────┬────────────────┐      │
│     │B0  │B1  │B2  │B3  │...              │      │
│     └────┴────┴────┴────┴────────────────┘      │
│        任何位置可存任何資料                        │
└─────────────────────────────────────────────────┘
```

### Cache 存取流程

```
Cache 存取流程：
┌─────────────────────────────────────────────────┐
│  讀取流程：                                      │
│                                                  │
│  發出位址 → 計算 Set → 比較 Tag → 　          │
│               ↓              ↓                 │
│            命中           失效                  │
│               ↓              ↓                 │
│        傳回資料      從下一層記憶體             │
│                       載入資料並更新            │
│                       傳回資料                 │
│                                                  │
│  命中延遲：~1-4 週期（L1）                     │
│  失效延遲：~10-30 週期（L2）                   │
│           ~100-400 週期（記憶體）              │
└─────────────────────────────────────────────────┘
```

### Cache 的優缺點

```
Cache 優缺點：
┌─────────────────────────────────────────────────┐
│  優點：                                          │
│  ✓ 對程式透明（易於使用）                     │
│  ✓ 自動適應存取模式                          │
│  ✓ 不需軟體管理                              │
│  ✓ 可移植性好                                 │
│                                                  │
│  缺點：                                          │
│  ✗ 標記（Tag）開銷                            │
│  ✗ 失效（Miss）懲罰大                        │
│  ✗ 功耗較高（標記比較）                     │
│  ✗ 效能不可預測（依命中率）                 │
└─────────────────────────────────────────────────┘
```

### 詳細比較表

```
Scratchpad vs Cache：
┌─────────────────────────────────────────────────┐
│  特性       │  Scratchpad     │  Cache          │
```

## AI 晶片的記憶體選擇

### GPU：兩者結合

```
GPU 的混合策略：
┌─────────────────────────────────────────────────┐
│  GPU 同時使用兩種類型：                          │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │                SM（Streaming Multip.）    │   │
│  │  ┌────────────────────────────────────┐  │   │
│  │  │  L1 Cache（硬體管理）              │  │   │
│  │  │   - 自動快取全域記憶體存取        │  │   │
│  │  └────────────────────────────────────┘  │   │
│  │  ┌────────────────────────────────────┐  │   │
│  │  │  Shared Memory（軟體管理）          │  │   │
│  │  │   - 可程式控制的 Scratchpad       │  │   │
│  │  │   - 與 L1 共用 SRAM               │  │   │
│  │  └────────────────────────────────────┘  │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  優勢：                                          │
│  - 軟體可選用哪種模式                        │
│  - 靈活性高                                   │
│  - 兼顧效率與易用性                          │
└─────────────────────────────────────────────────┘
```

### TPU/NPU：Scratchpad 主導

```
TPU 的 Scratchpad 策略：
┌─────────────────────────────────────────────────┐
│  TPU 主要使用 Scratchpad：                       │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │           Unified Buffer                 │   │
│  │      （28 MB Scratchpad）                │   │
│  │  - 存放輸入/輸出資料                    │   │
│  │  - 軟體（XLA 編譯器）管理               │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  原因：                                          │
│  - AI 工作負載的資料存取模式規則            │   │
│  - 可精確預測的資料重用                    │   │
│  - 軟體（編譯器）可完全控制             │   │
│  - 不需硬體自動偵測                        │   │
│                                                  │
│  結果：                                          │
│  - 更小的晶片面積                           │   │
│  - 更低的功耗                               │   │
│  - 更可預測的效能                           │   │
└─────────────────────────────────────────────────┘
```

## 資料重用策略

### 典型的重用技術

```
資料重用技術：
┌─────────────────────────────────────────────────┐
│  1. Tiling（分塊）                              │
│     - 將大矩陣分割為小區塊                    │
│     - 每個區塊載入 Scratchpad                 │
│     - 在片上完成所有重複運算                  │
│                                                  │
│  2. Ping-Pong Buffer                          │
│     - 雙緩衝區交替使用                        │
│     - 一邊運算一邊載入下一塊                 │
│     - 隱藏資料搬運延遲                       │
│                                                  │
│  3. 暫存器重用                                │
│     - 將最常用的資料放在暫存器               │
│     - 減少暫存器與記憶體間傳輸               │
└─────────────────────────────────────────────────┘
```

### Tiling 範例

```
Tiling 策略：
┌─────────────────────────────────────────────────┐
│  記憶體頻寬優化：                                │
│                                                  │
│  無 Tiling：                                     │
│  每次運算都需要從外部記憶體讀取                 │
│  → 記憶體頻寬成為瓶頸                          │
│                                                  │
│  有 Tiling：                                     │
│  ┌──────────┐  ┌──────────┐                    │
│  │ Tile 0   │  │ Tile 1   │  ...                │
│  │ (64×64)  │  │ (64×64)  │                    │
│  └──────────┘  └──────────┘                    │
│  - 每個 Tile 載入 Scratchpad                   │
│  - 在片上完成多次重用                          │
│  - 大幅減少外部記憶體存取                      │
│                                                  │
│  效果：                                          │
│  - 記憶體存取減少 T 倍                          │
│  - 效能提升 T 倍（若記憶體受限）              │
└─────────────────────────────────────────────────┘
```

## 本章小結

- Scratchpad 由軟體管理，行為可預測，效能可計算
- Cache 由硬體管理，對程式透明，但行為不可預測
- Cache 需要標記與比較邏輯，面積與功耗較高
- GPU 結合兩者，L1 Cache + Shared Memory 共用 SRAM
- TPU 主要使用 Scratchpad，因為 AI 工作負載規則可預測
- Tiling、Ping-Pong、暫存器重用是提升效能的關鍵
