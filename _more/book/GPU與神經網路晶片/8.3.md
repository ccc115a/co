# 8.3 Scale-Up 與 Scale-Out：晶片內與晶片間的高速通訊拓撲

## Scale-Up 與 Scale-Out 概念

### 兩種擴展方式

```
Scale-Up vs Scale-Out：
┌─────────────────────────────────────────────────┐
│  Scale-Up（向上擴展）：                          │
│  - 增加單一節點的資源                          │
│  - 例如：更多 GPU、更大記憶體                 │
│  - 使用高速互連（NVLink、CXL）                │
│  - 節點內擴展                                  │
│                                                  │
│  Scale-Out（向外擴展）：                        │
│  - 增加節點數量                                │
│  - 例如：更多伺服器                            │
│  - 使用網路互連（乙太網路、InfiniBand）       │
│  - 跨節點擴展                                  │
│                                                  │
│  AI 系統同時需要兩者：                          │
│  - 單一節點：GPU + 高頻寬記憶體（Scale-Up）   │
│  - 多節點：集群協作（Scale-Out）             │
└─────────────────────────────────────────────────┘
```

### AI 訓練的擴展模式

```
AI 訓練的擴展模式：
┌─────────────────────────────────────────────────┐
│  ┌──────────────────────────────────────────┐   │
│  │          數據平行（Data Parallel）       │   │
│  │  - 每 GPU 持有完整模型副本              │   │
│  │  - 每個處理不同資料批次                  │   │
│  │  - 需要頻繁梯度同步（Scale-Out）        │   │
│  └──────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────┐   │
│  │          流水線平行（Pipeline）        │   │
│  │  - 每 GPU 處理部分層                  │   │
│  │  - 前向+後向傳播                       │   │
│  │  - 節點間通訊（Scale-Out）            │   │
│  └──────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────┐   │
│  │          張量平行（Tensor Parallel）     │   │
│  │  - 矩陣在 GPU 間分割                    │   │
│  │  - 需要極高頻寬（Scale-Up 需求）        │   │
│  └──────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

## Scale-Up 架構

### 單節點 Scale-Up

```
節點內 Scale-Up：
┌─────────────────────────────────────────────────┐
│                                                  │
│              GPU 節點（DGX 等）                  │
│  ┌──────────────────────────────────────────┐   │
│  │      ┌───────────┐  ┌───────────┐       │   │
│  │      │   GPU 0   │←→│   GPU 1   │ NVLink │   │
│  │      └───────────┘  └───────────┘       │   │
│  │      ┌───────────┐  ┌───────────┐       │   │
│  │      │   GPU 2   │←→│   GPU 3   │ NVLink │   │
│  │      └───────────┘  └───────────┘       │   │
│  │              NVSwitch                    │   │
│  │      ┌──────────────────────────┐        │   │
│  │      │   8 個 GPU 全互連        │        │   │
│  │      └──────────────────────────┘        │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  Scale-Up 特點：                                │
│  - 高頻寬（NVLink）                           │
│  - 低延遲                                      │
│  - 記憶體統一存取                              │
│  - 適合張量平行                              │
└─────────────────────────────────────────────────┘
```

### GPU 記憶體統一

```
GPU 記憶體統一（Scale-Up）：
┌─────────────────────────────────────────────────┐
│  透過 NVLink 實現：                              │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │            多 GPU 記憶體池               │   │
│  │                                          │   │
│  │  ┌───────┐  ┌───────┐  ┌───────┐      │   │
│  │  │ GPU0  │  │ GPU1  │  │ GPU2  │      │   │
│  │  │80GB   │  │80GB   │  │80GB   │      │   │
│  │  └───────┘  └───────┘  └───────┘      │   │
│  │                    │                     │   │
│  │              統一可定址                    │   │
│  │            240 GB 虛擬記憶體              │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  優點：                                          │
│  - 支援超大模型（超過單 GPU 記憶體）           │
│  - 記憶體直接存取（Peer-to-Peer）             │
│  - 不經 CPU 中介                              │
│                                                  │
│  範例：                                          │
│  - NVIDIA 超大記憶體 GPU（如透過 NVLink）     │
└─────────────────────────────────────────────────┘
```

## Scale-Out 架構

### 多節點集群

```
多節點 Scale-Out：
┌─────────────────────────────────────────────────┐
│                                                  │
│              AI 集群                              │
│  ┌──────────────────────────────────────────┐   │
│  │  節點 0             節點 1              │   │
│  │  ┌──────────────────┐  ┌──────────────┐ │   │
│  │  │ 8× GPU           │  │ 8× GPU       │ │   │
│  │  │ + NVSwitch       │  │ + NVSwitch   │ │   │
│  │  └──┬───────────────┘  └──────┬───────┘ │   │
│  └─────┼─────────────────────────┼─────────┘   │
│        │     機架級互連           │              │
│  ┌─────┼─────────────────────────┼─────────┐   │
│  │  節點 2 ...      節點 N      │          │   │
│  └──────────────────────────────────────────┘   │
│        │                         │              │
│        └─────────┬───────────────┘              │
│                  │ 數據中心網路                 │
│            ┌─────┴─────┐                        │
│            │  Spine    │                        │
│            │  Switch   │                        │
│            └───────────┘                        │
│                                                  │
│  Scale-Out 特點：                                │
│  - 使用乙太網路或 InfiniBand                  │
│  - 較高延遲（相比 NVLink）                     │
│  - 廣闊的可擴展性                              │
│  - 適合數據平行與流水線平行                  │
└─────────────────────────────────────────────────┘
```

## 通訊拓撲比較

### 各種互連的特性

```
互連特性比較：
┌─────────────────────────────────────────────────┐
│  技術         │  頻寬    │  延遲    │  距離範圍 │
├─────────────────────────────────────────────────┤
│  NVLink       │  TB/s   │  ~0.5µs │  機架內  │
│  CXL          │  GB/s   │  ~0.2µs │  節點內  │
│  PCIe         │  GB/s   │  ~1-2µs │  節點內  │
│  乙太網路     │  GB/s   │  ~2-10µs│  數據中心│
│  InfiniBand   │  GB/s   │  ~1-3µs │  數據中心│
└─────────────────────────────────────────────────┘

權衡：
- 頻寬越高、延遲越低 → 距離越短
- 距離越遠 → 需要網路協定
- 不同層級使用不同技術
```

## 通訊模式

### 不同平行的通訊需求

```
各平行模式通訊需求：
┌─────────────────────────────────────────────────┐
│  1. 數據平行（Data Parallel）                   │
│     - 通訊：梯度同步（All-Reduce）             │
│     - 頻率：每步一次                          │
│     - 需求：中等頻寬、低延遲                │
│                                                  │
│  2. 張量平行（Tensor Parallel）                 │
│     - 通訊：中間結果傳輸                      │
│     - 頻率：每層多次                          │
│     - 需求：極高頻寬、極低延遲            │
│                                                  │
│  3. 流水線平行（Pipeline Parallel）             │
│     - 通訊：層間傳遞                         │
│     - 頻率：每批次傳渡                      │
│     - 需求：低頻寬但需保證時序            │
└─────────────────────────────────────────────────┘
```

### All-Reduce 通訊

```
All-Reduce 通訊：
┌─────────────────────────────────────────────────┐
│  目的：所有 GPU 獲得所有其他 GPU 的總和       │
│                                                  │
│  梯度同步（數據平行）：                          │
│  ┌──────────────────────────────────────────┐   │
│  │  GPU 0  GPU 1  GPU 2  GPU 3             │   │
│  │  │      │      │      │                 │   │
│  │  g0     g1     g2     g3                │   │
│  │  └──┬───┴──┬───┴──┬───┘               │   │
│  │     └───── All-Reduce ─────┘           │   │
│  │       ↓     ↓     ↓     ↓              │   │
│  │  g0+g1+g2+g3 (所有 GPU)               │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  演算法：                                        │
│  - Ring All-Reduce：環狀傳遞                   │
│  - Tree All-Reduce：樹狀聚聚                    │
│  - 減少資料量可降低通訊成本                │
└─────────────────────────────────────────────────┘
```

## 聚合通訊

### 集合操作

```
集合通訊操作：
┌─────────────────────────────────────────────────┐
│  常用操作：                                      │
│  ┌──────────────────────────────────────────┐   │
│  │  1. Broadcast（廣播）                   │   │
│  │     一個節點 → 所有節點                 │   │
│  │                                          │   │
│  │  2. Reduce（歸約）                      │   │
│  │     所有節點 → 一個節點                 │   │
│  │                                          │   │
│  │  3. All-Reduce（全歸約）                │   │
│  │     所有節點 → 所有節點                 │   │
│  │                                          │   │
│  │  4. All-Gather（全收集）                │   │
│  │     每個節點收集所有節點的資料          │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  硬體加速：                                      │
│  - NVIDIA NVSwitch 支援硬體 Aggregation        │
│  - 減少 CPU 調度負擔                          │
│  - 提升歸約效能                                │
└─────────────────────────────────────────────────┘
```

## 本章小結

- Scale-Up 增加單節點資源，Scale-Out 增加節點數量
- Scale-Up 使用 NVLink/CXL 等高速互連
- Scale-Out 使用乙太網路/InfiniBand
- 不同平行模式需要不同的通訊強度
- 通訊瓶頸是大規模 AI 系統的關鍵挑戰
- 未來趨勢包括光學互連與硬體化集合通訊
