# 4.4 C 擴充：16-bit 壓縮指令與程式碼密度優化

> 快閃記憶體（Flash）每 KB 都是錢，取指頻寬（Fetch Bandwidth）每瓦都是電。C 擴充（Compressed）用 16 位指令把程式碼壓小 25–30%，而效能幾乎不掉。

## 開場動機：32 位指令太「胖」嗎？

統計顯示：最常用的指令（`addi/lw/sw/beq/jal`）其暫存器編號、立即數常常很小，32 位編碼大半在浪費。C 擴充挑出高頻指令，給它們 16 位短碼：常用暫存器（x8–x15）用 3 位編、常用立即數截短，解碼時硬體再展開成 32 位執行——**編譯器無感、管線無感，只有 Flash 與 I-Cache 有感**。

## 核心講解：C 指令代表表

| 16 位指令 | 對應 32 位 | 節省原理 |
|-----------|------------|----------|
| `c.addi rd, nzimm` | `addi` | 短立即數（6 位），rd/rs1 共用欄位 |
| `c.mv rd, rs2` | `add rd, x0, rs2` | 隱含 x0，省一個來源欄位 |
| `c.li rd, imm` | `addi rd, x0, imm` | 同上，載入小常數 |
| `c.lw rd', off(rs1')` | `lw` | rd'/rs1' 限 x8–x15（3 位編碼，CL 格式） |
| `c.sw rs2', off(rs1')` | `sw` | 同上，Load/Store 配對壓縮 |
| `c.addi16sp / c.addi4spn` | `addi sp, sp, imm` | 堆疊調整專用短碼（函式進出必備） |
| `c.beqz / c.bnez rs', off` | `beq/bne rs', x0, off` | 隱含 x0 的判零分支 |
| `c.j / c.jal` | `jal x0/jal ra` | 短跳轉（±2KB） |
| `c.jr / c.jalr rs1` | `jalr` | 間接跳、返回（`c.jr ra` = ret） |

### 關鍵機制

| 機制 | 說明 |
|------|------|
| 長度判斷 | bit[1:0] ≠ 11 即 16 位指令（32 位指令 bit[1:0]=11），取指器一看便知 |
| 對齊放寬 | 開 C 後指令 2 位元組對齊即可，PC 最低位仍恆零但次低位可為 1 |
| 展開執行 | 解碼前端把 16 位展開為對等 32 位，後端管線完全不用改 |
| 常用暫存器窗口 | 3 位欄位只能編 x8–x15——編譯器配置時偏好這 8 個即得高壓縮率 |
| 取指對齊 | 32 位指令不能橫跨 4 位元組邊界，連結器（Linker）負責填補對齊 |
| 例外返回 | `mepc/sepc` 最低位可為 1（2 位元組對齊），`mret/sret` 直接跳回 |
| 效能實測 | SPEC 測試顯示開 C 後 I-Cache 缺失率下降，取指頻寬等效提升約三成 |

## 範例：壓縮前後對照

```asm
# 未壓縮（RV32I）：函式序幕 3 條 32-bit = 12 位元組
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)

# 開 C 擴充後（RV32IC）：同等語意，16-bit 短碼 = 6 位元組，省一半
    c.addi16sp sp, -16    # sp 調整專用短碼
    c.swsp ra, 12(sp)     # c.swsp：以 sp 為基址的壓縮儲存
    c.swsp s0, 8(sp)

# 分支/跳轉對照
    beqz a0, done         # 32-bit：beq a0, x0, done
    c.beqz a0, done       # 16-bit：隱含 x0，語意相同
done:
    ret                   # c.jr ra（16-bit）
```

```c
// 體積實驗：同一份韌體，比較 -march 差異
int blink(int n) {        // 假想 LED 韌體片段
    int s = 0;
    for (int i = 0; i < n; i++) s += i;
    return s;
}
// rv32imac：  迴圈約 6 條，多為 16-bit，.text 最小
// rv32ima ：  全 32-bit，.text 大 ~30%
// 量測：riscv64-unknown-elf-size a.out
```

## 本節小結

- C 擴充 = 高頻指令的 16 位短碼，程式碼體積省 25–30%，效能損失通常 <5%。
- 判斷法：bit[1:0]≠11 即壓縮指令；x8–x15 是 3 位窗口的寵兒。
- 開 C 後對齊放寬為 2 位元組，`jalr` 清零最低位仍保證正確。
- 解碼前端展開、後端管線不動——硬體代價小、軟體收益大。
- MCU（Flash 受限）必開 C；Linux 應用核（`rv64gc`）同樣標配。
- 下一節玩轉位元：B 擴充。
