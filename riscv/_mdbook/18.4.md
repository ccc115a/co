# 18.4 Linker Script 與 Sections

## 動機：程式碼放在哪裡，本身就是程式的一部分

同一個 `main.elf`，放在 QEMU `virt` 機器的 `0x80000000` 能跑，燒進 MCU 的 Flash `0x08000000` 卻死機——差別不在程式邏輯，而在連結腳本（Linker Script）描述的記憶體佈局。Bare-Metal 世界沒有作業系統幫你安排位址，`.text` 放 Flash 還是 RAM、堆疊頂設在哪、中斷向量表是否 256 位元組對齊，全由你手上的 `.ld` 檔決定。

本節核心觀念：**編譯器產生 section（節），連結器按腳本把 section 擺進記憶體**。讀懂這句話，就讀懂了韌體開機的一半。

## 核心講解

### 1. ELF 三大段與常見 Sections

| Section | 全名 | 內容 | 屬性 |
|---------|------|------|------|
| `.text` | 程式碼段 | 機器指令、`entry.S` 進入點 | 可執行、唯讀 |
| `.rodata` | 唯讀資料 | 字串常數、const 表格 | 唯讀、不可執行 |
| `.data` | 已初始化資料 | `int x = 5;` | 可讀寫，開機需從 Flash 拷貝到 RAM |
| `.bss` | 未初始化資料 | `static int y;` | 可讀寫，開機需清零 |
| `.stack` / `.heap` | 堆疊/堆積 | 執行期動態使用 | 由符號 `_stack_top`、`_end` 界定 |
| `.trapvec`（自訂） | 中斷向量 | trap 入口 | 需對齊（`mtvec` 要求） |

`crt0.s` 開機做的兩件事——「拷貝 `.data`、清零 `.bss`」——需要的起止符號（`_sdata`、`_edata`、`_sbss`、`_ebss`）正是 Linker Script 提供的。

### 2. MEMORY 與 SECTIONS：腳本的兩根支柱

- `MEMORY`：描述實體記憶體塊（Flash 起始/長度、RAM 起始/長度）。
- `SECTIONS`：描述每個 section 要放進哪個記憶體塊、對齊多少、定義哪些符號。

| 指令 | 作用 | 範例 |
|------|------|------|
| `ENTRY(sym)` | 指定進入點 | `ENTRY(_start)` |
| `PROVIDE(sym = .)` | 若未定義才提供符號 | `PROVIDE(_stack_top = ORIGIN(RAM)+LENGTH(RAM))` |
| `ALIGN(n)` / `ALIGNOF` | 對齊 | `.trapvec : { . = ALIGN(256); }` |
| `AT>` | 指定載入位址（LMA）與執行位址（VMA）分離 | `.data : AT(ADDR(FLASH)+SIZEOF(.text))` |
| `KEEP()` | 防止被 `--gc-sections` 丟棄 | `KEEP(*(.trapvec))` |

VMA（執行位址）vs. LMA（載入位址）是本節最易混的詞：`.data` 在 Flash 有一份初始值（LMA），開機拷貝到 RAM 執行（VMA），兩者不同是正常的。

### 3. 連結流程速覽

`entry.o + main.o + libc.a --(foo.ld)--> foo.elf`，再用 `objcopy -O binary` 去掉 ELF 標頭得到可燒錄映像。檢查三件套：`readelf -S`（sections）、`readelf -l`（segments）、`nm --print-size`（符號位址）。

## 範例：RV32 MCU 最小連結腳本

```ld
/* mcu.ld：Flash 0x08000000 (256K)，RAM 0x20000000 (64K) */
ENTRY(_start)
MEMORY {
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 256K
  RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 64K
}
SECTIONS {
  .text : {
    KEEP(*(.vectors))   /* 中斷向量表，不可被 GC */
    *(.text*) *(.rodata*)
    . = ALIGN(4);
    _etext = .;
  } > FLASH

  .data : AT(ADDR(FLASH) + SIZEOF(.text)) {
    . = ALIGN(4);
    _sdata = .;
    *(.data*) *(.sdata*)
    . = ALIGN(4);
    _edata = .;
  } > RAM

  .bss (NOLOAD) : {
    . = ALIGN(4);
    _sbss = .;
    *(.bss*) *(.sbss*) *(COMMON)
    . = ALIGN(4);
    _ebss = .;
  } > RAM

  PROVIDE(_stack_top = ORIGIN(RAM) + LENGTH(RAM));
  PROVIDE(_end = _ebss);
}
```

```bash
# 連結 + 檢查 + 轉燒錄檔
riscv64-unknown-elf-gcc -march=rv32imac -mabi=ilp32 \
  -nostdlib -T mcu.ld entry.S main.c -o fw.elf
riscv64-unknown-elf-readelf -S fw.elf | grep -E 'text|data|bss'
riscv64-unknown-elf-nm fw.elf | grep -E '_start|_sdata|_stack_top'
riscv64-unknown-elf-objcopy -O binary fw.elf fw.bin
ls -l fw.elf fw.bin
```

> 實驗分級 ★★：故意把 `ENTRY` 改錯，觀察 `readelf -h` 的 Entry point 變化；再拿掉 `KEEP(*(.vectors))` 加 `-Wl,--gc-sections`，看向量表是否消失。

## 本節小結

- 連結腳本回答「什麼放哪裡」：`MEMORY` 定義實體塊，`SECTIONS` 分配 sections 並輸出開機符號。
- `.data` 要拷貝、`.bss` 要清零，起止符號由腳本提供、`crt0.s` 取用，兩者是契約關係。
- VMA/LMA 分離、`ALIGN`、`KEEP` 是韌體腳本的三個關鍵字，缺一不可。
- 每次改腳本後用 `readelf -S` + `nm` 驗證，不要憑感覺燒板。

2. 中斷向量表為何要用 `KEEP()` 保護？`--gc-sections` 的垃圾回收機制如何誤判它是無用段？
