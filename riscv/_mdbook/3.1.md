# 3.1 六大指令格式解析（R/I/S/B/U/J-type）

> RISC-V 全部指令只有六種格式。本節背後的觀念只有一句：**編碼為解碼器服務，六種格式讓關鍵欄位永遠在固定位置**。

## 開場動機：為什麼格式越少越好？

解碼器（Decoder）是 CPU 的門面：每個週期都要從 32 位機器碼切出 opcode、來源暫存器（rs1/rs2）、目的暫存器（rd）、立即數（Immediate）。若每條指令欄位位置都不同，解碼就是一團多工器（MUX）惡夢。RISC-V 的解法：**rs1/rs2/rd 永遠在同一位元位置**，只有立即數的拼裝方式分六種。

## 核心講解：六格式位元表

### 總覽：欄位固定位置

| 格式 | 用途代表 | 位元佈局（31→0，高位在左） |
|------|----------|---------------------------|
| R | `add` | funct7[31:25] \| rs2[24:20] \| rs1[19:15] \| funct3[14:12] \| rd[11:7] \| opcode[6:0] |
| I | `addi`/`lw`/`jalr` | imm[31:20] \| rs1[19:15] \| funct3[14:12] \| rd[11:7] \| opcode[6:0] |
| S | `sw` | imm[11:5][31:25] \| rs2[24:20] \| rs1[19:15] \| funct3[14:12] \| imm[4:0][11:7] \| opcode[6:0] |
| B | `beq` | imm[12\|10:5][31:25] \| rs2 \| rs1 \| funct3 \| imm[4:1\|11][11:7] \| opcode |
| U | `lui` | imm[31:12][31:12] \| rd[11:7] \| opcode[6:0] |
| J | `jal` | imm[20\|10:1\|11\|19:12][31:12] \| rd[11:7] \| opcode[6:0] |

關鍵設計：

| 設計巧思 | 說明 |
|----------|------|
| rs1/rs2/rd 位置固定 | R/I/S/B 四種格式的 rs1、rs2、rd 位元範圍完全相同，解碼可並行讀暫存器檔 |
| 立即數符號位固定 | 六種格式的符號位永遠在 bit 31，符號擴展（Sign-extension）電路只需看一位 |
| S/B 共用、U/J 共用 | S 與 B 的 rs 欄位相同、U 與 J 的 rd 位置相同，硬體可複用 |
| B/J 最低位恆零 | 分支/跳轉偏移最低位不編碼（指令至少 2 位元組對齊），省出一位給更大範圍 |

### opcode 速查

| opcode[6:0] | 格式 | 指令群 |
|-------------|------|--------|
| 0110011 | R | ALU（add/sub/sll/slt/xor/srl/or/and） |
| 0010011 | I | ALU 立即數（addi/slti/xori/ori/andi/slli/srli） |
| 0000011 | I | 載入（lb/lh/lw/lbu/lhu） |
| 0100011 | S | 儲存（sb/sh/sw） |
| 1100011 | B | 分支（beq/bne/blt/bge/bltu/bgeu） |
| 1101111 | J | jal |
| 1100111 | I | jalr |
| 0110111 | U | lui |
| 0010111 | U | auipc |

## 範例：手解一條機器碼

```asm
# 已知機器碼 0x00208133，請解碼（紙筆練習經典題）
# 0x00208133 = 0000_0000_0010_0000_1000_0001_0011_0011
# opcode[6:0] = 0110011 -> R-type
# rd  = [11:7]  = 00010 = x2? 先別急，繼續切：
# funct3[14:12] = 000, rs1[19:15] = 00001 (x1), rs2[24:20] = 00010 (x2)
# rd[11:7] = 00010 (x2), funct7 = 0000000 -> ADD
# 結論：add x2, x1, x2

# 再看一條 I-type：addi a0, a1, 10
# addi opcode=0010011, funct3=000, rd=a0=x10, rs1=a1=x11, imm=10
    addi a0, a1, 10      # 組譯後：0x00A58513，可用 objdump 驗證
```

```c
// 用 C 驗證解碼：把機器碼切欄位（僅示意 R-type）
#include <stdio.h>
#include <stdint.h>
void decode_r(uint32_t w) {
    printf("opcode=%02x rd=%u funct3=%u rs1=%u rs2=%u funct7=%02x\n",
        w & 0x7F, (w >> 7) & 0x1F, (w >> 12) & 0x7,
        (w >> 15) & 0x1F, (w >> 20) & 0x1F, (w >> 25) & 0x7F);
}
int main(void) { decode_r(0x00208133); return 0; }  // 應印出 add x2,x1,x2
```

## 本節小結

- 六格式本質是「**三個暫存器欄位固定 + 六種立即數拼法**」。
- 符號位恆在 bit 31，B/J 最低位恆零，都是為解碼器省電路。
- opcode 一眼分類：`0110011`=R、`0010011`=I-ALU、`0000011`=Load、`0100011`=Store、`1100011`=Branch。
- 手解 `0x00208133 = add x2, x1, x2` 是本節必會考題。
- 後四節（3.2–3.5）就是把這六格式逐一填上語意。
