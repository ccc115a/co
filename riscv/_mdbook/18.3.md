# 18.3 組語與 Inline Assembly

## 動機：何時必須放下 C 語言？

C 語言能表達演算法，但表達不了三件事：開機第一條指令要放哪裡、上下文切換（Context Switch）時如何精確保存 32 個暫存器、`wfi`、`csrrw` 這類特權指令怎麼發。這些工作屬於組合語言（Assembly Language）的領地，而作業系統核心、中斷服務常式（ISR）、`crt0.s` 啟動碼，全都繞不開它。

本節的核心觀念：**組語是硬體的直接投影**，而行內組語（Inline Assembly）則是 C 與硬體之間的逃生門——用最小的組語片段，換取對暫存器與指令的精確控制。

## 核心講解

### 1. RISC-V 組語基本功

RISC-V 組語採用 `op rd, rs1, rs2` 格式，目的暫存器永遠在前。常用虛擬指令（Pseudo-instructions）由組譯器展開：

| 虛擬指令 | 展開 | 用途 |
|----------|------|------|
| `nop` | `addi x0, x0, 0` | 空操作、對齊 |
| `mv rd, rs` | `addi rd, rs, 0` | 暫存器搬移 |
| `li rd, imm` | `lui` + `addi` 組合 | 載入大常數 |
| `call sym` | `auipc` + `jalr` | 遠跳躍呼叫 |
| `ret` | `jalr x0, 0(ra)` | 函式返回 |
| `la rd, sym` | `auipc` + `addi` | 取符號位址 |

ABI 暫存器別名一定要熟（詳見 2.3 節）：`zero`、`ra`、`sp`、`gp`、`tp`、`t0-t6`、`s0-s11`、`a0-a7`。寫組語時用別名， C 函式用 `a0-a1` 回傳、`a0-a7` 傳參、`ra` 存返回位址，這是手寫 `crt0.s` 與 trap 入口的基礎。

### 2. GCC Inline Assembly 模板解剖

```c
__asm__ volatile (
  "csrrw %0, mstatus, %1"   // 組語模板
  : "=r" (old)              // 輸出（output）：寫入 C 變數
  : "r" (new_val)           // 輸入（input）：讀取 C 變數
  : "memory"                // 破壞描述（clobber）：告知編譯器副作用
);
```

| 元素 | 含義 | 常見取值 |
|------|------|----------|
| `volatile` | 禁止編譯器刪除或搬移 | 涉及 CSR、IO 必加 |
| `"=r"` | 只寫輸出，配置任一通用暫存器 | `"=r"`、`"=a"` |
| `"r"` / `"i"` | 暫存器輸入 / 立即數 | `"r"`、`"i"`、`"m"`（記憶體） |
| `"memory"` | 會讀寫記憶體，禁止重排 | MMIO、鎖必加 |

一句話記憶：**模板寫指令，冒號後寫合約**——你必須誠實告訴編譯器你碰了什麼，否則優化器會把你的程式「優化」成錯誤程式。

### 3. 什麼該用純組語 `.S`，什麼該用 Inline？

| 場景 | 選擇 | 原因 |
|------|------|------|
| `crt0.s`、trap 向量表 | 純組語 `.S` 檔 | 需精確控制 section 與對齊 |
| 上下文切換 `swtch.S` | 純組語 | 一次存取全部暫存器 |
| 讀寫單一 CSR | Inline Assembly | 一兩條指令，留在 C 流程中 |
| MMIO 輪詢、記憶體屏障 | Inline Assembly | 需 `volatile` 語義 |

## 範例：讀 CSR 與 MMIO 點燈

```c
// 例 1：讀寫 CSR（Inline Assembly，存檔為 csr.h）
#include <stdint.h>
static inline uint64_t r_mstatus(void) {
  uint64_t x;
  __asm__ volatile ("csrr %0, mstatus" : "=r" (x));
  return x;
}
static inline void w_mstatus(uint64_t x) {
  __asm__ volatile ("csrw mstatus, %0" :: "r" (x));
}

// 例 2：MMIO 輪詢 UART（假設基址 0x10000000）
#define UART_THR (*(volatile uint8_t *)0x10000000UL)
#define UART_LSR (*(volatile uint8_t *)0x10000005UL)
void uart_putc(char c) {
  while (!(UART_LSR & 0x20)) {
    __asm__ volatile ("nop");  // 防止空迴圈被優化掉
  }
  UART_THR = (uint8_t)c;
}
```

```bash
# 組譯並觀察：純組語檔 + C 檔混合連結
riscv64-unknown-elf-gcc -march=rv32imac -mabi=ilp32 \
  -c entry.S -o entry.o
riscv64-unknown-elf-gcc -march=rv32imac -mabi=ilp32 \
  -c main.c -o main.o
riscv64-unknown-elf-objdump -d entry.o | head -40
```

> 實驗分級 ★★：在 `entry.S` 寫一個只做 `li a0, 42; ret` 的函式，從 C 呼叫並列印回傳值，用 `objdump` 驗證 `a0` 傳參。

## 本節小結

- 純組語掌管開機、trap、上下文切換；Inline Assembly 處理 CSR、MMIO、屏障等小粒度硬體操作。
- Inline 模板 = 指令 + 輸入/輸出/破壞描述三段冒號，`volatile` 與 `"memory"` 是正確性的關鍵。
- 虛擬指令（`li`、`la`、`call`、`ret`）與 ABI 別名是閱讀反組譯的必備詞彙。
- 凡是編譯器看不見的副作用（CSR、MMIO），都要在 clobber 中誠實宣告。
