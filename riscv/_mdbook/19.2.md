# 19.2 AI/ML 加速器自訂指令實戰

## 動機：從一條指令到一座加速器

19.1 節的一條 `xor3` 省幾個週期；AI 推論要省的是幾個數量級。神經網路 90% 時間花在矩陣乘加（MAC，Multiply-Accumulate）與卷積滑窗上，通用管線每個 MAC 要取指、解碼、取數三次，而脈動陣列（Systolic Array）一個週期可吞吐上百個 MAC。RISC-V 的自訂指令就是 CPU 與這類加速器之間的橋樑。

本節核心觀念：**指令是加速器的門鈴，不是加速器本身**——CPU 用自訂指令下達「開始算、搬哪塊、算完通知我」，真正的資料搬移由 DMA 與片上緩衝（Scratchpad）完成。

## 核心講解

### 1. 三種耦合緊密度：選錯就卡死

| 耦合方式 | 位置 | 延遲 | 適合工作 |
|----------|------|------|----------|
| 緊耦合（Tightly-Coupled） | 執行級旁的 ALU 擴充 | 1–3 週期 | 量化 `dotp`、啟動函數近似、S-box |
| 鬆耦合協處理器（Loosely-Coupled RoCC） | 經 RoCC 介面外掛 | 數十週期 + DMA | 卷積 tile、矩陣乘方塊 |
| 獨立加速器（MMIO + 中斷） | 匯流排上的設備 | 數百週期以上 | 整層 transformer、整圖推論 |

Rocket Chip 的 RoCC（Rocket Custom Coprocessor Interface）是教學首選：它把加速器掛在核心旁，有自己的暫存器檔與 DMA 通道，CPU 用 `custom-2` 發命令，既不污染主 statu 管線，又比 MMIO 快一個數量級。

### 2. AI 算子到指令的映射表

| AI 熱點 | 數學形態 | 自訂指令設計 | 資料路徑 |
|---------|----------|--------------|----------|
| INT8 量化點積 | `sum(a[i]*b[i])` | `dotp8 rd, rs1, rs2`（32 位暫存器各塞 4×int8） | 緊耦合 ALU，單週期 4 MAC |
| 16 位累加卷積 | tile MAC + 累加 | `macc.cfg / macc.run`（組態 + 啟動） | RoCC + 內部累加器 |
| ReLU/量化重縮放 | `max(0, x*s+z)` | `relu.q rd, rs1, rs2` | 緊耦合，查表或比較器 |
| DMA 搬運權重 | 2D tile 拷貝 | `dma.copy len, src, dst` | RoCC 發 DMA，CPU 繼續算（雙緩衝） |

設計鐵律：**算術指令不碰記憶體，搬運指令不算術**。混在一起的指令會同時惹上 TLB 缺頁與管線停頓，除錯地獄就此開始。

### 3. 精度與驗證：AI 指令最痛的兩件事

AI 常用 INT8/FP16/BF16，溢位與捨入（Rounding）語義必須與軟體黃金模型（Golden Model，通常是 PyTorch）位元一致。建議流程：PyTorch 產生測資 → Spike 功能模型對拍 → RTL 跑同一測資，三方雜湊一致才算過。19.3 節的模擬器擴充就是這條鏈的第一步。

## 範例：INT8 點積 `dotp8` 的軟體側

```c
// dotp8：rs1/rs2 各含 4 個 int8，一次完成 4 乘 3 加並累加到 rd
#include <stdint.h>
// 假設編碼：custom-0, funct3=1, funct7=0x02
static inline uint32_t dotp8(uint32_t acc, uint32_t a, uint32_t b) {
  uint32_t r;
  __asm__ volatile (
    ".insn r 0x0b, 1, 0x02, %0, %1, %2"
    : "=r" (r) : "r" (acc), "r" (a), "r" (b));
  // 真實語義由 Spike/RTL 實現：r = acc + Σ a[i]*b[i]
  return r;
}

// 4x4 INT8 矩陣乘法內核（展示如何用 dotp8 疊 tile）
int32_t matmul_tile(int8_t A[4][4], int8_t B[4][4], int r, int c) {
  uint32_t acc = 0;
  for (int k = 0; k < 4; k += 4) {
    uint32_t a_pack = *(uint32_t *)&A[r][k];
    // B 需先轉置打包，此處簡化
    uint32_t b_pack = *(uint32_t *)&B[k][c];
    acc = dotp8(acc, a_pack, b_pack);
  }
  return (int32_t)acc;
}
```

```bash
# 產生黃金測資（主機 Python）並與 Spike 擴充版對拍
python3 gen_golden.py --tile 4 --dtype int8 --out golden.hex

spike --extension=dotp8 pk dotp8.elf   # 需先完成 19.3 的擴充

```

## 本節小結

- AI 加速 = 自訂指令（門鈴）+ DMA/Scratchpad（苦力）+ 雙緩衝（隱藏延遲），三者缺一不可。
- 緊耦合做點積/啟動函數，RoCC 做卷積 tile，整層推論交給 MMIO 加速器——按延遲選位。
- 算術與搬運分離、與 PyTorch 黃金模型位元對齊，是 AI 指令的兩條生死線。
- 先在 Spike 把語義跑通，再進 RTL，順序反了會付出十倍除錯成本。
