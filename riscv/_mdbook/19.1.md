# 19.1 自訂擴充指令

## 動機：標準指令不夠用時，該改軟體還是改硬體？

通用指令做 AES 加密要上百個週期，影像去馬賽克要大量位元搬移迴圈——這時與其把 CPU 時脈拉高，不如加一條專用指令。RISC-V 把這條路寫進了 ISA 基因：預留 Custom opcode 空間（自訂操作碼空間），任何人不用申請授權就能定義自己的指令，這正是特定領域架構（Domain-Specific Architecture, DSA）的起點。

本節核心觀念：**自訂指令 = 省下的週期 × 出貨量**。在你畫第一張編碼表之前，先學會算這筆帳，並認清 opcode 空間的邊界。

## 核心講解

### 1. RISC-V 自訂 opcode 空間一覽

RISC-V 用最低 7 位元 `opcode` 區分大類，其中四組完整保留給自訂：

| opcode（7 位元） | 名稱 | 說明 |
|------------------|------|------|
| `0001011` | `custom-0` | R-type 自訂，最常用，新手首選 |
| `0101011` | `custom-1` | R-type 自訂，與 custom-0 對稱 |
| `1011011` | `custom-2` | R-type 自訂，常給雙槽/加速器用 |
| `1111011` | `custom-3` | R-type 自訂，RV128 保留但暫可借用 |
| `0001010` 等（12 位元前綴） | N 擴充保留 | 使用者級中斷相關，勿碰 |
| 其餘標準 opcode | 标准指令 | M/A/F/D/C/V 等已佔用，擠進去即不相容 |

實務建議：只用 `custom-0` 起步。`funct7 + rs2 + rs1 + funct3 + rd + opcode` 的 R-type 格式可提供 `funct3`（3 位）× `funct7`（7 位）= 1024 種子操作，足夠容納一個小型加速器家族。

### 2. 設計自訂指令的三步法

1. **畫像（Profile）**：用 `perf` 或 Spike 計數找出熱點——占比 < 5% 的函式不值得做成指令。
2. **定語義（Semantics）**：寫下「輸入哪兩個暫存器、輸出到哪、是否碰記憶體」。只做暫存器到暫存器（R-type）最安全；碰記憶體就要處理對齊、例外與 MMU，複雜度暴增十倍。
3. **編碼（Encoding）**：填 `funct7/funct3`，並檢查是否與未來想用的標準擴充（B/V）衝突。

| 設計決策 | 保守選項 | 激進選項 |
|----------|----------|----------|
| 操作數 | R-type（`rd = f(rs1, rs2)`） | 含記憶體存取 |
| 狀態 | 無狀態（純組合邏輯） | 自帶內部暫存器/累加器 |
| 例外 | 永不觸發例外 | 可能缺頁、可能非對齊 |
| 驗證 | Spike 功能模型先行 | 直接改 RTL |

新手鐵律：**第一條自訂指令必須是無狀態 R-type**。先讓工具鏈、模擬器、RTL 三方對齊，再談累加器與 DMA。

### 3. 軟硬體合約：誰認識新指令？

加一條指令要同步四處：編譯器（intrinsic 或 inline asm 發射）、組譯器（認得助憶符）、模擬器（Spike/QEMU 行為模型）、硬體解碼器（RTL case 分支）。任一處缺席就會出現「組譯過了模擬器非法指令」或「模擬器過了上板當機」。19.3 節會帶你走完模擬器側。

## 範例：自訂 `xor3` 指令（一條指令做三次異或）

假設熱點是 `rd = rs1 ^ rs2 ^ 0x5A5A`，定義 `custom-0`、`funct3 = 0`、`funct7 = 0x01`。

```c
// 用 .insn 偽指令發射，不需改組譯器即可實驗（GCC/Clang 皆支援）
#include <stdint.h>
// .insn r opcode, funct3, funct7, rd, rs1, rs2
#define XOR3(rd, rs1, rs2) \
  __asm__ volatile (".insn r 0x0b, 0, 0x01, %0, %1, %2" \
    : "=r" (rd) : "r" (rs1), "r" (rs2))

uint32_t my_xor3(uint32_t a, uint32_t b) {
  uint32_t r;
  XOR3(r, a, b);   // 語義：r = a ^ b ^ 0x5A5A（由硬體/模擬器實現）
  return r;
}
```

```bash
# 編譯並確認編碼位元正確
riscv64-unknown-elf-gcc -march=rv32imac -mabi=ilp32 \
  -O2 -c custom_demo.c -o custom_demo.o
riscv64-unknown-elf-objdump -d custom_demo.o
# 在反組譯中找到 0x0b opcode 的字組，核對 funct7/funct3
```

> 實驗分級 ★★★：先在 Spike 側把該編碼實作成純軟體語義（見 19.3），再用 Verilog 在你的單週期 CPU 加一個 `case (opcode == 7'b0001011)` 分支，比對兩者結果一致。

> 對應範例：[`_code/ch19/custom_add.s`](_code/ch19/README.md) 用 `.insn` 發出一條 custom-0 指令，`make -C _code/ch19 check` 驗證 opcode 並跑解碼自查。

## 本節小結

- RISC-V 預留四組 custom opcode，其中 `custom-0`（`0001011`）是新手起點。
- 好設計始於 Profiling：先證明熱點值得，再定 R-type 無狀態語義，最後填編碼。
- 一條指令牽動編譯器、組譯器、模擬器、RTL 四方，缺一不可，建議用 `.insn` 先行實驗。
- 碰記憶體、帶狀態的指令留到 19.2 節，與加速器一起設計。
