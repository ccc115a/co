# 17.2 虛擬記憶體佈局與 Early Page Table 初始化

## 動機：核心還沒醒來，頁表從哪長出來？

Linux RISC-V 預設跑 Sv39/Sv48，但開機最初 MMU 是關的、DRAM 布局未知（只知 DTB 說了什麼）。
`head.S` 必須用「位置無關（Position-Independent）的 Early Page Table」
把核心鏡像（`vmlinux` 跑在高位 `PAGE_OFFSET=0xffffff...c0000000`）先映射起來，
才能跳入 C 語言的 `setup_arch()`，再由 `paging_init()` 換上正式頁表。
本節解剖這「先有雞（頁表）還是先有蛋（C 環境）」的破局法。

核心觀念：**Early Page Table 是用組語手刻的一次性鷹架，正式頁表才是鋼骨大樓**。

## 17.2.1 虛擬記憶體佈局：誰住高位、誰住低位？

| 區域 | VA 範圍（Sv39，PAGE_OFFSET 方案） | 內容 |
|---|---|---|
| 使用者空間 | `0x00000000_00000000 – 0x0000003f_ffffffff` | 使用者進程（每進程私有） |
| 直接映射區（Linear Map） | `PAGE_OFFSET – PAGE_OFFSET+DRAM` | 全部實體記憶體 `__va(pa)` |
| vmalloc 區 | 線性區之上 | `vmalloc/iomap` 動態映射 |
| 核心鏡像 | `KERN_VIRT – KERN_VIRT+size` | `.text/.data/.bss`（2 MiB 大頁映射） |
| Fixmap/DTB | 頂部固定窗口 | 早期 `fixmap`＋DTB 暫映射 |

```c
// arch/riscv/include/asm/page.h（概念）— __va/__pa 互轉
#define PAGE_OFFSET      0xff60000000000000UL  /* Sv39 線性區基（依版本略異） */
#define __va(x)          ((void *)((unsigned long)(x) + PAGE_OFFSET - PHYS_BASE))
#define __pa(x)          ((unsigned long)(x) - PAGE_OFFSET + PHYS_BASE)
```

## 17.2.2 head.S 手刻頁表：大頁一錘定音

```asm
# arch/riscv/kernel/head.S（概念簡化）— 建 1 GiB/2 MiB 大頁映射
    la t0, early_pg_dir          # 根表（編譯期靜態保留 .bss）
    # 1. 映射核心鏡像：VA(KERN_VIRT) → PA(PHYS_BASE)，2 MiB 葉
    # 2. 映射線性區：VA(PAGE_OFFSET) → PA(DRAM_BASE)，1 GiB 葉
    li t1, (PTE_V | PTE_R | PTE_W | PTE_X | PTE_G | PTE_A | PTE_D)
    sd t1, 0(t0)                 # 填 PTE（示意，實作迴圈填多項）
    # 3. satp = MODE_SV39 | PPN(early_pg_dir)，sfence.vma，relocate 跳高位
    la t2, early_pg_dir
    srli t2, t2, 12
    li t3, SATP_MODE_SV39 << 60
    or t2, t2, t3
    csrw satp, t2
    sfence.vma
```

用大頁（Megapage）是刻意為之：Early 階段只需「能跑」，1–2 個 PTE 即覆蓋 GB 級，
省去層層建表；`PTE_G`（全域）避免切換 `satp` 被沖掉。

## 17.2.3 paging_init：換正式頁表（swapper_pg_dir）

```bash
# 編譯核心並在 QEMU 觀察早期開機訊息（earlycon 直連 UART）
export ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu-
make defconfig && make -j$(nproc) Image
qemu-system-riscv64 -machine virt -nographic -bios default -kernel arch/riscv/boot/Image \
  -append "console=ttyS0 earlycon=sbi ro root=/dev/vda" \
  -drive file=rootfs.ext2,if=none,format=raw,id=hd0 \
  -device virtio-blk-device,drive=hd0,bus=virtio-mmio-bus.0
# dmesg | grep -i "Memory:\|paging\|satp" 可見線性區與可用記憶體統計
```

```c
// arch/riscv/mm/init.c（節選概念）
void __init paging_init(void) {
    setup_vm_final();            // 建 swapper_pg_dir：核心鏡像 4 KiB 精細映射
    setup_zero_page();           // 零頁（COW 起點）
    zone_sizes_init();           // 依 memblock 劃 DMA/NORMAL zone
}
```

```mermaid
flowchart LR
    A["MMU OFF<br/>PA 跑 head.S"] --> B["early_pg_dir<br/>大頁映射"]
    B --> C["satp + sfence<br/>跳高位 VA"]
    C --> D["setup_arch<br/>解析 DTB/bootmem"]
    D --> E["paging_init<br/>swapper_pg_dir"]
    E --> F["MMU ON 常態<br/>4 KiB 精細頁"]
```

## 本節小結

- 布局三分：低位使用者、私有核心鏡像、全域線性直接映射。
- Early 表用 1 GiB/2 MiB 大頁「求有」，正式表用 4 KiB「求好」。
- `satp`＋`sfence.vma`＋高位跳轉是 Early 啟用的標準三連。
