# 20.1 向量擴充與 HPC/車用趨勢

## 動機：為什麼超算與汽車同時看上 RISC-V？

頂級超算（HPC，High Performance Computing）要的是每瓦效能（Performance per Watt），車用晶片要的是長供貨週期與功能安全（Functional Safety）認證——這兩件事的交集，恰好是 RISC-V 向量擴充（Vector Extension, RVV）的強項：同一套 `vadd.vv` 指令，從嵌入式小核心到千核超算都能跑，只是向量長度（VLEN）不同。這種「寫一次，到處加速」的可攜性，是 NEON/SVE 陣營給不了的自由。

本節核心觀念：**向量長度無關（Length-Agnostic）編程**——軟體只說「對 N 個元素做運算」，硬體用多少 lane 由自己決定。

## 核心講解

### 1. RVV 關鍵思想：`vl`、`vtype`、`LMUL`

RVV 不固定暫存器寬度，而是靠三個 CSR 動態組態：

| 機制 | 寄存器/參數 | 作用 |
|------|-------------|------|
| `vtype` | 向量型態 CSR | 元素寬度（`e8/e16/e32/e64`）+ 分組倍率（LMUL） |
| `vl` | 向量長度 CSR | 本次實際處理幾個元素（由 `vsetvli` 回填） |
| `LMUL` | 分組倍率 | 把多個向量暫存器拼成一組（1/2/4/8），攤平長向量延遲 |
| `v0`（mask） | 遮罩暫存器 | 逐元素開關，取代分支（`vadd.vv ... , v0.t`） |
| Strip-mining | `vsetvli t0, a0, e32` | 「剩 `a0` 個、每次至多 `t0` 個」的迴圈正規寫法 |

Strip-mining 迴圈是 RVV 的 Hello World：硬體 VLEN=128 還是 1024，同一迴圈都能跑滿，只是迭代次數不同。

### 2. HPC 與車用為何選 RISC-V？

| 需求 | HPC（超算/AI 訓練） | 車用（ADAS/座艙） |
|------|---------------------|-------------------|
| 算力形態 | 長向量 + 矩陣（RVV + IME/AMX 類擴充） | 中向量 + 確定性延遲（RVV + 鎖步雙核） |
| 生態誘因 | 歐洲處理器計畫（EPI）、國產替代 | 擺脫授權 tied、手握原始碼做 ASIL-D 認證 |
| 代表晶片 | Esperanto ET-SoC（千核 RISC-V）、Ventana Veyron | SiFive Automotive、Renesas R-Car 新線 |
| 軟體棧 | LLVM 自動向量化 + MPI/OpenMP | AUTOSAR + 經認證的編譯器與 RTOS |
| 最大挑戰 | 記憶體頻寬牆（HBM/Chiplet） | 零失效率：ECC、鎖步（Lockstep）、追溯性 |

### 3. 與 Arm SVE / x86 AVX 的本質差異

| 特性 | RISC-V RVV | Arm SVE/SVE2 | x86 AVX-512 |
|------|------------|--------------|-------------|
| 向量長度 | 無關（同一二進位跑任意 VLEN） | 無關（但生態較封閉） | 固定（128/256/512 各一套指令） |
| 授權 | 開放免權利金 | 需架構授權 | 封閉 |
| 目標市場 | 從 MCU 到超算全光譜 | 行動/伺服器 | 伺服器/工作站 |

## 範例：RVV Strip-mining 向量加法

```c
// daxpy 風格：y[i] = a*x[i] + y[i]，長度無關寫法
#include <riscv_vector.h>
void daxpy_vec(size_t n, double a, double *x, double *y) {
  size_t vl;
  for (size_t i = 0; i < n; i += vl) {
    vl = __riscv_vsetvli(n - i, __riscv_e64, __riscv_m8);
    vfloat64m8_t vx = __riscv_vle64_v_f64m8(&x[i], vl);
    vfloat64m8_t vy = __riscv_vle64_v_f64m8(&y[i], vl);
    vy = __riscv_vfmacc_vf_f64m8(vy, a, vx, vl);
    __riscv_vse64_v_f64m8(&y[i], vy, vl);
  }
}
```

```bash
# 編譯並在 QEMU/Spike 上驗證（需 RVV 支援）
riscv64-linux-gnu-gcc -march=rv64gcv -mabi=lp64d \
  -O2 -o daxpy daxpy.c
qemu-riscv64 -cpu rv64,v=true,vext_spec=v1.0 ./daxpy
# 或用 Spike 指定向量長度：
spike --isa=rv64gcv --varch=vlen:128,elen:64 pk daxpy
```

> 實驗分級 ★★：分別用 `--varch=vlen:128` 與 `vlen:1024` 跑同一支二進位，用 `-l` 統計指令數，驗證「二進位不變、迭代次數改變」。

## 本節小結

- RVV 用 `vsetvli/vl/vtype/LMUL` 實現長度無關編程，同一二進位橫跨 MCU 到超算。
- HPC 買的是每瓦效能與開放生態，車用買的是原始碼自主與功能安全認證，兩者都指向向量 + 自訂擴充。
- 與 AVX 的固定寬度、SVE 的封閉授權相比，RVV 的開放 + 長度無關是最大差異化。
- 學 RVV 先學 strip-mining 迴圈，再學 mask 與 LMUL，順序對了就掌握八成。

## 想一想

2. 車用 ASIL-D 要求雙核鎖步（Lockstep），這與 HPC 追求的核心數最大化有何衝突？RISC-V 如何用同一 ISA 兼顧兩者？
3. （★★）把 `daxpy_vec` 改寫成 `e32` 單精度版並啟用 mask 跳過負值，對比 scalar 版效能，思考 mask 相比分支的優勢。
