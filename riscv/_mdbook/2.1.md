# 2.1 Base+Extensions 模組化思維

> 一套 ISA 如何同時服務「一顆電池用十年的感測器」和「跑 Linux 的超算節點」？答案是 Base + Extensions：共用地基，各蓋各的樓。

## 開場動機：光譜兩端的難題

傳統 ISA 只有一種體型：x86 再小也小不到手錶裡，ARM 則要靠 M/A/R 三條產品線分叉維護。RISC-V 換了一個思路：

- **Base（基礎）**：所有人都必須一樣的最小契約，保證軟體可攜（Portability）。
- **Extensions（擴充）**：按需掛載的能力包，用 `-march` 字符串聲明。

## 核心講解：模組化全景

### Base 的兩種體型

| Base | 暫存器數 | 目標場景 |
|------|----------|----------|
| RV32I / RV64I | 32 個 GPR（x0–x31） | 通用：從 MCU 到應用處理器 |
| RV32E / RV64E | 16 個 GPR（x0–x15） | 極小面積：深嵌入式、替代 8051 級 |

I 與 E 差別只在暫存器數量與編碼可達範圍，指令語意相同。選 E 就是用編譯器方便性換面積。

### 標準擴充一覽（詳見第 4 章）

| 擴充 | 全名（英文） | 功能一句話 | 典型用戶 |
|------|--------------|------------|----------|
| M | Integer Multiply/Divide | 硬體乘除法 | 幾乎所有人（除極小 MCU） |
| A | Atomic | LR/SC、AMO，多核同步 | 多核心晶片 |
| F / D | Single/Double Floating-Point | 浮點運算 + f 暫存器 | 訊號處理、科學計算 |
| C | Compressed | 16 位指令，省 25–30% 體積 | 快閃記憶體（Flash）受限的 MCU |
| B | Bit Manipulation | 位元抽取、計數、旋轉 | 加密、編解碼 |
| V | Vector | 向量暫存器群，AI/HPC 加速 | AI 加速器、超算 |

### 命名規則與 `-march` 字符串

`RV64IMAFDC` 可縮寫為 `RV64GC`（G = General，代表 IMAFD 組合）。工具鏈用法：

```mermaid
flowchart LR
    S["-march=rv64gc"] --> D["解碼: I+M+A+F+D+C"]
    D --> L["連結器檢查 .riscv.attributes"]
    L --> H["硬體: 必須有對應 FPU/乘法器"]
```

常見組合：

| `-march` | 含義 | 對應 `-mabi` |
|----------|------|--------------|
| `rv32i` | 最小 32 位 | `ilp32` |
| `rv32imac` | MCU 常見組合 | `ilp32` |
| `rv32imafdc`（=rv32g+c） | 帶浮點的 MCU/應用核 | `ilp32d` |
| `rv64gc` | Linux 應用處理器標配 | `lp64d` |

## 範例：同一份 C 程式，三種體型

```c
// mul_demo.c：有沒有 M 擴充，編譯結果天差地別
int mul_add(int a, int b, int c) {
    return a * b + c;
}
```

```asm
# -march=rv32im 起：直接用 M 擴充的 mul
mul_add:
    mul  a0, a0, a1      # a0 = a*b（單條硬體乘法）
    add  a0, a0, a2      # a0 += c
    ret

# -march=rv32i 起（無 M）：編譯器用加法+移位展開，或呼叫 __mulsi3
# mul_add:
#     ... 一串 slli/add ...   # 軟體模擬乘法，又慢又大
#     ret
```

```asm
# C 擴充的效果：同樣語意，體積更小（示意）
# 未壓縮： addi sp, sp, -16   (32-bit)
# 壓縮後： c.addi16sp sp, -16 (16-bit)，功能等價
```

## 本節小結

- Base 是最小契約（I=32 暫存器、E=16 暫存器），Extensions 是按需掛載的能力。
- G = IMAFD 是「通用」速記，C/B/V 按場景追加。
- `-march` 字符串就是硬體規格書，連結器會用屬性段（Attributes）檢查軟硬是否匹配。
- 選擴充 = 在**面積、功耗、效能、程式碼體積**之間做取捨。
- 下兩節深入 Base 的核心：暫存器檔（Register File）與 ABI。

## 想一想

1. 為什麼 E 只砍暫存器數量、不砍指令？從編譯器暫存器配置（Register Allocation）角度思考代價。
2. 你的 MCU 只有 64KB Flash，該選 `rv32i` 還是 `rv32imac`？說明 C 擴充省體積的原理。
3. 動手題（★★）：分別用 `-march=rv32i` 與 `-march=rv32im` 編譯 `mul_add`，用 `riscv64-unknown-elf-objdump -d` 比較行數差異。
