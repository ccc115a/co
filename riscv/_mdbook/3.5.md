# 3.5 環境呼叫與系統指令（ECALL, EBREAK, FENCE）

> 前面 47 條指令都在使用者世界裡打轉。本節的三條「系統指令」是通往作業系統、除錯器（Debugger）與多核心一致性的三扇門。

## 開場動機：使用者程式如何請作業系統幫忙？

使用者模式（User Mode, U-Mode）不能直接碰硬體：讀檔案、印字串、配置記憶體都要**陷入（Trap）**到更高特權級。RISC-V 用兩條環境指令開門，用一條柵欄指令維持秩序。

## 核心講解：三扇門

### 門一：ECALL——環境呼叫（Environment Call）

| 項目 | 說明 |
|------|------|
| 編碼 | SYSTEM（1110011），imm=0 |
| 語意 | 觸發同步例外（Synchronous Exception），跳到 trap 向量（Trap Vector） |
| 參數慣例 | Linux：a7 = 系統呼叫號（Syscall Number），a0–a5 = 引數，返回值回 a0 |
| 返回 | 執行 `mret/sret` 回到 `ecall` 下一條（`mepc/sepc` + 4） |

### 門二：EBREAK——環境斷點（Environment Breakpoint）

| 項目 | 說明 |
|------|------|
| 編碼 | SYSTEM，imm=1 |
| 語意 | 觸發斷點例外，交給除錯器或 SBI（Supervisor Binary Interface） |
| 用途 | GDB 軟斷點、`assert` 失敗、測試平台的「停機並回報」 |

### 門三：FENCE——記憶體柵欄（Memory Fence）

| 項目 | 說明 |
|------|------|
| 語法 | `fence pred, succ`（前集、後集：r/w/io/o） |
| 語意 | 保證柵欄前的記憶體操作對其他核心/裝置可見後，才執行柵欄後的操作 |
| 家族 | `fence.i`（指令流同步，自修改程式碼用）、`sfence.vma`（頁表切換時刷 TLB，見 13.3） |
| 何時用 | 弱記憶體模型（RVWMO）下做生產者-消費者同步、MMIO 先後順序 |

### 三指令速查

| 指令 | 類型 | 一句話 |
|------|------|--------|
| `ecall` | Trap | 「作業系統，請幫我做…」（a7 指明事項） |
| `ebreak` | Trap | 「除錯器，停下來看我！」 |
| `fence` / `fence.i` | 屏障 | 「前面的讀寫先做完，後面的再開始！」 |

## 範例：Hello World 的最後一哩路

```asm
# Linux RV64：write(1, msg, len) 的裸系統呼叫（a7=64）
    .data
msg:  .ascii "hi\n"
    .text
    .globl _start
_start:
    li   a0, 1             # fd = stdout
    la   a1, msg           # buf（auipc+addi 展開）
    li   a2, 3             # len
    li   a7, 64            # __NR_write = 64（RV64 Linux）
    ecall                 # 陷入核心，返回值回 a0（寫入位元組數）
    # exit(0)：a7=93
    li   a0, 0
    li   a7, 93            # __NR_exit
    ecall

# 除錯斷點示意
debug_here:
    ebreak                # GDB 會停在這裡
```

```c
// 同一邏輯的 C 版：libc 把 ecall 包裝成 write()/exit()
#include <unistd.h>
int main(void) {
    write(1, "hi\n", 3);  // 內部：a7=64, ecall
    return 0;             // 內部：ecall exit_group
}

// 生產者-消費者同步：fence 保證 data 先於 flag 可見
// int data, flag;
// 生產者：data = 42; __asm__("fence rw,rw"); flag = 1;
// 消費者：while(!flag){}; __asm__("fence r,rw"); use(data);
```

## 本節小結

- `ecall` 是使用者→核心的正門，a7 放呼叫號，`write=64`、`exit=93`（RV64 Linux）必背。
- `ebreak` 是給除錯器的門，GDB 斷點與測試停機都靠它。
- `fence` 是多核/MMIO 的秩序之門，RVWMO 弱模型下同步必備；`fence.i` 管指令流、`sfence.vma` 管頁表。
- 至此 RV32I 全數到齊：ALU + Load/Store + 分支跳躍 + 環境柵欄。
