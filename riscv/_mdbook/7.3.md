# 7.3 BOOM

BOOM（Berkeley Out-of-Order Machine）是建於 Rocket Chip 框架上的開源亂序超純量 RISC-V 核心，把 6.1/6.2 節的超純量、保留站、ROB、分支預測全部實作成可調參數的 Chisel。它是學術界對標商用高效能核心的標準擂台。

## 7.3.1 動機：開源也需要大核心

Rocket 跑 Linux 夠用，但 IPC 只有約 1；手機與伺服器要的是 IPC 2–3 的亂序核心。BOOM 證明開源社群也能玩 Tomasulo：SonicBOOM（BOOM v3）SPEC 2006 分數已可與同期 ARM Cortex-A9 量級對話，且全部參數（發射寬度、ROB 項數、物理暫存器數）開箱可調，是微結構研究的白老鼠。

> 核心觀念：BOOM = Rocket 前端（取指 + TileLink SoC）+ 全新亂序後端；框架複用讓研究者只聚焦後端。

## 7.3.2 核心講解：BOOM 後端與關鍵參數

BOOM 後端資料流：解碼 → 更名（RAT + 空閒表 Freelist）→ 發射佇列（Issue Queue，即分散式保留站）→ 暫存器讀 → 執行 → ROB 順序提交：

| 參數 | SmallBOOM | MediumBOOM | LargeBOOM（SonicBOOM） | 影響 |
|------|-----------|------------|------------------------|------|
| 發射寬度 | 1 | 2 | 3–4 | IPC 上限 |
| ROB / LQ / SQ | 32 / 8 / 8 | 64 / 16 / 16 | 128 / 32 / 32 | 記憶體延遲容忍視窗 |
| 整數 / 浮點物理暫存器 | 64 / 48 | 80 / 64 | 128 / 128 | 假相依消除能力 |
| 發射佇列項 | 8+8 | 16+12 | 32+20 | 等待操作數容量 |
| 分支預測器 | GShare + BTB | TAGE-lite + 大 BTB | TAGE + 大 BTB + Loop | 誤測率與 Flush 代價 |
| L1 I/D | 16KB | 32KB | 32KB + 預取 | AMAT |

分支誤測懲罰在 BOOM 深管線下達 10+ 週期，故 TAGE（Tagged Geometric）預測器與返回位址堆疊（RAS）的命中率直接決定 IPC；記憶體端靠推測執行的 Load（Speculative Load）+ Store Queue 前遞（Forwarding）隱藏延遲，違反推測（Violation）則回滾（Rollback）。

```scala
// BOOM 組態摘錄（Chisel）：MediumBOOM 風格參數
case class BoomConfig(
  fetchWidth = 2,          // 每週期取指寬度
  decodeWidth = 2,         // 解碼寬度
  issueWidth = 2,          // 發射寬度
  numRobEntries = 64,      // ROB 項數
  numPhysRegs = 80,        // 整數物理暫存器
  numLQEntries = 16,       // Load Queue
  numSQEntries = 16        // Store Queue
)
```

模擬與測試沿用 Rocket 流程，只是 Config 換成 BOOM：

```bash
# 產生 MediumBOOM Verilog 並以 Verilator 跑分
sbt "runMain freechips.rocketchip.system.Generator \
  -td ./boom-src -T BoomTop --target-dir ./boom-vsim"
make -C boom-vsim run CONFIG=MediumBoomConfig BINARY=dhrystone.riscv
```

## 7.3.3 架構參數對照表

| 參數 | PicoRV32（7.1） | Rocket（7.2） | BOOM（本節） |
|------|----------------|--------------|-------------|
| 微結構 | 多週期，順序 | 5 級管線，順序 | 10+ 級，亂序超純量 |
| 發射寬度 / IPC | 1 / < 0.3 | 1 / 約 0.8–1.0 | 2–4 / 約 1.5–2.5 |
| ROB / 更名 | 無 | 無 | 32–128 項 + RAT/ Freelist |
| 分支預測 | 無（重定向） | BTB + BHT + RAS | TAGE + 大 BTB + RAS + Loop |
| L1 快取 | 無（外部 SRAM） | 16–64KB VIPT | 32KB + 非阻塞 + 預取 |
| 實體暫存器 | 32 架構 | 32 架構 | 80–128 物理（更名池） |
| 語言 / 框架 | Verilog | Chisel + TileLink | Chisel + TileLink（同框架） |
| 適用場景 | MCU / 教學 | Linux SoC / 教學全棧 | 高效能研究 / IPC 優化 |

## 7.3.4 亂序後端流程圖

```mermaid
flowchart LR
  FE[前端: 取指 + TAGE 預測<br/>沿用 Rocket] --> DEC[解碼 + 更名 RAT]
  DEC --> IQ[發射佇列 Issue Queue<br/>等待操作數]
  DEC --> ROB[ROB 順序提交點]
  IQ --> PRF[物理暫存器讀]
  PRF --> EX[ALU / LSU / FPU 執行]
  EX --> CDB[CDB 廣播喚醒]
  CDB --> IQ
  EX --> ROB
  ROB --> COM[順序提交/誤測回滾]
```

## 7.3.5 本節小結

- BOOM 把課本概念變成可調旋鈕：ROB 加倍、TAGE 加大，IPC 曲線立刻回應，是最好的微結構實驗台。
- 深管線 + 寬發射放大一切：分支誤測更痛、CDB 更寬、驗證更難，這正是高效能設計的真實代價。
- 方法學啟示：Rocket/BOOM 共用前端與 SoC 框架證明「介面穩定、後端可換」是可行的開源硬體策略。
- 第二篇收束：5 章學會正確（單週期→管線→冒險），6 章學會快速（超純量→OoO→記憶體階層），7 章看見真實（小/中/大核心各就其位）。
