# 2.2 暫存器架構 x0-x31 與 PC

> RISC-V 的通用暫存器（General-Purpose Register, GPR）永遠 32 個（E 版 16 個），外加一個程式計數器（Program Counter, PC）。記住這一節的表，後面六章都在用它。

## 開場問題：為什麼是 32 個？

暫存器數量是 ISA 的經典取捨：

- 太少（如 x86 早期的 8 個）：編譯器頻繁 spill 到記憶體，效能差。
- 太多（如 Itanium 的 128 個）：上下文切換（Context Switch）與面積成本飆升。
- 32 個是 Berkeley 團隊認為的甜蜜點：**5 位元編碼（剛好放進指令欄位）、編譯器夠用、中斷現場夠小**。

外加兩條鐵律：`x0` 恆為零（Hardwired Zero）、沒有專用旗標暫存器。

## 核心講解：暫存器檔全表

### GPR 對照表（I 版，E 版僅前 16 個）

| 編號 | ABI 名 | 用途 | 保存責任（Caller/Callee-saved） |
|------|--------|------|-------------------------------|
| x0 | zero | 恆為 0，寫入丟棄 | —（常數） |
| x1 | ra | 返回位址（Return Address） | Caller-saved |
| x2 | sp | 堆疊指標（Stack Pointer） | Callee-saved |
| x3 | gp | 全域指標（Global Pointer） | —（全域） |
| x4 | tp | 執行緒指標（Thread Pointer） | —（執行緒區域） |
| x5–x7 | t0–t2 | 暫存器（Temporary） | Caller-saved |
| x8 | s0/fp | 被保存暫存器 / 框架指標（Frame Pointer） | Callee-saved |
| x9 | s1 | 被保存暫存器（Saved） | Callee-saved |
| x10–x11 | a0–a1 | 引數 / 返回值（Argument/Return Value） | Caller-saved |
| x12–x17 | a2–a7 | 引數（Argument） | Caller-saved |
| x18–x27 | s2–s11 | 被保存暫存器（Saved） | Callee-saved |
| x28–x31 | t3–t6 | 暫存器（Temporary） | Caller-saved |

記憶口訣：**a 開頭是拿來傳話的（caller 负责善後），s 開頭是借來要還的（callee 負責保存），t 開頭是用完即丟的**。

### x0 恆零的巧思

| 寫法 | 實際效果 | 省掉的東西 |
|------|----------|------------|
| `add a0, a1, x0` | `mv a0, a1`（搬移） | 不需要獨立的 `mov` 指令 |
| `addi a0, x0, 0` | `li a0, 0`（載入 0） | 不需要清零指令 |
| `beq a1, x0, label` | `beqz a1, label`（判零分支） | 不需要 compare-with-zero |
| `sw x0, 0(a0)` | `*p = 0` | 不需要先載入 0 再存 |

### PC：唯一的特殊暫存器

| 特性 | 說明 |
|------|------|
| 位寬 | XLEN（RV32=32 位，RV64=64 位） |
| 可見性 | **軟體不能直接讀寫 PC**，只能透過 `jal`/`jalr`/分支隱式改變 |
| 對齊 | RV32I 要求 4 位元組對齊；開 C 擴充後放寬為 2 位元組對齊 |
| 重置值 | 由平台定義（Platform-defined），通常指向 ROM（唯讀記憶體）入口 |

注意：控制狀態暫存器（CSR）如 `mstatus` 是另一套暫存器，不在 x0–x31 之內（見第 11 章）。

## 範例：暫存器的生死簿

```asm
# 示範 caller/callee-saved：leaf 函式 vs. 非 leaf 函式
    .text
    .globl leaf_add
leaf_add:
    # 葉函式（Leaf Function）：不呼叫別人，不必存 ra/s
    add  a0, a0, a1       # a0 = a+b，直接返回
    ret

    .globl nested_call
nested_call:
    # 非葉函式：要呼叫別人，必須先保存 ra 與 s0
    addi sp, sp, -16      # 開堆疊框架（Stack Frame）
    sw   ra, 12(sp)       # ra 是 caller-saved，呼叫前自保
    sw   s0, 8(sp)        # s0 是 callee-saved，用了就要還
    mv   s0, a0           # 借用 s0
    call leaf_add         # 可能破壞 a0-a7/t0-t6/ra
    mv   a0, s0           # 取回保存的值（此處僅示意邏輯）
    lw   s0, 8(sp)        # 歸還 s0
    lw   ra, 12(sp)       # 取回 ra
    addi sp, sp, 16
    ret
```

```c
// x0 恆零在 C 層的對應：NULL 與 0 的檢查最終都變成與 x0 比較
int is_null(const int *p) {
    return p == 0;  // 編譯為：snez/sltiu 或 beq a0, x0, ...
}
```

## 本節小結

- GPR 永遠 32 個（E 版 16 個），5 位元編碼，記住 a/s/t 三群分工。
- x0 恆為零：省掉 mov、清零、判零三類指令，是 RISC-V 簡潔的關鍵。
- Caller-saved（a/t/ra）由呼叫者自保；Callee-saved（s/sp）由被呼叫者歸還。
- PC 軟體不可直讀，只能由跳轉/分支改變；CSR 是另一套暫存器。
