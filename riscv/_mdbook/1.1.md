# 1.1 傳統 ISA 的痛點與專利限制（x86 vs. ARM）

> 為什麼一顆小小的嵌入式晶片，也要向遠方的公司繳「指令集稅」？本節從 x86 與 ARM 的商業模式談起，理解傳統指令集架構（Instruction Set Architecture, ISA）的痛點。

## 開場問題：ISA 為什麼會變成護城河？

指令集架構（ISA）是軟體與硬體之間的契約（Contract）：它定義了暫存器（Register）、指令（Instruction）、定址模式（Addressing Mode）與記憶體模型（Memory Model）。理論上它只是一份文件，但實務上它綁定了整個軟體生態系（Ecosystem）。

想像你是一家新創公司，想做一顆物聯網晶片：

- 若選 x86，你幾乎拿不到授權（License），只有 Intel、AMD 與極少數廠商能玩。
- 若選 ARM，你可以買授權，但要付授權費（Licensing Fee）加權利金（Royalty），而且指令集怎麼演進由 ARM 決定。
- 若你想加一條自己的 AI 加速指令？對不起，編碼空間（Encoding Space）不屬於你。

這就是本節的核心問題：**當 ISA 是私有財產時，創新就必須先繳稅**。

## 核心講解：x86 與 ARM 的兩種封閉

### x86：技術債堆出來的複雜指令集

x86 是複雜指令集電腦（Complex Instruction Set Computer, CISC）的代表。從 1978 年 Intel 8086 起，它為了相容（Compatibility）不斷疊床架屋：

| 特徵 | 說明 | 帶來的痛點 |
|------|------|------------|
| 可變長度編碼（Variable-Length Encoding） | 指令長度 1–15 位元組 | 解碼器（Decoder）極複雜，佔面積又耗電 |
| 歷史模式包袱 | 實模式（Real Mode）、保護模式（Protected Mode）、64 位元長模式（Long Mode）並存 | 驗證（Verification）成本爆炸 |
| 暫存器太少且不對稱 | 早期只有 8 個通用暫存器（General-Purpose Register, GPR），且各有特殊用途 | 編譯器（Compiler）暫存器配置困難 |
| 封閉授權 | x86 授權來自 Intel 與 AMD 的專利交叉授權，外人幾乎無法進入 | 學術界不能合法做一顆 x86 相容核心來流片（Tape-out） |

 Hillary Clinton？不，是歷史包袱：現代 x86 CPU 內部其實都把 CISC 指令先翻譯成類 RISC 的微運算（Micro-operation, μop）再執行，等於花了大代價把 CISC「假裝成 RISC」。

### ARM：精簡但仍要收稅的 RISC

ARM 是精簡指令集電腦（Reduced Instruction Set Computer, RISC）的成功商業範例，靠著授權模式席捲手機與嵌入式市場：

| 授權層級 | 內容 | 成本與限制 |
|----------|------|------------|
| 處理器授權（Processor License） | 直接買 Cortex-A/M 現成核心 | 最便宜但完全不能改 ISA |
| 架構授權（Architecture License） | 可自研相容 ARMv8/v9 的核心，如 Apple、Qualcomm | 數百萬至上千萬美元門檻，且仍需 ARM 核准 |
| 指令集演進主導權 | ARM 決定何時加入 SVE、PAC、BTI 等延伸 | 小廠只能跟隨，無法主導方向 |

ARM 比 x86 乾淨許多，但**商業模式仍是收租**：每賣一顆晶片都要抽權利金。對出貨量以億計的物聯網（IoT）廠商而言，這是一筆長期稅負。

### 痛點總整理

| 痛點維度 | x86 | ARM（傳統授權制） |
|----------|-----|-------------------|
| 授權開放性（Openness） | 幾乎不授權 | 授權但高價 + 權利金 |
| 自訂指令（Custom Instruction） | 不可能 | 需談判，編碼空間受限 |
| 學術研究自由度 | 只能模擬，不能實作相容硬體販售 | 教學可用，但流片仍受限 |
| 地緣與供應鏈風險 | 美國出口管制高度集中 | 曾發生公司主體與授權爭議，廠商擔憂斷供 |
| 技術包袱 | CISC 歷史相容負擔 | 相對輕，但版本碎片化（v7/v8/v9 並存） |

## 範例：算一筆「指令集稅」帳

以下用 C 語言示意：同樣的功能，在開放與封閉 ISA 下的成本結構差異（概念性試算，非真實報價）。

```c
#include <stdio.h>

// 概念試算：出貨 1000 萬顆 IoT 晶片的 ISA 相關成本
int main(void) {
    long volume = 10000000L;
    // 封閉 ISA：授權費 + 每顆權利金（假設值，僅示意結構）
    double license_fee = 5000000.0;      // 一次性授權費（美元）
    double royalty_per_chip = 0.15;      // 每顆權利金（美元）
    double closed_cost = license_fee + royalty_per_chip * volume;

    // 開放 ISA：無授權費與權利金，但需自負驗證與生態投入
    double verification_cost = 2000000.0; // 自研核心驗證投入
    double open_cost = verification_cost;

    printf("Closed ISA cost: $%.1fM\n", closed_cost / 1e6);
    printf("Open ISA cost:   $%.1fM\n", open_cost / 1e6);
    return 0;
}
```

```asm
# 同一段加法，在任何 ISA 下語意都一樣，差別只在「誰擁有編碼」
# RISC-V (開放)：編碼公開，任何人可實作
add  a0, a1, a2        # a0 = a1 + a2，無需授權即可設計執行它的硬體

# x86 (封閉)：語意類似，但只有授權廠商能合法賣相容 CPU
#   add eax, ebx       ; 只能由 Intel/AMD（及被授權者）實作販售
```

重點不在幾行組語，而在**硬體實作權**：RISC-V 的 `add` 任何人都能做成晶片拿去賣，x86/ARM 的對應指令不行。

## 本節小結

- ISA 是軟硬體契約，但傳統上也是商業護城河（Moat）。
- x86 的痛點是 **CISC 歷史包袱 + 幾乎不授權**，解碼與驗證成本高。
- ARM 的痛點是 **RISC 技術成功但商業封閉**，授權費與權利金是長期稅負。
- 兩者共同限制：**自訂指令困難、生態方向由單一廠商決定、地緣風險集中**。
- 這些痛點正是 RISC-V 誕生的直接動機：把 ISA 變成公共財（Public Good）。

## 想一想

1. 如果你是年出貨一億顆的穿戴裝置廠商，試估算每顆 0.1 美元權利金十年下來的總成本，並思考它對利潤率的影響。
2. 為什麼 x86 CPU 內部要把指令翻譯成 μop？這說明了 CISC 與 RISC 在微結構（Microarchitecture）層面有何趨同？
3. ARM 的架構授權（Architecture License）允許自研核心，為什麼它仍不算「開放」？從編碼主導權與授權成本兩方面回答。
