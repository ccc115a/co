# 2.1 傳統 CPU 的限制：超純量、指令預測與大快取

## CPU 的設計哲學

CPU（Central Processing Unit）是通用處理器的代表，其設計目標是最大化單一執行緒的效能。為此，CPU 採用了多種複雜的微架構技術：

### 超純量（Superscalar）架構

超純量處理器在單一時脈週期內可同時執行多條指令：

```
傳統標量處理器：
┌─────┐
│ ALU │  → 每週期 1 條指令
└─────┘

超純量處理器（4-way）：
┌─────┬─────┬─────┬─────┐
│ ALU │ ALU │ FPU │ LSU │  → 每週期 4 條指令
└─────┴─────┴─────┴─────┘
```

現代 CPU 的發射寬度：

| 處理器 | 發射寬度 | 代表產品 |
|--------|----------|----------|
| Intel | 6-wide | Core i9-14900K |
| AMD | 6-wide | Ryzen 9 7950X |
| Apple | 8-wide | M2 Ultra |

### 亂序執行（Out-of-Order Execution）

為避免指令管線停頓，CPU 可動態重排指令執行順序：

```
原始指令序列：
1. LOAD R1, [address]    ← 記憶體存取（延遲長）
2. ADD R2, R3, R4        ← 立即可執行
3. MUL R5, R6, R7        ← 立即可執行
4. ADD R8, R1, R5        ← 依賴 R1（需等待）

亂序執行：
1. ADD R2, R3, R4        ← 先執行
2. MUL R5, R6, R7        ← 接著執行
3. LOAD R1, [address]    ← 同時發出記憶體存取
4. ADD R8, R1, R5        ← 最後執行
```

### 分支預測（Branch Prediction）

CPU 試圖預測分支指令的結果，以維持管線充滿：

```
if (condition) {
    // 分支 A（預測為 true）
    do_something();
} else {
    // 分支 B（預測為 false）
    do_other();
}

分支預測準確率：
- 現代 CPU：~95-99%
- 對於 AI 工作負載：可能降至 ~50%（大量條件判斷）
```

## CPU 為什麼不適合 AI 運算？

### 1. 晶片面積分配不當

```
典型 CPU 晶片面積分配（以 Intel Core 為例）：
┌────────────────────────────────────────┐
│                                    │
│     控制邏輯（~30-40%）             │
│                                    │
├────────────────────────────────────────┤
│                                    │
│     快取記憶體（~30-40%）           │
│                                    │
├────────────────────────────────────────┤
│                                    │
│     運算單元（~20-30%）             │
│                                    │
└────────────────────────────────────────┘
```

### 2. 控制開銷過大

AI 運算具有高度規則的資料流，但 CPU 卻花費大量資源於：

- 分支預測器（Branch Predictor）
- 重排序緩衝區（Reorder Buffer, ROB）
- 載入/儲存佇列（Load/Store Queue）
- 暫存器別名表（Register Alias Table）

### 3. 記憶體存取模式不適合

AI 運算需要高頻寬的連續記憶體存取，但 CPU 的記憶體子系統設計偏向：

- 低延遲（而非高頻寬）
- 小型快取（用於時間/空間局部性）
- 複雜的快取一致性協定

## CPU 快取架構的限制

### 快取層級結構

```
┌─────────────────────────────────────────────┐
│              CPU 核心                        │
│  ┌─────────────────────────────────────────┐│
│  │           L1 Cache（32-64 KB）          ││
│  │    ┌──────────────┬──────────────┐      ││
│  │    │ L1 I-Cache   │ L1 D-Cache   │      ││
│  │    │ (指令快取)   │ (資料快取)   │      ││
│  │    └──────────────┴──────────────┘      ││
│  └─────────────────────────────────────────┘│
│                      ↓                       │
│  ┌─────────────────────────────────────────┐│
│  │           L2 Cache（256 KB - 1 MB）     ││
│  └─────────────────────────────────────────┘│
└─────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────┐
│           L3 Cache（8-64 MB）               │
│         （多核心共享）                       │
└─────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────┐
│           主記憶體（16-128 GB）              │
└─────────────────────────────────────────────┘
```

### 快取的限制

| 特性 | CPU L1 Cache | GPU Shared Memory |
|------|--------------|-------------------|
| 容量 | 32-64 KB | 48-228 KB |
| 延遲 | ~1-4 週期 | ~20-30 週期 |
| 程式控制 | 硬體管理 | 軟體管理 |
| 關聯性 | 8-16 路 | 無關聯性 |
| 資料搬運 | 自動 | 手動管理 |

## SIMD 指令集的嘗試

### x86 SIMD 演進

| 指令集 | 寬度 | 平行度 | 推出年份 |
|--------|------|--------|----------|
| MMX | 64-bit | 2× INT32 | 1997 |
| SSE | 128-bit | 4× FP32 | 1999 |
| AVX | 256-bit | 8× FP32 | 2011 |
| AVX-512 | 512-bit | 16× FP32 | 2016 |
| AMX | Tile-based | 1024+ INT8 | 2022 |

### SIMD 的限制

即使使用 AVX-512，CPU 的 AI 運算效能仍遠低於 GPU：

```
Intel Core i9-14900K（AVX-512）：
- FP32：~2 TFLOPS
- FP16：~4 TFLOPS（若支援）

NVIDIA RTX 4090（FP16 Tensor Core）：
- FP16：~165 TFLOPS

差距：~40-80 倍
```

## 量化比較：CPU vs GPU

### 硬體規格比較

| 特性 | Intel Xeon w9-3495X | NVIDIA H100 SXM |
|------|---------------------|------------------|
| 核心數 | 56 | 132 SM |
| 時脈頻率 | 1.9-3.5 GHz | 1.41-1.98 GHz |
| 暫存器數 | 32×56 = 1,792 | 65,536×132 |
| L1 Cache | 56×80 KB = 4.5 MB | 2.5 MB |
| L2 Cache | 56×2 MB = 112 MB | 50 MB |
| 記憶體 | DDR5-4800 8CH | HBM3 |
| 記憶體頻寬 | ~300 GB/s | 3.35 TB/s |
| FP32 | ~3.5 TFLOPS | 67 TFLOPS |
| FP16 | ~7 TFLOPS | 1,979 TFLOPS（Tensor Core） |

### AI 工作負載效能比較

```
ResNet-50 訓練（每秒處理影像數）：
- Intel Xeon：~200 images/sec
- NVIDIA A100：~7,000 images/sec
- NVIDIA H100：~14,000 images/sec

GPT-3 175B 參數量推論：
- Intel Xeon（56 核）：不可行（記憶體不足）
- NVIDIA H100×8：~30 tokens/sec
```

## CPU 的角色定位

儘管 CPU 不適合大規模 AI 運算，但在以下場景仍有價值：

1. **資料前處理**：ETL、清洗、轉換
2. **小規模推論**：邊緣裝置、即時應用
3. **控制平面**：作業系統、驅動程式、任務調度
4. **混合工作負載**：同時執行 CPU 與 GPU 任務

## 本章小結

- CPU 設計追求單一執行緒效能，採用超純量、亂序執行、分支預測等技術
- 這些技術對 AI 運算幫助有限，反而消耗大量晶片面積
- CPU 的快取架構偏向低延遲而非高頻寬，不適合 AI 的連續存取模式
- 即使使用 SIMD 指令集，CPU 的 AI 運算效能仍遠低於 GPU
- CPU 在 AI 生態系中主要扮演控制與資料前處理的角色
