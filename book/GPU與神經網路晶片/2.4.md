# 2.4 各類架構在 Latency（延遲）、Throughput（吞吐量）與 Efficiency（能效比）的取捨

## 基本概念定義

### Latency（延遲）

延遲是指從輸入到輸出所需的時間：

```
延遲類型：
┌─────────────────────────────────────────────────┐
│  1. 推論延遲（Inference Latency）                │
│     - 從輸入資料到輸出結果的時間                  │
│     - 單一樣本的處理時間                         │
│                                                  │
│  2. 記憶體延遲（Memory Latency）                 │
│     - 從發出記憶體請求到收到資料的時間            │
│     - 通常以時脈週期或奈秒衡量                   │
│                                                  │
│  3. 互連延遲（Interconnect Latency）             │
│     - 資料在節點間傳輸的時間                     │
│     - 包含傳播延遲與傳輸延遲                     │
└─────────────────────────────────────────────────┘
```

### Throughput（吞吐量）

吞吐量是指單位時間內可處理的資料量或任務數：

```
吞吐量衡量指標：
┌─────────────────────────────────────────────────┐
│  1. 每秒影像數（Images/sec）                    │
│     - 適用於影像分類、物件偵測                    │
│                                                  │
│  2. 每秒 Token 數（Tokens/sec）                 │
│     - 適用於語言模型推論                         │
│                                                  │
│  3. 每秒查詢數（Queries/sec, QPS）              │
│     - 適用於線上服務                            │
│                                                  │
│  4. 每秒樣本數（Samples/sec）                   │
│     - 適用於模型訓練                            │
└─────────────────────────────────────────────────┘
```

### Efficiency（能效比）

能效比是指每瓦特功耗可提供的運算效能：

```
能效比指標：
┌─────────────────────────────────────────────────┐
│  1. TOPS/W（每瓦特兆次運算）                    │
│     - 常用於 AI 晶片規格比較                    │
│                                                  │
│  2. FLOPS/W（每瓦特浮點運算）                   │
│     - 通用浮點運算的能效比                       │
│                                                  │
│  3. Frames/Watt（每瓦特幀數）                   │
│     - 適用於邊緣裝置                            │
│                                                  │
│  4. Tokens/Joule（每焦耳 Token 數）             │
│     - 適用於 LLM 推論                          │
└─────────────────────────────────────────────────┘
```

## 各架構特性比較

### CPU

```
CPU 特性：
┌─────────────────────────────────────────────────┐
│  Latency：低                                     │
│  ├── 單一執行緒優化                             │
│  ├── 低延遲記憶體存取                           │
│  └── 複雜分支預測                               │
│                                                  │
│  Throughput：低                                  │
│  ├── 核心數量有限（數十個）                      │
│  └── 每核心運算單元有限                         │
│                                                  │
│  Efficiency：低（對 AI 運算）                    │
│  ├── 大量晶片面積用於控制邏輯                   │
│  └── 通用設計無法針對 AI 優化                   │
└─────────────────────────────────────────────────┘
```

### GPU

```
GPU 特性：
┌─────────────────────────────────────────────────┐
│  Latency：中-高                                 │
│  ├── 依賴執行緒切換隱藏延遲                     │
│  ├── 記憶體延遲較高                             │
│  └── 但可透過批次處理降低平均延遲               │
│                                                  │
│  Throughput：高                                  │
│  ├── 大量平行運算單元                           │
│  ├── 高頻寬記憶體                               │
│  └── 適合大規模批次處理                         │
│                                                  │
│  Efficiency：中等                                │
│  ├── 平行架構提升運算效率                       │
│  ├── 但通用性帶來額外開銷                       │
│  └── 每瓦效能持續改善                           │
└─────────────────────────────────────────────────┘
```

### NPU/TPU

```
NPU/TPU 特性：
┌─────────────────────────────────────────────────┐
│  Latency：低-中                                 │
│  ├── 針對特定運算優化                           │
│  ├── 簡化控制邏輯                               │
│  └── 片上記憶體降低存取延遲                     │
│                                                  │
│  Throughput：高                                  │
│  ├── 高密度運算陣列                             │
│  ├── 優化的資料流                               │
│  └── 大容量片上 SRAM                            │
│                                                  │
│  Efficiency：高                                  │
│  ├── 移除不必要的通用功能                       │
│  ├── 專用運算單元                              │
│  └── 最佳化的記憶體存取模式                     │
└─────────────────────────────────────────────────┘
```

### 延遲 vs 吞吐量的取捨

```
延遲 vs 吞吐量關係圖：

吞吐量
    │
    │                          ○ GPU（批次=64）
    │                        ○
    │                      ○
    │                    ○
    │                  ○
    │                ○
    │              ○
    │            ○
    │          ○
    │        ○ GPU（批次=1）
    │      ○
    │    ○
    │  ○ NPU
    │○
    └──────────────────────── 延遲

觀察：
- GPU 透過增大批次提升吞吐量，但延遲增加
- NPU 延遲低，但批次處理能力有限
- CPU 延遲低，但吞吐量也低
```

## 設計取捨分析

### 1. 通用性 vs 專用性

```
通用性光譜：

CPU ──────────────────────────────────────────── 專用 ASIC
│                                                   │
│  高通用性                                       高效率
│  低效率                                         低通用性
│  適用於多種任務                               適用於單一任務
```

### 2. 延遲優化 vs 吞吐量優化

| 優化方向 | 策略 | 適用場景 |
|----------|------|----------|
| 延遲優化 | 增加 ALU 數量、提升時脈、簡化管線 | 即時推論、邊緣裝置 |
| 吞吐量優化 | 增加核心數、增大批次、提升頻寬 | 訓練、離線推論 |

### 3. 能效比優化策略

```
能效比提升方法：
┌─────────────────────────────────────────────────┐
│  1. 降低精度                                     │
│     FP32 → FP16 → INT8 → INT4                   │
│     效能提升 2-8 倍，功耗降低 2-4 倍             │
│                                                  │
│  2. 稀疏性加速                                   │
│     跳過零值運算                                 │
│     效能提升 2-4 倍（依稀疏度）                  │
│                                                  │
│  3. 記憶體優化                                   │
│     減少資料搬運                                 │
│     功耗降低 30-50%                             │
│                                                  │
│  4. 電壓/頻率調整                                │
│     動態電壓頻率調整（DVFS）                     │
│     功耗降低 20-40%                             │
└─────────────────────────────────────────────────┘
```

## 應用場景選擇指南

### 場景分析

| 場景 | 主要需求 | 推薦架構 |
|------|----------|----------|
| 訓練大型模型 | 吞吐量、可擴展性 | GPU 集群 |
| 線上推論服務 | 延遲、吞吐量 | GPU 或 NPU |
| 邊緣即時推論 | 延遲、功耗 | NPU、專用 ASIC |
| 移動裝置 | 功耗、延遲 | 行動 SoC + NPU |
| 資料中心推論 | 吞吐量、成本 | GPU 或 TPU |
| 自動駕駛 | 延遲、可靠性 | 專用 ASIC |

## 未來趨勢

### 1. 混合架構

```
異質運算架構：
┌─────────────────────────────────────────────────┐
│                    CPU（控制平面）               │
│                      ↓                          │
│  ┌─────────────────────────────────────────┐   │
│  │              GPU（訓練）                 │   │
│  └─────────────────────────────────────────┘   │
│                      ↓                          │
│  ┌─────────────────────────────────────────┐   │
│  │              NPU（推論）                 │   │
│  └─────────────────────────────────────────┘   │
│                      ↓                          │
│  ┌─────────────────────────────────────────┐   │
│  │         邊緣裝置（端側推論）             │   │
│  └─────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

### 2. 效能指標演進

| 時期 | 主要指標 | 次要指標 |
|------|----------|----------|
| 2010s | FLOPS | 功耗 |
| 2020s | TOPS/W | 延遲 |
| 2030s | Tokens/Joule | 端到端效能 |

## 本章小結

- Latency、Throughput、Efficiency 是評估 AI 晶片的三大指標
- 不同架構在這些指標上有不同的權衡
- CPU 延遲低但吞吐量有限
- GPU 吞吐量高但延遲較高（尤其小批次）
- NPU/TPU 在能效比上表現最佳
- 應用場景決定最佳架構選擇
- 未來趨勢是異質混合架構
