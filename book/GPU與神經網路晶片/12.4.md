# 12.4 邊端 AI（Edge AI）晶片的超低功耗設計

## Edge AI 簡介

### 為何需要邊端 AI

```
Edge AI 的動機：
┌─────────────────────────────────────────────────┐
│  雲端 AI 的限制：                                │
│  - 需要網路傳輸（延遲高）                  │
│  - 頻寬與成本                      │
│  - 隱私與安全問題                        │
│  - 無法完全覆蓋所有場景                  │
│                                                  │
│  邊端 AI 的需求：                                │
│  - 即時回應（毫秒級）                      │
│  - 離線可使用（不依賴網路）              │
│  - 資料本地處理（隱私保護）              │
│  - 低功耗長時間運行                        │
│                                                  │
│  應用場景：                                      │
│  - 智慧手機（拍照、語音）                │
│  - 穿戴裝置（健康監測）                  │
│  - 物聯網感測器（異常偵測）              │
│  - 自駕車/機器人（即時視覺）            │
│  - 零售/安防（影像辨識）                │
│    常見場景                     │
└─────────────────────────────────────────────────┘
```

### Edge AI 挑戰

```
Edge AI 晶片設計挑戰：
┌─────────────────────────────────────────────────┐
│  1. 極低功耗                                    │
│     - 電池供電，需長時間運行                │
│     - 目標可能僅 1mW-1W                     │
│                                                  │
│  2. 面積與成本受限                        │
│     - 小型封裝                            │
│     - 低單位成本                        │
│                                                  │
│  3. 記憶體受限                              │
│     - 片上記憶體小（SRAM 為主）              │
│     - 無法容納大型模型                  │
│                                                  │
│  4. 性能要求（依然需要）                │
│     - 即時推論（低延遲）                  │
│     - 足夠的準確度                      │
│     - 邊端與雲端折衷                    │
│                                                  │
│  5. 異質性需求                        │
│     - 多種感測器與任務                  │
│     - 靈活動態排程                      │
└─────────────────────────────────────────────────┘
```

## 超低功耗設計策略

### 計算精度與架構

```
Edge AI 架構選擇：
┌─────────────────────────────────────────────────┐
│  1. 量化（Quantization）                     │
│     - INT8 為主（功耗減半以上）              │
│     - INT4 或 二值化（極端）              │
│     - 立即節省記憶體與運算功耗            │
│                                                  │
│  2. 稀疏計算                                │
│     - 跳過零值（Reduce-Only）               │
│     - 事件驅動（感知變化才算）              │
│                                                  │
│  3. 小型模型專用架構                        │
│     - 專為小型 CNN/Transformer 最佳化      │
│     - 效率比通用 GPU 更高（但彈性低）        │
│                                                  │
│  4. 近似計算（Approximate Computing）          │
│     - 容錯場景允許小誤差                  │
│     - 犧牲精度換功耗                      │
│                                                  │
│  5. 記憶體節省                                │
│     - 權重重用                              │
│     - 模型壓縮（剪枝、蒸餾）              │
│     - 分區/分時載入                    │
└─────────────────────────────────────────────────┘
```

### 節能硬體技術

```
硬體節能技術：
┌─────────────────────────────────────────────────┐
│  1. 非同步/事件驅動設計：                    │
│     - 只有所需才運算                        │
│     - 閒置時零功耗                      │
│                                                  │
│  2. 動態電壓頻率調整（DVFS）             │
│     - 依負載調電壓/頻率                │
│     - 節能省電的重要技術              │
│                                                  │
│  3. 啟用控制（Clock/Power Gating）          │
│     - 完全關閉閒置功能方塊                │
│                                                  │
│  4. 低功耗記憶體設計                  │
│     - 深睡模式 DRAM                    │
│     - 低漏電 SRAM                     │
│     - RRAM（非揮發，可關機）          │
│                                                  │
│  5. 低壓操作                          │
│     - 近臨界電壓（Near-VT）              │
│     - 更低保壓但性能下降              │
└─────────────────────────────────────────────────┘
```

### 資料流與記憶體設計

```
記憶體/資料流最佳化：
┌─────────────────────────────────────────────────┐
│  1. 資料重用最大化                            │
│     - 盡量在片上運算（減少 DRAM）           │
│     - 資料流架構（Systolic）              │
│     - 減少走記憶體山高延遲              │
│                                                  │
│  2. 記憶體分層                                │
│     - 多層快取/Scratchpad                │
│     - 熱資料留在片上                    │
│                                                  │
│  3. 異質感測融合處理                    │
│     - 多感測資料流平行處理            │
│     - 動態分配計算資源              │
│                                                  │
│  4. 記憶體內運算（CIM）                  │
│     - RRAM/SRAM Compute-In-Memory          │
│     - 大幅減少資料搬運                    │
└─────────────────────────────────────────────────┘
```

```
Edge AI 效能指標：
```

```
案例：語音喚醒（Wake Word）
┌─────────────────────────────────────────────────┐
│  任務：持續監聽「Hey Siri」型指令                 │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  方案              │  功耗              │   │
│  ├──────────────────────────────────────────┤   │
│  │  CPU 處理           │  數百 mW          │   │
│  │  小型 NPU          │  數十 mW          │   │
│  │  專用喚醒電路        │  數 mW            │   │

```

## 異構架構與調度

### 分層計算

```
Edge AI 分層計算：
┌─────────────────────────────────────────────────┐
│  ┌──────────────────────────────────────────┐   │
│  │  層級  │  功能                          │   │
│  ├──────────────────────────────────────────┤   │
│  │  L0    │  Always-On（喚醒詞、事件偵測） │   │
│  │  L1    │  輕量任務（簡單分類、特徵）    │   │
│  │  L2    │  中型任務（物件偵測、語音）    │   │
│  │  L3    │  大型任務（深度模型、雲端協同）│   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  策略：                                          │
│  - 常態消耗低層算力（低功耗）              │
│  - 需要時才升級到高層（高功耗）            │
│  - 動態排程（RM 堆疊與功耗控制）            │
│                                                  │
│  優點：                                          │
│  - 長時間待機能耗極低                    │
│  - 需要時才啟用高算力                  │
└─────────────────────────────────────────────────┘
```

### 雲端協同

```
雲邊協同（Split/Offloading）：
┌─────────────────────────────────────────────────┐
│  兩種策略：                                      │
│  1. 部分推論在邊端：                          │
│     - 前幾層在邊端計算（特徵提取）            │
│     - 後續層傳到雲端（分類）                │
│     → 節省頻寬，保護隱私                 │
│                                                  │
│  2. 模型分割（Partitioning）：            │
│     - 根據延遲/功耗動態分配              │
│     - 邊端輕量模型 + 雲端大型模型          │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  邊端 ←→ 雲端（異質協同）                │   │
│  │  - 邊端：即時、輕量、省電                │   │
│  │  - 雲端：巨型模型、高精度                │   │
│  │  - 平衡延遲與精度                        │   │
│  └──────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

### 功耗預算實務

```
再談功耗預算：
┌─────────────────────────────────────────────────┐
│  範例：充電一次可用 30 天的穿戴裝置              │
│  電池 300 mAh @ 3.8V ≈ 4.1 Wh               │
│  平均功耗限制 ≈ 4.1 Wh / 720h ≈ 5.7 mW      │
│                                                  │
│  分配預算：                                      │
│  - 感測器：2 mW                              │
│  - 無線/通訊：2 mW                          │
│  - AI 推論（偶發）：1 mW 平均               │
│                                                  │
│  → AI 晶片的平均功耗必須 ≤1mW              │
│    只有事件驅動 + 分層喚醒才能達成          │
└─────────────────────────────────────────────────┘
```

## 本章小結

- Edge AI 需要極低功耗、即時回應、離線運算與隱私保護
- 超低功耗設計：（量化、稀疏、近似、事件驅動）組合
- 硬體技術：DVFS、Clock/Power Gating、低漏電記憶體
- 分層計算（Always-On → 輕量 → 大型）可大幅節能
- 代表晶片：Apple ANE、Google Edge TPU、ARM Ethos 等
- 常用指標：TOPS/W、TOPS/mm²、推論延遲
- 雲邊協同（模型分割/異構）是務實策略
- 未來：mW 級功耗、小型 LLM、CIM 記憶體計算、多模態融合
- 「以任務滿足為目標的最小功耗」是 Edge AI 設計核心
