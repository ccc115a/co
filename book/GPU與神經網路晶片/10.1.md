# 10.1 AI 編譯器架構：High-Level IR (Graph) 到 Low-Level IR (Operator)

## AI 編譯器的角色

### 為什麼需要 AI 編譯器

```
AI 編譯器動機：
┌─────────────────────────────────────────────────┐
│  問題：                                          │
│  深度學習框架產生高階運算圖                     │
│  但硬體需要低階指令                           │
│  中間需要一層轉換層                          │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  框架（PyTorch/TF）                     │   │
│  │    ↓ 高階計算圖（Graph）               │   │
│  │  ┌────────────────────────────────────┐  │   │
│  │  │        AI 編譯器                   │  │   │
│  │  │  - 圖最佳化                        │  │   │
│  │  │  - 算子排程                        │  │   │
│  │  │  - 代碼生成                        │  │   │
│  │  └────────────────────────────────────┘  │   │
│  │    ↓ 低階算子/指令                     │   │
│  │  硬體（GPU/NPU/TPU）                   │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  意義：                                          │
│  - 讓框架程式可跑到不同硬體                  │
│  - 優化硬體利用率                          │
└─────────────────────────────────────────────────┘
```

### AI 編譯器 vs 傳統編譯器

```
編譯器比較：
┌─────────────────────────────────────────────────┐
│  特性     │  傳統編譯器      │  AI 編譯器       │
├─────────────────────────────────────────────────┤
│  輸入     │  高階語言源碼    │  深度學習圖      │
│  輸出     │  機器碼          │  硬體 kernel    │
│  優化     │  資料流/控制流   │  算子/記憶體     │
│  主要操作 │  指令選擇        │  fusion/排程    │
│  目標     │  CPU/GPU 通用    │  AI 加速器      │
└─────────────────────────────────────────────────┘
```

## IR 層級

### 多層 IR

```
AI 編譯器內的多層 IR：
┌─────────────────────────────────────────────────┐
│  高階 IR（Graph-Level）：                        │
│  - 描述整個模型的計算圖                        │
│  - 節點 = 算子，邊 = 張量                     │
│  - 適合整體最佳化                              │
│                                                  │
│  中階 IR（Op-Level）：                           │
│  - 描述單一算子的詳細運算                    │
│  - 包含算子型態、形狀資訊                    │
│  - 適合算子融合/排程                        │
│                                                  │
│  低階 IR（Instruction-Level）：                  │
│  - 接近硬體指令                              │
│  - 包含記憶體搬運、計算指令                │
│  - 適合生成硬體代碼                      │
└─────────────────────────────────────────────────┘
```

### 圖結構 IR（Graph IR）

```
計算圖表示：
┌─────────────────────────────────────────────────┐
│  計算圖（Computation Graph）：                   │
│                                                  │
│  ┌──────┐      ┌──────┐      ┌──────┐           │
│  │ Input│─→│ MatMul│─→│ ReLU │─→ Output  │   │
│  └──────┘      └──────┘      └──────┘           │
│                  │                              │
│                  ↓                              │
│              ┌──────┐                          │
│              │ Bias │                          │
│              │ Add  │─→ (融合：MatMul+Add)     │
│              └──────┘                          │
│                                                  │
│  表示特性：                                      │
│  - 節點（Node）：算子                           │
│  - 邊（Edge）：資料依賴（張量）               │
│  - 有向無環圖（DAG）                           │
│  - 記錄張量形狀、資料型態                     │
│                                                  │
│  適用最佳化：                                    │
│  - 骨架移除（Dead Code Elimination）       │
│  - 常數折疊                            │
│  - 算子融合                                  │
│  - 記憶體配置規劃                          │
└─────────────────────────────────────────────────┘
```

## 高階最佳化（Graph Level）

### 圖最佳化技術

```
圖級最佳化：
┌─────────────────────────────────────────────────┐
│  1. 算子融合（Operator Fusion）                 │
│     ┌────┐ ┌────┐ ┌────┐    ┌────────────┐    │
│     │ Add│→│ Mul│→│ ReLU│ → │Fused Kernel │    │
│     └────┘ └────┘ └────┘    └────────────┘    │
│     - 減少記憶體往來                        │
│                                                  │
│  2. 死代碼消除（DCE）                        │
│     - 刪除不會被使用的運算                   │
│                                                  │
│  3. 常數折疊（Constant Folding）              │
│     - 計算編譯期已知的常數                   │
│                                                  │
│  4. 代數簡化（Algebraic Simplification）      │
│     - x×1 = x, x+0 = x, 等                 │
│                                                  │
│  5. 形狀推導（Shape Inference）              │
│     - 靜態推導每個張量的形狀               │
└─────────────────────────────────────────────────┘
```

## 中階 IR（Operator Level）

### 算子表示

```
算子 IR 表示：
┌─────────────────────────────────────────────────┐
│  複合算子拆分：                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  一個 Conv2D 算子                        │   │
│  │    拆分為：                              │   │
│  │    - im2col（坐標轉換）                │   │
│  │    - GEMM（矩陣乘法）                  │   │
│  │    - col2im（坐標還原）                │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  算子屬性：                                      │
│  - 算子類型（Type）                          │
│  - 輸入/輸出形狀                            │
│  - 資料型態（Data Type）                   │
│  - 佈局（Layout，如 NHWC/NCHW）            │
│  - 屬性（如卷積步長、填充）                │
│                                                  │
│  中階優化：                                      │
│  - 算子內迴圈優化              │
│  - 資料佈局轉換                            │
│  - 算子分塊（Tile）                  │
└─────────────────────────────────────────────────┘
```

## 低階 IR（Instruction Level）

### 指令級表示

```
低階 IR：
┌─────────────────────────────────────────────────┐
│  低階 IR 包含：                                  │
│                                                  │
│  1. 記憶體搬運指令                              │
│     - Load/Store 張量區塊                    │
│     - DMA 搬運                              │
│                                                  │
│  2. 計算指令                                    │
│     - MAC / 矩陣運算                         │
│     - 活化函數                              │
│                                                  │
│  3. 控制指令                                    │
│     - 迴圈（Loop）                              │
│     - 分支（Branch）                          │
│                                                  │
│  4. 同步指令                                    │
│     - 屏障（Barrier）                        │
│     - 等待 DMA                            │
│                                                  │
│  低階優化：                                      │
│  - Trampoline 程式碼生成                     │
│  - 指令排程                                │
│  - 暫存器分配                              │
│  - 硬體特化                                 │
└─────────────────────────────────────────────────┘
```

## 常用 AI 編譯器架構

### XLA（加速線性代數）

```
XLA 編譯流程：
┌─────────────────────────────────────────────────┐
│  PyTorch/TensorFlow Graph                        │
│                ↓                                 │
│  ┌──────────────────────────────────────────┐   │
│  │  HLO（High-Level Optimizer）             │   │
│  │   - 圖最佳化、融合                     │   │
│  │   - 高階優化                          │   │
│  └──────────────────────────────────────────┘   │
│                ↓                                 │
│  ┌──────────────────────────────────────────┐   │
│  │  LHLO（Low-Level HLO）                   │   │
│  │   - 迴圈/分塊優化                      │   │
│  │    - 硬體特化                      │   │
│  └──────────────────────────────────────────┘   │
│                ↓                                 │
│  ┌──────────────────────────────────────────┐   │
│  │  各後端（CPU/GPU/TPU）                 │   │
│  │   - 生成 LLVM IR 或 TPU 指令          │   │
│  └──────────────────────────────────────────┘   │
│                ↓                                 │
│             機器/硬體                            │
└─────────────────────────────────────────────────┘
```

## IR 設計原則

### 好的 IR 特性

```
IR 設計考量：
┌─────────────────────────────────────────────────┐
│  1. 支援多種硬體                              │
│     - 抽象層要能涵蓋不同硬體                │
│                                                  │
│  2. 保留優化空間                              │
│     - 不要過早特化成特定硬體                │
│                                                  │
│  3. 可驗證性                                    │
│     - 易於檢查語義正確性                    │
│                                                  │
│  4. 可擴展性                                    │
│     - 方便加入新算子                        │
│     - 方便加入新優化                        │
│                                                  │
│  5. 性能        │                              │
│     - 編譯成本不能太高                        │
│     - 生成的代碼要高效                      │
└─────────────────────────────────────────────────┘
```

## 完整編譯流程

### 端到端範例

```
從框架到硬體（完整流程）：
┌─────────────────────────────────────────────────┐
│  1. 框架產生計算圖                              │
│     Y = model(input)                          │
│     → 產生 DAG（Graph IR）                    │
│                                                  │
│  2. 圖最佳化                                    │
│     - 融合（Fusion）                         │
│     - 常數折疊                              │
│     - 死代碼移除                            │
│                                                  │
│  3. 算子拆分                                  │
│     - 每個算子展開為低階運算                │
│     - 如 Conv → im2col + GEMM                │
│                                                  │
│  4. 排程與分塊                                │
│     - 決定執行順序                          │
│     - 決定資料分塊（Tiling）                │
│     - 決定記憶體放置                        │
│                                                  │
│  5. 代碼生成                                  │
│     - 生成硬體 kernel（CUDA/TPU 指令）     │
│     - 生成宿主代碼（管理記憶體）          │
│                                                  │
│  6. 執行                                      │
│     - 載入並執行 kernel                    │
└─────────────────────────────────────────────────┘
```

## 本章小結

- AI 編譯器將高階計算圖轉換為硬體指令
- 多層 IR：Graph → Operator → Instruction
- 高階 IR 適合整體圖優化（融合、折疊）
- 中階 IR 適合算子排程與分塊
- 低階 IR 適合硬體代碼生成
- XLA、MLIR、Triton 等是主流 AI 編譯器
- IR 設計需兼顧通用性、可優化性與效能
