# 3.3 記憶體階層（Memory Hierarchy）：Registers、Shared Memory、L2 Cache 到 HBM

## GPU 記憶體架構概覽

GPU 使用多層記憶體結構，以平衡容量、速度與成本：

```
GPU 記憶體階層：
┌─────────────────────────────────────────────────────────┐
│  層級        │  容量      │  延遲      │  頻寬         │
├─────────────────────────────────────────────────────────┤
│  Registers   │  256 KB/SM │  ~1 cycle  │  ~30 TB/s/SM │
│  Shared Mem  │  48-228KB/SM│ ~20-30cyc │  ~20 TB/s/SM │
│  L1 Cache    │  128-256KB/SM│ ~30-40cyc │  ~10 TB/s/SM │
│  L2 Cache    │  10-50 MB   │ ~100-200cyc│  ~5-10 TB/s  │
│  HBM        │  24-80 GB   │ ~300-400cyc│  ~2-4 TB/s   │
└─────────────────────────────────────────────────────────┘
```

## Registers（暫存器）

### 暫存器特性

```
暫存器規格：
┌─────────────────────────────────────────────────┐
│  位置：每個 SM 內部                             │
│  容量：65,536 × 32-bit = 256 KB/SM             │
│  延遲：1 個時脈週期                            │
│  存取：每個執行緒專用                           │
│                                                  │
│  頻寬：                                          │
│  - 每個 SM 每週期可讀寫 256 個 32-bit 暫存器  │
│  - 以 2 GHz 計算：~20 TB/s/SM                  │
└─────────────────────────────────────────────────┘
```

### 暫存器分配

```
暫存器分配機制：
┌─────────────────────────────────────────────────┐
│  每個執行緒可使用 1-255 個暫存器               │
│                                                  │
│  分配方式：                                      │
│  - 編譯時決定（靜態分配）                       │
│  - 依 kernel 的暫存器使用量決定                │
│                                                  │
│  對佔用率的影響：                                │
│  ┌─────────────────────────────────────────┐   │
│  │  暫存器/執行緒 │ 最大執行緒/SM │ 佔用率  │   │
│  ├─────────────────┼───────────────┼─────────┤   │
│  │      32        │    2048       │ 100%    │   │
│  │      64        │    1024       │  50%    │   │
│  │     128        │     512       │  25%    │   │
│  │     255        │     256       │ 12.5%   │   │
│  └─────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

## Shared Memory（共享記憶體）

### 共享記憶體特性

```
共享記憶體規格：
┌─────────────────────────────────────────────────┐
│  位置：每個 SM 內部                             │
│  容量：48-228 KB/SM（依架構）                   │
│  延遲：~20-30 個時脈週期                       │
│  存取：Block 內所有執行緒共享                   │
│                                                  │
│  Bank 結構：                                    │
│  - 32 個 Bank                                  │
│  - 每 Bank 4 bytes 寬                          │
│  - 可同時存取 32 個不同 Bank                   │
└─────────────────────────────────────────────────┘
```

### Shared Memory 用途

```
共享記憶體主要用途：
┌─────────────────────────────────────────────────┐
│  1. 執行緒間資料共享                            │
│     - 同一 Block 的執行緒可互相通訊             │
│     - 用於歸約（reduction）運算                 │
│                                                  │
│  2. 全局記憶體快取                              │
│     - 暫存常用的全域記憶體資料                  │
│     - 減少重複的全局記憶體存取                  │
│                                                  │
│  3. 矩陣分塊（Tiling）                         │
│     - 將矩陣分割為小區塊                       │
│     - 每個 Block 載入一個區塊到共享記憶體      │
│     - 在共享記憶體中完成區塊運算                │
└─────────────────────────────────────────────────┘
```

### Bank Conflict 詳解

```
Bank Conflict 類型：
┌─────────────────────────────────────────────────┐
│  32 個 Bank，每個 4 bytes                       │
│                                                  │
│  地址映射：                                      │
│  Bank = (Byte Address / 4) % 32                 │
│                                                  │
│  情境 1：無衝突                                 │
│  T0 → Bank 0, T1 → Bank 1, T2 → Bank 2, ...    │
│  效能：32 bytes/cycle（100%）                   │
│                                                  │
│  情境 2：2-way 衝突                             │
│  T0 → Bank 0, T1 → Bank 0, T2 → Bank 2, ...    │
│  效能：16 bytes/cycle（50%）                    │
│                                                  │
│  情境 3：N-way 衝突                             │
│  T0,T1,...,T(N-1) → Bank 0                      │
│  效能：32/N bytes/cycle                         │
└─────────────────────────────────────────────────┘
```

## L1 Cache

### L1 Cache 特性

```
L1 Cache 規格：
┌─────────────────────────────────────────────────┐
│  位置：每個 SM 內部                             │
│  容量：128-256 KB/SM（與共享記憶體共用 SRAM）   │
│  延遲：~30-40 個時脈週期                       │
│  管線：硬體管理，對程式透明                     │
│                                                  │
│  L1 與共享記憶體的關係：                        │
│  ┌─────────────────────────────────────────┐   │
│  │         SRAM Pool (192 KB)              │   │
│  │  ┌─────────────────┬─────────────────┐  │   │
│  │  │   L1 Cache      │  Shared Memory  │  │   │
│  │  │   (可調整比例)   │  (可調整比例)   │  │   │
│  │  └─────────────────┴─────────────────┘  │   │
│  └─────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

### L1 Cache 行為

```
L1 Cache 管線策略：
┌─────────────────────────────────────────────────┐
│  資料存取流程：                                  │
│                                                  │
│  1. 發出記憶體請求                              │
│     ↓                                           │
│  2. 檢查 Shared Memory                         │
│     ├─ 命中 → 傳回資料                         │
│     └─ 未命中 ↓                                │
│                                                  │
│  3. 檢查 L1 Cache                              │
│     ├─ 命中 → 傳回資料（~30 cycles）           │
│     └─ 未命中 ↓                                │
│                                                  │
│  4. 檢查 L2 Cache                              │
│     ├─ 命中 → 傳回資料（~100 cycles）          │
│     └─ 未命中 ↓                                │
│                                                  │
│  5. 存取 HBM                                   │
│     └─ 傳回資料（~300 cycles）                 │
└─────────────────────────────────────────────────┘
```

## L2 Cache

### L2 Cache 特性

```
L2 Cache 規格：
┌─────────────────────────────────────────────────┐
│  位置：晶片全域，所有 SM 共享                   │
│  容量：10-50 MB（依架構）                       │
│  延遲：~100-200 個時脈週期                     │
│  頻寬：~5-10 TB/s                               │
│                                                  │
│  功能：                                          │
│  1. 作為 L1 Cache 的下一層                     │
│  2. SM 間的資料共享中介                         │
│  3. 全域記憶體的快取                            │
└─────────────────────────────────────────────────┘
```

### L2 Cache 結構

```
L2 Cache 結構（H100 為例）：
┌─────────────────────────────────────────────────┐
│                  L2 Cache (50 MB)                │
│  ┌─────────────────────────────────────────────┐│
│  │              Partition 0                    ││
│  │    ┌───────┐  ┌───────┐  ┌───────┐        ││
│  │    │ Tag   │  │ Data  │  │ Status│        ││
│  │    └───────┘  └───────┘  └───────┘        ││
│  └─────────────────────────────────────────────┘│
│  ┌─────────────────────────────────────────────┐│
│  │              Partition 1                    ││
│  └─────────────────────────────────────────────┘│
│                      ...                        │
│  ┌─────────────────────────────────────────────┐│
│  │              Partition N                    ││
│  └─────────────────────────────────────────────┘│
│                                                  │
│  特性：                                          │
│  - 聯合式（Set-Associative）快取               │
│  - 16-way set associative                       │
│  - 支援 LRU 或 Pseudo-LRU 替換策略            │
└─────────────────────────────────────────────────┘
```

## HBM（High Bandwidth Memory）

### HBM 技術概述

```
HBM 架構：
┌─────────────────────────────────────────────────┐
│                  HBM Stack                       │
│  ┌─────────────────────────────────────────────┐│
│  │              Logic Die                       ││
│  │    ┌─────────────────────────────────────┐  ││
│  │    │         控制邏輯                     │  ││
│  │    └─────────────────────────────────────┘  ││
│  ├─────────────────────────────────────────────┤│
│  │              DRAM Die 0                     ││
│  ├─────────────────────────────────────────────┤│
│  │              DRAM Die 1                     ││
│  ├─────────────────────────────────────────────┤│
│  │              ...                            ││
│  ├─────────────────────────────────────────────┤│
│  │              DRAM Die 7                     ││
│  └─────────────────────────────────────────────┘│
│                                                  │
│  TSV（矽穿孔）連接各 Die                        │
│  每個 Die 提供 128-bit 通道                     │
│  8 個 Die = 1024-bit 匯流排                    │
└─────────────────────────────────────────────────┘
```

### HBM 規格演進

| 規格 | 頻寬/Die | Stack 容量 | 總頻寬 | 總容量 |
|------|----------|------------|--------|--------|
| HBM2 | 256 GB/s | 4-8 GB | 512 GB/s | 8-16 GB |
| HBM2e | 307 GB/s | 8-16 GB | 614 GB/s | 16-24 GB |
| HBM3 | 410 GB/s | 16-24 GB | 820 GB/s | 24-48 GB |
| HBM3e | 520 GB/s | 24-36 GB | 1.04 TB/s | 36-64 GB |
| HBM4 | 665 GB/s | 32-48 GB | 1.33 TB/s | 48-96 GB |

### HBM 與其他記憶體比較

| 特性 | DDR5 | GDDR6 | HBM3 |
|------|------|-------|------|
| 頻寬/通道 | 50 GB/s | 64 GB/s | 410 GB/s |
| 通道數 | 2-8 | 1-2 | 4-8 stacks |
| 總頻寬 | 100-400 GB/s | 64-128 GB/s | 1.6-3.3 TB/s |
| 功耗/GB | ~5 mW | ~20 mW | ~10 mW |
| 延遲 | ~50 ns | ~30 ns | ~25 ns |
| 成本/GB | ~$2 | ~$5 | ~$15 |

## 記憶體存取最佳化

### 1. 記憶體連鎖（Memory Coalescing）

```
記憶體連鎖效果：
┌─────────────────────────────────────────────────┐
│  不連鎖的存取：                                 │
│  T0 → addr 0                                    │
│  T1 → addr 128                                  │
│  T2 → addr 256                                  │
│  ...                                            │
│  結果：32 個獨立記憶體事務                      │
│                                                  │
│  連鎖的存取：                                   │
│  T0 → addr 0                                    │
│  T1 → addr 4                                    │
│  T2 → addr 8                                    │
│  ...                                            │
│  結果：1 個記憶體事務（128 bytes）              │
│                                                  │
│  效能差異：32 倍                                │
└─────────────────────────────────────────────────┘
```

### 2. 向量化存取

```
向量化存取：
┌─────────────────────────────────────────────────┐
│  // 32-bit 存取                                 │
│  float value = data[tid];                       │
│  // 每個執行緒存取 4 bytes                      │
│                                                  │
│  // 128-bit 向量存取                            │
│  float4 value = reinterpret_cast<float4*>(data) │
│                                          [tid];  │
│  // 每個執行緒存取 16 bytes                     │
│  // 記憶體事務數減少 4 倍                       │
└─────────────────────────────────────────────────┘
```

### 3. 預取（Prefetching）

```
預取策略：
┌─────────────────────────────────────────────────┐
│  1. 硬體預取                                    │
│     - GPU 自動偵測存取模式                      │
│     - 提前載入可能使用的資料                    │
│                                                  │
│  2. 軟體預取                                    │
│     - 使用 __ldg() 函數                         │
│     - 明確提示編譯器預取                        │
│                                                  │
│  // 軟體預取範例                                │
│  float next = __ldg(&data[tid + BLOCK_SIZE]);   │
│  // 預取下一個區塊的資料                        │
└─────────────────────────────────────────────────┘
```

## 效能分析

### 記憶體瓶頸分析

```
記憶體瓶頸類型：
┌─────────────────────────────────────────────────┐
│  1. 延遲瓶頸                                    │
│     - 特徵：低運算密度，高延遲需求              │
│     - 解決：增加佔用率，隱藏延遲                │
│                                                  │
│  2. 頻寬瓶頸                                    │
│     - 特徵：高資料傳輸需求                      │
│     - 解決：連鎖存取，向量化                    │
│                                                  │
│  3. 衝突瓶頸                                    │
│     - 特徵：Bank Conflict，快取失效             │
│     - 解決：優化存取模式                        │
└─────────────────────────────────────────────────┘
```

## 本章小結

- GPU 使用多層記憶體結構：Registers → Shared Memory → L1 → L2 → HBM
- 暫存器最快但容量最小，HBM 最慢但容量最大
- 共享記憶體用於執行緒間資料共享與全局記憶體快取
- 記憶體連鎖、向量化存取、預取是最佳化的關鍵
- HBM 提供高頻寬以應對 AI 運算的資料需求
