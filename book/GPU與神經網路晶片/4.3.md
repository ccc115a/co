# 4.3 記憶體存取優化：Coalescing（合併存取）與 Bank Conflict 消除

## 記憶體存取基礎

### GPU 記憶體存取模型

```
GPU 記憶體存取流程：
┌─────────────────────────────────────────────────┐
│  Thread 0  Thread 1  Thread 2  ...  Thread 31   │
│     │         │         │              │        │
│     ↓         ↓         ↓              ↓        │
│  ┌─────────────────────────────────────────────┐│
│  │         Memory Controller                   ││
│  │  - 合併相鄰存取（Coalescing）               ││
│  │  - 產生記憶體事務（Memory Transaction）      ││
│  └─────────────────────────────────────────────┘│
│                     ↓                           │
│  ┌─────────────────────────────────────────────┐│
│  │         Global Memory (HBM)                 ││
│  └─────────────────────────────────────────────┘│
└─────────────────────────────────────────────────┘
```

### 記憶體事務

```
記憶體事務大小：
┌─────────────────────────────────────────────────┐
│  L1 Cache 事務：128 bytes                      │
│  L2 Cache 事務：32 bytes                       │
│                                                  │
│  例如：                                          │
│  32 個執行緒各讀取 4 bytes                      │
│  = 128 bytes                                    │
│  = 1 個 L1 事務（最佳情況）                    │
└─────────────────────────────────────────────────┘
```

## Coalescing（合併存取）

### 最佳合併模式

```
最佳合併存取：
┌─────────────────────────────────────────────────┐
│  執行緒    │  存取位址    │  事務數   │  效率   │
├─────────────────────────────────────────────────┤
│  T0 → A[0]│  0x00       │          │         │
│  T1 → A[1]│  0x04       │  1       │  100%   │
│  T2 → A[2]│  0x08       │  事務    │         │
│  ...     │  ...        │          │         │
│  T31→ A[31]│ 0x7C      │          │         │
│                                                  │
│  32 個執行緒存取連續位址                        │
│  = 1 個 128-byte L1 事務                       │
└─────────────────────────────────────────────────┘
```

### 不佳的合併模式

```
跨步存取（不佳）：
┌─────────────────────────────────────────────────┐
│  執行緒    │  存取位址      │  事務數 │  效率  │
├─────────────────────────────────────────────────┤
│  T0 → A[0] │  0x00         │         │        │
│  T1 → A[32]│  0x80         │  32     │  3.1%  │
│  T2 → A[64]│  0x100        │  事務   │        │
│  ...       │  ...          │         │        │
│  T31→A[992]│ 0x1F80       │         │        │
│                                                  │
│  每個執行緒存取相隔 32 個元素                  │
│  = 32 個 128-byte L1 事務                      │
└─────────────────────────────────────────────────┘
```

### 合併存取規則

```
Coalescing 規則：
┌─────────────────────────────────────────────────┐
│  1. Warp 內執行緒應存取連續位址                 │
│                                                  │
│  2. 存取位址應對齊到 128 bytes                 │
│                                                  │
│  3. 最佳模式：T[i] 存取 base + i × size        │
│                                                  │
│  4. 識別模式：                                  │
│     - T[i] 存取 base + i：最佳                 │
│     - T[i] 存取 base + i × stride：需 stride=1 │
│     - T[i] 存取 base + (i/32)：不佳            │
└─────────────────────────────────────────────────┘
```

### 合併存取範例

```cpp
// 最佳：連續存取
__global__ void coalesced_access(float *data, float *output) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    output[tid] = data[tid] * 2.0f;  // 連續存取，合併良好
}

// 不佳：跨步存取
__global__ void strided_access(float *matrix, float *output, int width) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    // 每個執行緒存取不同列的相同行
    // T[i] 存取 matrix[i * width + col]
    output[tid] = matrix[tid * width + col];  // 跨步存取
}

// 改進：轉置或重新排列資料
__global__ void improved_access(float *matrix, float *output, int width) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    int col = tid % width;
    int row = tid / width;
    output[tid] = matrix[row * width + col];  // 連續存取
}
```

## Bank Conflict

### Shared Memory Bank 結構

```
Shared Memory Bank 結構：
┌─────────────────────────────────────────────────┐
│  32 個 Bank，每個 4 bytes 寬                    │
│                                                  │
│  位址映射：                                      │
│  Bank = (Byte Address / 4) % 32                 │
│                                                  │
│  範例：                                          │
│  位址 0x00 → Bank 0                            │
│  位址 0x04 → Bank 1                            │
│  位址 0x08 → Bank 2                            │
│  ...                                            │
│  位址 0x7C → Bank 31                           │
│  位址 0x80 → Bank 0（回到 Bank 0）             │
└─────────────────────────────────────────────────┘
```

### Bank Conflict 類型

```
Bank Conflict 類型：
┌─────────────────────────────────────────────────┐
│                                                  │
│  1. 無衝突（No Conflict）                       │
│     ┌─────┬─────┬─────┬─────┐                  │
│     │ B0  │ B1  │ B2  │ B3  │ ...              │
│     └──┬──┘└──┬──┘└──┬──┘└──┬──┘              │
│        T0     T1     T2     T3                  │
│     每個執行緒存取不同 Bank                     │
│     效能：1 cycle/word                         │
│                                                  │
│  2. 2-way 衝突                                  │
│     ┌─────┬─────┬─────┬─────┐                  │
│     │ B0  │ B1  │ B2  │ B3  │ ...              │
│     └──┬──┘└──┬──┘└──┬──┘└──┬──┘              │
│      T0,T1   T2     T3     T4                   │
│     2 個執行緒存取同一 Bank                    │
│     效能：2 cycles/word                        │
│                                                  │
│  3. N-way 衝突                                  │
│     所有執行緒存取同一 Bank                     │
│     效能：N cycles/word                         │
│                                                  │
└─────────────────────────────────────────────────┘
```

### Bank Conflict 範例

```cpp
// 會產生 Bank Conflict 的程式碼
__global__ void bank_conflict_kernel(float *data) {
    __shared__ float s_data[32];
    
    int tid = threadIdx.x;
    s_data[tid] = data[tid];
    __syncthreads();
    
    // 不佳的存取模式：所有執行緒存取相同位置
    float value = s_data[0];  // 32-way Bank Conflict！
    
    // 改進：每個執行緒存取自己的位置
    float value = s_data[tid];  // 無 Bank Conflict
}
```

## Bank Conflict 消除技巧

### 1. Padding（填充）

```cpp
// 使用 Padding 消除 Bank Conflict
__global__ void padding_kernel(float *data) {
    // 加入 padding 避免衝突
    __shared__ float s_data[32 + 1];  // +1 padding
    
    int tid = threadIdx.x;
    s_data[tid] = data[tid];
    __syncthreads();
    
    // 2-stride 存取模式
    // T[i] 存取 s_data[i * 2]
    // 無衝突因為加入 padding
    float value = s_data[tid * 2];
}
```

### 2. 索引重排

```cpp
// 重排索引避免衝突
__global__ void reindex_kernel(float *data) {
    __shared__ float s_data[32];
    
    int tid = threadIdx.x;
    s_data[tid] = data[tid];
    __syncthreads();
    
    // 重排索引：T[i] 存取 s_data[(i * 2) % 32]
    // 這會產生 Bank Conflict
    
    // 改進：T[i] 存取 s_data[i]
    // 無衝突
    float value = s_data[tid];
}
```

### 3. 使用向量化型別

```cpp
// 使用 float2, float4 減少存取次數
__global__ void vectorized_kernel(float *data) {
    __shared__ float4 s_data[8];  // 8 個 float4 = 32 個 float
    
    int tid = threadIdx.x;
    // 每個執行緒載入一個 float4
    reinterpret_cast<float4*>(s_data)[tid] = 
        reinterpret_cast<const float4*>(data)[blockIdx.x * blockDim.x + tid];
    __syncthreads();
    
    // 使用資料
    float4 value = s_data[tid];
}
```

## 整體記憶體存取最佳化

### 記憶體層級最佳化策略

```
記憶體最佳化策略：
┌─────────────────────────────────────────────────┐
│  1. 暫存器                                     │
│     - 使用內建變數避免暫存器溢出                │
│     - 使用 __launch_bounds__ 控制暫存器使用    │
│                                                  │
│  2. 共享記憶體                                 │
│     - 避免 Bank Conflict                       │
│     - 使用 Padding                             │
│     - 最小化同步點                              │
│                                                  │
│  3. L1/L2 Cache                                │
│     - 使用連續存取模式                          │
│     - 利用時間/空間局部性                      │
│                                                  │
│  4. 全域記憶體（HBM）                          │
│     - 最大化 Coalescing                        │
│     - 使用向量化存取                            │
│     - 預取常用資料                              │
└─────────────────────────────────────────────────┘
```

### 範例：矩陣轉置

```cpp
// 矩陣轉置最佳化
__global__ void transpose_optimized(float *input, float *output, 
                                    int width, int height) {
    __shared__ float tile[32][33];  // +1 padding 避免 Bank Conflict
    
    int x = blockIdx.x * 32 + threadIdx.x;
    int y = blockIdx.y * 32 + threadIdx.y;
    
    // 載入到共享記憶體（Coalesced 讀取）
    if (x < width && y < height) {
        tile[threadIdx.y][threadIdx.x] = input[y * width + x];
    }
    __syncthreads();
    
    // 轉置索引
    x = blockIdx.y * 32 + threadIdx.x;
    y = blockIdx.x * 32 + threadIdx.y;
    
    // 寫入到全域記憶體（Coalesced 寫入）
    if (x < height && y < width) {
        output[y * height + x] = tile[threadIdx.x][threadIdx.y];
    }
}
```

### 範例：向量內積

```cpp
// 向量內積最佳化
__global__ void dot_product(float *a, float *b, float *result, int n) {
    __shared__ float s_data[256];
    
    int tid = threadIdx.x;
    int gid = blockIdx.x * blockDim.x + threadIdx.x;
    
    // 每個執行緒計算一個部分積
    float sum = 0.0f;
    if (gid < n) {
        sum = a[gid] * b[gid];
    }
    s_data[tid] = sum;
    __syncthreads();
    
    // 歸約運算（在共享記憶體中）
    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1) {
        if (tid < stride) {
            s_data[tid] += s_data[tid + stride];
        }
        __syncthreads();
    }
    
    // 第一個執行緒寫入結果
    if (tid == 0) {
        atomicAdd(result, s_data[0]);
    }
}
```

## 本章小結

- Coalescing 是將 Warp 內相鄰記憶體存取合併為單一事務的技術
- Bank Conflict 發生在多個執行緒同時存取同一 Bank 時
- Padding、索引重排、向量化是消除 Bank Conflict 的有效方法
- 記憶體存取最佳化應從暫存器到 HBM 全面考慮
- 效能分析工具可幫助識別記憶體瓶頸
