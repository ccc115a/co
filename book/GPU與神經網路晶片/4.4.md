# 4.4 CUDA Graph 與 Kernel Fusion（核心融合）技術

## CUDA Graph 概述

### CUDA Graph 的問題背景

在傳統 CUDA 程式中，每次 kernel 啟動都有固定開銷：

```
傳統 CUDA 啟動開銷：
┌─────────────────────────────────────────────────┐
│  Kernel 啟動流程：                               │
│  1. CPU 端 API 呼叫                             │
│  2. 驗證參數                                    │
│  3. 準備執行環境                                │
│  4. 將 kernel 加入執行佇列                      │
│  5. GPU 調度器分配資源                          │
│                                                  │
│  每次啟動開銷：~5-10 µs                        │
│                                                  │
│  問題：                                          │
│  - 大量小 kernel 導致 CPU 瓶頸                 │
│  - GPU 資源閒置等待 kernel 啟動                 │
│  - 頻繁的 CPU-GPU 同步                          │
└─────────────────────────────────────────────────┘
```

### CUDA Graph 解決方案

```
CUDA Graph 概念：
┌─────────────────────────────────────────────────┐
│                                                  │
│  傳統模式：                                      │
│  CPU → Kernel 1 → CPU → Kernel 2 → CPU → ...   │
│                                                  │
│  CUDA Graph 模式：                              │
│  CPU → Graph（Kernel 1, 2, 3...）→ GPU         │
│                                                  │
│  優勢：                                          │
│  - 一次定義，多次執行                           │
│  - 減少 CPU-GPU 互動                            │
│  - 更好的排程與最佳化                           │
└─────────────────────────────────────────────────┘
```

## CUDA Graph API

### Graph 建立方式

```cpp
// 方式 1：Capture 模式（自動捕獲）
cudaGraph_t graph;
cudaGraphExec_t graphExec;

// 開始捕獲
cudaStreamBeginCapture(stream, cudaStreamCaptureModeGlobal);

// 執行 kernel（這些會被記錄到 graph）
kernel1<<<grid, block, 0, stream>>>(args1);
kernel2<<<grid, block, 0, stream>>>(args2);
kernel3<<<grid, block, 0, stream>>>(args3);

// 結束捕獲
cudaStreamEndCapture(stream, &graph);

// 建立可執行的 graph
cudaGraphInstantiate(&graphExec, graph, nullptr, nullptr, 0);

// 執行 graph
cudaGraphLaunch(graphExec, stream);
cudaStreamSynchronize(stream);
```

```cpp
// 方式 2：手動建構（完全控制）
cudaGraph_t graph;
cudaGraphCreate(&graph, 0);

// 建立 kernel 節點
cudaKernelNodeParams nodeParams = {0};
nodeParams.func = (void*)kernel1;
nodeParams.gridDim = grid;
nodeParams.blockDim = block;
nodeParams.sharedMemSize = 0;
nodeParams.kernelParams = args1;

cudaGraphNode_t node1, node2, node3;
cudaGraphAddKernelNode(&node1, graph, nullptr, 0, &nodeParams);
cudaGraphAddKernelNode(&node2, graph, &node1, 1, &nodeParams2);
cudaGraphAddKernelNode(&node3, graph, &node2, 1, &nodeParams3);

// 建立可執行的 graph
cudaGraphInstantiate(&graphExec, graph, nullptr, nullptr, 0);
```

CUDA Graph 節點類型：
┌─────────────────────────────────────────────────┐
│  類型                   │  說明                  │

## Kernel Fusion 概述

### Kernel Fusion 的定義

Kernel Fusion 是將多個 kernel 合併為單一 kernel 的技術：

```
Kernel Fusion 概念：
┌─────────────────────────────────────────────────┐
│  融合前：                                        │
│  ┌─────────┐   ┌─────────┐   ┌─────────┐      │
│  │Kernel 1 │ → │Kernel 2 │ → │Kernel 3 │      │
│  │ (A+B)   │   │ (C×D)   │   │ (E+F)   │      │
│  └─────────┘   └─────────┘   └─────────┘      │
│                                                  │
│  問題：                                          │
│  - 3 次全域記憶體讀寫                           │
│  - 3 次 kernel 啟動開銷                         │
│  - 資料在 GPU 內來回搬運                        │
│                                                  │
│  融合後：                                        │
│  ┌─────────────────────────────────────────┐   │
│  │           Fused Kernel                   │   │
│  │   result = (A+B) × (C×D) + (E+F)       │   │
│  └─────────────────────────────────────────┘   │
│                                                  │
│  優勢：                                          │
│  - 1 次全域記憶體讀寫                           │
│  - 1 次 kernel 啟動開銷                         │
│  - 減少記憶體頻寬需求                           │
└─────────────────────────────────────────────────┘
```

### Fusion 類型

```
Kernel Fusion 類型：
┌─────────────────────────────────────────────────┐
│  1. Pointwise Fusion（逐元素融合）              │
│     - 融合逐元素運算                            │
│     - 如：add, multiply, activation            │
│     - 最常見且最容易實現                        │
│                                                  │
│  2. Reduction Fusion（歸約融合）               │
│     - 融合歸約運算                              │
│     - 如：sum, max, min                        │
│     - 需要同步操作                              │
│                                                  │
│  3. Layout Transformation Fusion              │
│     - 融合資料佈局轉換                          │
│     - 如：transpose, reshape                   │
│     - 可與其他運算融合                          │
│                                                  │
│  4. Attention Fusion                           │
│     - 融合注意力機制                            │
│     - 如：QK^T, softmax, ×V                   │
│     - Transformer 專用                         │
└─────────────────────────────────────────────────┘
```

## 實作 Kernel Fusion

### 手動 Fusion 範例

```cpp
// 融合前：三個獨立 kernel
__global__ void add_kernel(float *a, float *b, float *c, int n) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    if (tid < n) {
        c[tid] = a[tid] + b[tid];
    }
}

__global__ void mul_kernel(float *c, float *d, float *e, int n) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    if (tid < n) {
        e[tid] = c[tid] * d[tid];
    }
}

__global__ void activate_kernel(float *e, float *f, int n) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    if (tid < n) {
        f[tid] = tanhf(e[tid]);
    }
}

// 融合後：單一 kernel
__global__ void fused_kernel(float *a, float *b, float *d, 
                             float *f, int n) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    if (tid < n) {
        float sum = a[tid] + b[tid];
        float mul = sum * d[tid];
        f[tid] = tanhf(mul);
    }
}
```

### 使用 CUDA Graph 實現 Fusion

```cpp
// 使用 CUDA Graph 自動融合
void fused_execution(float *a, float *b, float *c, 
                     float *d, float *e, float *f, int n) {
    cudaStream_t stream;
    cudaStreamCreate(&stream);
    
    cudaGraph_t graph;
    cudaGraphExec_t graphExec;
    
    // 捕獲 kernel 執行
    cudaStreamBeginCapture(stream, cudaStreamCaptureModeGlobal);
    
    add_kernel<<<grid, block, 0, stream>>>(a, b, c, n);
    mul_kernel<<<grid, block, 0, stream>>>(c, d, e, n);
    activate_kernel<<<grid, block, 0, stream>>>(e, f, n);
    
    cudaStreamEndCapture(stream, &graph);
    cudaGraphInstantiate(&graphExec, graph, nullptr, nullptr, 0);
    
    // 多次執行（只需一次編譯）
    for (int i = 0; i < 1000; i++) {
        cudaGraphLaunch(graphExec, stream);
    }
    
    cudaStreamSynchronize(stream);
    
    // 清理
    cudaGraphExecDestroy(graphExec);
    cudaGraphDestroy(graph);
    cudaStreamDestroy(stream);
}
```

## 自動 Fusion 工具

### PyTorch TorchDynamo

```python
import torch

# 使用 torch.compile 自動 Fusion
@torch.compile
def fused_model(x, w1, b1, w2, b2):
    h = torch.relu(x @ w1 + b1)
    return h @ w2 + b2

# 自動 fusion + 編譯最佳化
output = fused_model(input, w1, b1, w2, b2)
```

### Triton

```python
import triton
import triton.language as tl

@triton.jit
def fused_add_mul_kernel(a_ptr, b_ptr, d_ptr, f_ptr, n_ptr,
                         BLOCK_SIZE: tl.constexpr):
    pid = tl.program_id(0)
    offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offsets < n_ptr
    
    a = tl.load(a_ptr + offsets, mask=mask)
    b = tl.load(b_ptr + offsets, mask=mask)
    d = tl.load(d_ptr + offsets, mask=mask)
    
    sum = a + b
    mul = sum * d
    f = tl.math.tanh(mul)
    
    tl.store(f_ptr + offsets, f, mask=mask)

# 啟動
BLOCK_SIZE = 1024
grid = lambda meta: (triton.cdiv(n, meta['BLOCK_SIZE']),)
fused_add_mul_kernel[grid](a, b, d, f, n, BLOCK_SIZE=BLOCK_SIZE)
```

## Fusion 效能分析

### Fusion 效益

```
Fusion 效益量化：
┌─────────────────────────────────────────────────┐
│  減少的記憶體存取：                             │
│  - 融合前：3 次讀 + 3 次寫 = 6 次全域存取     │
│  - 融合後：2 次讀 + 1 次寫 = 3 次全域存取     │
│  - 節省：50% 記憶體頻寬                        │
│                                                  │
│  減少的 kernel 啟動：                           │
│  - 融合前：3 次啟動 ≈ 15-30 µs                │
│  - 融合後：1 次啟動 ≈ 5-10 µs                 │
│                                                  │
│  改善的 cache 利用率：                          │
│  - 中間結果留在暫存器或共享記憶體              │
│  - 減少 L1/L2 cache 壓力                       │
└─────────────────────────────────────────────────┘
```

### Fusion 限制

```
Fusion 限制因素：
┌─────────────────────────────────────────────────┐
│  1. 暫存器壓力                                  │
│     - 融合增加暫存器使用                        │
│     - 可能降低佔用率                            │
│                                                  │
│  2. 程式複雜度                                  │
│     - 手動 Fusion 增加開發難度                  │
│     - 需要深入理解硬體                          │
│                                                  │
│  3. 精度問題                                    │
│     - 融合可能改變運算順序                      │
│     - 浮點運算的結合律不嚴格                    │
│                                                  │
│  4. 依賴關係                                    │
│     - 有資料依賴的 kernel 無法 Fusion          │
│     - 需要同步的運算難以 Fusion                │
└─────────────────────────────────────────────────┘
```

## 最佳化策略

### Graph 與 Fusion 結合

```cpp
// 結合 CUDA Graph 與 Fusion
void optimized_execution(float *input, float *output, int n) {
    static cudaGraphExec_t graphExec = nullptr;
    static bool initialized = false;
    
    if (!initialized) {
        cudaStream_t stream;
        cudaStreamCreate(&stream);
        
        cudaGraph_t graph;
        cudaStreamBeginCapture(stream, cudaStreamCaptureModeGlobal);
        
        // 融合的 kernel 邏輯
        fused_kernel<<<grid, block, 0, stream>>>(input, output, n);
        
        cudaStreamEndCapture(stream, &graph);
        cudaGraphInstantiate(&graphExec, graph, nullptr, nullptr, 0);
        
        cudaStreamDestroy(stream);
        initialized = true;
    }
    
    // 高效執行
    cudaGraphLaunch(graphExec, 0);
    cudaDeviceSynchronize();
}
```

### 動態 Fusion

```cpp
// 動態 Fusion：根據輸入大小選擇不同的 Fusion 策略
__global__ void dynamic_fused_kernel(float *a, float *b, 
                                      float *c, int n, int mode) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    
    if (mode == 0) {
        // 模式 0：簡單融合
        c[tid] = a[tid] + b[tid];
    } else if (mode == 1) {
        // 模式 1：複雜融合
        c[tid] = tanhf(a[tid] + b[tid]);
    } else {
        // 模式 2：更多運算
        c[tid] = expf(a[tid]) * logf(b[tid] + 1.0f);
    }
}
```

## 本章小結

- CUDA Graph 透過預先定義執行流程減少 kernel 啟動開銷
- Kernel Fusion 將多個 kernel 合併為單一 kernel，減少記憶體存取
- 自動 Fusion 工具如 TorchDynamo、Triton 可簡化開發
- Graph 與 Fusion 結合可進一步提升效能
- Fusion 受限於暫存器壓力、程式複雜度、精度問題等因素
