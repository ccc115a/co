# 11.3 KV Cache 記憶體管理與 PagedAttention 技術

## KV Cache 概念

### 什麼是 KV Cache

```
KV Cache 定義：
┌─────────────────────────────────────────────────┐
│  KV Cache 是 LLM 推論中的快取機制：              │
│                                                  │
│  - 儲存計算過的 Key（K）與 Value（V）向量      │
│  - 避免重複計算歷史 token 的 K、V            │
│                                                  │
│  運作原理：                                      │
│  ┌──────────────────────────────────────────┐   │
│  │  第 t 層：                               │   │
│  │  token 1 → K1, V1（計算並儲存）         │   │
│  │  token 2 → K2, V2（計算並儲存）         │   │
│  │  ...                                     │   │
│  │  token n → 只需讀取 K1..Vn（重用）      │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  用途：                                          │
│  - Decode 階段避免重算歷史 token 的 K、V    │
│  - 每次只需計算新 token 的 K、V             │
└─────────────────────────────────────────────────┘
```

### KV Cache 的記憶體需求

```
KV Cache 記憶體計算：
┌─────────────────────────────────────────────────┐
│  每個 token 的 KV Cache 大小：                   │
│  = 2（K和V）                                    │
│    × 層數（L）                                │
│    × 每層隱藏維度說明（2×，含 GQA）             │
│    × 位元組（如 2 bytes for FP16）              │
│                                                  │
│  範例（7B 模型）：                                │
│  - 層數：32                                    │
│  - 每層 KV 維度（GQA）：4096                  │
│  - 每 token：32×2×4096×2 = 512 KB             │
│                                                  │
│  序列長度影響：                                  │
│  - 序列長度 2048：512 KB × 2048 ≈ 1 GB        │
│  - 序列長度 128K：約 64 GB！                │
│                                                  │
│  概念：                                          │
│  KV Cache 隨著序列長度線性成長            │
│  在多請求併發時會非常龐大            │
└─────────────────────────────────────────────────┘
```

## KV Cache 記憶體管理問題

### 記憶體碎片與浪費

```
傳統 KV Cache 問題：
┌─────────────────────────────────────────────────┐
│  傳統管理方式：                                  │
│  - 每個請求「預先」分配最大長度記憶體      │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  請求 A（實際 100 token）                 │   │
│  │  [分配 2048 token 的空間]                 │   │
│  │  [░░░░░░100░░░░░░░ 空閒區░░░░░░░░]       │   │
│  └──────────────────────────────────────────┘   │
│  → 浪費大量未使用的空間                  │
│                                                  │
│  問題：                                          │
│  1. 內部碎片（Inner Fragmentation）             │
│     - 預先分配過多                    │
│  2. 外部碎片（External Fragmentation）          │
│     - 記憶體不連續，無法有效利用        │
│  3. 記憶體使用效率低                        │
│     - 通常只有 20-40% 有效率              │
└─────────────────────────────────────────────────┘
```

## PagedAttention

### PagedAttention 核心思想

```
PagedAttention（vLLM）：
┌─────────────────────────────────────────────────┐
│  靈感來源：OS 的虛擬記憶體分頁機制              │
│                                                  │
│  核心概念：                                      │
│  - 將 KV Cache 分割成「頁」（Block/Page）      │
│  - 動態分配頁（不像傳統預先分配）         │
│  - 像虛擬記憶體一樣映射              │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  傳統：一整塊連續記憶體                  │   │
│  │  [─────────── 整塊 ───────────]          │   │
│  │                                          │   │
│  │  PagedAttention：分割成頁              │   │
│  │  [頁0][頁1][頁2][頁3]...（分散位置）     │   │
│  │  （透過頁表映射到連續邏輯位址）          │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  優勢：                                          │
│  - 消除預先分配浪費                    │
│  - 消除外部碎片                        │
│  - 動態管理非常靈活                │
└─────────────────────────────────────────────────┘
```

### 邏輯與實體分離

```
邏輯/實體位址分離：
┌─────────────────────────────────────────────────┐
│  邏輯 KV Cache：                                 │
│  ┌──────────────────────────────────────────┐   │
│  │  邏輯頁 0    邏輯頁 1    邏輯頁 2         │   │
│  │  token0-31  token32-63  token64-95        │   │
│  └──────────────────────────────────────────┘   │
│               ↓ 頁表映射                        │
│  │                                                  │
│  實體記憶體：                                    │
│  ┌───────┬───────┬───────┬───────┬───────┐       │
│  │物理頁5│物理頁1│物理頁7│物理頁3│物理頁2│ ...  │
│  └───────┴───────┴───────┴───────┴───────┘       │
│                                                  │
│  頁表（Page Table）：                            │
│  │ 邏輯頁 0 → 物理頁 5                        │
│  │ 邏輯頁 1 → 物理頁 1                        │
│  │ 邏輯頁 2 → 物理頁 7                        │
│                                                  │
│  效果：                                          │
│  - 分散的物理記憶體可呈現連續邏輯         │
│  - 動態擴展不需重整                      │
└─────────────────────────────────────────────────┘
```

### Block 大小選擇

```
Block 大小設計：
┌─────────────────────────────────────────────────┐
│  Block 大小（每頁 token 數）：                   │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  Block 大小 │  優點         │  缺點     │   │
│  ├──────────────────────────────────────────┤   │
│  │  大（64）   │  較少頁表     │  內部碎片 │   │
│  │  中（16）   │  平衡        │  中等     │   │
│  │  小（4）    │  少碎片      │  頁表多   │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  vLLM 預設：16 token/block                    │
│                                                  │
│  儲存格式：                                      │
│  - Block 內使用緊湊的布局                  │
│  - 依層組織（Layer-Major）                │
│  - 依張量組織（Tensor-Major）            │
└─────────────────────────────────────────────────┘
```

## PagedAttention 的記憶體管理

### 動態分配

```
動態記憶體管理：
┌─────────────────────────────────────────────────┐
│  1. 請求到達：                                  │
│     - 預allocate 少量頁                │
│     - 隨 token 產生動態擴展            │
│                                                  │
│  2. 記憶體不足時：                              │
│     - 觸發淘汰（Eviction）              │
│     - 選擇要釋放的請求        │
│                                                  │
│  3. 請求完成：                                  │
│     - 釋放所有的頁                      │
│     - 歸還給記憶體池                  │
│                                                  │
│  優點：                                          │
│  - 記憶體利用率提升                        │
│  - 可服務更多並發請求                        │
│  - 靈活適應不同長度序列                  │
└─────────────────────────────────────────────────┘
```

### 記憶體共享（Copy-on-Write）

```
記憶體共享（針對多 token 生成）：
┌─────────────────────────────────────────────────┐
│  Beam Search / 平行抽樣：                        │
│  - 多個生成路徑共享相同的歷史            │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  共同前綴：token0-15（共享）             │   │
│  │  路徑 A：16, 17, 18...                  │   │
│  │  路徑 B：16, 19, 20...                  │   │
│  │                │                      │   │
│  │  前 16 token 的 KV Cache 可共享！        │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  Copy-on-Write：                          │
│  - 多個請求共享相同頁                     │
│  - 需要寫入時才複製（COW）          │
│  - 節省大量記憶體                    │
│                                                  │
│  同時支援：                                      │
│  - 前綴共享（Prefix Sharing）            │
│  - 並行抽取共享                        │
└─────────────────────────────────────────────────┘
```

## 效能影響

### 記憶體效率提升

```
PagedAttention 效益：
┌─────────────────────────────────────────────────┐
│  連續批次（Continuous Batching）：               │
│  - 傳統：等整個批次完成再換新批次               │
│  - 連續：一個請求完成立即加入新請求           │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  傳統批次：                              │   │
│  │  [請求A][請求B][空等]                    │   │
│  │         ↑ 等待                              │   │
│  │  連續批次：                                │   │
│  │  [請求A][請求C]（B完成，C加入）          │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  結果：                                          │
│  - 記憶體利用率：20-40% → 90%+             │
│  - 吞吐量提升：2-4 倍                       │
│  - 支援更多並發請求                    │
└─────────────────────────────────────────────────┘
```

## 其他 KV Cache 優化

### 相關技術

```
KV Cache 其他優化：
┌─────────────────────────────────────────────────┐
│  1. KV Cache 量化                              │
│     - 將 KV 量化到 INT8/FP8            │
│     - 減少記憶體一半以上               │
│                                                  │
│  2. KV Cache 共享（MLA）              │
│     - Multi-head Latent Attention      │
│     - 壓縮多個頭的 KV             │
│     - 大幅減少記憶體（DeepSeek）     │
│                                                  │
│  3. KV Cache 淘汰（Eviction）                │
│     - 丟棄不重要的歷史 KV              │
│     - 基於注意力權重重要性          │
│                                                  │
│  4. 滑動視窗（Sliding Window）        │
│     - 只保留最近的 KV             │
│     - 適用於局部注意力模型        │
└─────────────────────────────────────────────────┘
```

## 本章小結

- KV Cache 儲存計算過的 Key/Value 向量，避免重算
- KV Cache 記憶體隨序列長度線性成長
- 傳統管理有內部/外部碎片與浪費
- PagedAttention 將 KV Cache 分割成頁、動態管理
- 邏輯/實体位址分離提升記憶體利用率
- Copy-on-Write 支援多路徑共享
- 連續批次大幅提升吞吐量
- vLLM 基於 PagedAttention 實現高效推論
