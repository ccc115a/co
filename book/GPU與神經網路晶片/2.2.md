# 2.2 GPU 的崛起：SIMD/SIMT（單指令多執行緒）架構邏輯

## 從顯示卡到通用運算處理器

GPU（Graphics Processing Unit）最初是為加速 3D 圖形渲染而設計的。圖形運算具有高度平行性：每個像素的運算相互獨立，適合使用大量簡單的運算單元同時處理。

### 圖形管線與平行性

```
圖形管線（Graphics Pipeline）：
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 頂點    │ → │ 光柵化  │ → │ 像素    │ → │ 輸出    │
│ 處理    │   │         │   │ 著色    │   │ 影像    │
└─────────┘   └─────────┘   └─────────┘   └─────────┘
    ↑                          ↑
    │                          │
 幾何運算                    像素運算
（數量較少）              （數量龐大，可平行）
```

## SIMD 與 SIMT 的差異

### SIMD（Single Instruction, Multiple Data）

SIMD 是一種指令層級的平行技術，單一指令可同時處理多筆資料：

```
SIMD 運算示意：
指令：ADD V1, V2, V3（向量加法）

V1: [a1, a2, a3, a4]
V2: [b1, b2, b3, b4]
         ↓ SIMD 指令 ↓
V3: [a1+b1, a2+b2, a3+b3, a4+b4]

傳統 CPU（SMD）：
週期 1：a1 + b1
週期 2：a2 + b2
週期 3：a3 + b3
週期 4：a4 + b4

SIMD CPU：
週期 1：[a1+b1, a2+b2, a3+b3, a4+b4]
```

### SIMT（Single Instruction, Multiple Threads）

SIMT 是 NVIDIA GPU 使用的執行模型，結合了 SIMD 的效率與執行緒的抽象：

```
SIMT 執行模型：
┌─────────────────────────────────────────┐
│              Warp（32 個執行緒）          │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐  │
│  │ T0  │ T1  │ T2  │ T3  │ ... │ T31 │  │
│  └──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┘  │
│     │     │     │     │     │     │     │
│     ↓     ↓     ↓     ↓     ↓     ↓     │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐  │
│  │ ALU │ ALU │ ALU │ ALU │ ALU │ ALU │  │
│  └─────┴─────┴─────┴─────┴─────┴─────┘  │
└─────────────────────────────────────────┘
         同一指令，不同資料
```

### SIMD vs SIMT 的關鍵差異

| 特性 | SIMD | SIMT |
|------|------|------|
| 程式模型 | 向量運算 | 執行緒運算 |
| 資料寬度 | 固定（128/256/512-bit） | 彈性（依 Warp 大小） |
| 分支處理 | 需要掩碼（Mask） | 自然支援（但有效能損失） |
| 程式難度 | 需要向量化意識 | 接近平行程式設計 |
| 硬體實現 | 簡單 | 需要執行緒調度器 |

## GPU 微架構基礎

### Streaming Multiprocessor（SM）

SM 是 GPU 的核心運算單位：

```
┌─────────────────────────────────────────────────┐
│              Streaming Multiprocessor (SM)       │
│  ┌─────────────────────────────────────────────┐│
│  │           指管線（Instruction Pipeline）     ││
│  │  ┌──────────┐  ┌──────────┐  ┌──────────┐  ││
│  │  │ Warp     │  │ Warp     │  │ Warp     │  ││
│  │  │ Scheduler│  │ Scheduler│  │ Scheduler│  ││
│  │  │ #0       │  │ #1       │  │ #2       │  ││
│  │  └──────────┘  └──────────┘  └──────────┘  ││
│  └─────────────────────────────────────────────┘│
│                                                 │
│  ┌─────────────────────────────────────────────┐│
│  │           運算單元（Execution Units）        ││
│  │  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────────────┐  ││
│  │  │ FP32│ │ FP32│ │ INT32│ │ Tensor Core │  ││
│  │  │ ALU │ │ ALU │ │ ALU │ │             │  ││
│  │  └─────┘ └─────┘ └─────┘ └─────────────┘  ││
│  └─────────────────────────────────────────────┘│
│                                                 │
│  ┌─────────────────────────────────────────────┐│
│  │           記憶體子系統                        ││
│  │  ┌─────────────┐  ┌─────────────┐          ││
│  │  │ Register    │  │ Shared      │          ││
│  │  │ File        │  │ Memory      │          ││
│  │  │ (65536×32b) │  │ (48-228 KB) │          ││
│  │  └─────────────┘  └─────────────┘          ││
│  └─────────────────────────────────────────────┘│
└─────────────────────────────────────────────────┘
```

### Warp 執行模型

Warp 是 GPU 執行的基本單位，由 32 個執行緒組成：

```
Warp 執行流程：
┌─────────────────────────────────────────────────┐
│  週期 1：取出 Warp 0 的指令                      │
│  ┌─────┬─────┬─────┬─────┬─────┐               │
│  │ T0  │ T1  │ T2  │ ... │ T31 │ → 執行指令   │
│  └─────┴─────┴─────┴─────┴─────┘               │
├─────────────────────────────────────────────────┤
│  週期 2：取出 Warp 1 的指令                      │
│  ┌─────┬─────┬─────┬─────┬─────┐               │
│  │ T0  │ T1  │ T2  │ ... │ T31 │ → 執行指令   │
│  └─────┴─────┴─────┴─────┴─────┘               │
├─────────────────────────────────────────────────┤
│  ...                                            │
└─────────────────────────────────────────────────┘

GPU 可同時管理數十個 Warp（Warps in Flight）
```

### Warp Divergence（分支分歧）

當 Warp 內的執行緒需要走不同分支時，會產生效率損失：

```
if (threadIdx.x < 16) {
    // Path A：執行緒 0-15
    do_work_A();
} else {
    // Path B：執行緒 16-31
    do_work_B();
}

Warp 執行流程：
週期 1：啟用 Path A（T0-T15 執行，T16-T31 停用）
週期 2：啟用 Path B（T16-T31 執行，T0-T15 停用）

效能損失：~50%（理想情況）
```

## GPU 記憶體架構

### 記憶體層級

```
┌─────────────────────────────────────────────────┐
│                  記憶體層級                        │
├─────────────────────────────────────────────────┤
│  暫存器（Registers）        每 SM ~65K×32-bit    │
│  ↓                                               │
│  共享記憶體（Shared Memory）  每 SM 48-228 KB    │
│  ↓                                               │
│  L1 快取                    每 SM 128-256 KB    │
│  ↓                                               │
│  L2 快取                    全局 10-50 MB        │
│  ↓                                               │
│  全局記憶體（HBM）           24-80 GB            │
└─────────────────────────────────────────────────┘

頻寬與容量的權衡：
- 暫存器：~30 TB/s（理論），數百 KB
- 共享記憶體：~20 TB/s，數百 KB
- HBM：~3 TB/s，數十 GB
```

## GPU vs CPU 的核心差異

| 設計哲學 | CPU | GPU |
|----------|-----|-----|
| 核心數量 | 數十個 | 數千個 |
| 單核心複雜度 | 高（複雜控制邏輯） | 低（簡單控制） |
| 快取大小 | 大（數十 MB） | 小（數十 KB/SM） |
| 暫存器數量 | 數十個/核心 | 數萬個/SM |
| 指令集 | 複雜（CISC/RISC） | 簡單 |
| 適用場景 | 串行、複雜邏輯 | 平行、規則運算 |

## NVIDIA GPU 架構演進

|------|------|----------|
| Tesla | 2006 | 首個支援 CUDA 的架構 |

| Maxwell | 2014 | 更高的每瓦效能 |

| Blackwell | 2024 | 第二代 Tensor Core、FP4 |

## 本章小結

- GPU 從圖形處理器演進為通用平行運算處理器
- SIMT 模型結合了 SIMD 的效率與執行緒的程式抽象
- Warp 是 GPU 執行的基本單位，包含 32 個執行緒
- Warp Divergence 會導致效能下降，應盡量避免
- GPU 使用多層記憶體架構，在容量與頻寬間取得平衡
