# 3.1 Streaming Multiprocessor (SM) 核心組件：ALU、Tensor Core、L1 Cache/Shared Memory

## SM 的角色與地位

Streaming Multiprocessor（SM）是 NVIDIA GPU 的核心運算單位。每個 GPU 晶片包含多個 SM，每個 SM 又包含多個執行單元，可同時處理大量執行緒。

### GPU 晶片結構概覽

```
NVIDIA H100 SXM 架構：
┌─────────────────────────────────────────────────────────┐
│                        GPC × 8                          │
│  ┌─────────────────────────────────────────────────────┐│
│  │                      TPC × 2                        ││
│  │  ┌─────────────────────────────────────────────┐   ││
│  │  │              SM × 2                         │   ││
│  │  │  ┌─────────────────────────────────────┐   │   ││
│  │  │  │  - CUDA Cores × 128 (FP32)          │   │   ││
│  │  │  │  - Tensor Core × 4                  │   │   ││
│  │  │  │  - 特殊功能單元（SFU）               │   │   ││
│  │  │  │  - 載入/儲存單元（LSU）             │   │   ││
│  │  │  │  - 共享記憶體/L1 快取               │   │   ││
│  │  │  │  - 暫存器檔                         │   │   ││

│  │                    HBM3 (80 GB)                     ││
│  └─────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────┘

SM 總數：132 個
```

## SM 核心組件

### 1. CUDA Cores（運算單元）

CUDA Core 是基本的浮點運算單元，可執行 FP32 或 INT32 運算：

```
CUDA Core 結構：
┌─────────────────────────────────────────┐
│              CUDA Core                   │
│  ┌─────────────────────────────────┐   │
│  │         FP32 ALU               │   │
│  │    ┌─────────────────────┐     │   │
│  │    │    32-bit 浮點      │     │   │
│  │    │    乘加運算單元     │     │   │
│  │    └─────────────────────┘     │   │
│  └─────────────────────────────────┘   │
│  ┌─────────────────────────────────┐   │
│  │         INT32 ALU               │   │
│  │    ┌─────────────────────┐     │   │
│  │    │    32-bit 整數      │     │   │
│  │    │    運算單元         │     │   │
│  │    └─────────────────────┘     │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘

每 SM 的 CUDA Core 數量（依架構）：
- Ampere (A100): 64 FP32 + 64 INT32 = 128
- Hopper (H100): 128 FP32 + 128 INT32 = 256
```

### 2. Tensor Core（張量核心）

Tensor Core 是專門加速矩陣運算的單元，執行混合精度的矩陣乘加運算：

```
Tensor Core 運算：
D = A × B + C

其中：
A: M×K 矩陣（FP16/BF16/INT8/FP8）
B: K×N 矩陣（FP16/BF16/INT8/FP8）
C: M×N 矩陣（FP32）
D: M×N 矩陣（FP32）

每次運算：
- 從 A、B 讀取 M×K + K×N 個元素
- 從 C 讀取 M×N 個元素
- 計算 2×M×N×K 個 FLOPs
- 寫入 D: M×N 個元素
```

### Tensor Core 的演進

| 架構 | 支援精度 | 每 SM 數量 | 峰值效能（TFLOPS/SM） |
|------|----------|------------|----------------------|
| Volta | FP16 | 8 | ~125 |
| Turing | FP16, INT8 | 8 | ~150 |
| Ampere | FP16, BF16, TF32, INT8, FP8 | 4 | ~312 |
| Hopper | FP16, BF16, FP8, INT8, FP4 | 4 | ~500 |

### 3. Special Function Units（SFU）

SFU 處理超越函數與特殊運算：

```
SFU 支援的運算：
┌─────────────────────────────────────────┐
│  1. 三角函數                             │
│     sin(), cos(), tan()                  │
│                                          │
│  2. 反三角函數                           │
│     asin(), acos(), atan()               │
│                                          │
│  3. 指數與對數                           │
│     exp(), log(), exp2(), log2()         │
│                                          │
│  4. 倒數與平方根                         │
│     rcp(), rsqrt()                       │
│                                          │
│  5. 雙曲函數                             │
│     sinh(), cosh(), tanh()               │
└─────────────────────────────────────────┘

每 SM 的 SFU 數量：
- Ampere: 4 個 SFU
- Hopper: 4 個 SFU
```

### 4. Load/Store Units（LSU）

LSU 負責記憶體存取與資料搬運：

```
LSU 功能：
┌─────────────────────────────────────────┐
│  1. 記憶體地址計算                       │
│     - 基底 + 偏移                        │
│     - 向量化存取                         │
│                                          │
│  2. 記憶體連鎖（Coalescing）             │
│     - 合併相鄰存取                       │
│     - 最大化記憶體利用率                 │
│                                          │
│  3. 快取管理                             │
│     - L1 Cache 命中/失效                 │
│     - 預取控制                           │
│                                          │
│  4. 原子運算                             │
│     - atomicAdd(), atomicCAS()           │
│     - 用於歸約運算                       │
└─────────────────────────────────────────┘

每 SM 的 LSU 數量：
- Ampere: 32 個
- Hopper: 32 個
```

## 記憶體子系統

### Shared Memory（共享記憶體）

共享記憶體是可程式控制的 SRAM，用於執行緒間的資料共享：

```
Shared Memory 結構：
┌─────────────────────────────────────────┐
│         Shared Memory (48-228 KB)       │
│  ┌─────────────────────────────────┐   │
│  │     Bank 0     │     Bank 1    │   │
│  ├─────────────────┼───────────────┤   │
│  │     Bank 2     │     Bank 3    │   │
│  ├─────────────────┼───────────────┤   │
│  │     ...        │     ...       │   │
│  ├─────────────────┼───────────────┤   │
│  │     Bank 30    │     Bank 31   │   │
│  └─────────────────────────────────┘   │
│                                          │
│  Bank 數量：32 個                        │
│  Bank 寬度：4 bytes (32-bit)            │
│  存取延遲：~20-30 個時脈週期            │
│  頻寬：~32 bytes/cycle（per bank）      │
└─────────────────────────────────────────┘
```

### Bank Conflict

當多個執行緒同時存取同一 Bank 的不同位址時，會產生 Bank Conflict：

```
Bank Conflict 情境：
┌─────────────────────────────────────────┐
│  Bank 0  Bank 1  Bank 2  Bank 3         │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐      │
│  │ T0  │ │ T1  │ │ T2  │ │ T3  │      │
│  └─────┘ └─────┘ └─────┘ └─────┘      │
│                                          │
│  無衝突：T0→Bank0, T1→Bank1, T2→Bank2  │
│  2-way 衝突：T0→Bank0, T1→Bank0         │
│  4-way 衝突：T0,T1,T2,T3→Bank0          │
└─────────────────────────────────────────┘

效能影響：
- 無衝突：1 cycle 完成
- N-way 衝突：N cycles 完成
```

### L1 Cache

L1 Cache 是硬體管理的快取記憶體：

```
L1 Cache 配置：
┌─────────────────────────────────────────┐
│              L1 Cache                   │
│  ┌─────────────────────────────────┐   │
│  │     資料快取（D-Cache）          │   │
│  │     用於全域記憶體快取           │   │
│  └─────────────────────────────────┘   │
│  ┌─────────────────────────────────┐   │
│  │     純量快取（Scalar Cache）     │   │
│  │     用於常數與控制資料           │   │
│  └─────────────────────────────────┘   │
│                                          │
│  管線策略：L1 與 Shared Memory 共用 SRAM │
│  配置比例：可調整（如 192KB L1 + 32KB SM）│
└─────────────────────────────────────────┘
```

### 暫存器檔（Register File）

暫存器是最快的記憶體，每個執行緒可使用多個暫存器：

```
暫存器規格：
┌─────────────────────────────────────────┐
│              暫存器檔                    │
│                                          │
│  每 SM 總量：65,536 × 32-bit = 256 KB   │
│  每執行緒配額：最多 255 個暫存器         │
│  存取延遲：1 個時脈週期                 │
│  頻寬：極高（每個時脈可讀寫多次）       │
│                                          │
│  佔用率計算：                            │
│  執行緒數 = 65536 / 每執行緒暫存器數    │
│                                          │
│  範例：                                  │
│  - 使用 32 個暫存器/執行緒              │
│  - 最多 2048 個執行緒/SM               │
│  - 以 Warp 計算：64 warps              │
└─────────────────────────────────────────┘
```

## SM 的運作模式

### Warp 調度

SM 使用多個 Warp 調度器來隱藏延遲：

```
Warp 調度機制：
┌─────────────────────────────────────────┐
│              Warp Scheduler              │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐  │
│  │Scheduler│ │Scheduler│ │Scheduler│  │
│  │   #0    │ │   #1    │ │   #2    │  │
│  └────┬────┘ └────┬────┘ └────┬────┘  │
│       │           │           │         │
│       ↓           ↓           ↓         │
│  ┌─────────────────────────────────┐   │
│  │      Warp Pool（所有就緒 Warp）  │   │
│  └─────────────────────────────────┘   │
│                                          │
│  每時脈週期：                            │
│  - 每個 Scheduler 從 Pool 選擇一個 Warp │
│  - 該 Warp 發射一條指令                 │
│  - 若 Warp 被阻塞（如記憶體等待）       │
│    則選擇其他就緒 Warp                   │
└─────────────────────────────────────────┘
```

### 佔用率（Occupancy）

佔用率是實際使用執行緒數與最大可用執行緒數的比率：

```
佔用率 = (活躍 Warp 數 / 最大 Warp 數) × 100%

影響因素：
1. 暫存器使用量
2. 共享記憶體使用量
3. 同步指令數

範例（H100 SM）：
- 最大 Warp 數：48 warps（1536 threads）
- 若每個執行緒使用 32 個暫存器：
  - 使用暫存器：1536 × 32 = 49152
  - 佔用率：100%
- 若每個執行緒使用 64 個暫存器：
  - 最多可執行：65536 / 64 = 1024 threads = 32 warps
  - 佔用率：32/48 = 67%
```

## 本章小結

- SM 是 GPU 的核心運算單位，包含多種功能單元
- CUDA Core 基本浮點運算，Tensor Core 專門加速矩陣運算
- SFU 處理超越函數，LSU 負責記憶體存取
- 記憶體子系統包含共享記憶體、L1 Cache、暫存器
- Warp 調度與佔用率是影響效能的關鍵因素
