# 10.3 算子自動排程（Auto-Tuning）與記憶體配置優化

## 為什麼需要自動排程

### 手動排程的困境

```
手動排程問題：
┌─────────────────────────────────────────────────┐
│  排程需要大量專業知識：                          │
│  - 了解硬體架構                              │
│  - 知道記憶體層級與頻寬                      │
│  - 平衡多種權衡參數                        │
│                                                  │
│  排程參數非常多：                                │
│  ┌──────────────────────────────────────────┐   │
│  │  1. 分塊大小（Tiling）                  │   │
│  │  2. 迴圈順序                          │   │
│  │  3. 向量化寬度                        │   │
│  │  4. 平行化方式                        │   │
│  │  5. 快取/共享記憶體策略              │   │
│  │  6. 融合策略                              │   │
│  │  7. 展開因子                          │   │
│  │  8. 資料佈局                            │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  硬體差異大：                                    │
│  - 不同 GPU 的最佳參數不同                  │
│  - 需要針對每種硬體調整                    │
│                                                  │
│  結論：需要自動化                          │
└─────────────────────────────────────────────────┘
```

## 排程空間（Schedule Space）

### 什麼是排程空間

```
排程空間定義：
┌─────────────────────────────────────────────────┐
│  排程 = 一組將抽象計算                         │
│          變換為硬體可執行代碼的決策              │
│                                                  │
│  所有可能的排程構成「排程空間」                 │
│                                                  │
│  範例（矩陣乘法排程空間）：                      │
│  - 分塊大小：{16, 32, 64, 128}                │
│  - 迴圈順序：{i-j-k, i-k-j, j-i-k, ...}        │
│  - 向量化：{on, off}                          │
│  - 展開：{1, 2, 4}                            │
│  - 平行：{thread, block, warp}               │
│                                                  │
│  組合數：可能數以百萬計                      │
│  → 需要自動搜尋最佳排程                    │
└─────────────────────────────────────────────────┘
```

### 排程變換

```
常用排程變換：
┌─────────────────────────────────────────────────┐
│  1. Split（分割）                              │
│     將迴圈變數分為內外兩層                   │
│  for (i = 0; i < N; i++)   →   for (io...)     │
│                                 for (ii...)    │
│                                                  │
│  2. Reorder（重排）                            │
│     交換迴圈順序                              │
│  for i for j   →   for j for i                │
│                                                  │
│  3. Vectorize（向量化）                       │
│  儲存到向量暫存器                         │
│                                                  │
│  4. Parallelize（平行化）                     │
│  分配給多個執行緒/核心                    │
│                                                  │
│  5. Fuse（融合）                               │
│  合併多個迴圈                              │
│                                                  │
│  6. Cache Read/Write                          │
│  將資料緩存到共享記憶體                   │
└─────────────────────────────────────────────────┘
```

## Auto-Tuning 方法

### 搜尋方法

```
Auto-Tuning 搜尋策略：
┌─────────────────────────────────────────────────┐
│  1. 隨機搜尋（Random Search）                   │
│     - 隨機採樣排程空間                          │
│     - 簡單但效率低                              │
│                                                  │
│  2. 遺傳演算法（Genetic Algorithm）             │
│     - 演化式搜尋                              │
│     - 適合大空間                          │
│                                                  │
│  3. 貝式優化（Bayesian Optimization）          │
│     - 建立代理模型                        │
│     - 高效利用樣本                          │
│                                                  │
│  4. 強化學習（Reinforcement Learning）          │
│     - 學習排程策略                          │
│     - 可遷移至新任務                    │
│                                                  │
│  5. 啟發式搜尋（Heuristic）                  │
│     - 利用領域知識                          │
│     - 如先從粗粒度搜尋                    │
└─────────────────────────────────────────────────┘
```

### Ansor / AutoTVM

```
TVM 的 Auto-Tuning：
┌─────────────────────────────────────────────────┐
│  AutoTVM：                                       │
│  - 基於模板的調校（Template-Based）         │
│  - 預定義排程模板                          │
│  - 搜尋模板參數                            │
│                                                  │
│  Ansor：                                         │
│  - 進階排程搜尋                          │
│  - 自動生成排程（不需模板）            │
│  - 結合程式生成 + 搜尋                  │
│                                                  │
│  流程：                                          │
│  ┌──────────────────────────────────────────┐   │
│  │  1. 生成候選排程（含變換）              │   │
│  │  2. 執行並測量效能                      │   │
│  │  3. 更新模型（學習）                  │   │
│  │  4. 迭代搜尋最佳排程                  │   │
│  └──────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

### 搜尋流程

```
Auto-Tuning 完整流程：
┌─────────────────────────────────────────────────┐
│  語法：                                          │
│  ┌──────────────────────────────────────────┐   │
│  │  輸入：算子 + 目標硬體                   │   │
│  │                ↓                         │   │
│  │  1. 生成搜尋空間                        │   │
│  │     - 定義排程變換                    │   │
│  │     - 建立候選排程                    │   │
│  │                ↓                         │   │
│  │  2. 樣本評估                          │   │
│  │     - 對候選排程編譯、執行測量        │   │
│  │     - 記錄效能                          │   │
│  │                ↓                         │   │
│  │  3. 學習/選擇                        │   │
│  │     - 用結果更新模型                  │   │
│  │     - 選下一輪要測的排程              │   │
│  │                ↓                         │   │
│  │  4. 收斂 / 輸出                      │   │
│  │     - 找到最佳排程                    │   │
│  │     - 生成最終代碼                    │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  關鍵挑戰：                                      │
│  - 測量時間長                              │
│  - 需要平衡探索與利用                    │
└─────────────────────────────────────────────────┘
```

## 記憶體配置優化

### 記憶體規劃

```
記憶體配置問題：
┌─────────────────────────────────────────────────┐
│  深度學習記憶體需求：                            │
│  1. 模型權重（Weights）                        │
│  2. 中間激活（Activations）                   │
│  3. 梯度（Gradients，訓練）                 │
│  4. 優化器狀態                                │
│  5. 工作緩衝區                                │
│                                                  │
│  目標：                                          │
│  - 最小化總記憶體使用                      │
│  - 最大化記憶體吞吐                      │
│  - 確保資料可用於運算                    │
└─────────────────────────────────────────────────┘
```

### 記憶體優化技術

```
記憶體優化技術：
┌─────────────────────────────────────────────────┐
│  1. 記憶體重複使用（Memory Reuse）               │
│     - 不同階段的張量可重用同一空間            │
│     - 分析生命週期（Liveness Analysis）      │
│                                                  │
│  2. 深度分析（Liveness）                      │
│     ┌────────────────────────────────────┐    │
│     │  張量              生命週期         │    │
│     │  A                 1-3             │    │
│     │  B                 2-4             │    │
│     │  C                 5-7             │    │
│     │  → A 與 C 可重用同一空間           │    │
│     └────────────────────────────────────┘    │
│                                                  │
│  3. 就地（In-Place）運算                    │
│     - 覆蓋輸入，不需額外空間                │
│                                                  │
│  4. 記憶體池化（Memory Pooling）              │
│     - 統一分配管理                        │
│     - 減少碎片                          │
│                                                  │
│  5. 梯度記憶體節省（Gradient Checkpointing）    │
│     - 捨棄中間激活，反向時重算            │
└─────────────────────────────────────────────────┘
```

### 記憶體規劃演算法

```
記憶體分配流程：
┌─────────────────────────────────────────────────┐
│  1. 收集所有張量與生命週期                      │
│                                                  │
│  2. 構建衝突圖（Conflict Graph）：               │
│     ┌─────┐      ┌─────┐                       │
│     │  A  │─────│  B  │  ← 同時間存在衝突      │
│     └─────┘      └─────┘                       │
│       │               │                        │
│       └─────┌─────┐───┘                        │
│              │  C  │  ← 與 A/B 不同時          │
│              └─────┘                           │
│                                                  │
│  3. 著色（Coloring）：                          │
│     - 衝突的張量用不同顏色（空間）           │
│     - 不衝突的張量可共享                      │
│                                                  │
│  4. 分配實際記憶體位址                      │
│                                                  │
│  目標：最小化著色數（記憶體大小）         │
└─────────────────────────────────────────────────┘
```

## 排程與記憶體協同

### 整合最佳化

```
記憶體與排程協同：
┌─────────────────────────────────────────────────┐
│  排程決定資料在何處、如何使用：                  │
│                                                  │
│  ┌──────────────────────────────────────────┐   │
│  │  排程決策             記憶體影響         │   │
│  ├──────────────────────────────────────────┤   │
│  │  分塊大小           快取命中率          │   │
│  │  迴圈順序           資料重用            │   │
│  │  向量化             存取寬度            │   │
│  │  融合               中間資料量          │   │
│  │  平行               負載平衡            │   │
│  └──────────────────────────────────────────┘   │
│                                                  │
│  協同策略：                                      │
│  - 排程與記憶體配置同步搜尋                  │
│  - 考慮記憶體頻寬限制                        │
│  - 先粗排程再細步記憶體配置                │
└─────────────────────────────────────────────────┘
```

## 效能建模

### 預測效能

```
效能預估模型：
┌─────────────────────────────────────────────────┐
│  1. 分析模型（Analytical）                      │
│     - 基於硬體參數（頻寬、延遲）             │
│     - 快速但粗糙                              │
│                                                  │
│  2. 模擬模型（Simulation）                      │
│     - 模擬硬體行為                          │
│     - 準確但較慢                            │
│                                                  │
│  3. 機器學習模型                                │
│     - 用過去測量數據訓練                    │
│     - 結合速度與準確度                    │
│                                                  │
│  用途：                                          │
│  - 過濾差的排程（不需實際執行）            │
│  - 引導搜尋方向                          │
└─────────────────────────────────────────────────┘
```

## 本章小結

- 手動排程困難，因硬體與參數複雜
- 排程空間包含分塊、迴圈、向量化等決策
- Auto-Tuning 透過搜尋（隨機、遺傳、貝式、RL）找最佳排程
- TVM 的 AutoTVM/Ansor 是代表性工具
- 記憶體配置透過生命週期分析與著色最小化
- 排程與記憶體需協同最佳化
- 效能建模加速搜尋過程
