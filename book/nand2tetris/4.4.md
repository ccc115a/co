# 4.4 寫入你的第一個 Hack 組合語言程式

前三節分別建立了理論（ISA）、規格（A/C-指令編碼）與硬體介面（記憶體映射 I/O），現在是成果驗收的時刻：把原本只存在紙上的指令集，真正寫成一支能動的 Hack 組合語言程式，並在 CPU 模擬器中看到它執行。本節從最基本的語法開始，依序練習「數值相加、記憶體存取、迴圈、條件判斷」四大基本功，最後組合成兩支完整的範例程式（累加與乘法），教你如何在模擬器上載入、逐步執行與觀察暫存器變化。

## 組合語言語法速覽

Hack 組合語言（`.asm`）的語法非常輕量，幾乎沒有多餘的規則：

```text
// 這是一行註解：以 // 開頭，延伸至行末
/* 也可以使用區塊註解（組譯器會忽略） */

（標籤）      (LOOP)          —— 括號內是標籤宣告，本身不佔執行
（A-指令）    @16384           —— 把數字/符號載入 A
（C-指令）    D=M              —— 計算、儲存、跳躍
（C-指令）    M=D+1;JGT        —— dest=comp;jump 三段式
```

語法規則總表：

| 規則 | 說明 | 範例 |
|---|---|---|
| 註解 | `//` 之後到行末全部忽略 | `@1 // 取得 1` |
| 白空格 | 空白、Tab、空行皆可忽略 | 每行前後可自由縮排 |
| 大小寫 | **區分大小寫**，符號需一致 | `LOOP` 與 `loop` 是不同符號 |
| 一行一式 | 每行一條指令、一個標籤或一個「@值」 | 不可一行塞兩條 |
| 指令元素 | `@xxx` 或 `dest=comp;jump`，`dest=` 與 `;jump` 皆可略 | `D=M`、`0;JMP` |
| 標籤格式 | `(名稱)`，可作為跳躍目標，出現在 `@名稱` | `(LOOP) … @LOOP` |

**符號系統**：`@` 後面可以接數字，也可以接「符號」。符號有三種來源，組譯器會自動辨識與解析：

1. **預先定義符號**：R0～R15（＝0～15）、SCREEN（＝16384）、KBD（＝24576）、SP/LCL/ARG/THIS/THAT（＝0～4）。
2. **標籤**：程式裡用 `(名稱)` 宣告的位置，`@名稱` 代表該指令在 ROM 中的位址。
3. **變數**：第一次在 `@` 出現、又不是上述兩類的符號，會被配置到記憶體 16 起的位址。

把高階語言想成「抽象概念」，組合語言就是「指令與位址的流水帳」——玩法很瑣碎，但每一步都透明可見。

## 第一個練習：設定位址、搬移資料

在動手寫大程式前，先釐清三種最基礎的資料搬移，因為它們是後面所有程式的原子操作。我們以「把 RAM 位址 10 設為 10」與「D=A」系列操作為例：

```asm
// 最小練習：設定位址與拷貝
@10          // A = 10（把位址 10 餵給 A）
D=A          // D = 10（把 A 當作資料，拷貝進 D）

@10          // A = 10（再指定一次位址）
M=D          // RAM[10] = D = 10（寫入記憶體）

@10          // A = 10
A=M          // A = RAM[10] = 10（讀記憶體，把內容放進 A）
D=A          // D = 10
```

這六行雖然做著最無聊的事，卻涵蓋了 Hack 的全部「資料位置」語法。我們用一張表總結「誰會被讀、誰會被寫」：

| 指令 | 讀 | 寫 | 效果 |
|---|---|---|---|
| `@10` | — | A | 把立即值 10 送進 A |
| `D=A` | A | D | D = 位址本身（把位址當資料） |
| `M=D` | D | RAM[A] | 先定址再寫入 |
| `A=M` | RAM[A] | A | 先定址再讀出，結果放回 A（指標解參考） |
| `D=M` | RAM[A] | D | D = 記憶體內容 |

記住這個口訣：**`D=A` 是把「位址」當資料，`D=M` 是把「內容」當資料**。兩者一字之差，代表完全不同的兩件事。

## 範例一：把幾個數相加

最簡單的「有意義」程式：計算兩個常數的和，存入記憶體：

```asm
// AddConst.asm：把 7 與 9 相加，結果存到 RAM[8]
@7
D=A          // D = 7
@9
D=D+A        // D = 7 + 9 = 16
@8
M=D          // RAM[8] = 16

(END)
@END
0;JMP        // 註：程式停在這裡（無窮迴圈），不再執行其他記憶體內容
```

觀察要點：

* `D=A` → `D=D+A` 是「載入常數後累加」的標準旋律，靠 D 暫存器充當累加器。
* 最後的 `(END) / @END / 0;JMP` 是 Hack 的「程式結束」慣例——因為 CPU 用完 RAM 會一路抓後面的記憶體當指令執行，必須用「跳到自己的無窮迴圈」停下來。往後每個程式結束前都會放這個尾巴。

## 範例二：記憶體對記憶體的加總

常數相加不過癮，來真的：把「RAM[0] 的內容」與「RAM[1] 的內容」相加，存到 RAM[2]：

```asm
// AddMem.asm：RAM[2] = RAM[0] + RAM[1]
@R0
D=M          // D = RAM[0]（讀一號記憶體）
@R1
D=D+M        // D = RAM[0] + RAM[1]（邊讀二號記憶體邊加）
@R2
M=D          // RAM[2] = 總和

(END)
@END
0;JMP
```

這支程式（即 4.2 節手工組譯的 Add2.asm）示範了記憶體存取的完整來回：**「先 `@位址`，再用 `D=M` 讀、用 `M=D` 寫」**。你在模擬器上可以把 RAM[0]=5、RAM[1]=12，執行結束後觀察 RAM[2]=17。

## 範例三：迴圈與計數（累加 1 到 100）

迴圈是三元素中「跳躍」的實戰演練。計算 1+2+…+100，並把結果放進 RAM[0]：

```asm
// Sum1to100.asm：計算 1+2+...+100，結果存 RAM[0]
@100
D=A
@n
M=D          // n = 100（計數器）
@sum
M=0          // sum = 0（累加器）

(LOOP)
@n
D=M
@STOP
D;JEQ        // 若 n == 0，結束迴圈
@sum
M=D+M        // sum = sum + n（M=D+M：讀 M、邊讀邊加、寫回）
@n
M=M-1        // n = n - 1
@LOOP
0;JMP        // 跳回 LOOP 開頭，繼續判斷

(STOP)
@sum
D=M          // D = sum
@R0
M=D          // RAM[0] = sum

(END)
@END
0;JMP
```

拆解這個程式的控制流：

```text
           ┌───────────┐
           ▼           │
      (LOOP)───讀 n─────► n==0？──是──►(STOP)
           │
           否│
           ▼
      sum += n；n--
           │
           └───────────┘  （無條件跳回 LOOP）
```

技術重點：

1. **計數模式**：先判斷（`D=M` 讀計數器）再操作（`M=D+M`、`M=M-1`），這是「while 迴圈」的機械翻譯。
2. **forward 跳躍**：`@STOP` 出現在 `(STOP)` 標籤宣告之前的行——組譯器會用兩階段掃描解決這種「往後跳」，你寫程式時不必管行號。
3. **變數符號**：`n` 與 `sum` 會由組譯器自動配置到記憶體位址 16 與 17。

## 範例四：條件判斷（取最大值）

條件判斷是「跳躍」的另一面：依結果做不同路線。取 `RAM[0]`、`RAM[1]` 的較大者放到 `RAM[2]`：

```asm
// Max.asm：RAM[2] = max(RAM[0], RAM[1])
@R0
D=M          // D = RAM[0]
@R1
D=D-M        // D = RAM[0] - RAM[1]
@OUT_FIRST
D;JGT        // 若結果 > 0，代表 RAM[0] 較大，跳去輸出 RAM[0]
@R1
D=M          // 否則 RAM[1] 較大，D = RAM[1]
@STORE
0;JMP        // 跳過另一分支
(OUT_FIRST)
@R0
D=M          // D = RAM[0]
(STORE)
@R2
M=D          // RAM[2] = 較大者

(END)
@END
0;JMP
```

判斷的祕訣在於「**相減看正負」**：因為 ALU 的跳躍條件只認「結果是負/零/正」，所以拿 `RAM[0]-RAM[1]` 的正負來決定誰大誰小。對應到流程：

```text
   D = RAM[0] - RAM[1]
        │
  D>0？─是─► 輸出 RAM[0]
        │
        否
        ▼
   輸出 RAM[1]
```

這就是所有 `if-else` 在 Hack 層的共同基因：**先設法把「條件」變成「某個運算結果的正負零」，再用條件跳躍分岔**。

## 範例五：完整註解的乘法程式（三寶大合體）

最後一個範例同時使用「記憶體存取、迴圈、條件判斷」，是 4.4 節的總驗收：

```asm
// Mult.asm：計算 RAM[2] = RAM[0] × RAM[1]
//
// 策略：把乘法化為反覆加法。
//   RAM[0] 當「次數」，RAM[1] 當「被重複加的數」。
//   R3 是計數器副本，避免破壞 RAM[0] 的值。
// 陣營檢驗：RAM[0]=3、RAM[1]=4 → RAM[2]=12。

// ---- 初始化 ----
@R0
D=M
@END
D;JEQ        // 若 RAM[0]==0，積為 0，直接結束
@R0
D=M
@R3
M=D          // R3 = RAM[0]（計數器複本）

@R2
M=0          // RAM[2] = 0（累積器歸零）

// ---- 迴圈：把 RAM[1] 重複加 RAM[0] 次 ----
(LOOP)
@R2
D=M          // D = 目前的積
@R1
D=D+M        // D += RAM[1]
@R2
M=D          // RAM[2] = 更新後的積
@R3
M=M-1        // 計數器減一
@R3
D=M
@LOOP
D;JGT        // 計數器仍 > 0 → 繼續累加

(END)
@END
0;JMP        // 程式結束
```

試著自己追蹤一遍：RAM[2] 從 0 開始，每一圈加一次 RAM[1]，共加 RAM[0] 圈，最後恰為積。這支程式的另一個刻意設計是 **指標/計數器分離**（R3 保存副本），讓你體會「避免破壞來源資料」的程式設計紀律。

## 如何在 CPU 模擬器中執行

Nand2Tetris 工具組提供 **CPU Emulator（CPU 模擬器）**，直接載入 `.asm` 檔（它會自動幫你組譯）或事先組譯好的 `.hack` 檔。完整流程：

1. **開啟模擬器**：在軟體工具目錄中執行 `CPUEmulator.sh`（macOS/Linux）或 `CPUEmulator.bat`（Windows）。
2. **載入程式**：從功能表選 **File → Load Program**，選擇 `.asm`（或 `.hack`）。載入後程式的二進位內容會被放進 **ROM** 區塊，從位址 0 開始。
3. **設定初始資料**：在 **RAM** 面板中直接點擊格子，輸入初值（例如把 `RAM[0]=3`、`RAM[1]=4`）。
4. **重置與執行**：
   * 按 **Reset**（把 PC 歸零）。
   * 按一次 **Single Step** 即執行一條指令，便於逐步教學。
   * 按 **Run (No Animation)** 一口氣跑到底（記得結束尾巴要寫 `0;JMP` 無窮迴圈，以免程式暴走）。
5. **觀察結果**：看 **A/D 暫存器**、**PC** 與 **RAM** 的變化。螢幕與鍵盤程式（4.3 節的 Fill）則看模擬器裡的 **Screen / Keyboard** 視窗，在螢幕上按下滑鼠即可「發送按鍵訊號」。
6. **除錯技巧**：
   * 每執行一條指令就檢查一次 D/A 與 PC，用肉眼追蹤「兩步舞」是否正確。
   * 確認 `@` 後面的位址值與你想指的記憶體一致（`@R0`＝0、`@SCREEN`＝16384）。
   * 迴圈卡死？檢查 `0;JMP` 是否真的把 PC 導到正確標籤。

如果不先用模擬器，也可以照第六章的流程，用 **Assembler** 工具把 `.asm` 組譯成 `.hack`，再交給硬體模擬器（第五章的 Computer 晶片）執行——路線殊途同歸，目的都是驗證這四節建立的心智模型與真實電路一致。

## 設計思路與實作步驟

從零到一支可執行的 Hack 程式，按這份 SOP 走最不容易出錯：

1. **先用中文/虛擬碼寫出演算法**，確定輸入、輸出與變數（例如「要把 1..100 加總，結果放 RAM[0]」）。
2. **分配記憶體**：決定哪些位址放資料（R0～R15 或 16 起的變數），哪些做成計數器、累加器、指標。
3. **規劃控制流**：畫出流程圖，標出迴圈頂點（LOOP）與結束點（STOP/END），決定每一條跳躍的條件（正/零/負）。
4. **逐行翻譯**：依照「`@位址` → `D=M`（讀）」與「`@位址` → `M=D`（寫）」的口訣，把每一步改成 Hack 指令。
5. **補上註解**：每一行都寫明「現在在幹嘛」，對齊 4.2 節的編碼表逐行檢查。
6. **載入 CPU 模擬器驗證**：設好測試輸入、逐步執行、比對 RAM 結果；有錯就回到第 3 步修正控制流或第 4 步的位址。

「設計思路」層面還有兩條心法要記住：**先想清楚資料住哪裡，再想指令怎麼走**（組合語言是資料導向的思考）；以及**條件只認負零正**，任何 if 都要先化成一次減法或比較運算。

## 本章小結

- **語法**：註解用 `//`、白空格忽視、符號區分大小寫；指令只有 `@xxx` 或 `dest=comp;jump` 兩種形式，`dest=` 與 `;jump` 可省略，程式結束用 `0;JMP` 無窮迴圈。
- **資料搬移三寶**：`D=A`（位址當資料）、`D=M`（內容讀進 D）、`M=D`（存回記憶體），皆以「先 `@位址` 定址」為前提。
- **基本程式四大件**：常數相加（`D=A`→`D=D+A`）、記憶體加總（`D=M`→`D=D+M`→`M=D`）、迴圈（計數器 `M=M-1`＋條件跳躍）、條件判斷（相減看正負＋`D;JGT` 分岔）。
- **兩支完整範例**：累加 1~100（while 型迴圈）與乘法（化乘為加的累進迴圈），涵蓋了本節全部語法元件。
- **執行流程**：在 CPU Emulator 載入 `.asm` → 設定 RAM 初值 → Reset → Run；用 Single Step 逐步檢查 A/D/PC/RAM 即可完成除錯。
- **認知收穫**：你已經能獨立閱讀與撰寫 Hack 組合語言——下一章，我們將把這些指令真正「接通電」，組裝出能執行它們的 CPU 與完整電腦。

至此第四節結束，整個第四章（ISA、A/C-指令編碼、記憶體映射 I/O、第一個程式）也告一個段落。接下來第五章，我們要把這 16 位元的指令集化為真實電路，迎接「手寫電腦」計畫的第一座里程碑：一台可以執行我們親手寫的組合語言的完整計算機。
