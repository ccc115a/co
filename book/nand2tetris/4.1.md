# 4.1 硬體與軟體的交界：指令集架構（ISA）

在前面三章中，我們分別打造了布林運算的基石（邏輯閘）、算術的核心（ALU）以及儲存狀態的單元（暫存器與記憶體）。然而，無論這些電路多麼精巧，它們都還只是一堆「會算數的矽片」——真正讓一台電腦成為「可程式化機器」的關鍵，是**指令集架構（Instruction Set Architecture, ISA）**。 ISA 是硬體與軟體之間的一紙合約：它定義了 CPU 究竟「聽得懂」哪些指令、每個指令如何被編碼成 0 與 1、以及執行指令時要用到哪些暫存器與記憶體。本章要從巨觀的計算機原理出發，認識機器語言的三個核心元素，並建立起「運算、資料位置、跳躍」這三根支柱，為下一節詳細介紹 Hack 機器語言規格打下基礎。

## 什麼是指令集架構（ISA）

電腦的 CPU 無法直接懂得「`sum += i;`」這種高階語言的語法。它唯一能執行的，是本機的**機器指令（machine instruction）**——一串定義好的 0/1 位元。一個指令集架構，就是用來描述「CPU 能夠辨識與執行哪些指令」的完整規格，通常包含三大部分：

| 組成 | 說明 |
|---|---|
| **指令格式** | 每條指令長幾個位元？欄位如何劃分？例如「前 4 個位元是操作碼」。 |
| **定址模式** | 資料從哪裡來、結果送到哪裡去？例如立即值、暫存器、記憶體位址。 |
| **行為語意** | 每個指令在硬體上做什麼事？例如「把 A 與 D 相加並存回 D」。 |

我們常說「機器語言」或「組合語言」，其實都是 ISA 的不同面貌：

* **機器語言**：完整的 0/1 位元編碼，CPU 直接執行。
* **組合語言**：機器語言的助記式（mnemonic）寫法，用 `D=M+A`、`0;JMP` 這樣可讀的文字代替原始的位元串。
* **組譯器（Assembler）**：把組合語言一行行翻譯成機器碼的程式。

同一個 ISA 可以存在不同的助記元寫法（x86 有 AT&T 與 Intel 兩種語法便是著名例子），但它們背後的位元編碼是同一個。在 Nand2Tetris 中，我們將設計一個非常精簡、可以完全自己動手實作出來的 16 位元 ISA：**Hack 機器語言**。設計 Hack 的最大好處是——它的完整規格只有兩頁，而且我們親手電路（第五章的 CPU）真的能執行它。

## 從高階語言到機器語言：抽象的階梯

讓我們先感受一下同一段演算法在不同抽象層的樣貌。假設我們想知道「把變數 `a` 加 1 之後存入變數 `b`」，在每個層次大致長這樣：

```c
// 高階語言（C 語言風格）
b = a + 1;
```

```asm
// 組合語言（Hack）
@a        // 把 a 的位址送進 A 暫存器
D=M       // D = RAM[a]
@b        // 把 b 的位址送進 A 暫存器
M=D+1     // RAM[b] = D + 1
```

```text
// 機器語言（對應到上述 4 條指令的二進位編碼）
0000000000000000
1111110000010000
0000000000000001
1110111111010001
```

從上到下，每一層都是上一層的「機械化」。高階語言的人力成本最低、離硬體最遠；組合語言與機器語言離硬體最近、但每一行都瑣碎。撰寫編譯器（本書第二部的目標）的任務，就是把高層的表達翻譯成底層的位元。理解了 ISA，你就同時掌握了軟體的最底層與硬體的最頂層——這就是本章標題「硬體與軟體的交界」的真正含義。

## 機器語言的三個核心元素

翻遍所有電腦的機器語言，無論是學生實作的 Hack、Arduino 的 AVR、手機的 ARM 或是伺服器的 x86，核心概念都繞不開三件事：**運算（Operation）、資料位置（Operand Location）、跳躍（Jump）**。我們依序說明。

### 第一個元素：運算（Operation）

運算描述「這一條指令要對資料做什麼」。常見的運算包括：

| 類別 | 例子 |
|---|---|
| 算術運算 | 加法、減法、遞增、遞減 |
| 邏輯運算 | 位元 AND、OR、NOT |
| 資料搬移 | 把暫存器或記憶體的內容搬到目標 |
| 流程控制 | 條件跳躍或無條件跳躍 |

在 Hack 中，一切運算都由 **ALU** 完成，因此「運算」欄位幾乎直接對應我們在第二章打造的 ALU 控制訊號。算術與邏輯運算其實是同一回事：`D+A`、`D&A`、`!D` 通通是 ALU 能算的函數。

### 第二個元素：資料位置（Operand Location）

光有運算還不夠——我們必須指出「從哪裡取得運算元」以及「結果寫到哪裡」，這就是資料位置。程式語言的變數存取概念在機器層次被拆解成三種來源：

1. **立即值（immediate）**：常數直接寫在指令裡，例如「把 5 放進暫存器」。
2. **暫存器（register）**：CPU 內部的極高速儲存單元，例如「把 A 暫存器的值拿來用」。
3. **記憶體（memory）**：透過位址存取的較慢儲存空間，例如「把 RAM[100] 的值讀入」。

Hack 把這三種來源融合得十分優雅：`@值` 指令（A-指令）負責把立即值送進 A 暫存器；之後的 C-指令只要提到 `A`，就用暫存器內容；只要提到 `M`，就自動以 `A` 作為記憶體位址去存取 RAM。如此一來「資料位置」的語法只有 A、D、M 三個代號，簡單卻威力十足。

### 第三個元素：跳躍（Jump / Flow Control）

程式若只能一行接一行往下跑，將無法表達「迴圈」與「if-else」，也就無法寫出任何有意義的程式。跳躍指令改變程式計數器（PC）的值，讓 CPU 下一個循環去執行別的位置。跳躍分為兩類：

* **無條件跳躍**：不管條件如何都跳，例如「跳到 LOOP 標籤」。
* **條件跳躍**：根據上一次運算結果的性質決定跳不跳，例如「若結果大於 0 就跳」。

每條 C-指令的 ALU 都會算出一個 16 位元的結果；Hack 的硬體會順便告訴我們這個結果是**負、零、還是正**，條件跳躍正是檢查這三個狀態。跳躍目標一律存在 A 暫存器中（下一節會詳細說明）。用流程圖思考的話，三種元素各負責一件事：

```text
運算    ：做什麼（compute）
資料位置：從哪拿、放去哪（dest / source）
跳躍    ：接下來去哪裡（jump）
```

一個 ISA 只要具備了這三個元素，理論上就能寫出任意的可計算程式——這正是圖靈完備性的實務意義。

## 儲存程式計算機：Von Neumann 架構

1945 年，馮紐曼（John von Neumann）提出了影響至今的「儲存程式計算機」概念。核心思想只有一句話：**程式與資料存在同一個記憶體裡，指令依序被取出與執行**。這聽起來理所當然，但在當時並非如此——早期的計算機是把程式「接線」在電路板上，想改程式就得改硬體。

Von Neumann 架構由幾個關鍵元件組成：

```text
        ┌────────────────────────────────────┐
        │                                     │
        ▼                                     │
  ┌──────────┐   位址/資料匯流排   ┌────────────┐
  │   CPU    │◄──────────────────►│   記憶體    │
  │  ┌─────┐ │    （同時存放      └────────────┘
  │  │ ALU │ │     程式與資料）          ▲
  │  ├─────┤ │                           │
  │  │PC /  │ │        ┌──────────┐       │ I/O 映射
  │  │暫存器│ │        │ 輸入/輸出 │◄──────┘
  │  └─────┘ │        └──────────┘
  └──────────┘
```

1. **CPU**：負責解碼與執行指令，內部有 ALU、暫存器群與程式計數器 PC。
2. **記憶體**：同時存放「程式本身」與「程式要處理的資料」。
3. **I/O**：與外界溝通（螢幕、鍵盤）。
4. **匯流排**：串起上述元件的位址與資料傳輸線路。

在 Nand2Tetris 中，Hack 電腦正是這樣一台標準的 Von Neumann 機器：程式被載入 ROM（唯讀記憶體，專門放程式），資料放在 RAM，兩者對 CPU 而言都是「記憶體」。第五章我們組裝這種架構時，會看到 PC 決定下一條要抓去執行的指令位址，形成一次次的「抓取—解碼—執行」循環：

```text
INFINITE LOOP {
  instruction = ROM[PC]
  PC = PC + 1                      // 先指向下一條指令
  decode(instruction)              // 解讀操作碼與欄位
  execute(instruction)             // 運算、搬移、視條件更新 PC
  // 若是跳躍指令，PC 可能在 execute 中被覆寫
}
```

這個循環是第四節「是否停止執行」以及後續「作業系統」所有章節的共同節奏：程式只是記憶體中的位元串，CPU 只是依照 PC 一路讀讀做做。

## 資料暫存器與記憶體的位址

在 Hack 中，記憶體的一格是一個 16 位元字組（word），我們習慣用「RAM[i] = 第 i 個字組」。位址本身是 15 位元的非負整數，因此最多能定址 32768 個字組（0 到 32767，即 32K）。這意味著一切「說出位址」的場合，我們都只能表達 0～32767 的數字。

暫存器與記憶體的最大差異在於**速度與數量**：暫存器在 CPU 內部，數量極少但極快；記憶體在外圍，數量多（32K）但速度較慢（在 Hack 這樣的教育性架構中，我們只需要在乎功能正確，不必在乎速度）。下面的對照表幫你記住 Hack 的世界觀：

| 面向 | 立即值 | 資料暫存器 D | 位址暫存器 A | 記憶體 M / RAM |
|---|---|---|---|---|
| 本質 | 指令內嵌的常數 | CPU 內的暫存器 | CPU 內的暫存器 | 外部 32K 字組 |
| 數量 | 每一條指令各有一個 | 1 個 | 1 個 | 32768 個 |
| 作用 | 提供常數 | 存放資料，可讀可取 | 存放位址或資料 | 以 A 為索引的資料空間 |
| 存取語法 | `@值` | `D` | `A` | `M`（＝ RAM[A]）|

一個值得注意的 Hack 特色是：**A 暫存器具有雙重身分**。當我們只想「算一個常數」時，A 可以當暫存器用；當我們想要「讀寫記憶體」時，A 又變成記憶體的位址索引。這個設計讓指令格式可以極簡——只用兩類指令就涵蓋了立即值、暫存器、記憶體三種定址模式。下一節我們會看到，這一切的代價是：要存取記憶體，程式的第一步永遠必須是「先把位址載入 A」。

## Hack 機器語言的元件：A、D、M 三兄弟

來到壓軸：Hack 機器語言究竟有幾個「會動的零件」？答案只有三個，記住它們就記住了整個指令集的設計：

### 位址暫存器 A（16 位元）

* 唯一有能力「指出一個記憶體位址」的暫存器。
* 由 A-指令載入：`@100` 表示「把 100 放進 A」。
* 當需要算記憶體時，`M` 其實就是「RAM[A]」的縮寫。
* 也可以乾脆當普通資料暫存器使用（例如 `D=A+D`）。
* 同時是條件跳躍的目標位址來源。

### 資料暫存器 D（16 位元）

* 純粹存放資料用的暫存器，沒有任何位址意義。
* 運算時盡量「先把東西抓回 D」，因為絕大多數 C-指令的第一個運算元是 D。
* 它也是唯一能同時扮演「被讀取運算元」與「被寫入目標」的暫存器：`D=D+1` 完全合法。

### 記憶體 M（＝ RAM 中以 A 索引的那一格）

* 不是一個真實的暫存器，而是一個「虛擬同步參照」——只要程式的 A 暫存器指向某個位址，`M` 就代表那一格的內容。
* 在 C-指令中，可以由 `M`（a=1）作為運算元來源，也可以寫入 `M`（dest 含 M）。
* 是 I/O 的通道：螢幕、鍵盤都掛在記憶體的某些位址上（4.3 節）。

用一張「程式設計師視角的記憶體模型」結束本節：

```text
        A（位址暫存器）             D（資料暫存器）
              │                         │
              │  @值 載入                │  運算、暫存
              ▼                         ▼
   ┌──────────────────────────────────────┐
   │             ALU（第二章）             │
   └──────────────────────────────────────┘
              │       │
              │       └─────► M = RAM[A]（記憶體、螢幕、鍵盤）
              ▼
           PC（程式計數器，第三章）：跳躍時改變執行流向
```

## 設計思路與實作步驟

如果在真實世界設計一個教育用 ISA，我們的決策過程大致如下：

1. **決定字寬**：指令與資料都統一用 16 位元，與第二章 ALU 的輸出寬度一致，管線最單純。
2. **決定指令數**：捨棄 x86 上百種指令的複雜度，只保留 A-指令與 C-指令兩類，把「運算」徹底交給 ALU 那 18 種函數——ISA 變薄，組譯器與 CPU 都好做。
3. **整合定址模式**：用「A 暫存器 + M 虛擬符號」一網打盡立即值、暫存器、記憶體三種資料位置，不必為每種定址模式另設計算指令。
4. **把流程控制收到 C-指令裡**：跳躍目標永遠放在 A 暫存器，條件以「結果的負/零/正」為主，跳躍欄位只是三個位元。
5. **準備工具鏈**：下一節先定義精確的位元編碼表，組譯器（第六章）才能把助記元翻譯成硬體看得懂的 0/1。
6. **驗證**：用 CPU 模擬器把每條指令的執行行為跑過一遍，並在第五章用真實電路驗收。

這套「先有 ISA，再有組譯器，最後有 CPU」的順序，其實映射了真實世界的開發流程：**指令集架構先行，軟硬體各自朝這份合約靠攏**。

## 本章小結

- **ISA 是硬體與軟體之間的合約**：定義指令格式、定址模式與行為語意；機器語言是純位元，組合語言是可讀的助記形式。
- **機器語言的三個核心元素**：運算（做什麼）、資料位置（從哪拿、放哪）、跳躍（接下來去哪裡），三者齊備才足以寫出任意的可計算程式。
- **Von Neumann 架構**：程式與資料同存於記憶體，CPU 依 PC 進行「抓取—解碼—執行」的無限循環；Hack 電腦即此架構的教科書級實作。
- **A、D、M 三兄弟**：A 是唯一的位址暫存器（可兼任資料），D 是純資料暫存器，M 是「RAM[A]」的虛擬參照；記憶體全址為 0～32767 的 16 位元字組。
- **設計原則**：極簡雙指令、把運算外包給 ALU、跳躍目標統一放 A 暫存器——以最少的硬體零件支撐完整的程式語言能力。

有了對 ISA 的整體認識，下一步就是拿起放大鏡，把 A-指令與 C-指令的每一個位元欄位逐一解剖——那就是 4.2 節的工作。
