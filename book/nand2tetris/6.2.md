# 6.2 符號表（Symbol Table）與標號解析（Labels & Variables）

## 學習目標

讀完本節後，你應該能：

- 區分 Hack 組譯器中三類符號：預定義符號、標號、變數
- 默背預定義符號的位址（SP/LCL/ARG/THIS/THAT、R0~R15、SCREEN、KBD）
- 說明標號 `(xxx)` 如何決定位址（= 下一個可執行指令的行號）
- 說明變數如何配置位址（從 16 開始、逐號遞增、每支只配一次）
- 用 Python 設計符號表的資料結構並實作查詢與新增

---

## 前言

6.1 節我們把 A-指令、C-指令的編碼規律都講清楚了。但有一個大問題還沒解決：上節所有例子裡，`@7`、`@16384` 這種「直接寫數字」的用法，在真實程式中其實非常罕見。真實程式長這樣：

```asm
@i
M=1
(LOOP)
@i
M=M+1
@LOOP
0;JMP
```

`i` 是什麼？`LOOP` 是什麼？組譯器看到 `@i` 時，憑什麼知道該把哪個數字放進機器碼？

答案就是本節的主角：**符號表（Symbol Table）**——組譯器內部用來記錄「符號 → 位址」對應關係的資料結構。它是組譯器最核心、也最優雅的部份：整份程式中，你只需要維護一張「需要記住的符號」表格，就能讓程式設計師徹底脫離「記位址」的苦海。

---

## 1. 為什麼需要符號？

把問題反過來想：如果沒有符號，程式設計師寫 Hack 程式必須自己記所有位址：

- 變數 `i` 放在 RAM 哪一格？
- 程式要跳回去的那個「迴圈開頭」在第幾條指令？
- 螢幕基地位址是 16384，鍵盤是 24576——你得背下來？

這對於小程式還行，程式一大就徹底失控：在中間插入一行指令，後面所有行號全部錯位。

符號機制把這個負擔轉移給組譯器。程式設計師寫下抽象名字（`i`、`LOOP`、`SCREEN`），組譯器在組譯期間自動完成三件事：

1. **認識制度性的名字**：`R0`、`SCREEN` 這些是 Hack 規格保證存在的。
2. **替標號配位址**：`(LOOP)` 所在位置對應的指令行號。
3. **替變數配位址**：從 RAM 第 16 格開始，一支一支配。

這三件事對應三類符號。我們逐一拆解。

---

## 2. 三類符號的總覽

| 符號種類 | 長什麼樣 | 位址從哪來 | 什麼時候定案 |
|----------|----------|------------|--------------|
| **預定義符號** | `R0`、`SP`、`SCREEN`、`KBD` 等 | Hack 規格寫死 | 組譯開始前 |
| **標號（Label）** | `(LOOP)`、`(END)` | = 下一條指令的行號 | 第一遍掃描（見 6.3） |
| **變數（Variable）** | `@i`、`@sum`、`@x` | 從 16 起逐號遞增 | 第二遍掃描（見 6.3） |

辨識關鍵字（syntax）：

- 標號用**小括號包住**：`(LOOP)`，永遠獨立一行，而且**不佔指令行號**；
- 預定義符號與變數都出現在 `@` 之後：`@R1`（預定義）、`@i`（變數）；
- 兩者的區分方式很簡單：**先在預定義表查，查不到就當變數**。

---

## 3. 預定義符號與位址

### 3.1 記憶體映射規格先回顧

預定義符號之所以「預先定義」，是因為第 4 章設計 Hack 的記憶體地圖時，就已經把最重要的位址「命名」了。它們分五組：

| 符號 | 位址 | 意義 |
|------|------|------|
| `SP` | 0 | 堆疊指標（Stack Pointer）的基地，指向棧頂 |
| `LCL` | 1 | 區域變數段基地（Local） |
| `ARG` | 2 | 函式參數段基地（Argument） |
| `THIS` | 3 | this 指標（指向 current object / 物件段） |
| `THAT` | 4 | that 指標（指向另一物件段） |
| `R0` ~ `R15` | 0 ~ 15 | 通用暫存器別名（R0=SP、R1=LCL、R2=ARG...） |
| `SCREEN` | 16384 | 螢幕記憶體映射的起始位址（`0x4000`） |
| `KBD` | 24576 | 鍵盤記憶體映射的位址（`0x6000`） |

請注意一個有趣的細節：`SP` 與 `R0` **是同一格記憶體**（位址 0），只是兩個名字。同理 `LCL == R1`、`ARG == R2`、`THIS == R3`、`THAT == R4`。這是 Hack 的「雙重命名」，第 7 章虛擬機（VM）實作時，這些名字會全部派上用場。

### 3.2 記憶體地圖視覺化

```
位址           內容                       符號
─────   ───────────────────────   ────────
0       堆疊指標 / 暫存器 R0       SP / R0
1       區域變數基地 / R1          LCL / R1
2       參數基地   / R2           ARG / R2
3       this 指標 / R3            THIS / R3
4       that 指標 / R4            THAT / R4
5..15   暫存器 R5~R15             R5..R15
16..255 變數與陣列基地（組譯器分配）
256..   堆疊空間
16384.. 螢幕映射（8K words）       SCREEN
24576   鍵盤映射                   KBD
```

### 3.3 組譯器裡的表示：一張初始化的字典

預定義符號在 Python 中就是一張**預先填好的字典**：

```python
PREDEFINED = {
    'SP': 0, 'LCL': 1, 'ARG': 2, 'THIS': 3, 'THAT': 4,
    'R0': 0, 'R1': 1, 'R2': 2, 'R3': 3, 'R4': 4, 'R5': 5,
    'R6': 6, 'R7': 7, 'R8': 8, 'R9': 9, 'R10': 10, 'R11': 11,
    'R12': 12, 'R13': 13, 'R14': 14, 'R15': 15,
    'SCREEN': 16384, 'KBD': 24576,
}
```

這張表會在組譯器啟動時**先複製一份**成為符號表的主體（為什麼要複製而不是直接修改？因為組譯器的符號表會越長越大，不能污染「純淨的規格表」——程式一多的話，`@i` 的 16、`@sum` 的 17 會被塞進去）。

> **設計思路**：把預定義符號集中成一張表，而不是在程式裡寫一堆 `if sym == 'SCREEN'` 的判斷，是「資料驅動（data-driven）」的做法——組譯器不需要知道任何符號的語意，只管查表。這樣一支程式碼就能同時服務三類符號，邏輯統一、不易出錯。

## 4. 標號如何決定位址

### 4.1 規則只有一句話

標號（Label）的規則是整個組譯器最精簡的定義：

> `(xxx)` 的位址 = **緊跟在它之後那一條可執行指令的行號**（從 0 開始數）。

也就是：標號不佔行號，它只是幫「下一條指令的位置」取名字。

### 4.2 一個逐步示範

看下面這段程式（含空行與註解，模擬真實檔案）：

```
行號     原始文字                   說明
─────────────────────────────────────────────────
(L1)     (LOOP)                   ← 標號行，不佔行號
L0       @i                       ← 第 0 條指令
L1       M=M+1
L2       @LOOP         → 此時 LOOP = ? 
L3       0;JMP
         (END)                    ← 標號，不佔行號
L4       @END
L5       0;JMP
```

數行號時，**只數 A-指令與 C-指令**。於是：

- `(LOOP)` 後面第一條可執行指令是 L0 → `LOOP = 0`
- `(END)` 後面第一條可執行指令是 L4 → `END = 4`

驗證：`@LOOP` 與 `@END` 翻譯出來就是 `0000000000000000` 與 `0000000000000100`。

### 4.3 標號能不能放中間？——當然可以

標號不一定在迴圈開頭，也可以在前後文之間。例如把 `(XXX)` 放在兩條指令中間，它的值就是「下一條指令」的行號：

```asm
@7        // 第 0 條
(XXX)     // 標號：位址 = 1
D=A       // 第 1 條
```

規則一致：`XXX = 1`。

### 4.4 第一個陷阱：標號重複

Hack 規格（也是多數組譯器的行為）要求：**同一支標號只能宣告一次**，重複宣告屬於錯誤。為什麼？因為如果 `(LOOP)` 出現兩次就該取哪個位址？——矛盾。組譯器可以選擇報錯終止，也可以「後收到者覆蓋」（實作最簡單，很多教學組譯器這樣做）。進階實作要檢查重複宣告並印出錯誤訊息，這是 6.4 節除錯單元會講的細節。

## 5. 變數如何配置位址

### 5.1 規則也只有一句話

> 出現未被認識的符號 `@xxx` 時，組譯器在符號表新增 `xxx → next_var`，其中 `next_var` **從 16 開始，每配一支就 +1**。

### 5.2 為什麼是 16？

回想記憶體地圖：

- 位址 0~15 被預定義符號佔滿（SP/LCL/ARG/THIS/THAT/R0~R15）；
- 位址 16 之後到堆疊區域之前，是「自由區」。

規定變數從 16 起，組譯器就能保證「永遠不會踩到制度性位址」。

### 5.3 逐步示範：第一支變數

```asm
@i          // i 不在表內 → 配 16
M=0         // 等等，M=0 需要 A 內容為位址——對，A 正是 16
@i          // i 已在表內 → 直接取 16
D=M
```

組譯器處理過程（只看位址分配）：

| 遇到 | 查表結果 | 動作 | 符號表（新加入者） |
|------|----------|------|--------------------|
| `@i` | 找不到 | `i = 16`，next_var 變成 17 | `i → 16` |
| `@i` | 找到 16 | 直接用 | （不變） |

關鍵重點：**同一個變數，全程式只配一次位址**。第二次見到 `@i` 時直接查表。這保證了 `@i` 在整支程式中都指向同一格 RAM——否則迴圈就崩潰了。

### 5.4 多支變數的例子

```asm
@x          // x = 16
@y          // y = 17
@z          // z = 18
@x          // 查表 → 16
```

`next_var` 就像討債的櫃檯號碼機：每新增一號就叫下一個號碼。實作語言常說這是「自動遞增計數器」：

```python
next_address = 16          # 從 16 開始「發號碼」
def get_variable(symbol):
    nonlocal next_address  # （示意）
    if symbol not in table:
        table[symbol] = next_address
        next_address += 1
    return table[symbol]
```

### 5.5 順序問題：標號 vs 變數誰先誰後？

這是初學者最常問的問題，也直接引出 6.3 節的兩階段掃描：

- **標號**可能在程式「後半段」才被宣告，但「前半段」的 `@LOOP` 就要用到它 → 所以標號**必須先全部收齊**（第一遍掃描）。
- **變數**則相反，誰先用誰先配，走到哪配到哪（第二遍掃描）。

如果只掃描一遍，遇到 `@LOOP` 卻還沒看到後面的 `(LOOP)`，組譯器一查表找不到，就會誤把 `LOOP` 當成變數配成 16——那就全錯了。這就是「為什麼需要兩次掃描」的根源，6.3 節我們正式解決它。

## 6. 符號表的資料結構

### 6.1 功能需求

符號表要有三種操作：

1. **contains(symbol)**：這個符號出現過嗎？
2. **add(symbol, address)**：新增一筆對應
3. **getAddress(symbol)**：查詢位址（查不到就是 bug，或該當變數配置）

### 6.2 選型：Python 字典完全足矣

Hack 程式通常只有幾百支符號，所以最合適的資料結構就是**雜湊表（hash table）**。Python 的 `dict` 就是內建的雜湊表，插入與查詢都是平均 O(1)。

```python
class SymbolTable:
    """Hack 組譯器的符號表——包一層 dict 加上清楚的介面"""

    def __init__(self):
        self._table = {
            'SP': 0, 'LCL': 1, 'ARG': 2, 'THIS': 3, 'THAT': 4,
            'R0': 0, 'R1': 1, 'R2': 2, 'R3': 3, 'R4': 4, 'R5': 5,
            'R6': 6, 'R7': 7, 'R8': 8, 'R9': 9, 'R10': 10, 'R11': 11,
            'R12': 12, 'R13': 13, 'R14': 14, 'R15': 15,
            'SCREEN': 16384, 'KBD': 24576,
        }

    def add(self, symbol: str, address: int) -> None:
        self._table[symbol] = address

    def contains(self, symbol: str) -> bool:
        return symbol in self._table

    def getAddress(self, symbol: str) -> int:
        return self._table[symbol]

    def __repr__(self):
        return repr(self._table)
```

用起來像這樣：

```python
st = SymbolTable()
st.getAddress('SP')      # 0
st.getAddress('SCREEN')  # 16384
st.contains('LOOP')      # False
st.add('LOOP', 10)
st.getAddress('LOOP')    # 10
st.contains('LOOP')      # True
```

### 6.3 如果你是寫 C 語言？

在 C 語言我們沒有內建字典，最樸素的實作是「兩個平行陣列 + 線性搜尋」：

```c
// symbol.h（概念示意，非完整程式）
#define MAX_SYMBOLS 1024

typedef struct {
    char name[64];
    int  address;
} Symbol;

typedef struct {
    Symbol symbols[MAX_SYMBOLS];
    int    count;
} SymbolTable;

int  st_contains(SymbolTable *st, const char *name);
void st_add(SymbolTable *st, const char *name, int address);
int  st_get(SymbolTable *st, const char *name);
```

線性搜尋對哈克級程式（< 1000 支）綽綽有餘；要更快再換成真雜湊表。這個「拿空間換時間」的取捨，就是資料結構課教的內容，這裡我們用 Python 的內建 `dict` 一勞永逸。

> **設計思路**：為什麼不直接裸用 `dict`，還要包成 `SymbolTable` 類別？因為物件導向的封裝讓組譯器的其他部分（6.3 節的兩遍掃描）只依賴「add / contains / getAddress」三個方法，而不必知道底層是字典、陣列還是資料庫。這也讓單元測試（6.4 節）更容易寫——介面小，測項就少。

## 7. 查詢與更新操作：程式碼化的解析流程

「遇到符號怎麼辦」的完整規則，可以濃縮成一張決策表，寫在手冊上完全夠用：

```
組合語言中的符號 x
│
├─ 若 x 是純數字常數      → 直接用 int(x)（15 位元內）
├─ 若 x 是 (標號) 宣告    → 記錄「標號 x → 下一條指令行號」
├─ 若 x 出現在 @ 之後：
│   ├─ 符號表查得到       → 用表中的位址
│   └─ 符號表查不到       → 當作變數：
│                           table[x] = next_address
│                           next_address += 1
└─ 以上都做完 → 套用 6.1 節的編碼表翻譯
```

把「查表優先、查不到才配新位址」的邏輯，用 Python 寫成單一定義函數：

```python
def resolve(symbol: str, st: SymbolTable, next_address: int):
    # next_address 以可變容器傳入，避免作用域問題（6.3 會有完整版）
    if symbol.isdigit():
        return int(symbol)                 # 純數值常數
    if not st.contains(symbol):
        st.add(symbol, next_address[0])    # 新變數：配最新號碼
        next_address[0] += 1               # 號碼機 +1
    return st.getAddress(symbol)
```

> **設計思路**：注意判斷順序——「先看是不是純數字」。因為 Hack 規定變數名稱**不能是數字開頭**（組譯器檢查到 `@123abc` 應報錯），所以 `isdigit()` 檢查可以安全地把 `@7` 這種情況攔下來，不讓它誤入變數分配區。

## 8. 本章小結

- 符號是程式設計師與機器位址之間的中介，組譯器用**符號表**維護「符號 → 位址」對應。
- **預定義符號**：`SP=0, LCL=1, ARG=2, THIS=3, THAT=4, R0~R15=0~15, SCREEN=16384, KBD=24576`，組譯前就固定，常寫成一張初始化字典。
- **標號** `(xxx)` 的位址 = **緊接其後指令的行號**，不佔行號，須在第一遍掃描時收集齊全，因為可能「先被引用、後才宣告」。
- **變數** 從位址 16 開始，按「最先引用者先配」的原則逐號遞增，整支程式只配一次。
- 符號表適合用**雜湊表**實作（Python `dict`），包成 `add / contains / getAddress` 三方法的小類別最乾淨。
- 標號「先收集、變數「後分配」的次序，孕育出 6.3 節的**兩階段掃描（Two-Pass）**組譯器。
