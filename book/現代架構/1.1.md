## 1. RISC-V 的前世今生

### 1.1 為何需要新的 ISA？

RISC-V 起源於 2010 年，加州大學柏克萊分校（UC Berkeley）由 Krste Asanović、David Patterson 等人發起的開源指令集架構專案。相較於當時主流的 x86（Intel/AMD 私有）與 ARM（ARM Holdings 授權）架構，RISC-V 具備三個關鍵優勢：

| 特性 | x86 | ARM | RISC-V |
|------|-----|-----|--------|
| 授權 | 不開放 | 付費授權（royalty） | **開放標準（BSD/CC）** |
| 擴充 | 複雜多變異 | 授權綁定 | **模組化 / 標準化** |
| 長度 | 可變 1-15 bytes | 固定 32-bit / 可變 Thumb | **固定 32-bit 基線** |
| 可裁剪 | 不適合 | 有 Profiles | **RV32I 可極簡實作** |

RISC-V 的「開放」在意義上有三個層面：

1. **ISA 規範免費公開**：任何人可閱讀、下載、實作，不需授權費。
2. **可自訂擴充**：除了官方標準擴充（M/A/F/D/V…），允許廠商自訂商用擴充。
3. **軟體生態可共用**：同一份 GCC/LLVM/Linux 可針對不同實作編譯。

### 1.2 模組化設計：Base + Extensions

RISC-V 採用「**基底整數 ISA** + 可選擴充」的組合策略：

```
RV32/64/128I       基底整數指令集（必須存在）
        + M        整數乘法/除法
        + A        原子操作（Atomics，多核心必須）
        + F        單精度浮點 (32-bit)
        + D        雙精度浮點 (64-bit，F 的超集)
        + C        壓縮指令（16-bit，程式碼縮小 25%~30%）
        + V        向量擴充（RVV，見 3.3）
        + Zicsr    CSR 指令
        + Zifencei 指令快取屏障
```

命名慣例，例如 `RV32IMAC` 表示 32-bit 基底整數 + 整數乘除 + 原子操作 + 壓縮指令。

## 2. 暫存器規範與定址模式

### 2.1 通用暫存器 (x0-x31)

RISC-V 基底 ISA 提供 **32 個通用暫存器 (GPR)**，每個寬度為 `XLEN`（RV32 為 32-bit，RV64 為 64-bit）。暫存器硬體上僅以代號 `x0 ~ x31` 存在，其後的 `ra/sp/gp/...` 是 **ABI 助記名稱（mneumonic）**，說明該暫存器的程式設計用途。

| 暫存器 | ABI 名稱 | 用途 | 保存者 |
|--------|----------|------|--------|
| `x0` | `zero` | **Hardwired Zero**，恆為 0，寫入被忽略 | — |
| `x1` | `ra` | Return Address（函式返回位址） | Caller |
| `x2` | `sp` | Stack Pointer（堆疊指標） | Callee |
| `x3` | `gp` | Global Pointer（全域指標） | — |
| `x4` | `tp` | Thread Pointer（執行緒指標，TLS 基底） | — |
| `x5` | `t0` | Temporary / 備援連結位址 | Caller |
| `x6-7` | `t1-t2` | Temporaries | Caller |
| `x8` | `s0` / `fp` | Saved Reg / Frame Pointer（框架指標） | Callee |
| `x9` | `s1` | Saved Register | Callee |
| `x10-11` | `a0-a1` | 函式參數 / 傳回值 | Caller |
| `x12-17` | `a2-a7` | 函式參數 | Caller |
| `x18-27` | `s2-s11` | Saved Registers | Callee |
| `x28-31` | `t3-t6` | Temporaries | Caller |

關鍵性質：

- **`x0` 硬體接線為 0**：此設計消除了「建置 0 暫存器」的需求。例如 `addi x0, x0, 0` 就是標準的 `nop`；`j`（無條件跳躍）真正形式是 `jal x0, offset`——跳出去但不保存返回位址。
- **分工目的**：暫時性暫存器（`t`）由 Caller-Saved，呼叫函式前必須保存；保留暫存器（`s`）由 Callee-Saved，若函式修改必須自行壓棧保存。詳見 4.1 的 Calling Convention。

### 2.2 定址模式 (Addressing Modes)

RISC-V 刻意採用**精簡定址設計**，相較 x86 的十餘種定址模式，RISC-V 只有五種：

#### (1) Register Direct（暫存器直接定址）

運算元完全來自暫存器，無記憶體存取：

```asm
add   x5, x6, x7   # x5 = x6 + x7（三個暫存器）
sub   x5, x6, x7   # x5 = x6 - x7
```

#### (2) Immediate Addressing（立即定址）

運算元之一為指令內嵌的常數（Sign-Extended）：

```asm
addi  x5, x6, -100 # x5 = x6 + (-100)，立即數為 12-bit 有號
```

#### (3) Base-Offset Addressing（基底+偏移定址）

僅用於 **Load/Store 指令**。有效位址 = `Base Register + Sign-Extended Immediate`：

```asm
lw    x5, 8(x6)   # x5 = *(x6 + 8)；由記憶體讀 4 bytes
sw    x5, 8(x6)   # *(x6 + 8) = x5；寫入記憶體
```

注意：RISC-V 的 Load/Store **不支援**「暫存器 + 暫存器」的索引定址（如 x86 的 `[eax+ebx]`）。要算複雜位址，必須先用加法指令算好再存取——這是精簡設計取捨：簡化硬體，但不爽快。

#### (4) PC-Relative Addressing（PC 相對定址）

目標位址 = `PC + Sign-Extended Immediate`。**不消耗**絕對常數，因此天然支持 **位置無關程式碼 (PIC)**，讓共享庫可以被載入到記憶體任何位址：

```asm
jal   ra, label    # PC-relative：跳至 label，ra = 返回位址
beq   x5, x6, label # PC-relative：若 x5==x6 則跳至 label
```

#### (5) 只有 U/J 短暫的直接絕對定址（LUI/AUIPC 手腳架）

32-bit 立即數無法塞入單一指令。RISC-V 用兩條指令「組裝」完整 32-bit 常數：

- `lui rd, imm20`：將 20-bit 立即數放入暫存器最高 20 bits（低 12 bits 清 0）。
- `auipc rd, imm20`：`rd = PC + (imm20 << 12)`，用於 PIC 中取 PC 值。

```asm
# 將常數 0x12345678 載入 x5
lui   x5, 0x12345   # x5 = 0x12345000
addi  x5, x5, 0x678 # x5 = 0x12345678（若 overflow 需些微技巧）
```

## 3. 指令編碼格式 (R/I/S/B/U/J-Type)

### 3.1 設計核心：欄位位置的嚴格對齊

RISC-V 所有**基底指令皆為固定 32-bit**。最關鍵的硬體友善設計是：**來源暫存器欄位永遠固定在相同的 bit 位置**，與指令類型無關：

```
 bits:  31        25 | 24      20 | 19     15 | 14    12 | 11       7 | 6       0
        ┌───────────┬────────────┬───────────┬──────────┬───────────┬──────────┐
        │   funct7  │    rs2     │    rs1    │  funct3  │    rd     │  opcode  │
        └───────────┴────────────┴───────────┴──────────┴───────────┴──────────┘
                                    ▲              ▲          ▲          ▲
                  rs1 = bit 15-19   │              │          │          │ opcode 在最底
                  funct3 = bit 12-14               │          │
                  rd = bit 7-11                    └──────────┘
```

- **`opcode` 永遠在 bit 0-6**：decoder 第一眼（最低 7 bits）就認識指令家族。
- **`rd`（目標暫存器）永遠在 bit 7-11**：所有會寫回的指令共用此欄位。
- **`rs1`（來源暫存器 1）永遠在 bit 15-19**、**`rs2` 永遠在 bit 20-24**。
- 這種對齊讓 decode 與 register-file 讀取可以**平行進行**，甚至不必等 decode 完成就可以先讀暫存器——這是流水線設計（1.2 節）的重要基石。

### 3.2 六種格式逐一拆解

#### R-Type（Register–Register）

[-]運算元皆為暫存器，用於算術/邏輯/移位：

```
| funct7 (7b) | rs2 (5b) | rs1 (5b) | funct3 (3b) | rd (5b) | opcode (7b) |
  31:25         24:20      19:15       14:12         11:7       6:0
```

範例編碼 `add x5, x6, x7`：

```
funct7=0000000  rs2=x7(00111)  rs1=x6(00110)  funct3=000  rd=x5(00101)  opcode=0110011
→ machine code = 0000000 00111 00110 000 00101 0110011 (二進位)
                = 0x00C302B3
```

#### I-Type（Immediate / Load / JALR）

用於立即數運算、Load 指令與 `jalr`：

```
| imm[11:0] (12b) | rs1 (5b) | funct3 (3b) | rd (5b) | opcode (7b) |
   31:20            19:15       14:12         11:7       6:0
```

範例：`addi x5, x6, -8` → `imm=111111111000  x6=00110  000  x5=00101  0010011`。

`lw` 的 `funct3=010`；`jalr x5, 0(x6)` 的 `funct3=000`、`opcode=1100111`。

#### S-Type（Store）

Store 需要**兩個**來源暫存器（`rs1` = 基底、`rs2` = 資料），沒有 `rd`。因此 12-bit 立即數被**拆成兩段**塞進本該是 `rd` 的位元組：

```
| imm[11:5] (7b) | rs2 (5b) | rs1 (5b) | funct3 (3b) | imm[4:0] (5b) | opcode (7b) |
   31:25           24:20      19:15       14:12         11:7            6:0
```

`. . .` 立即數 `imm[11:0]` 的**多播順序被打亂**，但這不影響正確性，只是方便解碼電路沿用 R 型版面：rs1/rs2 仍在原位置，僅把無用的 `rd` 欄位改拿來放立即數片段。

範例：`sw x5, 8(x6)`（funct3=010）：

```
imm[11:5]=0000000  rs2=x5(00101)  rs1=x6(00110)  010  imm[4:0]=01000  0100011
→ 0x00C32423
```

#### B-Type（Branch）

條件跳躍的 PC 相對偏移。三位元組的特殊性：**偏移恆為 2 的倍數**（指令 32-bit 對齊，最低位永遠 0 不必編碼），所以 13-bit 有號偏移被壓縮成 12-bit：

```
| imm[12] imm[10:5] | rs2 | rs1 | funct3 | imm[4:1] imm[11] | opcode |
   31:25              24:20  19:15   14:12    11:7               6:0
```

實際目標偏移 = `{imm[12], imm[10:5], imm[4:1], imm[11], 0}`（重新排列並補上 bit0=0）。

範例：`beq x5, x6, +8`（向後跳 8 bytes）：

```
offset = +8 = 0_0000010_000_0...  → funct3=000（beq）
```

#### U-Type（Upper Immediate）

裝載高位立即數，對應 `lui` 與 `auipc`（也包含 `jal` 之外的 `opcode` 家族）。載入 20-bit，置入暫存器**最高欄位**：

```
| imm[31:12] (20b)        | rd (5b) | opcode (7b) |
   31:12                    11:7       6:0
```

#### J-Type（Jump）

無條件跳躍 `jal rd, offset`。20-bit 偏移（PC-relative，2-byte 對齊，低位 0）：

```
| imm[20] imm[10:1] imm[11] imm[19:12] | rd (5b) | opcode (7b) |
   31:30                                11:7       6:0
```

欄位排列呈「碎塊狀」，換來的是三小片立即數與 R/I/S/B 共用位元組，簡化 decoder。

## 4. 控制與狀態暫存器 (CSR) 與例外處理機制

### 4.1 核心 CSR 家族

CSR（Control and Status Register）是 CPU 內部與「控制」相關的暫存器，只能由**特權層級**以上程式透過 `csrrw/csrrs/csrrc` 指令存取。最重要的是機器模式（M-Mode）CSR：

| CSR 名稱 | 全名 | 功能 |
|----------|------|------|
| `mstatus` | Machine Status | 機器當前狀態：全域中斷致能 `MIE`、之前特權等級 `MPP`、中斷致能位元等 |
| `mtvec` | Machine Trap Vector | **Trap 處理程式的入口位址**（若 mode=Direct 即直跳該位址） |
| `mepc` | Machine Exception PC | 例外發生時的 PC；`mret` 會從此處繼續 |
| `mcause` | Machine Cause | 例外/中斷的原因編號（最高位 = 1 表示中斷） |
| `mstatus`/`mie`/`mip` | Interrupt Enable/Pending | 中斷致能與中斷等待旗標 |
| `satp` | Supervisor Address Translation & Protection | S-Mode 頁表根位址（2.2 節） |
| `mtval` | Machine Trap Value | 存放與 trap 相關的資料（如非法位址、非法指令編碼） |

`mcause` 常見編號（M-Mode）：

| cause 值 | 含義 |
|----------|------|
| 0 | Instruction Address Misaligned |
| 2 | Illegal Instruction（非法指令） |
| 3 | Breakpoint (`ebreak`) |
| 8 | Environment call from U-mode（U→S 的 `ecall`） |
| 11 | Environment call from M-mode |
| 12–13 | Instruction/Data Page Fault |
| `0x80000007` | M-Mode Timer Interrupt（中斷：最高位設 1） |

### 4.2 例外（Exception）與中斷（Interrupt）的處理流程

例外與中斷合稱 **Trap**。兩者的本質區別：

- **同步 Trap（Exception）**：由指令本身引起（Illegal Instruction、`ecall`、Page Fault、Div-by-Zero），固定發生在同一指令上。
- **非同步中斷（Interrupt）**：由外部事件引起（Timer、外設 UART/NVMe），可能在任意指令之間發生。

硬體自動完成的處理步驟（以 M-Mode 為例）：

1. **保存被中斷的狀態**
   - 將當前 PC 存入 `mepc`；若屬中斷，存入的是**尚未執行的下一條指令位址**（或依規格指定下數）。

2. **記錄原因與資訊**
   - 原因編號寫入 `mcause`；相關訊息（如非法指令的 32-bit 編碼）寫入 `mtval`。

3. **切換特權等級並跳轉**
   - `mstatus.MPP` 記錄原本特權等級，接著硬體切換到 M-Mode，並將 `PC` 強制設為 `mtvec` 指向的 Trap Handler 位址。
   - 中斷的觸發還受 `mstatus.MIE`（全域）與 `mie`（個別中斷來源）雙重管制。

4. **軟體處理與 `mret` 返回**
   - Trap Handler 檢查 `mcause` 分支處理（見 4.2 節），完成後執行 **`mret`** 指令：
     - 硬體將特權等級還原為 `MPP` 記錄值；
     - 將 `PC` 設回 `mepc`；
     - 重新致能中斷（`MIE` 還原）。

以 `ecall` 的完整路徑為例：

```asm
# 應用程式 (U-Mode)
li   a7, 64        # syscall number 64 = write
li   a0, 1         # fd = 1 (stdout)
la   a1, msg       # buf
li   a2, 13        # len
ecall              # trap! 硬體自動進入 S-Mode 的 stvec handler

# Trap Handler (S-Mode, 入口 = stvec)
trap_vector:
    csrrw sp, sscratch, sp   # 切換到 kernel stack
    ...                      # 保存 context、分派處理（詳見 4.2）
    csrrw sp, sscratch, sp   # 恢復 user sp
    sret                     # 硬體：特權切回 U-Mode，PC = sepc
```

## 5. 小結與延伸閱讀

- **設計哲學**：精簡、固定 32-bit 長度、模組化擴充、開放標準。
- **暫存器**：`x0`（Hardwired Zero）設計消除了 Zero Register 需求。
- **定址模式**：僅五種，Load/Store 用 Base-Offset，跳躍用 PC-Relative。
- **編碼格式**：R/I/S/B/U/J 六種，`rd`/`rs1` 欄位位置不變，decode 硬體簡單。
- **Trap 處理**：`mstatus/mtvec/mepc/mcause` 四管齊下，`mret` 優雅返回。
