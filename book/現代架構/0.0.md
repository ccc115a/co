# 計算機 structures 進階學習目錄：從 Nand2Tetris 到現代系統微架構

---

## 第一章：現代 ISA 與指令層級平行處理 (ILP)

### 1.1 RISC-V 指令集架構設計

* **暫存器規範與定址模式**
* **通用暫存器 (x0-x31)**：`x0` (Hardwired Zero)、`ra` (x1, Return Address)、`sp` (x2, Stack Pointer)、`gp`/`tp` (x3/x4, Global/Thread Pointer)、`t0-t6` (Temporaries)、`s0-s11` (Saved Registers)、`a0-a7` (Function Arguments/Return Values)。
* **定址模式 (Addressing Modes)**：RISC-V 採用精簡定址設計，主要包含 **Register Direct**、**Immediate Addressing**、**Base-Offset Addressing** (僅用於 Load/Store，位址等於 `Base Reg + Sign-Extended Immediate`) 與 **PC-Relative Addressing** (用於 Branch/Jal)。


* **指令編碼格式 (R/I/S/B/U/J-Type)**
* **固定 32-bit 長度**：`opcode` 位於最低 7 位 (bit 0-6)，`rs1` (bit 15-19)、`rs2` (bit 20-24)、`rd` (bit 7-11) 位置嚴格對齊，大幅簡化硬體 Decode 邏輯。
* **各格式用途**：
* **R-Type**：暫存器對暫存器運算 (`add`, `sub`, `sll`)。
* **I-Type**：獨立數運算、Load 指令、`jalr`。
* **S-Type**：Store 指令 (`sw`, `sb`)，拆分 12-bit Immediate 至 bit 7-11 與 bit 25-31。
* **B-Type**：條件跳躍 (`beq`, `bne`)，立即數乘以 2 (bit 0 為 0 不編碼)。
* **U-Type**：載入高位立即數 (`lui`, `auipc`)，含 20-bit Immediate。
* **J-Type**：無條件跳躍 (`jal`)，含 20-bit PC 相對偏移量。




* **控制與狀態暫存器 (CSR) 與例外處理機制**
* **核心 CSR**：`mstatus` (機器狀態)、`mtvec` (Trap 向量入口)、`mepc` (例外發生時的 PC)、`mcause` (例外原因)、`mie`/`mip` (中斷致能與 Pending)。
* **例外 (Exception) 與中斷 (Interrupt) 處理**：
1. 當觸發 Illegal Instruction、ECALL 或硬體中斷時，CPU 硬體自動將當前 PC 存入 `mepc`，原因寫入 `mcause`。
2. 硬體切換特權等級（如 User 至 Machine Mode），將 PC 強制跳轉至 `mtvec` 指向的 Trap Handler。
3. 軟體處理完畢後執行 `mret` 指令，硬體恢復 `mstatus` 並自 `mepc` 繼續執行。





### 1.2 五階段流水線 (5-Stage Pipeline) 實作

* **IF/ID/EX/MEM/WB 階段拆解與資料路徑**
* **IF (Instruction Fetch)**：根據 `PC` 自 I-Cache 讀取指令，更新 `PC = PC + 4`。
* **ID (Instruction Decode)**：Parse 指令，自 Register File 讀取 `rs1`/`rs2`，進行 Sign-Extension。
* **EX (Execute)**：ALU 計算地址、算術結果或判斷 Branch 是否成立。
* **MEM (Memory Access)**：依據 `MemRead`/`MemWrite` 控制訊號存取 D-Cache。
* **WB (Write Back)**：將 ALU 結果或 Memory 讀出值寫回 Register File (`rd`)。


* **資料冒險 (Data Hazards) 與前遞 (Forwarding) 機制**
* **RAW (Read-After-Write) 衝突**：後續指令需要讀取前述指令尚未寫回 Register 的結果。
* **Bypass/Forwarding 邏輯**：當 `EX/MEM.rd == ID/EX.rs1` 或 `MEM/WB.rd == ID/EX.rs1` 且 `RegWrite == 1` 時，將 EX/MEM 階段的 ALUResult 或 MEM/WB 階段的 WriteData 直接 bypass 回傳給 EX 階段的 ALU 輸入端多工器 (Mux)。


* **控制冒險 (Control Hazards) 與流水線氣泡 (Stalling)**
* **Load-Use Hazard**：Load 指令的資料須至 MEM 階段結束才可用，若下一條指令在 EX 階段即需使用，前遞無能為力。
* *解法*：Hazard Unit 偵測到 `ID/EX.MemRead && (ID/EX.rd == IF/ID.rs1 || IF/ID.rs2)`，強制凍結 PC 與 IF/ID 暫存器 1 Cycle，並向 ID/EX 注入清零控制訊號 (NOP/Bubble)。


* **Control Hazard (Branch)**：若在 EX 階段才確認 Branch 成立，需 Flush 清空已被錯誤讀取的 IF/ID 與 ID/EX 暫存器訊號。



### 1.3 動態分支預測 (Branch Prediction)

* **分支目標緩衝區 (BTB) 與分支歷史表 (BHT)**
* **BTB (Branch Target Buffer)**：位於 IF 階段的高速 Cache，記錄 `Branch PC` 到 `Target Address` 的映射，允許在 IF 階段直接取得預測跳轉目標。
* **BHT (Branch History Table)**：記錄歷史跳轉行為 (Taken / Not-Taken)。


* **雙位元飽和計數器與 2-Level 適應性預測器**
* **2-bit Saturated Counter**：包含 4 個狀態（Strongly Taken, Weakly Taken, Weakly Not-Taken, Strongly Not-Taken）。連續兩次預測錯誤才會改變跳轉方向，避免單次迴圈結束誤導預測器。
* **2-Level Adaptive Predictor**：
* **Global History Register (GHR)**：記錄近 $N$ 個分支的全局跳轉歷史（例如 `10110`）。
* **Pattern History Table (PHT)**：用 `PC XOR GHR` 索引 PHT（Gshare 預測器），精確捕捉不同分支之間的關聯性 (Correlation)。





### 1.4 超純量 (Superscalar) 與亂序執行 (Out-of-Order Execution)

* **保留站 (Reservation Stations) 與 Tomasulo 演算法**
* **Superscalar (多發射)**：單一 Cycle 內同時 Fetch/Decode/Issue 多條指令（如 2-way/4-way）。
* **Tomasulo 演算法**：
* **Issue**：指令自 Instruction Queue 發射至專屬 Functional Unit 的 Reservation Station (RS)。
* **Execute**：若運算元未就緒，指令在 RS 內監聽 Common Data Bus (CDB)；當廣播資料匹配時填入運算元，條件滿足即亂序 (Out-of-Order) 執行。
* **Write Result**：執行結果廣播至 CDB 與 RS，解除後續指令的資料依賴。




* **暫存器重新命名 (Register Renaming) 與重排序緩衝區 (ROB)**
* **消除 WAR (Write-After-Read) 與 WAW (Write-After-Write) 偽依賴**：將 ISA 架構暫存器 (Architectural Regs, 如 `x1`) 動態映射至數量更多的物理暫存器 (Physical Regs) 或 RS/ROB Entry。
* **ROB (Reorder Buffer) 與 Precise Interrupt**：
* 指令亂序執行 (Out-of-Order Execution)，但必須 **順序提交 (In-Order Commit)**。
* 所有指令發射時皆按程式順序在 ROB 註冊 Entry。執行完成僅將結果寫回 ROB，只有當 ROB 頂端的指令確認無例外且已完成時，才更新至 Architectural Register File。這保證了當例外發生時，CPU 狀態可以完美還原至特定指令前的狀態。

## 第二章：記憶體階層與儲存架構 (Memory Hierarchy)

### 2.1 快取記憶體 (Cache) 設計與優化

* **直接對映、組相聯與全相聯快取結構**
* **Direct-Mapped Cache**：每個記憶體位址嚴格映射至唯一的 Cache Line ($Index = \text{Block Address} \bmod \text{Total Lines}$)。結構最簡單、存取延遲最低，但極易發生 Ping-Pong 效能碰撞 (Conflict Misses)。
* **N-Way Set Associative Cache**：快取劃分為若干個 Set，每個 Set 包含 $N$ 個 Way。位址先透過 Index 找到特定的 Set，再平行比對該 Set 內 $N$ 個 Tag。這是現代 L1/L2/L3 Cache 的主流平衡設計。
* **Fully Associative Cache**：無 Index 欄位，位址可放入任意 Cache Line。比對時需使用內容可定址記憶體 (CAM) 平行比對所有 Tag，軟體彈性最高但硬體開銷與功耗極大，常用於小容量 TLB 設計。


* **寫入策略 (Write Policy) 與替換演算法 (LRU/FIFO)**
* **Write-Through vs. Write-Back**：
* *Write-Through*：寫入時同步更新 Cache 與下一層 Memory，邏輯簡單但極度消耗匯流排頻寬；通常搭配 Write Buffer 減緩延遲。
* *Write-Back*：寫入時僅更新 Cache 並將該 Line 標記為 `Dirty`，直到該 Line 被 Evict (驅逐) 時才寫回下一層 Memory。顯著節省頻寬，為現代 CPU 主要寫入機制。


* **Write Allocation Policy**：Write Miss 時，選擇載入該 Block 至 Cache 再寫入 (Write-Allocate，常搭配 Write-Back)，或直接寫回下一層不載入 Cache (No-Write-Allocate，常搭配 Write-Through)。
* **替換演算法 (Replacement Algorithms)**：
* *LRU (Least Recently Used)*：精確記錄使用歷史並剔除最久未使用的 Line，高 associativity 下硬體維護開銷昂貴。
* *Pseudo-LRU (PLRU)*：使用樹狀位元 (Tree-PLRU) 或 Bit-PLRU 近似 LRU 行為，大幅降低硬體邏輯複雜度。
* *FIFO / Random*：依據佇列順序或隨機剔除，實現簡單，但容易發生的 Belady 異常或誤殺頻繁存取的資料。




* **快取不命中 (Cache Misses) 分類與 3C 分析**
* **Compulsory Misses (冷啟動/強制不命中)**：資料第一次被存取時必定發生的 Miss。*解法*：增大 Block Size 或採用硬體預取器 (Hardware Prefetcher)。
* **Capacity Misses (容量不命中)**：快取容量不足以容納程式執行所需的工作集 (Working Set) 而產生的 Miss。*解法*：加大 Cache 總容量。
* **Conflict Misses (碰撞不命中)**：在 Set-Associative 或 Direct-Mapped 中，多個常用位址映射至同一個 Set 所導致的剔除 Miss。*解法*：提高 Associativity (如 4-way 改為 8-way) 或調整數據結構對齊。



### 2.2 虛擬記憶體與記憶體管理章 (VM & MMU)

* **頁表 (Page Table) 結構與多層頁表轉譯**
* **頁面機制 (Paging)**：將虛擬位址空間 (VA) 與實體位址空間 (PA) 切分為固定大小的頁面 (通常為 4KB)。
* **多層頁表 (Multi-level Page Table)**：為解決單層頁表龐大的記憶體佔用問題，將 VA 切分為多級 Index（例如 RISC-V Sv39 採用 3-Level Page Table）。只有被使用的頁表頁面才會被配置在 DRAM 中，大幅節省空間。
* **Page Fault 處理**：當頁表項 (PTE) 的 `Valid bit = 0` 時，MMU 觸發 Page Fault 異常，由 OS 載入磁碟頁面至 DRAM 並更新 PTE，最後重新執行該指令。


* **轉譯後備緩衝區 (TLB) 運作與 Cache 尋址 (VIPT/PIPT)**
* **TLB (Translation Lookaside Buffer)**：專門用來快取 PTE 的高速 HW Cache，用以加速 VA 到 PA 的轉譯過程。
* **Cache 尋址架構**：
* *PIPT (Physically Indexed, Physically Tagged)*：先經過 TLB 將 VA 轉為 PA，再存取 Cache。最直觀且無 Alias 問題，但 TLB 轉譯增加了 L1 Cache 存取 Critical Path。
* *VIPT (Virtually Indexed, Physically Tagged)*：利用 $VA[11:0]$ (Page Offset，轉譯前後不變) 作為 Cache Index 進行存取，同時平行查詢 TLB 取得 PA；當 Cache Tag 讀出時，正好與 TLB 產生的 PA 比對。**這是現代 L1 Cache 兼具高速與安全的主流架構**。





### 2.3 主記憶體與匯流排架構

* **DRAM 晶片組織、時序參數與預充電機制**
* **1T1C 結構**：DRAM 每個 Bit 由 1 個電晶體與 1 個電容器組成，由於電容電荷會洩漏，需定期進行 Refresh (刷存) 操作。
* **Bank / Row / Column 組織**：DRAM 晶片內部劃分為多個獨立的 Bank。存取時先送出 Row Address 執行 `Activate` (將列資料載入 Sense Amplifiers)，再送出 Column Address 進行 Read/Write。
* **關鍵時序參數 (Timing Parameters)**：
* $t_{RCD}$ (RAS to CAS Delay)：從 Activate Row 到下達 Column Read/Write 命令的等待時間。
* $CL / t_{CL}$ (CAS Latency)：下達 Read 命令到第一筆資料傳出的 Latency。
* $t_{RP}$ (Row Precharge Time)：關閉當前 Row 並恢復電容狀態以準備開啟新 Row 的時間。




* **匯流排仲裁 (Bus Arbitration) 與直接記憶體存取 (DMA)**
* **Bus Arbitration**：當有多個 Master（如 CPU、GPU、DMA 控制器）爭用系統匯流排時，由 Bus Arbiter 依據優先級（如 Fixed Priority、Round-Robin）決定 Bus 使用權。
* **DMA (Direct Memory Access)**：允許周邊裝置 (如 NVMe SSD、網卡) 直接與 DRAM 進行資料傳輸，無需 CPU 逐字搬移。傳輸前由 CPU 設定 DMA 控制器的 Source/Destination/Length，傳輸完畢後 DMA 觸發硬體中斷通知 CPU。

## 第三章：平行處理與多核心微架構 (Parallelism)

### 3.1 多核心與快取一致性 (Cache Coherence)

* **快取一致性問題 (The Coherence Problem)**
* 多核心系統中，每個核心擁有獨立的私有快取（如 L1/L2）。當多個核心同時快取並修改同一記憶體位址時，會導致資料不一致。
* **Coherence 核心原則**：單一寫入/多重讀取 (Single-Writer/Multiple-Reader) 與寫入傳播 (Write Propagation)。


* **Snooping (監聽式) 一致性協定**
* **機制**：所有核心的快取控制器透過共享匯流排 (Shared Bus) 廣播記憶體存取動作，互相監聽 (Snoop) 匯流排上的 Bus Read / Bus Write 事件。
* **適用場景**：核心數量較少（通常 $\le 8$ 核心）的小型多處理器系統，廣播開銷為 $\mathcal{O}(N^2)$。


* **Directory-Based (目錄式) 一致性協定**
* **機制**：在主記憶體或共享 L3 Cache 設立「目錄 (Directory)」，記錄各 Cache Line 目前被哪些核心快取及其狀態。點對點 (Unicast/Multicast) 發送無效化訊息，避免全域廣播。
* **適用場景**：大規模多核心與 NUMA 系統，延展性 (Scalability) 極佳。


* **MESI 與 MOESI 狀態機轉變**
* **MESI 協定**（四種狀態）：
* **Modified (M)**：已修改且為唯一副本，與主記憶體不一致（Dirty）。
* **Exclusive (E)**：未修改且為唯一副本，與主記憶體一致（Clean）。
* **Shared (S)**：可能被多個 Cache 共享且與主記憶體一致。
* **Invalid (I)**：無效狀態，存取會觸發 Cache Miss。


* **MOESI 協定**（加入 **Owner (O)** 狀態）：
* 允許 Dirty Line 被多個 Cache 共享。由 Owner 核心負責回應其他核心的 Read Request，無需先將資料寫回主記憶體，大幅降低 DRAM 存取次數。




* **虛假共享 (False Sharing)**
* **原因**：不同核心的獨立變數不幸落在「同一個 Cache Line (通常為 64 Bytes)」內。即使核心間沒有真正共用變數，也會因為乒乓效能無效化 (Cache Line Bouncing) 導致效能劇烈下降。
* **解法**：資料結構對齊 (Data Structure Alignment, 如 `alignas(64)`) 與 Padding 填充。



### 3.2 記憶體一致性模型 (Memory Consistency)

* **Consistency vs. Coherence 的區別**
* **Coherence (一致性)**：針對「單一記憶體位址」的讀寫行為與順序約束。
* **Consistency (連貫性/模型)**：針對「跨多個記憶體位址」的讀寫操作在全域時間軸上的執行順序規範。


* **順序一致性 (Sequential Consistency, SC)**
* **定義**：由 Leslie Lamport 提出。所有核心的讀寫操作看似依照一個全域交錯順序執行，且每個核心內部的操作順序與程式碼順序 (Program Order) 完全一致。
* **缺點**：嚴格禁止 CPU 進行 Write Buffer 重排 (Store-Load Reordering) 與亂序執行 (OoO)，極大地限制了硬體優化空間。


* **鬆散一致性 (Relaxed Consistency Models)**
* **TSO (Total Store Order, 如 x86)**：允許 Store-Load 重排（因為 FIFO Store Buffer 的存在），但禁止 Store-Store 或 Load-Load 重排。
* **Weak / Relaxed Memory Model (如 RISC-V, ARM)**：預設允許任意讀寫重排以提升硬體吞吐量，僅在明確下達屏障指令時保證順序。


* **記憶體屏障 (Memory Barriers / Fences)**
* **作用**：硬體指令（如 RISC-V `fence` 或 ARM `dmb`），強制清空 Store Buffer 並阻止編譯器/CPU 將屏障後的存取重排至屏障之前，確保跨核心同步邏輯（如 Spinlock、Lock-free Queue）正確運作。



### 3.3 資料層級平行 (DLP) 與向量運算

* **SIMD (Single Instruction, Multiple Data) 架構**
* **機制**：單一指令同時對一組向量暫存器（如 128/256/512 bits）內的純量元素進行相同運算（如 4 個 32-bit 浮點數同時相加）。
* **主流 ISA**：x86 (AVX-512)、ARM (NEON/SVE)、RISC-V Vector Extension (RVV)。
* **編譯器自動向量化 (Auto-Vectorization)**：迴圈展開 (Loop Unrolling) 與記憶體連續存取優化。


* **GPU 架構基礎：SIMT (Single Instruction, Multiple Threads) 執行模型**
* **SIMD vs. SIMT**：SIMD 顯式操作向量暫存器；SIMT 讓程式設計師寫單一線程邏輯，硬體自動將多個 Threads (如 32 個 Threads 組成一個 Warp/Wavefront) 鎖步 (Lock-step) 綁定至同一指令發射器執行。


* **Thread Block 與 硬體調度邏輯**
* **Grid / Block / Thread 階層**：軟體將任務切分為 Thread Block；硬體將 Thread Block 分配至 Streaming Multiprocessor (SM / Compute Unit)。
* **Warp Divergence (分歧處理)**：當 Warp 內不同 Thread 在 `if-else` 分支走向不同路徑時，硬體會將不符合條件的 Thread 設為 Mask/Disable，序列化執行兩條路徑，導致效能下降。
* **零開銷上下文切換 (Zero-Overhead Context Switch)**：SM 內建數千個 Registers，同時駐留多個 Warps。當一個 Warp 發生 Global Memory Access Latency (數百 Cycles) 時，HW Warp Scheduler 可在單一 Cycle 內切換至另一個 Ready Warp 執行，以計算隱藏延遲 (Latency Hiding)。

## 第四章：系統軟體硬體交會點 (System Software Interface)

### 4.1 組合語言與 ABI 規範

* **函式呼叫約定 (Calling Conventions) 與暫存器分工**
* **Caller-Saved vs. Callee-Saved Registers**：
* *Caller-Saved (如 RISC-V `t0-t6`, `a0-a7`)*：由呼叫者 (Caller) 負責在 `call` 前壓棧保存，函式內部可隨意覆寫。
* *Callee-Saved (如 RISC-V `s0-s11`)*：由被呼叫者 (Callee) 負責維護，若函式內需要改寫，必須在 Prologue 壓棧保存並於 Epilogue 恢復。


* **引數傳遞與傳回值**：優先使用暫存器（如 `a0-a7` 傳遞參數，`a0-a1` 傳回值）；當參數超過 8 個時，溢出 (Overflow) 參數改透過 Stack 傳遞。


* **堆疊框架管理 (Stack Frame Architecture)**
* **Stack Alignment**：RISC-V 規範 Stack Pointer (`sp`) 必須保持 16-Byte 對齊（因應 SIMD / 雙精度浮點存取需求）。
* **Prologue 與 Epilogue 流程**：
* *Prologue*：`sp` 向低位址生長（如 `addi sp, sp, -32`），將 `ra` (Return Address) 與 Callee-Saved 暫存器寫入 Stack，並設定 Frame Pointer (`fp/s0`)。
* *Epilogue*：自 Stack 還原暫存器與 `ra`，恢復 `sp`（如 `addi sp, sp, 32`），最後執行 `ret` (`jr ra`) 跳轉回呼叫處。




* **位置無關程式碼 (PIC) 與動態連結原理**
* **Position-Independent Code (PIC)**：允許共享庫 (.so / .dll) 被載入至記憶體任意位址而無需修正內部指令。
* **GOT (Global Offset Table)**：在 Data Segment 建立全局變數與函式的位址表。指令透過去 PC 相對定址 (`auipc`) 查詢 GOT 來取得目標實體位址。
* **PLT (Procedure Linkage Table) 與 Lazy Binding**：動態函式庫首次被呼叫時才發起符號解析 (Symbol Resolution)。PLT 搭配 GOT 完成延遲綁定，大幅加快程式啟動速度。



### 4.2 系統呼叫與中斷處理

* **特權等級 (Privilege Levels) 與保護機制**
* **RISC-V 特權模型**：User Mode (U-Mode, 應用程式)、Supervisor Mode (S-Mode, OS Kernel)、Machine Mode (M-Mode, Firmware/OpenSBI)。
* **硬體隔離**：U-Mode 無法存取控制暫存器 (CSR) 或受保護的實體記憶體（由 PMP/MMU 檢查），確保單一應用程式崩潰不會影響系統穩定度。


* **系統呼叫 (Syscall) 執行路徑**
* **`ecall` 指令觸發**：應用程式將 Syscall Number 填入 `a7`，參數填入 `a0-a6` 後執行 `ecall`。
* **硬體自動切換**：CPU 自動將特權等級升至 S-Mode，將當前 PC 存入 `sepc`，例外原因 (`Environment call from U-mode`) 寫入 `scause`，並強制 jump 至 `stvec` 記載的 Syscall Handler。


* **硬體中斷 (Hardware Interrupts) 與 Trap 處理流程**
* **中斷分類**：非同步硬體中斷（Timer、UART/NVMe 外部中斷）與同步 Trap/Fault（Page Fault、Divided-by-Zero）。
* **PLIC (Platform-Level Interrupt Controller) 與 CLINT (Core Local Interruptor)**：
* *CLINT*：處理核心私有的 Timer 與 Software Interrupts。
* *PLIC*：收集並仲裁所有外部裝置中斷，評估優先級 (Priority) 與 Threshold 後傳送給特定 CPU Core。


* **Trap Handler 執行步驟**：
1. **Save Context**：Assembly 入口處 (`trap_vector`) 將所有 32 個通用暫存器存入當前 Thread 的 Kernel Stack。
2. **Dispatch**：讀取 `scause` / `mcause` 分派至特定的 C 語言處理函式 (如 `handle_page_fault()` 或 `handle_timer_irq()`)。
3. **Restore Context & `sret**`：自 Kernel Stack 還原暫存器，執行 `sret` 指令切回 U-Mode，硬體重置特權等級並自 `sepc` 恢復執行。




* **上下文切換 (Context Switch) 的硬體開銷分析**
* **微架構直接開銷**：通用暫存器、CSR 與 Stack Pointer 的保存與還原 (約數百 Cycles)。
* **微架構間接開銷 (Indirect Overhead)**：
* **TLB Flush**：切換 Page Table (更新 `satp` CSR) 會使 TLB 失效（除非使用 ASID Address Space ID 標記）。
* **Cache Cold Misses**：新進程載入導致 L1/L2 Cache 遭遇 Compulsory/Capacity Misses，這是 Context Switch 最昂貴的效能懲罰。
