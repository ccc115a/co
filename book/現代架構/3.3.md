## 1. 三種平行度

| 平行度 | 全名 | 原理 | 手段 |
|--------|------|------|------|
| **ILP** | Instruction-Level | 在同一碼流裡平行 | 1.2–1.4：Pipeline、Superscalar、OoO |
| **TLP** | Thread-Level | 多執行緒各自推進 | 多核心、SMT、執行緒 |
| **DLP** | Data-Level | **同一指令對大量資料**同時運算 | SIMD、SIMT/GPU、向量 |

DLP 的哲學：與其追求「好幾條指令」便宜執行，不如**一條指令對「一堆資料」做同一個運算**——程式（如矩陣乘法、影像濾波、Conv/GEMM）佈滿此類「對大量同構資料做相同運算」。

## 2. SIMD (Single Instruction, Multiple Data)

### 2.1 概念與暫存器

單一指令操作**向量暫存器**，暫存器內分割多個「純量元素」。元素寬度與個數由 ISA 決定：

```
128-bit 向量暫存器（4 × 32-bit float）:
  指令: vadd.ps zmm0, zmm1, zmm2
  zmm1:  [f0|f1|f2|f3]      zmm2: [g0|g1|g2|g3]
  zmm0 = [f0+g0, f1+g1, f2+g2, f3+g3]    ← 一次完成 4 個加法
```

主流向量暫存器寬度：

| ISA | 指令集 | 暫存器寬度 |
|-----|--------|-----------|
| x86 | MMX/SSE | 64 / 128 |
| x86 | AVX / AVX2 | 256 |
| x86 | AVX-512 | **512**（8×64b, 16×32b, 64×8b） |
| ARM | NEON | 128 |
| ARM | SVE / SVE2 | **可變 128–2048**（scalable） |
| RISC-V | RVV (V ext) | **軟體可見的向量長度（VLEN）**，硬體可 128/256/512… |

### 2.2 RISC-V RVV 簡介

- 向量暫存器：`v0~v31`，寬度 VLEN（由實作決定，軟體用 `vsetvli` 設定元素類型與個數）。
- 例：`vsetvli t0, a0, e32, m1`（設定 32-bit element、VLEN/32 個元素）；`vadd.vv v0, v1, v2` 將 `v1+v2` 逐元素寫入 `v0`。
- **Scalable**：程式不需要知道硬體有多少 lane，同一份程式碼可在 128-bit 或 1024-bit 硬體跑（`vsetvli` 回報實際元素數）。

### 2.3 自動向量化 (Auto-Vectorization)

編譯器把可向量化的迴圈轉成 SIMD 指令，關鍵條件：

1. **資料平行**：迴圈 body 每次迭代互相獨立（無 RAW 依賴、無跨 iteration 的順序依賴）。
2. **連續位址**：陣列索引步進固定 → 載入可「一次抓一整段」（如 `A[i]` 連續）。
3. **無別名/指標逃逸**（`restrict` 幫助編譯器確認非重疊）。

經典轉換 **Loop Unrolling + Vectorization**：

```c
// 原始純量迴圈
for (i = 0; i < N; i++) c[i] = a[i] + b[i];

// 編譯器自動向量化後（4-wide）
for (i = 0; i < N; i += 4) {
    vec_a = load(a + i);        // 一次讀入 4 個 a
    vec_b = load(b + i);
    store(c + i, vec_a + vec_b);
}
// 尾巴  N%4 的部分退化成純量處理（epilog/remainder loop）
```

- **困難點**：依賴鏈（累加器）、非連續存取（`a[j[i]]` gather）、條件分支（masked 向量）。
- **Watermark 指標**：`#pragma omp simd`、`-O3 -march=native`、`-ftree-vectorize` 的故事。

## 3. GPU 架構基礎：SIMT (Single Instruction, Multiple Threads)

### 3.1 SIMD vs. SIMT 的基本差異

| | SIMD（CPU） | SIMT（GPU） |
|---|---|---|
| 程式員視角 | 顯式操作向量暫存器 | 寫**單一執行緒**邏輯 |
| 硬體架構 | 一條指令操作一個向量 | 把多個 Thread 鎖步（Lock-step）綁到**同一個指令發射器** |
| 執行單元 | 向量 Lane 在一個核內 | 數個 SM/Compute Unit，每個再分 Lane |
| 統一性 | 每 lane 資料不同但都執行同指令 | 同 warp 的 32 threads **同時執行同一指令** |

### 3.2 Thread → Thread Block → Grid

CUDA 的階層（映射到硬體調度）：

```
 Grid（一整個問題）
  ├─ Thread Blocks (Bx)   ＜── 由 HW 分配給某個 SM/CC
  │    ├─ Threads (Tx..)  ＜── 一個 SM 內多個 Warp
  │    └─（同一 block 的 threads 可共享 block-local memory）
  └─（無序，可任意順序被調度── 讓 HW 彈性應付資源與負載）
```

- **Block** = 硬體調度單位：一個 Block 整個分配給**一個 SM**（Streaming Multiprocessor / Compute Unit）。
- SM 內再切 **Warp**（NVIDIA 32 threads / AMD Wavefront 64）。硬體以 **Warp 為單位**執行：一個 Warp 的一條指令，實際等同執行 32 條 lane 上的數據操作（一次 fetch/decode/issue 給 32 lane 資料管線）。

### 3.3 記憶體布局與大量平行度

GPU「派大量執行緒」背後的本質：**latency hiding（延遲隱藏）**——沒有大 cache 的硬體（GPU L1 通常僅 32–128KB），用極多**並行 Warp** 來填滿等候。

```
SM 核心結構（Abstract）：
 ┌───────────────────────────────────────────────┐
 │ [Warp Scheduler] ──► [Dispatch]──► 32 lanes     │
 │   ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐              │
 │   │ W0  │ │ W1  │ │ W2  │ │ ... │ (多 warp 駐留)│
 │   └─────┘ └─────┘ └─────┘ └─────┘              │
 │   （大量 Register File：數萬到數萬個 registers）│
 └───────────────────────────────────────────────┘
```

### 3.4 Warp Divergence（分歧）—— SIMT 的弱點

同一 Warp 內不同 Thread 走到了不同的 `if-else` 分支：

```
if (idx % 2 == 0)   a = f(a);   // thread 0,2,4...
else                a = g(a);   // thread 1,3,5...
```

硬體**無法**同時執行兩個 branch body——只能**序列化**：

1. 有 mask：啟用 half-warp 的 threads 執行 `f`，另一半 mask（disable）。
2. 再執行另一半合乎條件的 threads 執行 `g`。
3. 結果：整個 Warp 一共花「兩倍」時間（若代價同）。

- 失去的正是 SIMT 的關鍵優勢；還會大幅干擾「同一 warp 內平行存取」。
- **編程建議**：避免在 warp 內分歧、用「整個 warp 一起分歧」（32 threads 全走同路）或 `if (threadIdx.x % 32 == 0)` 而非 `%2`。

### 3.5 Zero-Overhead Context Switch 與 Latency Hiding

GPU 沒有「中斷後儲存/恢復 register」的 context switch 開銷——因為硬體在 SM 內**同時駐留很多 Warp**：

```
當 Warp0 的存載遇到 memory 存取延遲（數百 cycles）：
  硬體 Warp Scheduler 立刻 pick 另一個 Ready Warp 上場
  → 下一個 cycle 就執行 Warp1 的指令
  → 不需要保存/恢復暫存器（所有 warp 的暫存器都在 SM 內）
  → 「零開銷」切換
```

- SM 內暫存器總量固定（如 64K registers）：每個 warp 分到越少暫存器 → 能駐留越多 warp → latency hiding 越強（但每個 thread 可用的空間越小）。
- 這是 GPU 與 CPU 本質上的差異：CPU 靠「推測/預取/快取」搶 latency，GPU 靠「海量並行度 + 零開銷切換」把 latency 藏起來。

## 4. 效能觀點與比較

| 場景 | CPU（ILP+向量） | GPU（SIMT+平行） |
|------|----------------|------------------|
| 少量大資料、依賴鏈長 | 好 | 差（沒 ILP 可藏） |
| 大量同構資料、無依賴 | SIMD 好 | **最佳（大吞吐）** |
| 分支多、分歧大 | 好（很多 ILP） | 差（warp divergence 砍半） |
| 記憶體延遲高、大量獨立資料 | 爆走 prefetch | 靠 warp 平行藏住 |

典型：讓 CPU 站在「較寬的 SIMD（AVX-512/RVV）+ 有序管線 + 少量大 thread」，GPU 站在「海量 warp 平行 + 算力密度」。現代的 RISC-V RVV 想讓 CPU 也有 GPU 的 DLP 彈性（scalable vector）。

---

## 5. 小結

- DLP = 一條指令對大量資料；ILP=單一資料的多指令、TLP=多執行緒。
- SIMD（CPU 顯式向量）與 SIMT（GPU 隱式多執行緒鎖步）達到類似吞吐量，但程式與硬體完全不同。
- Auto-Vectorization 依賴「獨立 + 連續 + 無別名」，編譯器自動抓住大部分。
- Warp Divergence 序列化；Zero-Overhead Context Switch 用駐留 warp 數隱藏記憶體延遲。
- RVV / SVE 把 CPU 的向量寬度也「可縮放」化，讓 DLP 更貼近硬體規模。
