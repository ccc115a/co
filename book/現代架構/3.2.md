## 1. Coherence vs. Consistency

### 1.1 兩個層次的問題

| 層次 | 範圍 | 問題 |
|------|------|------|
| **Coherence** | **單一記憶體位置** | 我寫 A，別人什麼時候看到我的寫？不同核寫同一 A，順序是否一致？ |
| **Consistency** | **跨多個記憶體位置** | 我寫 A 再寫 B，別人看到 A 與 B 的次序是否與我的程式順序一致？ |

Coherence 的「寫入序列化」保證：同一位置的寫有總次序。但**不同位置**之間呢？Consistency Model 定義「程式指令順序與記憶體操作次序之間的合法對應關係」——正是平行程式的**合法可見次序**。

### 1.2 一個直觀例子

```
初始: A=0, B=0
Core0:      Core1:
  store B=2   load A → ?
  store A=1   load B → ?
```
若 Core1 看到 (A=1, B=0)——反轉了 Core0 的次序——除非 Consistency Model 允許 store-store 重排，否則這是非法結果。Consistency Model 劃定了「哪些禁止」。

## 2. 順序一致性（Sequential Consistency, SC）

### 2.1 定義（Lamport, 1979）

> 整體系統的執行結果，等價於「所有記憶體操作（跨所有核心）」以某個**全域交錯次序**排列；且
> **每個核心內部**的記憶體操作次序，必須**維持其程式次序（Program Order）**。

形式化：

$$
\begin{aligned}
&\text{存在一個全域次序 } < \text{，涵蓋所有核心的所有記憶體操作}\\
&1.\ \text{每筆讀看到的是「在 }<\text{ 之前最近一次對同位置的寫」}\\
&2.\ \forall \text{ 核心 } c: \text{ 其 Program Order 與 } < \text{ 一致}
\end{aligned}
$$

### 2.2 SC 的風格例子（Litmus Test）

```
初始: x=y=0
P0:        P1:
  st x=1    st y=1
  ld y       ld x
結果 (x=0, y=0) 在 SC 下不可能出現
```

因為任何合乎 Program Order 的交錯，至少要一方先寫再讀，讀到對方寫完後的後續值。

### 2.3 為何 SC 對現代硬體太嚴苛？

要達成 SC 相當於**禁止所有重排**：

- **Store Buffer（寫緩衝）**：硬體為了不解慢 store，常先丟進 buffer 才落 memory——但這樣即使寫入未「完成」，下一條 load 也可能先被執行 → **Store→Load 重排**，違反 SC。
- **OoO 執行（1.4）**：load/store 依賴少（無 RAW）常被 CPU 重排 → Load→Load 重排也發生。
- **寫快取**：Write-Back Cache（2.1）本身就會讓「寫的實際落地」延後。

因此強制 SC 就等於給 Store Buffer、OoO、Write-Back Cache 的手腳綁起來——**性能極殺**。現代 CPU 幾乎都是「彈性」模型。

## 3. 鬆散一致性模型（Relaxed）

### 3.1 可以拆解的重排維度

一張「允許哪些重排」的矩陣（reorder allowed?）：

| 模型 | Store→Load | Store→Store | Load→Load | Load→Store |
|------|:---:|:---:|:---:|:---:|
| **SC** | ✗ | ✗ | ✗ | ✗ |
| **TSO (x86)** | ✔ | ✗ | ✗ | ✗ |
| **ARM / RISC-V (Weak)** | ✔ | ✔ | ✔ | ✔ |

### 3.2 TSO（Total Store Order）——x86 的模型

代表模型：**FIFO Store Buffer** 是創建 TSO 的硬體動機。

- **Store→Load 重排允許**（核心先用自己的 Store Buffer 讀自己的 store，不必等；而別核看到的 store 順序維持 FIFO）。
- **Store→Store、Load→Load 不重排**。
- x86 對「自己核」的 load 可以先於早在緩衝中的 store 完成。故 classic store buffer reorder 例如：

```
P0:                        P1:
  st x=1   ; buffered       st y=1   ; buffered
  ld y  ← 可能在 st x 之前   ld x  ← 同理
  「自己讀到的次序？」被破壞
```

### 3.3 Weak / Relaxed（ARM, RISC-V）

- **預設允許任意重排**（包括 Load→Store 的重排——0/1 重排全開）。
- 要保證順序，**程式必須顯式下屏障**。
- ARM C/C++ 需要編譯器生成欄欄屏障；Rust 的 `Ordering` 也直接對應到這些屏障。

### 3.4 為何允許重排對效能意義重大？

- **Load→Load 重排**：允許 CPU 把較早的 load 提早、較晚的 load 提早——一旦前一個 miss，後面的 load 不必等。
- **Store→Store 重排**：允許合併、允許延後 store、允許於 cache 層聚落——顯著減壓力。
- 高階核心（尤其是 GPU、arm big.LITTLE）尤依賴此彈性。

## 4. 記憶體屏障（Memory Barriers / Fences）

### 4.1 作用

屏障是一條顯式硬體指令：**把它放進去，阻止屏障前後的存取跨越邊界**（也阻止編譯器把屏障後的記憶體操作搬到前面）。RISC-V 的 `fence`、ARM 的 `dmb` / `dsb`、x86 的 `mfence` / `lfence` / `sfence`。

### 4.2 RISC-V fence 語法

```
fence  pred, succ
```

- 表示「屏障**之前（pred）**的所有存儲/載入，必須在屏障**之後（succ）**的存取可見之前完成」。
- 常用形式：`fence rw, rw`（完整屏障）；`fence iorw, iorw`（含對 MMIO）。

```
# Message Passing 範例
init: x=0, flag=0
writer:         reader:
  st x=1        spin: ld flag
  fence rw, rw        # ⬅ 屏障：flag 之後再寫 x
  st flag=1     beq  (跳)

讀到 flag=1 後：
  fence rw, rw  # 再屏障
  ld x  ➜ 必須看到 1
```

### 4.3 ARM 的語法與語義

- `dmb ish`（內共享域屏障）、`dsb`（更強：還等 cache/器件）——ARMv8 在「需順序」處放 `dmb ishld` / `dmb ishst` 視需要。
- C 記憶體模型（`atomic_*` + `memory_order_acquire/release/seq_cst`）編譯後就映射到這些鐵民屏障。
- x86：`mfence`（全域全序）、`lock` prefix（原子指令也有屏障特性）。

### 4.4 一個要屏障的經典難題（Message Passing）

```
初始: data=0, ready=0
P0:               P1:
  store data=1     while (load ready == 0) {}
  store ready=1    load data  → ?
```

- x86 / x86-TSO：`ready=1` 與 `data=1` 的次序由 Store Buffer FIFO 保證（Store-Store 不重排）→ **不需 barrier 也能讀到 1**。
- ARM / RISC-V Weak：P1 可能讀到 `ready=1` 但 `data=0`（兩個 store 重排）→ **需要 `fence rw,rw`（或 release/acquire 對）才能保證**。

**口訣**：release/acquire 是一對——writer 用 release 釋放「先完成其他寫」的信號，reader 用 acquire 對應讀取。

---

## 5. 與 Lock-free / Spinlock 的關聯

- **Spinlock**：`while(!CAS(&lock,0,1))`——CAS 帶 `lock` hint 或原子性能力。
- **lock-free queue**：各大 producer/consumer 的 publishing 儀軌依賴 release/acquire。
- C++ 的 `std::atomic` 提供 `memory_order_seq_cst`（最強）或 `acquire/release`（較鬆）——**正確的 model 加上正確的 barrier 後，跨架構移植才不會出奧步**。

---

## 6. 小結

| 模型 | 代表架構 | 允許的重排 | 需要的屏障 |
|------|----------|-----------|-----------|
| SC | 教科書 | 無 | — |
| TSO | x86 / SPARC | Store→Load | `mfence`（少數） |
| Weak | ARM, RISC-V | 全部 | `dmb` / `fence` 頻繁 |

- Consistency 管「不同位置的次序」，Coherence 管「同位置的序列化」。
- SC 最美但金貴；現代 CPU 寧可違規 + 屏障，來換 stream 上的效能。
- 寫多執行緒程式時把模型記在腦中——別假設「我看過它 → 它也順序保證」。
