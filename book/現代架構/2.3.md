## 1. 主記憶體（DRAM）概觀

### 1.1 為什麼用 DRAM 而非 SRAM

| | SRAM | DRAM |
|---|---|---|
| 每個 bit | 4–6 電晶體 | **1 電晶體 + 1 電容器 (1T1C)** |
| 速度 | 快（暫存器級） | 慢（電容讀寫） |
| 容量/成本 | 小、貴 | **超大、超便宜** |
| 性質 | 靜態（不需 refresh） | **動態：電容洩漏需 Refresh** |
| 用途 | L1/L2/L3 Cache | **主記憶體** |

DRAM 基於 1T1C：**比特存於電容器的電荷**。電容會自然放電（ms 級），因此必須定期 **Refresh**：記憶體控制器每 ~64ms 內把每一列讀出再寫回（自動充電恢復），約佔 1–2% 的頻寬。Refresh 是 DRAM 無法被當成大型 SRAM 使用的根本原因。

### 1.2 晶片內組織：Bank / Row / Column

```
        ┌─────────────── DRAM 晶片 ───────────────┐
        │  Bank0   Bank1   Bank2   Bank3          │  ← 獨立可並行
        │                                        │
        │ Row:  Capacitor 矩陣（如 1024 columns）│
        │ ┌────────────────────────────────┐    │
        │ │ Sense Amplifier 列（Sensing）  │    │  ← Activate 時讀出整 row
        │ └────────────────────────────────┘    │
        │  Column 選擇 (CAS) ──► I/O             │
        └──────────────────────────────────────── ┘
```

- **Bank**：晶片內多個獨立記憶體陣列，可**平行服務**不同操作（如 Bank0 在做 Precharge 時 Bank1 照樣 Activate/Read）——所以搭配多 bank 才有高流量。
- **Row**：一開啟（Activate）後，整列資料被拉進 **Sense Amplifiers**（感應放大器）——延遲後續讀寫可以很快。
- **Column**：在已啟動的 Row 內挑出特定 word 的資料移動。

### 1.3 存取序列

1. **Activate**（送 Row Address，RAS#）：開啟某 Bank 的某一行 → 該列複製進 Sense Amplifier。
2. **Read / Write**（送 Column Address，CAS#）：讀出 / 寫入 word。
3. **Precharge**：回復該 Bank 為「待機」狀態（準備開新 Row）。

若連續讀同一 Row 的不同 Column → 只需一次 Activate + 多次 CAS，稱 **Page Hit**（Row Buffer Hit），便宜得多。反之換 Row 就要先 Precharge 再重新 Activate——是主要的 DRAM 延遲來源。

## 2. DRAM 時序參數

由 DDR 標準規範（DDR4-3200 等）給出的典型數值（cycles）：

### 2.1 $t_{RCD}$（RAS to CAS Delay）

> Activate 命令發出後，到資料列在 Sense Amplifier 中就緒、可以發 Read/Write（CAS）命令的間隔。

$$
\text{總延遲} = t_{RCD} \times (\text{時脈時間})
$$

例：DDR4-3200，$t_{RCD}=16$，時脈週期 0.625ns → 16 × 0.625 = **10ns**。

### 2.2 $CL$ / $t_{CL}$（CAS Latency）

> 發出 Read（CAS）命令到第一筆資料從資料針腳傳出的延遲。

- DDR4-3200 常見 $CL = 14\text{–}22$ cycles。
- 是「熱門行命中後」的延遲主體，也是行銷常標榜的數字（美光片標 `CL16` 等）。

### 2.3 $t_{RP}$（Row Precharge Time）

> 關閉當前 Row、恢復 Sense Amplifier 並將 Bank 轉回「待命」以供 Activate 新行所需的時間。

一個「換行」的完整延遲 = $t_{RP} + t_{RCD} + CL$。

### 2.4 其他重要參數（簡列）

- **$t_{RAS}$**：Active 到 Precharge 最短時間（禁止開一下就關的行為）。
- **$t_{RC}$** = $t_{RAS} + t_{RP}$：兩個不同 Row 操作間最短間距。
- **$t_{WR}$ / $t_{DPL}$**：寫入後等到可以用其他命令的延遲。
- **$t_{RFC}$**：Refresh 週期——記憶體控制器需定期全列 Refresh。

## 3. 匯流排架構與仲裁

### 3.1 系統匯流排的角色

把所有腦的節點（CPU core、GPU、DMA controller、NVMe、Ethernet）接到 DRAM 的路由：

```
        CPU core0 / core1 / core2 / core3
                │  (Cache coherence, 見 3.1)
                ▼
        ┌──────────────┐
        │ Memory        │
        │ Controller    │  ← 仲裁（決定誰先用 DRAM）
        └──────┬───────┘
               ▼
        ┌──────────────┐   DDR4/DDR5 PHY
   ┌────►│ DRAM module  │
   │     └──────────────┘
   │
   ┌────► PCIe Root Complex ──► GPU / NVMe SSD / NIC
```

統一的 memory-mapped 位址空間讓所有 Master 都能看見同一塊 DRAM，透過同一個 Memory Controller 存取。

### 3.2 Bus Arbitration（匯流排仲裁）

當**多個 Master 同時**要用匯流排（或 DRAM Controller 的 request queue），需要仲裁選擇誰先用：

| 策略 | 機制 | 優點 | 缺點 |
|------|------|------|------|
| **Fixed Priority** | 依固定優先權（如 DMA > CPU） | 簡單、保證延遲上限 | 低優先權可能餓死（Starve） |
| **Round-Robin (RR)** | 依序輪流 | 公平、無餓死 | 高優先權急事被拖延 |
| **Weighted / ML-Based** | 加權或學歷判斷 | 兼顧公平與優先 | 複雜 |

- 匯流排仲裁也可連貫到 Cache Coherence（3.1）：多核心共享 L2/L3 時，連 snoop 也要仲裁。
- **Memory Controller 的 Queue 深度**有限：超過就必須 stall 來源 Master（back-pressure）。

### 3.3 DDR 與多通道

- 系統記憶體有多個 **DDR Channel**（如 2-4 channel），各自有獨立的 memory controller & 匯流排 → 平行增加總頻寬。
- 記憶體位址 interleaving（低位的 bank/channel bits 交錯）讓連續存取分散到不同 channel/bank，Page Hit 率提高。

## 4. 直接記憶體存取（DMA）

### 4.1 動機：CPU 搬資料太浪費

如果每次 SSD→RAM 都由 CPU 逐字複製：
- CPU 要執行上百萬條 store；寶貴的計算週期被搬資料吃掉；
- CPU 同時也別無他事，Memory 與 CPU 衝突頻寬。

**DMA** 把「搬資料」的苦差外包給專用硬體（DMA Controller 或做成設備內部的 engine）。

### 4.2 DMA 流程（以 NVMe SSD→DRAM 為例）

```
CPU：  設定 Command（Device → DMA, 資料長度, 目標記憶體）
        └► 寫 DMA 控制器 CSR：Source / Dest / Length / Enable
DMA：   自行把 Device 資料讀出並寫入 DRAM
        （不耗 CPU 計算週期）
        └► 完成 → 觸發硬體中斷（如 PLIC，見 4.2）
CPU 桌面續跑其他工作，直到中斷通知「搬好了」
```

關鍵角色：**Source / Destination / Length** 由 CPU 在傳輸前設定；傳輸中 CPU 完全不管——這就是「Unload the CPU」。

### 4.3 DMA 與快取一致性（Coherence）

DMA 直接寫 DRAM，但 CPU 可能已把「同一記憶體」緩存在其私有 L1/L2（dirty）——造成資料不一致。現代系統透過：

- **IOMMU / SMMU**（設備端轉譯 + 快取一致映射）；
- 或「先 invalidate CPU cache（dma_map_sync）再啟動 DMA」；
- 或硬體做 coherent DMA（如 ARM SoC 常用的 cache-coherent masters）。

Coherence 話題在 3.1 詳談，DMA 是第一個必須處理「外部 Agent 的記憶體視圖」的例子。

### 4.4 常見 DMA 應用

- NVMe / SATA SSD 資料面搬移；
- 網路卡收發大封包（下放 ring buffer）;
- GPU 資料面（push 到 replicable VRAM 區）；
- 音訊播放 buffer。

## 5. 效能與資料流整合觀點

```
ISO view（把「等待記憶體」當第一公民）：
  DRAM 頻寬 = 通道數 × (資料匯流排寬 × DDR 雙沿傳輸)
  DRAM 延遲 = t_RCD + CL + t_RP（換行時）+ Controller+Bus+Interconnect 層層
```

- 現代 CPU 的 Memory Wall 主因：**延遲（latency）**遠大於頻寬問題；多通道、Prefetch、OoO（1.4）都為「latency hiding」而設。
- **頻寬 vs 延遲**：增加通道數提頻寬但卻不減單請求延遲；要減延遲只能靠更短 $t_{RCD}/CL/t_{RP}$ 或 page hit（好 bank interleaving、好 stream 預取）。

---

## 6. 小結

- DRAM = 1T1C + 定期 Refresh；內部 Bank/Row/Column，Sense Amplifier 是開行的關鍵。
- 時序參數 $t_{RCD}$、$CL$、$t_{RP}$ 決定「換行」的總成本——Page Hit 是救星。
- 多 Master 系統需要 Bus Arbiter（Fixed Priority / Round-Robin）。
- DMA 用專用硬體搬資料，CPU 只設定 Source/Dest/Length 並收完成中斷。
- 多通道 + interleaving + prefetch 是現代記憶體系統的呼應。

第三 章把「多 Master」升級成「多核心」：Cache Coherence（3.1）、Memory Consistency（3.2）、然後進入 DLP/向量（3.3）。
